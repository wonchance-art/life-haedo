# 흐름 중심 블로그 개편 — 구현 계약

2026-10-18 Asia/Seoul. 사용자가 상세 설계 뒤 “좋아 진행해. UI UX 계속 개편시켜. 이미 만들어둔 것도 상관없이 일관성 있게 진행 ㄱ”라고 지시했다.

원래 목표는 메인에서 무엇을 해야 하는지 분명한 SNS형 블로그다. 이번 실행 단위는 승인된 [사용 흐름 설계](../docs/life-tools-design/sns-blog-user-journeys.md)의 P0: 하나의 대표 글 목록과 작성·읽기·복귀·실패 복구다. 공개·자산 서버 확장을 UI 작업에 숨겨 추가하지 않는다.

## 사용자 성공과 첫 화면

- 첫 글 쓰기 → 기존 로그인 → 시작 의도 복원 → 제목 없이 본문 → 비공개 저장 → 실제 글 읽기 → 그 글이 보이는 홈.
- 일반 로그인은 홈. 프로필 입력·자료 가져오기·공개는 첫 성공의 선행 조건이 아니다.
- 홈은 실제 블로그 소개 → 한 작성 행동 → 초안 이어쓰기 → 글/초안/보관함·내 글 검색 → 실제 내용의 목록이다.
- 빈 글 목록에서는 첫 글 쓰기 하나만 강조한다. 가짜 사회적 지표·장식 대시보드·기능 타일을 추가하지 않는다.

## 흐름과 보존

- 원문 기반 직접 작성 글, 기존 첨부 글, 신형 리치/사진 글을 홈의 읽기 투영으로 모은다. 저장 형식·버전·동기화·공개 범위는 변환하지 않는다.
- 제목은 선택이며 처음에는 본문에 집중한다. 빈 제목에 거대한 가짜 제목을 넣지 않는다.
- 초안 보관과 명시 저장을 구별한다. 저장 후 읽기에서 완성된 내용을 확인한다.
- 목록의 탭·검색·더보기 범위·출발 항목을 보존한다. 저장 성공 시 실제 새 ID와 글 형식으로 목적지를 확인한다.
- 검색 조건에 가려진 저장 결과는 설명과 명시적 검색 해제를 제공하며 검색어를 몰래 지우지 않는다.
- 저장·계정·작업공간 실패와 늦은 응답에서 입력/개인 자료를 보호한다. 초안 충돌 사본은 같은 실패 저장을 먼저 요구하지 않고 현재 메모리 입력·원본 바이트를 보존한다.
- 프로필은 단독 편집. 선택 자료 페이지는 자료실의 구성·기존 공개 사본 작업으로 구분하고 모든 기존 호환 작성/파일 접근을 보존한다.

## 공통 UI와 시각 규칙

- 홈/자료실/도구/설정. 내부 경로 ID는 유지한다.
- 현행 흰색·차콜, 파란 링크/초점, 한글 산세리프, 가는 구분선과 실제 사진을 유지한다. 공통 토큰의 의미를 바꾸지 않는다.
- 1440/820/390px 한 열. 데스크톱 라벨 탐색/태블릿 레일/모바일 화면 끝 하단 메뉴를 사용한다.
- 작성 중 모바일 하단 메뉴를 감추고 실제 닫기·저장을 남긴다. 읽기·닫기 뒤 메뉴와 여백이 복원된다. 기존 호환 작성기도 같은 동작이다.
- 44px 조작·16px 입력·한글 조합·키보드 초점·대비·안전 영역을 유지한다. 동일 복귀 조작을 중복해서 강조하지 않는다.

## 검증과 범위

실제 앱·SDK·IndexedDB와 익명 HTTP 인증으로 첫 글/목록 3형식/초안/보관/정확 복귀/검색 조합/일부 실패/계정·공간 늦은 응답을 확인한다. 첫 렌더 묶음과 최종 묶음 이후 독립 새 문맥 리뷰어에게 실제 캡처를 넘긴다. 기능 검사·시각 검토·실기 체험을 구분한다.

설치된 Impeccable은 지침 배포본이며 자동 context/detect/launcher/hook은 없다. 수동 맥락과 실제 브라우저 증거로 검토한다. P1 기본 작성 글 공개·P2 사진 공개/정확 원문 첨부 연결은 별도 후속이며 현재 구현됐다고 표시하지 않는다.
