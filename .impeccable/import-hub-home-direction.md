# 가져온 글 중심 홈 — 구현 전 계약

2026-10-18 KST. 모드: Operate + Read. 해도는 **외부 여러 곳에 흩어진 내 글과 저장한 자료를 가져와 한곳에서 찾고 관리하는 도구**다. 외부 블로그와 해도에서의 보관·관리·직접 작성·선택 공개는 구분한다. 현재 흰 본문·옅은 초록 회색·짙은 틸·Pretendard·공통 탐색과 안전 영역을 유지한다.

## 화면의 역할

- **공개 진입:** 목적을 실제 기능어로 설명하고 주 행동은 가져오기다. 로그인 뒤 가져오기로 이어진다. 가상 블로그 피드·사진·취향 문구를 제품 설명의 중심으로 두지 않는다. 파일·붙여넣기·링크 등 기존 지원 범위를 전체 SNS 계정 자동 연동으로 확대하지 않는다.
- **홈:** 검색 → 가져오기 → 있을 때 이어읽기 한 행 → 최근 자료 최대 6개. 최근에는 가져온 원문과 기존 형식의 직접 저장 글을 읽기 투영으로 섞되 저장 형식을 합치거나 복제하지 않는다. 프로필·작성 상자·글/초안/보관함 상태 탭은 홈에서 제거한다.
- **자료실:** 기존 원문 검색·분류·발췌/메모·자료 관리와 전체 탐색을 담당한다. 홈의 전체 보기는 sources로 이동한다. 별도 형식의 직접 쓴 글은 명시적인 진입점에서 writings로 열어, 같은 자료실 안의 그룹 접근으로 찾게 한다. 하나의 원천 목록에 전부 합쳤다고 표시하지 않는다.
- **직접 쓴 글:** writings는 기존 세 형식의 글·초안·보관함·내 글 검색·프로필·작성/읽기·원본 사진·첨부·백업 경로를 보존한다. 새 최상위 메뉴를 만들지 않고 홈에서 빠진 조작을 삭제로 처리하지 않는다.

## 보존과 의미

홈 목록은 실제 자료만 보여 주고 직접 작성 글이 0개여도 가져온 원문이 있으면 빈 화면으로 표시하지 않는다. 본문 미확보/null·출처·작성자 관계 미확인·자동 분류 후보를 구별한다. 보조 파일·기계 추출물을 사용자 글로 승격하거나 저장/가져온 시각을 원 작성일로 바꾸지 않는다. 자료 없음과 일부 읽기 실패도 다르게 표시한다.

원문·불변 버전·UTF-16 구간·첨부·사진 원본·계정/작업공간 경계·저장·동기화·공개·백업 형식은 유지한다. 읽기·검색·작성/저장·목록 복귀에는 출발 화면과 정확한 항목·필터·초점·위치를 보존한다. 늦은 응답이 다른 화면·계정·공간을 덮지 않게 한다. 실패한 저장 때문에 현재 입력을 잃지 않는다.

## 완료 판단

로그인 전/빈 홈/가져온 원문만 있는 홈/직접 저장 글과 섞인 홈, 본문 미확보와 일부 실패를 익명 자료로 확인한다. 검색·가져오기 의도 복원·이어읽기·최근 6개·전체 보기·writings 진입·세 형식과 초안/보관함·정확 읽기/저장 복귀를 1440·820·390px에서 확인한다. 기준 전 화면은 `.local/home-design-review-20261018`의 10개 익명 캡처다. 실제 결과와 시각 판단·실기/운영 한계는 [구현 기록](../docs/design-review/import-hub-home.md)에 분리해 남긴다.

자동 SNS 연결·AI·DB/schema/API·새 라이브러리·원문 재작성·새 공개 기능은 추가하지 않는다. 이전 미니멀 홈 비교 시안의 선택·채택으로 간주하지 않는다.
