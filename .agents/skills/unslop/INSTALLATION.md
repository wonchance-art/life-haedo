# Life-Haedo에서의 unslop 사용

[heydamir/unslop](https://github.com/heydamir/unslop)의 프로젝트 전용 **지침 설치**다. 만든 사람은 Damir Sokolovsky([@heydamir](https://x.com/heydamir))이고 라이선스는 [CC BY 4.0](LICENSE)이다. `SKILL.md`, `references/*.md`, `agents/openai.yaml`은 고정 커밋의 파일을 고치지 않고 그대로 두었다. 출처·커밋·파일별 SHA-256은 [UPSTREAM.json](UPSTREAM.json), 선택 이유와 재현 절차는 [도입 기록](../../../docs/design-review/unslop.md)에 있다.

이 파일은 해도가 덧붙인 사용 범위이며 unslop 원본의 일부가 아니다.

## 설치하지 않은 것

- `scripts/snapshot.mjs`, `scripts/story.mjs`: 설치하지 않았다. 라이브 페이지 저장과 스토리 영상 만들기를 **실행할 수 없다.** 실행했다고 보고하지 않는다.
- `references/refs/*.webp` 참고 이미지 5장: 설치하지 않았다. `SKILL.md`와 `references/refs.md`의 이미지 링크는 이 저장소에서 열리지 않는다. 필요하면 고정 커밋의 원본 저장소에서 본다.
- 이미지 생성 서비스 연결: 하지 않는다. 아래 "화면 그림" 항목을 따른다.

## 이 프로젝트에서 적용하는 범위

적용 순서는 사용자 요청 → `AGENTS.md`·`PRODUCT.md`·`DESIGN.md` → [해도 화면 작업 스킬](../life-haedo-design/SKILL.md) → unslop·Impeccable 참고 문서다. 외부 스킬의 일반 규칙이 소유자 결정과 다르면 소유자 결정을 따른다.

- **기본은 다듬기다.** 해도는 이미 정한 시각 방향(`DESIGN.md`)이 있다. unslop의 `Light slop`(다듬기) 또는 `No slop` 경로를 기본으로 쓴다. 팔레트·글꼴·배치를 새로 정하는 전체 과정은 소유자가 화면 개편을 요청했을 때만 쓴다.
- **방향 다섯 줄을 새로 짓지 않는다.** Product·Character·World·Moments·Signature는 `PRODUCT.md`와 `DESIGN.md`에서 옮겨 적는다. 문서에 없는 성격이나 상징을 만들어 넣지 않는다.
- **"방향을 보여 주고 멈춘다"는 단계.** 소유자가 이미 맡긴 화면 작업에서는 멈추지 않는다(unslop도 사용자가 그냥 하라고 한 경우 기다리지 않는다고 적었다). 점검 목록과 방향은 해당 변경 문서에 남긴다. 새 시각 방향을 정하는 일은 계속 소유자 결정이다.
- **점검(Audit)은 그대로 쓴다.** [references/signs.md](references/signs.md)의 항목을 화면별로 대조하고, 찾은 항목을 위치와 함께 한 줄씩 적는다. 실제 브라우저 화면(1440·820·390px, 익명 샘플)을 보고 판단한다.

### 단계별 적용

| unslop 단계 | 해도에서 |
| --- | --- |
| 1 간격 | 4px 단위·같은 것은 같은 크기·묶음 간격을 점검 기준으로 쓴다. 조작 영역 44px, 16px 입력, 안전 영역이 unslop의 "탐색 줄 32~36px"보다 우선한다. 값은 기존 토큰을 쓴다. |
| 2 색 | `DESIGN.md`의 표면·틸 조작색을 유지한다. unslop의 중립 색 표를 가져다 쓰지 않는다. 대비는 실제 표면색에서 잰다. |
| 3 아이콘 | 이미 쓰는 Lucide 1.51.0 부분집합(`vendor/lucide/`, `assets/life/icons.js`)과 2026-11-02 결정(선 굵기 1.8, 조작 20px·글 안 16px, 개념마다 그림 하나)을 유지한다. unslop의 16~18px·선 1.5 값으로 바꾸지 않는다. 아이콘 런타임이나 원격 요청을 더하지 않는다. 접근 가능한 이름과 키보드 도움말을 지운 채 아이콘만 남기지 않는다. |
| 4 문구 | 영어 기준 규칙(문장형 대소문자, 끝 마침표, 느낌표)은 뜻만 가져온다. 해도 문구 규칙은 기능어·비유 금지다. 저장 상태 문구처럼 소유자가 정한 문장은 바꾸지 않는다. 없는 수치·주장·반응을 만들지 않는다. |
| 5 글꼴 | Pretendard를 유지한다. unslop의 글꼴 표는 한글을 다루지 않으므로 쓰지 않는다. 굵기·크기 수를 줄이는 점검만 쓴다. 날짜·개수에 고정폭 글꼴을 쓰라는 권고는 따르지 않는다(2026-11-02 시안 점검에서 뺀 항목이다). |
| 6 배치 | 앱 화면의 구획과 순서를 유지한다. 랜딩 히어로 규칙은 로그인 전 공개 화면을 손볼 때만 참고한다. |
| 7 세부 | 반지름·활성 상태·초점 고리·표와 차트 위계 점검을 쓴다. |
| 8 화면 그림 | 생성 이미지를 쓰지 않는다. 해도의 사진은 사용자의 실제 사진이다. 이미지 생성 서비스(MCP 포함) 연결은 외부 전송과 비용이 따르므로 소유자 승인 없이는 제안 단계에서 멈춘다. |
| 9 움직임 | 이유 없는 반복 움직임과 `transition: all`을 걷어 내는 점검을 쓴다. 사용자 행동을 보여 주는 짧은 반응과 `prefers-reduced-motion` 대응은 유지한다. |

### 바꾸지 않는 것

- 원문·버전·발췌 위치, 공개·비공개 경계, 저장과 동기화 경로는 시각 정리 때문에 바꾸지 않는다.
- 검사를 통과시키려고 화면 요소를 숨기거나 단언을 약하게 하지 않는다.
- 화면에 개인 기록을 넣어 점검하지 않는다. 익명 샘플을 쓴다.

## 보고할 때

- "unslop 지침을 참고한 수동 점검"이라고 적는다. 점수나 자동 검사 통과로 표현하지 않는다.
- 찾은 항목, 고친 항목, 일부러 남긴 항목(소유자 결정과 충돌해 따르지 않은 규칙 포함)을 나눠 적는다.
- 눈으로 본 판단과 잰 값(대비·크기)을 구분한다.

## 저작자 표시

unslop 문서를 복사하거나 고쳐 쓴 글에는 "unslop by Damir Sokolovsky (@heydamir), CC BY 4.0"과 원본 저장소 링크를 남기고, 고친 부분을 밝힌다. 원본 파일 끝의 저작자 줄은 지우지 않는다.
