# Workflow 통합·효율화·자동화

2026-10-29 사용자 지시. 이 설계 세션은 **전체 시스템 구조, workflow 통합, 반복 작업의 효율화와 자동화**를 함께 책임진다. [제품 목적](product-purpose.md)을 기준으로 필요→입력→처리→결과→재개의 흐름을 설계하고, 화면·저장·계정·운영 조건·실패 복구·검수까지 실행 세션에 넘긴다. 실제 구현·가동·배포는 각각의 증거로 확인한다.

## 설계 순서와 완료

1. 사용자가 시작하는 이유와 원하는 종료 결과를 정한다.
2. 기존 기능의 입력·결과·정확한 참조를 이어 같은 내용을 다시 고르거나 입력하지 않게 한다.
3. 불필요한 단계·중복 보관·전체 재조회·대기부터 줄인다.
4. 남은 반복 처리는 조건에 맞춰 자동 실행하고, 사용자는 필요한 판단과 예외에 집중한다.
5. 실패·중복·중지·기기 전환 후 같은 결과로 재개되는지 검수한다.

화면이나 기능 하나의 완성만으로 끝내지 않는다. 자동화의 완료는 **실행 조건 충족→실제 처리→결과 보관 확인→다른 기기 재개→중지/복구**까지다. 앱 체류·수집량·기록량을 늘리는 것이 목적이 아니다. 코드로 충분한 반복 처리는 코드로 구현하고, AI는 필요한 설명·비교의 후보를 만드는 데 선택적으로 쓴다.

## Input → automated process → output

| Input·발생 조건 | 자동 처리의 목표 | Output·사용자가 직접 고르는 것 | 현재 상태·재사용 |
| --- | --- | --- | --- |
| 저장한 관심·복수 언어·출처·목록 갱신 옵션 | 허용된 카탈로그 갱신, 필터·순위 재계산, 출처별 직전 성공 보존 | 새 글 후보 목록. 읽기·도움·보관은 별도 행동 | [뉴스 자동화](../design-review/discovery-automation.md) 기존 구현. 개인 설정 계정 연속성은 PR140 인계 |
| 사용자가 켠 원천 연결·예약 조건 | 목록 대조·신규 후보 수집·정확 판/사진 검증·중복 방지 | 확보 범위가 확인된 비공개 자료 | [네이버 운영 계약](../design-review/naver-operational-readiness.md) 재사용. PR143 병합/부분 설치와 실제 가동은 구분 |
| 자료·메모·계획의 명시 저장 | 원자 커밋→영속 전송 대기→계정 전송/수신→충돌·재시도 | 같은 계정의 같은 대상 재개. 충돌 시 양쪽 보존 후 선택 | 자료 Core는 기존 구현. [새 메모](../design-review/reading-decision-journey.md)·[계획](../design-review/planning-practice-review.md)은 확장 설계 |
| 선택 문장·현재 자료·기존 목표/습관 | 정확 참조·문구·대상 문맥 전달, 기존 항목 조회, 중복 작업 재개 | 사용자가 확정한 연결 한 개와 원래 위치 | [통합 동선](../design-review/reading-planning-integration.md) 설계/시연. 새 메모·월 항목 자동 생성 없음 |
| 명시 좋아요·담기·제외·관심 변경 | 해당 신호만 기존 추천 계산에 반영, 취소/제외에 맞춰 다시 계산 | 조정된 후보. 클릭을 읽음/도움으로 승격하지 않음 | 기존 반응·정렬 재사용. 추천 효용과 새 알고리즘은 별도 검증 |
| 현재 대상·선택 기간의 확인 요청 | 선택 범위의 날짜별 체크·현재 진척·근거 대조, 중복 집계 방지 | 읽고 종료 또는 직접 판단·회고 저장 | 기간 회고 설계/시연. 확인 요청은 회고 저장이나 다음 계획 생성이 아님 |
| 온라인 복귀·인증 확인·작업 재개 | 같은 owner/세대의 미완료 작업만 재확인, 필요한 정확 자료만 우선 수신 | 마지막 확정 결과와 실제 대기/충돌 상태 | 기존 계정 coordinator·outbox·정확 판 복구 재사용. 브라우저 종료 중에는 서버 작업만 실행 가능 |
| 사용자가 고른 표현·파일 범위 | 기존 검증·출력 투영·정확 ID 매핑·파일 생성 | 명시 선택한 글·파일. 공개/외부 전달은 별도 선택 | 기존 작성기·백업·공개 계약 재사용. 개인 메모를 자동 게시하지 않음 |

이 표는 목표와 현재 상태를 함께 표시한다. 저장을 누른 뒤 전송·검증을 자동으로 이어가는 일과, 저장할 내용 자체를 시스템이 결정하는 일을 구분한다. 명시 선택을 매 단계 다시 묻지 않고 기존에 저장한 유효 범위와 옵션을 재사용한다.

### 실행 위치와 가동 상태

| 기존 자동화 | 실행 위치·조건 | 중지 범위·현재 한계 |
| --- | --- | --- |
| 자료 기본 계정 보관 | 인증된 브라우저의 저장·전송 대기·재접속 coordinator | 오프라인/종료 중 대기는 보존, 브라우저 실행은 멈춤. 새 기기 수신은 해당 서버 ACK 범위 |
| 개인 뉴스 자동 목록 갱신 | 옵션을 켠 뉴스 화면이 보이고 온라인·인증 확인된 동안 15분 due 확인 | 해당 화면의 요청/타이머 중지. 공용 수집 일정과 별개. 현재 설정은 계정/공간의 로컬 메타이며 계정 연속성은 실행 대상 |
| 공용 뉴스 카탈로그 수집 | 기존 GitHub Actions 일정·main 작업, 개인 화면 종료와 독립 | 개인 갱신 토글이 공용 수집을 중지하지 않음. 일정은 지연/누락 가능, 마지막 성공 결과로 확인 |
| 네이버 원천 수집 | 별도 서버 worker·예약과 사용자가 활성화한 연결 | 구독 중지·서버 준비 관문을 구분. PR143 인계 기록의 ready=false·예약 미설치·실수집 미검증은 당시 관측이며 이번 설계에서 운영을 재조회하거나 가동하지 않음 |

계정에 보관할 새 옵션은 revision/CAS·owner 범위로 갱신하고 구기기의 오래된 옵션으로 중지를 되돌리지 않는다. 공용 작업, 개인 계정, 특정 연결, 현재 화면의 중지를 하나의 전역 off로 합치지 않는다. 정상 계정 보관을 끄고 브라우저만 쓰는 모드를 새로 제공하는 지시도 아니다.

## 자동 실행의 공통 계약

아래는 여러 모듈이 공유할 **의미와 검수 기준**이며 새 범용 작업 엔진을 만드는 지시가 아니다. 현재 Core/계정 coordinator, 도메인 CAS·영속 작업, 기존 worker/예약 기능을 재사용한다.

| 항목 | 구현자가 정할 값·동작 |
| --- | --- |
| 트리거 | 명시 저장/옵션 변경, 인증된 재접속, 유효한 예약 시각 중 해당 도메인에 필요한 것 |
| 입력 범위 | 확인된 owner·공간·정확 대상/판·선택 옵션 revision. 실행 중 범위 변경 시 옛 결과를 새 화면에 적용하지 않음 |
| 같은 작업 | 고정 operationId와 입력 snapshot/해시. 응답 유실은 같은 영수증 확인으로 재개하고 새 ID를 만들지 않음 |
| 실행 위치 | 브라우저 가시 화면/백그라운드 서버를 명시. 브라우저 타이머를 앱 종료 중 예약 실행이라고 표시하지 않음 |
| 자원 우선순위 | 현재 읽기·입력·선택 대상 먼저, 나머지 목록·사진은 제한 동시 실행. 이미 성공한 무관 자료 전체 재수신 금지 |
| 결과 확인 | 로컬 커밋·서버 ACK·정확 바이트 검증·실제 공개/예약 결과를 각 단계의 사실로 판정 |
| 재시도 | 일시 통신/레이트 제한은 기존 대기·backoff/서버 지시를 재사용. 인증·권한·형식·용량·충돌은 이유가 해소될 때 재개. 무한 즉시 반복 금지 |
| 중지 | 새 실행/claim 차단·취소 가능한 요청 중단. 시작 전/진행 중/이미 커밋된 결과를 구분하고 성공 자료를 지우지 않음 |
| 재개 | 같은 작업의 영수증·checkpoint를 확인한 뒤 남은 단계만 진행. 두 탭/worker 중복 처리도 같은 결과로 수렴 |
| 관찰 | 마지막 시도·마지막 성공·다음 조건·처리/대기/실패 개수와 이유. 원문·개인 메모를 실행 로그에 복제하지 않음 |

계정 보관은 기본 동작이고 브라우저는 캐시·전송 대기다. 자료 자동 보관을 수동 전송 옵션으로 되돌리지 않는다. 외부 수집·개인 자동 목록 갱신·선택 AI처럼 사용자가 켜고 끄는 옵션은 서로 독립적이다. 개인 갱신 토글을 껐다고 공용 카탈로그의 서버 예약까지 중단됐다고 표시하지 않는다.

자동화 옵션은 기존 뉴스 설정·원천 연결·계정/보관 관리에 목적별로 둔다. 현재 작업의 실패·재개는 해당 문맥에서 바로 해결한다. 새 최상위 ‘자동화 센터’, 본문 위 작업 현황 카드, 매번 설정 방문을 기본 흐름에 추가하지 않는다.

## 기존 허용 범위에서 자동으로 이어갈 것

- **저장 후 처리:** 전송 버튼을 다시 누르지 않고 해당 계정의 영속 대기를 처리한다. 오프라인에도 마지막 성공/대기와 입력을 보존한다.
- **맥락 전달:** 선택 문장·정확 출처·대상·기간·복귀 위치를 다음 조작에 전달한다. 내용 채택과 대상 선택은 같은 짧은 조작에서 확정한다.
- **정해진 범위의 수집·갱신:** 저장된 출처/관심/언어·활성 옵션을 기준으로 후보를 갱신한다. 설정이 유효한 동안 매 실행마다 같은 입력을 요구하지 않는다.
- **변경 반영:** 명시 반응·자료 변경에 의존하는 목록/계산만 무효화·갱신한다. 최신화가 현재 입력·선택·읽던 정확 판을 바꾸지 않게 한다.
- **실패 복구:** 잠시 끊겼다가 돌아오면 미완료 작업을 같은 ID로 재개한다. 사용자 판단이 필요한 충돌만 비교 화면으로 올린다.

계획 채택·실제 수행 체크·내 판단·회고 확정·공개는 계속 해당 사용자의 행동이다. AI 후보는 근거·확보 범위와 함께 보여 주고 자동으로 사실/개인 판단/성과로 저장하지 않는다. 추후 자동 채택 규칙이 필요해지면 대상·조건·되돌리기·결과 확인까지 별도 기능 계약으로 정의한다.

## 완료를 판단하는 실제 비교

같은 자료·시작·결과에서 반복 입력/대상 재선택, 수동 전송·새로고침, 결과까지의 대기, 실패 후 다시 해야 한 일을 기록한다. 자동으로 한 작업 수보다 **사용자가 직접 관리해야 하는 횟수가 줄었는지**를 확인한다. 새 분석 SDK·상시 개인 행동 추적은 이 비교의 선행 조건이 아니다.

필수 반례는 같은 입력 중복 실행, 처리 성공 후 응답 유실, 중간 단계만 성공, off 직후 늦은 응답, 계정/공간 변경, 구기기·삭제된 대상, 일시 중단 후 재접속이다. 원본·사용자 입력·선택하지 않은 충돌 사본을 보존하고 중복 결과·삭제 부활·다른 계정 노출·허위 완료가 없어야 한다. 실제 scheduler/외부 제공처가 관여하면 앱을 닫은 상태의 실행 근거를 별도로 확인한다.

## 진행 책임과 다음 묶음

설계 세션은 전체 자동화 경로를 먼저 정리하고, 구현 후보가 없어도 트리거·입력/출력·상태·기기/운영 경계·복구를 상세화한다. 실행 세션은 이 계약으로 실제 기능을 연결하고 설치·가동·회귀 검수를 마친다. 총괄은 동일 장면의 전후 비교와 실제 실패 복구를 보고 흐름을 교정한다. 후보 구현을 기다리는 것만을 설계의 다음 작업으로 두지 않는다.

우선 묶음은 **후보 갱신/수집 → 정확 자료 계정 보관 → 선택 메모·대상 연결 → 같은 기기/다른 기기 재개 → 선택 기간 확인**이다. 뉴스 공급·계정 보관·계획은 책임이 다른 도메인으로 유지하면서 사용자 흐름을 통합한다. 최신 순서와 완료 조건은 [로드맵](roadmap.md)을 따른다.
