# 글을 돌아보는 세 관점 — 독립 시제품

2026-10-10. 최신 요청인 ‘개인 원고 완주를 전제로 하지 않는 분석 관점’을 따른다. Local의 홈·탐색·책 통합과 별도로 검토한다. **현재 AI 분석 기능이나 실제 책 저장 기능이 아니다.** 글과 해석은 개발 중 Codex가 구성한 고정 예시다. 앱이 입력 자료를 분석해 생성한 결과가 아니다.

## 이번 사용 목표

같은 익명 글을 관심·질문·변화로 읽는다 → 해석의 정확한 근거 원문을 확인한다 → 다른 설명을 고려한다 → 내 해석을 직접 적는다 → 남길 후보만 파일로 받는다.

본 앱의 저장·동기화·백업·공개 계약과 화면에는 변경이 없다. 기본 스타일·승인 A 인용 아이콘만 재사용한다. 시제품은 메모리만 사용하며 파일을 받지 않고 탭을 닫거나 새로고침하면 입력이 사라진다. 나가기 경고는 브라우저가 허용하는 보조 수단이며 영속 저장이 아니다.

## 관점별 판정

| 관점 | 살펴볼 차이 | 근거 요구 | 결론으로 만들지 않을 것 |
|---|---|---|---|
| 관심의 궤적 | 무엇을 좋아하며 이유가 어떻게 표현되는가 | 다른 시기의 직접 쓴 표현, 당시 맥락 | 많이 쓴 주제=더 중요한 취향, 빈 기간=관심 없음 |
| 계속 돌아온 질문 | 같은 질문인지, 상황이 달라 질문도 달라졌는지 | 반복 표현과 서로 다른 맥락을 함께 제시 | 유사한 단어만으로 고민이 같다고 단정 |
| 생각이 달라진 지점 | 같은 대상에 대한 판단·선택 기준의 차이 | 날짜가 있는 전후 표현, 반대 방향의 구절 | 성장 순위·성격 진단, 계획=실행, 추정=사실 |

현재 범위를 줄였을 때 필요한 근거가 빠지면 해당 예시를 감춘다. 실제 분석기는 아직 없으므로 좁힌 기간에 맞는 새 결론을 생성하지 않는다. 자료 15건/본문 버전 16개 중 현재 직접 쓴 글 13개를 범위로 삼는다. 이전 버전 1개와 타인 글 2개(본문 없는 링크 포함)는 제외한다. 날짜 미확인 1개는 전체 범위에 남기되 변화 근거로 사용할 수 없다. 서로 다른 주제를 한 질문으로 묶은 예시는 그 연결을 거절해 볼 수 있도록 의도적으로 포함했다.

## 제안·근거·사용자 해석 계약

- `proposal.origin=authored_example`, `templateVersion`: 사전 작성한 예시의 출처. 실제 모델 이름을 만들어 넣지 않는다.
- `scope`: 후보를 담은 시점의 기간과 정확한 version ID 목록. 이후 필터 변경이 이미 담은 후보를 바꾸지 않는다.
- `evidence`: `sourceId`, 정확한 `versionId`, UTF-16 `[start,end)`, 원문 `text`, 작성 관계·확보 범위·날짜·역할 `support/counter`.
- 인용 문자열과 원문 범위가 일치해야 한다. 이모지를 포함해 정규화·위치 추정을 하지 않는다. 버전 누락, 범위 밖 자료, 타인 글, 본문 없음, 잘못된 역할·인용은 담기 거절이다.
- `userInterpretation`: 사용자가 직접 적은 별도 문자열. 예시 해석을 자동으로 ‘내 생각’에 넣지 않는다. 최대 20,000 UTF-16 code units. 빈 입력과 초과 입력은 거절하고 입력을 유지한다.
- 보류는 이 예시 해석만 접고 담은 후보에서도 뺀다. 원문 삭제·전역 분석 제외가 아니다. 다시 열면 입력이 남는다.
- 출력 형식 `haedo-analysis-candidates-prototype-v1`은 검토용 JSON/Markdown이다. `synthetic=true`, `modelUsed=null`과 예시·내 해석·반대 근거를 보존한다. **현재 책·자료 백업으로 가져올 수 있는 형식이 아니다.**

이 검증기는 구조와 정확 인용을 확인한다. 인용이 정확하다고 해석도 맞는 것은 아니다. 현재 고정 예시용 계약이며 외부 AI 응답의 신뢰 경계 검증기로 재사용하면 안 된다. 실제 연결 시 타입·크기·중복 ID·모델/실행 정보·취소/오래된 응답·수정 이력을 별도로 설계한다.

## 평가 자료와 합격 기준

기술 검증과 의미 평가를 분리한다. 이번 자동 검사는 기술 검증이다. 실제 모델의 정확도 점수로 보고하지 않는다.

| 사례 | 실패 판정 | 현재 확인 방법 |
|---|---|---|
| 바뀐 메모의 이전 버전 v08-old | 과거의 강한 단정을 현재 생각으로 사용 | 최신 범위에서 제외, v08 반대 근거와 정확 버전 출력 검사 |
| 저장한 타인의 문장 v11 | 사용자의 신념으로 인용 | 작성 관계 검사로 거절 |
| URL만 있는 v13 | 본문을 읽은 것으로 표시 | 본문 없는 근거 거절 |
| 날짜 미확인 v12 | 임의 연도·변화 순서를 부여 | 변화 관점 거절 |
| 이모지 뒤 문장 v05 | 한 글자 밀린 인용 | UTF-16 정확 slice 검사 |
| 계획 v14, 추정 표현 v15 | 행동 변화·성취 사실로 확정 | 자료와 예시의 수동 의미 검토; 자동 진위 판별 아님 |
| 빈 기간 / 좁힌 기간 | 증거 없는 결론 재사용 | 근거 부족 상태와 원래 범위 복귀 |
| 상반된 현재 문장 v08 | ‘인정 욕구를 버렸다’만 제시 | 반대 방향 근거를 결과와 파일에 유지 |
| 책 취향과 휴식 | 비슷한 단어로 단일 문제라고 단정 | ‘묶지 않는 편이 정확할 수 있음’과 보류 기능 |

후속 실제 분석 평가에서는 모든 제안에 대해 **근거 일치 / 작성자 귀속 / 시간 해석 / 다른 설명 / 과도한 단정 / 사용자가 남길 가치**를 각각 판정한다. 잘못된 작성자·버전·인용·사실 단정은 건별 실패로 남기고 평균 점수로 숨기지 않는다. 작은 익명 자료에서 검증한 뒤 사용자 선택 자료의 로컬 미리보기로 확장한다. 실제 개인 자료와 외부 AI 전송은 이번 작업에 포함하지 않았다.

## 후속 우선순위

1. 이 시제품으로 세 관점의 유용성·정보 밀도 판단. 실제 개인 글 없이도 후보를 남길 수 있는지 체험한다.
2. Local 통합 완료 후 실제 회고의 **명시적으로 선택한 자료**에 대한 읽기 전용 근거 목록·관점 선택 연결. 기존 저장 경계를 먼저 확인한다.
3. 후보를 실제 책으로 명시 저장하는 어댑터와 계정/작업공간·충돌/복원 계약. 임시 후보를 기존 백업에 슬쩍 추가하지 않는다.
4. 필요성이 확인된 분석만 실제 실행기로 비교한다. 외부 AI 전송 여부·범위 선택은 별도다.
5. 나머지 세 관점과 정밀 조판은 위 체험 결과 뒤에 정한다. 개인 원고 완주는 전제 조건이 아니다.
