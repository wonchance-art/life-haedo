# 제품 안의 AI: 대화·자료·제안·자동화 설계

2026-10-05 후속: 최신 제품 방향은 [활동 통합·내 페이지](lifestyle-blog.md)다. SNS는 가져오기 전용이며 원본 SNS에 게시·수정·삭제하지 않는다. AI는 활동 연결 후보·발견·회고를 돕고 사용자가 고른 결과만 공유용 초안으로 편집한다. 수집한 자료·분석에 허용한 자료·공개 사본은 서로 다르며, 공개 페이지의 활동량으로 개인의 성장이나 생활을 평가하지 않는다. 아래는 설계이고 모델 호출·자동 수집·공개 블로그가 구현됐다는 뜻은 아니다.

기준: 2026-10-03 당시 사용자 방향인 기존 자료의 추출·통합을 우선한 설계다. 모델 설치·외부 호출·예약 실행·기능 구현 결과가 아니다.
근거는 [현재 필요](../current.md), [참조 설계](../design.md), [인계](../handoff.md)이며 구체 계약은 [데이터 설계](data-model.md)를 따른다.

## 1. 목표와 기본 선택

R1은 Apple 메모·Obsidian·네이버 블로그·인스타그램에서 사용자가 선택해 제공한 자료를 iPad Chrome에서 가져와 보존·검토·통합하는 흐름이다.
`원문 가져오기 → 결정적 추출/수동 발췌 → 후보 검토 → 통합 → 출처 확인·재개·내보내기`는 AI 없이 완료한다. 의미 추출·관점 연결·대화는 [로드맵 R4](roadmap.md)의 후속 선택 보조다.
R1 입력은 UTF-8 텍스트·Markdown 파일, 선택 본문 붙여넣기·URL 등록부터 제안한다. 네 서비스의 자동 연동·계정 접근·전용 내보내기 전체 형식을 보장하지 않으며 실제 확보 가능한 형식은 [기술 설계](architecture.md)의 조사·검증 범위다.
기본 동작은 선택 자료의 로컬 가져오기다. 원문 확보·저장, 페이지·문제 수 등 숫자 수정은 AI 호출·계정·비용 잔액과 독립이다.
후속 AI 기능에서 사용자가 `의미 추출`, `대화`, `생각 연결`을 선택할 때만 해당 범위의 요청을 만든다. AI는 사용자가 판단하고 자료를 다시 활용할 수 있으면 종료한다.
자동 후속 질문·매일 대화 알림·무한 추천 피드는 기본값에 넣지 않는다. 새 사용자도 이전 기록 없이 질문 하나로 시작한다.
개발 팀 총괄 1명과 전문 담당 6명은 이번 설계 작업의 인원이다. 제품 안에 7개 AI가 상시 실행된다는 뜻이 아니다.

| 기능 | 일반 코드의 책임 | 선택적 AI의 책임 |
| --- | --- | --- |
| 가져오기 | 받은 원문 보존, 형식·누락 표시, 문단·화자 경계 확인 | 불명확한 의미·관계의 후보 제시 |
| 기록 | 수동 발췌·규칙 추출, 검토, 저장, 충돌 확인, 되돌리기 | 원문에서 주장·생각·경험·질문 후보 추출 |
| 자료 | 자료 선택, 접근권한, 불변 버전·위치, 출처 열기 | 선택한 범위 설명·비교·질문 연결 |
| 생각 | 작성자·시점·버전·연결 보존 | 전제·반례·관점 변화의 후보 제시 |
| 실행 | 허용 범위 확인, 중복 방지, 상태 조회 | 작업 초안과 필요한 조건 설명 |

## 2. 한 페이지에서 이어지는 실제 흐름

### R1: 기존 자료에서 생각을 꺼내 통합하기

1. iPad Chrome에서 `자료 가져오기`를 열고 사용자가 선택한 메모 본문, Markdown 파일, 게시물 텍스트 또는 URL을 제공한다. 계정 전체 접근은 요구하지 않는다.
2. `원문 확인`에서 받은 내용·형식·누락을 확인한다. URL만 받았다면 `본문 미확보`로 보관하며 자동 접속하거나 본문을 읽었다고 표시하지 않는다.
3. 원문은 SourceVersion에 변경 없이 보존하고 ImportSession(stageId)에 원문·후보·검토 상태를 둔다. `나중에 계속`으로 중단하고 같은 검토 위치를 재개한다.
4. 원문 구절을 선택해 `발췌 추가`하거나 규칙으로 나눈 문단을 검토한다. R1 규칙은 구절·문단·명시된 링크를 추출하며 의미를 판정하지 않는다. 사용자가 붙인 `주장`, `생각`, `경험`, `질문`도 검토할 후보로 원문 위치·화자·시점과 함께 보여준다.
5. `후보 검토`에서 유형·인용 경계·날짜·작성자를 확인하거나 `모름`으로 남긴다. 같은 경험·중복·사실·완료·계획 여부는 자동 확정하지 않는다.
6. `통합 확인`에서 채택 후보와 기존 기록의 차이를 본 뒤 선택한 변경을 원자적으로 저장한다. 보류·제외 후보와 원문을 지우거나 모두 한 요약으로 대체하지 않는다.
7. `출처 보기`에서 받은 원문 버전의 정확한 구절로 돌아간다. 닫고 다시 열어 검토를 이어가며 원문·출처·채택 결과를 재사용 가능한 형식으로 내보낸다.

전체 글을 분류할 의무는 없다. 자료만 보관하거나 구절 두 개를 주제에 연결해 끝낼 수 있다. 원문 포함 백업·사본 복원은 읽기용 텍스트/Markdown 내보내기와 구분한다.

### 후속: 의미 추출과 깊은 대화

R4의 `의미 추출`은 선택 구절에서 주장·생각·경험·질문과 관계를 해석해 후보로 만드는 기능이다. 별도 소규모 실험은 일찍 비교할 수 있으나 R1 완료의 의존성은 아니다. `자료 선택`에 `사용할 자료: 메모 발췌 2개`와 실제 범위를 표시한다.
외부 AI를 쓰는 경우 허용된 제공처·선택 범위·시점에서만 전송한다. 가져오기나 원문 저장을 외부 전송 동의로 해석하지 않는다.
`질문 보내기` 후 설명은 선택한 원문에 연결한다. `생각 연결`은 이전 구절·작성 시점·현재 관점과의 관계를 후보로 보여준다.
`통합 확인`에서 수락한 내용만 반영한다. 원문의 과거 주장과 현재 결론이 상충해도 둘을 보존하고 `관점 변화`로 연결할 수 있다.
사용자의 반응에 따라 질문·자료 범위를 조정한다. 대화 결과를 기록·공개하지 않고 끝내도 된다. 응답 중 원문 저장·숫자 입력은 계속 가능하다.
기존 글의 `빛이 약했다`는 원저자의 관찰이고 AI의 `집중을 유도했을 수 있다`는 추정이다. 가져온 글이 항상 사용자 경험인 것은 아니다.

### 관계와 약속

사용자가 선택한 공동 경험과 상대가 제공한 관심만으로 `대화 소재 만들기`를 실행한다. 상대의 내면·성향을 확정하지 않는다.
공통 관심과 서로 다른 관심의 접점을 후보로 보여주고, 각 사람과의 연결 이유·실제 인용·출처·AI가 작성한 초안을 구분한다. 알려진 공유 이력이 없으면 이미 전달했는지 추정하지 않는다.
출력은 `말 걸기 초안`이며 메시지 전송과 별도다. 외부 전송이 나중에 구현되면 수신자·본문·첨부 버전이 허용 범위에 포함된다.
개인 기록에서 만든 초안도 공개 가능하다고 간주하지 않는다. 공유 화면에서 공개할 필드와 대상만 별도로 선택한다.

## 3. 요청·자료·출력 계약

논리 계약이며 독립 서버·테이블 수를 뜻하지 않는다. 데이터 담당의 공통 참조·저장 계약을 따른다.

| 항목 | 설계 계약 |
| --- | --- |
| 요청 맥락 | `runId`, `workspaceId`, `stageId?`, 대상·활동 참조, 질문, 선택한 답변 방식, 요청 시각 |
| 원천 정체성 | Source는 원천 문서 정체성, SourceVersion은 실제 받은 본문·형식·coverage의 불변 스냅샷 |
| 원문 근거 | `sourceRefs:[{sourceId, sourceVersionId, locator}]`; locator는 해당 contentText의 UTF-16 `[start,end)`이며 원문을 변형하지 않음 |
| 작업·적용 참조 | `entityRefs:[{workspaceId, entityType, entityId, revision}]`; 원문 sourceRefs와 별도로 선택한 기존 기록·생각의 현재 버전을 확인 |
| 전송 범위 | 선택 필드·발췌 범위·필요한 대화 턴의 스냅샷, 공급자/실행 위치, 적용한 권한 버전 |
| 출처·시점 | 제목, 원저자, URL/내부 참조, `originalCreatedAt?`, `originalUpdatedAt?`, `importedAt`; 원문 시각 미상은 가져온 시각으로 대체하지 않음 |
| 원문 구간 | segments의 `speakerRole=user\|assistant\|quote\|unknown`; 화자·인용자·원저자는 확인된 근거로 구별하고 불명은 unknown |
| 후보 | `proposalId`, `runId?`, `reviewStatus=proposed\|confirmed`, 유형, `sourceRefs`, 변경 후보, 추론 여부, `baseRevision`; 수동·규칙 추출에도 검토 적용 |
| 생성 이력 | `provenance{kind:user\|imported\|ai, actorId?, modelRunId?}`; 사용자가 적용해도 AI 기원은 유지 |
| 적용 | `Storage.commitLocal({operationId, workspaceId, baseRevision, changes})`; 각 수정 항목에 `expectedRevision` 포함 |

ImportSession(stageId)는 원문·후보·검토의 staging이다. 검토 완료한 묶음만 위 저장 계약으로 통합하며 중단·실패 후 검토 상태를 복원한다.
SourceVersion이 새로 들어와도 기존 sourceRefs를 새 버전으로 자동 이동하지 않는다. 글이 수정되거나 URL이 사라져도 받은 버전의 근거를 추적한다.
제목·URL·발췌·본문의 확보 수준을 구분한다. 잘린 본문·생략된 댓글·이미지 미지원은 coverage로 표시하고 사진 속 글을 읽은 것으로 처리하지 않는다.
원문의 명령·과거 사용자 요청·assistant 제안은 자료다. 외부 URL 추가 수집·AI 전송·과거 작업 실행 권한이 아니다.
최초 선택 범위에서 추가 자료가 필요하면 `자료 추가`를 제시한다. 관련 있어 보인다는 이유로 비공개 기록 전체를 전송하지 않는다.
긴 대화는 전송할 요약과 포함할 턴을 확인할 수 있게 한다. 요약에도 원래 턴의 참조를 남기고 생략으로 생긴 불확실성을 표시한다.
다른 대상 화면으로 이동해도 진행 중 요청은 원래 대상에 귀속한다. 완료 응답이 새 대상의 기록에 붙지 않는다.

## 4. 근거를 읽을 수 있는 답변

| 표시 | 의미 | 최소 조건 |
| --- | --- | --- |
| `직접 인용` | 확보한 원문 그대로 | sourceVersionId·locator로 문자열 대조; 생략·번역은 별도 표시 |
| `요약` | 확보한 내용을 줄여 표현 | 원문 범위 연결, 원저자 말처럼 따옴표 처리하지 않음 |
| `내 기록` | 작성자가 확인된 사용자의 생각·경험 | 작성 시점과 원문 연결; 가져온 자료 전체를 내 경험으로 표시하지 않음 |
| `추정` | 자료만으로 확정되지 않은 해석 | 추정의 근거와 확인할 조건을 짧게 표시 |
| `출처 미확인` | 검증 가능한 근거를 확보하지 못함 | 인용·사실 확인 완료로 표시하지 않고 확인 방법 제공 |

후보마다 SourceVersion의 locator와 근거 인용을 갖춘다. AI가 내놓은 출처 ID는 실제 선택 목록에 있는지 코드로 확인하고 존재하지 않는 위치·인용문은 인용 표시를 차단한다.
user 발언·assistant 출력·인용·원저자를 보존한다. assistant의 조언은 사용자의 경험·현재 결정으로 바꾸지 않고 `과거 제안`으로 남긴다.
`검토 확인`은 사용자가 후보의 분류·반영을 확인했다는 뜻이며 원저자의 주장 자체가 객관적 사실로 검증됐다는 뜻은 아니다.
이 검사는 주장 전체의 진실을 보증하지 않는다. 원문 대조와 사용자의 해석 판단을 구분하며, 임의 신뢰도 백분율은 표시하지 않는다.
발췌 두 문단만 읽었다면 `선택한 발췌 기준`이라고 답한다. 저작권·접근 범위가 허용하지 않는 본문 전체 수집은 전제하지 않는다.
자료를 불러오지 못하면 확보한 범위와 빠진 범위를 표시한다. 없는 자료를 생성해 출처로 저장하지 않는다.

## 5. 과거 생각·추천·메타인지

`이전 생각 연결`은 사용자가 허용한 기록 범위 안에서 후보를 찾는다. 최초 검색은 로컬 메타데이터·텍스트 검색으로도 가능하다.
후보에는 원문 날짜와 가져온 날짜, 짧은 원문, 현재 질문과의 관계, `비슷한 생각` 또는 `달라진 생각`의 이유를 붙인다.
같은 문장·유사 제목·같은 날짜는 중복 후보의 단서다. 동일 경험으로 병합하거나 서로 다른 관점을 최신 문장 하나로 덮는 근거가 아니다.
일시적 발언으로 정체성·취향을 고정하지 않는다. 사용자는 `이 연결 제외`, `이번 대화에만 사용`, `연결 저장`을 선택한다.
기록이 없으면 연결을 꾸미지 않고 현재 질문과 선택 자료로 대화를 계속한다.

`같은 저자·출판사`는 서지정보 탐색이다. `질문에 맞는 자료`는 현재 질문과의 관계를 설명하는 추천이다.
추천은 기본 3개 이내로 끝내고, 이미 가진 자료를 먼저 살펴본다. 새 구매·외부 사이트 이동을 필수 단계로 만들지 않는다.
각 추천에는 질문과 연결되는 이유, 근거가 된 자료 범위, 보유 여부, 읽을 부분, 확보하지 못한 정보가 붙는다.
외부 검색은 별도로 활성화한 제공처·범위에서만 수행한다. 검색 결과 제목만 본 자료는 `본문 미확인`이다.

메타인지 도움은 `검토하기`에서 사용하거나 답변의 판단에 꼭 필요한 한 가지에 한정한다.
예: `이 두 글은 같은 주제를 다루지만 결론이 다릅니다. 생각이 바뀐 것인지 상황이 달랐던 것인지 원문과 함께 확인할 수 있어요.`
전제, 다른 해석, 작은 실험, 추가 부담 중 적절한 것을 고른다. 모든 답변에 반론·추천·공유 제안을 덧붙이지 않는다.
철학은 개념·논증, 언어는 목적·수준·뉘앙스, 예술은 관찰·맥락, 기술은 제약·재현 조건을 우선한다.
`도움 됨`, `관련 없음`, `제안 줄이기`는 사용자 선택의 피드백이다. 세션 길이·생산량을 성공 지표로 대체하지 않는다.

## 6. 제안을 기록에 적용하기

기록의 확정과 대화 완료는 별개다. 원문 `다음 주 읽어보자`는 과거 시점의 계획 후보이며 현재 일정·완료 기록을 자동 생성하지 않는다.
`통합 확인`은 원래 값, 후보 값, 대상·활동·날짜·화자, 근거 인용, 추론한 필드를 보여준다. 불명확한 날짜·숫자·사실·수행 상태는 미확정으로 남긴다.
R1에서 사용자는 후보를 선택·수정·제외하거나 통합을 보류한다. 후속 AI 결과도 같은 검토 경로를 거치며 원문을 덮어쓰지 않는다.
사용자가 선택한 변경은 일반 저장 경로에서 검증하고 변경 묶음을 로컬에서 원자적으로 저장한다. `stored` 영수증을 보존해 같은 operationId의 성공한 적용은 한 번만 처리한다.
baseRevision이 바뀌면 영향을 받은 항목을 대조한다. 사용자가 수정한 최신 값을 덮지 않고 `내용이 바뀌었습니다`와 비교를 보여준다.
독립된 항목으로 안전하게 재구성할 수 있으면 새 제안을 만들고, 충돌 항목은 사용자가 결정한다. 기준·내용 변경 시 새 operationId를 사용하며 새 버전에 옛 허용을 재사용하지 않는다.
적용 후 `되돌리기`는 새 operationId의 복구 작업이며 `적용 내역`에서도 찾는다. 그 뒤 다른 수정이 있으면 복구 후보를 비교하며 이후 변경을 지우지 않는다.
AI 응답 실패·취소·시간 초과는 이미 저장된 기록을 되돌리지 않는다. `질문 다시 보내기`는 저장 작업을 반복하지 않는다.
단순 요청 취소 후 늦게 도착한 응답은 자동 적용하지 않고 현재 권한이 유효한 경우만 사용자가 열 수 있다. 자료 삭제·권한 철회로 취소된 응답은 아래 정책에 따라 폐기한다.

## 7. 데이터 선택·전송·보존·공유

로컬 보관, AI 제공처 전송, 사람에게 공유는 별도 범위다. 특정인 공유 권한이 AI 전송 허용을 뜻하지 않는다.
R1 가져오기·원문 저장·규칙 추출에는 외부 AI 전송이 없다. 후속 AI의 전송 범위는 현재 질문과 사용자가 선택한 최소 발췌이며, 승인된 시점의 버전·범위로 고정한다.
전체 가져오기 묶음·생활 기록·친구 목록·기기 백업·자격증명은 요청 맥락에 자동 포함하지 않는다. 선택한 원문에서 외부 URL을 발견해도 추가로 수집·전송하지 않는다.
외부 AI 첫 사용에는 제공처, 전송 항목, 보존 조건, 예상 비용 범위를 확인할 수 있어야 한다. 같은 허용 범위는 반복 확인하지 않는다.
선택 범위·제공처·보존 조건이 달라지면 바뀐 부분을 제시한다. 제공처 보존 조건이 확인되지 않으면 외부 전송 활성화를 보류한다.
초기 설계 기본값은 대화의 기기 내 비공개 보관이며 `대화 저장 안 함`을 제공한다. AI 대화를 기존 charts 동기화에 자동 편입하지 않는다.
저장하지 않는 대화는 현재 세션에서만 유지하고 종료 시 제거한다. 사용자가 별도로 저장한 생각·제안 적용 기록은 독립된 기록이다.
외부 제공처 보존은 앱의 삭제 기능과 동일하지 않다. 실제 삭제 지원·기간·학습 사용 여부를 공급자 선택 시 확인하고 화면에 사실대로 표시한다.
감사 기록은 요청 ID·자료 참조·전송 범위·실행 상태 중심으로 남기며 원문 전체·비밀값을 로그에 복제하지 않는다.
원문 삭제·권한 철회 시 tombstone과 파생 인덱스 무효화를 같은 로컬 트랜잭션으로 기록한다. 요약·추천·진행 요청에서도 해당 자료를 제외한다.
이미 전송한 요청의 응답도 권한을 다시 검사한다. 철회된 자료를 포함하면 표시·기록 적용·공유에 사용하지 않고 폐기한다.
로컬 삭제 완료와 외부 삭제 처리는 구분하며 외부 확인 전에는 `pending_revocation`으로 남긴다. 이미 받은 사람의 사본 회수는 보장하지 않는다.
공유는 데이터 설계의 ShareSnapshot 계약을 따른다. 원문 근거는 `sourceRefs[{sourceId,sourceVersionId,locator}]`, 공개 대상의 고정 버전은 별도 `entityRefs[{entityType,entityId,revision}]`로 구별한다.
공유본은 승인한 스냅샷만 담고 대화·관련 기록·내부 출처 링크를 자동 따라가지 않는다. 공개 출처도 공개 가능한 필드만 담는다.
원본 수정은 기존 공유본을 조용히 갱신하지 않는다. `공유본 업데이트`에서 바뀐 내용과 대상을 검토한다.

## 8. 자동화의 허용 범위와 실행 상태

R1은 원문 가져오기·검토·선택한 로컬 통합이다. AI 대화·제안은 후속 선택 기능이며 예약·외부 실행은 필요와 실행 환경을 검증한 뒤 별도 단계로 도입한다.
허용 단위는 `주체 + 대상/수신자 + 작업 종류 + 정확한 내용 버전 + 사용 자료 범위 + 기간/횟수/비용 한도 + 권한 버전`이다.
사용자가 이미 허용한 범위 안에서는 계속 진행한다. 외부 실행 내용·수신자·공개 범위·버전이 달라지면 새 허용이 필요하다.
단순 조회에는 기록 저장·후속 발송이 따라붙지 않는다. 반복 자동화는 종료 시각·최대 횟수와 `일시 중지`를 갖추고 기본 꺼짐이다.
예약마다 변하는 내용은 허용한 템플릿·필드·조건을 고정한다. 그 범위를 벗어난 생성 결과는 `검토 필요`로 멈춘다.
네트워크 대기 중에도 기록은 먼저 보존한다. 보류된 작업은 저장 성공 후 보류 사유와 사용자가 할 다음 행동을 표시한다.

| 상태 / 화면 문구 | 의미와 다음 행동 |
| --- | --- |
| 초안 / `통합 확인` | 후보·제안 작성 완료. 실행 효과 없음. 선택한 범위로 허용을 기록 |
| 대기 / `실행 대기` | 허용·조건을 확보. 실행 직전에 최신 권한·내용 버전·한도를 다시 확인 |
| 보류 / `연결 후 다시 시도`·`권한 확인 필요` | 조건 미충족. 원본 기록 보존. 조건이 복구되면 여전히 유효한 허용만 재개 |
| 실행 중 / `처리 중` | operationId와 외부 요청 ID를 보존. 실행 점유로 여러 기기 중복 실행 방지 |
| 성공 / `완료` | 로컬 저장 결과 또는 외부의 확정 증거를 확보. 응답 문장만으로 성공 처리하지 않음 |
| 실패 / `실행되지 않음` | 실패와 미실행이 확인됨. 실패 단계만 같은 operationId로 재시도 가능 |
| 결과 불명 / `결과 확인 필요` | 전송 후 응답 유실·시간 초과. 재전송 보류, 외부 상태 조회·대조 우선 |
| 취소 요청 / `취소 확인 중` | 요청만 접수. 이미 진행 중인 외부 작업의 취소 완료를 의미하지 않음 |
| 취소 완료 / `취소됨` | 미실행 또는 외부 취소 증거 확보. 이미 완료됐다면 성공 상태와 복구 경로 표시 |
| 복구 필요 / `되돌리기 확인` | 외부 삭제·수정 등 보상 작업 후보. 역작업 가능성과 새 허용 범위를 확인 |

결과 불명은 외부 조회로 성공·미실행·취소를 확인한 뒤 전이한다. 확인 수단이 없으면 불명을 유지하고 중복 위험을 설명한다.
중복 방지 키를 제공하는 외부 API는 동일 키로 조회·재시도한다. 제공하지 않으면 시간 초과를 자동 재시도 조건으로 쓰지 않는다.
권한 철회는 대기·새 실행을 막고 실행 중 작업에 가능한 취소를 요청한다. 이미 발생한 효과는 상태를 대조한 뒤 따로 복구한다.
새로고침·앱 종료·다른 기기 재개는 작업 상태를 복원한다. 내부 기록 저장 대조와 외부 실행 결과 대조는 각각 수행한다.
부분 성공 시 완료한 단계는 반복하지 않는다. 복구는 원래 실행의 반대 효과를 보장하지 않으며 불가능한 외부 회수는 명시한다.
이 실행 점유·중복 방지·결과 대조는 미래 외부 자동화의 도입 조건이다. 현재 앱의 큐가 이미 보장한다고 가정하지 않는다.

## 9. 구성 선택과 보류할 사항

R1은 원문 보존·수동 발췌·결정적 규칙 추출을 우선한다. 첫 후속 AI 구현 후보는 일반 저장·권한 계층 위의 단일 요청 어댑터와 출력 검증기다.
상시 다중 에이전트는 비용·지연·권한 추적 부담이 늘어 초기 기본값으로 채택하지 않는다. 독립 검토의 이득을 실측한 작업만 분리한다.
유료 API·특정 제공처·벡터 DB·상시 서버는 원문 확보·통합의 필수 조건이 아니다. AI를 연결하지 않아도 R1을 끝까지 사용할 수 있어야 한다.
공급자 비교 기준은 한국어 대화 품질, 인용 충실도, 문맥 길이, 지연, 비용 상한, 데이터 보존·삭제, 배포 위치, 취소·장애 대응이다.
기기 내 모델은 전송을 줄일 수 있으나 실제 iPad Chrome의 성능·메모리·다운로드·인용 품질을 검증해야 한다. 외부 모델은 키 보관·중계·보존 계약을 검증해야 한다.
공개 정적 앱에 공급자 비밀키를 심지 않는다. 구체적 중계·사용자 연결 방식은 AI 도입 단계에서 결정한다.
모델명·공급자·요금제·보존 기간·외부 검색 계약·예약 실행 환경은 보류한다. 결정 전 익명 과제 묶음으로 품질·비용·삭제 경로를 비교한다.
어댑터 교체 시 자료 선택·제안·출처·적용 계약을 유지한다. 모델을 바꿔도 기존 사용자 기록의 의미나 소유권은 바뀌지 않는다.

## 10. 수용 기준과 다른 영역의 의존성

1. R1: AI 미연결 상태에서 선택 원문 가져오기 → 보존 → 발췌/규칙 추출 → 검토 → 통합 → 닫기·재개 → 내보내기를 완료한다. 숫자 수정·저장도 계속 가능하다.
2. R1: URL만 제공, 잘린 본문, 이미지 미지원 사례에서 확보 범위를 표시하고 없는 인용·내용을 만들지 않는다. 네 서비스별 형식 지원은 실제 샘플 검사 결과로만 보고한다.
3. R1: 모든 채택 후보에서 sourceVersionId·locator의 정확한 인용을 연다. 원문 수정본을 가져와도 이전 후보의 근거는 이전 버전에 남는다.
4. R1: user/assistant/인용/원저자, 원문 시각/가져온 시각, 과거 계획/현재 결정, 추론/확인을 구분한다. 중복·동일 경험·완료·상충 관점을 자동 확정·병합하지 않는다.
5. R1: staging 중 앱 전환·닫기 후 원문·후보·검토 위치를 복원한다. 통합 시 충돌은 대조하며 중복 클릭·재개는 한 번만 반영하고 이후 편집을 보존해 되돌린다.
6. R1: 원문에 과거 명령이나 URL이 있어도 실행·추가 수집·전송하지 않는다. 내보낸 원문·출처·검토 결과를 다시 읽고 출처를 추적할 수 있다.
7. 후속 AI: 선택하지 않은 자료는 전송하지 않는다. 요청의 실제 본문·버전·범위를 익명 샘플로 대조하고 검토되지 않은 제안을 자동 적용하지 않는다.
8. 후속 AI/공유: 삭제·권한 철회 후 응답·추천·검색에 철회 자료를 노출하지 않는다. 공개 필드만 공유하며 원본 수정으로 승인된 공유본을 자동 갱신하지 않는다.
9. 후속 외부 실행: 응답 유실은 결과 불명으로 유지하고 자동 재전송하지 않는다. 취소 요청 직후 성공 응답을 취소 완료로 오인하지 않는다.
10. 실제 iPad Chrome에서 세로·가로·분할 화면, 터치 발췌·한글 입력·화면 키보드·앱 복귀를 확인한다. 데스크톱 모사를 실제 기기 검사로 보고하지 않는다.

데이터 담당과 SourceVersion·locator·stageId·revision·operationId·공유·철회 계약을 맞춘다. 경험 담당은 `원문 확인`·`후보 검토`·`통합 확인`·`출처 보기`를 연결한다.
기술 담당은 네 서비스의 실제 제공 형식과 원문 보존·내보내기 경로를 조사하고, AI 독립 저장과 공급자 교체 경계를 보존한다. 후속 분야 도구에서는 확정 재개 위치와 탐색 cursor·완료 여부를 구별한다.
수용 기준은 향후 구현 검증 항목이다. 이번 산출물은 설계 문서이며 기존 앱의 통과 검사로 새 AI 기능의 동작을 증명하지 않는다.
