# 화면과 사용 흐름 — 기존 기록을 가져와 다시 읽기

2026-10-05 후속: 최신 흐름은 **분산 활동 가져오기 → 개인 보관·연결·활용 → 선택 편집 → 내 페이지·공유 모음**이며 [통합 시안](../design-review/activity-hub.md)에서 볼 수 있다. SNS 원본 게시·수정·삭제는 제외한다. 기존 기록·도구·관리 안에서 내 페이지를 열고 대표 글/모음과 선택한 최근 활동을 구성한다. 소개·배치·공개 초안의 부분 선택과 방문자 미리보기는 독립 시안에만 있으며 아직 운영 기능이 아니다. 아래 R1은 이전 사용 흐름의 이력이다.

기준: 2026-10-03. 최신 사용자 요청으로 첫 사용과 R1의 중심을 교체한 설계다. 새 기능·실기 검증 완료를 뜻하지 않는다.
확인된 제약은 [작업 지침](../../AGENTS.md), 공통 구조는 [통합 설계](README.md), 단계는 [로드맵](roadmap.md)을 따른다.
첫 원천은 **Apple 메모·Obsidian·네이버 블로그·Instagram**, 사용 환경은 **Mac·iPad·iPhone**이다. iPad Chrome은 기존 확인 환경이며 Mac과 iPhone의 브라우저 버전은 실기 검증 때 기록한다.
각 서비스의 공식 내보내기·접근 가능성은 [기술 설계](architecture.md)에서 조사한다. 실제 샘플과 첫 최소 지원 형식은 아직 검증하지 않았다.

## 1. 핵심 선택과 바뀐 첫 사용

사용자는 이미 원래 앱에서 기록한다. 새 도구의 첫 가치는 그중 선택한 내용을 가져와 관심 주제로 연결하고, 근거를 읽고, 나중에 다시 찾는 데 있다.
R1은 **가져오기 → 원문·출처 확인 → 발췌·후보 검토 → 주제별 모아보기 → 원문 복귀·재열기·내보내기**다.
오늘·빠른 활동 기록·진행 중/중단/마침은 홈 기본에서 제외한다. 직접 입력은 가져온 내용의 빈 항목·질문·연결 이유를 보완할 때 사용한다.
원래 앱의 기록은 그대로 두고 사용자가 선택한 범위만 로컬 사본으로 보존한다. 계정 전체를 수집하거나 원앱에 수정 내용을 쓰지 않는다.
깊은 대화·소비한 자료와 관심의 연결·선택적 공유는 유지한다. AI나 공개를 거치지 않아도 모아보기와 원문 복귀로 일을 끝낼 수 있다.

## 2. 기본 탐색과 한 페이지의 맥락

| 위치 또는 행동 | 사용 목적 | 기본 내용 |
| --- | --- | --- |
| 모아보기 — 홈 | 흩어진 내용을 주제로 다시 읽기 | 사용자 주제 모음, 최근 열어본 모음·기록, 이어 읽을 위치 |
| 원천 기록 | 가져온 기록과 확보 범위 확인 | 원천·본문 확보 여부·작성 시각·검색 필터; 가져온 사본과 출처 |
| 시간 보기 | 시간의 흐름을 보기 | 기존 연표·목록·편집·백업 유지, 확인한 기록만 선택 연결 |
| 가져오기 — 상시 행동 | 선택한 기록을 추가 | 파일 선택·선택 내용 붙여넣기·링크 추가 |
| 선택 기록 안 | 발췌·연결·질문 확인 | 원문 사본이 본문, 발췌/연결/대화 중 필요한 보조 내용 하나 |

자료·대화·내보내기는 현재 모음이나 기록의 행동이다. 처음부터 전역 메뉴를 더 늘리지 않는다.
맥락 헤더는 모음 이름, 기록 제목, 원천, 본문 확보 여부를 유지한다. 원문 작성 시각과 가져온 시각은 상세 출처에서 별도로 확인한다.
본문 하나와 보조 패널 하나만 펼친다. 발췌 목록·출처 비교·대화를 동시에 띄우지 않으며 다른 보조 내용을 열 때 초안을 보존한다.
긴 글을 읽다가 발췌·질문을 열어도 원문 위치와 주제를 잃지 않는다. 모음으로 돌아오면 검색 조건과 선택 기록을 복원한다.

```text
iPad 넓은 화면
[모아보기 | 원천 기록 | 시간 보기]          [검색] [가져오기]
[건축 > 선택 기록] [Obsidian] [본문 일부]   [원문 열기]
[원문 사본: 긴 글 읽기                   ][발췌 또는 출처 비교]
[읽던 위치와 선택 문장 유지             ][선택한 내용 모음에 추가]

iPad 분할 화면 / 좁은 화면 / 390px
[모아보기 | 원천 기록 | 시간 보기] [가져오기]
[건축 > 선택 기록] [원천·확보 범위]
[원문 사본: 한 영역만 표시]
[발췌 확인 / 원문으로 돌아가기]
```

분할 화면에서 너비가 줄면 보조 내용을 본문 전환으로 제공한다. 복귀는 이전 문장·스크롤·포커스로 돌아온다.
원문 사본과 원앱은 구별한다. `원문에서 보기`는 가져온 사본의 문장 위치, `원래 앱 또는 사이트 열기`는 외부 출처로 이동한다.

## 3. 세 가지 첫 사용 장면

| 장면 | 시작·입력 | 얻고 닫는 결과 | 가장 작은 확인 |
| --- | --- | --- | --- |
| EXP-01 선택 기록을 가져오기 | Apple 메모의 선택 문단을 복사하거나 Obsidian의 선택 Markdown/텍스트 파일을 제공 | 가져온 범위·출처·사진 누락을 확인하고 발췌 하나를 관심 주제에 연결 | iPad 파일 앱 또는 복사 경로가 가능한지, 원문과 줄바꿈·문장이 맞는지 확인 |
| EXP-02 여러 원천을 주제로 묶기 | 블로그의 선택 본문/링크와 Instagram의 내 게시물 또는 내가 저장한 다른 사람의 게시물 링크 제공 | 같은 관심 주제에서 함께 읽되 원문·작성자·확보 범위는 각각 유지 | 본문 없는 링크를 읽은 글처럼 표시하지 않고 두 원천을 자동 병합하지 않는지 확인 |
| EXP-03 며칠 뒤 다시 읽고 옮기기 | iPad Chrome을 닫았다가 평소 경로로 재열고 주제 모음을 선택 | 발췌에서 원문 위치·원앱으로 돌아가고 선택 모음과 출처를 내보냄 | 읽던 위치, 외부 이동 실패, 파일 저장 위치 선택·재선택·앱 밖 가독성 확인 |

세 장면은 검증 계획이다. 실제 개인 샘플을 읽거나 사용자가 수행한 결과로 보고하지 않는다.
이득은 기록량이 아니라 기존 앱을 따로 검색하는 것보다 관심 자료와 원문 근거를 다시 찾기 쉬워졌는지로 판단한다.

## 4. 가져오기와 출처 확인

1. `가져오기`에서 파일 선택·선택 내용 붙여넣기·링크 추가 중 가능한 경로로 시작한다. 첫 최소 지원 형식은 실제 익명 샘플을 확인한 뒤 확정한다.
2. 파일 선택 취소는 아무 항목도 만들지 않는다. 붙여넣기는 비어 있는 명시 입력창에서만 받고 다른 앱 내용이나 클립보드를 상시 읽지 않는다.
3. 받은 입력을 ImportSession의 staging에 보관하고 제목/본문·출처·확보 범위·누락을 대조한다. 실제 보존 성공에서만 `검토 중 보관됨`으로 표시하며 통합 완료와 구별한다.
4. 사용자는 원문을 읽으며 포함할 항목·발췌·주제를 고른다. 제목·시간이 없어도 출처 미확인/시간 모름을 유지하며 필드 보완을 강요하지 않는다.
5. `선택한 내용 모음에 추가`는 원문·선택 발췌·연결·재개 정보와 적용 상태를 원자 저장한다. 분류 전 `자료만 보관`으로 SourceVersion만 확정할 수도 있으며, 이후 발췌·모음 연결은 해당 버전을 참조하는 별도 저장이다.
파일의 모든 내용을 매번 개별 승인하거나 문장마다 확인 버튼을 누르게 하지 않는다. 닫았다가 다시 열면 검토 중 항목은 해당 단계·선택 상태로 돌아온다.
검토 취소는 아직 미적용된 stage만 취소하며 이미 성공적으로 보관한 자료를 자동 삭제하지 않는다. 자료 삭제는 별도 명시 행동이다.

선택 본문·텍스트·Markdown·링크를 공통 수동 경로 후보로 제안한다. 네 서비스의 전체 내보내기 지원이나 상시 자동 연동을 약속하지 않는다.
Obsidian의 Markdown 평문은 기술 조사로 확인됐다. Obsidian Importer의 Apple 메모 가져오기는 macOS 전용이며 iPad에서는 지원하지 않는다. 우리 웹앱의 공유 메뉴 수신도 확인되지 않았으므로 해당 조작을 지원 버튼처럼 보여주지 않는다.
PDF·이미지 OCR·전체 Obsidian vault 해석·계정 로그인·자동 웹 본문 수집은 첫 공통 경로에 전제하지 않는다.
링크만 제공되면 `본문 미확보`, 일부 복사면 `선택한 본문만 보관`으로 표시한다. URL 추가 성공을 본문 수집 성공으로 표현하지 않는다.
Apple 메모의 사진·표, Markdown 첨부, 블로그 사진 등은 실제 포함한 범위만 보관한다. 미지원 요소는 위치를 알면 표시하고, 알 수 없으면 `첨부 포함 여부 미확인`으로 남긴다.
Instagram은 `내 게시물`과 `내가 저장한 다른 사람의 게시물`을 구별한다. 저장했다는 사실을 저작·본문 확보·재공유 허용으로 해석하지 않는다.
앱이 선택 기록의 유형을 알 수 없으면 이를 확인할 수 있게 하되 저장 목록 전체나 타인 계정 접근을 자동 요청하지 않는다.

## 5. 원문 보존·발췌·주제별 모아보기

가져온 원문 사본을 읽고 문장 선택 후 `발췌 추가`로 주제를 고른다. 주제는 자유롭게 적으며 분야 분류나 제목·ISBN 등록을 먼저 요구하지 않는다.
발췌에는 원문 위치·원천·작성자/확보 수준을 연결한다. 사용자가 쓴 연결 이유·질문은 선택 입력이며 인용문에 섞지 않는다.
긴 글 전체와 읽은 일부를 구분한다. 가져왔거나 모음에 넣었다고 읽음·이해·동의·활동 완료로 표시하지 않는다.
주제 모음에는 발췌와 출처를 먼저 보여주고 필요하면 문맥을 펼친다. 새 내용이 없어도 기존 발췌에서 시작할 수 있다.
같은 경험의 메모·블로그·게시물을 연결해 함께 볼 수 있으나 `같은 경험으로 연결`은 사용자 선택이다.
연결해도 원문·작성 시각·원천 ID는 각각 유지한다. 일치하는 제목·날짜만으로 하나의 활동이나 합쳐진 원문을 만들지 않는다.
재가져오기에서 같은 내용 후보는 이전 사본과 비교해 `기존 기록 보기`·`별도 기록으로 보관` 등을 선택한다. 새로운 내용이 원문을 조용히 덮지 않는다.
URL만 있는 항목은 제목·출처 링크·사용자가 남긴 이유로 모을 수 있으나 발췌·본문 요약은 제공하지 않는다.
원문 오류를 발견하면 사본을 고쳐 사실을 바꾸는 대신 출처 보완 또는 사용자 메모를 별도로 남긴다.

## 6. 원문 복귀·재열기·내보내기

발췌의 `원문에서 보기`는 해당 원문 사본의 문장으로 이동하고 선택 범위를 강조한다. 정확한 위치를 찾지 못하면 주변 문맥을 보여주고 위치 미확인을 표시한다.
`원래 앱 또는 사이트 열기`는 제공된 링크만 사용한다. iPad에서 원앱으로 열리는지 또는 웹으로 열리는지는 실제 검증 결과로 안내한다.
외부 앱 전환 후 돌아오면 동일 모음·기록·읽던 위치를 복원한다. URL이 없거나 링크가 막혀도 가져온 본문 사본은 읽을 수 있다.
오프라인에서는 보관한 본문·발췌·모음을 읽는다. 외부 원문·보관하지 않은 사진은 `연결 필요` 또는 `사진 미보관`을 표시한다.
며칠 뒤 홈은 마지막 열어본 모음과 기록으로 돌아가는 길을 제공한다. 읽던 화면 위치는 활동 수행 시간·완료 사실로 바꾸지 않는다.
`모음 내보내기`는 선택한 발췌·사용자 메모·출처·미확보 항목을 읽을 수 있는 형식으로 옮기는 행동이다. 정확한 지원 형식은 기술 검토와 샘플로 정한다.
전체 백업과 선택 모음 내보내기는 범위를 구분한다. URL 목록만 있으면 원격 본문·사진까지 백업됐다고 표시하지 않는다.
iPad의 저장 위치 선택·취소·동일 이름 파일 처리를 확인하고, 파일 생성 요청만으로 `파일 앱에 저장됨`이라고 표시하지 않는다.
내보낸 파일을 다시 선택해 앱 밖에서 내용·출처를 읽고 사본 복원 시 연결이 살아 있는지 확인한다. 원래 앱으로 자동 업로드하지 않는다.

## 7. 직접 입력·책·교재·생활 도구의 경계

직접 입력은 제목/출처 보완, 연결 이유, 현재 질문, 가져온 본문 없는 항목에 사용자가 제공하는 내용을 위해 제공한다. 원문 인용과 작성자 기원을 구별한다.
책·교재에 관한 기존 메모도 주제로 모을 수 있다. 판본·페이지를 제공받은 범위에서만 표시하며 독서 구간·문제 완료를 메모에서 자동 확정하지 않는다.
소비한 책·전시·장소·관심 자료를 다시 찾고 다른 해석으로 이어가는 가치는 유지한다. 첫 사용에는 대상 등록·진도율·계획을 요구하지 않는다.
계획→수행→기록→재개와 책·교재 전용 도구는 후속 필요가 확인된 별도 흐름으로 둔다. 가져오기에서 Activity를 자동 생성하지 않는다.
후속 활동에서도 예정/실제, 세션 마침/완독·단원 완료, 확정 재개 위치/탐색 cursor는 구분한다. 진행 중/중단/마침을 가져온 기록의 상태로 쓰지 않는다.

## 8. 선택 자료를 보며 대화·AI 후보 검토

R1의 발췌·주제 연결은 사용자 선택만으로 동작한다. 자동 추출·주제 추천·깊은 대화는 [AI 설계](ai-workflows.md)의 후속 선택이다.
현재 원문/발췌/질문을 선택하고 `자료 선택`에서 전송 범위를 확인한 뒤 `질문 보내기`를 실행한다. 전체 원천 보관함을 자동 전송하지 않는다.
대화 응답은 원문과 분리하고 `직접 인용`·`요약`·`추정`·`출처 미확인`을 구별한다. 링크만 있거나 목차만 있으면 본문을 읽은 답변을 만들지 않는다.
발췌·주제·연결의 AI 후보는 원문 근거와 변경 전후를 보여주며 `선택한 내용 적용`으로만 저장한다. AI 기원은 적용 후에도 남는다.
적용은 baseRevision을 확인한다. 원문/메모가 달라졌으면 비교 후 다시 선택하고, 생성 완료나 패널 닫기가 적용을 뜻하지 않는다.
`되돌리기`는 해당 변경만 복구하며 이후 사용자 수정을 지우지 않는다. 요청 취소 후 늦은 응답은 자동 적용하지 않고 자료 권한이 유효할 때만 열 수 있다.
기본 대화는 기기에 비공개 보관하고 `대화 저장 안 함`을 제공한다. AI 실패·계정·비용은 수동 가져오기·발췌·모음 저장의 선행 조건이 아니다.

## 9. 개인 원본과 공유본·방문형 서재

R1은 개인 보관이다. 후속 `공유 미리보기`에서 나만 보기·특정 사람/모임·공개를 구분하고 선택 기록/발췌·출처 필드만 검토한다.
원천에서 가져왔거나 웹에 공개돼 있다는 이유로 재공유 가능한 자료로 간주하지 않는다. 사용자 메모와 타인의 본문·사진을 구별한다.
공유본은 고정 revision·필드 allowlist·수신 범위를 갖춘 사본이다. 개인 대화·관련 기록·원앱 비공개 링크를 자동 따라가지 않는다.
원문 변경 후 기존 공유본은 그대로 두고 `변경 내용 보기` → 미리보기 → `공유본 갱신`으로 선택한 변경만 반영한다.
`공유본 저장`과 실제 `공유 실행`의 성공을 분리한다. 결과 불명은 결과 조회 전 재전송을 보류하고 철회도 확인 가능한 외부 상태로 표시한다.
공개/읽기 전용 방문은 공유 projection만 받고 같은 origin의 개인 작업공간을 자동 열지 않는다. 기존 VIEW_ONLY의 신규 쓰기는 차단한다.
승인한 책·노트·사진을 방문자가 둘러보는 서재는 후속 방향으로 유지한다. 출처·가져온 범위와 접근성을 보존하며 개인 정리 흐름을 공개에 의존시키지 않는다.

## 10. 논리 데이터·초안·화면 상태

| 구분 | 보존 내용 | 화면의 복원 규칙 |
| --- | --- | --- |
| 원천 기록·원문 사본 | 원천 ID/유형, 선택 본문·URL·파일 참조, 작성자 기원, 원문 작성 시각, 가져온 시각, 확보 범위·첨부 상태 | 원문과 후속 메모 분리; 모르는 작성 시각은 그대로, 가져온 시각으로 대체 금지 |
| 발췌·주제 연결 | sourceRefs의 sourceId·sourceVersionId·locator, 사용자 또는 AI 기원, 주제·연결 이유·질문 | 원문에서 검증 가능; 같은 경험 연결은 각각의 원문 참조를 유지 |
| 가져오기/편집 초안 | ImportSession의 stageId·선택 내용·현재 단계·보완값·기준 버전·보존 결과 | 통합된 기록과 구별; 새로고침 후 검토 단계·선택 상태 복원/초안 버리기 |
| 기기별 UI 상태 | 선택 모음·기록·검색·펼침·스크롤·포커스 | 통계·읽음·활동 상태를 바꾸지 않음; 기기 간 자동 병합 없음 |

앱 shell은 작업공간·모음·원천 기록·선택 발췌의 맥락을 유지하고 저장 snapshot/revision으로 갱신한다. 구체 참조 형식은 [데이터 계약](data-model.md)을 따른다.
원문 작성 시각은 원천이 제공하거나 사용자가 확인한 범위만 저장한다. 원문 수정 시각·가져온 시각·현재 발췌 작성 시각도 혼합하지 않는다.
메모 앱에 붙여 둔 AI 답변·타인 인용은 사용자 원저작으로 바꾸지 않는다. 발화 주체와 생성 기원은 별개이며 모르면 미확인으로 남긴다.
발췌의 locator는 불변 제공텍스트의 범위를 참조한다. UTF-16 `[start,end)`와 실제 선택 문자열 대조는 데이터 계층이 수행한다.
화면/기록 전환 전 초안을 보존한다. 보존 실패 시 전환을 보류하고 내용 복사·다시 저장·명시적 버리고 이동을 제공한다.
복원된 기존 연표 외부 참조는 확인 전 자동 재연결하지 않는다. URL에는 개인 본문·질문·수신자를 넣지 않는다.

## 11. 상태 전이와 실패·복구

| 상태 또는 전이 | 보이는 동작과 다음 선택 |
| --- | --- |
| 선택 → 가져오기 전 확인 | 본문·출처·확보 범위를 표시; 파일 선택 취소/빈 입력은 아무 기록도 만들지 않음 |
| staging 보존 → 검토 중 | `검토 중 보관됨`; 닫아도 확인을 재개할 수 있지만 아직 모음에 통합 완료된 것은 아님 |
| 자료만 보관 → 원문 확정 | `자료 보관됨 · 이 브라우저에 저장됨`; 아직 발췌·모음이 없어도 유효하며 후속 검토 취소로 삭제하지 않음 |
| 미지원·일부 읽기 | 성공·미확보·오류 항목을 분리, 선택한 성공 항목만 저장 가능; 깨진 본문을 사실처럼 보관하지 않음 |
| 적용 요청 → 로컬 성공 | 선택 원문·출처·발췌/연결·재개 정보·stage 적용 상태를 원자 저장; 성공 후 `모음에 반영됨 · 이 브라우저에 저장됨`, 성공 전 입력 제거/완료 표시 금지 |
| 로컬 실패·다른 탭 충돌 | 입력과 양쪽 사본 보존, 다시 저장·복사/가능한 내보내기·비교 제공; 조용한 덮어쓰기 없음 |
| 저장 후 출처 비교 | 원문 사본·원천·발췌 위치를 확인; 수정은 보완 메모이며 원래 앱에는 쓰지 않음 |
| 오프라인·원문 이동 실패 | 보관한 본문 읽기 유지; 링크만 있으면 본문 미확보 표시, 외부 요청 실패로 사본 삭제 안 함 |
| 재가져오기·유사 기록 | 후보 차이와 원천을 비교하고 기존 보기/별도 보관/사용자 연결; 자동 병합·수행 완료 추론 없음 |
| 수정/삭제 충돌 | 삭제 상태 유지·수정 사본 별도 보존; 복구는 사용자가 선택하며 원앱 삭제와도 구별 |
| 내보내기·파일 저장 취소 | 앱 기록 유지, 재시도 가능; 생성/저장 UI 호출/사용자가 보관한 파일을 같은 성공으로 처리하지 않음 |

`Storage.commitLocal` 결과는 `stored | conflict | rejected`, 별도 sync는 `not_configured | pending | syncing | synced | conflict | error`다.
stored에서만 `이 브라우저에 저장됨`을 표시한다. R1은 not_configured가 정상이며 같은 iPad의 다른 브라우저/PWA에서도 보인다고 약속하지 않는다.
staging 보존은 검토 재개 안내이며 commitLocal의 stored는 선택한 자료 보관 또는 모음 적용의 성공이다. 적용 실패는 일부 통합 없이 staging과 이전 성공 자료를 유지한다.
stored+error는 `이 브라우저에 저장됨 · 동기화 실패`, rejected는 `저장하지 못함`과 입력 유지, conflict는 `다른 탭의 변경 확인 필요`다.
브라우저 보관은 원래 앱 백업을 대신하지 않는다. 신규 사본의 백업·복원과 기기 밖에서 접근할 사본 범위는 따로 확인한다.

## 12. 새 사용자·iPad·접근성·검토 부담

빈 홈에는 `파일 선택`·`선택 내용 붙여넣기`·`링크 추가`만 안내한다. 가입·AI·전체 계정 연결·활동 상태 선택을 첫 단계로 두지 않는다.
익명 예시는 선택적으로 열고 개인 보관함에 자동 복제하지 않는다. 빈 제목·시간·본문은 무엇이 미확보인지 설명한다.
iPad Chrome의 파일 앱 열기/선택 취소, 원앱 선택 복사, 붙여넣기 줄바꿈·한글 입력·화면 키보드와 앱 전환 복귀를 우선 검증한다.
세로·가로·분할 화면에서 원문/발췌 비교·긴 글 읽기·선택 메뉴와 터치가 서로 가리지 않는지 확인한다. 데스크톱 폭 모사를 실기 검사로 보고하지 않는다.
외부 원문 jump는 해당 원앱/웹의 실제 결과·오프라인·삭제/비공개 링크 실패까지 확인하며, 자체 사본 위치 복귀는 별도 검증한다.
사진 없는 글이 원래 기록 전체처럼 보이지 않는지, 파일 내보내기 저장 위치 선택 후 다시 찾고 여는지 실제 iPad에서 확인한다.
390px 보조 확인은 가로 페이지 스크롤 없이 한다. 최소 44px 터치 목표·16px 입력 글자·safe-area를 고려하고 키보드가 선택 문장·주 행동을 가리지 않게 한다.
키보드/화면 읽기 도구로 파일 선택 대안·발췌 선택·주제 연결·원문 복귀·복구를 수행한다. 문장 드래그만 가능한 발췌 UI는 채택하지 않는다.
Tab 순서는 전역 탐색→맥락→본문→보조 내용, 모달만 포커스를 가둔다. Esc 닫기 후 시작 버튼으로 복귀하고 닫기로 초안을 삭제하지 않는다.
본문 전환 시 제목에, 원문 복귀 시 선택 문장/직전 위치에 포커스를 둔다. 저장 안내는 조용히 읽고 조치가 필요한 오류는 구체 행동과 함께 안내한다.
색만으로 원천·본문미확보·AI기원·오류를 구별하지 않는다. 기능어·봄 테마 변수·따뜻한 바탕·적은 경계·긴 글의 여백을 유지한다.
검토 부담은 “가져오기 확인→문장 선택→주제 선택”의 작은 시안과 한 화면에서 범위·주제를 정하는 시안을 비교한다.
선택한 원문 보존·사실 확인·외부 공유의 필요한 경계는 지키되 같은 범위를 여러 버튼으로 반복 승인하게 하지 않는다. 혼동 없는 쪽으로 단계를 줄인다.

## 13. 기존 연표와 선택·검증 경계

시간 보기는 기존 연표·목록·검색·편집·백업·사본 복원과 저장 키를 보존한다. 신규 원문 사본을 기존 DATA/afterMutate로 쓰지 않는다.
원문 작성일은 실제 경험일이 아닐 수 있으므로 가져온 기록을 자동 사건으로 표시하지 않는다. 사용자가 확인한 기록/경험 연결만 읽기 참조로 제공한다.
시간을 모르는 항목은 시간 모름으로 남기고 가져온 날짜를 경험일로 대체하지 않는다. 필터·모음 연결·보기 전환은 기존 통계를 바꾸지 않는다.
예정 점선·곡선·집계·SVG 내보내기 등 기존 연표 규칙은 유지한다. 연결 해제는 원문 사본·기존 사건·모음 어느 쪽도 삭제하지 않는다.
채택 이유는 기존 기록을 다시 쓰는 부담 없이 근거와 관심을 연결하기 위해서다. 원천 통합을 오늘 기록 화면의 보조 기능으로 붙이는 대안은 첫 사용 목적과 맞지 않아 제외한다.
되돌릴 수 있는 경계는 메뉴 배치·가져오기 최소 형식·주제 표현·검토 단계 수다. 원문/발췌/메모, 사용자/AI, 작성/가져오기 시각의 구분은 유지한다.
R1 완료는 EXP-01~03의 가져오기·출처 대조·발췌/모음·재열기·원문 복귀·내보내기/사본 복원을 익명 샘플로 끝내고 실패 후 입력과 원본이 보존되는 것이다.
후속 실제 사용에서는 며칠 뒤 기존 앱 검색 대비 탐색·재설명·중복 입력이 줄었는지 확인한다. 효과가 없으면 자동화 추가 전에 화면·입력 단계를 축소한다.
이번 문서의 링크·표·참조를 점검한다. 실제 서비스 형식·iPad 파일 저장·접근성·외부 원문 이동·사용 가치의 통과는 이후 결과로 구분한다.
