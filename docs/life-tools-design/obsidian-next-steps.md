# Obsidian 통합 다음 실행 묶음

2026-10-17 UTC. 착수 전 계획과 보존 계약이다. 아래 실행 묶음을 구현했으며 실제 동작·검수·한계는 [연결 선택과 새 사본](../design-review/obsidian-decisions.md)을 따른다. 실제 개인 연결 판단·계정 반영·실기는 완료로 간주하지 않는다.

## 목표와 현재 근거

**검토할 연결 선택 → 원문과 후보 대조 → 변경 미리보기 → 새 비공개 사본 생성 → 다시 열어 확인**을 다음 한 묶음으로 완결한다. 현재 보고서는 판단 대상을 읽을 수 있지만 판단을 저장하거나 연결에 반영하지 못한다. 검토 개수를 줄이는 것보다 선택 결과를 보존하고 잘못 연결했을 때 되돌릴 수 있게 하는 것이 목표다.

- PR [#93](https://github.com/wonchance-art/life-haedo/pull/93)의 구현 HEAD `043d146f03a498b13df3b6ada5fc93cb3e4a1db2`: [CI](https://github.com/wonchance-art/life-haedo/actions/runs/38983058387) 정적 검사와 전체 브라우저 검사 성공. 배포/build 작업은 건너뛰었으며 운영 적용 완료를 뜻하지 않는다.
- 전체 6,899개 파일의 원본·경로·Git 출처를 보존했고 기존 노트 연결은 2,568개다. [구현·검수](../design-review/obsidian-vault-integration.md)를 기준으로 한다.
- 미확정 참조 454회 중 판단 대상은 152회/60묶음이다. 후보가 있는 15묶음과 대상 노트는 알려졌으나 제목·블록 위치가 없는 2묶음부터 검토할 수 있다. 나머지 43묶음은 보류 상태를 유지할 수 있어야 한다.
- 별도 안내 302회에는 원본에 없는 첨부 268회 등이 포함된다. 안내 분류를 누락 복구나 연결 해결로 표시하지 않는다.

## 구현 순서와 완료 기준

| 순서 | 구현할 내용 | 완료 기준 |
| --- | --- | --- |
| 1. 선택·검증 어댑터 | 기존 비공개 변환 결과와 선택 파일을 받아 변경안을 계산한다. 후보 경로·원문 위치·정확 버전을 검증하고 기본은 보류한다. | 연결 추가/위치 보완과 변경 없음이 구분된다. 다른 원본/옛 검토 결과/존재하지 않는 후보/범위 밖 위치/상충하는 선택은 출력 전 거부한다. |
| 2. 비공개 검토 화면 | 묶음에서 참조 노트와 후보의 제목·경로·본문 일부를 대조하고 적용할 참조를 명시 선택한다. 선택을 파일로 저장하고 다시 연다. | 15개 후보 묶음부터 처리하되 자동 선택하지 않는다. 묶음 안의 서로 다른 참조를 일괄 승인하지 않는다. 키보드·좁은 화면·선택 취소·재열기가 가능하다. |
| 3. 미리보기·새 출력 | 적용 전 추가/위치 보완/보류 개수와 대상을 보여준다. 확정한 결과만 별도 새 디렉터리에 쓰고 기존 복원기를 재사용한다. | 원본·기존 출력은 그대로 남는다. 새 JSON을 복원하고 정확한 연결/역방향 연결과 JSON 재백업을 확인한다. 쓰기 실패 시 성공 표시나 기존 파일 변경이 없다. |
| 4. 통합 인계 | 최종 HEAD의 CI와 익명 사용 흐름을 확인하고 로그인한 본인 계정의 새 작업공간 복원 안내를 갱신한다. | 자동 설치·동기화 없이 새 사본으로 복원 가능하다. 실기·운영 반영 여부를 따로 기록한다. |

첫 착수는 **1번의 익명 고정 자료로 선택 → 검증 → 변경 미리보기를 통과시키는 작은 실험**이다. 그 계약을 확인한 뒤 2·3번을 같은 흐름으로 연결한다. 실제 개인 연결을 개발자가 대신 확정하지 않는다.

## 보존 계약

1. **원문 불변:** Git 보관함·본문 바이트·원본 경로·정확한 Git URL·기존 발췌의 UTF-16 위치를 바꾸지 않는다. Markdown을 고쳐 링크를 정상화하지 않는다. 변경은 새 사본의 연결 정보에 한정한다.
2. **검토 근거 고정:** 저장소 URL/Git ref, 감사 파일 해시, 출발·대상 파일 경로와 SHA-256, 출발 토큰의 정확한 UTF-16 범위/문자열로 선택을 확인한다. 묶음 ID만으로 적용하지 않는다. 재변환 때 달라지는 앱 ID는 현재 감사 파일의 경로/버전 매핑으로 확인한다.
3. **위치 보완 구분:** 제목·블록 미확인 2묶음은 문서 연결이 이미 존재한다. 새 연결을 중복 생성하지 않고 확인한 정확 위치만 새 사본에서 보완한다. 위치를 고르지 않으면 기존 문서 연결과 미확인 안내를 유지한다. 위치 선택이 첫 실험에서 검증되지 않으면 이 두 묶음은 보류한다.
4. **감사 유지:** 최초 미확정 참조 454회와 원래 보고서는 그대로 보존한다. 선택·적용·보류 결과는 별도 이력에 남기며 원래 누락을 지우지 않는다. 같은 선택의 재적용은 연결을 중복 생성하지 않는다.
5. **기존 작업공간 보호:** 새 출력은 원래 가져오기 패키지에서 만든 별도 사본이다. 이미 가져온 작업공간의 후속 편집을 합치거나 업데이트하는 기능으로 표시하지 않는다. 본인 계정 복원도 새 작업공간이며 기존 사본은 유지한다.
6. **비공개·실패 복구:** 개인 파일은 앱 저장소 밖에 두고 기존 0700/0600·새 경로·심볼릭 링크 거부 규칙을 재사용한다. 콘솔/CI/공개 증거에는 집계와 익명 자료만 남긴다. 검토 화면은 외부 리소스 요청이나 원문 속 코드 실행을 하지 않는다.

## 구현 선택과 반대 검토

기존 `obsidian-vault.mjs`·`obsidian-review.mjs`, Core의 validate/restore/backup, 네이티브 파일 선택·다운로드를 우선 재사용한다. [기존 공식 문서·오픈소스 비교](open-source-review.md)의 원문 보존 결정을 유지한다. 새 Markdown 엔진·상태 관리·DB 형식을 이 계획에서 추가하지 않는다. 실제 도입이 필요해지면 공식 최신 배포·라이선스·권고를 다시 확인한다.

검토 화면의 호스팅 방식은 구현 가설이다. 기존 보고서는 스크립트 없는 읽기용 HTML이므로 그대로 유지하고, 선택 기능은 별도 로컬 도구로 실험한다. **개인 패키지를 웹 루트에 복사하지 않고 파일 선택으로 읽는 방식**을 먼저 확인한다. 자동으로 연관 개인 파일을 찾아 읽거나 개인 경로를 공개 URL로 만들지 않는다. CLI 선택 파일만으로도 검증 어댑터를 사용할 수 있게 한다.

실험에서 확인할 불확실성은 파일 재열기·선택 보존·큰 JSON의 응답성이다. 구현 담당자가 익명 전체 규모 자료로 확인하고, 기본 파일 API로 충분하면 별도 서버/계정/저장소를 늘리지 않는다. 실제 Apple Files에서 HTML을 직접 여는 동작은 확인 전 지원 완료로 표시하지 않는다. 60묶음에 대규모 자동 추천이나 전문 Markdown 편집기를 붙이는 선택은 현재 근거가 부족하다.

## 필요한 검수와 이후 순서

- Node: 원본 불일치·중복/상충 선택·잘못된 위치·일부 미확정·재적용·출력 실패를 포함한다. 원문/해시/기존 연결 보존과 새 연결의 정확 버전을 대조한다.
- 익명 브라우저: 후보 비교 → 일부 선택 → 취소/재열기 → 미리보기 → 새 사본 복원 → 정확 위치·역방향 연결 → 재백업을 한 흐름으로 확인한다. 선택하지 않은 참조와 기존 작업공간의 보존도 확인한다.
- UI 변경 시 접근성·390/1440px·외부 요청/콘솔 오류를 검수하고, 런타임 변경 시 해당 회귀/PWA 갱신 검사를 수행한다. 최종 HEAD의 CI를 확인한다.
- Mac/iPad/iPhone의 한글 입력·Files 선택/저장·큰 JSON 복원·VoiceOver는 Local 실기로 남긴다. Chromium 화면 크기 검사는 실기 결과를 대신하지 않는다.

이 묶음 이후에는 실제 복원·읽기에서 드러난 부담을 우선 고친다. 첨부 268회의 복구는 원본 파일 확보가 선행 조건이다. 자동 Git 갱신·원본 저장소 쓰기·AI 재분류·동기화·공개 확장은 별도 후속이다. 선행 PR 통합·운영 배포는 기존 Local 인계 범위를 유지한다.
