# 영역별 최소 동작

2026-10-05 사용자의 “연결 기능보다 각 영역을 직접 들어가 써볼 수 있게” 요청에 따른 운영 UI다. 이전 [시각 프로토타입](../design-review/activity-hub.md)과 달리 현재 로그인 계정의 실제 자료를 읽고 구성을 저장한다. 자동 SNS 연결, 공개 게시, 외부 추천, AI 분석은 포함하지 않는다.

## 직접 살펴보기

1. [홈](https://wonchance-art.github.io/life-haedo/)에서 로그인하고 `자료`에서 보관한 원문을 확인한다. 자료가 없다면 기존 `가져오기`로 글·파일·링크를 보관한다.
2. `활동`에서 제목을 정하고 같은 경험의 원문을 고른다. 연결을 풀어도 원문은 남는다.
3. `내 페이지`에서 활동 또는 개별 원문을 추가한다. 소개·메모를 편집하고 항목이나 원문 부분을 켜고 끈 다음 비공개 미리보기로 읽는다. 활동을 나중에 수정해도 페이지의 편집 사본을 자동 변경하지 않는다.
4. `도구 → 다시 찾기`로 저장한 자료를 검색하고, `회고`에서 직접 고른 자료와 메모를 살펴본다. 자료 수는 선택 범위의 집계이며 성격·성장이나 AI 분석 결과가 아니다.
5. `관리 → 자료·구성 백업`으로 JSON 파일을 보관한다. 복원하면 원문·활동·페이지·회고를 새 작업공간 사본으로 열고 이전 자료를 그대로 남긴다.

현재 연표·목표·습관·원문 읽기·발췌는 기존 화면을 사용한다. 연표 값·계산·저장 키를 바꾸지 않는다. 실제 UI가 부족한 부분은 영역과 행동을 기준으로 피드백을 받아 다음 단위를 정한다.

## 저장과 복구 범위

| 대상 | 보관 / 이동 |
| --- | --- |
| 확정한 원문·발췌·출처 | 기존 IndexedDB와 사용자가 연결한 원문 동기화 유지 |
| 활동·내 페이지·회고 구성 | 같은 브라우저·계정·작업공간에 별도 저장. 현재 원문 동기화에는 포함하지 않음 |
| 자료·구성 JSON | `life-workbench-backup-v1`. 확정 원문과 구성을 포함, 새 사본 복원 |
| 기존 자료 JSON / Markdown | 기존 형식 유지. 새 활동·페이지·회고 구성은 제외 |
| 연표·목표·습관 | 기존 플랫폼 백업. 자료·구성 JSON에 포함하지 않음 |

검토 중 가져오기 초안·계정 인증·전송 대기 요청·원문에 보관하지 않은 미디어는 통합 백업에도 포함하지 않는다. 미리보기는 비공개이며 켜기/끄기는 편집 상태다. 공개 URL이나 외부 접근 권한을 만들지 않는다.

활동과 페이지는 `sourceVersionId`를 고정 참조한다. 원문이 누락되면 해당 부분을 사용할 수 없다고 표시하고 다른 버전으로 바꾸지 않는다. 복원은 원문·발췌와 구성 참조를 새 ID로 함께 바꾸며, 누락 참조도 동일한 누락 관계로 남긴다. 자료와 구성은 한 IndexedDB 트랜잭션에서 읽고 설치하여 서로 다른 시점의 백업이나 부분 설치를 피한다.

구성은 독립 revision을 사용한다. 다른 탭이 먼저 저장했거나 쓰기가 실패하면 현재 입력을 보존하고 덮어쓰지 않는다. 화면 이동·로그아웃 전에 저장을 마치고, 계정 변경으로 폐기한 화면의 늦은 결과를 새 계정 화면에 적용하지 않는다.

## 구현 선택과 다음 판단

[공식 오픈소스 비교](open-source-review.md#활동내-페이지돌아보기의-최소-로컬-구성) 후 현재 idb 8.0.3, native DOM, `Core.searchSources()`를 재사용했다. 새 런타임 의존성, 서버, SQL, Core bundle 형식은 추가하지 않았다. `workbench.js`는 앱 고유 구성 검증과 백업만, `workbench-ui.js`는 최소 편집/미리보기만 담당한다. 원문과 저장 엔진을 복제하지 않는다.

가정은 사용자가 실제 자료를 선택하고 한 번 다시 열어보는 것만으로도 영역 구성이 적절한지 판단할 수 있다는 것이다. 더 단순한 대안은 계속 자료 목록과 원문 화면만 쓰는 것이며 활동이나 페이지를 만들 필요는 없다. 실제 체험에서 반복 설정 부담이 확인되면 선택 기본값을 먼저 줄인다. 구성의 기기 간 동기화·공개 게시·자동 연결은 이번 실험의 성공으로 간주하지 않고 별도 요구와 실패 복구를 검토한다.

## 검증

모의 Auth·합성 자료와 실제 동봉 SDK·IndexedDB로 확인했다. 운영 계정·SQL·SNS에는 쓰지 않았다.

- 정적 검사: HTML 16개·JavaScript 36개·로컬 참조 195개와 PWA 통과. Node 회귀 **206/206** 통과.
- 새 영역 기능 **14/14**: 활동 생성, 저장 후 같은 입력 재편집, 페이지 독립 사본, 표시/고정, 미리보기·재열기, 과거 버전·누락 원문, 검색·회고, JSON 왕복 복원, 저장 실패 후 재시도, 키보드, 잘못된 UTF-8 거절, 복원 중 이동 차단, 늦은 읽기의 화면 덮기 차단.
- 실제 IndexedDB 저장 경계 **5/5**: 두 탭 경쟁 저장에서 한 건 성공·한 건 충돌, 변경 알림, 다른 계정 접근 거절, 구성 편집으로 추가 자료 전송 없음.
- 기존 통합 홈 **12/12**, 가져오기·발췌 **6/6** 통과. 로그인 복귀, 서버 확인 전 저장소 미개방, 계정 변경, 원문·발췌 위치와 기존 JSON 형식을 확인했다. 모의 인증 실패는 의도한 오류 1건으로 구분하며 실제 Google 로그인 검증을 반복했다고 보고하지 않는다.
- 시각 검토: **1440·820·390px × 9상태 = 27상태**. 각 영역, 빈 상태, 로딩, 저장 오류와 긴 제목·여러 자료를 확인했다. 가로 넘침·44px 미만 조작·16px 미만 입력·누락 접근 이름 없음, 측정한 텍스트 최소 대비 **6.05:1**. 새 화면 검사 콘솔·페이지 오류·예상 밖 외부 요청 0건.

[영역/시각 검사 보고](../design-review/evidence/working-sections/combined-report.json), [실제 IndexedDB 보고](../design-review/evidence/working-sections/storage-report.json)에 실행별 결과를 구분했다. 초기 검사에서 탐색 선택자 중복과 미리보기의 비동기 대기 누락을 바로잡아 해당 검사를 다시 수행했다. 합산 결과는 동일 검사를 중복 계산하지 않는다.

대표 합성 자료 화면: [활동 390px](../design-review/evidence/working-sections/activities-390.png), [비공개 미리보기 820px](../design-review/evidence/working-sections/visitor-820.png), [다시 찾기 1440px](../design-review/evidence/working-sections/discover-1440.png). 긴 페이지 전체 캡처의 고정 하단 메뉴는 캡처 시점의 화면 위치에 찍힌다. 실제 스크롤·키보드 조작 검사는 이미지 검토와 별개로 수행했다.

재현: `npm run dev` 후 `BASE_URL=http://127.0.0.1:4173 node tests/life-workbench-browser.cjs`, `BASE_URL=http://127.0.0.1:4173 node tests/workbench-storage-browser.cjs`를 실행한다. 테스트용 Chromium/Playwright는 개발 환경 도구이며 앱 의존성이 아니다.

**미검증:** 실제 Mac/iPad/iPhone의 한글 IME·터치·Files 체험. Chromium의 화면 크기와 터치 설정 모사를 Apple 실기 확인으로 표현하지 않는다. 실제 개인 자료의 사용성 평가는 사용자가 각 영역을 직접 확인한 뒤 다음 범위를 정한다.
