# R2 텍스트·Markdown 여러 파일 검토

2026-10-03 · 선택한 UTF-8 `.txt`·`.md` 여러 파일을 한 건씩 검토·확정하는 단위의 로컬 구현·통합 검증 완료. 실제 기기 확인은 아래 검증 상태로 구분한다. R2의 원천별 전체 형식·폴더·계정 수집과 자동 통합은 후속 범위다.

## 사용 장면과 원천 의미

Obsidian에서 고른 독서 메모와 관련 질문, 사용자가 별도로 만든 블로그 글의 텍스트 사본을 함께 선택한다. 파일별로 받은 본문과 출처를 확인하고, 자료만 보관하거나 필요한 구절에 같은 주제를 붙인다. 마지막에는 모음에서 각 발췌의 원문으로 돌아간다. 같은 주제·문장이 있어도 같은 경험으로 자동 합치지 않는다.

| 원천 | R2에서 받는 것 | 보장하지 않는 것 |
| --- | --- | --- |
| Apple 메모 | 사용자가 직접 준비한 UTF-8 텍스트·Markdown 또는 기존 본문 붙여넣기 | Apple 메모의 공식 일괄 내보내기 지원, 사진·스캔·폴더·원작성일 복원 |
| Obsidian | 선택한 `.md`·`.txt`의 텍스트 | vault/폴더 탐색, YAML 속성 해석, `[[위키 링크]]` 연결 해석, 첨부 파일 수집 |
| 네이버 블로그 | 사용자가 준비한 텍스트 사본·선택 본문과 제공한 URL | 글 자동 수집, HTML·이미지·댓글·수정 이력 가져오기 |
| 인스타그램 | 사용자가 준비한 캡션 텍스트·설명과 제공한 URL | 공식 내보내기 묶음·저장 게시물 전체·미디어 가져오기 |

Obsidian의 YAML, 위키 링크, 미디어 참조 표기는 받은 문자로 보관한다. 링크 해석·렌더링·미디어 로딩을 실행하지 않는다. 파일의 수정 시각을 원작성일로 쓰지 않고, 작성자·작성일·포함 범위를 모르면 미확인으로 남긴다. 사용자가 제공한 전체 텍스트와 원천 앱의 문서·첨부 전체를 확보했다는 주장은 구분한다.

## 입력과 검토 경계

- 한 번에 최대 **10개**, 파일당 **1 MiB**, 선택 합계 **5 MiB**의 UTF-8 `.txt`·`.md`를 받는다. 잘못된 UTF-8·지원하지 않는 확장자는 거절한다. 이 수치는 초기 화면의 입력 제한이며 실기 성능·브라우저 저장 용량·원격 동기화 용량을 보장하지 않는다.
- 선택 목록을 고정한 뒤 파일을 순서대로 읽어 로컬 검토 초안으로 저장한다. **파일 선택과 초안 저장은 원문 확정·일괄 업로드·동기화 연결이 아니다.** 기존 한 건 붙여넣기·파일·링크 경로도 유지한다.
- `선택한 파일` 목록에서 `이 파일 검토`로 한 파일을 열고 명시적으로 저장한다. `자료만 보관` 또는 발췌 반영 후 목록으로 돌아오며, `다음 파일 검토`를 눌러 다음 항목을 연다. 원문을 자동으로 전환하지 않는다. 파일마다 독립적으로 확정하며 전체를 한 번에 적용하거나 성공한 항목을 일괄 원복하지 않는다.
- 각 검토·확정은 최신 작업공간을 기준으로 중복·새 버전·겹침을 다시 확인한다. 앞서 확정한 파일도 이후 비교에 포함한다. 같은 파일명이나 본문만으로 합치지 않고, 출처가 불확실하면 별개 보관 또는 검토 보류를 선택한다. 이름이 바뀐 파일을 같은 원천의 새 버전으로 연결하는 기능은 이번 단계에서 보장하지 않는다.
- 원문은 받은 텍스트로 표시·보관한다. 파일 속 HTML·Markdown·과거 지시·스크립트는 실행하지 않는다. PDF·ZIP·폴더·OCR·첨부·원천 API 연결·AI 추출은 포함하지 않는다.

기존 Core의 검증·원문 해시·발췌 위치·중복 계약과 idb의 초안 저장을 재사용한다. 파일 읽기는 브라우저의 File/TextDecoder를 사용하며 새 parser 의존성·DB 버전·백업 형식을 추가하지 않는다. [원천·오픈소스 검토](open-source-review.md)와 [R1 계약](implementation-contract.md)을 유지한다.

## 중단·실패·재개

| 상황 | 남는 것과 다음 행동 |
| --- | --- |
| `건너뛰기 · 초안 유지` | 저장된 검토 초안을 유지한다. 삭제나 원문 확정으로 표시하지 않는다. 건너뛰기 표시는 현재 화면의 상태이며 새로고침 후에는 검토 초안으로 다시 열 수 있다. |
| `파일 읽기 중단` | 이미 저장된 초안·확정 결과는 유지한다. 아직 읽지 않은 파일은 다시 선택해야 한다. |
| 읽기·인코딩 실패 | 해당 파일을 보관 완료로 표시하지 않는다. 다른 성공 항목과 원래 파일은 유지한다. |
| 저장 용량·다른 탭 변경으로 실패 | 현재 입력을 유지하고 다시 검토·저장한다. 저장 성공 확인 전에는 완료로 표시하지 않는다. |
| 새로고침·앱 다시 열기 | 같은 계정·작업공간의 저장된 초안과 확정 상태로 재개한다. 저장되지 않은 실패·미읽기 항목의 파일 목록 복구는 보장하지 않는다. |
| 로그아웃·계정·작업공간 전환 | 진행 중 읽기의 늦은 결과를 적용하지 않는다. 이전 계정의 파일 본문·초안을 새 계정 화면에 보여주지 않는다. |

상단 `선택 파일 목록`과 검토 목록의 파일 묶음에서 재개한다. 확정 결과의 원문·버전 연결을 초안의 적용 상태와 같은 저장 작업에 남겨 `보관한 원문 열기`로 돌아간다. 다시 열었을 때 이미 적용한 항목을 재확정하지 않는다. 예전 적용 초안에 결과 연결이 없으면 없는 정보를 만들어 표시하지 않는다. 파일 재선택은 새 검토이며 파일명으로 기존 자료를 덮어쓰지 않는다.

## 백업과 동기화

`자료 JSON 백업`에는 **확정한 원문·발췌·출처**가 들어간다. 여러 파일 검토 초안·파일 선택 목록·실패/미읽기 항목·동기화 전송 대기 요청·계정 연결 정보는 들어가지 않는다. 읽기용 Markdown도 검토 대기 목록의 백업이 아니다.

초안은 해당 브라우저에 남으며 다른 기기로 동기화하지 않는다. 이미 동기화를 시작한 작업공간에서는 파일을 **확정한 뒤** 기존 동기화 규칙에 따라 전송될 수 있다. 파일 선택만으로 동기화를 새로 시작하지 않는다. 브라우저 데이터를 지우기 전에 필요한 파일을 확정해 JSON 백업을 보관하거나 원래 파일을 별도로 보존한다.

## 직접 확인

```sh
npm run check
npm test
npm run dev
```

`http://127.0.0.1:4173/life.html`에서 확인한다. 개인 화면에는 [공용 인증 설정](../platform.md)이 필요하다. 실제 Google 제공자 로그인 성공과 익명 테스트의 모의 인증은 구분한다. 서버 종료는 실행 터미널에서 `Ctrl+C`다. 공개 사이트는 배포 전까지 로컬 변경을 포함하지 않는다.

1. 개인 정보 없는 짧은 UTF-8 `.txt`·`.md`를 준비한다. Markdown에는 한글·emoji·YAML·위키 링크·첨부 참조 표기를 넣고 실제 실행·이미지 로딩 없이 문자로 남는지 확인한다.
2. `가져오기`의 접힌 `여러 텍스트 파일 가져오기`를 열어 파일들을 선택한다. `선택한 파일`에서 파일명·검토 상태를 확인한다. 이때 원천 목록에 새 원문이 확정되지 않아야 한다.
3. `이 파일 검토`로 첫 파일을 열어 `자료만 보관`으로 확정한다. 목록의 `다음 파일 검토`로 다음 파일을 열어 구절을 같은 주제로 확정하고 모음에서 원문 구간을 대조한다. `보관한 원문 열기`도 확인한다.
4. 한 항목에서 `건너뛰기 · 초안 유지`를 누르고 새로고침한다. `선택 파일 목록`에서 저장한 검토와 확정 원문이 각각 남고, 확정한 항목이 다시 적용되지 않는지 확인한다.
5. JSON 백업을 내려받아 새 사본으로 복원한다. 확정 원문·발췌는 보존되고 검토 초안은 백업에 없음을 확인한다. 원래 파일·작업공간은 유지해야 한다.

브라우저 검사는 합계 54개 통과다. 예상 밖 console/pageerror는 0개이며, 실패 복구를 의도한 console 오류는 자료/동기화/플랫폼 검사에서 각각 1/7/1개로 별도 집계했다. 익명 HTTP fixture와 Chromium 크기 모사는 실제 Apple 하드웨어·Google OAuth·실서비스 RLS의 검증을 대신하지 않는다. 이번 검사는 새 운영 DB 행을 만들거나 실제 개인 자료·원천 서비스 계정을 가져오지 않았다.

검증 도구 Playwright 1.57의 비동기 `waitForFunction`이 false 결과에도 완료되던 대기를 실제 boolean 폴링 또는 동기 DOM 조건과 명시 assertion으로 바꾸고 관련 검사를 다시 통과했다. 제품 서비스워커 변경은 캐시 버전 52다. 브라우저 재현에는 격리된 localhost 테스트와 환경의 Playwright/Chromium이 필요하며 앱 의존성을 새로 추가하지 않는다.

외부 Google 설정·실제 OAuth 체험, 기존 익명 검증 8행의 관리자 정리, PR 병합·공개 배포는 대기 상태다. 이번 텍스트·Markdown 단위 완료를 R2 전체 원천 지원이나 배포 완료로 확대하지 않는다.
