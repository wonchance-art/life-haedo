# R1 구현과 검증 기록

2026-10-03 · 사용자 요청으로 설계에서 구현으로 진행. 대상은 Mac·iPad·iPhone이며 iPad Chrome은 기존 확인 환경이다. 로컬에서 처음부터 끝까지 사용할 수 있는 첫 구현을 완료했다. 아래 실행한 범위와 후속 기능·실기 검증을 구분한다.

## 구현 범위

별도 `life.html`에서 선택 본문·UTF-8 텍스트/Markdown 파일·링크를 가져와 원문·발췌·출처를 주제로 모은다. 원문 확인과 새로고침 후 재방문, JSON 백업의 새 사본 복원, 읽기용 Markdown 내보내기까지 하나의 사용 흐름으로 만든다.

기존 연표와 저장소는 별도 보존한다. 자료만 보관과 발췌 통합을 구별하고, 원문·화자·작성일이 알려지지 않으면 빈 값을 임의로 채우지 않는다. 일부 제공과 링크만 제공한 상태를 표시한다. 과거 원문 명령·HTML·Markdown·URL은 앱 실행 권한이 아니다.

[공통 구현 계약](implementation-contract.md)과 [원천·OSS 조사](open-source-review.md)를 따른다. idb 8.0.3은 고정한 UMD와 ISC 고지를 함께 배포하며 자체 범용 저장 래퍼를 새로 만들지 않는다. 앱 고유 revision·검토·중복·복원 규칙은 별도 코드로 검증한다.

## 실행한 검증

- `npm run check`: HTML 7개, JavaScript 블록/파일 17개, 로컬 리소스 44개와 PWA 셸 통과.
- `npm test`: **57개 통과**. 기존 22개에 Core 20개, 저장 계약 10개, 서비스워커 5개 회귀를 추가했다. Node 저장 계약 검사는 실제 IDB 검증과 구분한다.
- `node tests/life-browser.cjs`: **23개 통과**. 격리 Chromium의 실제 IndexedDB·화면·오프라인 검사이며 console error·pageerror는 0개다. 실제 트랜잭션 abort 후 원문/발췌/영수증 원복, 동일 작업 재시도, 두 탭 CAS, stage revision, 복원 실패의 active pointer 보존, versionchange 쓰기 중지를 확인했다.
- 화면은 1440·1180·820·390px에서 확인했다. 원문·발췌·검색·파일 이동의 가로 넘침이 없고 스크린샷을 눈으로 확인했다. 익명 샘플을 쓴 Chromium 151.0.7922.173이며 Apple 기기 검증은 아니다.
- 실제 서비스워커 v48을 설치한 별도 격리 세션에서 v49로 갱신했다. 캐시/워커 전환과 이전 캐시 정리, 컨트롤러, 보관 원문의 오프라인 재열기, 기존 localStorage 샘플 불변을 확인했다. SW 제거로 업데이트를 대신하지 않았다.
- 새 자료 화면은 실제 console error·pageerror가 없었다. 연결하지 않은 Supabase·원천 서비스·AI의 성공으로 확대하지 않는다.

검증 도구는 환경에 설치된 Playwright와 `/usr/bin/chromium`을 사용했다. 앱 의존성에 추가하지 않았고 다른 환경에서는 `PW_MODULE_PATH`, `CHROMIUM_PATH`, `BASE_URL`로 기존 도구 위치를 지정할 수 있다. 브라우저 검증 스크립트는 익명 localhost 세션만 허용한다.

## 검증에서 수정한 문제

- 본문 교체 후 기존 발췌 좌표가 다른 문장을 가리키던 문제: 유효 후보를 해제하고 이전 원문 구절·주제·메모를 검토 초안에 보존해 다시 선택하도록 했다.
- URL만 제공했을 때 본문 범위 검증에서 거절되던 문제: 본문 미확보 `link_only`로 처리하고 내용/hash를 만들지 않는다.
- 비동기 해시 중 입력이 바뀌는 경합: 입력 사본·검토 버전을 고정하고 늦은 결과를 폐기한다. 작업 중 입력 잠금과 실패 후 입력 보존을 함께 적용했다.
- CRLF와 emoji: textarea의 줄바꿈 표시와 실제 원문의 UTF-16 위치를 대응시켜 정확한 구절을 추적한다.
- 다수의 backtick이 있는 정상 크기 원문: Markdown 내보내기의 최대 인자 개수 오류를 없애고 원문을 실행되지 않는 코드 구획으로 내보낸다.

## 미완료와 실제 기기 한계

Mac·iPad·iPhone 하드웨어, Safari 및 각 기기의 Chrome 파일 선택·화면 키보드·한글 IME·공유 메뉴는 실제 기기 확인 전이다. Chromium 크기 모사는 이를 대신하지 않는다.
Apple 메모·Obsidian·네이버 블로그·인스타그램의 실제 개인 자료·계정 전체 내보내기·자동 API 연결을 검사하지 않는다. 익명 샘플을 사용하며 새 외부 전송은 없다.
기기 간 자동 동기화는 다음 우선 작업이다. 현재 백업 파일을 다른 기기로 가져오면 새 사본이 생기며 두 사본을 자동 병합하지 않는다.
AI 의미 추출·OCR·이미지/PDF/ZIP parser·원문 버전 삭제 UI·삭제 전파·특정인 공유·자동 게시·공동 편집은 구현 범위 밖이다. 원문 보관을 위한 새 서버/DB 스키마도 만들지 않는다.

## 다음 작업과 완료 범위

이 결과는 첫 로컬 구현이다. 설계의 모든 V 검증이나 사용자 사용 평가를 완료한 것은 아니다. 실제 원천별 파일 전달·Apple 실기·장기 재방문의 효용 확인은 남아 있다.
여러 기기 사용을 위해 다음 우선 작업은 R3의 새 자료 개인 동기화다. 새 원격 스키마/소유권·충돌·삭제·원문/첨부 범위를 검증한 뒤 연결한다. 기존 charts 동기화를 새 자료에 바로 재사용하지 않는다.
백업은 확정 자료만 포함하고 임시 검토는 제외한다. 원문 버전 삭제 UI는 아직 제공하지 않으며 현재 제거 기능은 발췌와 그 연결에 한정한다. 읽던 위치는 화면 내 복원과 저장된 발췌의 원문 이동을 지원하며 기기 간 읽기 위치 동기화는 후속이다.
커밋·푸시·공개 배포는 수행하지 않았다. 기존 개인 자료·DB·인증 설정은 작업 대상으로 읽거나 변경하지 않았다.

## 실행

`npm run dev` 후 `http://127.0.0.1:4173/life.html`을 연다. 처음에는 빈 작업공간으로 시작하고 개인 원문·샘플을 자동 등록하지 않는다. 로컬 변경은 공개 배포에 반영되지 않는다. 서버 종료는 실행 터미널에서 Ctrl+C다.
