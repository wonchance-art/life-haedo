# 기존 자료 통합과 분야별 보기

설계 기준: 2026-10-03 (Asia/Seoul). 최신 사용자 요구에 따라 이미 기록된 자료의 추출·통합을 기본 흐름으로 갱신했다.
이 문서는 설계 계약이며 기능 구현·검증·DB 구조 확정이 아니다. 사례는 가상이며 개인 원문을 옮기지 않았다.
[현재 기준](../current.md), [참조 설계](../design.md), [인계](../handoff.md)의 기존 선호를 보존하되 최신 요청을 우선한다.

## 1. 목적과 R1의 경계

사용자는 여러 도구에 이미 남긴 생각·감상·질문·자료를 반복 입력하지 않고 모아 이해하고 다시 쓰고 싶어 한다.
주요 원천은 **Apple 메모·Obsidian·네이버 블로그·인스타그램**이다. 각 원천에서 사용자가 선택한 부분부터 다룬다.
R1은 **선택한 기존 자료 가져오기·원문/출처 보존 → 발췌·검토 → 주제/경험별 연결 → 원문 재추적·재열기·내보내기**다.
직접 입력은 빠진 맥락·현재 판단·연결 이유를 보완하는 경로다. 현장에서 새 활동을 기록해야만 사용할 수 있는 구조로 만들지 않는다.
계정·AI·공유 연결 없이 개인 로컬에서 이 흐름을 완결하고, 닫았다 돌아와도 검토 맥락과 원문 참조를 복원한다.
사본 백업과 내보내기는 보존한 원문·발췌·통합 결과의 관계를 유지해야 한다. 원천 서비스 자체의 완전 백업을 뜻하지 않는다.

분야는 새로운 입력 양식의 묶음이 아니라 **같은 자료를 질문·대상·경험 관점에서 모아보는 후속 보기**다.
독서·학습, 일상, 문화·여행, 창작, 관계는 격리된 보관함이 아니다. 자료 하나를 필요한 여러 보기에서 참조한다.
책 진도·계획·실제 활동 도구는 필요한 경우의 후속 기능이며 R1을 시작하기 위한 준비 조건이 아니다.
플랫폼·다중 사용자·자동 수집 시스템을 먼저 만드는 방향으로 확대하지 않는다. 후속 순서는 [로드맵](roadmap.md)에서 통합한다.

| 구분 | R1에서 제공할 흐름 | 후속 범위 |
| --- | --- | --- |
| 시작 | 선택 본문·텍스트·Markdown·URL 가져오기, 원천·확보 범위 확인 | 검증된 제공처 연동, 첨부·형식 확장 |
| 검토 | 원문을 보며 발췌·생각·제안·인용을 구분 | 선택 자료에 대한 깊은 대화·해석 비교 |
| 통합 | 주제·질문·대상 연결, 관련 경험 후보를 사용자 확인 | 분야 고유 상태, 확정된 경험별 돌아보기 |
| 재개 | 마지막 검토 자료·발췌 위치·미결 연결·질문 복원 | 책/교재 위치·재독·복습 도구 |
| 재사용 | 원문 재열기, 발췌와 출처를 포함한 내보내기·사본 보존 | 특정 사람 공유·방문형 공개 서재·창작 편집 |

## 2. 원천별 입력과 확보 범위

아래는 우선 검토할 수동 입력 경로다. 자동 API·크롤링·전체 계정 복사·기능 지원 확인을 약속하지 않는다.
실제 제공 경로·형식·제약은 [기술 구조](architecture.md)의 원천 조사와 작은 입력 실험으로 확인한다.

| 원천 | 우선 입력 경로 | 도메인에서 보존할 맥락 | 미확보 경계 |
| --- | --- | --- | --- |
| Apple 메모 | 사용자가 선택한 본문 또는 텍스트 | 메모 제목·원천 이름·사용자가 준 작성 정보·선택 범위 | 노트 전체·이미지·스캔·폴더 구조를 확보했다고 가정하지 않음 |
| Obsidian | 선택한 Markdown/텍스트·관련 링크 | 문서 제목·사용자가 준 상대 경로·원래 링크와 발췌 위치 | 링크 대상 본문·첨부·플러그인 의미까지 읽었다고 가정하지 않음 |
| 네이버 블로그 | URL·사용자가 제공한 선택 본문/텍스트 | 원 게시물 URL·제목·제공된 작성 정보·확보한 범위 | URL만 있으면 본문 미확보; 게시물 전체·사진·댓글 수집을 추정하지 않음 |
| 인스타그램 | 사용자가 제공한 저장 링크·선택 텍스트 | 원 게시물 URL·제공된 설명·사용자가 적은 저장 이유 | 저장 목록 전체·이미지·영상·비공개 본문을 확보했다고 가정하지 않음 |

원문을 보존한다는 것은 **사용자가 제공한 범위의 원래 내용**을 변형하지 않고 남긴다는 뜻이다.
선택 본문만 제공받으면 전체 원문이 아니라 부분 확보로 표시한다. URL만 제공받으면 연결 주소와 사용자 설명만 보존한다.
제공된 작성일·경험일·발행일과 가져온 시점을 구분한다. 가져온 날짜가 실제 경험 날짜가 되지 않는다.
원천에서 바로 열 수 있는 주소가 없으면 제공된 문서명·경로와 보존한 원문 사본으로 되찾게 한다. 존재하지 않는 딥링크를 만들지 않는다.

## 3. 자료·발췌·해석의 공통 계약

아래 개념은 의미 구분을 위한 계약이며 모두 독립 화면·서비스·테이블로 만들라는 뜻이 아니다.

| 개념 | 뜻과 예 | 구분할 것 |
| --- | --- | --- |
| 원문 자료 | 가져온 메모·Markdown·게시물 본문 또는 URL과 제공 설명 | 보존한 원문과 정리 결과, 전체 확보와 부분 확보 |
| 발췌 | 원문에서 선택한 구간과 그 위치 | 원문 인용과 편집·요약 문장; 위치가 불명하면 불명 상태 |
| 기록 | 사용자가 남긴 경험·관찰·작업 과정의 서술 | 경험 서술과 실제 수행 확정, 인용된 타인의 경험 |
| 생각 | 사용자 질문·해석·판단 | 당시 생각과 현재 생각, 작성자의 생각과 AI의 제안 |
| 자료/출처 | 내용의 근거와 원래 위치를 되찾는 참조 | 제목·링크 확보와 본문 접근, 원문과 요약 |
| 대상 | 자료를 함께 보는 책·작품·장소·프로젝트·모임 등 | 같은 제목과 같은 판본, 주제 유사성과 동일 대상 |
| 연결 | 발췌·질문·대상·경험 사이의 관계와 이유 | 관련 후보와 사용자 확인 연결, 같은 주제와 같은 경험 |
| 통합노트 | 선택 발췌와 사용자의 정리를 모아 만든 결과 | 통합 문장과 원문, 새 판단과 원래 작성자의 주장 |
| 계획/활동 | 사용자가 일정·실제 경험으로 확인한 선택 구조 | 원문 내용 전부를 Plan/Activity로 강제 변환하지 않음 |

자료 하나에 여러 생각·인용·제안이 섞일 수 있다. 문서 전체를 하나의 경험이나 하나의 현재 선호로 처리하지 않는다.
발췌와 통합 결과에는 원문 참조를 유지하고, 원문을 직접 고쳐 요약처럼 만드는 대신 별도 정리 결과를 만든다.
원문과 발췌를 불러오는 데 대상 등록·계획·활동 생성은 필수가 아니다. 분류하지 않은 자료도 저장·재조회·내보낼 수 있다.
같은 자료를 독서와 창작에서 참조해도 원문을 분야별로 복사하지 않는다. 발췌별 해석은 원래 위치로 되돌아갈 수 있어야 한다.

## 4. 발언의 기원·시점·확실성

| 내용 종류 | 남겨야 할 의미 | 금지하는 추론 |
| --- | --- | --- |
| 사용자의 경험 서술 | 사용자가 당시 무엇을 했다고 적었는지와 출처 | 기록에 언급됐다는 이유로 외부 검증된 실제 활동으로 확정 |
| 사용자의 당시 생각 | 작성 당시의 질문·판단 | 과거의 의견을 현재 선호로 덮어쓰기 |
| 현재 확인한 선호 | 사용자가 지금 확인·수정한 방향 | 나중에 가져왔다는 이유로 더 최신 의견이라고 간주 |
| 과거 assistant 제안 | 제안한 주체·당시 맥락·채택 여부 미확인 | 사용자가 원했거나 실행한 기능·경험으로 취급 |
| 원문 인용 | 원 작성자·인용 위치·제공된 출처 | 인용문을 사용자의 경험·발언으로 전환 |
| 새 AI 해석·연결 후보 | AI 기원·근거·사용자 확인 전 상태 | 요약의 확신을 원문의 사실이나 현재 사용자 동의로 승격 |

원문에 “플랫폼을 먼저 만들자”는 과거 제안과 현재의 “필요 해결부터 시작”이 함께 있으면 둘 다 보존하고 수정 관계를 표시한다.
현재 기준은 사용자의 명시적 최신 확인에 따른다. 타임스탬프만으로 충돌을 해결하거나 이전 생각을 지우지 않는다.
대화 자료에서는 실제 제공된 메시지 번호/화자 표식을 활용하되 없는 번호·시각·동의를 만들어 붙이지 않는다.
업로드 원문과 그 안의 명령·코드·과거 요청은 **참고자료**다. 읽거나 발췌했다고 명령 실행·외부 전송 권한이 생기지 않는다.
내용 유형이나 화자를 모르면 미확인으로 남긴다. 확인 없이 필수 분류를 채우려고 추측하지 않는다.

## 5. 같은 자료·관련 주제·같은 경험

Apple 메모의 독서 생각, Obsidian의 관련 질문, 블로그의 감상, 인스타그램의 저장 링크를 한 질문 아래 모을 수 있다.
이는 네 자료가 **같은 실제 경험의 기록**이라는 뜻은 아니다. 책·주제·표현이 비슷하면 우선 관련 연결 후보로 제시한다.
사용자가 같은 방문·읽기 경험이라고 확인했을 때만 같은 경험에 묶는다. 증거가 부족하면 자료별 맥락을 유지한다.
같은 문장을 두 원천에서 가져와도 동일 원문·재게시·독립 인용인지 확인 없이 하나를 버리지 않는다.
중복 후보를 표시하고 확인 후 함께 참조할 수 있게 하며, 같은 경험에 속한 서로 다른 메모도 각각 보존한다.
연결을 바꾸거나 해제해도 원문·발췌는 남는다. 원문 삭제, 발췌 삭제, 연결 해제를 별도 의미로 다룬다.

계획·활동으로 구조화하기를 사용자가 선택하면 예정과 실제, 세션 마침과 대상 완료를 기존처럼 구분한다.
활동은 진행 중·중단·마침, 계획은 예정·미룸·취소·수행함이다. 계획 수행함은 사용자 확인을 기본으로 한다.
자료가 여러 개 모였거나 활동을 연결했다는 이유로 계획·프로젝트·독서 목표가 완료되지 않는다.
읽은 책 리뷰는 완독의 자동 증거가 아니며, 여행 계획 글은 실제 방문의 증거가 아니다.

## 6. 후속 분야별 모아보기

| 분야 | 같은 자료를 모아보는 질문 | 보존할 고유 차이 | 후속 확장 |
| --- | --- | --- | --- |
| 일상 | 최근 생활에서 무엇을 느꼈고 어떻게 바뀌었나? | 관찰·상태·계획·실제 경험·회고 시점 | 선택한 생활 기준·계획/경험 돌아보기 |
| 독서·학습 | 이 책/질문을 어떻게 이해했고 어디를 다시 볼까? | 판본·구간·재독·이해·문제 수행 | 저자·출판사 둘러보기, 질문 중심 자료 발견·복습 |
| 문화·여행 | 이 장소/작품을 직접 경험한 내용과 참고 설명은? | 계획·현장 감상·타인 설명, 작품과 연주/녹음 | 지역·언어를 바꿔도 자료·관찰·질문 연결 재사용 |
| 창작 | 어떤 자료를 선택했고 생각·작업물이 어떻게 바뀌었나? | 소재 원문·선택 이유·초안·결과·공개본 | 여러 자료를 글·사진·교육 자료로 선별·편집 |
| 관계 | 제공된 관심과 함께한 경험에서 무엇을 나눌까? | 사용자 메모·상대 발언·추정·약속 확정 | 근거와 출처가 있는 소재 후보, 선택한 사람과 공유 |

언어 학습·가르치기와 음악 감상도 기존 선호로 유지한다. 분야별 정보를 한 성과율·완료 단위·필수 입력 양식으로 합치지 않는다.
깊은 대화는 선택 자료에서 사용자 생각·근거·다른 해석·과거 생각을 연결하는 후속 흐름이며, 모든 발췌의 필수 종료 단계가 아니다.
방문형 공개 서재는 사용자가 공개 승인한 책·메모·사진 등을 탐색하는 후속 표현이다. 개인 원문을 공개 원본으로 사용하지 않는다.

| 항목 | 구분할 의미 | 원문 통합에서 지킬 것 |
| --- | --- | --- |
| 마지막 위치 | 사용자가 확인한 재개위치와 단순 탐색 위치 | “80쪽을 열었다”는 메모로 1~80쪽 읽음·재개 확정을 추론하지 않음 |
| 읽은 구간 | 사용자가 실제 읽었다고 남긴 범위 | 31~45쪽·70~75쪽만 확인되면 사이 구간은 미기록 |
| 재독 | 기존 구간을 다시 읽은 별도 경험 | 기존 읽음과 이번 재독 서술을 보존하고 고유 분량을 부풀리지 않음 |
| 이해 | 사용자의 이해 판단·어려움·질문 | 감상문 존재·읽음으로 이해를 확정하지 않음 |
| 문제 수행 | 미시도·시도 중·풀이 완료; 검토 필요 별도 | 풀이 완료+검토 필요가 공존하며 정답 확인·해설 이해도 별도 |
| 완독/단원 완료 | 사용자가 해당 대상·단원을 마쳤다는 확인 | 게시·세션 마침·마지막 페이지 열기만으로 완료 처리하지 않음 |

판본·위치·쪽수·목차가 미확보여도 원문·발췌·질문을 보존한다. 책 정보 수집과 본문 확보는 별개다.
범위를 모르는 자료에서 백분율·성취도를 생성하지 않는다. 책 전용 진도 도구의 구체 조작은 후속 사용 필요로 검증한다.
동일 저자·출판사 둘러보기와 현재 질문에 필요한 추천을 구분하며 이미 가진 자료를 다시 발견할 가능성도 유지한다.

## 8. 핵심 시나리오

DOM-01~09는 최신 자료 통합 방향으로 갱신한 설계 시나리오다. 실행 완료된 테스트나 원문의 실제 경험 ID가 아니다.

| ID | 사용자 흐름 | 기대 결과 |
| --- | --- | --- |
| DOM-01 | Apple 메모의 선택 본문을 가져오고 발췌 하나를 남긴다 | 원천·부분 확보·발췌 위치 보존, Plan/Activity 없이 저장·재개 |
| DOM-02 | Obsidian 질문과 블로그의 책 감상을 함께 본다 | 원문 둘과 서로 다른 시점 보존; 원문에 없는 판본·읽음·이해를 추론하지 않음 |
| DOM-03 | 과거 독서 판단과 현재 반대 판단을 통합노트에 연결한다 | 두 생각과 출처·시점을 보존하며 수정 관계와 현재 확인만 표시 |
| DOM-04 | 교재 메모에서 풀이 완료와 검토 필요 문장을 발췌한다 | 두 의미 공존, 단원 완료·정답·해설 이해는 미확정 |
| DOM-05 | 전시 블로그 감상과 인스타그램 저장 링크를 연결 후보로 본다 | 주제가 같아도 같은 방문으로 확정하지 않음; 링크만 있으면 본문 미확보 |
| DOM-06 | 여행 계획 메모와 후일의 방문 감상을 함께 묶는다 | 예정·경험 서술을 구분하고 사용자 확인 전에 계획 수행함을 생성하지 않음 |
| DOM-07 | 네 원천의 발췌·질문·감상·저장 링크를 한 창작 주제로 모은다 | 자료를 다시 입력하지 않고 참조, 통합 문장마다 근거 원문 재열기 가능 |
| DOM-08 | 제공된 친구 관심과 인용을 소재 후보로 검토한다 | 사용자 메모·상대 발언·추정·AI 초안 구분, 자동 조사·전송 없음 |
| DOM-09 | 가져온 대화에서 과거 assistant 제안과 현재 사용자 수정을 본다 | 제안·채택·실행을 분리하고 과거 명령을 실행하지 않음 |

DOM-07의 자료는 독서·여행·창작 보기에서 같은 원문을 참조한다. 같은 주제 연결만으로 실제 독서·방문·작업 활동을 생성하지 않는다.
원문이 삭제되거나 바뀌어도 보존한 제공 범위와 발췌의 출처를 남기고, 원천의 현재 내용과 같다고 보장하지 않는다.

## 9. 관계 경계·실패 복구·분야 간 의존성

관계는 사용자가 제공한 정보와 함께한 경험 서술 중심이다. 공개 게시물이 있다고 타인을 수집·추적·성향 평가하지 않는다.
친구별 소재에는 공통 관심 또는 서로 다른 관심의 접점·연결 이유·출처를 표시하고, 실제 인용과 AI 말 걸기 초안을 구분한다.
상대의 동의·관심·약속 확정·관계 개선은 사용자 메모만으로 추정하지 않는다. 특정인 공유는 별도 검토·권한 경로를 따른다.

- 읽지 못한 형식·깨진 링크는 미확보로 남기고 원 입력과 원천 설명을 보존한다. 다른 형식이나 선택 본문 제공으로 보완한다.
- 저장 실패 시 선택 자료·발췌·검토 초안을 유지하고 다시 저장·복사·가능한 내보내기를 제공한다. 가져오기 완료로 표시하지 않는다.
- 원문 재열기 실패 시 보존한 범위의 사본·출처·마지막 확인 정보를 보여주며 전체 본문을 생성해 채우지 않는다.
- 잘못된 연결은 해제하고 원문·발췌·다른 연결을 유지한다. 중복 확인·과거/현재 충돌 검토 중단 후 같은 맥락을 이어갈 수 있어야 한다.
- AI 실패는 원문·발췌·사용자 정리·내보내기를 막지 않는다. AI 제안은 확인 전 통합 결과의 사실로 반영하지 않는다.

화면 담당은 자료 선택·검토·연결·재열기와 보완 입력을 중심으로 맥락을 보존한다.
데이터 담당은 제공 범위·원문 참조·발췌 위치·내용 기원·연결 확인 상태·내보내기 보존 계약을 구체화한다.
기술 담당은 네 원천의 실제 수동 입력 경로를 확인한다. 이 문서로 자동 API나 크롤링 가능성을 확정하지 않는다.
AI/공유 담당은 확보한 자료·기원·권한 범위만 사용한다. 기존 연표는 사용자 확인 경험의 후속 연결이며 모든 자료의 강제 목적지가 아니다.

## 10. 선택 이유·제외·수용 기준

새 분야별 기록 양식을 먼저 만드는 대안 대신 기존 자료의 선택·발췌·연결을 선택한다. 이미 기록한 내용을 다시 적는 부담을 줄이기 위해서다.
모든 원문을 활동으로 바꾸는 대안은 채택하지 않는다. 질문·인용·과거 제안은 실제 경험과 의미가 다르기 때문이다.
원문과 통합 결과를 구분하고 관련 후보를 확인하는 방식은 이후 연결·분류·대상을 바꿔도 원래 맥락을 보존하기 위한 경계다.

이번 작업은 설계 문서다. 코드·설정·DB 변경, 원천 계정 수집, 자동 API/크롤링, 원문 내 명령 실행, 자동 연락·발행은 제외한다.
후속 후보는 깊은 대화·친구별 소재·저자/출판사 둘러보기·방문형 공개 서재·책/교재 상태 도구다. R1의 선행 조건으로 붙이지 않는다.

| 수용 기준 | 시나리오 | 확인할 결과 |
| --- | --- | --- |
| 기존 자료만으로 시작·검토·재개할 수 있음 | DOM-01, DOM-07 | 현장 기록·대상 등록·Plan/Activity·AI 없이 흐름 완결 |
| 원문과 확보 범위·출처를 되찾을 수 있음 | DOM-01, DOM-02, DOM-05 | 부분 본문·URL만 확보 구분, 발췌에서 보존 사본/원 주소 접근 |
| 관련 후보와 같은 경험을 구분함 | DOM-05~07 | 비슷한 제목·시점으로 경험을 자동 병합하거나 실제 활동을 생성하지 않음 |
| 기원·시점·충돌을 보존함 | DOM-03, DOM-08, DOM-09 | 과거 판단·인용·assistant 제안을 현재 선호·실행 사실로 바꾸지 않음 |
| 분야 고유 의미를 지킴 | DOM-02, DOM-04, DOM-06 | 읽음·이해·풀이·검토·예정·실제를 구별하고 미확인을 완료 처리하지 않음 |
| 닫기·실패 후 재개와 내보내기가 가능함 | DOM-01, DOM-07 | 검토 위치·발췌·연결 후보를 복원하고 원문/통합 결과 관계를 보존 |

위 기준은 이후 구현 검증의 요구다. 문서 작성만으로 네 서비스 입력·저장·재열기가 작동한다고 주장하지 않는다.
