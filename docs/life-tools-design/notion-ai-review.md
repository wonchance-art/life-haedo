# Notion의 AI 통합 방식과 해도 적용 검토

2026-11-02 KST 조사·검토. 설계 검토 문서이며 모델 호출·외부 전송·새 Edge 함수를 구현하거나 운영에 적용한 결과가 아니다. 해도 쪽 기준은 [AI와 자동화](ai-workflows.md)의 요청·근거·적용·전송 계약이고, 이 문서는 그 계약 위에서 **무엇을 먼저 만들 가치가 있는지**를 Notion 사례로 다시 고른다.

### Notion 방식의 핵심 원리

1. **AI가 따로 있는 화면이 아니라 쓰는 자리에 있다.** 선택 → 요청 → 결과 비교 → 수락/버리기가 편집기 안에서 끝난다.
2. **최근 방향은 "바로 고치기"에서 "제안 후 승인"으로** 옮겨 가고 있다(suggest edits, Review for me). 자율 범위가 커질수록 사람의 확인 지점을 다시 넣었다.
3. **맥락은 사용자가 볼 수 있는 문서다.** 지침·메모리를 편집 가능한 페이지로 두고, 권한은 공유 메뉴·열 권한 같은 기존 권한 모델을 그대로 쓴다.
4. **답에는 인용을 붙이고, 신뢰할 문서를 사람이 지정한다**(검증 배지).
5. **팀 자동화(예약·트리거·연결 앱 150개+)와 비용 관리(크레딧·라우터·관리자 통제)** 가 최근 출시의 대부분이다. 이 부분은 다수 사용자 작업공간을 위한 것이다.

## 2. 해도와의 차이

| 조건 | Notion | 해도 |
| --- | --- | --- |
| 사용자 | 팀·조직 | 소유자 한 명, Mac·iPad·iPhone |
| 데이터 성격 | 업무 문서 | 개인 글·일기성 기록·저장한 타인 글. 원문·버전·출처 보존이 제품 규칙 |
| 실행 환경 | 자체 서버·모델 계약 | 빌드 없는 정적 Pages + Supabase(Auth·DB·Edge 함수 `haedo-blog-media`·`haedo-naver-blog`) |
| 저장 의미 | 페이지 직접 편집 | 로컬 초안 → 명시 저장 → 새 불변 본문 버전, CAS·영수증·복구 사본 |
| 해석 규칙 | 별도 규칙 없음 | 원문·내 글·AI 해석 구분, 저장을 동의·신념으로 추정하지 않음, 자동 공개 없음 |
| 지금까지의 자동 분석 | 상용 LLM | 로컬 임베딩+NLI 관심 추출을 MODEL-02(48문서)·MODEL-03(60문서)에서 기각, 제품에서 비활성 |

해도에는 아직 LLM 호출 경로가 없다. API 키는 브라우저에 둘 수 없으므로 Edge 함수가 필요하고, 이는 **개인 글의 외부 전송**이라는 새 범위다. `AGENTS.md`에 따라 소유자 승인이 있어야 착수한다.

## 4. 첫 작업 묶음 제안 — "글쓰기·자료 안의 AI 제안"

**목표:** 글을 쓰거나 자료로 글을 준비할 때, 선택한 범위에 대해 AI 제안을 받고 비교한 뒤 고른 것만 초안에 넣는다. 저장·버전·동기화·공개 경로는 바꾸지 않는다.

**이번 범위**

1. Edge 함수 `haedo-ai`: 로그인 계정 검증, 요청 크기·월 호출 상한, 공급자 키는 비밀값으로만 보관. 요청·응답 본문을 로그에 남기지 않고 요청 ID·크기·상태·시각만 기록한다.
2. 글쓰기 편집기(`writing*`·`photo-post*`): 선택 영역 → "다듬기 / 줄이기 / 이어 쓰기 / 직접 요청" → 변경 구간 비교 → 구간별 수락·거절·다시 시도. 수락은 편집기 입력과 같은 경로로 초안을 바꾸며 한글 조합 중에는 적용하지 않는다.
3. 자료로 글쓰기(`material-writing*`): 사용자가 고른 자료 발췌만 보내 "질문하기 / 개요 제안". 답의 인용을 코드로 대조하고, 통과하지 못한 인용은 `출처 미확인`으로 표시한다.
4. 설정의 "AI 지침" 문서와 첫 사용 안내(공급자·전송 항목·보존 조건). 기본 꺼짐.

**보존 조건:** 원문·버전·인용 위치 불변, 명시 저장 전 새 버전 없음, 열린 편집기의 미저장 입력·한글 조합을 늦은 응답이 덮지 않음, 화면 이동·계정 전환 뒤 도착한 응답은 원래 대상에만 귀속(아니면 폐기), 공개·사진 공개 선택과 독립, 백업·동기화 형식 호환.

**완료 기준:** 위 흐름을 Mac·iPad 폭에서 처음부터 끝까지 쓸 수 있고, 실패·시간 초과·중복 클릭·계정 전환·늦은 응답·한글 조합 회귀 검사가 있으며, 없는 인용 차단 단위 검사가 있고, 독립 검수와 CI 녹색을 거친다. 실제 기기 사용 평가는 소유자 확인으로 따로 남긴다.

**착수 전 소유자 결정이 필요한 것**

- 개인 글 발췌를 외부 LLM 공급자에 보내는 것 자체의 승인(새 외부 전송 범위).
- 공급자 선택과 보존 조건. 후보는 학습 미사용·보존 기간이 문서로 확인되는 공급자이며, 정확한 모델·요금·보존 조건은 착수 시점에 공식 문서로 다시 확인해 [오픈소스 검토](open-source-review.md)에 기록한다.
- 월 비용 상한.

**바꿀 조건:** 소유자가 외부 전송을 원하지 않으면, 같은 화면 흐름을 브라우저 내 소형 모델로 대체하는 실험을 먼저 하되 MODEL-03 결과를 고려해 "문장 다듬기"처럼 검증이 쉬운 작업으로 한정한다.

## 5. 반대 검토

- **가정이 틀릴 수 있는 곳:** 소유자가 글을 AI로 다듬고 싶어 한다는 근거는 아직 없다. 그래서 1순위를 편집기 안의 선택형 도구로 작게 시작하고, 쓰지 않으면 지우기 쉬운 구조로 둔다.
- **더 단순한 대안:** 외부 AI 앱에 필요한 발췌를 복사해 쓰는 현재 방식. 해도 안에 넣는 가치는 출처 인용 검증·초안 비교·버전 보존이다. 이 셋이 빠지면 도입할 이유가 약하다.
- **실패 후 복구:** AI 응답은 초안 제안에만 들어가므로 실패·취소는 저장된 글에 영향이 없다. Edge 함수를 끄면 기능 전체가 사라지고 나머지 앱은 그대로 동작해야 한다.
