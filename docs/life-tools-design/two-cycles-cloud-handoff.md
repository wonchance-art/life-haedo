# 두 순환 로드맵 · Cloud 실행 인계

2026-10-13 KST. 사용자는 [로드맵의 종합 맵](roadmap.md)을 승인하고 후속 작업을 Cloud로 넘기기로 했다. 이 문서는 실행 요청의 기준이며 이미 구현·통합·배포됐다는 보고가 아니다.

## 먼저 읽고 맞출 기준

- `AGENTS.md`, [현재 로드맵](roadmap.md), [종합 맵 원본](../diagrams/life_two_cycles_20261013.mmd), `DESIGN.md`와 작업할 PR의 `docs/design-review/` 인계를 읽는다. 최신 사용자 지시와 두 순환을 이전 단계표·팀 배치보다 우선한다. 상시 다중 에이전트는 요구하지 않는다.
- 인계 문서 브랜치: `codex/two-cycle-roadmap`. 작성 기준 main: `29a325b8e90702eb0f56e64732440cbe2e8c616e`. 착수 때 원격 main·PR head/base·병합/설치 상태를 새로 확인하고 문서 변경을 최신 통합 브랜치에 포함한다. 오래된 Local `codex/pr17-sync-alignment`를 구현 기반으로 사용하지 않는다.
- Local의 기존 작업 폴더·미커밋 문서·`.claude/`·이전 이미지와 검증 자료는 보존했다. 이 인계 PR에는 문서와 Mermaid 원본만 포함하며 개인 자료·이미지 시안·실행 파일·SQL·Auth 변경을 포함하지 않는다.

## 첫 작업 — P0의 한 흐름을 실제로 완결

1. #58 연표 복구와 #59 → #60 → #61 홈·복귀·관리 변경을 최신 main과 대조한다. 이미 병합된 작업을 다시 적용하지 않고 의존성과 충돌을 확인한다.
2. 익명 샘플을 새 사본으로 시작해 기존 기록 찾기 → 원문 열기 → 편집 → 저장 → 홈/하위 화면 복귀 → 새로고침 → 백업 → 새 사본 복원을 확인한다. 연표는 별도로 기존 형식의 업로드·실패 재시도와 값 보존을 확인한다. 개인 자료를 대체하지 않는다.
3. 발견한 문제는 관련 파일의 작은 수정으로 고친다. 적용한 동작의 저장 실패·재시도·초안/원문 보존을 포함한 회귀와 정적 검사, 넓은/중간/좁은 화면의 브라우저 검사를 수행한다. 화면 크기·touch/composition 이벤트 모사를 실제 Apple 기기·native IME/Files로 보고하지 않는다.
4. 최종 통합 커밋·검사 결과·남은 제약·짧은 직접 체험 절차를 남긴다. 구현·CI와 운영 로그인·RLS·라이브 검증을 구분한다. 병합·배포를 실행할 때는 기존 승인 범위 안에서 실제 원격 상태와 배포 후 공개 주소를 확인하며, 접근 불가능한 운영 검사를 통과로 표시하지 않는다.

## 다음 단위와 두 순환의 연결

- **P1:** #56·#64를 통합해 기존 글 → 근거·회고 → 내 생각 → 책 한 장/개인 파일 또는 다음 행동 → 다시 회고를 완결한다. 행동·새 질문 연결의 현재 구현 여부를 먼저 확인하고, 없는 구조를 있다고 표시하지 않는다. 개인 활용 경로에는 공개나 AI가 필수가 아니다.
- **P2:** #66 → #67 → #68 → #69. 컬렉션 보관·정보·표지·대상 선택을 연결한다. 현재 PR의 저장은 계정·공간별 브라우저 저장이며 자동 동기화가 아니다.
- **P3:** #71 → #72. 글·첨부·초안·선택 공개를 연결한다. #70은 #71로 대체됐으므로 제외하고 #63·#65 시안은 병합 선행 조건으로 두지 않는다.
- **P4:** 실제로 막히는 인풋·기기 이동·생활 연결부터 개선한다. 수신 전용 원천, 외부 분석, 특정인 전달·외부 채널 출력은 서로 다른 범위이며 제공처·출처·전송 범위·비용·중지·결과 대조를 정하고 구현한다.

각 단위마다 **실제 사용 → 불편/유용성 → 작은 비교·선택 → 구현·검증 → 다시 사용**을 실행 기록으로 남긴다. 순환 A의 콘텐츠 생성이나 보고서가 순환 B의 개발·외부 공개를 자동 촉발하지 않는다. 사용자의 체험 평가가 없으면 에이전트 검사를 그 평가로 대신하지 않는다.

## 운영 전제와 보존 경계

- #71의 신규 SQL은 `supabase/migrations/20261012010000_life_page_posts.sql`, 읽기 전용 설치 점검은 `supabase/tests/life-page-posts-installation.sql`이다. 해당 PR의 최종 버전을 대조한 뒤 설치 여부부터 확인하고, 미설치일 때만 관리자 연결에서 적용한다. **8조건 passed=true 확인 전 #71 앱 배포 금지.** 이 인계 문서나 main에 이 파일이 있다는 뜻은 아니다. #72에는 별도 신규 SQL이 없다.
- 관리자 연결이 없는 Cloud 환경에서 SQL 설치를 합성 검사나 테스트 DB로 대체하지 않는다. 정확한 최종 PR 커밋·SQL·점검 파일·남은 운영 조치를 관리자 연결이 있는 실행 환경으로 인계한다. 설치된 SQL·기존 동기화·Auth를 중복 변경하지 않는다.
- 원문·정확 버전·발췌·소유권·계정별 저장·동기화·백업·공개 사본과 승인된 미니멀 A 디자인을 보존한다. 수집·분석 범위·공개 권한·화면 배치는 독립이다. 새 자료 도착·화면 숨김만으로 공개하거나 철회한 것으로 처리하지 않는다.
- 외부 SNS는 이후 확정한 수신 전용 범위를 유지한다. 이 맵의 후속 채널 가지는 원본 SNS 게시·수정·삭제나 메시지 전송의 실행 승인 또는 구현 완료가 아니다.
- 서비스워커 버전은 실제 최종 통합 코드를 기준으로 정한다. 운영 자료를 삭제하지 않고, 로그·스크린샷·보고에 키·비밀번호·개인 자료를 넣지 않는다.

## Cloud 시작 프롬프트

> wonchance-art/life-haedo의 `codex/two-cycle-roadmap` 문서 변경을 최신 main 기반에 포함하고 `docs/life-tools-design/roadmap.md`와 `two-cycles-cloud-handoff.md`를 읽어 작업을 이어가라. 두 순환을 기준으로 P0(#58, #59→#60→#61)의 실제 통합 상태부터 확인하고 작은 사용 흐름의 구현·실패 복구·회귀·브라우저 검증·PR 인계까지 완결하라. 기존 자료·미커밋 변경·원문/버전/출처·계정별 저장·백업·공개 범위와 승인된 A 디자인을 보존하라. 현재 구현과 계획, 합성/브라우저 검사와 실제 운영 검증을 구분하고 이미 병합·설치된 작업은 중복 실행하지 말라. 접근 불가능한 운영 작업만 정확한 외부 조치로 인계하고, 각 단계마다 반복 승인을 요구하지 말라.
