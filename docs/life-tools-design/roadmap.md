## 로그인 뒤 첫 화면 지연 회귀 수정 — PR181 병합·배포, 캐시 `haedo-v181` (2026-11-03 KST)

- **검수·출시**

## 내 데이터 한 번에 지키기 — 공개 배포 완료, 실기기 확인 전 (2026-11-01 KST)

설정의 **백업·복원** 한 화면에서 받기·복원·형식별 파일을 모두 연다. 계약은 [백업·복원 한 화면](../design-review/full-backup.md)에 있다.
- **모두 받기:** 계정의 모든 자료공간을 ZIP 하나로 받는다. 안의 파일은 기존 형식 그대로이고, `manifest.json`·`README.txt`가 형식·개수·크기·SHA-256을 기록한다. 계정 문서만 새 `haedo-account-documents-v1` 형식이다.
- **실패 처리:** 한 항목이라도 읽지 못하면 전체 ZIP을 만들지 않는다. 실패 항목 재시도 또는 빠진 항목을 표시한 일부 ZIP만 고른다.
- **복원:** 목록 밖·누락·해시·형식 불일치 파일을 거부한다. 미리보기 뒤 고른 형식만 원래 공간마다 새 사본으로 만든다. 기존 공간과 로컬 계정 문서를 덮어쓰지 않는다.
- **제외:** 보관 범위·근거 파일, 연표·목표·습관, 공개 표지 설정은 각 전용 화면에서 복원한다. 탈퇴는 단일 사용자에게 위험 대비 이득이 작아 이번 범위에서 뺐다.
- **독립 검수 2회:** 1차 지적(전체처럼 보이지만 연재·자료 준비·네이버 사진·원본 첨부 누락, 같은 백업 재복원 시 조용한 전체 중복, 사진 2배 메모리)과 2차 지적(네이버 사진이 원문마다 새 공간 생성)을 고쳤다. 담지 않는 항목(작성 중 초안·공개 상태·설정 충돌 복구 사본·서버에만 있는 원본 첨부)은 README·화면·manifest `notIncluded`에 이유와 보관 방법을 표시한다. 재복원 경고 영수증은 기기별이다.
- **검증:** `npm test` 1688/1688, `npm run check` 통과, 새 브라우저 흐름 `tests/full-backup-browser.cjs` 7/7(같은 계정 재복원 경고 포함, CI 그룹 2), 백업 화면을 쓰는 purpose-workflow·feature-flow·management-clarity 재통과, SW `haedo-v171`. 큰 묶음 나눠 받기는 없어 iPhone에서 수 GB ZIP은 실기기 확인이 필요하다.

### 이후 큰 작업 묶음

1. **네이버 실제 목록·예약 수집부터 활용까지 운영 완주:** 이미 있는 수집/보관 기능이 실제 블로그에서 작동하는지 확인한다. **선행:** 허용된 네이버·사진 CDN 접근, 대상별 robots·대표 응답, 서버 자격·예약 준비. **완료:** 공개 목록·기수집 대조 → 대표 본문/사진의 확보 범위·픽셀 검증 → 앱 종료 중 예약 보관 → 같은 계정 재접속·정확 판 복구 → 선택 글쓰기·전용 파일·중지/실패 복구. 실제 새 글이 없으면 신규 게시 감지는 미확인으로 남긴다.
2. **실제 두 기기의 사진 기록 완주와 Apple 입력 보강:** 합성 Chromium 결과를 실제 Mac/iPad/iPhone 체험과 구분하고 사진 선택·앱 전환·긴 글 재개 부담을 줄인다. **선행:** 소유자 기기와 직접 고른 대표 사진·글, HEIC 원본/보기용 변환의 보관 범위 결정. **완료:** A 사진 글 작성·서버 보관 → B 정확 원문/원본·수정 → A 재개 → 파일 복원까지 관찰하고 재현된 문제를 묶어 개선한다. 현재 JPEG·PNG·WebP 원본 보존과 별도 공개 선택은 유지한다.
