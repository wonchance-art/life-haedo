# 글쓰기·메모 앱의 AI 통합 방식과 해도 적용 검토

2026-11-02 KST 조사·검토. 설계 검토 문서이며 모델 호출·외부 전송·새 Edge 함수를 구현하거나 운영에 적용한 결과가 아니다. 해도 쪽 기준은 [AI와 자동화](ai-workflows.md)의 요청·근거·적용·전송 계약이고, 이 문서는 그 계약 위에서 **무엇을 먼저 만들 가치가 있는지**를 다른 제품 사례로 다시 고른다.

조사 대상: Notion, Apple Intelligence 글쓰기 도구, iA Writer, NotebookLM, Day One, Mem·Reflect·Craft, Ulysses, Obsidian 플러그인(Smart Connections·Copilot·Smart Composer·Text Generator). 출처는 각 공식 페이지·저장소를 우선했다. 제3자 리뷰는 날짜·가격이 서로 어긋나 사실 근거로 쓰지 않았고, 공식 근거가 없는 항목은 "미확인"으로 적었다.

## 3. 도구들 사이의 공통 패턴

1. **선택 → 제안 → 비교 → 수락/거절.** Notion suggest edits, Apple 교정, iA `Paste Edits`, Smart Composer Apply Edit, Copilot Quick Ask 모두 같은 흐름이다. 수정 이유를 보여 주는 쪽(Apple)과 거절을 지원하는 쪽이 더 믿을 만하다.
2. **누가 쓴 글인지 남긴다.** iA Writer만 정면으로 다루지만, 해도 규칙과 가장 잘 맞는다.
3. **근거가 붙는 질문은 범위를 사용자가 정한다.** NotebookLM의 노트북, Smart Composer의 `@파일`, Notion의 공유 권한.
4. **"비슷한 글"은 로컬 임베딩으로, 판단은 사람이.** Smart Connections는 의미를 단정하지 않고 후보와 점수만 보여 주며 연결은 사용자가 만든다.
5. **질문을 던지는 AI는 요청할 때만.** Day One은 켜야 동작하고, 결과는 질문이지 해석이 아니다.
6. **기기 안 처리 우선.** Apple·Day One·Smart Connections는 기기 안 처리를 기본이나 우선 경로로 둔다. 외부 전송은 따로 표시한다.
7. **반례.** 자동 태그·자동 연결(Mem)과 장시간 자율 에이전트(Notion)는 사용자의 판단을 대신한다. 개인 기록 보존을 최우선으로 하는 해도와는 방향이 다르다.

## 4. 해도와의 차이

| 조건 | 일반 도구 | 해도 |
| --- | --- | --- |
| 사용자 | 팀·조직 또는 불특정 개인 | 소유자 한 명, Mac·iPad·iPhone |
| 데이터 성격 | 업무 문서·노트 | 개인 글·일기성 기록·저장한 타인 글. 원문·버전·출처 보존이 제품 규칙 |
| 실행 환경 | 자체 서버·모델 계약, 데스크톱 앱 | 빌드 없는 정적 Pages + Supabase(Auth·DB·Edge 함수 `haedo-blog-media`·`haedo-naver-blog`) |
| 저장 의미 | 문서 직접 편집 | 로컬 초안 → 명시 저장 → 새 불변 본문 버전, CAS·영수증·복구 사본 |
| 해석 규칙 | 대부분 없음 | 원문·내 글·AI 해석 구분, 저장을 동의·신념으로 추정하지 않음, 자동 공개 없음 |
| 이미 있는 기반 | — | 브라우저 안 다국어 임베딩 워커(`interest-model-worker.js`, Transformers.js 4.3.1 + MiniLM-L12 384차원, 해시 고정, 명시 준비) |
| 지금까지의 자동 분석 | 상용 LLM | 관심 추출을 MODEL-02(48문서)·MODEL-03(60문서)에서 기각. 단 MODEL-03의 **후보 검색 단계**는 정답 51개 중 50개, 반복 질문 6쌍 모두를 후보에 포함했고, 실패는 NLI 검증 단계였다. |

해도에는 아직 LLM 호출 경로가 없다. API 키는 브라우저에 둘 수 없으므로 Edge 함수가 필요하고, 이는 **개인 글의 외부 전송**이라는 새 범위다. `AGENTS.md`에 따라 소유자 승인이 있어야 착수한다. 반대로 아래 0·1순위와 3순위는 외부 전송 없이 할 수 있다.

## 6. 다음 작업 묶음 제안

### 묶음 A — 외부 전송 없이 시작: "AI와 함께 쓴 글을 구분해 남기기" (0·1순위)

- **필요한 이유:** 소유자가 다른 AI 앱이나 OS 글쓰기 도구를 이미 쓰고 있다면, 지금 해도에는 그 문장이 섞여도 구분할 방법이 없다. 제품 규칙(원문·내 글·AI 해석 구분)을 외부 전송 없이 지킬 수 있다.
- **범위:** 글쓰기·사진 글 편집기의 OS 글쓰기 도구 호환 점검과 수정, 작성 주체 표시(붙여넣기·표시·해제, 사람이 고친 부분 자동 해제), 표시 구간의 본문 버전 메타데이터 보존, 백업·동기화·복원 왕복.
- **보존 조건:** 기존 본문 형식과 이전 판 기기 호환(표시 정보가 없는 글은 그대로), 정확 원문·버전 불변, 공개 사본에는 표시를 넣지 않음(2026-11-02 소유자 결정).
- **완료 기준:** 붙여넣기 → 표시 → 일부 고쳐 쓰기 → 저장 → 다른 기기 동기화 → 백업 복원까지 표시 구간이 정확하다. 한글 조합·되돌리기 회귀 검사, 독립 검수, CI 녹색. Apple 글쓰기 도구의 실제 동작은 소유자 실기기 확인으로 분리한다.

### 묶음 B — 승인 후: "글쓰기·자료 안의 AI 제안" (2순위)

- **선행 조건(소유자 결정):** 개인 글 발췌를 외부 LLM으로 보내도 되는지, 공급자와 보존 조건, 월 비용 상한.
- **범위:** Edge 함수 `haedo-ai`(계정 검증, 요청 크기·월 호출 상한, 본문 미기록), 편집기 선택 영역 제안(수정 이유 표시, 구간별 수락·거절·다시 시도), 자료로 글쓰기의 인용 대조 질문·개요 제안, AI 지침 문서(기본 꺼짐). 수락한 구간은 묶음 A의 AI 표시로 남는다.
- **보존 조건:** 명시 저장 전 새 버전 없음, 열린 편집기의 미저장 입력·한글 조합을 늦은 응답이 덮지 않음, 화면 이동·계정 전환 뒤 도착한 응답은 원래 대상에만 귀속(아니면 폐기), 공개 선택과 독립.
- **완료 기준:** Mac·iPad 폭 전체 흐름, 실패·시간 초과·중복 클릭·계정 전환·늦은 응답·한글 조합 회귀 검사, 없는 인용 차단 단위 검사, 독립 검수, CI 녹색. 공급자·모델·요금·보존 조건은 착수 시점에 공식 문서로 다시 확인해 [오픈소스 검토](open-source-review.md)에 기록한다.

### 묶음 C — 실험 먼저: "기기 안 비슷한 문단" (3순위)

- **먼저 할 작은 실험:** 기존 임베딩 워커로 익명 샘플 자료 200문단을 iPhone 폭·iPad에서 색인할 때의 시간·메모리·저장 용량, 그리고 MODEL-03 자료로 상위 3개 후보의 적중률을 잰다. 기준을 넘으면 재발견 화면에 붙인다.
- **바꿀 조건:** 색인이 기기에서 감당되지 않거나 후보가 기존 공통어 규칙보다 낫지 않으면 넣지 않는다.

## 7. 반대 검토

- **가정이 틀릴 수 있는 곳:** 소유자가 해도 안에서 AI로 글을 다듬고 싶어 한다는 근거는 아직 없다. 그래서 외부 전송이 없는 묶음 A부터 시작하고, 묶음 B는 승인과 실제 필요가 확인된 뒤에 한다.
- **더 단순한 대안:** 외부 AI 앱이나 OS 도구에 맡기고 해도는 아무것도 하지 않는 것. 해도에 넣을 가치가 있는 것은 작성 주체 기록, 출처 인용 대조, 버전 보존 셋뿐이다. 이 셋이 빠진 일반 채팅·생성 기능은 만들지 않는다.
- **실패 후 복구:** 작성 주체 표시는 메타데이터라 지워도 본문이 바뀌지 않아야 한다. AI 응답은 초안 제안에만 들어가므로 실패·취소가 저장된 글에 영향을 주지 않는다. Edge 함수를 끄면 묶음 B 기능만 사라지고 나머지 앱은 그대로 동작해야 한다.

### 8.3 월 비용 시나리오

- 요청 1회는 입력 약 2,000토큰(지시문·AI 지침 약 500 + 선택 영역 최대 1,500)이다.

  - Opus 5.5: 입력 $4, 출력 $20

### 8.5 승인되면 할 일과 완료 기준

위 §6의 "묶음 B — 승인 후"를 따른다. 아래 순서로 진행하고, 각 단계마다 독립 검수와 CI 녹색을 거친다.

1. Edge 함수 `haedo-ai`를 만든다. 계정 검증, 크기·월 상한, 본문 미기록을 넣는다. 운영 적용은 총괄이 한다.
2. 편집기 제안 비교를 만든다. 구간별 수락·거절·다시 시도가 되고, 수락한 구간은 AI 글로 표시한다.
3. 자료 질문을 만든다. 인용을 원문과 대조하고, 맞지 않으면 `출처 미확인`으로 표시한다.

공급자 키는 Supabase 비밀값으로만 둔다. 저장소·브라우저·로그에는 두지 않는다.

### 8.6 2026-11-04 승인 → 단계 1·2 구현

2026-11-04 소유자가 묶음 B를 승인했다(총괄 전달). 조건은 공급자 Anthropic, 전송은 선택 영역·작업 종류·AI 지침만(자료 질문은 고른 발췌 포함), 월 $10 서버 강제, 모델은 다듬기 계열 `claude-haiku-5-5`·질문·개요 `claude-sonnet-5-5`다. 이에 따라 단계 1(Edge 함수 `haedo-ai`, 월 상한 마이그레이션 `20261104090000_life_ai_usage.sql`·운영 설치 파일)과 단계 2의 기기 모듈(`assets/life/writing-ai.js`: 보낼 내용 미리보기, 명시 전송, 늦은 응답 폐기, 구간별 수락·`author:"ai"` 적용, 인용 대조)을 구현하고 격리 검사를 마쳤다. 화면 연결·운영 적용·비밀값 등록·배포·실제 공급자 호출은 하지 않았다. 흐름·허용 목록·상한·로그 정책·연결 지점·미검증과 출시 순서는 [AI 제안 서버와 기기 모듈](../design-review/writing-ai-suggestions.md)에 있다.
