# 라이프스타일 블로그 · 발견 · 자기 이해

2026-10-05 후속 사용자 요청을 반영한다. **여러 SNS와 생활 도구의 활동·글·결과물을 모아 스스로 활용하고, 선택한 내용으로 자신을 보여주는 중심 페이지**가 해도의 방향이다. 방문자는 라이프스타일 블로그를 보고, 사용자는 그 뒤의 수집·관리·추천·자기 이해를 개인적으로 활용한다. 기존 가져오기·원문·발췌·검색·백업을 기반으로 한다.

사용자는 SNS 원본의 게시·수정·삭제 없이 가져오는 것으로 충분하다고 정했고, 나머지 추천 방향을 승인하며 흐름 통합과 시각자료를 요청했다. 초기 [독립 시각 프로토타입](../design-review/activity-hub.md) 이후 묶음·선택 편집·미리보기, 선택 사본 공개, 직접 글쓰기를 차례로 구현했다. 현재 단위는 [기록 재발견](../design-review/rediscovery.md)이며 SNS 자동 연결·외부 콘텐츠 추천·AI 보고서는 후속이다. 외부 AI로 개인 자료를 전송하지 않는다.

## 백업에서 이어지는 전체 맥락

[백업 전체 재검토](context-review.md#2026-10-05-전체-백업-재검토와-v3)를 반영해 생활·여유, 깊은 대화, 친구와 나누는 작은 발견을 제품 맥락에 유지한다. 기록을 모두 콘텐츠로 만들 필요는 없으며 관리 수고를 덜어 실제 읽기·경험·감각을 위한 시간을 남긴다. 질문 → 근거와 다른 해석 → 내 반응 → 생각 수정의 대화는 추천·보고서와 독립적으로 시작하거나 끝낼 수 있다.

개인 보관 / 특정 친구·모임 / 공개 블로그는 별도 선택이다. 친구에게는 알려준 관심·허용된 공동 경험으로 같은 관심뿐 아니라 서로 다른 관심을 잇는 소재를 제안할 수 있다. 관계 기능과 실제 전송은 후속 범위이며 선택 편집·미리보기의 선행 조건이 아니다. 방문자가 나의 세계를 만나는 목적은 유지하되 현재 본문 중심 디자인을 우선한다.

[활동 중심 v4 도식](../diagrams/activity_hub_v4.mmd)은 이번 통합 흐름을, [전체 도식 안내](../diagrams/README.md)는 기존 v3의 생활 맥락과 현재/후속 기능의 경계를 함께 보여준다.

## 가져오기에서 내 페이지까지

**분산된 자료 가져오기 → 같은 활동의 기록 연결 → 개인 활용 → 보여줄 내용 선택·편집 → 내 페이지·공유 모음**으로 이어진다. 모든 자료가 끝까지 갈 필요는 없다. 읽고 보관하는 것만으로 종료할 수 있고, 추천·보고서·직접 글쓰기도 공개와 독립적으로 쓴다.

1. **가져오기:** 현재는 사용자가 선택 본문·TXT/Markdown 파일·링크를 제공한다. 자동 계정 연결과 최신 글 갱신은 서비스별 공식 접근 경로·가져올 범위·확인 시점을 검증한 뒤 추가할 후속 기능이다. 접근하지 못한 자료나 URL만 있는 글을 읽은 본문으로 표시하지 않는다.
2. **활동 연결:** 같은 전시에 대한 블로그 감상·SNS 사진 설명·개인 메모처럼 사용자가 확인한 자료를 묶는다. 원문·버전·날짜·작성자는 각각 유지하며 연결을 풀어도 원문은 남는다. 비슷한 장소·제목·날짜만으로 같은 경험을 확정하거나 원문을 병합하지 않는다. 이 묶음은 기존 연표의 사건 생성·값 변경이나 활동 완료 판정이 아니다.
3. **개인 활용:** 검색·읽기·발췌·모음·대화로 다시 활용하고, 선택 범위에서 추천과 보고서를 이용한다. 공개에 고르지 않은 자료도 개인적으로 유용할 수 있다.
4. **선택 편집:** 대표 자료, 보여줄 발췌·내 코멘트·제목·순서를 정한다. 가져온 원문을 덮어쓰지 않고 표현용 초안을 편집한다. 모든 글에 코멘트나 주제 분류를 입력하게 하지 않는다.
5. **내 페이지·공유 모음:** 방문자에게 보일 필드와 대상을 미리 보고 선택한 사본을 게시한다. 내 페이지는 대표 글·모음과 선택한 최근 활동을 보여주며, 모든 원천의 최신 글을 그대로 나열하는 것을 기본값으로 삼지 않는다. 특정인 공유는 공개 링크와 다른 접근 권한이 필요하다.

**SNS 연동은 수신 전용이다.** 해도에서 원본 SNS에 새 글을 게시하거나 기존 글을 수정·삭제하지 않는다. 해도 안의 편집·게시·갱신·철회는 해도 사본에만 적용된다. 원천에서 나중에 바뀐 내용을 받으면 별도 버전·상태로 확인하며, 이미 선택한 공개 사본을 조용히 바꾸지 않는다. 수집 실패나 연결 해제는 보관한 사본·백업·게시본의 삭제와 다르다.

## 설정의 의미와 상속

하나의 on/off로 아래 네 가지를 함께 바꾸지 않는다. 실제 화면에는 해당 작업에 필요한 설정만 드러낸다.

| 설정 | 켜거나 끌 때의 의미 | 자동으로 바뀌지 않는 것 |
| --- | --- | --- |
| 수집 | 후속 연결에서 새 자료를 가져올 원천·범위를 정하거나 중지 | 이미 보관한 자료, 분석 허용, 해도 게시본, 원본 SNS |
| 분석 | 추천·보고서에 쓸 자료 범위를 정하거나 제외 | 원문 보관과 공개 여부; 외부 AI 전송은 별도 범위 확인 |
| 공개 | 해도 사본을 누가 읽을 수 있는지 정하고 게시·갱신·철회 | 원본 SNS, 개인 보관 자료 전체, 다른 대상의 별도 공유본 |
| 화면 배치 | 허용된 글·모음을 내 페이지 어디에 표시할지 정렬·표시·숨김 | 직접 주소의 공개 접근 권한. 숨기기만으로 공개가 철회되지는 않음 |

기본은 **비공개 가져오기 → 필요한 내용만 선택 공개**다. 반복 설정은 **원천별 기본값 → 모음 설정 → 항목별 예외**로 줄인다. 각 항목에서는 실제 적용 범위와 예외를 확인할 수 있게 하고, 여러 모음에 연결된 자료의 표시·공유 범위를 한 번의 토글로 다른 모음에 전파하지 않는다. 명시적 분석 제외는 다른 모음에 넣었다고 해제되지 않는다. 기본값·배치를 바꾸거나 새 자료가 도착했다는 이유로 공개 권한을 넓히지 않는다.

사용자가 명시적으로 정한 규칙으로 새 자료를 자동 공개하는 방식은 **후속 후보**다. 도입할 때 원천·조건·공개할 필드·대상·실제 적용 예시와 중지 방식을 먼저 정해야 한다. 현재 수동 선택 공개나 이번 시각자료에 자동 게시가 포함됐다고 표시하지 않는다.

## 무엇을 표현하는 공간인가

직접 쓴 글, 다른 글을 고른 이유, 인용에 덧붙인 생각, 함께 묶은 주제가 쌓여 그 사람의 관심과 관점을 보여준다. 소개 문구와 취향 태그를 먼저 완성해야 쓰기 시작할 수 있는 구조로 만들지 않는다. ‘직접 입력은 보완만 한다’는 이전 제약은 앞으로의 글쓰기에는 적용하지 않는다. 기존 앱에서 쓰고 가져오는 방식도 계속 유효하다.

| 콘텐츠 | 표현하는 것 | 유지할 구분 |
| --- | --- | --- |
| 내가 쓴 글 | 경험·생각·질문·현재의 해석 | 초안/보관/공개, 과거 버전, 직접 쓴 문장과 인용 |
| 저장한 글과 내 코멘트 | 관심의 대상과 선택한 이유 | 원저자와 나, 저장과 동의, 나중에 읽기와 읽고 남긴 생각 |
| 활동 묶음·주제별 모음 | 흩어진 경험과 책·장소·예술·생활을 연결하는 나만의 구성 | 같은 활동과 같은 주제 구분, 원문을 합치지 않는 해제 가능한 연결, 대표 글·정렬 선택 |
| 자기 이해 보고서 | 선택한 기록에 나타난 반복·변화·다음 질문 | 관찰과 해석, 근거와 누락, 사용자 정정, 비공개 기본값 |

글을 공개하지 않아도 쓰기·읽기·추천·보고서를 이용할 수 있다. 공개 페이지는 본인이 고른 자기 표현이고, 분석 결과는 본인에게 돌아오는 해석이다. 알고리즘이 프로필 소개나 공개 모음을 자동으로 고쳐 쓰지 않는다.

## 화면 제안

기존 **기록·도구·관리**와 본문 중심 한 열, 승인한 아이콘을 유지한다. 기능이 늘 때마다 전역 메뉴와 대시보드를 추가하지 않는다.

- **기록:** 가져온 자료·직접 쓴 글·발췌·활동 묶음·모음을 읽는 개인 피드. 필요한 곳에서 연결·선택 편집·내 페이지 미리보기를 연다. 글쓰기와 가져오기를 구분한다. 추천은 필요할 때 여는 ‘발견’ 보기로 두고 개인 피드의 순서를 임의로 바꾸지 않는다.
- **내 페이지:** 소개 한 줄, 고정한 글/모음, 선택한 최근 활동으로 구성하는 방문 화면. 개인 편집 화면과 방문자 미리보기를 구분한다. 다른 사람의 글은 출처와 내 선택 이유가 드러나는 형태로 구성한다. 개인 관리 도구·공개하지 않은 자료·추천 근거를 방문자 화면에 자동 포함하지 않는다.
- **도구:** 선택한 기간·자료로 자기 이해 보고서를 열고, 읽고 싶은 주제·질문을 정리한다. 기존 목표·습관을 계속 사용할 수 있다.
- **관리:** 원천별 수집 기본값, 분석 범위·제외 항목, 글·모음의 공개 대상, 연결 상태, 동기화·백업을 다룬다. 설정은 모음과 항목에서 필요한 예외만 고치며 모든 항목을 매번 설정하지 않는다.

본문과 실제 사진이 중심이고 큰 취향 점수·성격 차트·장식용 통계는 넣지 않는다. 사진을 블로그 표현에 도입할 때는 직접 제공한 미디어의 저장·용량·대체 텍스트·백업·공개 범위를 별도로 완결한다. 현재 링크·평문 입력을 사진 수집 지원으로 표시하지 않는다.

## 추천: 관련성과 확장을 함께

추천 목적은 더 오래 머무르게 하는 것이 아니라 **읽고 싶은 다음 자료와, 지금의 생각을 넓힐 연결을 찾게 하는 것**이다. ‘나에 대해 알고 있는 정보’는 사용자가 읽고 고칠 수 있어야 한다.

1. **입력 신호:** 직접 선택한 주제·질문·읽기 목표, 본인이 쓴 글, 저장 이유·발췌·내 코멘트를 우선한다. 저장만 한 타인의 글은 약한 관심 단서이며 동의나 자신의 신념으로 간주하지 않는다. 분류·이유 입력은 선택 사항이다. 제목·링크만 있는 자료는 본문을 분석한 신호로 쓰지 않는다.
2. **후보:** 처음에는 이미 가진 자료에서 다시 읽을 후보를 찾는다. 이후 사용자가 고른 공개 제공처·RSS·공식 API 등에서 확보할 수 있는 자료를 추가한다. URL·제목·저자·확보 범위·조회 시점이 있는 실제 후보만 추천하며 없는 링크를 생성하지 않는다. 외부 후보 풀이 없으면 ‘새 콘텐츠 추천’으로 표시하지 않는다.
3. **정렬:** 첫 비교는 주제·질문·사용자가 고른 관계를 이용하는 설명 가능한 규칙과 최신순 기준이다. 같은 자료/같은 원천의 중복을 줄이고, 익숙한 관심을 깊게 읽는 글·인접 분야·다른 관점의 비중을 비교한다. 최근 관심과 오래 유지한 관심, 앞으로 배우고 싶은 관심을 구분한다. 특정 비율·가중치는 실제 평가 전 확정하지 않는다.
4. **전달:** 첫 제안은 3개 정도의 끝이 있는 목록으로 실험한다. 제목·출처·짧은 추천 이유와 ‘무엇을 더 알 수 있는지’를 보여준다. 자세한 근거는 펼쳐 본다. ‘관련 없음’, ‘이 주제 덜 보기’, ‘이 출처 제외’, ‘분석에서 제외’를 구분한다. 피드백을 주지 않았다고 거절로 간주하지 않는다.
5. **개선:** 키워드 기준에서 한국어 의미 연결이 부족한 사례가 확인되면 임베딩 검색·다양성 정렬과 비교한다. 생성형 AI는 확보한 후보의 연결 이유·읽기 질문·보고서 문장화를 돕는 후보이며 자료 존재나 소유권을 판정하지 않는다. 공급자·모델·비용은 아직 선정하지 않았다.

추천을 노출했다는 사실이나 AI가 쓴 요약을 다시 관심의 근거로 합산하지 않는다. 추천에서 유입된 저장은 그 경로를 남기고 독립적인 자발적 관심 신호와 구분한다. 같은 자료를 반복 가져와도 관심이 여러 배 강해졌다고 처리하지 않는다. 읽기 시간·클릭·스크롤만으로 이해도나 지식 성장을 단정하지 않는다. 새 사용자는 주제나 질문 하나로 시작할 수 있고, 제공된 자료가 적으면 그 한계를 그대로 보여준다.

## 자기 이해 보고서

첫 보고서는 사용자가 고른 기간·자료에 한정한 짧은 회고다. 주간/월간은 보기의 후보이며 자동 예약·알림을 먼저 만들지 않는다. 기록의 작성일, 저장한 시각, 실제 읽거나 경험한 시각을 구분한다. 옛 글을 오늘 가져왔다고 오늘 생긴 관심으로 해석하지 않는다.

| 구성 | 보고할 내용 |
| --- | --- |
| 분석 범위 | 기간·선택 자료·자기 글/타인 글·본문 확보 여부·제외/부족한 자료 |
| 관찰 | 반복된 주제·질문, 직접 남긴 표현, 명시적으로 이어진 모음과 근거 구절 |
| 변화 | 비교 가능한 과거와 현재 기록, 바뀐 표현과 유지한 관심. 자료 구성이 달라졌으면 그 차이도 표시 |
| 해석 후보 | ‘이 관심이 이어지는 것 같다’는 근거와 다른 가능한 설명. 맞음/수정/제외 가능 |
| 다음 탐색 | 사용자가 더 알고 싶다고 한 질문과 관련 자료, 작게 시도할 읽기·쓰기 제안 |

예시 출력은 익명 가정이다: **‘선택한 내 글 두 편에는 산책 중 관찰한 장면이 나오고, 저장한 세 글은 공간 디자인을 다룹니다. 둘의 연결을 더 살펴볼까요?’** 각 문장에는 실제 근거 글·버전·구절을 붙인다. 이 예시는 사용자를 분석한 결과가 아니다.

보고서는 기록에 나타난 경향을 설명한다. 몇 편의 글로 ‘당신은 이런 사람’이라고 고정하거나 성격·성장 점수를 만들지 않는다. 건강·정치·종교 등 민감한 주제를 보관했다는 이유로 개인의 상태나 정체성을 단정하지 않는다. 사용자의 정정은 원문을 바꾸지 않는 해석 수정으로 남긴다. 분석에서 제외한 근거는 이후 추천/보고서에서 빼고 기존 보고서에는 범위 변경을 표시한다. 원문 삭제·권한 철회는 별도로 처리해 해당 원문과 복제 인용·파생 해석을 기존 보고서와 늦은 응답에서도 다시 노출하지 않는다. 영향받은 부분을 숨기고 재생성을 제안하되 사용자가 독립적으로 쓴 생각까지 자동 삭제하지 않는다.

## 자료와 공개의 경계

현재 원문 버전·정확한 발췌 위치·작성자 관계를 재사용한다. 앞으로 필요한 논리 단위는 **해제 가능한 활동 연결, 선택 편집 초안과 배치, 내 글, 선택한 공개 사본, 추천 근거/피드백, 보고서와 분석 범위**다. 이것을 기존 가져오기 입력의 임의 필드에 끼워 넣거나 지금 새 DB 테이블로 확정하지 않는다. 다음 구현에서 실제 스키마 allowlist·계정별 저장·동기화·백업 호환성을 함께 설계한다.

개인 기록, 추천에 사용하도록 선택한 기록, 공개할 기록은 별도 범위다. 분석에 사용하는 자료가 공개될 이유는 없다. 공개 블로그에는 선택한 자기 글·코멘트·출처·허용한 인용만 담은 사본을 제공하며 비공개 작업공간 전체를 조회하지 않는다. 타인의 본문·사진을 저장했다고 자동 재게시하지 않는다. 공개 전 방문자 미리보기, 명시적 게시/갱신/철회와 익명 접근 검사를 완결한다. 철회해도 이미 외부에서 내려받은 사본까지 삭제됐다고 약속하지 않는다.

첫 추천·집계는 로컬에서 가능한 범위를 비교한다. 외부 분석이 필요하면 제공처·보낼 자료·보관/삭제·비용을 정하고 선택 범위만 전송한다. 서비스 키는 정적 사이트에 넣지 않는다. 요청이 끝났을 때 계정·근거 버전·허용 범위를 다시 확인한다. 가져온 본문의 명령은 분석할 자료이며 도구 실행 지시가 아니다.

## 구현 순서와 다음 완결 단위

| 순서 | 결과 | 완료 기준 |
| --- | --- | --- |
| 1. 기존 자료로 선택 편집·미리보기 | 보관한 자료의 연결·대표 글·발췌·코멘트·순서를 정하고 방문자 관점으로 보기 | 선택 초안 → 미리보기 → 수정 → 재열기 → JSON 사본 복원. 연결 해제·원문 위치·기존 자료 보존. 실제 공개는 수행하지 않음 |
| 2. 해도 내 페이지·공유 모음 게시 | 선택한 사본을 정한 대상에게 보여주고 갱신·철회 | 공개 읽기 모델·익명/수신자 권한·직접 주소 접근·실패 복구 검증. 원본 SNS에 쓰지 않음 |
| 3. 직접 글쓰기 | 자기 글과 인용·내 해석을 개인 피드에서 읽고 수정 | 초안·편집본과 불변 원문의 관계, 재열기·동기화·백업/복원. 공개를 요구하지 않음 |
| 4. 발견 | 관련 자료 재발견 → 선택 제공처의 새 콘텐츠 추천 | 최신순/규칙 기준과 비교, 후보·추천 이유·제외가 실제 결과와 일치. 외부 자료 없으면 재발견만 제공 |
| 5. 자기 이해 | 선택 자료의 관찰 → 근거 있는 해석 보고서 | 범위·근거 인용·누락·사용자 정정·제외/삭제 반영. 개인 활용은 공개·AI 실패와 독립 |
| 6. 수신 전용 연결 확대 | 실제로 접근 가능한 원천의 새 자료를 가져오기 | 제공처별 공식 경로·범위·갱신 시점·중복·버전·중단·복구 확인. 원본 SNS 게시·수정·삭제 없음 |

1~3번의 현재 구현은 각각 [영역별 동작](working-sections.md), [공개 게시](../design-review/page-publication.md), [직접 글쓰기](../design-review/direct-writing.md)에 기록했다. 4번의 첫 단위는 [로컬 재발견](../design-review/rediscovery.md)이며 이후 순서는 실제 입력·편집 부담에 따라 조정한다. 직접 글쓰기·추천·보고서와 원천 연결의 작은 비교는 1~2와 병렬 준비할 수 있다. 공개 블로그·에디터·모든 분야 도구·자동 수집의 완료를 개인 활용이나 미리보기의 선행 조건으로 만들지 않는다. 연표 값·계산과 LPE 보류는 유지한다.

**현재 단위는 이미 보관한 기록의 재발견이다.** 기준 기록 → 관련 기록과 근거 → 제외/복원 → 묶음 검토까지 완결한다. 외부 콘텐츠나 자기 이해 보고서는 로컬 연결의 유용성을 확인한 뒤 확장한다. 활동 연결·선택 편집·에디터·공개 블로그·추천 후보별로 착수할 때 최신 공식 배포·라이선스·유지보수·기존 앱과의 적합성을 [오픈소스 검토](open-source-review.md)에 비교한다. CMS·벡터 DB·AI 서비스의 도입을 확정하지 않았다.

## 성공을 확인하는 방법

root가 제품·디자인을 책임지고 데이터 담당은 글/원문/공개 범위, 추천 담당은 근거·후보·피드백, 검증 담당은 독립 반례와 실제 기기 체험을 맡는다. 앞선 제품 방향 검토는 설계 검토였으며, 이번 통합 시안의 실제 브라우저 검사는 [시각자료 기록](../design-review/activity-hub.md)에 별도로 남긴다.

- 익명 자료로 최신순 통합과 대표 글·선택한 최근 활동을 비교하고, 표현 만족·선택 부담·방문 범위의 이해를 확인한다. 이번 프로토타입의 실제 확인 범위는 [시각자료 검토](../design-review/activity-hub.md)에 남긴다.
- 활동 연결을 해제해도 각 원문·출처·발췌가 남고 연표 값·계산이 바뀌지 않는지 확인한다.
- 수집 중지·분석 제외·화면 숨김·공개 철회를 구분하며, 새 글 도착이나 모음 이동으로 공개 범위가 넓어지지 않는지 확인한다.
- 해도에서 코멘트·배치·공유본을 바꿔도 원본 SNS에 게시·수정·삭제 요청을 보내지 않는지 확인한다.
- 저장한 반대 의견을 자신의 주장으로 쓰지 않는지, 타인 인용과 내 코멘트를 분리하는지 확인한다.
- 동일 자료 반복 가져오기·추천 재노출·AI 요약이 관심을 증폭시키지 않는지 대조한다.
- 오래된 글의 일괄 가져오기를 최근 취향 변화로 보고하지 않는지 확인한다.
- 링크만 있거나 자료가 적을 때 본문 해석·변화·지식 성장을 만들어내지 않는지 확인한다.
- 제외/삭제 후 추천·보고서 근거와 공개 미리보기에서 관련 비공개 내용이 남는지 확인한다.

추천 평가는 익명 한국어 자료 묶음에서 관련성·다양한 출처·새 연결·중복을 기준과 비교하고, 실제 사용에서는 ‘도움 된 연결인가’, ‘왜 추천했는지 이해하는가’, ‘내 페이지가 나를 잘 표현하는가’를 묻는다. 표현 만족·이해 성장은 클릭률이나 자료 수로 대신 측정하지 않는다. 출처 오류·자료 유출·거짓 인용이 없다는 검증과 추천이 유용하다는 사용자 평가는 별도 결과로 남긴다.
