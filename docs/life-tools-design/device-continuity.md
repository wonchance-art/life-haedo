# 기기 간 이어쓰기: 다음 구현 계약

2026-10-05 설계. **이 문서는 아직 구현·설치된 동기화가 아니다.** Mac·iPad·iPhone에서 같은 계정으로 읽고 정리하는 흐름을 다음 제품 우선순위로 둔다.

## 현재 경계

| 데이터 | 현재 이동 방법 |
| --- | --- |
| 저장한 원문·버전·발췌 | 사용자가 연결한 작업공간의 기존 동기화, 자료 백업 |
| 묶음·내 페이지·회고·관련 기록 제외 | 이 브라우저의 계정/공간별 구성, 자료·구성 통합 JSON 사본 복원 |
| 가져오기 검토·글쓰기 초안 | 이 브라우저의 계정/공간별 초안 |
| 공개 페이지 | 명시 게시한 독립 사본. 비공개 편집 변경을 자동 반영하지 않음 |

같은 계정 로그인은 로컬 구성·초안이 자동으로 보인다는 뜻이 아니다. 백업은 복구/이동 수단이며 자동 이어쓰기를 대신하는 장기 해결책이 아니다.

## 권장 구현 순서

1. **구성부터**: 기존 원문 연결에 명시적으로 추가하는 비공개 구성 동기화. 원문과 별도 revision/CAS를 두되 연결된 정확 버전이 도착하기 전에는 자동 최신 대체나 참조 삭제를 하지 않는다. 로컬 미연결 자료는 로그인만으로 업로드하지 않는다. 연결 화면은 업로드 범위와 기기 차이를 짧게 보여준다.
2. **충돌 복구**: 다른 기기의 새 revision을 발견하면 미저장 입력을 유지하고 비교/사본 보관/최신 읽기를 제공한다. last-write-wins로 코멘트·표시 선택을 덮어쓰지 않는다. 재시도는 operation ID로 멱등이며 응답이 사라지면 서버 결과부터 확인한다.
3. **초안 이어쓰기**: 구성이 안정된 뒤 글쓰기 초안을 선택 동기화한다. 같은 초안을 두 기기에서 수정하면 양쪽을 보존한다. 가져오기 파일의 원본 대용량 바이트는 이 범위에서 자동 전송하지 않는다.
4. **읽던 위치**: 버전 ID·유효 UTF-16 위치·갱신 시각만 후보로 삼는다. 먼저 로컬 위치를 유지하고 다른 기기 위치로 갈지는 사용자가 선택한다. 모든 읽기 행동을 분석 로그로 수집하지 않는다.

## 구현 전 필요한 근거와 승인 범위

기존 Supabase RPC·RLS·버전 참조·재시도 계약과 통합/별도 테이블을 비교하고, 최신 관련 오픈소스의 충돌·오프라인 처리 접근을 검토한 뒤 최소 스키마를 결정한다. 운영 SQL은 원문과 롤백/설치 검사를 준비하고 기존 관리자 권한 경로로 실행한다. 문서만으로 SQL이 설치되었다고 보지 않는다. 기존 사용자 연결 동의보다 넓게 전송하지 않는다.

## 완료 시나리오

- A 기기에서 원문 2개를 묶고 코멘트를 적은 내 페이지를 저장 → 연결된 B 기기에서 같은 정확 버전/순서/표시로 열기.
- B 오프라인 편집 중 A도 변경 → 재연결 후 양쪽 입력 보존, 충돌을 선택해 해소.
- 계정 변경·작업공간 변경·로그아웃 도중 늦은 응답이 와도 다른 계정 화면/저장소에 반영되지 않음.
- 백업 내보내기/새 사본 복원으로 원문 참조가 유효하며 원래 구성은 보존됨.
- 비공개 구성 동기화·표시 변경이 기존 공개 사본을 게시·갱신·철회하지 않음.
- 브라우저 모의 검증과 Mac/iPad/iPhone 실제 기기 전환을 분리해서 보고.
