# 기기 간 이어쓰기

2026-10-06 KST. 첫 단위인 **비공개 구성 이어쓰기**의 앱·SQL을 구현했다. 운영 설치·병합·배포는 아직 완료하지 않았다. [설치 인계](composition-installation.md)와 [검증 기록](../design-review/composition-continuity.md)을 구분한다.

## 사용 흐름과 경계

A에서 원문을 묶고 내 페이지 코멘트를 저장한 뒤, B에서도 같은 원문 버전과 순서·표시로 이어 편집한다. 먼저 각 기기에서 기존 원문 작업공간을 연결/받고, 관리 → 기기 간 동기화 → `묶음·내 페이지 이어쓰기`를 따로 시작한다. 첫 수신에 서버 구성이 있으면 양쪽을 비교해 선택한다. 로그인이나 기존 원문 연결만으로 새 전송 범위를 넓히지 않는다.

| 데이터 | 이동 방법 |
| --- | --- |
| 저장한 원문·불변 버전·발췌 | 기존 작업공간 동기화, 자료 백업 |
| 묶음·비공개 내 페이지·회고·관련 기록 제외 | 이번 별도 구성 연결, 자료·구성 통합 JSON |
| 가져오기 검토·글쓰기 초안 | 해당 브라우저의 계정/공간별 초안. 이번 전송에서 제외 |
| 공개 페이지 | 명시 게시한 독립 사본. 구성 동기화로 갱신·철회하지 않음 |
| 충돌 복구 사본 | 선택하지 않은 구성과 원문을 이 브라우저에 함께 보관. 직접 다운로드 가능 |

브라우저 데이터를 지우면 미전송 내용과 기기 복구 사본이 사라질 수 있다. 복구 사본은 자동 서버 백업이 아니다. `복구 사본 내려받기`의 통합 JSON을 기존 `자료·구성 백업`에서 새 작업공간으로 복원한다. 새 사본은 원래 서버와 자동 연결하지 않는다.

## 선택한 구현

[Yjs·Automerge·RxDB 공식 릴리스 비교](open-source-review.md)를 거쳐 기존 CAS 저장 방식을 확장했다. 실시간 공동 편집이 아닌 개인의 선택적 기기 이동이며, 불변 원문 버전과 공개 사본의 경계를 유지하는 것이 먼저다. 새 런타임 라이브러리를 넣지 않았다. 잦은 충돌 때문에 전체 구성 선택이 실제 사용을 방해하면 필드 단위 병합/CRDT를 다시 평가한다.

- `composition-remote.js`는 공용 Google Auth가 검증한 기존 SDK를 제한된 composition RPC 범위로 빌린다. 별도 로그인·세션 복사·키 저장을 만들지 않는다.
- `composition-sync.js`는 원문 도착을 먼저 확인하고 별도 revision/CAS로 구성을 보낸다. `source_revision`보다 원문 수신이 뒤처지면 적용하지 않는다. 서버의 원문 revision은 참조가 모두 존재한다는 증거가 아니므로, 없는 정확 버전은 누락 상태로 보존하고 최신으로 치환하지 않는다.
- 저장소의 `compositionSync`와 `compositionHead`는 별도 메타데이터다. outbox는 요청 ID·본문·비교 revision·원문 기준을 고정한다. 응답이 유실되면 **같은 요청을 새 서버 읽기보다 먼저 재전송**하고 저장 영수증을 확인한다. 전송 중 로컬 편집은 다음 outbox로 남는다.
- 로컬 미변경 상태의 새 서버 구성만 자동 적용한다. 양쪽 변경 또는 첫 수신은 비교를 요구한다. 선택 시 원문+선택하지 않은 구성을 같은 IndexedDB 트랜잭션에 먼저 보존한다. 저장 공간 부족이나 기준 변경은 선택 적용 전체를 중단한다.
- 연결 중지·계정 변경은 이전 비동기 결과를 적용하지 않는다. 중지 후 재개는 멈춘 이전 네트워크 요청의 완료를 기다리지 않는다. 서버가 이미 수락한 전송은 중지 버튼으로 되돌리지 않으며, outbox 영수증을 보존해 재연결 때 확인한다.
- 두 테이블/여섯 함수의 운영 SQL과 read-only 설치 검사는 별도다. 직접 테이블 권한은 닫고 소유자 RPC만 허용한다. 원문 RPC와 동일한 계정/작업공간 advisory lock을 쓴다.

## 실패 후 사용 결과

- B 오프라인 편집 중 A도 변경: 양쪽을 덮어쓰지 않고 비교한다. 같은 개수라도 원문 제목·정확 버전·본문 일부·표시 차이가 보인다.
- 비교 뒤 로컬 또는 서버 변경: 오래된 선택을 거부하고 다시 비교한다.
- 서버 구성 삭제/누락: 자동 재생성하지 않는다. 기기 내용과 백업 경로를 유지한다.
- SQL 미설치: 준비 필요 오류를 보여주고 최초 연결 상태를 쓰지 않는다.
- 계정 전환/작업공간 이동: 고정 계정 저장 핸들과 세대 검사로 이전 응답을 다른 화면/저장소에 넣지 않는다. 저장 중 입력의 기존 충돌 처리는 그대로다.

## 다음 단위

1. 운영 SQL 설치·읽기 전용 HTTP·CI 이후 배포하고, 실제 Mac/iPad/iPhone에서 같은 구성의 전환을 확인한다. 화면 폭 모사와 실제 기기를 구분한다.
2. 이 단위가 안정되면 글쓰기 초안의 명시 연결과 동시 편집 보존을 구현한다. 가져오기 파일의 대용량 바이트를 자동 전송하지 않는다.
3. 읽던 위치는 정확 버전·유효 UTF-16 위치·갱신 시각만 후보로 삼는다. 다른 기기의 위치로 갈지는 사용자가 선택하며 모든 읽기를 분석 로그로 수집하지 않는다.
