# 기록을 돌아보고 한 권의 글로 엮기

갱신일 **2026-10-08 KST**. 사용자의 최신 우선순위는 올해 20대를 마무리하며 지난 글을 돌아보고, 생각의 흐름을 이해한 뒤 ‘20대’ 또는 나이와 무관한 특정 주제의 책자로 엮는 것이다. [기존 자기 이해 설계](lifestyle-blog.md#자기-이해-보고서)를 구체화한다. 이 문서는 목표와 단계별 계약이며 실제 개인 기록 분석·책자 완성·공개 게시를 수행했다는 보고가 아니다.

**이번 단위는 여러 책 프로젝트에 제목·기간·질문을 두고, 장별 원고와 선택한 근거를 목차 순서로 저장·편집하는 흐름이다.** 앞선 [회고 읽기 단위](../design-review/reflection-reading.md)의 단일 회고는 그대로 유지한다. 책별 Markdown까지 다루되 근거에 연결한 자동 AI 분석, 주장·반례 모델, PDF·인쇄 출력·공개 출판은 후속이다. 현재 책 구현의 기능·브라우저·운영 SQL 검증은 진행 중이며, 이전 회고의 검사 결과로 책 기능의 완료를 대신하지 않는다.

## 만들고 싶은 결과

책은 자신을 평가하는 성적표보다 **당시의 글과 지금의 해석을 함께 읽을 수 있는 선택된 이야기**다. 반복된 관심뿐 아니라 바뀐 관점, 아직 답하지 못한 질문, 기록에 드러나지 않은 시기도 남길 수 있다. 타인의 글을 저장한 이유가 명시되지 않았다면 동의·취향·신념을 추정하지 않는다.

‘20대’는 첫 사용 장면의 프로젝트 제목·범위다. 생년이나 나이 계산 방식을 추정해 기간을 채우지 않는다. 실제 기간은 사용자가 선택하며, 같은 구조로 ‘일과 쉼’, ‘도시에서 살기’, ‘관계에 대한 생각’처럼 기간 제한 없는 주제를 다룰 수 있어야 한다. 모든 해의 자료를 채우거나 모든 글을 분류해야 시작할 수 있는 설계는 피한다.

```mermaid
flowchart TD
    A[기간 또는 주제와 질문 정하기] --> B[글을 고르고 정확한 원문 버전 읽기]
    B --> C{읽는 순서 선택}
    C --> D[작성 시점별 흐름]
    C --> E[주제별 연결]
    D --> F[근거에 연결해 현재 생각 적기]
    E --> F
    F --> G[해석 수정·제외·반례 확인]
    G --> H[장과 목차 구성]
    H --> I[원고 편집]
    I --> J[개인용 책자 출력]
    I --> K[공개할 내용 별도 선택]
    K --> L[공개용 원고 확인·출력]
    F -. 기존 회고의 중간 산출물 .-> M[선택 자료와 메모의 Markdown 원고]
    M -. 외부 편집에서 계속 .-> I
    G -. 질문을 바꾸거나 자료를 더 읽기 .-> B
```

흐름은 되돌아갈 수 있다. 시간순으로 읽다가 주제별로 묶어도 원문이나 선택 범위를 바꾸지 않는다. 목차를 먼저 정한 뒤 맞는 글만 끼워 넣는 방식도 강제하지 않는다.

## 전체 목표와 이번 책 단위의 경계

| 단계 | 최종적으로 필요한 경험 | 이번 책 단위의 범위 |
| --- | --- | --- |
| 프로젝트의 기간·주제·질문 | ‘20대’, 특정 기간 또는 주제로 프로젝트를 만들고 다시 열기 | 책별 제목·선택 기간·질문을 저장. 기간은 설명용이며 근거를 자동 선택·제외하지 않음. 기존 회고 화면의 세션 보기 조건과 구분 |
| 근거 읽기 | 선택한 정확 버전의 원문·발췌·출처를 오가기 | 장별 정확 버전을 선택하고 원문으로 복귀. 동일 원문을 여러 장에서 참조 가능. 구절 단위 책 전용 참조 모델은 후속 |
| 자기 해석 | 주장·관찰마다 근거와 반례를 붙이고 수정·제외하기 | 장의 평문 원고에 직접 서술. 선택 원문은 장 전체의 근거 목록이며 각 문장을 자동 입증하지 않음. 자동 분석·주장/반례 모델은 후속 |
| 장·목차 | 장마다 질문·선택 구절·원고를 배치하고 순서를 바꾸기 | 장 추가·제목·순서·원고·원문 선택을 저장. 장 배열 순서가 한 단계 목차이며 자동 주제 분류·다단계 장 구조는 없음 |
| 원고 편집 | 당시 원문·타인 인용·현재 서술을 구별하며 문장을 다듬기 | 기존 textarea 기반 장별 작성·저장·재열기. 독립 문장 개정 이력·리치 서식·Markdown 역가져오기는 후속 |
| 책자 출력 | 한글 조판·목차·쪽수·주석·이미지 등을 검토해 개인용/공개용 출력 | 책 질문·장 순서·원고·출처의 UTF-8 Markdown, 본문 포함은 명시적 선택. PDF·전자책·인쇄본·공개 게시 완료로 표시하지 않음 |

**현재 우선순위는 특정 주제의 책 프로젝트와 장 구성을 저장하는 단위**다. 실제 원고를 엮으며 어떤 근거·서식·출력이 필요한지 확인한 뒤 다음 범위를 정한다. SNS 연결이나 자동 수집을 완료해야 책 작업을 시작할 수 있는 순서로 만들지 않는다.

## 근거·작성자·시간을 다루는 기준

### 원문과 현재 해석

| 내용 | 근거와 표시 | 바뀔 때 보존할 것 |
| --- | --- | --- |
| 당시 내가 쓴 글 | `originalAuthor.relation=self`인 선택 원문. 실제로 직접 쓴 글인지와 가져온 자기 글인지도 기존 출처대로 유지 | `SourceVersion.id`를 고정. 지금의 견해와 같다고 가정하지 않음 |
| 저장한 타인의 글 | 작성자·출처·확보 범위를 표시. 저장 이유가 있다면 현재 메모 또는 당시 메모와 따로 읽음 | 내 발언이나 신념으로 바꾸지 않음. 선택했다는 사실만으로 전체 재게시하지 않음 |
| 작성자 미확인 자료 | 미확인을 그대로 보여주며 저자를 추정하지 않음 | 다른 자료의 작성자 정보를 자동 승계하지 않음 |
| 지금 쓰는 회고 | 현재 사용자가 쓰는 해석·기억·질문. 과거 원문 인용과 문단을 구분 | 원문을 고치지 않는 현재 서술. 근거가 없는 기억도 쓸 수 있으나 원문으로 확인한 사실처럼 표시하지 않음 |
| 후속 AI 제안 | 실행할 때 선택한 근거와 생성 기원, 제안 상태를 표시 | 채택 후에도 AI 기원 유지. 근거 없는 성격 단정·성장 점수·진단은 만들지 않음 |

향후 해석 한 개에는 관찰/해석의 구분, 근거 구절, 다른 설명 또는 반례, 사용자의 수정·제외 상태가 필요하다. 예를 들어 ‘혼자 있는 것을 좋아하게 됐다’는 결론에는 그 방향의 글뿐 아니라 함께하는 시간을 원한 글도 검토할 수 있어야 한다. 글 몇 편의 차이를 성격 변화로 단정하지 않는다. **첫 메모 화면이 이런 구조화된 분석 기능을 갖췄다고 표시하지 않는다.**

발췌는 기존 `{sourceId, sourceVersionId, locator}`와 해당 원문의 UTF-16 `[start,end)` 계약을 따른다. 선택한 옛 버전에 연결된 근거를 최신 버전에서 찾은 것처럼 보이지 않는다. 원문이 누락되면 누락을 표시하고 비슷한 글로 대신 채우지 않는다. URL만 있는 자료는 본문을 읽거나 분석한 근거로 사용하지 않는다.

### 작성일·경험일·가져온 날

- **원 작성 시점:** 원문에서 확인한 `originalCreatedAt`. 연도별 보기의 기준으로 사용할 때 그 의미를 표시한다. 날짜의 해석이 불가능하거나 미상이면 별도 ‘시점 미확인’으로 남긴다.
- **경험 시점:** 글에서 회상하는 사건의 때. 2025년에 쓴 2018년 이야기를 두 날짜 중 하나로 자동 합치지 않는다. 현재 모델에는 독립 경험일 필드가 없으므로 첫 구현은 이를 추출·저장한 연표처럼 표시하지 않는다.
- **가져온/저장한 시점:** 해도에 들어온 때다. 오래된 글을 오늘 가져왔다고 올해의 관심이나 경험으로 집계하지 않는다.
- **현재 회고 시점:** 지금 해석을 적은 맥락이다. 현재 구성 revision이 각 문장의 작성 이력을 보장하지는 않는다.

연도별 자료 수는 선택한 **원문 버전 수**이며 경험·노력·성장의 양이 아니다. 같은 글의 두 버전을 선택하면 두 근거로 표시하되 두 경험으로 세지 않는다. 기록이 없는 해는 실패·공백 인생·관심 상실의 증거가 아니다. 정확한 날짜·분류를 몰라도 글을 선택하고 현재 생각을 적을 수 있어야 한다. 기존 연표 데이터와 계산은 바꾸지 않는다.

### 기존 회고의 시간순과 주제별 보기

시간순 보기는 확인한 원 작성 시점을 따른다. 첫 주제별 보기는 **현재 회고에서 고른 버전과 기존 묶음의 버전 목록이 겹치는 범위**를 사용한다. 묶음 제목은 사용자가 정한 연결이며 자동 분석한 주제가 아니다. 발췌 주제 전체를 새로 분석하거나 제목의 단어만으로 심리적 주제를 부여하지 않는다. 한 글이 여러 묶음에 걸칠 수 있고 묶음이 없는 글도 남는다. 같은 글을 여러 곳에서 보여주더라도 원문을 복제하거나 전체 선택 개수를 중복으로 늘리지 않는다.

기존 회고에서 정렬·그룹·기간은 읽기용 보기 조건이다. 회고의 기간 선택은 현재 화면 세션에만 유지한다. 이번에 별도로 저장할 **책의 기간**은 프로젝트 설명이고, **장 배열의 순서**가 목차다. 세 가지를 같은 설정으로 취급하지 않는다. 회고 보기나 책 기간을 바꿨다고 선택한 근거·원고가 사라지거나 원문의 날짜·주제가 바뀌면 안 된다.

## 기존 회고: 선택 → 읽기 → 질문 → 메모 → 원고

1. **선택:** 현재 작업공간에서 회고할 원문 버전을 직접 고른다. 자기 글·타인 글·미확인·본문 없음의 실제 범위를 읽을 수 있다. 선택 해제는 이번 회고의 범위를 줄이는 동작이며 원문 삭제나 모든 분석에서의 영구 제외가 아니다.
2. **읽기:** 연도별 또는 기존 주제별로 보고 정확한 원문을 연다. 날짜 없는 글·본문 없는 링크·누락된 참조를 별도로 표시한다. 원문을 읽고 돌아오면 선택과 메모를 이어간다.
3. **질문:** 고정된 짧은 질문을 사용자가 선택했을 때만 메모에 추가한다. 예: ‘그때 중요했던 것은 무엇이었나?’, ‘지금 읽으면 다르게 보이는 부분은?’, ‘이 해석과 맞지 않는 글도 있나?’, ‘다음 글에서 더 묻고 싶은 것은?’ 질문은 분석 결과가 아니며 답을 미리 만들어 넣지 않는다. 기존 글을 지우지 않고 추가하고 한도 초과 시 입력을 보존한다.
4. **메모:** 현재 생각을 자유롭게 쓴다. 필요한 경우 원문 제목·근거 구절을 직접 연결해 적는다. 메모 전체가 특정 원문을 입증하는 주장으로 자동 분해되는 기능은 없다. 자료를 빼도 사용자가 쓴 메모는 자동 삭제하지 않으므로 더 이상 선택되지 않은 근거를 언급하는지 사용자가 검토할 수 있어야 한다.
5. **원고:** 선택한 자료, 읽기 기준, 현재 메모를 UTF-8 Markdown으로 내보낸다. 내보내기에 무엇이 포함되는지 알리고, 선택하지 않은 작업공간 전체 원문을 몰래 포함하지 않는다. 실제 파일 보관·재열기로 완료를 확인한다.

질문·집계가 본문을 밀어내지 않게 기존 회고의 단일 흐름과 공통 컴포넌트를 재사용한다. 상시 큰 분석 대시보드·점수판·새 최상위 메뉴는 필요하지 않다. 연도/주제 전환, 원문 열기, 질문 추가, 원고 내보내기에 접근 가능한 이름을 주고 한글 입력과 읽기의 공간을 우선한다.

### 기존 회고 Markdown의 계약

내보내는 것은 개인이 계속 편집할 **원고 재료**다. 목차가 완성된 출판용 책이나 복원 백업과 구분한다.

- 기본값은 **현재 메모와 전체 선택 근거의 출처 목록**이다. 원문 본문은 별도로 선택해 포함한다. 기간·주제 보기를 바꿨다고 전체 선택 목록이 좁아지거나 원고의 범위가 자동 변경된 것처럼 표시하지 않는다. 본문·발췌를 포함하면 포함한 실제 범위와 누락을 함께 표시한다.
- 각 근거에 원천 ID·정확 버전 ID·제목·원저자 관계·원 작성 시점·URL·본문 확보 범위를 유지한다. 구절을 내보낼 때는 실제 위치와 원문을 함께 대조한다. 링크·ID만으로 외부 편집기에서 비공개 앱 원문을 항상 열 수 있다고 약속하지 않는다.
- 원문의 Markdown·HTML·백틱 때문에 파일의 장 구조나 작성자 표시가 바뀌지 않도록 기존 안전한 평문 내보내기 방식을 재사용한다. 원문을 읽기 좋게 바꾸더라도 원본 저장본·발췌 위치를 변경하지 않는다.
- 다운로드는 공개 게시나 외부 AI 전송이 아니다. 개인 메모·원문 URL·타인 인용이 파일에 포함될 수 있음을 범위 표시로 알린다. 공개본은 별도로 고르고 검토한다.
- 원고 파일을 수정해도 앱의 원문·회고·공개 사본은 자동 변경되지 않는다. 앱의 재사용 가능한 보존·사본 복원에는 기존 자료·구성 JSON 백업을 함께 사용한다.

## 이번 책 프로젝트의 모델과 사용 흐름

기존 [`Workbench.empty()`·`validate()`](../../assets/life/workbench.js)의 `reflection: {versionIds: [], note: ''}`는 그대로 유지한다. 같은 `life-workbench-v1` 구성에 **optional `books` 배열**을 더한다. 이전 파일에 `books`가 없어도 수용하며, 회고문에 숨은 JSON을 넣거나 내 페이지 항목을 책 장으로 재해석하지 않는다.

```js
books: [{
  id, title, fromYear, toYear, question,
  chapters: [{ id, title, note, versionIds: [] }]
}]
```

`fromYear`·`toYear`는 빈 문자열 또는 0보다 큰 네 자리 연도 문자열이다. 둘 다 있으면 시작이 끝보다 늦을 수 없다. 기간을 비워 나이와 무관한 주제의 책을 만들 수 있다. 이 값은 **책에 적어 두는 기간 메타데이터**이며 장에 담을 원문의 연도를 제한하지 않는다. 원문 선택을 바꾸지 않고 책의 기간만 수정할 수 있어야 한다.

| 저장 단위 | 이번 계약 |
| --- | --- |
| 책 | 고유 ID·제목·기간·질문. 최대 20개. 제목은 최대 500 UTF-16 코드 단위, 질문은 최대 20,000 |
| 장 | 고유 ID·제목·현재 원고 `note`·선택 원문 버전 목록. 책마다 최대 100장. 제목 최대 500, 장 원고 최대 20,000 UTF-16 코드 단위 |
| 목차 | `chapters` 배열 순서. 장을 위/아래로 옮겨도 장 ID·원고·원문 참조를 그대로 이동. 제목·작성일로 자동 정렬하지 않음 |
| 장의 근거 | 장당 최대 1,000개의 고유 `versionIds`. 같은 버전을 다른 장이나 다른 책에서 다시 참조할 수 있음. 원문을 복제·변경하지 않음 |
| 전체 한도 | 책·묶음·페이지·회고 등을 합친 Workbench 구성의 UTF-8 JSON이 2 MiB 이하. 각 항목 최대치를 모든 장에서 동시에 채울 수 있다는 보장은 아님 |

사용 흐름은 **도구 → 책 → 새 책 또는 현재 회고에서 시작 → 제목·기간·질문 → 장 추가 → 근거 선택·원고 작성 → 목차 순서 조정 → 저장·재열기 → 책 원고 내보내기**다. root가 기존 본문 중심 화면과 공통 아이콘·입력 스타일을 통합한다. 새 최상위 메뉴나 별도 편집기 프레임은 만들지 않는다.

현재 회고에서 시작하는 조작은 선택한 원문 목록과 회고문을 **새 책의 장으로 복사**한다. 원래 `reflection`은 지우거나 연결하지 않는다. 복사 후 회고를 고쳐도 책에 자동 전파하지 않고, 책을 고쳐도 회고를 바꾸지 않는다. 장·책 삭제는 해당 구성·원고·선택 참조를 지우는 범위를 알리며 원문·발췌·기존 회고를 지우는 동작과 구분한다.

장은 원문을 그 자리에 합쳐 넣은 사본이 아니라 **현재 원고와 근거 참조의 조합**이다. 옛 버전을 선택하면 그 버전을 읽고, 최신 버전이 생겨도 참조를 바꾸지 않는다. 본문 미확보·부분 제공·작성자 미확인·없는 참조는 그대로 설명한다. 근거를 장에서 제외해도 이미 직접 쓴 원고의 관련 문장을 자동 삭제하거나 검증된 문장으로 표시하지 않는다.

### 책별 Markdown과 백업

책별 Markdown은 책 제목·기간·질문, **장 배열의 목차 순서**, 각 장의 원고와 선택 근거의 출처가 기본이다. ‘원문 본문 포함’을 명시적으로 선택할 때만 실제 확보한 텍스트를 추가한다. 책의 기간 밖인 자료라도 장에서 선택했다면 포함하며, 같은 버전이 두 장의 근거일 수 있음을 그대로 유지한다. 책에 담지 않은 원문·다른 책·기존 회고는 끼워 넣지 않는다.

기존 [`Reflection`](../../assets/life/reflection.js)의 작성 시점·정확 버전·출처 표시와 안전한 텍스트 내보내기를 재사용한다. 사용자가 작성한 장 원고와 원문 인용의 구분을 유지하며 원문의 HTML·Markdown을 앱에서 실행하지 않는다. 작성자·원형 URL·원문 버전·본문 확보 범위·누락을 파일에서 확인할 수 있어야 한다. 이 파일은 공개 게시·PDF·mdBook/novelWriter 프로젝트 파일이 아니다.

다운로드 전 해당 구성 저장을 완료하고, 실패하면 원고를 유지한다. 복원에는 자료·구성 JSON을 사용한다. 새 사본 복원은 책·장 ID와 모든 `versionIds`를 함께 재매핑하고 원문의 정확 버전·목차 순서를 보존해야 한다. Markdown을 고친 뒤 가져온다고 책 구조·장 ID까지 자동 복원되지는 않는다.

### 구성 이어쓰기와 운영 설치

책은 기존 Workbench 구성 저장·CAS·선택한 구성 이어쓰기 경계 안에서 다룬다. 책 추가만으로 새 원격 연결이나 공개 사본을 만들지 않는다. 기존 연결을 사용할 때도 원문 선행·정확 버전·실패 후 로컬 입력 보존을 유지하고, 책 구성 전송 범위가 실제 안내와 일치해야 한다.

서버가 optional `books`를 검증하려면 **기존 구성 SQL validator를 additive 방식으로 갱신**해야 한다. SQL 파일 작성·로컬 함수 검사와 실제 Supabase 설치·권한·왕복 검사는 별도다. **Local 설치·검증 대기**로 보고하며, 구형 서버가 책 필드를 거절할 때 책을 조용히 제거해 전송하거나 서버 저장 완료로 표시하지 않는다. 기존 회고·책 없는 v1·묶음/페이지와 원문 자료를 보존한다.

### 이 모델에도 아직 없는 것

이번 `books`는 여러 프로젝트·한 단계 목차·장별 평문·근거 선택을 저장하는 최소 모델이다. **문장별 주장/반례/인용 위치, AI 제안 기원과 수락 이력, 원고 개정본, 장의 계층, 공개용 편집 사본, PDF 조판**은 없다. 장에 근거가 있다는 사실이 그 장의 모든 서술을 입증하지 않는다. 이 후속 구조는 실제 책 작업에서 필요한 범위를 확인하고 모델·동기화·백업·제외/삭제 이후 처리까지 별도로 설계한다.

## 기존 Markdown과 편집을 재사용하는 이유

이번에는 [mdBook v0.5.4·novelWriter v26.2.1 공식 비교](open-source-review.md#책-프로젝트목차원고--기존-편집과-출처-모델-위에-구성-추가)를 새로 수행했다. 라이선스·릴리스·유지관리·공개 권고·태그 문서를 확인했고 두 도구의 **목차 순서와 원고/참고 자료 분리, 출력 내용 선택**을 설계 참고로 택했다. 소스·자산·파서를 복사하거나 앱을 설치하지 않았다.

mdBook은 Markdown 파일에서 온라인 책을 build하는 Rust 도구이고 novelWriter는 Python·Qt 데스크톱 편집기다. 둘 다 해도의 브라우저 계정·불변 원문 버전·기존 백업 계약을 바로 대체하지 않는다. 앞선 기본 textarea·편집기 비교는 재사용하되 CodeMirror·Tiptap의 당시 버전을 이번에 재조회한 것으로 보고하지 않는다. **새 runtime 의존성 없이** 기존 입력·Workbench·Reflection을 확장한다.

[`Core.toMarkdown()`](../../assets/life/core.js)은 작업공간 전체 읽기 내보내기이므로 그 결과를 ‘책 한 권’으로 표시하지 않는다. 책·장의 명시적 범위에 기존 평문 보존·출처 표시 계약을 적용한다. 한글 조판·쪽나눔·각주·이미지·폰트 포함·인쇄 여백은 Markdown 다운로드만으로 해결되지 않으며, 이 단계에 필요한 출력 도구를 선택한 것은 아니다.

## 기존 회고의 실험 기준

개인 계정 자료 대신 익명 샘플로 **내 글 두 편, 저장한 타인 글 한 편, 날짜 없는 글, 링크만 있는 자료, 같은 글의 옛/새 버전**을 준비한다. 서로 다른 견해가 담긴 글을 포함한다. 연도별 선택 → 주제별 재검토 → 정확한 옛 원문 열기 → 질문 추가 → 메모 → 원고 다운로드 → 재열기까지 한 번에 체험한다.

| 확인 영역 | 첫 단위의 완료 조건 |
| --- | --- |
| 근거와 시점 | 정확 버전·작성자·확보 범위가 UI와 파일에서 맞음. 가져온 날로 원 작성일을 채우지 않으며 시점 미확인 자료가 사라지지 않음 |
| 보기 전환 | 연도/주제 전환이 선택·메모·원문을 바꾸지 않음. 중복 주제 노출을 경험 횟수로 집계하지 않음 |
| 질문과 입력 | 사용자가 고른 질문만 기존 메모 뒤에 추가. 질문 연속 선택·한글 조합·한도 도달·저장 오류에서도 입력을 잃지 않음 |
| 선택·제외 | 자료를 빼면 선택 근거와 다음 원고 범위에 반영. 원문이나 독립 메모를 자동 삭제하지 않음. 구조화되지 않은 메모의 인용이 자동 갱신된 것처럼 표시하지 않음 |
| 저장·복구 | 새로고침·재열기·계정 전환에서 기존 저장 계약을 유지. 자료·구성 JSON 백업의 새 사본 복원 후 선택 근거를 정확히 다시 연결 |
| 원고 파일 | 선택 범위·메모·출처·버전·누락을 확인하며 선택 밖 원문이 없음. 한글·emoji·빈 줄·백틱·HTML 모양의 원문을 재열어 대조. JSON과 PDF로 오인시키지 않음 |
| 사용 흐름·시각 | 1440·820·390px에서 본문 읽기·원문 복귀·질문/내보내기 조작 가능. 키보드·터치 대상·긴 제목·빈/오류 상태를 확인하며 실제 Apple 기기와 크기 모사를 구분 |

자동 검사는 입력·출처·보존을 확인한다. **사용자가 과거 글과 현재 생각을 연결하기 쉬워졌는지, 이 파일로 한 편의 글을 계속 써볼 수 있는지**는 별도 체험 결과로 판단한다. 파일이 생성되거나 질문 수가 늘었다는 이유만으로 자기 이해가 깊어졌다고 보고하지 않는다.

## 이번 책 단위의 완료 조건과 현재 확인 상태

책 두 개와 장 세 개를 익명 샘플로 만든다. 같은 옛 버전을 두 장에 연결하고, 타인 글·링크만 있는 자료·날짜 미상을 포함한다. 기존 회고에서 한 책을 시작한 다음 회고와 책을 각각 수정해 서로 덮어쓰지 않는지 확인한다. 기간을 바꾸고 장을 옮겨도 선택한 근거가 유지되어야 한다.

| 구분 | 완료 조건 | 현재 상태 |
| --- | --- | --- |
| 모델·호환 | 책 없는 v1, 빈 책, 한도·잘못된 기간·중복 ID 거절, 같은 원문의 여러 장 참조, 정확 버전 보존 | 단위 검사 통과; [검증 기록](../design-review/book-projects.md) |
| 사용 흐름 | 책 생성/전환·회고 복사·장 추가/제목/원고/순서·근거 선택·제거·재열기를 한 흐름으로 완료 | 합성 브라우저 흐름 통과 |
| 입력·복구 | 한글 조합·저장 뒤 재편집·빠른 전환·계정/공간 이동·저장 실패·충돌 때 원고와 대상 보존 | 저장 실패·충돌·계정/공간 검사 통과; 실제 IME는 미검증 |
| 백업·원고 | JSON 새 사본의 책/장/근거 재매핑, 기본 Markdown의 메모·출처와 명시적 본문 포함, 목차 순서·선택 범위 대조 | 단위·실제 JSON 다운로드/새 사본 검사 통과 |
| 시각·접근 | 1440·820·390px, 키보드/터치 순서 변경, 긴 제목·빈/오류 상태, 원문 읽기와 복귀, 최소 프레임 | 3폭 기능·배치 검사와 root/QA 직접 캡처 검토 완료 |
| 서버 | additive validator 설치, 이전 구성 호환, 책 구성의 권한·왕복·실패 복구 | Local 운영 설치·검증 대기 |

이 표는 **실행할 검사와 남은 조건**이며 아직 통과 수치가 아니다. 앞선 회고의 단위·브라우저 결과를 이번 책 모델/목차/장 편집의 검사로 반복 집계하지 않는다. 문서 담당은 공식 자료 비교와 링크·내용 검사를 수행하며 앱 검사 결과는 담당자의 실제 보고 뒤 반영한다.
