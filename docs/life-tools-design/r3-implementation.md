# R3 개인 기기 간 동기화

2026-10-03 · 로컬 구현과 실제 Supabase HTTP 검증 완료. 공용 Google 인증·전체 화면 통합·실제 Apple 기기 확인·공개 배포와 구분한다. [Local 인계 검증](local-handoff-verification.md)을 현재 서버 상태의 기준으로 삼는다.

## 바뀌는 사용 흐름

아래 흐름은 Cloud의 독립 개발 화면 기준이다. PR #17 통합 제품은 Google OAuth·PKCE 공용 로그인으로 변경하며 아직 화면을 병합하지 않았다. Mac·iPad·iPhone에서 같은 자료 작업공간을 이어 쓴다. `기기 간 동기화`에서 프로젝트의 공개 키와 이메일·비밀번호로 로그인한 뒤, 올릴 작업공간에서 `이 작업공간 동기화 시작`을 누른다. 다른 기기는 같은 프로젝트·계정으로 로그인하고 서버 목록에서 필요한 작업공간을 받는다. 로그인만으로 다른 로컬 작업공간을 올리지 않는다.

로컬 저장과 서버 상태를 따로 표시한다. 오프라인 편집은 로컬에 보관하고 연결 복구 시 이어서 전송한다. 전송 내용과 작업 ID를 IndexedDB에 먼저 저장하므로 응답이 유실되어도 동일 요청을 재시도한다. 로컬 저장소를 지우면 전송되지 않은 내용도 사라지므로 JSON 백업은 계속 필요하다.

양쪽에서 같은 작업공간을 바꾼 경우 자동 덮어쓰기를 멈춘다. 원문·발췌를 비교하고 한쪽을 선택하면 선택하지 않은 내용을 새 로컬 작업공간 사본으로 보관한다. 선택하는 동안 다시 바뀌면 새 충돌로 다룬다. 로그아웃·연결 중지는 자료를 지우지 않는다. 로그아웃은 자동 재접속 설정도 지우므로 다음 앱 시작에서 로그인하려면 프로젝트 연결 정보를 다시 입력한다. 다른 계정에 묶인 자료는 자동 전송하지 않는다.

## 서버 설치

Local 세션이 같은 해도 전용 프로젝트에 설치를 완료했고, Cloud에서도 실제 SELECT·RPC를 확인했다. **설치 SQL을 다시 실행할 필요는 없다.** 적용 버전은 `20261003085426`, 이름은 `life_sync_workspaces`다. [설치된 migration](../../supabase/migrations/20261003085426_life_sync_workspaces.sql)은 Cloud 원본과 같은 내용이며 파일명만 서버 버전에 맞췄다.

추가한 객체는 `life_workspaces`, `life_sync_receipts`, `life_sync_put`이다. 기존 `charts`, `haedo_documents`, `haedo_items`와 Auth 설정을 바꾸지 않았다. Cloud에는 일반 테스트 계정만 있고 관리자 연결은 Local에 있으므로, 익명 HTTP 테스트 8행의 정리만 Local에 인계한다. 세부 증거와 정리 SQL 위치는 [인계 검증 기록](local-handoff-verification.md)에 있다.

## 구현 경계

- [공통 계약](sync-implementation-contract.md): 계정 바인딩, 서버 revision, 영속 전송, 충돌 사본의 원자 반영.
- IndexedDB의 기존 버전과 bundle/백업 형식을 유지하고 새 동기화 메타데이터만 추가한다. 백업에는 인증·비밀번호·세션·전송 큐를 넣지 않는다. 미적용 가져오기 검토는 해당 브라우저에 남는다.
- 원격에서는 소유자 RLS 읽기와 CAS RPC 쓰기를 사용한다. 직접 쓰기와 익명 접근을 거절하고 서버 성공 영수증을 스냅샷과 같은 트랜잭션에 저장한다.
- 공식 Supabase JavaScript SDK를 버전 고정하여 로컬 배포한다. Auth·세션 갱신을 재사용하고 원문 hash·출처 참조 검증은 수신 경계에서 수행한다. [선택 근거와 라이선스](open-source-review.md)를 참고한다.
- 원격 스냅샷 제한은 16 MiB다. 서버 JSONB 표현의 크기도 검사하므로 경계값에서 클라이언트보다 먼저 제한될 수 있다. 초과 시 로컬 자료를 유지한다.
- 기기 간 읽던 위치, 공동 편집, 자동 병합, 원문/작업공간 삭제, 첨부·OCR·AI 자동 추출은 이번 범위에 포함하지 않는다. 발췌 삭제 표식은 스냅샷과 함께 전송한다.
- 같은 origin의 스크립트·브라우저 프로필이 개인 자료에 접근할 수 있다. 계정 RLS는 서버의 사용자 구분이며 로컬 암호화나 종단 간 암호화를 뜻하지 않는다.

## 검증 기록

- `npm run check`: HTML 7개, JavaScript 20개, 로컬 리소스 50개와 PWA 셸 통과.
- `npm test`: **91개 통과**, 실패·건너뜀 0개. 기존 57개에 저장 10개, Remote 15개, 동기화 관리자 경계 9개를 추가했다.
- 기존 `node tests/life-browser.cjs`: 23개 통과. 실제 IndexedDB·원문/발췌·초안·백업·오프라인 회귀와 console/pageerror 0개를 확인했다.
- `tests/life-sql.cjs`: test-only PGlite 0.5.8에서 PostgreSQL SQL/RLS 17개 통과. 재실행·익명/다른 소유자·직접쓰기/영수증 접근 거절·CAS·중복 재시도·16 MiB·트랜잭션 원복을 확인했다. 단일 연결이므로 실제 다중 세션 경합을 증명하지 않는다.
- 실제 Supabase: Local 설치 후 테스트 A/B 인증·새 스키마 확인과 HTTP 검사 **11개 통과**(exit 0). 계정/익명 격리·직접쓰기 거절·CAS 동시 생성/수정·영수증 재시도·서버 JSONB 크기 제한을 확인했다. 큰 HTTP 본문에 대한 비정형 401과 익명 8행 관리자 정리는 [인계 검증 기록](local-handoff-verification.md)에 구분한다.
- 서비스워커: 저장소 HEAD의 실제 v48을 설치한 격리 Chromium에서 v50으로 갱신했다. 이전 캐시 정리·원문 보존·기존 localStorage 불변·오프라인 SDK와 Sync 모듈 로드를 확인했다. 워커 제거로 업데이트 경로를 대신하지 않았다.
- 화면: 설정·충돌 화면 각 1440/820/390px, 총 6개 스크린샷을 직접 확인했다. 가로 넘침·console/pageerror는 0개, 주요 충돌 선택 버튼은 44px 이상이었다. 익명 fixture의 Chromium 151.0.7922.173 검증이며 실제 Apple 하드웨어 검증은 아니다.

`node tests/life-sync-browser.cjs`는 실제 SDK·IndexedDB와 모의 HTTP 서버에서 14개 통과했다. 명시 연결·두 기기 수신·응답 유실과 재로드·충돌 양쪽 선택·사본·계정 변경 후 늦은 응답·오프라인 시작 복구·원문 해시·트랜잭션 중단을 확인했다. 예상 밖 console/pageerror는 0개이며 의도한 통신 실패·스키마 404 콘솔 7개는 별도 집계했다. 실제 서버 RLS의 증거로 확대하지 않는다. 모든 브라우저 세션은 종료했고 개발 서버는 유지했다. Mac·iPad·iPhone 하드웨어와 Safari·한글 화면 키보드는 별도 사용자 확인이 필요하다.

재현 명령은 `npm run check`, `npm test`, 개발 서버 실행 후 `node tests/life-browser.cjs`, `node tests/life-sync-browser.cjs`다. PostgreSQL 검사는 앱 의존성과 분리한다.

```sh
npm install --prefix /tmp/life-pglite-check --ignore-scripts @electric-sql/pglite@0.5.8
PGLITE_MODULE_PATH=/tmp/life-pglite-check/node_modules/@electric-sql/pglite node tests/life-sql.cjs
```

`python3 scripts/check-life-cloud.py`는 설정된 두 테스트 계정으로 고유 익명 행만 생성해 실제 권한·경합을 검사하고, 해당 행에 한정한 관리자용 정리 SQL을 `/tmp`에 남긴다. 기존 개인 자료나 charts를 조회하거나 지우지 않는다. 키·비밀번호는 환경 설정을 사용하며 출력·파일에 기록하지 않는다.

## 검토에서 보완한 경계

오프라인에서 저장된 로그인으로 앱을 처음 열었을 때 연결 복구를 놓치던 경로를 고쳤다. 네트워크 실패만 다시 연결하며 인증 거절은 별도로 남긴다. 로그아웃은 자동 재개 설정을 제거하고, 로그인 도중 취소·다른 로그인·이전 로그아웃 응답이 겹쳐도 폐기된 SDK가 새 세션을 쓰거나 지우지 못하도록 했다.

충돌 뒤 로컬 내용을 다시 편집했을 때 최신 비교를 명시하면 그 내용을 기준으로 해결할 수 있다. 비교 이후 비동기 사본 준비 중 추가 편집은 원자 검사에서 거절한다. 원문 해시 오류·같은 버전 ID의 내용 변경·저장 트랜잭션 중단·잘못된 전송 크기에서 로컬 내용을 유지한다.

SQL 설치와 실제 Supabase HTTP 권한·동시 경합 검증은 완료했다. PR #17 공용 인증·화면 병합, Google OAuth 실제 로그인, Apple 기기 체험, 익명 검증 행의 관리자 정리는 남아 있다. 커밋·푸시·공개 배포는 수행하지 않았다.

## 직접 확인

`npm run dev`로 개발 서버를 시작한 뒤 `life.html`을 연다. 한 기기에서 익명 자료를 가져와 동기화를 시작하고, 다른 기기에서 같은 계정의 서버 목록으로 받는다. 각 기기의 인터넷 연결을 끊고 서로 다른 발췌를 추가한 뒤 연결하면 자동 덮어쓰기 대신 양쪽 변경 비교가 나타나야 한다. 선택 후 별도 사본과 기존 원문을 모두 확인한다.

공개 사이트에는 푸시·배포 전까지 반영되지 않는다. 실제 Apple 기기의 파일 선택·앱 전환·오프라인 복귀·충돌 비교 체험 결과는 자동 검사와 별도로 남긴다.
