# 가져와서 활용하기 — 직접 체험

Local에서 #74·#75·입력/활용 품질 후속을 적용한 뒤 실행한다. 아직 공개 사이트에 반영되지 않았다면 저장소 개발 환경에서 사용한다. 자동 수집·분석·공개는 시작하지 않는다.

아래 익명 글을 TXT/Markdown으로 저장하거나 붙여넣어도 되고, 공개해도 괜찮은 개인 글 한 편을 직접 골라도 된다. 개인 글과 계정 정보는 피드백에 첨부할 필요가 없다.

> 산책하며 돌아본 오래된 질문
>
> 예전에는 잘하는 모습을 먼저 보여 주고 싶었다. 오늘은 오래 궁금한 것을 천천히 살펴보는 편이 더 편안하다.
> 같은 길을 다시 걸으며 무엇이 달라졌는지 적어 두고 싶다.

제목 `다시 걷는 길`, 원천 `Apple 메모` 또는 `Obsidian`, 작성 관계 `내 글`, 작성일 `2022-04-03`을 직접 확인해 입력한다. 샘플 날짜이며 사용자 이력이 아니다.

| 과제 | 설명을 보지 않고 먼저 해볼 일 | 확인할 결과 |
| --- | --- | --- |
| 가져오기 | 글을 보관하고 다시 열기 | 원문·작성 관계·날짜가 유지되는가. 링크만 받은 경우 본문 미확보가 분명한가 |
| 다시 찾기 | 홈에서 `궁금한 것`으로 찾기 → 읽기 → 돌아오기 | 어디서 검색할지 알 수 있는가. 같은 검색 결과와 읽던 버전으로 돌아오는가 |
| 내 생각 활용 | 회고에 지금의 생각을 쓰고 내 페이지 글로 옮기기 | 도움 없이 조작을 찾는가. 원문과 내 생각을 구분하는가 |
| 독립 편집 | 페이지에서 마지막 문장 수정·비공개 저장 → 미리보기 → 회고 복귀 | 비공개 글이 방문자 미리보기에 없는 이유가 분명한가. 원래 회고는 유지되는가 |
| 파일 보관 | 회고를 파일로 받고 다시 열기 | 파일을 찾을 수 있는가. 원문 포함 여부와 JSON 복원용 백업의 차이를 이해하는가 |

여러 파일 중 실제로 실패한 파일이 있다면 그 행에서만 다시 선택해 본다. 정상 파일을 일부러 손상시키거나 개인 자료를 삭제할 필요는 없다. 앱의 다운로드 버튼 성공과 Files 앱에서 파일을 확인한 결과는 따로 기록한다.

## 피드백 한 건씩

- 사용 기기 / OS / 브라우저 / 앱 버전 또는 PR:
- 하려던 일:
- 막힌 화면·조작:
- 예상한 결과:
- 실제 결과:
- 입력·자료는 유지됐는가:
- 도움 없이 끝냈는가 / 설명이 필요했는가:
- 한 가지만 바꾼다면:

앱에 새 기록을 남기는 방식의 평가가 아니다. 이 양식을 복사해 답하거나 한두 문장으로 알려도 된다. 스크린샷은 개인 글·계정 표시를 가린 경우에만 선택적으로 제공한다. 에이전트의 익명 검사는 이 체험 결과를 대신하지 않는다.
