## 사용자 목표와 현재 공백

사용자는 기능마다 자료를 다시 선택하거나 기기마다 설정을 반복하지 않고 **발견 → 읽기/보관 → 필요한 글 또는 실천 → 중단·재개 → 원래 근거로 복귀**하기를 원한다. 모든 자료를 글이나 공개로 끝내도록 강제하지 않는다.

이미 배포된 것은 홈·뉴스·자료실·계획·설정의 목적별 메뉴, 뉴스→자료→글, 원문·폴더·저장 구성·원본 첨부의 계정 연동, 저장 글·사진의 기본 비공개 서버 보관, 명시 Obsidian 연결이다. 이를 새 기능으로 재작성하지 않는다.

현재 남는 공백:

- 네이버의 같은 원문 판에 속한 사진을 다른 기기에서 정확하게 복구하는 경로는 미출시 후보다.
- 일반 계정 글 재개는 본문·사진과 정확 인용 근거의 이동 범위가 다르다. **명시 연결된 작성 준비 이어쓰기에는 이미 정확 원문·선택 근거 이동 경로가 있다.** 이를 재사용하고 일반 글 수신 경로와 혼동하지 않는다.
- 뉴스 관심·언어·좋아요·담기·읽기 평가는 계정/공간별 로컬 저장이다.
- 연간 계획은 로컬, 목표·습관은 계정 저장이다. 월 계획과 실행·회고의 내용 연결은 없다.
- 원문 언어 선택 UI와 실제 언어별 공급은 별개다. 개인 추천은 좋아요 표현 기반 규칙이며 도움 개선이 입증된 학습 모델이 아니다.

| --- | --- | --- | --- |

A의 미확정 실패를 덮고 모든 기능을 동시에 구현하지 않는다. A를 닫는 동안 B/C의 계약·공식 자료 조사는 병렬로 할 수 있다. B의 뉴스와 계획은 공통 보관 상태·이관 원칙 합의 뒤 독립 담당으로 나눌 수 있다. C의 계획 연결과 추천 개선은 서로 다른 결과물이므로 각각의 여정·완료 판정을 유지한다. 관련 화면·저장·재시도·검수·문서·출시를 작은 후속 요청으로 사용자에게 반복해서 넘기지 않는다.

권장 소유 분담은 총괄(범위·공통 계약·통합·Git), 모델/저장, 원격 서비스, UI, 브라우저 검수, 독립 리뷰다. `storage.js`·`ui.js`·`sw.js`·`pages.yml`의 동시 변경은 파일 담당 한 명이 통합한다. 작업 인원을 채우기 위해 범위를 추가하지 않는다.

## 공통 설계 계약

- **저장 경험을 통일한다.** 각 영역의 실제 서버 반영 근거를 읽어 보관 중/계정 보관 완료/확인 필요를 표시한다. 원문 완료만으로 사진·근거까지 완료 처리하지 않는다.
- **데이터 경계는 유지한다.** 원문·구성·큰 파일·글·뉴스·계획을 한 payload로 합치지 않는다. 기존 CAS·영속 전송 대기·adapter·충돌 양쪽 사본을 재사용한다. 공개는 비공개 계정 보관과 별도 선택이다.
- **정확한 원문을 유지한다.** source/version·원문 문자열·UTF-16 구절·본문/사진 해시·출처 관계를 보존한다. 같은 제목/본문/최신 순서로 다른 판을 추정 연결하지 않는다.
- **초안과 기기 맥락을 구분한다.** 기존 초안을 자동 전송하는 정책 변경은 별도 설계 대상이다. 다른 기기의 열린 탭·스크롤을 계정 값으로 덮지 않는다. UI 입력·한글 조합·정확 대상·복귀 위치를 늦은 응답으로 바꾸지 않는다.
- **사용자 판단을 보존한다.** 좋아요·담기·읽음·도움·관련 없음은 다른 의미다. 자동 추천 opt-in이나 공개 동의를 이관·조회·화면 이동으로 새로 만들지 않는다.
- **현실적인 UI를 유지한다.** 본문 중심, 접힌 관리, 기존 다섯 메뉴와 문맥 조작을 사용한다. 새 통합 대시보드·기능 설명 패널·런타임 프레임워크 교체는 이 인계의 목표가 아니다.

## 검수·출시와 현재 권한

이 인계 PR은 미완료 후보를 보존하는 **Draft**다. PR CI 실행이 새 핵심 여정의 통과를 대신하지 않으며, 이번 전달에서 main 병합·운영 배포를 수행하지 않는다. 실행 세션은 기존 승인 범위에서 구현·검수·출시를 이어가되, 통합 검수와 독립 리뷰의 차단 사항이 남아 있으면 완료로 표시하지 않는다. 새로운 사용자 승인 절차를 임의로 추가하지 않는다.

이 PR의 제품 변경은 사진 복구 후보이며 뉴스·계획은 실행 명세다. 전체 후속 구현을 이 PR 하나에 넣는 지시가 아니다. 사진 후보의 완료를 먼저 확정하고 이후 도메인별 여정을 별도 변경으로 이어간다.

실제 개인 계정·자료의 읽기/쓰기, 공개 게시, 상류 네이버 수집·예약 활성화, 기존 서버 데이터 이관은 이번 Git 전달에 포함되지 않는다. 샘플 계정의 모의 HTTP·실제 SDK/IndexedDB와 격리 SQL 검사를 우선하며 운영 설치가 필요한 후속은 정확 변경안·기존 설치 대조·보존/롤백 근거를 먼저 만든다. 저장소에 SQL이 있다는 사실만으로 설치 완료를 주장하지 않는다.

각 실행 묶음의 검수는 **시작 → 명시 저장/실제 서버 반영 → 독립 B 재개 → A 반영 → 실패/충돌 복구 → 파일 복원**으로 잡는다. 실제 바뀐 경계의 회귀, 1440/820/390px·키보드·한글 입력, 기존 주소·PWA 업데이트를 포함한다. 최초 실패와 제품/검사 해시를 보존하고, 단언 완화·근거 없는 시간 연장·서비스워커 삭제로 통과시키지 않는다. 이미 통과한 검사는 코드나 미해결 우려가 바뀐 경우에만 다시 실행한다.

완료 보고는 구현 존재·핵심 여정 검증·정확 버전 출시·실제 사용자 효과를 구분한다. 마지막에 최신 로드맵을 다시 읽고 완료 범위와 남은 조건, 다음 큰 묶음 1~3개를 갱신한다.
