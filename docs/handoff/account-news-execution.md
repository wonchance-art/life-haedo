# 실행 인계: 같은 계정의 뉴스 설정·읽기·활용 이어가기

2026-10-29 KST. 설계 기준은 배포 main `ab6aef594a2d6d0cabbaf89864e7994ce22a6fec`(PR139)다. 이 파일은 실행 명세이며 아래 계정 동기화·새 공급·추천 개선이 이미 구현됐다는 뜻이 아니다. 인계 브랜치에 포함된 네이버 사진 복구 후보와 별도 도메인이다. 실행 전 최신 main·다른 작업을 대조하고 이미 구현된 부분은 재사용한다.

## 목표와 끝나는 상태

**A에서 관심·원문/번역 언어·출처를 설정 → 후보 읽기·좋아요/담기 → B의 같은 계정에서 같은 선택을 이어 받기 → 선택한 후보를 자료/글로 활용 → A에서 변경 확인**을 완결한다. 읽기나 담기로 끝내는 것도 정상 결과다. 설정 화면 추가나 서버 테이블 설치만으로 완료하지 않는다.

추천의 후속 목표는 외국어 학습·독서·집중력·Grit에 관해 선택 언어의 유효 후보를 공급하고, 실제 읽은 뒤 도움이 있었는지 확인해 정책을 개선하는 것이다. 클릭·체류 시간·좋아요·담기·도움을 하나의 만족도 값으로 합치지 않는다.

## 먼저 고정할 설계 결정

### 1. 계정과 자료공간의 범위

권장 최종 방향은 **원문/번역 언어·출처 기본값은 계정 공통, 특정 공간에서 의도적으로 달리 고른 관심과 비교 근거는 공간별**이다. 현재 모든 뉴스 모델은 `workspaceId`를 포함하므로 계정 공통화를 단순 필드 삭제로 처리할 수 없다.

실행의 첫 완주 범위는 기존 의미를 보존하는 **같은 계정·같은 자료공간의 상태 동기화**로 정한다. 계정 공통 기본값은 이 동기화 모델과 로컬 이관이 검증된 뒤 도입할 수 있다. 사용자에게 공간별 독립 설정을 다시 강제하는 최종 설계로 고정하지 말고, 아래 결정표를 구현 착수 시 확정 기록한다.

| 상태 | 첫 완주 범위 | 계정 공통화 전 확인할 것 |
| --- | --- | --- |
| 직접 입력한 관심·출처/관심 켜기·끄기 | 같은 공간의 기존 ID 관계를 그대로 이동 | 관심 ID와 disabledInterestIds의 동시 이관. 서로 다른 공간의 같은 표현을 임의 병합하지 않음 |
| 원문/번역 언어·자동 갱신 | 같은 공간의 설정을 그대로 이동 | 공통 기본값과 공간별 명시 예외의 우선순위·초기 선택 |
| 좋아요·담기·제외 | 같은 공간의 URL·스냅샷·명시 상태를 이동 | 계정 전체 목록으로 모을 경우 충돌한 같은 URL의 반응·삭제와 출처 추적 |
| 읽기 비교·수동 관심 외 분석 | 공간별 유지 | 정확한 당시 조건·원문 근거와 연결되어 있으므로 공통 선호로 승격하지 않음 |

위 범위 선택은 제품 정책이다. 예전 `workspaceId`에 가짜 계정 ID를 넣거나 모든 공간 중 처음 열린 값을 공통값으로 삼지 않는다. 실행 담당자가 최종 범위를 선택한 이유와 이관 예제를 PR에 적는다.

### 2. 무엇을 서버에 보관할 것인가

동기화 대상은 명시적으로 저장한 뉴스 설정·수동 관심·반응·제외 상태를 우선한다. **`InterestProfile` 전체를 그대로 업로드하지 않는다.** `analysis`에는 비공개 원문 구절·해시·판 참조가 있을 수 있고 지금은 로컬 계약이다. 수동 관심의 계정 보관은 허용 필드를 정확히 투영하고 기존 분석을 로컬에 보존한다. 수동 관심과 disabledInterestIds는 같은 유효 스냅샷으로 대조할 수 있어야 한다.

읽기 비교의 기기 간 재개를 포함할 경우 고정된 공개 메타데이터·비교 조건·명시 응답만 대상으로 별도 형식과 이관 범위를 명시한다. 뉴스 설정을 옮겼다는 이유로 기존 평가나 개인 메모가 함께 전송되게 하지 않는다. 서버 보관과 추천 학습은 독립이며 기존 `personalizationEnabled`를 자동으로 켜지 않는다.

### 3. 재사용할 동기화 기반

`library-meta-sync.js`와 `writing-sync.js`는 기존 `CompositionSync`를 도메인 adapter로 재사용하는 선례다. 인증 수명주기·전송 대기·operation ID·CAS·유실 ACK 재생·충돌 사본을 재사용할 수 있는지 먼저 검토한다. `library-meta.js`의 기존 허용 필드에 뉴스 데이터를 끼워 넣지 않는다.

`CompositionSync`는 현재 원문 준비와 공간 바인딩을 전제로 한다. 순수 뉴스 설정은 원문 전송 완료를 기다릴 이유가 없으므로 **가짜 source ACK나 항상 성공하는 source adapter를 넣어 의존성을 우회하지 않는다.** 첫 범위의 실제 의존성에 맞는 제한된 엔진 확장과 독립 adapter를 비교하고, 기존 원문/구성/글쓰기 경로를 바꾸지 않는 방식을 선택한다. 새 RPC·테이블 이름과 최종 스키마는 아직 결정되지 않았다. 기존 DB 설치가 새 뉴스 도메인까지 지원한다고 가정하지 않는다.

## 로컬 이관·충돌·삭제 계약

1. 현재 서버 계정을 검증한 뒤 그 계정·해당 공간의 로컬 상태만 읽는다. 로그인 전 자료나 다른 계정의 저장소를 이메일·비슷한 공간 이름으로 추정해 합치지 않는다.
2. 먼저 서버 상태를 조회한다. 새 기기의 빈 기본값이 이미 있는 서버 관심/반응을 덮어쓰지 않게 한다. 이전 로컬 상태의 원본 사본과 형식·revision을 보존한 뒤 준비한 이관을 기록한다.
3. 서버가 비어 있을 때의 초기 등록 경합을 CAS와 영속 operation ID로 처리한다. A/B가 동시에 처음 연결해도 하나의 상태를 조용히 잃거나 이관을 중복 생성하지 않아야 한다.
4. 양쪽에 값이 있으면 무조건 최신 시각 또는 좋아요/담기의 OR 합집합을 사용하지 않는다. 서로 다른 URL의 독립 변경과 같은 URL의 모순 변경을 구분한다. 자동 병합 근거가 없는 충돌은 양쪽 사본을 보존하고 현재 화면에서 해결한다.
5. 기존 모델의 `forget/undo`는 로컬 배열에서 행을 제거하고 전체 revision을 올린다. 이를 그대로 행 단위 증분 병합으로 바꾸면 오프라인 B가 삭제를 되살릴 수 있다. 첫 버전은 전체 스냅샷 CAS로 모순을 드러내거나, 필요성이 확인되면 명시 삭제 세대/묘비를 설계한다. 시간값만으로 삭제 우선순위를 정하지 않는다.
6. 화면의 로컬 저장 성공과 서버 반영 확인을 구분한다. 실패해도 입력·로컬 값·전송 대기를 유지하며 재시도 후 같은 작업을 한 번만 반영한다. 네트워크 실패 때 기존 설정을 기본값으로 초기화하지 않는다.
7. 계정/공간 전환·로그아웃·화면 이탈 이후의 조회·ACK는 이전 세대에서만 종료한다. 현재 피드를 뒤늦게 재정렬하거나 새 계정에 반응을 쓰지 않는다.
8. 기존 반응 사본의 `mergeCopy`는 개인 추천을 끄고 가져온 행을 추천 제외 상태로 둔다. 계정 동기화를 사본 가져오기로 구현하지 말고, 두 계약과 기존 파일 형식을 따로 유지한다.

## 공급·추천을 고도화하는 조건

- **공급 현황:** 현재 ko/en 9개 정의와 실제 최신 산출물의 성공 출처·언어·발행일은 다른 사실이다. 공개 산출물을 새로 확인하고 관심 분야×언어별 후보 수와 누락을 기록한다. ja/zh/fr 선택 UI를 공급 완료로 보고하지 않는다.
- **출처 추가:** 공식 피드·권리·robots·리디렉션·언어·날짜 의미를 확인한다. 검토한 메타데이터만 수집하고 본문·사진 권한을 확대하지 않는다. 출처 장애가 나면 마지막 검증 목록과 실패 상태를 남긴다. 사용자의 관심·좋아요를 공용 수집기에 전송하지 않는다.
- **운영 분리:** 공개 수집은 현재 앱의 전체 검사/배포를 기다린다. 실제 갱신 지연을 측정한 뒤 필요하면 검증된 피드 artifact의 생산·설치 경계를 분리한다. 스키마/허용 출처/크기·중복·날짜 검증과 마지막 정상본 복구는 유지한다. 이번 인계만으로 예약 수집을 추가 실행하거나 운영 일정을 바꾸지 않는다.
- **평가 단위:** 공급 버전·필터·정책·시각을 고정하고 최신순/관심순/개인 정렬을 비교한다. 같은 URL의 다른 시점 제목과 과거 응답을 섞지 않는다. 읽기 전 의향, 읽은 범위, 읽은 뒤 도움, 후속 자료 활용을 별도 사실로 보관한다.
- **신호 정책:** 좋아요·담기·관련 없음·읽음·도움은 독립이다. 담기를 정렬에 쓸 경우 ‘도움’으로 간주하지 말고 별도 이용 목적·opt-in·정책 버전을 정의한 뒤 기존 규칙과 비교한다. 무반응·긴 체류를 긍정/부정으로 채우지 않는다.
- **채택 기준:** 실제 후보를 읽은 사용자 판단에서 기존 기준보다 가치가 확인되고, 다양성·언어·출처 편중과 비용/지연이 허용 범위일 때 채택한다. 표본과 판단이 부족하면 결론을 보류하되 계정 이어쓰기 구현의 완료를 막지는 않는다. 모델 점수나 자동 검사 수를 읽기 효용의 증거로 쓰지 않는다.

## 완료 검수표

| 시작/반례 | 필수 확인 |
| --- | --- |
| A 관심·언어·출처·좋아요/담기 변경 → B 새 로그인 | 같은 허용 상태·메타데이터·opt-in 도착. 빈 B가 A를 초기화하지 않음 |
| B에서 독립 변경 → A 재개 | 중복 행·다른 공간 혼합 없음. 읽는 중인 목록·미저장 입력을 갑자기 대체하지 않음 |
| 오프라인 변경·서버 ACK 유실·동시 최초 연결 | 같은 operation 재시도 멱등, 실제 반영 확인 전 완료 표시 없음, 양쪽 자료 보존 |
| A 삭제/반응 해제 → 옛 B 늦은 재전송 | 삭제가 자동 부활하지 않음. 모순 상태는 보존된 충돌로 표시 |
| 계정/공간 변경 중 느린 조회·사진/글 진입 | 이전 응답의 쓰기·화면 반영 없음, 현재 원문·글·초안 보존 |
| 기존 로컬 관심 분석과 원문·개인 메모 | 수동 관심 이관만으로 비공개 구절/분석/원문을 추가 전송하지 않음 |
| 원문/번역 열기·읽기 비교 | 명시 클릭, 번역 끄기 즉시 반영, 의향/읽기/도움 분리, 평가가 반응·추천 opt-in을 자동 변경하지 않음 |
| 뉴스→자료→글→뉴스 및 파일 사본 | 정확 판·출처·복귀 위치·기존 반응 사본 형식과 추천 제외 계약 보존 |
| 1440/820/390px·키보드·IME·실패 상태 | 본문 집중, 조작 이름·초점·44px·입력16px·가로 넘침·입력 보존 |
| 기존 PWA→후보·오프라인·재인증 | 새 필수 모듈 설치와 실제 바이트, 기존 설정/반응/비교·원문 불변 |

기존 회귀 출발점은 `tests/purpose-news-browser.cjs`, `life-news-browser.cjs`, `life-discovery-automation-browser.cjs`, `life-discovery-languages-browser.cjs`, `life-discovery-reactions-browser.cjs`, `life-discovery-reading-browser.cjs`, `life-external-discovery-browser.cjs`, `life-external-discovery-pwa-browser.cjs` 및 해당 순수 모델/저장 단위 검사다. 기존 검사를 새 서버 계약에 맞춰 보완할 때 원래 단언·실패 기록·시간 한계를 유지한다. 전체 검사를 무조건 여러 번 반복하지 말고 변경 경계와 새 실패 근거에 맞춰 실행한다.

## 범위 밖과 결과 보고

새 SNS 게시, 임의 웹 전체 수집, 숨은 클릭/체류 추적, 자동 관심 추출 재활성화, 모든 자료의 서버 분석, 모든 백업 형식 병합, 공개 권한 확대는 이 목표에 포함하지 않는다. 실제 개인 계정 로그인·운영 데이터 이관을 합성 검수로 대신하거나 반대로 합성 데이터를 운영에 쓰지 않는다.

결과는 **구현됨 / 핵심 흐름 검증됨 / 실제 배포됨 / 실제 읽기 효용 확인됨**을 분리해 보고한다. PR에는 확정 범위·이관 예제·RPC/권한 설치 여부·첫 실패와 교정 근거·정확 커밋 검수·실제 산출물·남은 사용자 체험 조건을 적고, 최신 로드맵의 같은 작업 한 줄을 갱신한다.
