# 코드 리뷰와 앱 개편 — 2026-09-10

기존의 따뜻한 종이색·분야 팔레트·행복도 곡선을 유지하면서 문서 관리, 편집 접근성, 데이터 보존을 개선했다.
작업 브랜치는 `codex/review-and-refresh`다. 사용자 승인에 따라 PR 병합과 GitHub Pages 배포를 진행한다. 운영 DB 설정은 변경하지 않았다. 배포 상태는 GitHub의 PR·Pages 실행 결과를 따른다.

## 검토 범위

실행 앱의 HTML/CSS/JavaScript, 데이터 마이그레이션과 저장, 다중 문서, Supabase REST 동기화,
곡선 집계와 SVG 편집·출력, 검색·일괄 입력, 지도·격자, PWA 캐시를 확인했다.
다섯 개의 독립 디자인 시안은 구문·리소스 검사를 수행하고 비교 자료로 남겼다.

## 주요 수정

| 발견한 문제 | 변경 |
| --- | --- |
| 업로드 대기 중 문서를 전환하면 현재 문서 ID를 참조해 다른 문서가 전송될 수 있음 | 문서별 대기열, ID·내용·수정 시각을 함께 캡처, 같은 문서의 요청 직렬화 |
| 읽기 확인 뒤 upsert 사이에 다른 기기의 수정이 끼어들 수 있음 | `updated_at` 조건부 PATCH, 새 문서는 INSERT, 충돌 시 로컬 원본 유지 |
| 원격 삭제 문서가 다시 만들어지거나 미전송 로컬 편집이 pull로 바뀔 수 있음 | 삭제 감지, 수정 대기 문서 보호, 계정·연결 변경 시 오래된 요청 결과 무시 |
| 다른 문서의 전송 완료가 현재 문서의 충돌 표시를 덮을 수 있음 | 문서별 동기화 상태 표시 |
| 같은 ID의 백업 복원이 원본을 덮어쓰고, 이름·크기 기반 중복 정리가 별개 문서를 삭제할 수 있음 | 가져오기는 새 ID의 사본, 형식 일괄 검사·실패 롤백, 자동 중복 삭제 제거 |
| 잘못된 날짜·배열·좌표·행복도 값이 계산을 깨뜨릴 수 있음 | 실제 달력 검사, 월 이동 시 말일 보정, 손상 값을 `_quarantine`에 보관 |
| 손상된 현재 문서를 샘플로 덮을 수 있음 | 별도 복구 문서 사용, 원본 키·손상 목록과 고아 문서를 백업에 포함 |
| 현재 월의 실제 기록이 미래로 분류되거나 월말 날짜가 다음 달로 표시될 수 있음 | 현지 오늘 날짜와 월 변환 경계 수정 |
| 예정 점 이후의 실제 구간도 계속 점선이 됨 | 실제·예정 구간별 클리핑, 화면과 SVG 출력에 같은 규칙 적용 |
| 기록 밀도가 모두 0이면 NaN 좌표 생성 | 분모의 최솟값 보장 |
| 장소 검색 도중 문서를 바꾸면 늦게 도착한 결과가 편집에 반영될 수 있음 | 문서 ID·대상·에디터 생존 여부 확인 |
| 가져온 색·레이어 ID가 HTML 속성에 그대로 들어가는 경로 | 색 형식 검증, 속성 이스케이프, DOM으로 안전하게 텍스트 구성 |
| 서비스워커가 실패 응답을 저장하고 다른 앱 캐시도 삭제함 | 셸 전체 설치 성공 후 활성화, 정상 응답만 저장, 앱의 이전 캐시만 정리 |
| 없는 JS/CSS 요청에 index HTML을 반환함 | 탐색 요청에만 HTML 폴백, 누락 리소스는 실패로 유지 |

클라우드 화면의 `using(true)`/`with check(true)` 전체 허용 정책 안내는 제거했다.
공개 키만 받도록 했으며 실제 계정 격리는 서버 RLS에서 강제해야 한다.

## 화면과 구조

- 문서 선택·새 문서·파일·저장 상태를 상단에 모았다.
- 지도 라이브러리는 지도를 열 때 불러온다. 외부 지도 CDN 응답이 연표 첫 실행을 막지 않는다.
- 기록 목록, 종류 필터와 텍스트 검색을 추가했다. 곡선을 직접 조작하지 않고도 기록을 편집할 수 있다.
- JSON 백업·사본 가져오기·PNG/SVG 출력을 파일 메뉴에 모았다.
- 범위 버튼·오늘 이동·지도·격자 설정을 정리하고, 화면 높이에 맞춰 곡선 영역을 조절했다.
- 에디터의 완료 버튼, 모바일 하단 편집창, 모달 포커스 복귀·Tab 순환, 메뉴 키보드 이동을 추가했다.
- 자동 순환하던 요약 수치는 직접 선택하도록 바꿨다.
- `index.html`, `assets/app.css`, `app.js`, `data.js`, `sync.js`, `workspace.js`로 분리했다.
  기존 localStorage 키와 JSON 형식, 월별 집계 우선순위, 선 두께와 기본 팔레트는 유지한다.

- 정적 검사: HTML 6개, 프로젝트 JavaScript, 리소스와 PWA 셸. `git diff --check`.
- 격리된 localhost 브라우저: 사건 추가, 불가능한 날짜 거부, 윤년 날짜 저장과 재로드.
- 통합 검사 20개: 목록 검색·종류 필터·수정·undo/redo·검색 모달 포커스·사본 복원과 원본 바이트 보존·잘못된 백업의 원자성·전체 백업·PNG/SVG·격자·새 문서·월말 경계·가로 넘침.
- 최종 수정 후 곡선 구간·SVG/PNG·문서별 충돌 표시·연결 변경 차단 5개 추가 브라우저 검사 통과.
- 지도 버튼에서 라이브러리가 로드되고 1352×447 지도 영역에 표시되는 것을 확인. 최종 온라인 세션의 페이지 오류·콘솔 오류 0건.
- 1440×1000 및 390×844 화면을 눈으로 확인. 모바일 편집창이 화면 안에 들어오는지 확인.
- 실제 v45→v46 서비스워커 업데이트에서 익명 기록 7건과 `unrelated-app` 캐시 보존을 확인.
- 별도 검증 서버를 실제 중지한 뒤 캐시에서 연표가 다시 렌더되고 저장한 기록 7건이 복원되는 것을 확인. 브라우저 전체의 오프라인 에뮬레이션은 도구 응답 오류가 있어 서버 중지 방식으로 대체했다.

스크린샷과 브라우저 검증 스크립트는 `/private/tmp/life-haedo-review/`에 있다.
익명 샘플만 사용했고, 게이트는 새 localhost 테스트 저장소에 통과 상태를 설정했다. 비밀번호 입력 흐름은 이 검사에 포함하지 않는다.

## 외부 검증과 운영상의 제약

운영 Supabase의 스키마·RLS·실제 두 계정 권한은 접근하거나 변경하지 않았다.
조건부 쓰기와 충돌 처리 검사는 가짜 응답을 사용하므로 실제 서버 권한을 증명하지 않는다.
현재 동기화는 PostgreSQL에서 `id`가 고유하고 `updated_at`으로 조건을 걸 수 있는 기존 `charts` 테이블을 전제로 한다.

충돌 문서는 자동으로 덮지 않는다. 먼저 `파일 → 전체 문서 백업`으로 보관한 뒤,
JSON을 새 사본으로 가져와 별도 문서로 작업을 계속할 수 있다.
지도·장소 검색·외부 폰트는 네트워크 상태와 제공 서비스의 가용성에 영향을 받는다.
localStorage는 브라우저 데이터 삭제 시 지워지므로 파일 백업은 계속 필요하다.
