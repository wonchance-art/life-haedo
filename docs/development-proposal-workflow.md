# 개발 제안 루프 — 검토용 지침 초안

보관 상태: 02 October 2026 (Asia/Seoul). 아래는 대화에서 작성한 제안 방식의 초안이다. 이번 업로드는 문서 보관만이며 AGENTS.md·Skill·Codex 설정에 연결하거나 자동 적용하지 않는다. 향후 사용자가 적용을 요청할 때 검토할 자료다.

## 목적

실제 생활에 필요한 도구와 경험을 잘 만드는 데 집중하면서, 작은 변화로 가능한 개선·재사용·공유·확장을 발견한다. 플랫폼·다중 에이전트·대규모 자동화를 미리 정답으로 정하지 않는다.

## 두 병행 흐름

필요 해결: 실제 필요 → 원하는 사용 경험 → 해결안 → 검토 → 명시적으로 허용된 실행 → 결과 확인.

개발 제안: 새로운 맥락 → 기회 발견 → 현재 필요와의 관련성 검토 → 대안 비교 → 선택적 제안 → 사용자 판단 → 상태 기록 → 실제 결과에 따른 수정.

제안 흐름은 필요 해결을 지원하는 역할이다. 제안 때문에 원래 요청을 미루거나 범위를 확대하지 않는 것이 원칙이다.

## 발동 조건 후보

새로운 필요·불편·사용 장면, 실제 사용 결과의 반복·입력 부담·막힘, 다른 활동의 공통 정보·절차, 작은 변경으로 가능한 다른 활용, 검증 결과·사용자 피드백·채택·거절, 전제 변화나 더 단순한 해결책이 검토 계기가 된다.

확인하지 않은 사용 이력·실패·반복을 관찰한 사실처럼 취급하지 않는다. 외부 자료를 읽거나 변경할 때의 접근권한은 별도로 확인한다.

## 검토 관점

| 관점 | 확인 내용 |
| --- | --- |
| 현재 필요 | 지금 해결할 필요와 사용자가 원하는 결과 |
| 단순한 대안 | 현 방식 유지, 기능 축소, 기존 도구 활용 |
| 가까운 개선 | 입력 감소·맥락 복원·재사용·품질·잡무 감소 |
| 가까운 확장 | 다른 활동·사용자, 결과나 방법의 공유 |
| 추가 부담 | 구현·운영·권한·검증·비용·유지관리 |
| 근거 | 사용자 발언·확정 사실·추정·미검증 가설의 구분 |
| 검증 | 효과를 확인할 실제 사용 장면과 관찰 기준 |

일반 대화나 작은 수정에는 가벼운 탐지를, 유망한 후보에는 맥락·중복·대안 비교를, 개인정보·외부 전송·큰 비용·복잡한 변경에는 추가 검토를 적용하는 안이다. 역할·스킬·effort는 필요한 경우 제안하되 설정 변경이나 설치를 수행했다는 뜻은 아니다.

## 제안 형식

현재 필요 / 작은 전환 / 새로운 활용 / 관찰·근거 / 추가 부담 / 더 단순한 대안 / 확인할 가설.

작은 제안은 몇 문장으로 압축하고, 기본적으로 현재 맥락에서 가장 가치 있는 후보 하나를 보여준다. 아이디어 발산을 요청하면 넓힐 수 있다. 좋은 후보가 없으면 제안하지 않고 종료한다.

## 상태와 권한

후보·제안·보류·설계 채택·제외를 구분하고, 실제 검증 결과와 실행 허가는 별도 항목으로 관리한다. 명확한 자연어 판단만 반영하고 애매한 긍정을 실행 허가로 해석하지 않는다.

아이디어 채택은 코드 작성·배포·결제·외부 공개·제3자 전송 허가가 아니다. 설계 요청만으로 구현·스택 선정·작업 순서를 새로 시작하지 않는다. 사용자가 이미 허용한 범위는 불필요하게 재확인하지 않는다.

## 누적·중복·종료

제안 이름보다 해결할 필요와 실제 변경점을 기준으로 중복을 묶는다. 채택·보류·제외 이유와 당시 전제를 남긴다. 새 근거가 생긴 경우에만 보류·제외안을 재검토한다. 최신 사용자 판단과 과거 AI 제안을 구분한다.

새 사용자 입력·실제 검증·전제 변화가 없는 동일 상태에서는 검토를 종료한다. 제안 문서의 갱신, AI 자신의 요약, 같은 이벤트 재처리는 새로운 제안 근거가 아니다. 독립 에이전트 사용이나 파일 쓰기는 실제 요청과 기존 권한 규칙을 따르는 별도 실행이다.

## 평가 기준

아이디어 수·기능 수 대신 현재 필요 해결, 반복 입력과 관리 부담 감소, 이해·탐구·실제 활동의 질, 사용자의 유용성 평가, 복잡성 대비 이득을 본다.

## 사례

현재 필요는 책·교재의 읽던 위치와 질문을 쉽게 이어가는 것이다. 가까운 전환은 이미 있는 책·메모 중 공개할 것만 골라 방문형 서재로 보여주는 것이다. 추가 부담은 공개본 분리·미리보기·철회와 접근권한이다. 공개 기능은 진도 관리의 필수 조건이 아니다.

공개 서재는 이미 사용자 선호가 확인된 방향이므로 매번 새 아이디어처럼 제안하지 않는다. [현재 기준](current.md), [결정 기록](decisions.md), [제안 목록](proposals.md)은 맥락을 비교하는 참고 자료다.

이 문서를 저장하는 것과 예약 실행·상시 감시·자동 PR·배포·Codex 지침 적용은 서로 다르다. 문서 보관 상태와 실제 설치·적용 상태를 구분한다.
