# 생활 도구와 확장 가능성 — 참조 설계

2026-10-05 갱신 안내: 이 문서는 이전 맥락의 보관본이다. 백업과 최신 요청을 대조한 [Mermaid v3·변경 이유·검증](diagrams/README.md)이 최신 도식이며 v2 원본은 이력으로 보존했다.

기준: 02 October 2026 (Asia/Seoul). 넓은 논의의 지도이며 확정 스택·작업 순서·전체 기능 발주서가 아니다. [현재 기준](current.md)과 실제 요청 범위를 우선한다. 이번 보관으로 기능이나 지침이 설치·활성화되는 것은 아니다.

## 목적

일상 기록·관리 위에서 직접 경험·깊은 탐구·관계·선택적 표현을 연결한다. 반복 입력을 줄이고 경험의 질·이해·여백을 높인다. 기능 수·접속시간·생산량을 목표로 대체하지 않는다.

## 활동 영역 × 공통 흐름

| 영역 | 준비·관리 | 경험·체화 | 기록·축적 | 탐구·대화 | 관계·교류 | 표현·공유 |
| --- | --- | --- | --- | --- | --- | --- |
| 생활 기반 | 일정·루틴·환경 | 하루 생활·신체 활동 | 수행·상태 | 생활 회고 | 약속·동행 | 선택적 일상 기록 |
| 학습·지식 | 언어·책·교재·기술 | 읽기·학습·실험 | 진도·표현·질문 | 원문·논증·문제 해결 | 책친구·학습자 | 리뷰·교육 자료 |
| 문화·현장 경험 | 장소·전시·작품·음반 | 여행·건축·감상·자연 | 사진·장소·감상 | 역사·지역·해석 비교 | 함께 경험 | 여행기·큐레이션 |
| 창작·제작 | 소재·레퍼런스·프로젝트 | 글·사진·디자인·개발 | 초안·선택 이유 | 비평·검증 | 협업·피드백 | 작품·도구·매거진 |
| 관계·교육 | 사람·모임·수업 | 만남·교육 | 대화·다음 약속 | 공동 관심·교수법 | 연결·공동 활동 | 승인된 공동 기록 |

분류는 보기이며 서로 격리된 폴더가 아니다. 여행 중 촬영·독서·친구 만남이 같은 경험을 공유할 수 있다. 모든 활동이 여섯 프로세스·AI 대화·발행을 거칠 필요는 없다.

## 준비된 도구 위에 기록

대상을 등록하고 기본 맥락을 확인한 다음, 실제 활동에서 달라진 것만 입력한다. 일반 기능으로 할 수 있는 조작을 자연어 설명으로 대체하지 않는다. 필요한 순간에만 AI를 통해 이해·연결·비평을 깊게 한다.

책은 판본·목차·페이지·재독, 교재는 단원·문제·복습, 음악은 작품·연주·녹음, 여행은 장소·일정·현장 기록을 지원할 수 있다. 고유 단위를 동일화하지 않는다. 제목 검색은 후보 확인을 포함하고 미확보 목차·원문은 생성해서 사실처럼 저장하지 않는다.

마지막으로 연 위치, 실제 읽은 구간, 이해 여부, 문제 완료는 다르다. 재개 화면은 진도율뿐 아니라 남긴 질문과 다시 볼 곳을 보여준다. 기본 기록은 외부 서비스나 AI 실패와 독립적으로 보존한다.

## 한 페이지와 공개 서재

오늘 관리·활동 도구·기록·대화·편집을 오가면서 현재 대상·위치·질문을 유지한다. 필요한 패널만 펼치고 긴 작업의 상태는 접어서 확인한다. 하나의 화면이 하나의 입력창이나 복잡한 대시보드를 뜻하지 않는다.

방문형 서재를 구체화하면 공개 승인한 책·메모·사진·음악·프로젝트를 책장·책상·노트·지도 등으로 탐색하게 할 수 있다. 사실적인 3D와 장식은 필수가 아니다. 개인 작업실의 효율적인 기능어와 공개 공간의 공간적 표현은 다른 목적이다. 내부 전체 기록을 직접 노출하지 않는다.

## 시스템의 계층과 공통 정보

| 층위 | 역할 |
| --- | --- |
| 개인 운영 지원 | 맥락·실행·자료·권한·비용·실패·개선을 조율 |
| 공통 시스템 | 라이브러리·계획, 활동, 기록·검색, 대화, 관계, 편집 |
| 특화 모듈 | 책·교재, 장소·여행, 작품·녹음 등 분야 고유 규칙 |
| 하위 기능 | 필요가 확인된 페이지·문제·복습·편집 등의 세부 처리 |

각 기능의 입력·책임·결과·검증·오류·종료를 정의한다. 공통 정보는 재사용하고 분야만 바뀌면 설정으로 처리 가능한지 먼저 본다. 모든 하위 시스템이 AI·에이전트·독립 서비스일 필요는 없다. 개발 에이전트와 실제 제품의 생활 지원 AI도 분리한다.

개념 단위는 대상·활동·생각이며, 계획·상태·출처·권한·버전이 함께 필요하다. 이것은 DB 스키마 확정이 아니다. 책의 공용 서지정보와 개인 진도·대화는 소유 범위가 다르다. 예정/실행, 원문/AI 요약/가설, 보유/진행, 비공개/승인된 공유본을 구분한다.

## 탐구·기억·교류

현재 질문 이해 ↔ 필요한 원문·과거 기록·자료 선택 ↔ 설명·질문·다른 해석 중 적절한 개입 ↔ 사용자 반응 ↔ 관점 수정.

분야별 좋은 대화의 기준은 다르다. 철학은 개념·논증·원전, 언어는 읽는 목적·수준·뉘앙스, 예술·지역은 관찰·문화 맥락·비교, IT는 제약·재현·검증을 중시할 수 있다. 모든 답변에 반론·추천·공유 제안을 한꺼번에 붙이지 않는다. 일시적 관심을 고정된 정체성으로 취급하지 않는다.

친구별 소재는 사용자가 제공한 관심과 허용된 함께한 경험을 바탕으로 공통 관심과 서로 다른 관심의 접점을 찾는다. 실제 인용·출처·추천 이유·AI가 작성한 말 걸기 초안을 구분한다. 개인 보관 / 특정 사람·모임 / 공개를 별도 경로로 둔다.

SNS와 웹은 허용된 범위의 연결·사용자가 제공한 자료만 다룬다. 홈 추천 피드 전체 복제를 전제하지 않는다. 수집량과 노출량을 분리하고 읽지 못한 자료를 읽은 것처럼 요약하지 않는다. 실제 제공처·권한·이용 조건·비용은 별도 확인한다.

## 세 가지 순환

생활: 계획·준비 → 실제 생활 → 기록 → 돌아보기 → 다음 생활 조정.

탐구·관계: 경험 ↔ 자료·기억·대화 ↔ 사람과 교류 → 선택적 표현 → 새 경험.

개발 제안: 새 필요·결과 → 가까운 개선·확장 탐지 → 대안·부담·가설 → 사용자 선택 → 확인. [검토용 제안 규칙](development-proposal-workflow.md)에 구체적인 안이 있다.

제안 지침을 문서화했다고 상시 감시·예약·자동 구현을 설치한 것이 아니다. 변화가 없으면 종료한다. 사용자가 앱을 닫고 읽고 걷고 사람을 만나는 것도 좋은 결과다.

## 승인·복구 v2 — 참조 원본과 미결 사항

[전체 실행 구조](diagrams/platform_workflow_v2.mmd)와 [승인·실행·복구 상세](diagrams/platform_approval_recovery_v2.mmd)는 대화에서 만든 참고 도식이다. 이번 문서 보관은 문법 검사·동작 검증을 새로 수행한 결과가 아니다. 플랫폼 선행 전제를 수정하기 이전의 넓은 설계를 포함하므로 필요한 부분만 다시 판단한다.

기본 기록 선저장, 현재 권한 재확인, 승인된 내용·대상·버전 고정, 실패 단계만 복구, 외부 결과 불명 시 재전송 보류는 참고할 방향이다. Outbox·원자적 저장·실행 점유는 구현 후보이며 기존 큐에 이미 그런 보장이 있다고 가정하지 않는다.

| ID | v2 이후 보완 질문 |
| --- | --- |
| O-01 | 단순 조회를 저장·후속 실행과 분리할 경로 |

| O-05 | 취소 요청·취소 완료·이미 실행됨·결과 불명의 구분 |

이 질문 전체를 구현 전 통과 관문으로 삼지 않는다. 관련 기능을 다룰 때 필요한 범위만 설계한다. 도식을 수정하면 새 버전·수정 이유·검증 수준을 남긴다.

## 기존 앱과의 접점

[현재 구조](architecture.md)와 [검토 기록](review-update.md)의 관련 부분을 기준으로 연표·데이터·동기화·PWA를 보존한다. 연표는 한 가지 보기로 두고 새 활동을 연결하는 경로를 검토한다. 새 서재가 모든 생활 도구를 연표 형식으로 만들거나 기존 앱을 전면 이식할 이유는 아니다.

운영 센터는 모든 권한을 가진 단일 AI일 필요가 없다. 일반 규칙의 저장·권한·검증과 AI의 해석·선별·대화를 구분한다. 선택되지 않은 모델·서비스·프레임워크·다중 에이전트 구성은 확정하지 않는다.
