# 책 읽기에서 편집하고 돌아오기

2026-10-08 KST. [책 프로젝트](book-projects.md)와 [장별 생각·근거](book-insights.md)를 바탕으로 **책 읽기 → 필요한 장 편집 → 읽던 곳 복귀 → 같은 범위의 원고 다운로드**를 연결하는 단위다. root가 공통 디자인과 UI를 통합한다. 구현·검증 결과와 Local 인계를 아래에 구분한다. 공개 배포 완료를 뜻하지 않는다.

## 목표와 범위

책을 만들던 입력 화면을 벗어나 장 순서대로 현재 원고를 읽고, 고칠 장으로 들어간 뒤 읽기를 이어갈 수 있게 한다. 장 원고·현재 해석·근거 출처를 구분하고 본문에 집중하는 기존 한 열 화면을 유지한다. 새 최상위 메뉴, 리치 편집기, 자동 해석·AI API, 공개 게시, PDF 조판을 추가하지 않는다.

이 단위는 **UI와 `Books.project` 공통 출력 모델**의 변경이다. 기존 Workbench 책/장/insights 저장 형식, 계정별 저장, 구성 CAS, JSON 백업과 공개 모델은 유지한다. 읽기 화면을 열었다는 이유로 책 내용을 고치거나 새 동기화 연결을 만들지 않는다. 기존 연표 값·계산에도 영향이 없어야 한다.

## 사용 흐름

개발 환경은 `npm run dev` 후 로그인된 보호 화면의 `index.html?section=tools&view=books`에서 연다. 개발 주소는 공개 배포 주소가 아니다. Local의 선행 반영·배포 이후 실제 앱에서는 도구 → 책 만들기에서 책을 선택한다.

1. **책 읽기:** 선택한 책의 제목·질문과 장 배열의 목차 순서로 현재 내용을 읽는다. 설정 기간은 책의 설명이며 그 밖의 선택 근거를 숨기는 필터가 아니다.
2. **포함 범위:** 기본은 장 원고·제외하지 않은 생각·그 근거/반례·장 전체 근거의 출처다. 원문 본문은 명시적으로 포함할 때만 표시·다운로드한다. 같은 옵션이 화면과 파일에 적용되어야 한다.
3. **편집:** 고칠 장을 명시적으로 열어 기존 제목·원고·생각/근거 편집을 사용한다. 저장 중·한글 조합 중·실패 상태를 무시하고 이동해 입력을 잃지 않는다.
4. **복귀:** 저장을 마친 뒤 같은 책의 읽기 화면으로 돌아와 해당 장의 문맥을 이어간다. 수정한 내용은 다시 계산한 출력 모델에 반영한다. 다른 책이나 첫 장으로 조용히 바꾸지 않는다.
5. **다운로드:** 현재 책과 포함 선택을 확인하고 Markdown을 받는다. 다운로드 전에 필요한 저장을 완료하며 저장 실패·계정/공간 이탈이면 성공한 파일로 안내하지 않는다.

근거 원문을 열 때는 기존의 정확한 `sourceVersionId`를 사용한다. 링크만 있는 자료·미확인 저자·부분 본문·없는 참조를 그대로 표시하며 최신 버전이나 다른 글로 대신 채우지 않는다. 원문 왕복도 책·장 맥락과 입력 보존을 유지해야 한다.

읽기/편집 전환과 복귀 위치는 **현재 화면 세션의 상태**다. 새 저장 필드·읽기 이력·기기 간 동기화된 독서 위치를 만들지 않는다. 새로고침이나 다른 기기에서도 같은 스크롤이 이어진다고 약속하지 않는다. 같은 문장과 위치 키로 복귀를 시도하며 문장을 삭제·교체하면 같은 위치 키 또는 해당 장 제목으로 돌아간다. 반복된 동일 문장과 큰 편집에서는 의미상 같은 구간까지 보장하지 않는다. 현재 책/장이 실제로 없어졌다면 그 상태를 설명하고 안전하게 목록으로 돌아가며 다른 항목을 편집 대상으로 대체하지 않는다.

## UI와 파일이 공유할 내용

[`Books`](../../assets/life/books.js)의 `project`는 현재 책을 읽고 내보낼 내용을 구성하는 공통 모델이다. UI와 Markdown이 각각 해석 제외·근거 선택 규칙을 새로 만드는 것을 피한다. 이 출력 모델은 별도 저장 사본이나 원고 개정본이 아니며 원래 책·장·원문을 변경하지 않아야 한다.

| 내용 | 공통 계약 |
| --- | --- |
| 책·장 | 선택한 책 하나, 명시적 장 배열 순서, 현재 제목·질문·기간·원고 |
| 구조화된 생각 | `excluded=false`인 해석만 포함. 직접 쓴 생각·모르는 점·근거/반례 역할을 구분 |
| 장 원고 | `chapter.note` 원값 유지. 제외한 생각과 같은 문장을 사용자가 직접 썼더라도 자동 삭제하지 않음 |
| 원문 참조 | 장 전체 목록과 개별 생각의 두 목록은 독립. 같은 버전이 다른 역할에서 사용되면 그 역할은 유지 |
| 출처·본문 | 선택한 정확 버전의 작성자 관계·작성 시점·URL·포함 범위·누락. 본문은 명시적 옵션, 확보하지 않은 본문은 생성하지 않음 |
| 누락·빈 상태 | 빈 책·빈 장·작성 중인 빈 생각·근거 미선택·본문 미확보·없는 참조를 서로 다른 사실로 표시 |

‘원고에서 제외’의 범위는 해당 구조화된 해석이다. 원문 삭제·전역 분석 제외·JSON/동기화 제외가 아니다. 다른 활성 해석이나 장 전체 목록에 같은 원문이 있다면 그 출처와 선택 본문은 계속 나올 수 있다. 제외한 항목을 검토하고 복원하는 기능은 기존 편집 화면에서 유지한다.

### 안전한 평문 읽기와 기존 Markdown

기존 `Books.markdown`은 출처·보관 원문·구조화 해석에 동적 fence를 사용하고 **장 원고 `chapter.note`는 raw 문자열**로 내보낸다. 이번 브라우저 읽기는 **Markdown 문법을 렌더링하지 않는다.** 앱이 구성한 책/장 제목과 목록은 구조화해 보여주지만 원고·원문의 `# 제목`, `**강조**`, 링크·이미지 구문·HTML 태그는 글자 그대로 표시한다.

원문과 사용자 원고를 `Text`/`textContent`로 넣고 `innerHTML`, Markdown→HTML 변환, 외부 embed·이미지 실행 경로로 넘기지 않는다. 읽기 화면을 열거나 본문을 포함했다고 출처 사이트를 자동 요청하지 않는다. 출처를 사용자가 명시적으로 여는 기존 행동과 자동 리소스 로딩을 구분한다.

**화면과 파일의 일치는 내용·순서·포함 범위에 대한 계약**이다. 외부 Markdown 편집기의 서식·줄바꿈·쪽나눔과 같은 시각 결과를 보장하지 않는다. 화면 DOM을 파일로 역변환하거나 Markdown 문자열에서 장 구조를 다시 파싱하지 않는다. 다운로드된 파일 수정은 앱 원고를 자동 변경하지 않으며 복원용 백업은 기존 자료·구성 JSON이다.

## Local 선행 조건과 다음 단계

**이번에는 새 migration·SQL validator·DB schema 변경이 없다.** 다만 앱이 읽는 책과 해석은 선행 PR의 저장 계약에 의존한다. Local은 이미 완료한 작업을 재실행하지 않고 현재 적용 상태를 확인한다.

1. **PR #46 책 구성:** [책 validator와 설치 확인](book-projects.md#local-인계)의 적용·읽기 전용 12조건을 확인한다.
2. **PR #47 장별 생각:** [해석 validator와 설치 확인](book-insights.md#local-인계와-다음-단위)의 적용·읽기 전용 13조건을 확인한다. 선행 SQL의 격리 검사 통과를 운영 설치·실제 권한·왕복 성공으로 대신하지 않는다.
3. 선행 PR의 병합·배포·서버 확인 후 이번 UI를 반영하고 실제 앱에서 책 읽기·장 수정·복귀·Markdown 보관을 확인한다. Cloud 문서 작업은 운영 SQL·병합·배포를 실행하지 않았다.

다음 단계는 **현재 원고의 명시적 개정본을 남기고 비교·되돌리는 흐름**, 이어 **한글 PDF·인쇄용 책자 출력**이다. 개정본의 저장·백업·동기화 계약과 개인용/공개용 내용 선택을 별도로 설계한다. 이번 읽기 화면이나 Markdown 다운로드를 원고 개정 이력·PDF 미리보기·공개 출판으로 보고하지 않는다.
