# 재발견 품질: 작은 한글 자료군과 반대 사례 평가

2026-10-07. **이번 결론은 알고리즘 유지다.** 12개 익명 자료에서 상투어 오탐과 조사 변형 누락을 확인했다. 두 불용어 추가 실험은 별도 돌봄 사례에서 실제 연결을 놓쳐 기각했다. 새 라이브러리·AI·형태소 분석·점수 체계·저장 형식은 도입하지 않았으며 `assets/life/rediscovery.js`의 최종 변경은 없다.

현재 방식은 실제 단어가 일치한다는 사실을 설명하지만, 그 사실만으로 함께 읽을 가치가 보장되지는 않는다. 이번에는 [기존 근거·버전 계약](rediscovery.md)을 보존하는 평가 자료와 회귀 검사를 추가했다.

## 자료와 방법

Apple 메모 4개, Obsidian 3개, Instagram 캡션 3개, 네이버 본문/링크 2개로 총 12개다. 개인 자료를 쓰지 않았다. 전체 제목·본문은 [`qualitySamples`](../../tests/life-rediscovery.test.cjs)에 있으며, 테스트에서 ‘주말 관찰 노트’의 최신 본문을 천문 관찰로 바꾼다. 각 자료의 주제와 기대 연결을 먼저 정하고 현재 엔진을 실행했다.

첫 기준은 ‘비 온 뒤 동네 정원을 걷다’다. 캡션과 행사 링크는 같은 정원 산책 자료, 조사만 바뀐 녹지 관찰은 의미상 관련 자료로 보았다. 소설·회의·커피·기차·요리는 주제상 무관하다. ‘돌담 옆 화단’은 내용상 관련되지만 사용자가 기준 원문에서 제외한 별도 정책 사례다.

최대 3개 제한이 문제를 숨기지 않도록 기준과 후보 한 쌍씩의 자격 판정을 함께 확인했다. 이는 전체 목록의 순위 정확도 측정이 아니다. 전체 12개를 함께 계산한 한 실행에서는 행사 링크·캡션·커피 기록이 나왔다. 동점은 기존 source ID 순서이므로 다른 ID로 새 fixture를 만들면 동점 후보 순서가 달라질 수 있다. 이 한 화면을 precision@3나 제품 전체의 정확도로 일반화하지 않는다.

## 작은 수정 실험과 기각 이유

기존 whole-token 불용어에 `도움이`, `되었다`만 임시 추가했다. 초기 자료에서는 다섯 무관 후보가 사라지고 캡션·링크가 남았다. 하지만 같은 자료만 다시 맞추는 것으로는 채택할 수 없어, 초기 12개에 없던 아래 대조쌍을 양방향으로 확인했다.

| 별도 대조쌍 | 기대 | 기존 → 두 불용어 실험 |
| --- | --- | --- |
| ‘도움이 필요한 이웃에게 연락했다’ ↔ ‘도움이 필요한 어르신에게 안부를 물었다’ | 돌봄·자원활동의 실질적 연결 | 양방향 연결 → **양방향 누락**. `도움이`가 주제어 역할도 하므로 전역 제외는 부적절 |
| 서로 다른 돌봄 본문에 사용자가 명시한 동일 주제 `도움이 필요한 이웃` | 정확 버전의 명시 주제 보존 | 양방향 주제 연결 유지 |
| ‘도움 요청 방법’ ↔ ‘도움 요청 창구’ | 실질적인 도움 요청 연결 | 양방향 `도움`, `요청` 유지. 부분 문자열이 아니라 whole-token 정책인 점 확인 |
| 두 천문 관찰 글의 앞부분에 ‘도움이 되었다’, 뒷부분에 `천문학 망원경` | 실제 내용도 관련 | 연결 유지. 기존 설명은 상투어 두 개, 실험 설명은 천문학·망원경으로 바뀜. 후보 자격뿐 아니라 **설명에 더 유용한 근거가 나오는가**도 별도 과제임 |
| 가계부와 수영 수업에 ‘일단 시간을 따로 정했다’ 반복 | 무관 | 양방향 오탐 유지. 실제 표시된 `일단`, `시간을`만으로 주제 연결을 설명하기 어려움 |

이 대조쌍도 같은 검토자가 만든 작은 반대 사례이며 통계적으로 독립된 사용자 모집단이나 정식 블라인드 벤치마크는 아니다. 한 종류의 명확한 기능 저하만으로도 두 불용어 실험을 채택하지 않을 이유는 충분했다. 실험 코드는 되돌렸고, 실질적인 도움 관련 연결과 명시 주제 보존을 회귀에 추가했다. `되었다` 하나만 추가하는 등의 반복 미세 조정으로 이번 자료의 점수를 맞추지 않았다.

## 보존 검증과 품질 판단의 구분

`node --test tests/life-rediscovery.test.cjs`: **22/22 통과**. 이번에 2개 검사를 추가했다.

- 12개 원문 쌍을 양방향으로 순회하며 표시한 단어가 실제 기준·후보 문자열에 있고 snippet이 후보 본문에서 나온 것을 확인했다. 링크 본문은 만들지 않았다. 기준은 선택 버전, 후보는 해당 source의 최신 버전이며 방향 있는 제외·제외의 역방향·입력 데이터 불변을 확인했다.
- 돌봄·도움 요청·천문 대조쌍과 사용자의 명시 주제를 양방향으로 확인했다. `도움이`를 일괄 제거하는 수정은 이 검사에서 실패한다.

이 검사는 ‘원문 근거와 데이터 경계가 거짓으로 표시되지 않는다’는 보존 검사다. 현재의 무관 후보를 원하는 동작으로 고정하는 assertion은 추가하지 않았다. **기능 검사 통과가 관련성 평가의 오탐·누락을 해결했다는 뜻은 아니다.** 앱·UI 변경이 없어 새 브라우저 캡처나 기존 전체 브라우저 검사를 반복하지 않았다. 실험 원본은 `.local/rediscovery-quality/`에 있으며, 재현 가능한 주요 자료와 보존 검사는 위 테스트 파일에 남았다.

## 다음 비교 단위

다음은 불용어를 계속 늘리는 작업보다 **별도 한국어 검색·재발견 평가셋과 알고리즘 비교**가 먼저다. 동의받은 익명 실제 자료 또는 서로 다른 작성자의 합성 자료에서 다음을 구분한다.

1. 조사·활용형·동의어 때문에 놓치는 관련성, 반복 생활 표현 때문에 생기는 오탐, 제목만 확보한 링크를 별도 표시한다.
2. 자료 작성에 사용하지 않은 평가쌍을 분리하고, 공통 표현 억제와 실질적 도움·시간·읽기 주제 보존을 함께 본다. 방향 있는 제외와 정확 버전은 모든 후보 방식의 필수 조건이다.
3. 현행 exact-token을 기준으로 제한적 어형 처리·빈도에 따른 공통어 억제 등 작은 대안을 같은 자료에 비교한다. 후보 선정과 표시 이유의 유용성을 따로 평가한다. 데이터 전송·임베딩·외부 AI는 별도 범위다.
4. 새 결과를 위해 저장본·공개본을 바꾸지 않는다. 품질 이득과 회귀가 확인되기 전에는 점수 체계나 라이브러리를 교체하지 않는다.

이번 결과는 12개 자료와 5개 대조쌍의 제한된 판단이다. 추천의 일반 정확도, 사용자의 신념·관심, 실제 Apple 기기에서의 유용성을 증명하지 않는다.
