# 좋아요·담기에서 개인 추천까지

2026-10-19 KST. 사용자가 [SNS·오픈소스 조사](recommendation-feedback-research.md) 뒤 진행을 요청한 첫 구현 묶음이다. 목표는 **새 글 → 좋아요/담기 → 각 목록에서 원문 재열기 → 해제·복구 → 개인 추천 반영·끄기 → 전용 사본 보관**이다. 기존 원문·읽음/제외·주제/출처 설정과 자동 목록 갱신을 보존한다.

## 범위와 의미

좋아요와 담기는 계정·작업공간별 이 브라우저의 독립된 반응이다. 둘을 동시에 선택하거나 각각 해제할 수 있다. 담기는 나중 읽기/참고 목록이며 긍정 취향으로 학습하지 않는다. 좋아요도 글에 대한 반응이지 사용자의 신념·본문 전체에 대한 동의가 아니다. 원문 열기·읽음·무반응은 긍정/부정 학습 신호를 생성하지 않는다.

도구 → 새 글 찾기에 새 글·좋아요한 글·담은 글·취소한 글을 연결한다. 좋아요/담은/취소 목록에서는 새 글 검색용 주제·옵션·정렬을 접어 보관한 글을 바로 읽고, 새 글로 돌아오면 기존 입력 DOM을 복구한다. 선택을 취소한 행은 되돌릴 수 있고, 완전히 지우기는 두 반응과 복구 메타데이터를 제거한다. 반응/목록 초기화는 개인 추천도 끈다. 자료실 원문을 지우거나 실제 원문을 자동 보관하는 동작은 없다. 기존 링크 보관 검토는 별도로 유지한다.

개인 추천은 기본 꺼짐이며 사용자가 켜거나 개인 추천을 명시 선택하면 저장 성공 후 계산한다. 최신순·관심순에는 좋아요 점수를 섞지 않는다. 끄면 직전에 선택한 기준 순서로 복귀하고 좋아요·담은 목록은 유지한다. 새 진입의 기준 순서는 관심순이다. 한 반응을 누른 순간 현재 읽는 행이나 순서를 바꾸지 않고, 새 추천 보기에서 다음 순서를 적용한다. 좋아요 해제·근거 제외 때는 이전 개인 점수·근거를 버리고 현재 행의 표시 순서만 잠시 유지한다.

## 독립 저장과 보존

[DiscoveryActions](../../assets/life/discovery-actions.js)는 schemaVersion 1, workspaceId, revision, deleted, updatedAt, personalizationEnabled, entries를 갖는다. URL별 liked/bookmarked, 각 시각, 추천 근거 제외, 최소 공개 snapshot을 저장한다. 기존 관심·읽음/제외·설정 schema는 변경하지 않는다. 500행/직렬화 1MiB 미만이며 용량 초과 때 조용히 오래된 항목을 지우지 않는다.

Snapshot은 allowlist 출처·HTTPS URL·권리/범위를 확인한 제목·태그·출처명·작성자·날짜 등 목록용 메타데이터다. 본문·요약·개인 메모를 복사하지 않고 link_only/metadata_only로 제한한다. 의미 query의 raw 표기와 canonical URL 계약을 재사용하며 provider ID 재사용으로 다른 글을 같은 반응으로 바꾸지 않는다.

처음 좋아요하거나 해제 뒤 다시 좋아요할 때 실제 선택한 카드의 메타데이터를 남긴다. 이미 좋아요한 상태에서 담기를 바꿔도 그 좋아요 근거를 새 제목/태그로 바꾸지 않는다. 이 snapshot은 본문 버전 보존이 아니다. 공급 목록에서 빠지거나 출처를 꺼도 보관된 목록에서 URL을 다시 열 수 있고, 원문 접근 가능 여부를 자동 검사하지 않는다.

[Storage](../../assets/life/storage.js)의 별도 `discoveryActions:accountKey:workspaceId` 메타 CAS를 사용한다. owner/project/workspace·revision·transaction 완료·dispose 취소를 재사용하고 원문 bundle/구성 revision을 바꾸지 않는다. 초기화도 revision을 남긴다. 저장 실패·충돌은 대상 boolean intent를 유지하며 최신 확인→명시 재시도/취소를 제공한다. 본인 저장 알림은 같은 facade에서만 local로 표시하고, 다른 탭에는 종류·공간·revision·sender만 전송한다. 외부 채널의 local 표시는 신뢰하지 않는다.

끄기는 저장 실패나 다른 저장의 완료를 기다리지 않고 개인 결과를 중지한다. 다른 탭의 변경도 최신 조회 전에 이전 근거를 제거한다. 이탈 중 바뀐 반응·설정은 복귀 시 이전 개인 결과를 되살리지 않는다. 입력과 한글 조합, 인증 확인 전 화면 중단·검증 후 복귀 경계는 기존 계약을 유지한다.

## 개인 추천 정책

[DiscoveryRecommendations](../../assets/life/discovery-recommendations.js)의 `public-title-tags-v1`은 학습 모델이나 확률이 아닌 설명 가능한 로컬 규칙이다. [기존 Discovery](../../assets/life/discovery.js)의 검증·공통 후보 풀·정렬 투영을 재사용한다. 기준 순위 출력은 바꾸지 않는다.

1. 출처 선택·유효 URL·권리·이미 보관/읽음/제외·중복 조건을 먼저 적용한다.
2. 허용된 과거 좋아요의 저장 당시 공개 제목·태그만 사용한다. 담기·취소 횟수·클릭·읽음은 사용하지 않는다. 꺼진 출처·추천 근거 제외·미래 반응/미래 수집 메타데이터는 신호에서 뺀다.
3. Unicode 단어 토큰과 기존 검토된 단일 단어 별칭만 대조한다. 짧은 토큰·일반 안내어를 제외하고, 한 과거 좋아요와 최소 두 정보 토큰이 겹친 후보만 고른다. 임의 부분 문자열·형태소 확장·의미 추론은 하지 않는다.
4. 겹친 단어는 1점, 양쪽 모두 태그인 단어는 추가 1점이다. 같은 표현 반복이나 여러 좋아요 수를 누적하지 않고 가장 강한 한 글의 근거를 쓴다. 점수·기존 관심 근거·날짜·안정 URL로 정렬한다. 최고 남은 점수의 1점 이내에서 아직 쓰지 않은 출처를 우선해 편중을 줄인다. 무관한 글로 빈자리를 채우지 않는다.
5. 꺼짐·유효 신호 부족·겹치는 후보 없음이면 같은 입력의 기존 관심순/최신순 결과를 그대로 반환한다. 이미 좋아요한 글 자체를 새 추천 성과로 세지 않는다. 명시된 관심/피드백 작업공간이 반응과 다르면 개인 계산을 거절한다.

화면의 추천 이유는 어느 보관 제목/태그와 어느 후보 표현이 겹쳤는지다. 사본의 태그 진위를 확인했다는 의미로 표시하지 않는다. 모든 계산은 브라우저에서 수행하며 개인 점수/벡터를 서버나 공개 JSON으로 내보내지 않는다. 별도 모델·임베딩·벡터 DB·추천 서버·새 라이브러리를 추가하지 않았다. 조사 당시 [오픈소스 비교와 재사용 판단](../life-tools-design/open-source-review.md)을 따른다.

**품질 한계:** 두 단어가 겹치는 동음이의어도 오탐할 수 있다. 예를 들어 프로그래밍과 자연어 문맥을 표면 토큰만으로 구별한다고 보장하지 않는다. 한국어 조사·띄어쓰기 차이와 짧은 제목 때문에 관련 글을 놓칠 수도 있다. 현재 공개 공급 50개는 모두 본문 없는 링크 정보이며 주제별 공급 부족은 순위 계산만으로 해결하지 못한다. 규칙값은 초기 정책이며 최적 가중치·사용자 유용성·의미 이해를 입증하지 않았다.

## 전용 사본

목록 사본과 초기화에서 활성 좋아요·담기만 JSON으로 내보낸다. 계정 ID·작업공간 ID·서버 연결·원문/개인 메모·개인 추천 설정·취소 이력은 파일에 넣지 않는다. 이 파일은 사용자의 사적 선택이므로 개인 파일이며 공개 수집 artifact에 포함하지 않는다.

사본에서 추가는 파일 크기·UTF-8·JSON strict shape·500행/1MiB·등록 출처·URL·날짜·범위를 검사한 후 미리보기와 명시 적용을 거친다. 기존 URL의 선택과 취소 행을 모두 우선하고 새 URL만 추가한다. 가져온 반응은 추천 근거에서 제외하며 개인 추천도 끈다. 기존 반응을 덮어쓰는 전체 복원이나 새 작업공간 생성은 아니다. 사용자가 각 반응의 추천 허용을 다시 선택할 수 있다. 손상·초과·충돌은 기존 자료와 확인 중 파일 선택을 보존한다.

내보내기는 유효 파일을 같은 크기 한도 안에서 다시 읽을 수 있게 공백 없는 JSON을 쓴다. 다운로드 요청과 실제 OS 파일 보관은 구분한다. 앱 밖의 사본을 자동 회수하지 않으며, 파일을 골랐다는 이유로 개인 추천을 다시 켜지 않는다. 현재 로컬 목록은 기존 원문/구성 백업·서버 동기화·공개 사본에 자동 포함되지 않는다.

## 체험

`npm run dev` → 도구 → 새 글 찾기에서 주제/출처를 선택하고 같은 글에 좋아요와 담기를 각각 누른다. 좋아요한 글·담은 글에서 상태를 확인하고, 한쪽만 해제해 다른 상태가 유지되는지 확인한다. 취소한 글에서 복구하거나 목록 정보를 완전히 지울 수 있다.

개인 추천을 켜고 새 추천 보기를 누르면 겹치는 표현이 있는 다른 글과 이유를 확인한다. 근거가 부족하면 기존 기준 순서를 보여 준다. 최신순을 선택해 비교한 뒤 개인 추천을 껐을 때 그 순서로 돌아오는지 확인한다. 목록 사본을 받은 뒤 파일을 골라 미리보기에서 기존 항목 유지/새 항목 수를 확인하고 추가한다. 자동 원문 보관·읽음·공개가 발생하지 않아야 한다. localhost는 실제 외부 기기에서 접근 가능한 배포 주소와 다르다.
