# 네이버 글 수집·본문·사진 보관을 함께 완결하는 실행 설계

2026-10-21 UTC · 사용자 요청에 따른 작업 범위 검토. 기준 main `d6009ea`, [추출 오픈소스 조사](naver-extraction-open-source.md)를 반영한 설계이며 아래 기능의 신규 구현·운영 가동은 아직 하지 않았다.

## 목표와 사용 흐름

**블로그 아이디 연결 → 확인한 공개 목록에서 기존/새 글 대조 → 선택한 과거 글 또는 켜 둔 연결의 새 글 본문 수집 → 본문·사진의 확보 범위 확인 → 비공개 서버 보관 → 같은 계정의 다른 기기에서 받기 → 필요한 내용으로 글쓰기·파일 보관 → 같은 목록 복귀**를 한 작업 묶음으로 완결한다.

첫 연결의 목록 확인과 과거 글 본문·사진 일괄 다운로드는 별개다. 과거 글은 사용자가 선택해 받고, 이후 자동 수집은 아래 기준 목록을 완료한 뒤 **새로 발견한 공개 글**이라는 범위를 안내하고 연결에서 명시 선택한다. 수집 자료를 직접 작성한 글로 추정하거나 홈의 내 글·새 초안·공개본을 자동 생성하지 않는다. 본문 수정이나 RSS 미등장으로 기존 자료·인용·사진을 삭제하지 않는다.

## 저장·식별 계약

- **연결과 목적 공간을 분리한다.** 같은 계정의 기존 연결을 발견하고 선택한 공간에 받는다. 기기가 바뀌었다는 이유로 같은 블로그 연결이나 파일을 다시 만들지 않으며, 다른 계정의 연결은 보이지 않는다. 계정 전체 미보관과 현재 공간에 없는 상태를 같은 의미로 표시하지 않는다.
- **글 정체성은 기존 blogId/logNo를 재사용한다.** 글 제목·날짜·파일명만으로 중복 판정하지 않는다. 다른 origin/여러 자료가 같은 URL이면 후보로만 제시하고 자동 병합하지 않는다. URL 없는 수동 자료의 동일성은 추정하지 않는다.
- **자동 수집의 기준 목록을 고정한다.** 연결별 첫 공개 목록·완료 상태/시각을 보관하고, 완료 뒤 새로 확인된 ID를 자동 수집 후보로 삼는다. 이는 새로 발견한 공개 글이며 설정 후 실제 작성된 글이라고 단정하지 않는다. 첫 목록·확인하지 못한 페이지의 글·현재 목적 공간에 없는 글을 새 게시물로 추정하지 않는다. 기준 목록이 미완료면 자동 본문/사진 수집은 보류하고 선택 받기만 제공한다. 새 기기 수신이나 목적 공간 변경으로 기준 목록을 초기화하지 않는다.
- **본문 수집 판과 추출 판을 구분한다.** 관측 시각·추출기 버전과 실제 원문/미디어 변경을 분리해, 재조회나 추출기 업그레이드만으로 네이버 글이 수정됐다고 표시하지 않는다. 수집 본문과 변환 본문의 hash/형식을 구분하고 미확인 작성일은 만들지 않는다.
- **옛 버전을 보존한다.** 기존 RSS 행과 source URL을 재작성하지 않는다. 보완은 Core의 existingSourceId·exact_duplicate/new_revision과 기존 CAS를 사용한다. 옛 UTF-16 인용·근거는 최신 본문으로 치환하지 않는다.
- **사진은 원문 버전에 연결한다.** 원문 텍스트/인용 위치를 깨지 않는 별도 명세·Blob 경로를 사용한다. 사진 라벨·갤러리 안내가 발췌 텍스트에 섞이지 않도록 읽기 영역을 분리한다. 기존 PhotoPost의 형식/바이트 검증을 재사용하되 지원 형식·장수 한도를 넘으면 명시 보류하며 조용히 자르지 않는다.
- **서버·로컬·파일의 보관 범위를 일치시킨다.** 본문 판과 사진 명세 설치는 원자적으로 확인하고 파일은 해시를 검증한다. 현재 텍스트 JSON을 사진 포함 백업으로 부르지 않는다. 새 사진 보존 계약은 명시 버전으로 구분하고 기존 JSON·글 ZIP·Preservation 읽기/복원 계약을 유지한다.

## 재사용과 새 구현

기존 연결 UI, 블로그 ID/글 번호 검증, Auth·RLS, Core 불변 원문·재가져오기, Storage CAS·계정/공간 전환 guard, 본문/근거 원자 저장, PhotoPost 사진 바이트 검사, 자료로 글쓰기·글 서버 보관, fflate와 기존 선택 백업을 재사용한다. 뉴스·작성기·CMS·공개 시스템을 새로 만들지 않는다.

새 구현은 **목록 인벤토리/재개 상태, 순수 추출 어댑터, 계정 연결 발견과 수집 판 계약, 원문 사진 명세·비공개 파일 저장/보존, 검토 입력·목록 복귀 연결**에 한정한다. 서버 스키마는 이미 설치한 migration을 수정하지 않고 추가한다. 새 렌더러·브라우저 worker·별도 Python 서비스는 정적 추출/기존 화면으로 요구를 충족하지 못한다는 근거가 있을 때만 비교한다.

## 외부 선행과 시작할 수 있는 범위

현재 관측 spec360은 최신/enforced이며 네이버 허용 호스트가 없다. 라이브 네이버 요청·차단 우회는 하지 않았다. 네이버 본문/RSS 접근 허용, 실제 응답·robots/접근 조건 확인, 서버 비공개 실행 자격과 일정 준비가 실수집 가동의 선행이다. 사진 CDN은 실제 본문에 등장하는 출처를 확인해 필요한 호스트만 같은 운영 설정 묶음에 포함한다. URL 발견을 임의 호스트 다운로드 허용으로 해석하지 않는다.

접근이 막힌 동안에도 추출 순수 함수·합성 입력, 저장/미디어 계약, 검토 입력·목록 왕복과 실패 복구 연결은 구현할 수 있다. 이를 실제 블로그 수집·전체 과거 글·원본 사진 확보·예약 운영 성공으로 기록하지 않는다. 실제 검증 전 기존 수집 gate는 비활성으로 유지한다.

## 한 묶음의 완료 기준

1. 확인한 공개 목록에서 기존/새/보완/보류를 올바르게 구분하고, 중간 중단·목록 변경 뒤 이어받는다. 전체 목록을 확인하지 못했으면 미확인 범위를 표시한다.
2. 실제 대표 글의 문단·링크·접힘·누락과 사진을 대조한다. 기존 일부 본문에 새 판을 명시 보완하고 옛 정확 인용을 그대로 연다.
3. 사진별 실수신 해시/픽셀/순서/설명을 서버와 새 기기의 독립 저장소에서 대조하고 실제 연다. 원본 여부 미확인을 유지한다.
4. 선택한 문단·사진으로 기존 글쓰기를 마치고 저장·재열기·원래 네이버 목록 복귀를 확인한다. 선택 파일 복원 후 같은 본문·사진·근거가 열린다.
5. 앱을 닫은 동안 실제 예약 실행과 서버 보관을 확인하고 재접속해 같은 판을 한 번 받는다. 본문/사진 일부 실패·최종 응답 유실·동시 탭/다른 기기·중지·계정 변경을 포함해 복구한다.
6. 새 게시물이 실제로 관측되지 않았다면 최초 수집·반복 멱등만 완료로 기록하고 신규 게시 감지는 미확인으로 남긴다. 실제 Google/Apple 기기 체험도 합성 검수와 구분한다.

이번 설계 검토에서는 파일·버전/원문 보완·사진·서버·UI·독립 검수를 분담해 현재 코드의 공백을 대조했다. 제품 코드 수정·운영 DB/설정 변경·실제 수집·새 테스트 실행은 하지 않았다. 다음 실행 목표는 위 사용자 흐름 전체이며 별도 기능 수 증가를 목표로 삼지 않는다.
