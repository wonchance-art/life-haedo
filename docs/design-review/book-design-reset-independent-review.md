# 책 작업실 비교 시안 독립 디자인 검토

2026-10-09 KST · 검토자 design_finish_review · 최종 확인 · 실제 앱 적용 승인과 별개

## 1. 판정

**disposition: ship — 사용자에게 비교 시안을 제시할 수 있다.** 실제 앱 구현·병합·배포 승인이라는 뜻은 아니다. 우선 추천은 **A · 원고 중심**이며, 장을 자주 오가는 집필에는 **B · 편집 작업실**을 비교할 이유가 있다.

1차 판정은 fix였다. 모바일 A/B의 구조적 차이 부족, B 목록의 중복 목차, 배경색 계약 불일치, 비교 도구와 제품 화면의 구분을 한 배치로 수정한 뒤 최종 확인했다. 추가 심미 수정 없이 비교 단계에서 마감할 수 있다.

검토 입력은 [방향 계약](book-design-reset.md), [기존 감사](book-design-reset-audit.md), [비교 HTML](evidence/book-design-reset/comparison.html), [craft floor](../../.agents/skills/impeccable/reference/craft-floor.md)다. 자동 detector는 실행하지 않았다. 1차 18개와 최종 18개 PNG를 각각 `view_image`로 열었고 contact sheet로 대신하지 않았다. 모든 최종 캡처에 해당 화면과 한글 원고가 보이며 빈 캡처·검은 영역·화면명 불일치는 없다. 기존 화면은 `before/editor-390.png`, `before/reading-390-arrival.png`, `before/list-1440.png`도 실제로 열었다.

최종 캡처는 독립 HTML의 `presentation=1`이 비교 도구·예시 안내만 숨긴 실제 렌더다. 이미지에서 도구를 지운 편집본이 아니다. 기본 체험 HTML에는 시안 선택과 안내가 남는다. 캡처 높이는 세 폭 모두 900px로 기존 감사의 1440/820×1000, 390×844와 다르므로 첫 화면의 줄 수를 동등한 양적 성과로 비교하지 않는다. 1차 대비 약 90px가 올라온 부분은 비교 도구 제외의 결과이며 앱 디자인 개선으로 계산하지 않는다.

## 2. 핵심 시각 판단

**필수 결함은 해결됐다.** B 모바일은 상단 장 선택을 드러내고 A는 접어 쓰는 목차를 유지한다. B 목록은 장 구성 → 원고 앞부분 순서이며, A는 원고 앞부분 → 읽기/집필 → 장 구성 순서다. 따라서 이제 390px에서도 색만 다른 두 안은 아니다. B 목록의 sidebar를 없애 제목·목차 중복도 제거했다. A는 흰 원고, B는 흰 원고와 옅은 청회색 목차 면으로 계약이 구분된다.

남은 시각적 비용은 다음과 같다. 이는 비교 제시를 막는 결함이나 추가 수정 지시가 아니다.

- **A:** 목록의 긴 책 제목이 모바일에서 세 줄을 차지하며, 목차는 읽기·집필 화면에서 아이콘을 열어야 발견할 수 있다. 책 아이콘이 목차와 전체 읽기 양쪽에 쓰이므로 처음 보는 사람에게 의미가 완전히 자명하지는 않다.
- **B:** 모바일 읽기의 장 선택, 책 제목, 장 번호와 장 제목이 위쪽에 함께 놓인다. 원고 첫 요소가 A보다 72px 아래다. 상시 탐색을 얻는 대신 읽기 지면을 쓰는 선택이며, 현재 사용자의 본문 집중 요구에서는 A를 추천하는 이유다.
- **B 820px:** 고정 목차와 본문을 함께 볼 수 있지만, 긴 책 제목과 네 장 목록이 왼쪽에 계속 보인다. 1차보다 제목 무게를 낮춰 경쟁은 줄였으나 집중 읽기에서는 여전히 A보다 프레임이 많다.

TYPE은 같은 한글 산세리프와 분명한 제목/본문 위계로 계약에 부합한다. MATERIAL은 평평한 문서와 실제 SVG 조작이며 불필요한 종이·그림 효과가 없다. GROUND는 최종 이미지에서 흰 본문과 제한된 옅은 색으로 수정됐다. 단정한 활자·간격이 중심이고 장식으로 빈 공간을 채우지 않는다.

넓은 A 본문은 19px/37.05px, B 읽기는 17px/32.3px, 모바일 두 안은 17px/32.3px다. 같은 한글을 읽는 비교에서 A는 큰 활자, B는 더 많은 문장과 탐색이라는 차이를 보인다. textarea 내부 높이와 내용 높이가 같은 측정은 기존 이중 스크롤 축소를 뒷받침하지만 실제 한글 입력 안정성을 대신 증명하지 않는다. 수치가 낮거나 검사에 통과했다는 이유로 디자인을 좋다고 판정하지 않았다.

### 추가 확인: 원문을 펼친 1440px

기본 18화면 이후 [A 원문 펼침](evidence/book-design-reset/after/A-sources-1440.png)과 [B 원문 펼침](evidence/book-design-reset/after/B-sources-1440.png)을 각각 `view_image`로 추가 확인했다. 이 두 상태의 시각 검토만 보완했으며 전체 검토나 기능 검사를 다시 실행하지 않았다. **비교 시안 제시 가능 판정과 A 우선 추천은 유지한다.**

A는 원문을 장 번호·원문 접기 행 바로 아래에 배치해 펼친 결과가 첫 화면에서 보인다. 연결 원문, 작성자·날짜·확보 범위·이전 버전, 별도의 `내 해석`을 확인한 뒤 원고가 이어지는 한 열이다. 원고 제목과 본문이 아래로 밀리므로 펼친 동안은 자료를 먼저 읽는 선택이며, 짧게 확인하고 같은 접기 조작으로 원고에 돌아오는 방향에 맞는다. 접기 조작은 화면 위에 보이지만 실제 닫기와 초점 복귀는 이 이미지로 검증한 것이 아니다.

B는 목차·원고·원문을 나란히 보여 집필 문장과 연결 자료를 동시에 대조할 수 있다. 오른쪽 자료 열은 폭이 좁아 출처 메타데이터와 URL, 해석 문장이 여러 줄로 감기지만 가로 넘침이나 원고와의 영역 혼동은 보이지 않는다. 자료를 길게 읽는 편안함은 A가, 원고와 비교하는 동시성은 B가 더 낫다. 두 안 모두 `이전 버전`과 `내 해석`을 원고와 구분해 표시한다. 이 추가 확인은 1440px 펼침 상태에 한정하며 820/390px의 펼침 화면이나 실제 자료 이동을 확인한 것으로 확대하지 않는다.

## 4. 우선 수정 목록과 처리

| 우선순위 | 1차 요구 | 최종 확인 |
| --- | --- | --- |
| 1 | B 모바일 탐색을 색 이외의 구조로 구분 | 집필·읽기의 native 장 select, 목록의 장 구성 우선 순서로 해결. 기존 목차 아이콘과 중복하지 않음. |
| 2 | B 목록 제목·목차 중복 제거 | 세 폭 모두 목록 sidebar가 사라지고 목차 한 벌만 보임. |
| 3 | A 흰 원고 / B 청회색 목차 | 세 폭의 실제 화면에서 확인. |
| 4 | 시안 도구와 제품 화면 구분 | 명시적인 presentation 모드 캡처, 기본 체험 HTML의 도구는 보존. 높이 차이와 y값 해석을 위에 기록. |

**비교 시안 완결을 위한 미처리 필수 수정은 없다.** 실제 앱 적용을 선택한다면 이후 범위에서 목차 발견성, B 모바일 중복 제목의 읽기 비용, 실제 기기의 입력·복귀를 확인해야 한다. 지금 새 기능·전체 앱 시험·추가 심미 루프를 늘릴 이유는 없다.

## 5. 추천과 남은 제약

**A를 우선 추천한다.** 책의 실제 문장으로 대상을 알아보고, 장 원고를 같은 단일 열에서 읽고 쓰는 구조가 본문 집중·간결한 프레임이라는 사용자 의도에 가장 가깝다. 반대 근거는 접힌 목차를 찾는 비용과 긴 책 제목의 지면이다.

**B는 집필 중 장 이동이 잦다면 선택할 만하다.** 넓은 화면의 고정 목차와 휴대폰의 장 select가 같은 탐색 우선 방향을 이어간다. 반대 근거는 읽는 동안 남는 탐색 프레임과 모바일 첫 본문의 하강이다. 두 안은 이제 장단점을 실제 화면으로 비교할 수 있다.

이 검토는 기본 상태와 위 1440px 원문 펼침 두 화면의 시각·내용 위계 평가다. 그 외 펼침 폭, 오류·빈 목록·로딩·많은 책, 초점·IME·소프트 키보드·스크롤 중 sticky 동작은 별도 QA 범위이며, 실제 iPad/iPhone 사용은 수행하지 않았다. 기능 QA 성공도 사용자 선호의 증거가 아니다. 책·원고의 동일성은 제공된 자료 계약과 별도 QA에 의존하며 이미지의 한글을 전부 문자열 대조한 것은 아니다. 실제 앱 파일·저장 구조·DESIGN.md·배포는 이 리뷰가 승인하지 않는다.
