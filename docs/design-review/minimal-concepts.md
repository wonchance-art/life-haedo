# 비교 03 · 본문 중심의 세 가지 자료 화면

2026-10-03. 최신 요청은 **본문에 집중하고 기본 메뉴·프레임을 극도로 줄이며 직관적인 문양만 사용하는 화면**이다. 이전 02의 컬러 링·타일·상시 패널을 유지하는 것을 목표로 삼지 않는다. [실행 시안](../../social-sample.html)의 A/B/C는 같은 익명 자료 12건을 사용하며 목록의 폭과 밀도를 비교한다. 기존 운영 앱은 변경하지 않았다.

## 공통으로 바뀐 것

- 흰 바탕과 시스템 한글 산세리프를 사용한다. 큰 소개 문구, 주제 링, 컬러 문장 타일, 상시 옆 패널과 중복 범위 탭을 없앴다. 검색과 자료의 제목·문장이 기본 화면을 차지한다.
- 넓은 화면의 메뉴는 72px 아이콘 레일, 모바일은 하단 5개 아이콘이다. 책·돋보기·북마크·인용부호·더하기는 각각 모아보기·검색·다시 볼 자료·내 발췌·가져오기에 대응한다. 보이는 글자 메뉴는 줄여도 버튼의 `aria-label`, 키보드 초점과 hover/focus 도움말은 유지한다. 조작 영역은 44×44px이다.
- 출처·주제는 검색 옆 필터 아이콘을 눌렀을 때 펼친다. 선택 조건은 필터 아이콘 상태와 결과 개수 옆의 짧은 문구로 확인한다. 메뉴를 줄인 대가로 조건을 찾기 어려워지지 않는지 사용자 비교가 필요하다.
- 원문은 최대 700px의 한 열, 본문 18px·1.95 행간이다. 모바일은 17px이다. 작은 뒤로·정보·인용·북마크 도구만 위에 남긴다. 출처 상세는 정보 버튼으로 열고, 발췌 입력은 원문 끝의 패널로 필요할 때 연다. 닫기/Escape는 열기 전 읽던 위치와 버튼 초점으로 돌아간다.
- 문장을 선택해도 패널을 자동으로 열거나 읽는 초점을 옮기지 않는다. 인용 버튼의 상태가 바뀌고, 사용자가 직접 발췌 도구를 열어 주제·내 생각을 선택 입력한다. 출처가 접혀도 일부 본문·본문 미확보·이전 버전 단서는 남는다.
- ‘시안 비교’ 도구도 기본 접힘이다. 펼쳤을 때만 A/B/C와 빈 상태·로딩·오류를 바꾼다. 운영 메뉴와 디자인 검토용 도구를 구분한다.

## 같은 틀 안의 세 가지 차이

| 안 | 현재 구현 | 적합한 장면과 비용 |
| --- | --- | --- |
| A · 넓은 목록 | 최대 880px 목록, 넓은 화면 2열·모바일 1열. 색 타일 없이 제목·짧은 문맥 중심. 핑크는 작은 선택·행동에만 사용 | 여러 기록을 한눈에 골라보기. 두 열을 오가며 긴 문맥을 읽는 부담은 비교해야 한다. |
| **B · 문장 피드 — 우선 추천** | 최대 660px의 한 열. 본문 문맥을 길게 보여주고 항목 간 여백을 둔다. 바이올렛은 선택·발췌 연결에만 사용 | 이번 본문 집중 요구에 가장 직접적이다. 제목→문맥→원문→내 생각의 흐름을 한 열로 읽는다. 같은 높이에 보이는 자료 수는 줄어든다. |
| C · 빠른 탐색 | 최대 760px의 한 열. 제목 17px, 문맥 15px, 항목 간격을 더 좁게 사용. 작은 블루 선택 반응 | 많은 자료를 빠르게 훑기. 간단 미리보기는 요청했을 때 목록 위에 나타나며 닫을 수 있다. 전체 원문 병렬 읽기나 상시 옆 패널은 아니다. |

세 안의 원문 읽기 틀은 같다. 추천 B는 이번 목적에 대한 제안이며 사용자 확정이나 기본 코드값을 의미하지 않는다. 현재 시안은 첫 진입 때 A로 열리고 ‘시안 비교’에서 B/C로 바꿀 수 있다. 사용자가 원문 읽기보다 목록의 많은 자료를 동시에 고르는 일을 우선하면 A/C를 다시 비교한다.

## 짧은 비교 순서

1. ‘시안 비교’를 펼쳐 B를 고르고 다시 접는다. 기억나는 문장을 검색하고 필터 아이콘으로 출처·주제를 좁힌다.
2. 제목을 눌러 원문을 읽는다. 필요한 때 정보 버튼으로 출처/확보 범위를 확인하고 다시 접는다. 목록 복귀 시 검색어·조건·위치가 남는지 본다.
3. 문장을 선택한 뒤 인용 버튼을 누른다. 주제와 내 생각은 선택 입력으로 연결하고, 패널을 닫아 읽던 위치로 돌아온다. 목록에서 원문 아래에 붙은 내 발췌를 확인한다.

아이콘이 ‘직관적’이라는 평가는 코드의 접근 가능한 이름이나 검사 통과만으로 확정할 수 없다. 실제 사용자에게 책·인용부호·필터를 설명 없이 찾아보게 하는 작은 비교가 필요하다. 특히 터치 화면의 hover 부재와 아이콘 구별은 실제 기기에서 확인한다.

위 이미지의 배치 관찰은 사용자의 읽기 속도·피로가 개선됐다는 실증이 아니다. 세 안의 목록 밀도와 읽는 느낌을 선택하기 위한 근거이며, 자동 검사의 실행 범위는 별도 [검증 문서](minimal-verification.md)를 따른다.

## 보존하는 의미와 한계

담기와 발췌는 시안 메모리에만 남고 새로고침하면 초기화된다. 인증·계정별 저장·동기화·백업·Core를 연결한 운영 기능이 아니다. 가짜 인기·좋아요·외부 댓글을 추가하지 않으며, 가져오기 버튼은 기존 앱의 범위임을 안내한다. 검색어는 URL·지속 저장·외부 요청으로 보내지 않는다.

원문/내 생각, 작성 시각/가져온 시각, 미상 날짜, 일부 본문·본문 미확보와 이전 버전의 뜻은 유지한다. DOM 선택 문자열과 예시 구절은 운영 `SourceVersion.contentText`의 raw UTF-16 위치를 보장하지 않는다. 운영 반영 때 정확한 버전·CRLF·이모지·중복 문장·참조·검색 복귀를 기존 계약으로 연결해야 한다. 메뉴에서 줄인 계정·작업공간·동기화·사본 복원은 운영 통합 때 접근 경로를 마련해야 한다.

이번 검토는 Linux Chromium과 익명 샘플을 대상으로 한다. 실제 Mac·iPad·iPhone, iPad Chrome, Apple 글꼴·한글 IME·VoiceOver·터치 선택 손잡이와 사용자의 읽기 피로는 별도 확인이 필요하다. [검증 범위와 실행 결과](minimal-verification.md)는 직접 시각 검토와 자동 검사, 실제 기기 체험을 구분한다. 이전 [02 콘셉트](social-concepts.md)와 [02 검증](social-verification.md)의 증거는 보존한다.
