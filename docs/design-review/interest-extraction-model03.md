# 관심 주제·질문 추출의 분리 검증 — MODEL-03

2026-10-19 KST. **새 60문서의 전체 실행에서 주제·질문 제안이 모두 0개여서 MODEL-03을 채택하지 않는다.** 질문 원문 검출은 18/18, 문장형 질문은 9/9였지만 NLI 검증을 통과한 질문이 없었다. 제품의 자동 분석은 계속 비활성이며, 기존 수동 관심 입력·명시 보관은 유지한다. 이전 [MODEL-02 판정](interest-validation.md)은 별도 결과로 보존한다.

## 실행·보존 검수

실제 Linux/Chromium, Transformers.js 4.3.1, 고정 revision, q8/CPU/WASM 1스레드로 한 번 실행했다. MiniLM과 NLI는 별도 context에서 순차 준비·해제했다.

- 전체 모델 준비·후보 처리·추론 **168.846초**. 준비는 MiniLM 17.76초와 NLI 40.17초, 실제 모델 추론은 각각 6.14초와 101.50초였다.
- 임베딩 고유 입력 **144개**, NLI 고유 입력 **479쌍**을 실제 추론했다. NLI 요청 506쌍 중 동일 입력 27쌍은 검증된 캐시를 재사용했다.
- 장문 3개는 전체 tokenizer 길이가 모두 512를 넘었다. 전체 길이 최대는 MiniLM 3,099 / NLI 3,241 tokens이며 실제 window 입력 최대는 각각 182 / 72 tokens였다. 무음 절단·토큰 초과·본문 전송·가변 main revision 요청·예상외 실행 오류는 0이었다.
- 관측 브라우저 프로세스 RSS 합계 최대는 약 **652MiB**다. 250ms 표본이며 공유 페이지 중복과 표본 사이 최대치 누락 가능성이 있다. 전체 RAM의 정확한 peak나 Apple 성능으로 표현하지 않는다.
- 합성 어댑터 구조·보존 검사 **10/10**. 줄바꿈 뒤 부정 scope, 여러 줄 ASCII 인용, 잘못된 Unicode 입력의 공개 반례를 수정하고 재확인했다. 이 검사는 실제 모델 의미 품질과 별도다.
- 후보·실행기·평가기·사전등록·입력·정답의 **6개 봉인 SHA**, 기존 제품 **9개 파일 SHA**, 원본 저장소의 HEAD와 clean 상태가 실행 후에도 일치했다. 앱 분석 정책·원문·저장·백업·PWA 형식은 유지했다.

## 실행 지시

목표는 선택한 한국어 자료의 주제와 서로 다른 본문의 비슷한 질문을 정확한 근거와 함께 제안할 수 있는지 판정하는 것이다. 범위는 공개 개발 예제 → 후보 생성과 의미 검증의 분리 → 코드·임계값·자료 동결 → 새 독립 자료의 실제 CPU 추론 → 독립 채점·채택 판정이다.

원본 저장소, 기존 앱·저장 형식·PWA 셸·분석 정책은 변경하지 않는다. 실험에는 새 합성 자료만 사용하고 본문을 외부 서비스에 보내지 않는다. 실제 Google 계정·운영 DB·유료 API·배포를 사용하지 않는다. 구현 담당자는 새 평가 본문과 정답을 동결 전에 열람하지 않는다.

## 설계와 비교 범위

새 후보는 생성형 모델을 추가하지 않는다. 문서 전체의 문장·질문 구간을 추출한 다음 기존 MiniLM 임베딩으로 주제·질문 쌍 후보를 찾고, 별도 mDeBERTa NLI로 근거와 가설을 검증한다. 후보가 검색되지 않은 실패와 검색 후 검증에서 탈락한 실패를 구분한다.

- 주제는 기존 10개 분류의 **보관 자료 주제**다. 목록 밖의 새 주제를 자유롭게 발견하는 기능은 검증하지 않는다. 작성자 미상을 사용자로 추정하지 않으며 현재 선호·신념을 확정하지 않는다.
- 질문은 원문 구간을 보존한 쌍이다. 같은 주제의 다른 질문을 합치지 않아야 한다. 양방향 NLI 점수는 의문문의 논리적 동치나 답의 진실을 입증하지 않는다.
- 정확한 UTF-8 SHA와 UTF-16 인용 구간, 저자 관계·인용 출처, 서로 다른 본문 지지를 보존한다. 같은 본문의 복제로 반복 지지를 늘리지 않는다.
- 원문 전체 순회, 임베딩 검사, 실제 NLI 검사 범위를 따로 기록한다. 긴 문장의 문맥을 보존할 수 없으면 기권하고, 처리 예산 초과는 미완료로 보고한다.

큰 모델로 모든 문장·모든 주제를 검사하는 경로는 CPU 비용 때문에 선택하지 않았다. 의미 유사도나 부정 정규식만 강화하는 경로도 기존 실패를 해결한다는 근거가 없어 채택하지 않았다. 제품에 이미 있는 수동 입력은 실험과 독립적으로 계속 사용할 수 있다.

## 공개 개발 비교

새 평가 본문을 공개하기 전에 두 차례만 비교했다. 첫 16쌍은 주제·명령·질문 존재·질문 재서술의 기본 가설을 확인했고, 다음 32쌍은 짧은 한국어·영어 주제 문구와 구체 활동 명제를 비교했다. 각 원입력·원출력·실행 runner 해시를 별도로 보존한다.

첫 비교에서 일반적인 주제 가설은 양성 예제에서도 함의 softmax 점수가 약 0.12~0.18로 낮았다. 질문 존재 가설도 직접 질문 0.20, 간접 질문 0.33 수준이었다. 짧은 주제 문구도 안정적인 해결이 아니었고, 특정 읽기 활동을 명제로 바꾸면 일부 점수는 올랐으나 전체 주제의 의미를 유지하지 못했다. 낮은 점수에 맞춰 임계값만 내려 중립 판정을 긍정 근거로 바꾸는 경로는 선택하지 않았다.

여기의 3라벨 softmax 점수는 보정된 정답 확률이나 사용자 관심의 신뢰도가 아니다. 공개 예제에서 문구와 운영 임계값을 선택한 사실과, 미사용 자료의 독립 품질 판정을 구분한다. MODEL-02의 짧은 12쌍 성공이 새 주제·질문 가설에 그대로 일반화된다고 가정하지 않는다.

공개 16/32쌍 실행 당시 runner는 이후 보강 전에 소스 사본을 따로 남기지 않았다. 당시 소스 해시·설정·원출력·토큰·네트워크 기록은 있으나 그 소스 바이트의 독립 재현은 미보존 한계다. 최종 60문서 실행은 후보와 runner의 실제 소스 바이트를 모두 동결해 보존한다.

최종 동결 점수는 주제·질문 존재·질문 쌍 양방향 각각 0.55다. 명령 가능성은 짧은 별도 가설의 0.45 이상에서 기권한다. 이 기권 기준은 명령임을 입증했다는 판정이 아니며 진짜 요청형 질문도 제외할 수 있다. 주제는 원래 가설을 유지한다. 전체 실행은 모델 준비·같은 동결 실행의 재시도까지 합쳐 15분이며, 초과 시 완료 결과 대신 중단·미처리 기록을 남긴다.

## 판정 기준과 재현성

최소 기준은 주제·질문별 근거 정밀도 95%, 주제 문서 macro recall 70%, 반복 질문 recall 70%, 금지 근거 0, 정확 source/hash/UTF-16 구간 100%, 무음 절단 0이다. 구문상 질문 검출과 반복 질문 쌍 회수, 정밀도와 기권·누락을 각각 기록한다. 자료 분모와 세부 span rubric은 추론 전에 사전등록한다.

공개 개발 자료에서 선택한 문구·임계값과 실제 원출력을 보존한다. 새 평가 공개 전에 후보·runner·모델·runtime·예산을 동결하고, 정답을 제외한 입력만 runner에 전달한다. 결과를 본 뒤 같은 자료에 맞춰 규칙을 고쳐 합격시키지 않는다.

합성 자료 통과만으로 앱을 활성화하지 않는다. 다운로드 크기·전체 CPU 시간·관측 메모리, 실제 Mac/iPad/iPhone에서의 실행·취소·재진입과 사용자 교정 조건을 별도로 확인해야 한다.

## 채점 형식 보정과 증거

봉인한 평가기는 전체 문서 토큰 수를 문서별 map/list로 읽도록 작성됐고, 실행기는 같은 숫자를 `{rows:[...],elapsedMs}` 안에 기록했다. 원본 채점에서는 이 wrapper 차이로 장문 길이가 미확인으로 읽혔다. 원본 runtime·평가기·채점은 보존하고, 모든 행·숫자·메타데이터가 동일함을 검사한 별도 정규화 사본을 같은 평가기로 채점했다. 달라진 gate는 장문 3개가 512 tokens를 넘었다는 확인뿐이며 모든 품질 지표와 기각 결론은 동일하다. 임계값·gold·소스·원출력은 변경하지 않았다.

사전등록, 입력/정답 봉인, 동결 소스, 원출력, 원본·정규화 채점, 단계별 누락, 보존·독립 검토는 [증거와 재현 방법](evidence/interest-extraction-model03/README.md)에 있다. 기존 제품 구현 `5137e52`의 전체 CI는 통과했다. 이번 후속 변경은 실험 소스·증거·문서이며 앱 실행 코드의 변경이 아니다.

## 다음 실행 단위

현재 후보는 채택하지 않고 자동 분석을 비활성으로 유지한다. **외부 공급 재통합 → 직접 입력·명시 보관한 관심으로 새 글 제안 → 정확 원문·복귀 → 명시 보관 → 피드백·취소**를 다음 P1으로 진행한다. 동일 출처의 최신순과 유용성을 비교하고 실제 기기·Google 인증·라이브 버전은 별도 확인한다.

추출 연구는 P2다. 주제·질문 존재 가설을 검증할 구체적인 대안과 비용 상한·새 독립 평가가 있을 때만 재개한다. 이 60문서 결과를 보고 같은 자료에 맞춘 임계값 조정을 새 검증으로 부르지 않는다. 최신 우선순위는 [로드맵](../life-tools-design/roadmap.md)을 따른다.
