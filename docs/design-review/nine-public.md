# 선택 영역의 공개 9칸 취향 페이지

2026-10-18 KST. 기반 PR [#101](https://github.com/wonchance-art/life-haedo/pull/101) `031c31d`의 CI #183은 완료했으며 착수 시점 미병합·미배포다. 이번 후보의 구현·검수·병합·배포 증거와 구분한다. 목표는 비공개 9칸에서 선택한 영역 하나를 검토해 게시하고, 방문자가 항목과 출처를 직접 둘러보는 경험이다.

## 목표와 이번 범위

소유자는 기존 9칸에서 한 영역을 고르고 공개 제목·소개를 확인한다. 공개 소개는 빈 입력에서 직접 적는다. 공개할 항목의 제목·창작자·유형·출처 전체를 미리보기에서 읽고 동의한 뒤 게시한다. 방문자는 3×3에서 항목을 열어 전체 제목과 정확한 출처를 읽고 외부 출처로 이동하거나 원래 칸으로 돌아간다. 소유자는 공개 상태를 다시 확인해 명시 갱신·철회한다.

처음 공개하는 영역의 소개는 빈 값이다. 이미 공개한 영역을 다시 열 때는 소유 상태→현재 공개 snapshot→소유 상태의 revision/주소를 대조한 읽기 전용 경로로, 이전에 직접 공개한 제목·소개만 복구한다. 원래 개인 소개나 영역 메모를 가져오지 않는다. 처음 여는 동안 추가 입력/한글 조합/계정 전환이 있으면 늦은 복구로 입력을 덮지 않으며, 이후 상태 새로고침은 현재 입력을 바꾸지 않는다. 게시·갱신은 계속 새 미리보기와 명시 동의가 필요하다.

기존 `life-share-v1`의 항목 하나와 첨부 1~9개로 표현하며 기존 Share/ShareRemote·CAS·영수증을 재사용한다. 새 SQL·공개 사진 저장·추천/수집·홈/검색/전역 탐색 재설계는 추가하지 않는다. 원래 9칸 PNG/JSON/HTML·선택 파일 복구·비공개 글 초안 생성은 유지한다.

## 보존과 공개 경계

- 공개 사본에는 검토한 제목·직접 쓴 소개와 선택 영역의 첨부 순서·제목·창작자·유형·출처만 둔다. 개인 ID·선택 이유·구조화 인용/정확 원문·구성 소개·영역 메모·다른 영역은 후보 화면과 공개 payload에 자동 포함하지 않는다.
- ID 제외는 익명 공개 snapshot의 경계다. 인증된 게시 관리 RPC는 기존 슬롯 `p_workspace_id`에 선택 영역 UUID를 사용한다. 출처 URL의 사용자가 검토한 문자열에서 우연히 일치하는 식별자를 추정해 지우거나 재작성하지 않는다.
- 원래 자료·9칸·개인 메모는 수정하지 않는다. 공개는 별도 사본이며 원영역 변경을 자동 전파하지 않는다. 변경 후에는 새 미리보기와 동의로 갱신한다.
- 1~9개 실제 항목만 게시하며 빈 영역은 게시하지 않는다. 방문자 3×3의 빈 칸은 비포커스 빈 상태로 남기고 순위·추천·가짜 작품으로 채우지 않는다.
- 카드에서 긴 문자열을 시각적으로 줄일 수 있어도 항목 상세와 소유자 미리보기에는 정확한 전체 문자열을 제공한다. 이미지·임베드·원문 본문을 자동 조회하지 않는다. 출처 링크에는 안전 URL·창 분리·referrer 차단을 적용한다.
- 표지는 기본 꺼짐이며 방문자가 명시적으로 켠 경우에만 정확한 Open Library 책 출처에서 파생한 기존 `CollectionMedia.describe/mount` 경로를 재사용한다. 앨범·영화·YouTube·원문 이미지를 새로 조회하지 않는다. 표지를 불러오지 못해도 제목·창작자·출처를 읽을 수 있고 화면 종료·철회 때 표지 요청/이미지를 해제한다.
- 같은 실패의 재시도는 기존 영수증으로 확인하며 새 게시 사본을 만들지 않는다. 공개 CAS 충돌과 원영역 변경은 옛 검토·동의를 폐기하고 다시 확인한다. 계정·작업공간 변경 후 늦은 결과가 옛 개인 화면/식별자/내용을 되살리지 않아야 한다.
- 철회·없음·오류·비활성 화면에서는 이전 공개 내용을 제거하고 새 상태를 보여 준다. 이미 받은 파일·화면 복사를 회수한다고 보장하지 않는다.

## 화면과 반대 검토

본문 중심의 흰 표면·현재 공통 색/글꼴·44px 조작을 사용한다. 복잡한 작품 표지 갤러리나 별도 편집기를 도입하지 않고 기존 3×3의 명시 순서를 유지한다. 항목 상세를 닫으면 정확한 칸의 키보드 초점과 읽던 위치를 복원한다. 빈 칸은 조작으로 노출하지 않는다.

공식 Muuri 0.9.5(MIT)를 비교했지만 드래그·필터·임의 레이아웃·worker 엔진은 고정 순서 9칸 읽기에 필요하지 않았다. 기존 CSS Grid·NineBoard 허용 필드 투영·CollectionMedia·Share/ShareRemote와 작은 표시 어댑터를 재사용한다. 2026-10-18 공식 릴리스/유지 이력·라이선스와 보안 권고 재조회 한계, 직접 도입하지 않은 이유는 [오픈소스 검토](../life-tools-design/open-source-review.md#선택-영역의-공개-9칸--2026-10-18-kst)에 기록했다.

공개한 영역에서 마지막 항목을 뺀 뒤에도 공개 상태 조회와 철회는 열 수 있다. 빈 영역으로 새로 게시/갱신하는 투영은 거절하지만 그 거절을 기존 공개 사본의 철회 차단으로 사용하지 않는다. 전체 영역 보기에서는 먼저 한 영역을 선택한다.

원래 영역 자체를 삭제한 뒤에는 기존 **설정 → 공개 페이지 관리**에서 그 공개 제목을 찾아 상태를 확인하고 두 단계 확인으로 철회한다. 기존 계정별 공개 목록·CAS·영수증을 그대로 재사용하며 삭제를 새 네트워크 쓰기나 자동 철회 권한으로 해석하지 않는다.

## 검수 상태

공개 재개까지 포함해 로컬 구현·통합 검수를 마쳤다. 로컬 Node22.23.3 전체 단위 716/716(실패/skip 0), 정적 21 HTML·120 JS·512 로컬 참조·PWA 셸을 확인했다(`.local/nine-public/unit-final-resume.log`, `check-final-resume.log`). 원격 어댑터 10개·소유자 대화상자 12개 단위에 공개 재개, 읽기 실패, 늦은 입력/IME/계정 변화와 현재 입력 보호를 포함한다.

영구 종합 검수 `tests/nine-public-browser.cjs`는 최종 9개 흐름을 통과했다(`.local/nine-public/report.json`: pass=true, `.local/nine-public/browser-resume-final.log`: exit0). 실제 동봉 SDK·계정별 IndexedDB·기존 PostgreSQL 공개 페이지 RPC와 익명 화면을 연결했다. Auth·출처/표지 HTTP는 합성이며 실제 운영 계정·원본은 사용하지 않았다.

- 개인 이유/원문/다른 영역 sentinel과 정확 v2 인용 근거를 포함한 자료에서, 9개 항목의 전체 제목·창작자·출처를 미리보기 상세로 검토했다. 공개 snapshot·실제 RPC가 커밋한 SQL 사본·익명 DOM에 미선택 자료와 개인 식별자/근거가 들어가지 않음을 대조했다. 인증 관리 RPC의 영역 UUID 슬롯과 익명 snapshot을 구분했다.
- 게시 응답을 실제 SQL 커밋 뒤 유실시켜 같은 operation/payload의 영수증 재시도로 확인했다. 원래 작업공간의 공개 페이지·원문·사진 글·9칸·구성·컬렉션·초안은 그대로였고 블로그 글 게시/사진 업로드 요청은 0이었다.
- 익명 9칸의 순서·전체 상세·긴 출처, 키보드로 열기와 정확 칸 복귀, 안전한 새 창 출처 이동을 확인했다. 원영역 변경 후 옛 동의로는 쓰기 0, 새 미리보기/동의 후 같은 공개 주소의 명시 갱신을 확인했다. 실제 두 탭의 공개 CAS 경합은 기존 공개본을 보존하고 새 검토·동의 전 두 번째 클릭으로 덮어쓰지 못했다.
- 기본 외부 표지 요청은 0이었다. 명시 Open Library 표지의 합성 실패→텍스트/출처 유지→끄기/다시 켜기→실제 이미지 디코딩→끄기를 확인했다. 한 항목의 9칸은 비포커스 빈 칸 8개를 유지했다.
- 마지막 항목을 실제 편집 UI에서 뺀 뒤 빈 영역의 상태 조회/철회가 작동했다. 별도로 게시한 영역을 개인 저장소에서 삭제한 뒤에도 실제 설정의 공개 페이지 관리에서 제목으로 찾아 두 단계 확인으로 철회했고 익명 화면은 비었다. 다른 공개 사본은 유지했다.
- 원래 JSON/HTML/1800×2100 PNG를 실제 내려받아 기존 모델 결과와 대조하고, 기존 비공개 글쓰기 검토/취소와 원본 불변을 확인했다. JSON/HTML의 기존 개인 내용 보관과 이번 공개 snapshot의 제외 범위를 섞지 않았다. 계정 전환 후 늦게 도착한 이전 계정의 실제 RPC 읽기는 새 화면/저장소를 바꾸지 않았다.
- 공개 제목·여러 줄 소개를 개인 값과 다르게 적어 게시→닫기/동일 영역 재개→정확한 공개 값 복구를 확인했다. 재개와 상태 새로고침의 쓰기는 0이고 수정 중 입력은 보존됐다. 새 미리보기/동의로 갱신한 뒤 재재개·익명 화면의 값도 일치했다.

1440/820/390px에서 소유자 검토·미리보기 그리드·익명 그리드·전체 상세의 12개 화면을 측정했다. 3열·행 안 카드 높이·가로 넘침·44px 조작·입력 16px·이름·대비 단언을 통과했다. 최신 모바일 소유자/익명 상세와 데스크톱 미리보기 PNG를 직접 읽어 긴 제목/출처의 전체 상세와 9칸 정렬을 검토했다. 예기치 않은 콘솔·페이지 오류·외부 요청은 0이다. 의도한 응답 유실 콘솔 1개, 명시 출처 이동 1개와 표지 실패/성공 2개는 별도 기록했으며 모두 합성 HTTP로 응답해 실제 제공자 전송과 구분했다. 브라우저/컨텍스트는 종료했다. Linux Chromium151.0.7922.173의 화면 모사이며 CI 고정 Chromium153·실제 Apple 기기 검수와 다르다.

독립 reader lifecycle 7개 흐름을 통과했다(`.local/nine-public-reader/report.json`, `.local/nine-public-reader-final.log`). 누락/중복/잘못된 주소·엄격 형식 오류·철회/숨김/오프라인/늦은 응답에서 옛 내용을 제거하고, 내용이 같은 재조회는 DOM·선택 구절·스크롤을 유지했다. 명시적 Open Library 표지·지연 로드·끄기/실패 후 정리, YouTube/불일치 책 주소의 미조회, 중첩 대화상자의 정확한 복귀를 확인했다. 익명 local/session 저장소·IndexedDB·Cache 접근 기록 0과 Auth/SDK/개인 Storage 미로딩, 공개 RPC의 credentials omit·cache no-store도 별도로 확인했다. 이 검수의 Auth/공개 RPC/표지 응답은 합성이며 실제 owner·SQL 종합 검수와 구분한다.

독립 실제 PostgreSQL 검수는 기존 공개 페이지 RPC를 사용한 4개 흐름을 통과했다(`.local/nine-public-backend/report.json`, `sql-final.log`). 허용된 v2 메타데이터만 게시, 기존 공간/모음/다른 영역 공개 사본 불변, 로컬 revision·같은 revision의 선택 변경·Auth 검증 대기 중 변경의 SQL 쓰기 차단, CAS 동의 소모·영수증 재시도·소유권·독립 철회를 확인했다. 새 SQL/운영 DB/호스팅 제공자를 검증한 것으로 표현하지 않는다.

소유자 미리보기의 긴 상세에서 복귀할 때, 창 스크롤만 복원해 실제 대화상자는 3060→상세3975→복귀3520으로 남고 선택 칸이 보이지 않는 문제를 재현했다. 표시용 부모 스크롤 좌표를 함께 보관/복원해 3060으로 돌아오고 칸이 보이는 것을 확인했다. 원본이나 공개 snapshot에는 스크롤 상태를 추가하지 않았다. 카드가 같은 행에서 다른 높이로 보이던 시각 문제도 실제 화면에서 확인해 행 높이를 맞추고 종합 시각 단언을 추가했다. 빈 영역의 새 게시 거절과 기존 공개 상태/철회 접근도 분리했다.

최종 후보 커밋·원격 CI는 해당 PR의 HEAD/검사 기록을 따른다. 기반 PR101의 성공을 이번 새 기능 결과로 사용하지 않는다. 합성 Auth·격리 SQL·Chromium 화면 모사는 Google 제공자 인증·운영 서버·Apple 기기/IME/Files·사용자 개인 게시나 배포의 성공이 아니다. 이번 검수로 병합·배포 완료를 표시하지 않는다.

## 직접 체험

`npm run dev`로 실행한 로그인 환경의 `http://127.0.0.1:4173/index.html?section=records&view=page`에서 **9칸 구성 → 한 영역 선택 → 선택 영역 공개 검토**를 연다. 공개 제목·직접 쓴 소개와 각 칸의 전체 상세/출처를 확인한 뒤 미리보기 동의와 게시를 선택한다. 생성한 `taste.html?nine=...` 주소는 별도 익명 창에서 9칸·항목 상세·출처로 읽는다. 표지는 기본 꺼져 있으며 원할 때 **책 표지 보기**로 켠다.

같은 영역을 다시 열면 이전에 직접 게시한 제목·소개를 이어 쓸 수 있다. 상태 조회만으로 현재 입력이나 공개본이 바뀌지 않으며, 수정 반영은 새 미리보기와 동의로 갱신한다. 철회는 별도 동의로 확정한다. 원래 영역을 삭제했다면 **설정 → 공개 페이지 관리**에서 그 제목을 찾아 두 단계로 철회한다. 이 절은 체험 절차이며 실제 Google 로그인·운영 게시를 수행했다는 증거가 아니다.
