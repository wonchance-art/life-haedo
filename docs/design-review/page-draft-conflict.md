# 내 페이지 초안 충돌 → 새 사본 복구

2026-10-14 KST. #84의 수정 HEAD `3fe211c` 위 후속. 내 초안의 CAS 충돌을 앱 안에서 비교·보관·이어쓰기까지 연결한다. 병합·운영 배포는 Local 담당이다.

## 확인된 공백과 이번 범위

다른 탭이 초안 보관함을 먼저 바꾸면 본문 입력은 남지만 저장·닫기·탐색은 계속 같은 충돌에 막혔다. 파일을 받아 새로고침한 뒤 선택 복원하는 우회만 있었다. 이번에는 기존 파일 복구의 미리보기·평문 렌더·원자적 추가를 재사용한다.

| 묶음 | 동작·보존 조건 |
| --- | --- |
| 상태·진입 | `초안 충돌 · 입력 유지`와 `최신 초안과 비교`. 저장하지 못한 초안을 ‘저장됨’으로 표시하지 않음. 읽기 실패 뒤에도 비교 행동·현재 입력 유지 |
| 비교 | 현재 보관함의 본문·첨부·출처·범위와 내 변경을 구분. 취소는 본문 DOM·커서와 미저장 입력을 유지. 반영하지 않은 첨부나 한글 조합 중에는 진입 차단 |
| 새 사본 복구 | 마지막 실제 보관에 성공한 초안과 현재 입력을 비교해 새로 만들거나 바꾼 초안만 모두 복사. 최신 초안에 새 ID·비공개·수정 연결 없는 사본으로 추가하고 성공 뒤에만 화면 상태 교체 |
| 다시 이어쓰기 | 최신 보관함과 내 사본이 함께 남음. 쓰던 초안의 새 사본과 UTF-16 커서 위치로 복귀. 관련 workbench 충돌 경고만 정리하며 다른 오류는 유지 |
| 실패 대안 | 저장/재경합·200개·합산 용량 한도에 실패해도 양쪽 내용 유지. 최신 상태에 다시 추가하거나 현재 화면의 초안을 기존 v1 파일로 받을 수 있음 |

원문·컬렉션·저장한 글·공개 사본을 변경하지 않는다. 로컬 초안은 구성 동기화·공개 payload에 포함되지 않는다. v1 파일·revision/posts·계정/작업공간 소유권·기존 CAS/트랜잭션을 그대로 사용하며 새 SQL·의존성은 없다.

## 보존과 반대 검토

- 전체 옛 보관함을 다시 추가하면 다른 탭에서 삭제한 미변경 초안도 되살아난다. **로컬의 마지막 성공 보관본과 비교한 변경만** 복구한다. 다른 탭의 삭제·새 초안·수정을 그대로 유지한다. 본문·첨부 네 필드/순서·범위·수정 연결·원래 날짜를 정확 비교하며 객체 필드 순서는 의미로 취급하지 않는다.
- 저장 응답을 기다리는 중 사용자가 더 입력할 수 있다. 비교 기준은 `.then` 시점의 현재 화면이 아니라 실제 저장에 성공한 payload다. 그 사이 추가한 내용은 다음 충돌에서 새 변경으로 남는다. 성공한 복구/최종 글 저장/삭제/파일 복원/명시 재읽기마다 기준을 갱신한다.
- 일부만 골라 복구하면 선택하지 않은 미저장 입력이 최신 화면 전환 때 빠질 수 있다. 충돌 복구는 읽기 전용 비교와 **내 변경 모두 보관**으로 단순화한다. 파일에서의 임의 선택 복구는 #84에 별도로 유지한다. 같은 본문·첨부가 이미 있어도 내 변경 사본을 조용히 버리지 않는다.
- 새 사본은 비공개이며 수정 대상 연결을 끊는다. 비교에서 이를 설명하고 이후 글 저장·공개 후보 선택은 사용자가 따로 한다. 원래 날짜·첨부/출처는 보존하고 기존 글을 자동 교체하지 않는다.
- 용량 한도를 넘으면 일부만 저장하거나 옛 초안을 자동 삭제하지 않는다. 현재 화면의 **전체 초안**을 v1 파일로 받을 수 있다. 이 파일은 다른 탭의 최신 보관함 전체를 합친 파일이 아니며, 실제 파일 보관 완료나 클라우드 이어쓰기를 의미하지 않는다.
- `PageComposer`의 마지막 성공 상태, `PagePosts.changedDrafts`, #84 미리보기/선택 복원 경로, idb 원자 저장을 확장했다. [기존 오픈소스 재사용 판단](../life-tools-design/open-source-review.md)을 따르며 새 기반 모듈·파서·편집기·저장 라이브러리를 도입하지 않는다.

미반영 첨부 폼의 강제 종료 후 복구와 실제 Apple 기기의 IME/Files는 이번 범위 밖이다. [첨부 입력 보호](attachment-edit-preservation.md)의 제약은 유지한다.

## 체험

`npm run dev` 후 내 페이지를 같은 계정·작업공간의 두 탭에서 연다. 합성 Auth·실제 IndexedDB의 자동 체험은 `node tests/page-draft-conflict-browser.cjs`다.

1. 한 탭에서 초안을 열고 다른 탭에서 같은 보관함을 바꾼다.
2. 첫 탭에서 계속 입력하면 충돌 상태가 나온다. `최신 초안과 비교`에서 양쪽 본문·첨부·원래 출처를 확인한다.
3. `내 변경을 새 초안으로 보관`하면 다른 탭의 내용과 내 비공개 사본이 함께 남고 쓰던 사본에 커서가 돌아온다. 글 `저장`은 별도다.
4. 비교를 닫아도 입력은 남는다. 저장 실패 시 같은 화면에서 재시도하거나 `내 초안 파일 받기`로 파일을 보관한다.
5. 내 입력이 마지막 보관본과 완전히 같으면 사본을 만들지 않고 최신 보관함을 연다.
