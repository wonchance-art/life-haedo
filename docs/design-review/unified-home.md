# 기록·도구·관리 통합 홈

2026-10-04 · 기존 해도 화면을 하나의 탐색 체계로 연결했다. LPE 자료·코드·외부 DB는 이번 범위에 포함하지 않는다. 새 런타임 라이브러리나 저장 마이그레이션도 추가하지 않는다.

## 화면과 동작

| 영역 | 첫 화면과 경로 |
| --- | --- |
| 기록 | 로그인 후 바로 자료·발췌 피드. 상단 아이콘으로 원천 검색·연표·가져오기 전환 |
| 도구 | 기존 목표·습관 편집기로 이어지는 간결한 두 행 |
| 관리 | 계정, 자료 작업공간·동기화·자료 백업, 별도 연표·목표·습관 백업 |

`index.html`은 로그인 전 간단한 진입 안내를 표시하고, 서버 계정 검증 후 계정별 자료를 연다. 별도 소개 대시보드를 거치지 않는다. 발췌가 아직 없는 공간에도 보관한 원문의 제목·본문 일부를 표시해 실제 자료를 바로 열 수 있게 했다. 발췌가 있으면 기존 발췌 피드를 유지한다.

`life.html` 기존 주소도 같은 UI를 제공한다. `workspace.html`은 기록의 연표 목록이고, `workspace.html?section=manage`는 기존 플랫폼 백업/복원으로 들어간다. 주소는 `section=tools|manage` 및 허용한 `view`만 로그인 반환 경로에 보존한다. 임의 외부 주소·인증 쿼리는 반환 경로로 사용하지 않는다.

공통 메뉴는 큰 화면의 왼쪽 72px, 700px 이하의 하단 세 아이콘이다. 20px SVG·44px 조작 영역, 한글 산세리프·흰 표면·얇은 구분선을 재사용한다. 연표 차트의 좌표·색·저장 알고리즘은 유지하고 바깥 프레임만 연결했다. 계정 메뉴는 홈의 관리에서, 기존 편집 화면에서는 공통 계정 아이콘에서 연다.

같은 홈에서 섹션을 오갈 때 가져오기 초안·검토 후보·원문 발췌 입력·검색 복귀 맥락을 보존한다. 다른 편집기로 이동하기 전 초안을 보관한다. 저장에 실패하면 현재 입력을 유지하고 이동을 막는다. 새로고침 뒤 읽던 모든 위치를 복원하는 영속 읽기 이력 기능을 추가한 것은 아니다.

## 재사용과 선택 근거

[기존 비교 기록](references.md)의 Lucide 1.51.0 로컬 SVG(ISC 및 Feather MIT 고지), 사용자 승인 A 인용, 네이티브 `details`·링크·History API를 재사용했다. 새로 필요한 연표·목표·습관 도형은 같은 24×24 좌표·2단위 둥근 선으로 그렸다. 별도 아이콘 폰트나 라우터를 추가할 만큼 복잡한 탐색이 아니므로 기존 일반 JavaScript와 [History API](https://developer.mozilla.org/en-US/docs/Web/API/History_API)를 사용한다.

[Impeccable 도입 기록](impeccable.md)의 프로젝트 지침·craft floor를 적용했다. 이번 작업에서 공식 패키지 버전·라이선스를 변경하거나 외부 엔진을 실행하지 않았다. 기존 daisyUI/연표 CSS 위에는 공통 셸을 제한적으로 적용하며 자료 홈에는 불필요한 연표 엔진·지도를 로드하지 않는다.

디자인 책임자는 root다. 공통 HTML/탐색은 unified_shell, 인증·경계 검토는 management_plan, 기능/시각 검증은 sequence_review가 분담했다. 화면마다 별도 메뉴·팔레트·아이콘 체계를 만들지 않았다.

## 기능 검사와 시각 검토

- 정적 검사: HTML 16개·JavaScript 34개·로컬 리소스 참조 199개 및 PWA 셸 통과.
- Node 회귀: **188/188**. 인증 반환 허용 목록과 오프라인 `section` 경로를 포함한다.
- 브라우저 기능: 자료 **23**, 모음 **6**, 검색 **7**, 여러 파일 **8**, 동기화 **14**, 플랫폼 통합 **9**, 통합 홈 **12**, 플랫폼 가져오기 **3** — 합계 **82/82**.
- 시각 검토: Linux Chromium 151.0.7922.173, **1440·820·390px**, 27장면·170개 계측 통과. 기능 검사와 별도다. 키보드 메뉴·Escape 도움말·터치 조작 크기·대비·모션 감소를 검사했다.
- 플랫폼 통합은 실제 동봉 SDK·IndexedDB·서비스워커와 모의 HTTP로 v56→v57 업데이트 및 기존 자료·초안 보존을 확인했다. 서버 계정 확인 전 개인 저장소를 열지 않고, A/B 계정 전환·로그아웃 뒤 늦은 응답·오프라인 재확인도 검사했다.
- 관리 이동 또는 로그아웃 전에 초안 저장이 실패하면 입력과 계정을 유지하는 흐름을 확인했다. 독립 경계 검토에서는 활성 작업공간 정보가 없는 복구 화면에서 메뉴를 눌러도 선택기를 보존하고, 선택 뒤 원래 관리 하위 화면으로 이어짐을 확인했다.
- 실제 console/pageerror를 수집했다. 의도한 네트워크·인증 실패는 별도 집계하고 예상하지 않은 오류는 없었다. 운영 Supabase 쓰기·합성 자료 재생성은 하지 않았다.

화면 크기·터치 모사는 실제 Apple 기기 검증이 아니다. 이번에는 실제 Google 로그인, iPad/iPhone/Mac의 한글 IME·Files·VoiceOver·선택 손잡이·앱 전환 체험을 수행하지 않았다. 이전 실제 Mac 인증 확인을 이번 변경의 실기 통과로 재사용하지 않는다.

## 보존 경계와 다음 확인

자료 IndexedDB와 연표/목표/습관의 기존 저장·백업 형식은 분리해 유지한다. 하나의 홈이 모든 자료를 한 백업에 넣는다는 뜻이 아니다. 계정별 자료 접근, 명시적 동기화 연결, 정확한 원문 버전·출처·UTF-16 발췌 위치는 그대로다. 미연결 자료를 로그인만으로 업로드하지 않는다. 공개 산출물은 명시적 허용 목록이며 문서·시안·스크린샷은 Pages에 포함하지 않는다.

체험 순서: 홈 로그인 → 기록의 원문 또는 발췌 열기 → 도구 → 기록 복귀 → 연표 아이콘으로 기존 목록 확인 → 관리에서 자료 백업과 연표 백업의 구분 확인. 아이콘의 실제 이해도와 iPad에서의 구절 선택 부담은 사용자 체험으로 판단한다. 관리 하위 화면의 안내·복원 미리보기 개선은 이 공통 진입 구조 위에서 별도 작은 단위로 진행한다.
