# 관리의 보관 위치와 백업 범위

2026-10-09 KST. 홈·탐색 다음 단위이며 root가 디자인·구현·검토를 맡았다. 책 확장은 보류하고 기존 책/회고를 포함한 백업 계약은 유지한다.

## 문제와 결정

[변경 전 390px](evidence/management-clarity/before-390.png)에서는 공개 관리, 두 종류 백업, 동기화가 같은 무게로 나열되고 보관 상태는 맨 아래에 있었다. `자료·구성 백업`과 `자료 백업·복원`의 차이를 선택 전에 알기 어려웠다.

- 현재 작업공간 이름 아래에 **이 브라우저**와 실제 자료 수를 먼저 둔다. 작업공간 선택 조작은 그대로다.
- 그다음 동기화 상태를 보여준다. 이 요약은 **원문·발췌**의 상태이며 묶음·내 페이지와 글쓰기 초안은 각각 연결한다는 문구를 남긴다. 동기화 상태만 갱신하고 버튼을 교체하지 않아 초점을 유지한다.
- `파일로 보관` 아래에 자료·구성 백업을 먼저, 자료만 JSON/Markdown으로 받는 경로를 그다음에 둔다. 연표·목표·습관은 별도 파일임을 표시한다. 공개 관리는 마지막에 분리한다.
- 백업 화면은 포함 범위를 짧게 보여주고 제외 범위는 펼쳐 확인한다. 구성 백업의 중복 제목과 편집용 저장 표시를 제거했다. 다운로드 전 기존 flush와 오류·충돌 복구는 남긴다.

별도 통합 백업 형식을 만들거나 경로를 합쳐 다른 형식의 파일을 잘못 복원하게 하지 않았다. 이번은 기존 `actionRow`, 공통 아이콘/색상, native details, `syncPresentation`과 백업 생성기를 재사용하는 화면 정리다. 신규 의존성·편집기·저장 형식·운영 SQL은 없다. 공식 Impeccable 4.5.0 지침의 Operate/craft-floor를 참고했다([도입 출처](impeccable.md)). 새 라이브러리의 최신 릴리스를 조사·도입하거나 자동 엔진을 실행한 작업은 아니다.

## 보존과 실패 처리

현재 작업공간 ID와 동기화 상태의 조회 대상을 대조한다. 공간을 바꾸면 이전 공간의 `서버와 동기화됨`을 재사용하지 않고 `확인 중`을 표시한다. 늦은 성공·실패 응답이 다른 공간의 상태를 덮지 않게 한다. 상태 조회 실패는 기존 연결을 지우거나 새로 시작하지 않으며 동기화 화면에서 다시 확인한다. 관리 화면을 열었다고 자료를 업로드하지 않는다.

원문·정확 버전·발췌 위치·계정별 보관·선택 동기화·공개 범위와 두 JSON 형식은 그대로다. 구성 백업에는 묶음·내 페이지·회고·책도 포함된다. 두 파일 모두 미적용 글쓰기/가져오기 초안, 읽기 위치, 사진·미확보 본문, 연표·목표·습관, 이미 게시한 사본을 백업하는 것으로 안내하지 않는다. 새 사본 복원과 자동 동기화 연결도 구분한다.
