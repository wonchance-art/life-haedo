## 사용 장면과 구현 범위

사용자는 대량 사진 관리보다 여행·일상 글에 몇 장의 사진을 붙여 편하게 쓰고 읽기를 원했다. 내 페이지의 **사진 글쓰기 → 제목/본문·서식·사진 → 글 저장 → 같은 모습으로 읽기·원본 확대 → 사진 포함 백업/새 초안 복원**을 연결했다. 네이버 블로그의 친숙한 본문 편집 경험을 참고하며 전체 기능 복제나 같은 공개 서비스를 구현했다고 표현하지 않는다.

기본 문단·큰/작은 제목·굵게·기울임·밑줄·인용·번호/글머리 목록·가운데 정렬·링크·실행 취소/다시 실행을 제공한다. 사진은 커서 위치에 넣고 설명·대체 텍스트·앞/뒤 이동·빼기를 편집한다. 파일 선택, 사진 붙여넣기와 파일 드롭을 받으며 외부 HTML/원격 사진 붙여넣기는 평문으로 처리한다. 사진 선택은 키보드 Enter/Space로도 가능하다. 실제 Apple IME·Photos·Files 체험을 Linux 모사로 대신하지 않는다.

기존 평문 글·대상 첨부·초안·공개 payload·SQL 형식을 유지했다. 새 사진 글은 같은 내 페이지 안의 명시한 진입점과 목록·읽기에서 사용한다. 이전 작성기의 미반영 입력/저장 실패가 있으면 사진 작성기로 넘어가 숨기지 않고 먼저 보존하게 한다. 이 선택은 기존 strict 클라이언트/구성 동기화에 사진이나 편집기 전용 필드를 넣지 않기 위한 경계다. 두 작성 흐름을 합치는 후속은 기존 글·첨부·공개 호환성을 보존하는 별도 검토로 남긴다.

## 사진 품질·보관 계약

- JPEG·PNG·WebP의 **브라우저에 전달된 원본 바이트·해상도**를 그대로 Blob으로 보관한다. 리사이즈·캔버스 재인코딩·JPEG 재압축·작은 썸네일 확대를 하지 않는다. 본문은 원본을 화면 폭에 맞춰 표시하고 작은 이미지는 억지로 늘리지 않는다. 크게 보기에서 화면 맞춤/실제 원본 크기·원본 내려받기를 제공한다.
- 한 글 20장, 원본 한 장 64 MiB, 원본 합계 256 MiB까지다. 용량 초과·열 수 없는 파일을 알리고 자동 축소하지 않는다. HEIC/HEIF·영상·SVG는 이번에 지원하지 않는다. OS 사진 선택기가 파일을 전달하기 전에 변환하는 경우까지 카메라 원본과 동일하다고 보장하지 않는다.
- 계정·작업공간별 **이 브라우저에만** 저장한다. 원본의 EXIF 등 메타데이터도 파일과 함께 유지된다. 일반 자료·구성/초안 JSON, 구성 동기화, 공개 사본에는 포함하지 않는다. 보관 안내와 전용 ZIP 조작으로 범위를 표시한다. 서버 업로드·사진 공개·원격 갤러리를 이번 완료로 표현하지 않는다.
- ZIP은 제목·제한된 Delta·설명/대체 텍스트·원본 파일·픽셀/크기/타입/SHA-256 정보를 함께 담는다. 원본 파일을 압축 수준 0으로 포장하며 재인코딩하지 않는다. 복원은 내용 확인 후 **새 비공개 초안**으로만 설치한다. 문서/사진 ID를 새로 부여하고 원본 해시·타입·실제 디코딩 해상도·참조·파일 수·중복/경로·펼친 크기를 확인한다. 원본 계정/공간 ID를 파일에 넣지 않는다.

## 저장·실패 후 복구

`photo-post.js`는 제한된 구조만 받는다. 임의 HTML·스크립트·외부 이미지 embed·지원하지 않는 서식/링크·누락된 Blob을 거부한다. `photo-post-ui.js`는 Quill 2.0.3의 편집/IME/history 엔진을 재사용하고 읽기에는 검증된 데이터로 DOM을 만든다. [공식 배포·라이선스·무결성·공개 권고 확인](../life-tools-design/open-source-review.md#사진-글-편집원본-zip-보관--2026-10-15-kst). Quill BSD-3-Clause와 배포 저작권·번들 의존성 고지, fflate MIT를 vendor와 공개 산출물에 보존했다. 새 앱 빌드나 외부 CDN은 필요 없다.

문서별 CAS와 사진/목록 메타데이터를 같은 IndexedDB 트랜잭션에서 저장한다. 저장한 글 수정은 새 초안으로 시작해 원래 글을 유지하며 명시 저장 때 기준 revision을 재확인한다. 실패한 저장/입력/한글 조합/사진 처리 중 이동을 막는다. 같은 초안의 두 탭 충돌은 현재 입력을 새 초안으로 보관하고, 저장한 글의 충돌은 기존 저장본을 유지한 채 새 글로 저장할 수 있다. 저장 응답 중 새 입력은 실제 저장 payload의 tick/revision을 기준으로 다시 저장한다.

브라우저 URL은 렌더링에만 쓰고 저장 Delta에는 넣지 않는다. 삭제한 사진의 실행 취소에도 현재 편집 세션의 원본을 유지하며, 저장본에는 참조한 사진만 담는다. 화면/계정/공간을 떠난 늦은 읽기는 새 화면에 적용하지 않는다. 문서 본문과 원본이 성공적으로 commit된 뒤 같은 계정의 변경 알림을 보낸다. 기존 원문·일반 글·컬렉션·9칸 저장본을 변경하지 않는다.

통합 검색은 저장한 사진 글의 제목·본문·사진 설명을 작은 텍스트 요약에서 찾는다. 초안·사진 바이트를 검색 대상으로 가져오지 않는다. 실제 저장 글을 확인해 열고 검색어/결과 초점으로 돌아온다. 다른 저장 범위가 실패해도 독립 결과를 유지한다.

**반대 검토:** 사진을 기존 JSON 본문에 base64로 넣으면 용량·호환성·공개/동기화 범위를 함께 바꾸게 된다. 원본 파일과 제한된 편집 문서를 별도로 저장하는 작은 단위를 택했다. 브라우저 보관만으로 장기 보존을 약속하지 않고 ZIP 백업을 제공한다. 한도 최댓값·많은 글의 메모리/모바일 처리 시간은 아직 실측하지 않았다. 실제 사용에서 두 작성 진입점이나 백업 이동이 반복 부담으로 확인되면 통합 편집/선택적 사진 동기화를 다음 범위로 비교한다.
