# 뉴스에서 내 글 저장·재열기까지

2026-10-21 KST. 뉴스의 설정·반응·평가 준비를 별도 완료로 끊던 범위를 **뉴스 선택→원문 열기·반응→명시 링크 보관→정확한 자료로 작성 준비→내 문단·출처 선택→미리보기·초안→글 저장·재열기→같은 뉴스 복귀**로 통합했다. 기존 뉴스·MaterialWriting·PhotoPost·저장/복귀 경로를 재사용한다.

## 바로 사용하는 순서

1. [뉴스](https://wonchance-art.github.io/life-haedo/index.html?section=news)에서 글을 고른다. 원문/명시 번역, 좋아요·담기와 언어·출처 옵션은 기존대로 사용한다. 읽음/관련 없음으로 제외한 글도 `제외한 글`에서 현재 공급에 남아 있으면 원문·번역·링크 보관 검토를 바로 연다. 제외를 자동으로 되돌리지 않는다.
2. `링크 보관 검토`→`자료만 보관`을 선택한다. 자료 화면에서 **이 자료로 글쓰기**를 누르면 해당 자료의 정확한 버전이 들어 있는 새 작성 준비로 바로 간다. 제목 검색·자료 페이지에 담기·버전 재선택을 반복하지 않는다.
3. 글 제목과 내 문단을 쓴다. 필요하면 자료의 **출처 링크를 글에 담기**로 제목·공개 HTTPS URL을 일반 문단으로 넣는다. 전체 미리보기에서 확인하고 명시 동의 후 기존 글 초안을 만든다.
4. 기존 작성기에서 `글 저장`을 누르고 보관 상태를 확인한다. 같은 글을 다시 열거나 작성 준비로 돌아온 뒤 위쪽 뒤로가기로 원래 뉴스에 복귀한다. 뉴스의 모드·언어·반응·제외 상태를 바꾸지 않는다.

## 연결과 보존

자료 읽기 화면은 클릭 시 현재 계정·공간·탐색 세대와 정확한 자료/버전/해시를 다시 확인한다. 해시가 없는 링크 자료도 `null` 그대로 비교한다. 요청 ID를 기존 준비 ID로 사용해 재시도·같은 요청 재진입이 준비를 중복 생성하지 않도록 했다. 준비 저장·충돌 처리와 초안 인계는 기존 원자 CAS·영속 영수증을 사용한다. 기존 준비의 미저장 입력·한글 조합·자료 선택은 flush 성공 전 바꾸지 않는다.

새 준비는 선택 자료만 연결하며 글 제목·본문·인용·자료 메모를 자동으로 쓰지 않는다. 링크 자료는 본문/해시가 `null`인 상태를 유지한다. 명시 출처 링크는 제목과 URL의 일반 문단이며 원문 인용·본문 확보·구조화된 인용 근거로 표현하지 않는다. 출처 링크 클릭 중 자료가 바뀌거나 정확한 버전이 사라지면 중단한다. 현재 공급에서 사라진 제외 행에는 원문 메타데이터를 만들어 보관 버튼을 붙이지 않는다.

뉴스 복귀 정보는 화면 세션에만 둔다. 계정·공간이 바뀐 늦은 결과를 적용하지 않으며 개인 자료·백업·서버·공개 내용에 복귀 정보를 넣지 않는다. 준비에서 원문을 다시 열고 돌아오거나 글을 저장·재열기해도 같은 뉴스 origin을 유지한다. 재시작 뒤 없는 세션 위치를 추정하지 않는다.

기본 작성기의 명시 글 저장 후 비공개 서버 보관 계약은 그대로다. 준비·초안·출처 링크 삽입·재열기만으로 전송하거나 공개하지 않는다. 서버 실패에도 로컬 글·원본과 재시도 상태를 남기며, 기존의 명시 보관 중지·별도 공개 동의를 유지한다. 기존 자료·정확 버전·사진·백업 형식과 SQL은 바꾸지 않았다.

## 검수와 출시

단위1122/1122·정적22HTML/147JS/627참조·MWUI집중21/21·자료 카드 브라우저10/10을 통과했다. 두 개의 기존 뉴스 준비 검사와 하나의 연속 목표(3/3)에서 링크 보관·정확한 준비·명시 출처 문단·미동의 차단/입력 보존·초안 전송0→명시 글 저장 후 모의 비공개 보관1·공개0·같은 글 재열기·뉴스 목록/포커스·재시작 보존을 확인했다. 최종 제품16파일 해시는 실행 전후 동일하다. 이 집중 실행을 기존 뉴스 전체9개 검사로 합산하지 않는다.

실제 새 reader·작성 문단·저장 글의390/1440px viewport6장을 직접 검토했다. 발견한 reader의 두 버튼 겹침을 새 작업 행의 여백만 보완해 해결했으며, 최종 두 조작 높이는44px 이상·간격15px·가로 넘침0으로 확인했다. 전체 페이지 촬영의 입력/고정 메뉴 paint 한계는 실제 viewport 촬영으로 구분했다. 독립 보존 검토는 계정·정확 버전·초안/글 저장·공개/백업 경계의 차단 문제0이다.

정확한 SW144→145 PWA9/9에서 설치 캐시의 최신 ui.js/ui.css 바이트, 자료·반응·언어·옵션, 오프라인/Auth 거부·복구를 확인했다. 이전 워커만144인 현재 모듈 검수이며 이전 앱 전체를 재현한 것은 아니다. [고정 검수 영수증](evidence/news-to-writing/verification.json). 원래 실패·가정 오류·시각 수정 전 증거는 ignored 로컬 폴더에 보존했다.

최종 커밋의 전체 CI·병합·수집/게시 파일 대조는 [이번 통합 PR·출시 기록](https://github.com/wonchance-art/life-haedo/pulls?q=is%3Apr+head%3Acodex%2Fnews-writing-complete-20261021)의 실제 SHA/검사/운영 영수증을 따른다. 로컬 검수 결과로 운영 배포를 추정하지 않는다. 실제 계정·Google 원문/번역 결과·Apple 기기·사용자 읽기 효용을 합성 검수로 대신하지 않는다. 최신 상태와 후속 목표는 [로드맵](../life-tools-design/roadmap.md)을 따른다.
