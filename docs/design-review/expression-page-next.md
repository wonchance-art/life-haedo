# 내 페이지 정보 배치: 다음 비교안

2026-10-08 KST. root가 디자인 결정을 맡는다. 이번 결과는 현행 코드와 PR39 익명 화면을 바탕으로 한 **문서 설계**다. 앱·CSS·HTML 시안은 수정하지 않았고 아래 A/B 화면도 아직 만들거나 캡처하지 않았다.

## 목표와 근거

선택한 글을 읽으면서 작성자의 코멘트와 활동의 이어짐을 알아볼 수 있는 내 페이지를 비교한다. [현재 디자인](../../DESIGN.md)의 흰 본문·700px 한 열·한글 산세리프·절제된 탐색을 유지한다. SNS의 짧은 글 단위를 참고하되 프로필 통계·반응 수·추천 패널·사진 자리·주제 카드로 공간을 채우지 않는다. [핵심 경험](core-experience.md)의 원문 → 내 코멘트 순서와 제목 중복 억제를 유지한다.

직접 본 기존 화면은 PR39 [편집 820px](evidence/product-flow-quality/page-edited-820.png), [비공개 미리보기 390px](evidence/product-flow-quality/page-preview-390.png), [새 원문 가져오기 뒤 이전 버전 미리보기 1440px](evidence/product-flow-quality/page-reopened-1440.png)다. 앞선 작업에서 동일 흐름의 `.local/product-flow-quality/` 세 폭 이미지도 검토했다. 이는 익명 전시·정원 자료의 현행 화면이며, 아래 8개 글 비교의 화면 증거는 아니다.

정적 근거는 [pagePart/renderPage/renderVisitor](../../assets/life/workbench-ui.js), [페이지 본문 스타일](../../assets/life/workbench.css), [원문 버전 필드](../../assets/life/core.js), [공개 사본 선택](../../assets/life/share.js)다. 현재 페이지는 고정 항목을 먼저 놓고 같은 그룹 안의 수동 순서를 유지한다. 원문 본문은 편집 결과와 미리보기에서 높이 제한 없이 나오며 코멘트가 모든 원문 뒤에 있다. `originalCreatedAt`은 원문 버전에 있으나 페이지 기본 메타에는 나오지 않는다. `importedAt`·페이지 저장 시각은 활동 시각이 아니다.

기존 [통합 활동 시안](activity-hub.md)은 연결 방향의 참고다. 과거 두 열 편집이나 장식은 현재 배치의 확정 근거로 사용하지 않는다.

## 두 안의 공통 계약

- 내 페이지 기본은 결과를 읽는 화면이다. 항목 편집은 제목 옆 기존 연필과 접힌 상세로 연다. 표시·고정·원문 선택·순서·삭제를 기본 피드에 나열하지 않는다.
- 제목·소개와 읽기 조작의 위계를 정리하되 전역 탐색은 바꾸지 않는다. 비공개 미리보기와 `편집으로 돌아가기`는 명시한다. 정상 보관 상태는 작은 한 행으로 묶고 저장 실패는 메시지와 재시도를 숨기지 않는다. 공개 사본 관리는 현재 경로를 보존한다.
- 원문 또는 화면에서 발췌한 앞부분을 먼저, `내 코멘트`를 그다음에 둔다. 다른 사람의 원문과 사용자의 생각을 합치지 않는다. 같은 첫 원문/항목 제목은 한 번만 표시한다.
- 짧게 보여주는 것은 **화면의 접힘**이다. 원문 문자열·정확 버전·UTF-16 위치·항목 선택·본문 표시 설정을 바꾸지 않는다. `본문 펼치기`는 현재 항목 안에서 전체를 열며 다시 접을 때 해당 조작으로 초점을 돌린다. CSS 말줄임만으로 긴 본문을 접근 불가능하게 만들지 않는다.
- 확인된 `originalCreatedAt`만 `원문 작성일`로 표시한다. 날짜를 모르면 추정하지 않는다. 여러 원문의 날짜가 다르면 원문별로 표시하며 묶음 전체에 임의의 활동일을 붙이지 않는다. 링크만 있는 글·부분 본문·타인 글·이전 버전의 필요한 표시는 계속 보인다.
- 두 안 모두 같은 항목·선택·고정·수동 순서를 사용한다. 날짜 정렬·월별 섹션·자동 활동 연결·자동 요약을 추가하지 않는다. 단순 배치를 바꿔 기존 순서를 재해석하지 않는다.

## A안: 글의 앞부분을 이어 읽는 피드

기존 구조에 가까운 우선 비교안이다. 항목 제목 → 원문 작성일/필수 출처 메타 → 원문 앞부분 → `본문 펼치기` → 내 코멘트 → 다음 항목으로 읽는다. 여러 원문 항목도 출처별 구분을 유지한다.

각 원문은 실제 앞 문단을 기준으로 대략 6~8줄까지만 기본 표시하고 초과분만 접는다. 문단이 너무 길면 앞부분임을 명시하고 전체 열기를 제공한다. 짧은 글은 전부 보인다. 내 코멘트는 그대로 읽히며 긴 코멘트도 임의 요약하지 않는다. 날짜는 보조 메타이고 별도 시간선·연결선·색 패널이 없다.

장점은 현재의 본문 중심 감각과 편집 위치를 유지하면서 긴 글의 부담을 줄이는 것이다. 약점은 긴 코멘트나 여러 출처가 있는 첫 항목에서는 다음 활동이 여전히 늦게 나올 수 있다는 점이다. 모든 글이 짧을 때 접기 조작이 늘어나는 안이면 기각한다.

## B안: 활동 항목과 출처를 먼저 구별하는 흐름

같은 한 열·같은 수동 순서에서 항목을 활동 단위로 더 뚜렷하게 읽는다. 항목 제목 → 연결한 원문 각각의 제목/작성일/필수 메타와 짧은 앞 문단 → 각 원문의 `본문 펼치기` → 내 코멘트 → 다음 항목으로 이어진다. 두 글이 같은 활동에 속한다는 근거는 **이미 사용자가 만든 항목 구성**이며 내용 유사도나 날짜 근접성으로 새 활동을 만들어내지 않는다.

각 원문 앞부분은 대략 3~4줄로 시작하고 제목·작성일이 있는 출처 단위를 일정한 간격으로 구분한다. 한 원문뿐인 항목은 반복 제목을 만들지 않는다. 날짜는 각 글에 붙고, 시간선·월별 헤더·그리드·상시 목차는 없다. 긴 글보다 여러 원문과 다음 활동을 먼저 찾기 쉽도록 밀도를 낮춘다.

장점은 전시 감상과 산책 캡션처럼 한 활동 안의 자료를 구별하고 다른 활동으로 이동하기 쉽다는 것이다. 약점은 출처·날짜가 글보다 두드러지거나 짧은 앞부분으로 문맥이 부족할 수 있다는 점이다. 활동 목록이 원문을 여는 링크 모음처럼 느껴지면 A안으로 돌아간다.

| 비교 지점 | A안 | B안 |
| --- | --- | --- |
| 기본 읽기 단위 | 원문 앞 문단 6~8줄 | 활동 안의 원문별 앞 문단 3~4줄 |
| 날짜·출처 | 본문을 위한 보조 메타 | 여러 원문을 구별하는 작은 기준 |
| 기대 효과 | 글과 코멘트를 충분히 읽으면서 이동 | 한 활동의 출처와 다음 활동을 빠르게 파악 |
| 먼저 확인할 위험 | 첫 항목이 여전히 너무 길음 | 요약 목록처럼 느껴지고 문맥이 부족함 |

줄 수는 설계 가설이다. 실제 한글 문단·폭을 보고 한 번 조정하며 합격 수치로 고정하지 않는다. 접힘이 필요 없다는 결과도 유효하다.

같은 항목 순서는 사용자의 선택이며 날짜순이라고 표시하지 않는다. 확인된 날짜는 항목 1의 두 기록처럼 실제 선후를 설명할 때만 근거로 쓴다. 날짜가 없는 ⑦/⑧을 다른 활동 앞뒤로 추정하지 않는다.

## 최소 비교와 결정 조건

후속 구현을 맡으면 root가 A/B에 공통 자료를 넣고 1440·820·390px에서 기본 첫 화면, 첫 항목 전체 펼침, 두 번째 활동 진입, 편집 왕복을 각 한 번 확인한다. 현재 문서 작업에서는 브라우저를 새로 실행하거나 이 안을 검증했다고 보고하지 않는다.

내용 과제는 네 가지다. 첫 활동의 내 코멘트를 찾아 원문과 구분하기, 전시 메모 뒤 작성된 캡션을 확인된 날짜로 설명하기, 네 번째 짧은 글을 찾아 전체 읽기, 이전 버전의 정확 원문으로 갔다가 같은 위치로 돌아오기다. 전체 게시를 요구하는 과제는 넣지 않는다.

실제 화면 검토는 코멘트·다음 항목 발견, 문단 문맥, 반복 제목, 출처/버전 판독으로 판단한다. 계측은 넘침·44px 조작·16px 입력·작은 글자 대비·키보드 초점·하단 탐색 가림을 별도로 기록한다. 펼치기/복귀 클릭과 본문 시작 위치는 두 안의 차이를 설명하는 자료로만 쓴다.

A안을 먼저 최소 구현하는 것이 현재의 잠정 권고다. B안이 출처와 선후를 더 쉽게 설명하게 하면서 글의 문맥과 코멘트 읽기를 해치지 않을 때만 B안을 고른다. 차이가 없으면 추가 구조가 적은 A안을 유지한다. 둘 다 본문/코멘트 이해를 떨어뜨리면 접힘을 철회하고 날짜·상단 조작 정리만 남긴다. root가 비교 뒤 결정하며 현재 기본 배치를 바꾸는 승인으로 해석하지 않는다.

## 보존 경계와 미검증

이 배치는 비공개 내 페이지와 비공개 미리보기의 읽기 가설이다. [공개 사본](page-publication.md)의 본문/구절 선택·검토·명시 게시·갱신·철회는 별도다. 접힌 본문을 공개에서 제외했다고 표시하거나, 전체를 펼치는 것만으로 전송 내용을 늘리지 않는다. 배치 변경으로 게시한 사본을 자동 갱신하지 않는다. 공개 방문 화면에 같은 배치를 적용할지는 별도 검토한다.

AI 해석·새 공개 기능·자동 SNS 연결·활동일 스키마·백업/동기화 형식 변경은 이 비교에 포함하지 않는다. 저장 실패·원문 없음·전체 숨김에서도 현재 복구 경로를 유지한다. 실제 Mac/iPad/iPhone의 읽기·선택 손잡이·IME·VoiceOver와 8개 글 장기 사용은 미검증이다.
