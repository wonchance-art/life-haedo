# 계정 자료를 현재 자료실에서 사용하기

2026-10-20 · 구현·자동 검수와 운영 등록 목록 설치를 완료했다. 최종 PR·main 배포, 실제 사용자 브라우저 등록과 Google·Apple 체험은 미완료다.

## 목표와 자료 범위

이미 계정 서버에 보관된 IDEAS 노트를 다른 작업공간으로 이동할 필요 없이, 현재 쓰는 자료실에서 검색·읽기·정확한 구절 채택에 사용한다. 기존 글·사진·개인 메모와 현재 작업공간을 유지한다.

- 노트 3,479개를 일반 원문 자료로 등록한다. 시스템 경로·README 파일명에 해당하는 노트는 없으며, 이름만으로 내용을 제외하지 않는다.
- 보조 파일 3,420개 중 YAML 3,400개는 별도 일반 본문으로 중복 등록하지 않는다. 그중 3,358개의 경로 필드가 노트와 정확히 대응한다.
- 이 대조는 YAML 전체의 의미가 같거나 불필요하다는 판정이 아니다. 나머지 42개도 노트 본문으로 추정 변환하거나 자동 병합하지 않는다.
- 보조 자료의 설정·스크립트·기타 파일과 원래 패키지는 보존한다. 서버의 원본 두 작업공간도 삭제·재작성하지 않는다.
- 기존 기본 자료와 원본 패키지의 비어 있지 않은 본문 해시 중복은 확인되지 않았다. 노트 내부의 같은 해시는 서로 다른 경로·참조를 가질 수 있어 삭제 근거로 삼지 않는다.

## 서버 목록과 부팅 동작

1. 신규 `life_account_materials`는 소유자별 비공개 등록 목록이며, RLS로 다른 계정·익명 접근을 제한한다.
2. 목록에는 기존 서버 원문 작업공간을 가리키는 manifest pointer만 둔다. 원문 본문을 새 서버 테이블에 복사하지 않는다.
3. 인증된 내 자료 부팅 시 현재 계정의 목록을 GET하고, 등록된 원문 작업공간의 정확한 revision·SHA와 내용을 검증한다.
4. 검증된 원문을 현재 활성 작업공간에 같은 source/version/link ID로 추가한다. 원문 바이트·포함 범위·정확 버전·링크 위치를 보존한다.
5. 현재 공간의 revision을 기준으로 additive CAS를 수행하고, 자료와 등록 marker를 같은 트랜잭션에 기록한다. 일부 자료만 설치하거나 marker만 완료시키지 않는다.
6. 같은 등록을 새 operation·재부팅·새로고침으로 반복해도 자료가 중복 추가되지 않는다. marker뿐 아니라 기존 정확 자료와도 대조한다.
7. 등록을 위해 사용자가 서버 작업공간을 따로 받거나 새 공간을 만들거나 활성 공간을 바꿀 필요가 없다.

## 보존과 실패 경계

- 현재 공간에 있는 원문·모든 버전·발췌·개인 메모·글·사진·구성·보관 상태를 변경하지 않는다. 원문을 사용자 작성 글로 바꾸지 않는다.
- 같은 ID에 다른 내용이 있으면 최신판으로 덮어쓰지 않는다. 검증·소유권·정확 pin 불일치는 등록을 중단하고 기존 자료를 유지한다.
- 원본 두 작업공간은 기존 정확 참조·백업의 출처로 남는다. 화면의 중복을 줄이는 것을 서버 원본 삭제로 구현하지 않는다.
- 계정·작업공간 전환 중 늦게 도착한 목록·원문·저장 결과는 기존 scope 가드로 차단한다. 다른 계정 자료를 이메일이나 제목으로 추정 연결하지 않는다.
- 현재 공간에 이미 활성 동기화가 있으면 기존 선택·outbox·충돌 정책을 따른다. 등록이 새 동기화를 켜거나 공개를 시작하지 않는다.
- outbox 처리·충돌·용량 제한으로 안전한 추가가 불가능하면 기존 원문을 보호한 채 중단한다. 16 MiB 제한을 우회하거나 일부 원문·버전을 버려 맞추지 않는다.
- 일시적 조회 실패와 등록 자료 없음은 구분한다. 실패를 빈 목록으로 확정하거나 원본이 사라졌다고 표시하지 않는다.
- 표시·검색·글쓰기와 자료의 서버 보관·공개는 별도 범위다. 이번 등록이 자동 개인 분석이나 전체 자료 자동 전송의 새 권한은 아니다.

## 기존 구현 재사용과 검토 근거

원문 모델·불변 버전·정확 링크는 기존 Core, 부팅과 소유권 검사는 기존 계정 저장소, 조건부 저장·outbox는 기존 CAS 흐름을 재사용한다. 새 범용 동기화 엔진이나 별도 원문 저장 형식은 도입하지 않는다.

비공개 패키지·설치 기록을 읽기 전용으로 대조했다. 네 패키지 사본의 원문 대응과 감사 파일에 기록된 본문 해시는 일치했으며, 입력 파일은 변경하지 않았다. 개인 제목·본문·소유자·식별자·파일 경로는 이 문서에 싣지 않는다.

실제 데이터는 오프라인 새 서비스의 prepare로만 대조했다. 기본 6개 자료·7버전에 노트를 더한 원문 3,485개·버전 3,486개·링크 2,568개가 Core 검증에 맞고, 직렬화 크기는 14,763,809바이트로 16 MiB 이하였다. Node에서 약 6초였으며 실제 Apple 성능이나 사용자 브라우저 등록·동기화 성공을 입증하지 않는다.
