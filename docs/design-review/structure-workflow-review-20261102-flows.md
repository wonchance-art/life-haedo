# 3. 사용 흐름 6개 점검 (2026-11-02)

전체 구조·작업 흐름 점검의 3절이다. 앱 코드는 바꾸지 않았다.

- 기준: `origin/main` `a8d4a65`
- 환경: Linux Chromium(Playwright 1243 빌드), 로컬 `python3 -m http.server`
- 데이터: 저장소의 가짜 서버(`FakeCloud`, `CompositionCloud().enableAccountLibrary()`, `NaverCloud`)와 익명 합성 계정·자료만 썼다. 실제 Google 로그인, 운영 DB, 실제 네이버는 쓰지 않았다.
- 화면 폭: 390×844(`isMobile`·`hasTouch` 모사)와 1440×900. **모사이며 실제 Apple 기기 확인이 아니다.**
- 한글 입력: `compositionstart` → `insertText` → `compositionend`를 합성 이벤트로 보냈다. 실제 IME 확인이 아니다.
- 실행 스크립트는 작업 폴더(scratchpad)에만 두었고 커밋하지 않았다. 재현 순서는 각 항목에 적었다.
- 화면 캡처: `docs/design-review/evidence/structure-workflow-20261102/` (30장, 약 0.7MB, JPEG). 파일 이름의 `f1`~`f6`은 흐름 번호, 끝의 `390`·`1440`은 화면 폭이다.
  - 흐름별 주요 장면: 편집·저장·보관(f1), 가져오기 검토·읽기·작성 준비(f2), 뉴스·설정(f3), 연결 전·목록·실패(f4), 백업·복원 미리보기·결과(f5), 계획·목표 실패(f6)

## 3.2 결함 후보 — 기능·흐름 (심각도순)

블로커: 없음.

### 메이저

**M1. 글쓰기·글 읽기 화면에서 새로고침하면 자료실 `선택 자료 페이지`가 열린다** — 흐름 1, 확인됨(1440·390 모두)

- 재현:
  1. 로그인한 홈에서 `첫 글 쓰기`를 누른다. 주소는 `index.html?view=page`가 된다.
  2. 제목과 본문을 쓴다. 또는 저장한 글을 홈에서 다시 연다.
  3. 새로고침한다.
- 관찰: 주소가 `index.html?view=page&section=records`로 바뀐다. 자료실 탭의 `선택 자료 페이지`가 열린다. 초안은 IndexedDB에 남아 있다(`초안` 탭에서 다시 열 수 있음).
- 기대: 같은 글쓰기 화면이나 같은 글로 돌아온다. 최소한 홈 `내 글`로 돌아온다.
- 영향: iPad·iPhone에서 백그라운드 탭이 다시 로드되면 같은 일이 생긴다. 입력은 남지만 쓰던 글을 잃은 것처럼 보인다.
- 근거:
  - `f1-reload-in-editor-1440.jpg`
  - 원인 추정: `assets/life/ui.js:1501` — `view=page`는 `page` 모드로 해석된다.
  - `assets/life/ui.js:1491` — 새로 로드하면 `blogPageTask`가 없어서 `sectionFor('page')`가 `records`가 된다.
  - 옛 주소 `index.html?view=page`도 같은 결과다.

**M2. 브라우저 뒤로 가기가 직전 화면이 아니라 이전 탭이나 앱 밖으로 간다** — 흐름 1·2·4·5·6, 확인됨

- 재현 (흐름 1):
  1. `index.html?section=records`를 연다.
  2. 메뉴에서 `홈`을 누른다.
  3. `첫 글 쓰기`를 누른다.
  4. 본문을 입력하고 브라우저 뒤로 가기를 누른다.
- 관찰: 홈이 아니라 자료실 목록으로 간다. 초안은 보존된다. 주소창으로 바로 연 화면에서 시작하면 `about:blank`(앱 밖)로 나간다.
  - 흐름 1: 저장한 글
  - 흐름 4: 네이버 목록에서 연 자료
- 같은 원인의 다른 경우:
  - 자료 읽기 → `이 자료로 글쓰기` → 뒤로 가기: 읽던 자료나 목록이 아니라 `홈`으로 간다.
  - `설정 → 백업·복원`이나 `계획 → 연간 계획`에서 뒤로 가기: 설정 목록·계획 목록을 건너뛰고 `홈`으로 간다.
- 기대: 화면 안 이동(목록 → 글, 목록 → 하위 화면)도 한 단계씩 돌아간다. 화면 안의 `←`·`돌아가기` 버튼과 같은 곳으로 간다.
- 근거: `assets/life/ui.js:1355`
  - `navigate()`가 모든 화면 이동에서 `writeRoute(mode, false)`, 즉 `replaceState`를 쓴다.
  - `pushState`는 전역 메뉴로 탭을 바꿀 때만 쓴다(`ui.js:1525,1565`).
- 참고: iPad Chrome의 뒤로 밀기 제스처와 Mac 뒤로 가기에서 체감이 크다. 설치형(PWA) 단독 실행에는 뒤로 버튼이 없어 영향이 작다.

**M3. 자료 읽기에서 `이 자료로 글쓰기` → `돌아가기`를 누르면 읽던 자료가 아니라 `선택 자료 페이지`로 간다** — 흐름 2, 확인됨(1440·390)

- 재현:
  1. 자료실 → `가져오기`로 본문을 붙여넣는다.
  2. `원문·출처 확인` → 발췌 후보 추가 → `선택한 발췌 모음에 반영`을 누른다.
  3. 목록에서 `자료 읽기: …`를 누른다.
  4. `이 자료로 글쓰기`를 누른다.
  5. 작성 준비 화면에서 `돌아가기`(`#mwClose`)를 누른다.
- 관찰: `index.html?section=records&view=page`의 `선택 자료 페이지`에 머문다. 초점은 `자료로 글쓰기` 버튼에 있다. 읽던 자료와 스크롤 위치로 돌아가지 않는다.
- 기대: 출발한 자료 읽기 화면(같은 자료·같은 버전)으로 돌아가고, 초점은 `이 자료로 글쓰기`에 있다.
- 근거:
  - `assets/life/ui.js:3441` — 읽기 화면은 `navigate('page', { materialWritingSeed })`로 페이지 구성 화면을 연다.
  - `assets/life/workbench-ui.js:1128` — 그 화면의 `onClose`는 페이지 구성 화면만 다시 그린다. 출발지를 기억하지 않는다.
  - 화면: `f2-material-writing-390.jpg`

**M4. 같은 계정에 백업을 복원하면 홈 `내 글`에 모든 글이 두 번 보이고, 자료공간 이름이 같아 구분할 수 없다** — 흐름 5, 확인됨

- 재현:
  1. 글 1개와 자료 1개가 있는 계정에서 `설정 → 백업·복원 → 모두 받기`를 누른다.
  2. 같은 화면에서 받은 ZIP을 연다 → `복원`을 누른다.
  3. `홈`으로 간다.
- 관찰:
  - 결과 문구는 `새 자료공간 1개 … 기존 자료는 바뀌지 않았습니다`다.
  - 그런데 홈 `내 글`에 같은 제목의 글이 2개 보인다. 원래 공간이 활성인 상태에서도 그렇다.
  - `현재 자료공간` 선택 목록에 `내 자료`가 두 번 있다.
  - 결과 버튼 이름도 `내 자료 열기`다.
- 기대: 복원 사본임을 이름으로 구분한다(예: `내 자료 (복원 11월 2일)`). 계정 전체 글 목록에 중복이 생긴다는 점을 복원 전에 알린다. 또는 이미 있는 같은 글은 건너뛰는 선택지를 준다.
- 근거:
  - `f5-home-duplicates-390.jpg`
  - 같은 파일을 두 번째로 열 때의 경고는 있다(기존 검사). 첫 복원에 대한 안내는 없다.
- 미확인(추정): 복원한 글이 BlogSync로 다른 기기에도 올라가는지. 가짜 서버 호출 수(`life_blog_save` 1회)로는 원래 글과 사본을 가려내지 못했다.

### 마이너

**m1. 자료 읽기 화면을 새로고침하면 자료 목록으로 돌아간다** — 흐름 2, 확인됨

- 재현: 자료실에서 자료를 연다 → 새로고침.
- 관찰: 주소가 `index.html?section=records`라서 자료 ID가 없다. 목록이 열린다.
- 기대: 같은 자료·버전이 열린다.
- 근거: `assets/life/ui.js:1518` — `source` 모드는 주소에 `sources`로만 기록된다.

**m2. 작성 준비 화면의 저장 문구가 실제 동기화와 다르다** — 흐름 2, 확인됨

- 관찰: 계정 동기화(`life_material_put` 호출 확인) 중에도 상태가 `이 브라우저에 비공개로 저장됨`이다. 같은 화면 위쪽에는 `계정에 보관됨`이 함께 보인다.
- 기대: 2026-11-01 계정 자동 연동 지시에 맞게 계정 저장 상태를 한 줄로 보여 준다.
- 근거: `assets/life/material-writing-ui.js:21`, `f2-material-writing-390.jpg`
- 같은 고정 문구가 있는 곳: `assets/life/blog-series-ui.js:22`, `assets/life/nine-board-ui.js:16`. 이 두 곳은 화면에서 확인하지 않았다(추정).

**m3. 네이버 `자동 수집 켜기`를 누르면 목록에 이미 보이던 글까지 한 번에 자료로 받는다** — 흐름 4, 가짜 서버에서 확인, 운영 동작은 추정

- 재현:
  1. 수집 준비가 된 상태에서 목록에 `아직 보관하지 않은 글` 3개가 보인다.
  2. `자동 수집 켜기`를 누른다.
- 관찰: `연결 설정을 보관했습니다. 3개 글을 이 공간의 자료에 반영했습니다.`
- 기대: 도움말(`새로 확인되는 글을 비공개 자료로 수집`, `이후 새로 발견한 글 자동 수집 켜기`)대로 켠 뒤 새로 발견한 글만 받는다. 또는 기존 목록도 받는다고 미리 알린다.
- 근거: `assets/life/naver-blog-sync.js:96-106` — 켜진 구독이면 수신함의 `new` 항목을 모두 받는다.
- 운영 서버 수신함에 켜기 전 글이 들어오는지는 확인하지 못했다.

**m4. 네이버 연결 상태 줄이 헷갈린다** — 흐름 4, 확인됨

- `자동 수집 중지`가 상태 문구(꺼짐)와 버튼 이름(끄기) 두 뜻으로 쓰인다(`assets/life/naver-blog-ui.js:292,301`).

- 한 화면에 확인 성격의 버튼이 4개다: `최신 내용 확인`, `목록 다시 확인`, `지금 확인`, `수집 상태 다시 확인`.
- 같은 블로그 카드가 `네이버 블로그 연결`과 `과거 글·사진 가져오기` 두 곳에 나온다.
- 화면: `f4-ready-list-390.jpg`

**m5. 네이버 실패 문구가 원인과 관계없이 같다** — 흐름 4, 확인됨

- 아래 세 경우 모두 `확인하지 못함 · 기존 자료 유지` / `처리하지 못했습니다. 입력과 기존 자료는 그대로 있습니다. 목록을 다시 확인한 뒤 다시 시도해 주세요.`가 나온다.
  - 서버 확인 실패(Edge 함수 503)
  - 목록 읽기 실패(RPC 503)
  - 오프라인
- 입력과 기존 자료가 보존되는 것은 확인했다. 오프라인인지 서버 문제인지는 구분되지 않는다.
- 화면: `f4-check-failed-390.jpg`

**m6. 백업 복원 미리보기가 다른 탭에 다녀오면 사라진다** — 흐름 5, 확인됨

- 재현: ZIP을 열어 미리보기를 띄운다 → `홈` → 브라우저 뒤로 가기.
- 관찰: `백업·복원` 화면은 다시 열리지만 미리보기가 없다. 파일을 다시 골라야 한다.
- 영향: iPad에서 파일 앱을 다시 거쳐야 한다. 데이터는 바뀌지 않는다.

**m7. 보관함으로 옮긴 직후 동기화 실패처럼 보이는 표시가 잠깐 나온다** — 흐름 1, 확인됨(시간 의존)

- 관찰:
  - 직후 약 0.3초: `저장됨 · 계정에 올리기 대기 중`과 `서버 보관 다시 시도` 버튼
  - 약 1.5초 뒤: `모든 기기에 저장됨 (비공개)`
  - 본문 위 상태: 보관 직후 `자동 저장됨`. 보관했다는 확인 문구는 없다. 글 정보 줄의 `보관함 ·`만 바뀐다.
- 기대: 보관·복원 직후에는 `보관함으로 옮겼어요`처럼 결과를 말한다. 재시도 버튼은 실제 실패에만 보인다.

### 다듬기

- **p1.** 저장 신호의 단어가 흐름마다 다르다. `모든 기기에 저장됨`(글), `계정에 보관됨`(자료), `이 브라우저에 비공개로 저장됨`(작성 준비), `저장됨`(연간 계획), `기기에 저장했습니다`(목표). 사용자는 어느 것이 다른 기기까지 갔는지 알 수 없다. 확인됨.

## 3.4 문제없이 확인한 것

- **글쓰기**
  - 자동 저장은 입력이 멈춘 뒤 약 0.3초에 시작한다(기존 검사 단언).
  - 조합 중에는 `한글 입력 중…`이 보이고 확정 저장으로 표시하지 않는다.
  - 사진 1장을 붙인 뒤에도 `자동 저장됨`이 나온다.
- **오프라인 저장**
  - 오프라인에서 `글 저장`을 누르면 로컬에는 저장된다.
  - 이때 문구는 `저장됨 · 계정에 올리지 못했습니다. 자동으로 다시 시도합니다.`다.
  - 다시 연결되면 버튼을 누르지 않아도 `모든 기기에 저장됨`이 된다.
- **편집 중 이탈**
  - 편집 중 홈으로 가면 `기존 글 수정 중` 초안과 `작성하던 글 · 이어쓰기`가 남는다.
  - 로그아웃 직전에 쓰던 글도 다시 로그인한 뒤 초안으로 남는다. 마지막 몇 글자까지 남았는지는 비교하지 않았다.
- **보관함**: `보관함으로 옮기기` → `보관함` 탭 → `목록으로 복원`이 두 폭에서 동작한다.
- **자료**
  - 다른 기기에서 같은 본문을 가져오면 `같은 자료로 확인 · 버전 비교`·`별개 자료로 보관`을 먼저 묻는다.
  - 발췌 반영 뒤 `계정에 보관됨`이 표시된다.
- **뉴스**
  - 좋아요가 저장되고 홈 왕복·뒤로 가기 뒤에도 유지된다.
  - 옛 주소 4개가 뉴스 또는 해당 화면으로 열린다(`life.html?view=external-discovery`, `?section=tools&view=external-discovery` 등).
  - 원문 링크는 `target=_blank`, `rel=noopener noreferrer`다.
- **네이버**
  - 수집 준비 전에는 자동 수집 체크가 꺼진 채 비활성이다.
  - 옛 주소 `?section=tools&view=naver-blog`가 자료실 네이버 화면으로 열린다.
- **백업**
  - 오프라인에서도 `모두 받기`가 ZIP을 내려받는다.
  - 백업 화면은 새로고침해도 유지된다.
- **계획**
  - 연간 계획 입력이 새로고침 뒤 남는다.
  - `life_account_document_put` 호출을 확인했다.

저장 실패(IndexedDB 중단), 늦은 응답, 흐름 중 계정 전환은 새로 만들지 않고 기존 회귀 검사를 같은 기준 커밋·로컬 서버(포트 4837)에서 다시 돌려 확인했다(3.5).
