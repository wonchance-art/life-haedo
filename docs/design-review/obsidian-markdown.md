# Obsidian Markdown 속성과 원문 보존

2026-10-23 KST · 가져온 Obsidian 문서에서 속성과 본문이 같은 Markdown으로 처리되던 문제를 바로잡는다. 사용자가 제공한 실제 제목·속성 값은 추적 문서·샘플·화면 기록에 옮기지 않고 익명 문서로 검수한다. 이번 목표는 **속성/본문을 구분해 읽기 → 정확 원문 확인 → 내 사본 수정·미리보기·저장·재열기 → 기존 백업/복원**이다. Obsidian 플러그인·테마 전체를 실행하거나 외부 보관함을 자동 탐색하는 목표가 아니다.

## 공식 형식과 이번 교정

[Obsidian Properties](https://help.obsidian.md/properties)는 문서의 맨 앞에서 여는 `---`와 닫는 `---` 사이에 YAML 속성을 둔다. 키는 중복할 수 없으며 텍스트·목록·숫자·참/거짓·날짜/날짜시각·태그를 표현한다. 내부 링크를 속성 값에 넣을 때는 따옴표로 감싼다. 공식 안내 자체도 속성 안의 Markdown 서식과 중첩 속성 UI를 지원하지 않는다고 명시한다.

아래는 사용자의 실제 문서가 아닌 익명 예시다.

```yaml
---
title: 익명 문서
date: 2026-01-01
tags:
  - 연구
  - 독서
related:
  - "[[익명 연결 문서]]"
---

# 본문 제목

본문 **강조**와 목록은 속성 뒤에서 시작한다.
```

유효한 속성은 기본으로 접힌 **속성**에서 이름과 값을 읽는다. 값은 안전한 텍스트이며 링크 클릭·태그 학습·문서 제목/작성일 변경·사용자 관심 추출로 승격하지 않는다. 속성 전용 편집기를 추가하지 않고 기존 전체 원문 편집에서 YAML을 직접 고친 뒤 미리보기·명시 저장을 사용한다.

맨 앞의 올바른 YAML 경계가 없는 `title: …`, `date: …` 같은 일반 문장은 속성으로 추정하지 않는다. 본문의 구분선·코드 안 YAML·닫히지 않은 머리말도 임의로 잘라 숨기지 않는다. 두 구분선 사이의 정상 스칼라·목록·null·빈 내용·주석만 있는 내용은 일반 Markdown으로 유지한다. 명확한 속성 매핑이지만 YAML 오류가 있거나 허용하지 않는 값/빈 매핑 `{}`이면 머리말을 원형 코드로 남기고 뒤의 본문을 서식화한다. 첫 의미 줄의 제한된 `key: value`/흐름 매핑 판별은 파서가 거절한 머리말의 오류 분류에만 쓰며, 실제 속성 승인은 공식 YAML 파서의 `Map` 결과로만 결정한다. 이 보조 판별로 일반 YAML 파서를 대신하지 않는다.

## 문법 지원 범위

공식 [기본 문법](https://help.obsidian.md/syntax)·[고급 문법](https://help.obsidian.md/advanced-syntax)과 현재 `SourceMarkdown`을 대조했다. 아래의 **기존**은 현재 파서·렌더러 정책의 범위이며 모든 Obsidian 화면을 재현했다는 뜻이 아니다. **이번 교정**의 검수·배포 결과는 뒤의 상태 절에서 별도로 확정한다.

| 문법 | 해도의 표시 범위 | 보존과 한계 |
| --- | --- | --- |
| 문단·제목·굵게/기울임·취소선·인용·순서/일반 목록·구분선 | 기존 기본 Markdown 서식 | 실제 원문은 가공하지 않으며 크기/중첩/토큰 한도를 넘으면 정확 원문 읽기로 돌아간다. |
| 표·인라인/펜스 코드 | 기존 표와 코드 표시 | 코드 구문 색상이나 실행 결과를 추가하지 않는다. |
| 문서 첫 YAML 속성 | 이번 교정: 속성과 본문을 분리하고 접힌 텍스트 목록으로 표시 | 올바른 경계·유효한 제한 값만 투영하며 원문 전체·정확 위치를 유지한다. |
| 속성의 `title`, `date`, `tags`, `related` 등 | 속성의 이름·스칼라·목록 값을 읽기 | source 메타데이터·검색 주제·관심·원문 관계를 자동 변경하지 않는다. 따옴표로 감싼 `[[내부 링크]]`도 속성에서는 텍스트다. |
| 안전한 HTTP/HTTPS Markdown 링크 | 기존 명시 링크 열기 | 외부 내용을 자동 요청하지 않는다. 상대 경로·앵커·위험 스킴은 임의 목적지로 바꾸지 않으며 원문에서 주소를 확인한다. |
| `[[위키 링크]]`, Obsidian 내부 링크/블록 참조 | 본문의 기호·텍스트를 보존 | 가져오기 어댑터의 정확 버전 연결과 본문 위키 문법 렌더링은 별개다. 파일명만 보고 다른 문서를 자동 연결하지 않는다. |
| 외부 이미지, `![[파일]]`·PDF/오디오/노트 임베드 | 이미지 대체 문구 또는 원문 텍스트 | 외부 이미지·미디어·포함 문서를 자동 수집/실행하지 않는다. 기존에 확보한 파일·사진의 보관 경로와 구분한다. |
| `- [ ]`, `- [x]` 작업 목록 | 일반 목록 안의 상태 기호/텍스트 | 상호작용하는 체크박스나 목표/습관 체크를 만들지 않는다. |
| `==강조==`, `%%주석%%`, 각주 | 전용 확장 없이 원문 기호를 보존 | Obsidian의 형광펜·주석 숨김·각주 탐색과 같지 않다. 주석이 읽기 화면에서 숨겨진다고 가정하지 않는다. |
| `[!note]` 등의 callout | 기존 인용문과 표식 텍스트 | 전용 종류·접힘 UI를 만들지 않는다. |
| 수식, Mermaid, Dataview/Templater 등 플러그인 코드 | 원문/코드 텍스트 | 수식·다이어그램·쿼리·템플릿을 실행하거나 전체 플러그인 호환을 약속하지 않는다. |
| 원시 HTML·SVG·MathML | 문자로 표시하거나 기존 정제 정책으로 거절 | 스크립트·스타일·iframe·폼·입력 요소를 허용하지 않는다. |

## 원문·편집·백업 보존

속성은 읽기용 투영이다. 저장 문자열에서 머리말을 제거하거나 YAML을 다시 직렬화하지 않는다. BOM·CRLF/CR·공백·정확 UTF-16 위치, 원문 해시·버전·기존 발췌/검색/이어 읽기·내보내기를 유지한다. 본문 블록은 속성 뒤의 원래 줄 위치를 사용하며 속성이 차지한 전체 원문 범위를 별도 앵커로 보관한다. 그 범위로 명시적으로 이동하면 속성을 펼치거나 정확 원문 보기로 돌아가야 하며 가까운 본문 위치를 만들어 대신 열지 않는다.

기존 **서식/원문 보기**, 자료 옵션의 **내 사본 수정 → 미리보기 → 새 판 저장 → 재열기**, 과거 버전·전체 자료 백업·선택 근거 보관을 재사용한다. 속성은 source의 제목/날짜/태그 필드를 자동 갱신하는 명령이 아니다. 원문에 적힌 가져오기·플러그인 명령도 현재 앱에 대한 실행 지시가 아니다. 별도 저장 스키마·마이그레이션·서버 쓰기를 추가하지 않는다.

## 파서 선택과 표시 경계

공식 후보 비교는 [오픈소스 검토](../life-tools-design/open-source-review.md#obsidian-yaml-속성과-원문-위치--2026-10-23)를 따른다. 일반 YAML 처리는 현재 공식 브라우저 UMD가 있는 **js-yaml5.5.0**의 공식 로컬 UMD를 채택했다. 정확 배포물·라이선스·해시는 `vendor/js-yaml` 기록에 남기고 CLI-only argparse와 브라우저 실행 의존성을 구분한다. YAML 해석과 문서 첫 경계/원문 앵커는 별도 책임이다.

`JSON_SCHEMA.withTags(realMapTag)`를 명시해 날짜를 JS `Date`나 실행 가능한 사용자 정의 객체로 바꾸지 않는다. 공식 `realMapTag`로 키의 실제 형식을 보존한 뒤 최상위 문자열 키와 제한된 스칼라/스칼라 목록만 표시한다. 안전하게 표현할 수 없는 큰 정수도 반올림된 속성으로 표시하지 않고 원문을 남긴다. alias0·merge0·중복 키 거절·깊이8, 머리말64 KiB·속성100개·전체 값1,000개·파서 이벤트4,096개를 제한하고 anchor·명시 tag·directive를 거절한다. 파서의 일반 YAML 지원을 모두 앱의 표시 권한으로 사용하지 않는다. 값은 `textContent`/정제된 제한 DOM으로만 넣으며 사용자 값으로 ID·style·이벤트 핸들러를 만들지 않는다. 기본 머리말·본문의 표·목록·안전한 링크는 기존 Markdown/DOMPurify 정책을 유지한다.

## 구현·로컬 검수 결과

정적22 HTML·162 JavaScript·690참조와 최종 전체 단위1,344개를 통과했다(실패·취소·skip·todo0). SourceMarkdown 집중17개와 가져오기/원문/선택 연결/편집/백업의 추가 보존3개, 기존 검사를 합친34개를 확인했다. 새 저장 스키마·서버 쓰기 없이 정확 원문·메타데이터·과거/수정 버전·기존 인용의 보존을 검수했다.

최종 SourceMarkdown `d64e841e18593a046cde5f3f5dc55816d3390fe8806bfc68506b82b11d53d20a`에서 실제 파일 가져오기·자료 읽기·정확 원문/인용·수정 미리보기·저장·재열기·백업의 **브라우저4흐름과 음성 대조15개**를 통과했다. 익명 FakeCloud Auth·실제 동봉 SDK·계정별 IndexedDB를 사용했고 콘솔/페이지 오류·외부 요청·개인 정보 유출·원격 쓰기는0이다. 속성 범위로의 이어 읽기, 제목/서식만 수정할 때의 BOM/CRLF 보존과 본문 수정 때의 새 LF 버전도 구분했다. 제품12파일과 검사 원형의 SHA는 실행 전후 동일하며 컨텍스트4개와 브라우저를 종료했다. 기존 자료실의 읽기/편집/휴지통/복원·실제 IDB 실패·두 탭 충돌 **3흐름도 통과**했다.

첫 전체 단위1,344개와 첫4흐름도 통과했지만 추가 반대 검수에서 두 구분선 사이의 제목·굵게/기울임·링크·코드를 YAML 오류로 오인하는 경우를 찾았다. 첫 의미 줄의 최대1,024자 키/흐름 매핑 판별을 오류 분류에 도입하고 공식 YAML `Map`만 속성으로 승인하도록 보완했다. 정상 스칼라/목록/null/빈 내용/주석과 일반 Markdown을 유지하는 최종 단위와 브라우저4흐름/15반례를 다시 통과했으며 최초 소스·영수증을 보존했다.

최종 브라우저 실행은 새 소스를 실제로 사용했다. 시각 자료는 이전1440/820/390px의3장과 당시 소스·원형 보고서를 유지하고, 이전/최종 소스의 정상 문서 전체 `prepare` 결과와3폭의 속성/잘못된 머리말 기하가 동일함을 검증해 **기존 캡처를 재사용했다(새 캡처0)**. 최종 소스/위치·안전성·재사용 근거와 그3장을 읽은 독립 검토의 판단은 **ship**, 검토 범위의 새P0/P1 차단은0이다. 새로운 캡처·독립 검토자의 브라우저 실행·실제 사용자 기기 확인으로 확대하지 않는다.

정확한 기준 main `2012ab4`의 이전 **SW157→158 PWA9/9**와 셸180개·설치 파일16개의 실제 해시를 확인했다. 새 YAML UMD, BOM/CRLF 속성이 있는 원문 seed·연간 계획·뉴스의 다섯 언어 설정·반응·과거 v3 읽기 판을 보존했다. 이 검사는 이전 SW만 과거 코드이며 앱 모듈과 합성 계정/입력은 현재 모듈을 사용해 이전 앱 전체를 재구축한 검사가 아니다. 엄격한 오프라인 Auth 차단과 로컬 보존을 구분하며 실제 Google·Apple 기기·운영 계정 확인은 포함하지 않는다.

정확한 최종 PR/main CI·공개 배포·실제 배포본의 결과는 [출시 기록](https://github.com/wonchance-art/life-haedo/pulls?q=is%3Apr+head%3Acodex%2Fobsidian-markdown-20261023)에 확정 후 갱신한다. 현재 로컬 완료를 해당 원격 검사·배포 완료로 읽지 않는다. 실제 사용자 기기·원래 개인 보관함 전체·Obsidian 플러그인 전체 호환·OS 파일 저장 성공은 자동 검수와 별도 미확인이다. 사용자의 실제 제목·속성 값은 추적 문서/fixture/화면에 넣지 않았다.

## 다음 큰 작업 묶음

1. **실제 Obsidian 문서 읽기부터 수정·재사용까지:** 이번 원인 교정이 사용자 보관함의 읽기 부담을 줄이는지 확인하기 위해서다. **선행:** 사용자가 직접 고른 대표 문서와 지원표에 없는 실제 문법, 해당 기기. **완료:** 읽기/속성→정확 원문·근거→수정·저장·재열기→백업/복원과 필요한 정적 문법 개선을 한 흐름에서 확인한다.
2. **내부 문서·첨부의 정확 연결 활용:** 위키 문법의 원문 보존과 실제 목적지 열기를 연결할 필요가 확인될 때 진행한다. **선행:** 보관함의 명시 파일 범위·기존 정확 버전 관계·사용자 연결 선택. **완료:** 동명이인 파일·헤더/블록 목적지·미확보 첨부를 구분하고 명시 연결·왕복·파일 보관/복구를 검수한다. 링크 모양만으로 자동 수집이나 다른 파일 연결을 켜지 않는다.

연간 계획의 구현·검수와 기존 뉴스/수집의 운영 한계는 [전체 로드맵](../life-tools-design/roadmap.md)에 보존한다.
