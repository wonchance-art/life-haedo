확인한 main은 `88ccfe5e381a37818a46e7abdaabfc48cff58c56`, 이전 공식 blog branch는 `f90777c835b726c42bbe213dff06c157e2c4623c`다. 이전 `/workspace/haedo-blog-platform`의 발견 기능 미커밋 원본은 현재 파일과 두 Git tree에 없었다. 원본 `/workspace/life-haedo`는 clean 상태를 유지했고 별도 `/workspace/haedo-discovery`의 `codex/discovery-interest-validation`에서 새로 조립했다. ## 실제 사용 범위

`npm run dev`로 실행한 뒤 로그인된 앱의 **도구 → 관심 확인**으로 이동한다. `index.html?section=tools&view=interests`와 기존 `life.html` 주소를 모두 지원한다.

1. 관심을 한 줄에 하나씩 입력하고 **관심 보관**을 누르면 이 계정·작업공간의 이 브라우저에 남는다. 다시 열어 같은 값을 확인한다.
2. 화면 내 이동은 미보관 입력을 메모리에 유지한다. **입력 되돌리기**는 미보관 입력·후보 선택을 저장 상태로 되돌린다. 계정/공간 변경·외부 이동 전 미보관 입력은 보관 또는 되돌리기를 요구한다.
3. 다른 탭이 먼저 보관하면 현재 입력을 덮지 않고 충돌을 표시한다. **최신 관심 확인**은 수정하지 않은 입력을 최신으로 갱신하고 실제 작성 중인 입력은 유지한다.
4. **관심 초기화**는 revision을 남기는 tombstone이다. 원문·글·사진·기존 구성은 지우지 않는다. 오래된 탭이 초기화 전 값을 다시 설치할 수 없다.

분석 선택 목록은 최신 본문이 있는 자료와 제외 수를 표시한다. 선택만으로 모델을 받지 않는다. 자동 분석은 `interest-policy.js`에서 비활성이고 실제 버튼도 비활성이다. 수동 관심의 보관과 실험 분석·사용자 확인은 별도 상태다. 외부 글 공급·추천·보관·피드백의 전체 발견 흐름은 이번 소스에 아직 재통합하지 않았다.

분석 모듈의 사용 흐름은 익명 모의 계정·명시 합성 벡터로 검수했다. 정확 인용·작성 관계·본문 확보 범위 → 원문 버전의 해당 구절 → 입력·초점 복귀 → 후보 선택 확인을 연결했다. 이 검수는 실제 모델의 의미 품질을 대신하지 않는다. 자료의 주제·질문을 사용자 신념이나 작성자 확정으로 바꾸지 않는다.

## 저장·수명주기 계약

- `InterestProfile`은 직접 입력과 모델 제안·확인 ID를 분리한다. 제안·확인 시 정확 버전, raw UTF-8 SHA, UTF-16 위치, 작성 관계·확보 범위를 대조한다. 같은 본문은 독립 지원 한 개로 계산한다.
- 기존 IndexedDB meta 안에 계정의 projectUrl/userId·workspaceId별 독립 revision으로 저장한다. 원문/구성 revision을 올리지 않으며 백업·서버 동기화·공개 payload에는 포함하지 않는다. 초기 복구는 관심 재입력·재생성이며 기기 이동 파일은 아직 없다.
- SHA 계산을 트랜잭션 밖에서 수행한 뒤 동일 쓰기 트랜잭션에서 선택 원문·hash·source·작성자·확보 범위를 snapshot과 다시 비교한다. CAS·256KiB 제한·tombstone을 적용한다.
- 모델은 전용 module Worker에 둔다. 명시 준비 전 Worker/모델 다운로드는 없으며 취소는 Worker를 종료한다. 늦은 메시지는 세대가 다르면 버리고 같은 논리 adapter는 새 Worker로 재준비할 수 있다.
- 공개 파일·고정 revision·GET만 사용하는 Worker 경로를 검증했다. 이 실험에서 본문 전송·`resolve/main` 요청은 0건이었다.

## 사전 고정한 48문서 비교

## 대체 모델의 기초 가능성

공식 한국어 NLI 학습·MIT·Transformers.js 모델/토크나이저/WASM 지원을 확인한 `onnx-community/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7-ONNX`의 revision `cdc8277b4682665e2f2e87cd83da7da07b153d75`를 별도 비교했다. q8 파일은 공식 metadata 기준 338,341,610 bytes다. 기존 48개와 다른 새 문장쌍 12개에서 premise/hypothesis만 모델에 보내고 세 logits의 argmax로 판정했다. 정답은 입력에 포함하지 않았다.

**12/12 정답, 부정 3/3·과거 인용 명령 3/3**으로 후속 가능성 기준을 통과했다. 준비 49.37초, 12쌍 추론 3.72초, 관측 JS heap 약 441MB였으며 전체 프로세스 RAM/최대치가 아니다. 입력은 41–72 tokens이고 절단·런타임 오류·본문 전송·가변 revision 요청은 0건이었다.

이는 짧은 원문·가설 쌍의 함의 판정만 검증했다. 관심/질문 후보 생성·장문·누락·저자 귀속·Apple 메모리·전체 추천 품질은 검증하지 않았고 앱 다운로드 모델도 바꾸지 않았다. [고정 manifest](evidence/interest-validation/nli-fixed-manifest.json), [사전등록](evidence/interest-validation/nli-preregistration.md), [결과·한계](evidence/interest-validation/nli-probe-report.md)를 따른다. 48문서 후보의 기각은 유지한다.
