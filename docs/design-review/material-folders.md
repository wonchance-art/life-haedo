# 자료실 가상 폴더와 분류

2026-10-23 KST · **자료실 → 폴더 만들기/정리 → 자료 한 개 또는 선택 자료 이동 → 폴더/검색으로 찾기 → 같은 자료 읽기·수정·목록 복귀 → 백업·새 사본 복원**을 하나의 흐름으로 연결한다. 사용자의 실제 문서 제목·폴더 이름은 추적 샘플/화면에 사용하지 않는다. 구현·검수 결과는 뒤의 상태 절에서 실제 영수증으로 확정한다.

## 목적과 기존 기능의 구분

기존 **주제**는 발췌/메모의 분류이고 **묶음**은 정확한 자료 버전의 연결이다. **컬렉션**은 책·음악 등 별도 대상 메타데이터다. 이번 **폴더**는 자료 원본의 ID에 연결한 한 개의 기본 분류다. 기존 주제·묶음·컬렉션을 폴더로 바꾸거나 새 폴더를 만들었다고 그 구성을 자동으로 생성하지 않는다.

가상 폴더의 이름과 계층은 원래 파일시스템 경로가 아니다. 이름 변경·상위 폴더 이동·자료 분류로 Obsidian 경로, sourceKey, 본문·BOM/CRLF·해시·버전·인용·정확 내부 링크를 바꾸지 않는다. 한 자료의 모든 버전은 같은 기본 폴더에 속한다. 내 사본 수정은 기존과 같은 source ID의 새 판을 만들므로 별도 복사/분류 승계 추정 없이 분류가 유지된다.

| 입력 | 자동 처리 | 결과 |
| --- | --- | --- |
| 폴더 이름·상위 폴더 | 이름·동일 형제·부모 존재·순환·전체 하위 깊이 검사 | 최대5단계의 가상 폴더 |
| 자료 하나 또는 선택한 정확 버전들, 목적 폴더 | 같은 자료 ID 중복을 합치고 현재 자료/분류의 CAS 확인 | 자료당 한 기본 폴더, 나머지는 미분류 |
| 폴더·검색어·원천·한글 띄어쓰기 보기 | 부모 선택의 하위 폴더를 포함하고 기존 검색 조건과 교집합 계산 | 정확 버전 결과와 기존 읽기/편집 왕복 |
| 공통 자료·구성 백업 | 원문/구성과 폴더를 함께 읽고 새 사본의 자료·폴더 ID를 정확 재매핑 | 분류까지 보존하는 새 작업공간 사본 |

## 만들기·이동·삭제·찾기

자료 목록의 작은 폴더 선택기와 접힌 관리 영역을 사용한다. 상시 사이드바나 카드마다 같은 폴더 설명을 추가하지 않는다. 폴더 만들기·이름 변경·상위 이동은 같은 인라인 폼에서 처리하고 자료의 이동은 목적지를 확인해 명시 제출한다. 여러 판을 선택했더라도 같은 원본은 한 번만 분류한다.

- **전체 / 미분류 / 폴더:** 분류가 없는 자료가 미분류다. 상위 폴더 선택은 하위 전체를 포함하며 기존 검색어·원천·띄어쓰기 조건과 함께 적용한다. 검색은 여전히 정확한 자료 버전별 결과다. 폴더별 조건을 바꿨을 때 더보기 범위를 다시 계산하고 읽기/수정 뒤에는 같은 폴더·검색·결과 문맥으로 돌아간다.
- **상위 폴더 이동:** 자기 자신·자손으로 이동, 없는 상위 폴더, 순환, 이동할 하위 전체가5단계를 넘는 경우를 거절한다. 같은 상위 아래의 이름은 NFC 정규화와 소문자 비교로 중복을 막는다. 최대200폴더이며 이름은 공백 정리 후120 UTF-16 단위 이내, 제어문자·경로 구분자를 허용하지 않는다.
- **폴더 삭제:** 자식이 있는 폴더는 자식을 먼저 이동해야 한다. 자식 없는 폴더를 삭제하면 그 폴더와 직접 분류 정보만 없애고 자료는 **미분류**로 남긴다. 폴더 삭제와 자료 휴지통 이동을 같은 동작으로 표시하지 않는다.
- **자료 휴지통/복원:** 휴지통 자료는 활성 목록과 개수에서 제외하지만 폴더 분류는 유지한다. 같은 자료를 복원하면 원래 폴더에서 다시 찾을 수 있다. 분류만 바꿀 때는 원문/구성 revision을 올리거나 자료 버전을 새로 만들지 않는다.
- **사라진 참조:** 계정 수신/조회 중 원래 자료가 일시적으로 보이지 않아도 기존 분류를 삭제하거나 제목·파일명으로 다른 자료에 붙이지 않는다. 관리에서 확인할 수 없는 참조를 알리고, 새로 없는/다른 공간 자료를 분류하거나 그 상태를 유효한 통합 백업으로 설치하는 것은 거절한다.

전체 분류 상태는 UTF-8 기준2 MiB·자료 연결20,000개 이내로 제한한다. 선택 이동은 한 번에 자료 ID200개까지다. 한도 초과를 오래된 분류의 자동 삭제로 해결하지 않는다.

## 로컬 저장·충돌·백업

폴더는 계정·작업공간별 **별도 로컬 메타데이터**다. 기존 Storage의 계정 확인·소유자·같은 IndexedDB 트랜잭션·CAS·최소 변경 방송 패턴을 재사용한다. 새 원격 동기화·게시·DB 스키마를 추가하지 않는다. 동시 탭 충돌은 입력을 유지한 채 최신 분류 확인 후 사용자가 다시 제출하며 자동 재적용/덮어쓰기로 해결하지 않는다. 실패/늦은 응답이 이전 저장 그래프를 바꾸거나 다른 계정/공간에 영향을 주지 않게 한다.

**공통 자료·구성 백업**은 분류가 있을 때 `life-material-library-backup-v1` 외곽에 기존 Workbench 백업과 폴더를 넣는다. 원문·구성·분류는 같은 저장 스냅샷에서 읽고, 폴더가 없는 사용자의 기존 백업 형식은 그대로 유지한다. 분류가 있는 상태를 조용히 빼서 성공 백업으로 내보내지 않는다. 기존 자료/구성 형식 자체와 원격 payload는 바꾸지 않는다.

새 외곽과 기존 Workbench 백업을 모두 읽는다. 복원은 기존 검증·원문 해시·정확 판 재매핑을 재사용한 **새 공간 사본**이며 자료·구성·폴더를 원자적으로 설치한다. 폴더도 새 ID를 받고 부모 관계와 기본 분류를 검증된 원본→사본 대응으로 옮긴다. 이름·경로가 비슷하다는 이유로 재매핑하지 않는다. 구형 백업은 빈 폴더 상태로 받는다. 비동기 복원 중 호출자가 파일 객체를 바꿔 다른 자료/분류가 설치되지 않게 입력 스냅샷을 보존한다.

기존 **자료 전용 백업**은 계속 원문/발췌 중심이며 폴더·기타 구성을 포함하지 않는다. 공통 백업과 그 범위를 해당 조작에서 구분한다. 기존 복구/초안 사본·사진 ZIP·선택 근거 파일을 이번 분류 전체 백업으로 바꾸지 않는다. 로컬 분류가 기기 간 자동으로 따라온다고 표시하지 않는다.

## 구현 선택과 검수 기준

[공식 후보2개 검토](../life-tools-design/open-source-review.md#자료실-가상-폴더와-기존-cas-재사용--2026-10-23) 뒤 새 트리 프레임워크보다 기존 Core 자료 목록·정확 버전·읽기/수정·Storage CAS/백업 패턴과 네이티브 선택/목록을 재사용한다. Workbench의 `versionIds` 묶음을 폴더로 재명명하거나 jQuery·트리 위젯·드래그 전용 인터페이스를 새로 넣지 않는다. 파일 이동·가져오기 어댑터·플러그인 실행과도 분리한다.

## 구현·로컬 검수 결과

정적22 HTML·164 JavaScript·699참조와 전체 단위1,367개를 통과했다(실패·취소·skip·todo0). 통합 후 동결한19파일은 보존됐으며 원문·해시·과거 판·인용·주제·묶음·뉴스/연간 계획과 다른 설정을 폴더 변경으로 다시 쓰지 않는다.

실제 동봉 SDK·계정별 IndexedDB와 익명 FakeCloud Auth의 **새 분류 브라우저4/4**에서 하위 포함 분류, 같은 자료의 두 판 본문 검색과 정확 판 초점/원문 선택·필터/원천/검색/스크롤 복귀, 선택한 여러 판의 source ID 중복 제거, 자식 없는 폴더 삭제와 미분류, 휴지통/복원, 같은 source ID 수정·공통 백업/신규 ID 재매핑·구형 백업, 두 탭 CAS 입력 유지/최신 확인/명시 제출, 실제 IDB 트랜잭션 중단 뒤의 명시 재시도를 확인했다. 콘솔/페이지 오류·외부 요청·개인 정보 유출·원격 쓰기는0이며 검사 원형과 보조 파일은 전후 동일하다. 컨텍스트4개와 브라우저를 종료했다.

기존 자료실 **3흐름**, Obsidian **4흐름/15반례**, 공통 Workbench 백업의 정상 복원·잘못된 후보 교체·대기 중 복원 경계 **3흐름**도 통과했다. 정확 원문·BOM/개행·과거/수정 판·인용과 그룹 관계를 보존하며 무효 후보나 충돌을 정상 설치로 표시하지 않는다.

정확한 기준 main `8c62d8e`의 이전 **SW158→159 PWA9/9**, 셸183개·설치 파일19개의 실제 해시와 폴더2개/분류1개의 보존을 확인했다. 기존 연간 계획·뉴스의 다섯 언어/반응·과거 v3 읽기 판도 유지했다. 이전 SW만 과거 코드이고 앱 모듈·폴더/기타 입력은 현재 모듈의 합성 로컬 계정 API를 쓰는 업데이트 검사다. 이전 앱 전체 재구축·실제 계정·Google/Apple·외부 수집 성공으로 확대하지 않는다. 검사 소유 서버/프로세스와 브라우저는 정리했다.

1440/820/390px의 새 폴더 화면3장을 기록했고 root가 모두 직접 확인했다. 각 문서 폭은 뷰포트와 일치하며 네이티브 선택/입력/버튼의44px 조작·접근 가능한 이름·초점과 실제 포인터 도달을 확인했다. 최종 소스와 같은3장을 직접 읽은 독립 검토의 판단은 **ship**, 검토 범위의 새P0/P1 차단은0이다. 독립 검토자가 새 브라우저 실행/캡처를 추가한 것은 아니며 기존 최종 실행 증거와 그 화면에 대한 읽기 전용 검토다. 실제 기기의 터치·키보드·분류 효용은 별도다.

첫 신규 브라우저2건의 실패는 검증 보조 함수가 원문 요소에 초점을 주지 않은 문제와, 제목 검색이 최신 한 판을 반환하는 기존 정책에서 두 판을 기대한 합성 조건이었다. 동일 raw 상태·Range 및 Core 검색 정책/DOM 진단으로 원인을 구분한 뒤 focus 한 줄과 두 판에 공통인 실제 본문 검색어로 fixture를 보완했다. 제품 코드는 바꾸지 않았으며 원래 단언·15초 제한과 첫 증거를 유지한 최종4흐름이 통과했다.

기존 Workbench의 ‘요청0’ 검사는 정확한 기준 배포 artifact에서도 각 흐름의 소유자 필터가 있는 본문 없는 계정 자료 GET3회로 동일하게 실패했다. 허용하는 조회의 owner/method/body를 확인하고 실제 작업공간 자료 다운로드·쓰기0을 검사하도록 원형을 갱신한 뒤 정상/무효/대기 복원3흐름을 통과했다. 조회 허용을 임의 자료 접근·전송 허용으로 바꾸거나 기능 단언/제한시간을 낮추지 않았다. 최초 실행과 기준 배포본 재현은 보존했다.

정확한 PR/main CI·공개 파일/실제 배포본의 확정 결과는 [출시 기록](https://github.com/wonchance-art/life-haedo/pulls?q=is%3Apr+head%3Acodex%2Fmaterial-folders-20261023)을 따른다. 현재 로컬 완료를 원격 검사·공개 배포 완료로 읽지 않는다. 실제 사용자 보관함/기기의 전체 분류 흐름·OS 파일 저장·기기 간 폴더 동기화·위키/첨부 목적지 완주는 이번 합성/로컬 검수로 완료했다고 표시하지 않는다.

## 다음 큰 작업 묶음

1. **실제 자료 분류부터 읽기·수정·재사용까지:** 새 분류가 대표 자료를 다시 찾고 활용하는 부담을 줄이는지 확인하기 위해서다. **선행:** 사용자가 직접 고른 대표 자료/폴더·검색 장면과 주 기기. **완료:** 분류→검색/정확 원문→속성/본문 읽기→수정·저장·재열기→같은 폴더 복귀→공통 백업/복원을 끝내고 필요한 개선만 채택한다.
2. **내부 문서·첨부의 정확 연결 활용:** 분류 위치와 원래 위키/파일 목적지의 연결이 필요한 실제 장면을 이어가기 위해서다. **선행:** 명시 보관함 범위·기존 정확 버전 관계·사용자 연결 선택. **완료:** 동명 파일·헤더/블록 목적지·미확보 첨부를 구분하고 명시 연결·왕복·파일 보관/복구를 확인한다. 폴더만 만들었다고 내부 링크 목적지 해결이나 미디어 확보를 완료한 것으로 표시하지 않는다.

Obsidian의 속성·정확 원문·수정/백업은 이미 구현된 기반이며, 실제 개인 보관함/기기의 전체 완주와 플러그인/첨부 호환은 여전히 별도다. 이전 기능 상태는 [전체 로드맵](../life-tools-design/roadmap.md)에 보존한다.
