# 선택한 글쓰기 초안 이어쓰기

2026-10-06. 디자인·통합 책임 root. 로컬 글쓰기는 유지하면서 **선택한 글 한 편**을 다른 기기에서도 이어 쓴다. 새 프레임워크나 동기화 엔진을 도입하지 않고 구성 동기화의 CAS·재시도·계정 수명 처리를 도메인 어댑터로 재사용했다. [오픈소스 판단](../life-tools-design/open-source-review.md)과 [Local 일괄 설치](../life-tools-design/continuity-batch-installation.md)를 따른다. 운영 SQL 설치·공개 배포·실제 Apple 기기 확인은 아직 완료하지 않았다.

## 직접 이어 쓰는 흐름

1. A에서 원문 작업공간을 연결하고 글쓰기의 제목·본문을 쓴다. 자동 보관은 먼저 기기에 한다.
2. 본문 아래 `초안 이어쓰기`를 펼쳐 **이 초안 이어쓰기**를 시작한다. 이후 새로 만든 다른 글은 자동으로 연결하지 않는다.
3. B에서 같은 원문 작업공간을 받은 뒤, 글쓰기 → `다른 기기의 초안 찾기` → 원하는 글을 선택한다. 선택 수신은 그 글의 연결을 시작하며 목록에도 이를 설명한다. 목록은 100개씩 조회한다.
4. 동시에 바꾼 글은 제목·전체 본문을 비교한다. 어느 쪽을 골라도 다른 쪽은 **새 미연결 초안**으로 먼저 보관한다. 초안 목록에서 다시 열고 TXT를 받을 수 있다.
5. `저장`을 직접 누를 때만 원문 버전과 `applied` 종료 상태를 같은 로컬 트랜잭션에 만든다. 원문이 서버에 도착한 뒤 초안 종료를 보낸다. 공개 페이지는 바뀌지 않는다.

초안 백업은 TXT이며 원문·구성 백업이 미완성 글을 포함한다고 표시하지 않는다. 종료 상태와 다른 입력이 충돌하면 같은 ID를 다시 초안으로 바꾸지 않고 다른 입력을 새 글의 초안으로 남긴다. 연결을 중지한 뒤 기록으로 저장한 경우에도 새 글쓰기의 `저장 완료 전송 확인` 목록에서 해당 건을 열어 **저장 완료 상태 이어쓰기**를 재개할 수 있다. 미연결 초안을 저장한 것만으로 이 목록/전송에 추가하지 않는다.

## 보존과 실패 계약

- 제목·본문·수정 기준·시간이 있는 기존 Writing v1을 재사용한다. `source_revision`과 더불어 완료된 원문의 정확한 source/version 쌍을 확인한다. 클라이언트는 원문 종류·본문 일치도 검증한다. 도착하지 않거나 다른 쌍은 보존 오류이며 최신 버전으로 치환하지 않는다.
- outbox의 operation ID·본문·비교 revision을 고정한다. 유실 응답은 새 서버 읽기보다 먼저 같은 요청을 재전송한다. 완료된 서버 초안에 새 쓰기는 거부하고 과거 성공 영수증만 같은 성공을 반환한다.
- 일반 초안 충돌은 선택과 다른 쪽 복구를 같은 IndexedDB 트랜잭션에서 처리한다. 복구 저장 실패·낡은 비교는 현재 글을 대체하지 않는다. applied가 어느 쪽에 있든 종료 상태를 보존하며 다른 글은 새 ID로 복구한다.
- 원문 동기화가 중지/충돌/미완료이면 초안 전송·수신을 성공으로 표시하지 않는다. 같은 초안을 A/B에서 오프라인으로 각각 기록 저장하면 서로 다른 로컬 원문이 생길 수 있다. **전역 한 번 저장을 보장하지 않는다.** 기존 원문 CAS 충돌에서 양쪽을 보존하고 정확한 종료 참조가 도착하기 전에는 완료 처리를 보류한다. 임의 중복 합치기/삭제는 하지 않는다.
- 원격 알림은 현재 편집기를 다시 렌더하지 않는다. 새로 받은 내용 열기나 입력 사본 보관은 명시 조작이다. 입력 중 DOM/value·caret·한글 composition을 유지한다. 저장소 응답의 stage ID·요청 순서·계정 세대가 다르면 이전 알림을 버린다.
- 중지는 이후 전송을 멈춘다. 이미 서버가 수락한 전송이나 서버 사본을 삭제하지 않는다. 중지 중 멈춘 요청의 완료를 기다리지 않고 다시 연결할 수 있다. 연결된 초안의 로컬 삭제는 대기 전송/영수증을 없애지 않도록 차단한다.

## 화면 판단

본문·제목·기존 저장 조작을 우선하고 새 조작은 접힌 하단 영역으로 제한했다. 옅은 라벤더 강조, 기존 타이포그래피·44px 조작·A 아이콘을 유지한다. 비교에서는 한 열로 두 본문을 펼쳐 읽고, 내부 스크롤과 초점을 보존한다. 읽기/피드/공개 사본 표면은 추가하지 않았다.

긴 제목은 기존 한 줄 편집 input의 가로 스크롤을 사용한다. 좁은 화면에서 전체 제목이 동시에 보이지 않는 한계는 유지되며 저장 값은 잘리지 않는다. 비교 화면에서는 같은 제목을 줄바꿈해 표시한다. 전체 페이지 이미지의 고정 하단 메뉴는 화면 높이 기준으로 합성되며 전체 문서 바닥이 아니다.

## 검사 범위

- 정적 검사 HTML 17 / JS 50 / 참조 249 / PWA 통과. Node 300 통과(원격 어댑터 10조건 포함).
- 실제 IndexedDB/BroadcastChannel의 새 초안 저장 17조건 통과. 기존 구성 저장 13조건, 관련 Node 76조건 통과. 실제 UI의 기존 직접 글쓰기 12/12, 3폭 9상태, 예상 외 console/pageerror 0.
- 새 두 브라우저 시나리오는 선택 연결·다른 초안/가져오기 제외·양쪽 복구/TXT·응답 유실·중지/재개·계정 전환·IME DOM 보존·기록 저장 종료·100개 목록·중지 후 종료 전송 재개를 확인한다. **전체 10/10, 8상태×3폭 24캡처**, 예상 외 console/pageerror·외부 요청·운영 쓰기 0으로 확인했다. 첫 9사례 중 하네스의 비동기 UI 완료 대기 2곳을 보완했고, 후속 paused/applied 사례를 더한 최종 10개 전체를 다시 통과했다.
- 독립 비동기 알림 회귀 2/2: 실제 Chromium DOM과 실제 Writing 모델, 지연을 제어한 메모리 저장소. stage ID/순서 가드를 제거한 부정 대조 0/2로 두 경합을 재현했다. 이를 실제 IndexedDB나 Apple IME 결과로 주장하지 않는다.
- PWA 9/9: 보존한 v69 산출물에서 v70으로 캐시를 지우지 않고 갱신해 기존 자료·가져오기 초안·연표 키와 새 모듈의 해시를 대조했다. 의도한 전송/콜백 실패 2건과 예상 외 오류를 구분했다.
- 격리 PostgreSQL 17.11: 역할/RLS/RPC·형식·terminal·원문 쌍 159조건, 설치 메타데이터 9조건, 실제 동시 트랜잭션 6조건 통과. 첫 설치/재설치에서 기존 구조·권한·자료를 보존하고 컨테이너를 정리했다. HTTP 검사기의 모의 경로 5조건 통과. 운영 SQL/HTTP는 실행하지 않았다.

로컬 브라우저는 Playwright 1.63.0 / 시스템 Chromium 151.0.7922.173이다. CI는 저장소에 고정한 Playwright/Chromium을 사용한다. 모의 Auth/HTTP, 화면 폭 검사는 실제 Google 로그인·운영 authenticated 쓰기·Mac/iPad/iPhone 실기·Files/VoiceOver·장기 사용 평가를 대신하지 않는다.
