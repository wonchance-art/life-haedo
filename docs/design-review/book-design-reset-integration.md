# 원고 중심 A안 실제 앱 적용

2026-10-09 KST · 디자인 책임자 root · 병합·배포는 Local 담당

사용자가 [비교 시안](book-design-reset.md)에서 **A · 원고 중심**을 선택한 뒤 실제 책 작업실에 적용했다. 원고 앞에 누적되던 설정·보관·출력 조작을 옮기고, 책 선택 → 읽기 → 보이는 장 집필 → 읽던 문단 재확인을 같은 한 열로 연결했다. 기능 확장이나 저장 형식 변경은 없다.

## 직접 체험

해당 브랜치로 실행한 앱에서 **도구 → 내 책**으로 들어간다. 주소는 `index.html?section=tools&view=books`다. 기존 개인 자료를 테스트 샘플로 덮지 않는다. 격리된 테스트 계정/브라우저에서는 [익명 네 장 백업](evidence/book-edition/reader-book-backup.json)을 관리의 자료·구성 백업에서 **새 사본으로 복원**해 같은 장면을 체험할 수 있다.

1. 목록의 책 제목 또는 **전체 읽기**로 원고를 읽는다. 편집 아이콘과 목록 목차는 기존처럼 집필로 들어간다.
2. 상단 목차에서 장을 고른다. **집필**은 고정 도구 모음 아래 화면을 가장 넓게 차지하는 장을 열며, 각 장 옆 편집 아이콘으로 대상 장을 정확히 지정할 수도 있다.
3. 장 제목과 본문은 문서처럼 늘어난다. 입력창 내부와 페이지를 따로 스크롤하지 않는다. 상단 **읽기**로 전환했다가 같은 장에 돌아오면 커서·보던 위치를 복원한다.
4. 인용 아이콘은 해당 장의 근거를 펼친다. 원문·내 해석은 원고와 별도이며 정확한 원문 버전과 작성 관계를 유지한다.
5. 상단 설정 아이콘은 원고 아래 책 설정·개정본·파일로 이동한다. 읽기 화면의 다운로드 아이콘은 점검·파일·인쇄 영역으로 이동한다. 저장 실패 때는 입력을 유지하며 전환을 막는다.

## 적용 범위와 선택 이유

- 흰 본문, 옅은 자주색 조작, 한글 산세리프와 680px 읽기 열. 집필 제목 32/27px, 본문 19/17px(넓은 화면/390px), 본문 행간 1.95/1.9.
- 목록은 실제 첫 문단을 최대 200개 코드포인트까지 미리 보여준다. 이 화면용 요약은 원고·내보내기를 자르지 않는다. 한 권·여섯 장 이하는 목차를 기본 펼친다.
- 집필/읽기의 상단은 작은 탐색·저장 조작만 유지한다. 모바일의 전역 dock는 집중 화면에서 접히며 책 목록으로 돌아가면 다시 보인다.
- 시안의 모든 위치를 복제하지 않았다. 기존 관리·개정본·가져오기 조작을 유지하기 위해 아래 보조 영역을 사용한다. 네이티브 details·textarea와 기존 아이콘을 재사용했다.
- [공식 제품·오픈소스 비교](book-design-reset-references.md)는 구조와 읽기 경험의 참고다. 편집기·Markdown 파서·프레임워크를 추가하지 않았다. 기존 Books.project와 평문 렌더링으로 필요한 범위를 해결할 수 있고, 새 편집기는 IME·저장·정확 버전 복귀의 추가 유지 비용을 만든다.

## 보존과 발견한 수정

`Books.project`, Markdown/책자 HTML/PDF 생성, 원문·버전·UTF-16 위치, 저장/계정/CAS/백업/공개 모델은 변경하지 않았다. 서비스워커 캐시만 v88로 갱신한다. 이번 변경에 SQL은 필요 없다.

자동 높이 계산 때 textarea를 잠시 축소하면 문서 스크롤이 위로 이동하는 문제를 실제 긴 원고에서 재현했다. 계산 전후 페이지 위치를 보존하고, 읽기/가져오기 복귀에서는 입력창의 화면상 위치도 복원한다. 장 제목은 여러 줄로 **표시**하되 기존 단일 행 값 계약을 유지한다. 한글 조합 중 정규화·이동을 강제하지 않는다. 늦은 조합 종료·폰트·폭 변경은 현재 연결된 화면에서만 처리한다.

목차 이동 후 이전 장의 남은 여백 때문에 상단 집필이 앞 장을 고르던 결함도 수정했다. 고정 Y좌표 비교 대신 실제 보이는 면적을 사용하며, 목차 → 두 번째 장 → 집필 → 해당 장의 커서/위치 복귀를 회귀 검사에 남긴다.

## 검증과 한계

정적 검사(HTML 18/JS 59/참조 271/PWA)와 Node 398/398이 통과했다. 기존 경계 회귀 18/18, 새 장문 입력·복귀 3/3을 확인했고, 읽기 6개는 마지막 경계 수정 후 다시 통과했다(중복 합산하지 않음). [실제 앱 화면 모음](evidence/book-design-reset/app/index.html)에서 목록·집필·읽기를 비교할 수 있다.

기능 검사는 저장 실패·충돌·계정 전환·정확 버전·백업·출력 경계를, 시각 검토는 같은 익명 네 장 자료의 목록·집필·읽기를 각각 판단한다. 실행 시점·범위와 최종 증거는 위 QA 문서를 따른다. 비교 시안의 저장 모사 검사를 실제 앱 검사에 합산하지 않는다.

1440·820·390px Chromium 브라우저 크기 검증이다. 실제 개인 자료, iPad/iPhone의 소프트 키보드·IME·Files, Safari/WebKit, 실제 VoiceOver는 이번에 확인하지 않았다. 합성 composition 이벤트는 실제 Apple 한글 조합 체험을 대신하지 않는다. 공개 배포·실 Google 재로그인·운영 동기화 검증으로 보고하지 않는다.

## Local 인계

2026-10-09 Local 진행과 실제 기기/대체 검증의 구분, 선행 SQL 설치 결과는 [A안 Local 통합 검증](book-device-release-qa.md)을 따른다. 아래 목록은 원래 Cloud 인계 당시의 조건이다.

1. 이번 브랜치는 `codex/book-restore-entry`의 PR #54 위에 쌓았다. #54의 선행 #53과 #52를 포함해 실제 병합 상태를 확인하고 의존 순서대로 검토한다. 기존 PR을 이미 병합했다면 중복 병합하거나 SQL을 다시 설치하지 않는다.
2. 초안 PR의 마지막 head에서 `check`와 `browser` 결과를 확인한다. Cloud는 main 병합·Pages 배포·운영 SQL을 실행하지 않는다.
3. 실제 기기에서 목록 → 장 집필 → 긴 한글 조합 → 읽기/목차 → 같은 장 복귀 → 근거 열기 → 개정본 복원 → 파일 받기를 체험한다. 계정별 백업을 먼저 보존하고 익명 자료 또는 명시 선택한 자료만 쓴다.
4. 배포 후 v88 자산 적용과 저장 실패/오프라인 알림, 모바일 키보드 가림·안전 영역·다운로드를 확인한다. 기존 동기화/게시 범위가 자동 확장되지 않았는지도 확인한다.

다음 우선순위는 실제 Apple 기기의 장문 집필 체험이다. 사용 중 끊기는 경로가 발견되면 먼저 수정하고, 그다음 책 작업실 밖의 자료 검토 → 장 구성 진입도 승인한 A의 본문 우선 기준으로 연결한다.
