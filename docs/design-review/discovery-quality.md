# 뉴스 공급·추천 근거·직접 읽기 비교

2026-10-21 KST. 뉴스에서 같은 조건의 목록을 비교하고 직접 판단을 보관하는 흐름과, 확인된 어휘·추천 근거 문제를 함께 개선한다. 기존 뉴스 → 링크 자료 → 글 저장·재열기 → 뉴스 복귀도 보존한다. 실제 읽기 판단을 자동 생성하거나 합성 검수로 추천 효용을 확정하지 않는다.

## 확인한 문제와 선택

직전 공개 공급 `dcaed2da515c138fa7d4b41159c8a59a3035cf4d66867d12164959a41cb25c24`의 같은 시각·빈 제외 조건에서 전체90/한국어50/영어40개를 확인했다. 긴 관심 문구는0개, `언어`는 제목1개, `Language`는8개, `Linguistics`는20개와 일치했다. 마지막20개는 모두 MIT의 공식 태그와 일치한 것으로 제목 의미·실제 도움의 증거는 아니다. `Language`는 단백질 언어 모델도 포함한다. 복수형·의미만 비슷한 표현과 긴 설명은 현재 정확 문자열 정책이 놓칠 수 있다.

- **좁은 용어 연결:** 검토한 `언어학 ↔ linguistics`만 기존 공개 동의어에 추가한다. 예시 버튼도 명시 클릭으로 추가하며 사용자의 긴 관심 설명을 언어학으로 바꾸거나 자동 관심을 저장하지 않는다. 번역 언어와 콘텐츠 언어는 별도다.
- **정확한 단어 경계:** 보조 평면 유니코드 문자 내부를 단어 경계로 오인하던 부분을 code point로 확인한다. 근거 위치는 기존 UTF-16 구간이다.
- **추천 근거 부풀림 제거:** 기관명 태그 한 개가 여러 단어로 분해돼 최소 공통 표현 수를 충족하던 반례를 고친다. `public-title-tag-expressions-v2`는 제목 단어와 태그 전체 표현을 사용하고 같은 표현·동의어를 한 번만 센다. 태그 하나만 공유하면 기존 기본 순서로 돌아간다. 점수는 규칙값이며 문맥·찬성·효용 확률이 아니다.
- **공급:** 공식 선언 RSS·robots·메타데이터·권리를 확인한 Language Learning & Technology를 언어교육 동료심사 연구 출처로 추가한다. 날짜·저자·태그가 없는 RSS 값은 null/빈 배열이며 발행일이나 언어학 태그를 만들지 않는다. 실용 조언의 품질을 보증하지 않는다. Cambridge ELT는 공식 약관의 수집·저장 제한 때문에 채택하지 않는다. D2의 robots 리디렉션은 우회하지 않고 Woowa의 한 번 회복과 지속 운영 성공을 구분한다.

일반 검색·추천 서버나 모델을 도입하지 않는다. 기존 Discovery/Recommendations·Actions metadata snapshot·Storage의 계정별 IDB/CAS·네이티브 폼/링크와 제한 RSS 수집기를 재사용한다. 같은 URL의 대표 행을 고르는 기존 정책과 복수형/의미 확장까지 이번 수정의 개선 효과로 합산하지 않는다.

## 한 번에 사용하는 흐름

뉴스 목록 아래 **읽기 비교**를 펼친다. 주제·언어·옵션의 미저장 입력을 해결한 뒤 **현재 조건으로 비교 시작**을 누른다. 같은 공급·시각·유효 주제·출처·언어·보관/제외 조건으로 최신순·관심순의 상위2개를 고정하며 개인 추천은 기존 opt-in 때만 계산한다. 중복 글은 한 번만 평가하고 합집합은 최대6개다. 후보가 없거나 같은 기본 목록이면 그대로 표시한다.

글 제목의 읽기 전 의향, 명시적으로 연 원문의 읽은 범위, 읽은 뒤 도움 여부와 선택적 이유를 저장한다. 읽은 범위를 선택하기 전에는 실독 후 도움을 입력할 수 없다. 원문·번역 링크는 명시 클릭에만 열리고 팝업/체류로 읽기·도움을 채우지 않는다. 번역은 비교 당시 조건과 현재의 저장된 번역 설정이 일치할 때만 제공하며 전역 끄기를 즉시 반영한다.

같은 비교를 다시 열어 판단과 목록 선호를 수정하거나 삭제한다. 현재 비교는 한 개만 보관하며 새 비교는 기존 비교를 명시 삭제한 뒤 만든다. 공급·제목·설정이 바뀌어도 기존 글 스냅샷과 응답을 새 비교로 옮기지 않는다. 정렬명의 고정 노출·소수 표본은 무작위 실험이나 인과 효과 검증이 아니다.

## 저장과 실패 복구

평가는 `discoveryReading`의 계정·작업공간별 독립 메타 행이다. 기존 반응·관심·읽음 제외·자료·글·구성 백업·공개·서버 동기화와 분리한다. 제목/URL/출처/권리 등의 링크 메타데이터와 비교 조건·명시 응답만 보관하며 본문·자유 메모를 수집하지 않는다. 좋아요·담기·읽음·도움·목록 선호가 서로를 자동 생성하거나 개인 추천 opt-in을 바꾸지 않는다. 모델·서버 학습으로 전송하지 않는다.

명시 저장은 revision CAS를 사용한다. 실패 시 입력과 의도를 보존하고 재시도·입력 취소를 제공한다. 다른 탭과 충돌하면 최신 내용을 확인한 뒤 같은 세션에만 다시 적용한다. 삭제는 revision과 tombstone을 유지해 늦은 쓰기가 비교를 재생성하지 못하게 한다. 계정·작업공간·탐색 세대·원격 revision의 늦은 결과는 이전 화면에 적용하지 않는다. 손상된 행을 빈 평가로 덮어쓰지 않는다.

브라우저의 `rankInputSHA256`은 정규화된 평가 입력의 해시다. 원본 공개 파일 bytes의 SHA라고 부르지 않는다. 기존 CLI는 과거 좋아요 URL을 네 비교군의 known 제외에 합치는 별도 평가 정책을 유지한다. 앱 비교는 현재 UI의 실제 known 조건을 사용하므로 둘을 완전히 같은 화면 재현이라고 주장하지 않는다.
