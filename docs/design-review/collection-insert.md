# 컬렉션 정보를 글과 내 페이지에 넣기

2026-10-12 UTC. PR #69의 선택창을 글쓰기와 내 페이지에서 재사용한다. 이번 결과는 **선택한 제목·창작자·출처의 텍스트 사본**이다. 앨범 카드·임베드·컬렉션 ID에 연결된 자동 갱신 첨부를 구현했다고 표현하지 않는다.

## 직접 체험

`npm run dev` → 로그인 → 기록에서 다음 순서로 확인한다.

- 글쓰기 (`index.html?section=records&view=write`): 본문에 커서를 놓고 하단 북마크 아이콘 **컬렉션 정보 넣기** → 항목 선택 → 넣을 정보 확인 → **본문에 넣기**. 선택한 문장을 지우지 않고 선택 끝 위치에 추가한다. 바로 **정보 넣기 되돌리기**도 가능하다. 초안은 기존 방식으로 보관되고 **기록에 저장**이 불변 원문 버전을 만든다.
- 내 페이지 (`index.html?section=records&view=page`): 북마크 아이콘 → 항목 선택 → **페이지에 넣기** → 항목 편집·숨기기·고정·순서 변경 → **방문자 미리보기**. 별도 항목으로 보관되며 공개 사본 갱신은 기존 명시적인 공개 검토·게시 과정이다.
- 검색은 내 컬렉션, 외부 조회는 기존 YouTube·GitHub 링크 조회다. 없는 대상은 직접 입력 후 검토할 수 있다. 검토 화면에서 정보를 고쳐도 컬렉션 원본은 바뀌지 않는다. 새 입력을 컬렉션에 자동 등록하지 않는다.

## 설계와 보존 계약

현재 글쓰기의 불변 원문은 일반 텍스트, 페이지 항목은 원문 참조와 코멘트다. 이를 재사용하면 출처 정보를 넣은 후 기존 편집·TXT·백업·이어쓰기를 그대로 쓸 수 있다. 이 단계에서 첨부 객체를 추가하면 글쓰기 초안/원문/구성/공개 각각의 저장·동기화 계약을 동시에 바꿔야 한다. 따라서 텍스트 삽입임을 선택 확정 전에 알리고, 구조화된 첨부는 후속으로 분리했다. 이미지형 피드를 완성한 것으로 평가하지 않는다.

- **선택 → 검토 → 확정** 전에는 저장하지 않는다. 검토는 기존 native dialog 선택창과 공통 스타일을 재사용한다. 후보 조회·저장·공개를 같은 행동으로 묶지 않는다.
- 허용한 정보는 종류·제목·창작자·출처뿐이다. 개인 메모·주제·권리 메모·내부 ID·계정 식별자는 복사하지 않는다. 채널/저장소 소유자를 아티스트/저자로 추정하지 않는다. `참고한 항목`이라는 표시를 둬 인용 정보와 작성자의 문장을 구분한다.
- 글에는 본문 중간 또는 끝에 정보를 넣는다. 원래 선택 구간을 덮어쓰지 않고 UTF-16 서로게이트도 자르지 않는다. 삽입 이후 추가 편집이 없을 때만 직전 삽입을 되돌린다. 기존 불변 버전과 발췌 위치는 변경하지 않는다.
- 페이지에는 표준 항목의 title/note를 사용한다. 원문 복제·가짜 발췌를 만들지 않으며 제목은 한 번만 표시한다. note만 있는 항목은 `내 코멘트` 대신 중립적인 `내용`으로 표시한다. 다른 원문을 함께 넣는 기존 편집 기능도 유지한다.
- 나중에 컬렉션을 수정/보관해도 이미 넣은 정보는 그대로다. 페이지 항목 제거도 컬렉션을 지우지 않는다. 자동 갱신되는 연결로 표현하지 않는다.
- 기존 계정/작업공간·CAS·백업·동기화 계약을 유지한다. 삽입한 텍스트는 대상 글/페이지의 기존 저장 및 사용자가 연결한 이어쓰기 범위를 따른다. 컬렉션 전체를 새로 동기화하거나 공개하지 않는다. 새 포맷/SQL/패키지는 없다.
- 화면 이탈/계정 범위 변경 시 늦은 읽기나 선택 결과를 무시한다. 글 저장·IME 중에는 삽입을 막고, 초안/구성 저장 실패 때 입력을 보존한다.

이전 [선택창의 공식 배포·라이선스 비교](collection-picker.md#구현-선택과-참고)를 재사용한다. Radix Dialog 1.3.1(MIT) 대신 native dialog를 선택한 이유가 이번에도 동일하며 새 라이브러리는 설치하지 않았다. 앱 내부의 Workbench/Writing 모델을 유지하는 데 외부 편집기 도입은 필요하지 않다.

## Local 인계

1. 선행 #66 → #67 → #68 → #69 위의 `codex/collection-insert`를 비교한다. 병합·배포는 Local이 맡고 Cloud에서는 수행하지 않는다. 스택을 retarget할 때 기존 변경의 중복 여부를 확인한다.
2. SQL·새 환경 변수·패키지 설치는 필요 없다. 운영 합성 자료를 만들지 않는다. `npm test`, `npm run check`, 실제 기기의 글/페이지 삽입·취소·저장·복귀를 확인한다.
3. 새 공개 산출물의 `collection-reference.js`, `collection-insert.js` 포함과 SW v95를 확인한다. 다른 Local 작업의 캐시 버전과 겹치면 최종 배포에서 통합 조정한다. 기존 연표/원문/개인 컬렉션을 그대로 유지한다.
4. 다음 우선순위는 **표지·앨범·도구 아이콘을 유지하는 구조화된 첨부와 얇은 간격의 프로필 피드**다. 텍스트를 역으로 파싱해 첨부처럼 가장하지 않고, 명시적인 첨부 모델의 저장·이어쓰기·백업·공개 호환을 먼저 설계한다. 이후 음악/책/장소 이름 검색의 공식 제공자·한국어 품질·비용을 비교한다.
