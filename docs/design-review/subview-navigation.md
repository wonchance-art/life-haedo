# 하위 화면의 위치와 작업 복귀

2026-10-09 KST. 홈·탐색 로드맵의 다음 단위다. 목표는 **홈/검색/도구/관리에서 작업 화면으로 이동 → 입력 또는 확인 → 들어온 위치로 복귀**다. root가 디자인·구현·통합 검토를 담당했다. 책 확장은 보류하며 기존 책/회고 기능을 추가하지 않았다.

## 재현한 문제와 결과

[변경 전 관찰](evidence/subview-navigation/before.json): 가져오기 상단은 `기록`, 자료 백업 상단은 `관리`로 표시됐다. 글쓰기/가져오기에 들어온 위치로 돌아가는 공통 조작이 없었고, 백업 화면에서 선택된 `관리` 메뉴를 다시 눌러도 `transfer` 화면에 그대로 머물렀다.

| 조작 | 변경 후 |
| --- | --- |
| 하위 화면 제목 | 가져오기·글쓰기·연표·묶음·내 페이지·다시 찾기·기기 간 동기화·자료 백업/구성 백업·공개 페이지 관리 중 실제 화면 이름 |
| 상단 뒤로가기 | 홈에서 들어오면 홈, 검색 목록에서 들어오면 해당 목록, 도구/관리에서 들어오면 그 목록으로 복귀 |
| 선택된 기본 메뉴 다시 누르기 | 해당 영역 목록으로 이동. 검색에서 연 원문은 기존 정확 검색 복귀 경로 재사용 |
| 주소로 직접 연 화면 | 기억된 진입점이 없으므로 기록/도구/관리의 기본 상위 목록으로 복귀 |
| 저장 실패 | URL·현재 화면·입력 유지. 저장 재시도 후 복귀 가능 |
| 느린 홈 조회 | 다른 메뉴를 즉시 사용할 수 있음. 늦은 조회가 다른 화면이나 초점을 바꾸지 않음 |

후속 검토에서 묶음 제목을 바꾼 뒤 홈의 같은 항목에 초점이 돌아오지 않는 실패를 [재현](evidence/subview-navigation/group-before.log)했다. 홈 조작은 전환 전에 초점을 유지하고, 묶음의 기존 ID를 복귀 키로 사용하도록 수정했다. 내 페이지 편집 버튼의 홈 복귀도 함께 검증했다.

글쓰기의 기존 내부 뒤로가기는 공통 상단으로 합쳤다. `lifeWritingClose` 조작 ID와 저장 보호는 유지한다. 단독 WritingUI의 기본 복귀는 그대로이며 공통 프레임을 제공하는 경우에만 내부 중복 조작을 생략한다. 기존 원문 읽기·관련 기록·책의 전용 복귀 계약을 새 일반 복귀로 대체하지 않았다.

## 구현 판단과 보존

기존 `navigate`, 저장 `flush`, `returnToResults`, 공통 아이콘/버튼/제목 행을 재사용한다. 복귀 정보는 UI 인스턴스의 Map에 화면 이름·작업공간 범위·초점 대상·스크롤만 보관한다. 다른 작업공간 선택/복원과 계정 폐기에서 초기화한다. 원문·정확 버전·발췌·초안·백업·동기화·공개 스키마에 추가하지 않는다. 저장에 실패하면 복귀 정보도 새 대상으로 확정하지 않는다.

반대 검토: 하위 화면마다 별도 사이드바나 안내 문구를 추가하면 프레임이 커진다. 기존 제목 행의 20px 도형/44px 조작을 재사용하는 쪽을 택했다. 탐색 라이브러리나 새 상태 저장 모듈 없이 기존 화면 경계를 연결하므로 신규 의존성·운영 SQL·인증 설정이 없다. 공식 Impeccable 4.5.0 지침의 Operate/craft-floor와 [프로젝트 도입 기록](impeccable.md)을 직접 참고했다. 외부 제품의 최신 릴리스를 이번에 새로 비교하거나 Impeccable 실행 엔진을 사용했다는 뜻은 아니다.

이번 상단 뒤로가기는 **앱 안의 복귀 조작**이다. 브라우저의 Back/Forward는 기존 영역 이동 이력 계약을 유지한다. 모든 하위 작업·원문·입력 상태를 브라우저 이력으로 직렬화하는 기능은 추가하지 않았다. 새로고침하면 화면 진입점 기억이 초기화되고 기본 상위 목록을 사용한다. 저장된 초안과 자료는 초기화되지 않는다.

## Local 인계와 직접 체험

- 브랜치 `codex/subview-navigation`, 선행 PR #59 `codex/home-navigation-focus` / `bf6e943` 위의 변경이다. **#59 적용 후 이번 변경을 적용**한다. #58 연표 복구는 별도이며 해당 내용을 이 브랜치에 포함하지 않았다.
- 사용자 변경을 보존한 뒤 통합한다. #58 v90 / #59 v91 / 이번 v92의 서비스워커 번호가 통합 중 이전 값으로 덮이지 않게 확인한다. 이후 다른 배포가 있었다면 새 고유 번호로 올린다.
- 새 SQL/인증 설정은 없다. `npm run check`, `npm test`, 로컬 `BASE_URL`과 설치된 `PW_MODULE_PATH`를 지정한 `tests/subview-navigation-browser.cjs`, `tests/unified-home-browser.cjs`, `tests/life-writing-browser.cjs`로 통합 결과를 확인한다.
- 체험: 홈 → 글쓰기 입력 → 상단 뒤로가기 → 같은 버튼 초점 → 글쓰기 재개. 기록 검색 → 내 페이지 → 뒤로가기 → 검색 조건 유지. 관리 → 자료 백업 → 기본 관리 메뉴 → 관리 목록.
- 병합·배포·라이브 실제 계정 확인은 Local 담당이며 Cloud는 실행하지 않았다. 실제 채연 연표 데이터 복구는 계속 별도 미완료다.

다음 우선순위는 관리에서 작업공간·이 브라우저 보관·서버 연결·자료/연표 백업 범위가 구분되는지 검토하는 것이다. 실제 기기 검증을 병행하고 수집·검색 개선을 이어간다. 책 확장은 계속 보류한다.
