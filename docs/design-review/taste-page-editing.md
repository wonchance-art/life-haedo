# 취향 페이지 검수 후 편집 흐름 개선

2026-10-11. PR #65 후속. 목표는 **자료 선택 → 배치 → 결과를 보며 수정 → 파일로 보관 → 다시 열기**다. 새 테마 수보다 기존 시안의 편집과 복구를 우선했다. 실제 앱 통합이나 제품 출시 판정은 아니다.

## 수정한 문제

- 고정 책·도구·컬렉션을 두 섹션의 독립적인 자료 목록으로 바꿨다. 12개 가상 자료 중 추가·제외·순서 이동, 섹션 이름·표시·순서 변경이 가능하다. 원본 가상 자료는 바꾸지 않는다.
- 모바일 편집창을 80%에서 최대 45svh로 줄이고 비모달로 변경했다. 페이지를 계속 스크롤할 수 있고, Escape/닫기로 편집 버튼에 복귀한다. 태블릿/데스크톱은 옆에 둔다. 파일과 긴 목록 때문에 편집창이 화면을 넘던 문제도 내부 스크롤로 수정했다.
- 글자마다 기록을 소모하던 되돌리기를 필드 편집 단위로 묶었다. 62자 입력도 한 번에 되돌리고 그 이전 배치 변경으로 돌아갈 수 있다. 최근 80개 편집의 메모리 기록이며 영구 개정본은 아니다.
- ‘만든 사람 표시’를 ‘카드 아래 작성자 표시’로 명확히 했다. 책 표지와 상세 정보의 출처는 보존한다. 미리보기 상세는 내부 자료 메모를 제외한다. 명시적으로 쓴 페이지 문장은 사용자가 선택한 페이지 내용으로 남는다.
- 제목·소개 영역을 줄였다. 자료 내용과 무관하게 고정돼 있던 ‘음악, 책…’, ‘하루가 느려지는…’ 소개를 제거했다. 많은 대표 자료는 작은 옆 열 대신 넓은 목록으로 펼친다. 도구는 앱 아이콘, 영상은 가로형, 책은 세로형, 표지 없는 자료는 텍스트로 구분한다.

## 파일 계약과 보존

`haedo-taste-prototype` v1 JSON은 페이지 제목·소개·내 문장, 배치 설정, 두 섹션 이름/상태/순서, 가상 자료 ID 배열만 담는다. 계정·원문·비공개 자료 메모·이미지 파일은 담지 않는다. 사용자가 직접 내려받아 보관하며 새 브라우저 컨텍스트에서도 다시 열어 확인했다. 해도 자료 백업 형식과 별개다.

파일을 최대 32KB로 제한하고 필수 키·문자열 길이·열거값·boolean·알 수 없는/중복 ID를 검증한다. 실패하면 편집을 유지한다. 비동기 읽기 도중 다른 편집이 있으면 현재 상태를 우선하고 파일 적용을 거절한다. 성공한 파일 열기 자체도 되돌릴 수 있다. 다운로드 요청은 실제 디스크 저장 성공으로 보고하지 않는다. 이탈 경고는 브라우저 보조 수단이며 영구 보관이 아니다.

운영 HTML/JS/CSS·Auth·SQL·계정 저장·원문 버전·동기화·백업·공개 API는 수정하지 않았다. CSP connect/frame/form 차단, 외부 요청 없음, 영속 브라우저 저장소 없음 유지. 새 의존성 없이 기존 아이콘과 native dialog/File/Blob을 썼다. 기존 공식 시각 참고와 라이선스 기록은 [이전 검토](taste-page.md)를 따른다. 이번에 외부 제품을 새로 조사한 것으로 표현하지 않는다.

## 2026-10-12 · 좋아하는 인물

사용자 요청에 따라 이전의 ‘인물은 우선 관계 정보’ 제안에서 범위를 확장해 독립 `person` 유형을 추가했다. 작품의 작가/감독 문자열과 인물의 정체성을 자동으로 합치지 않는다. 이름은 title, 활동 분야는 별도 field, 출처는 source에 두며 creator에 활동 분야를 넣지 않는다. 카드·검색·선택기·글 연결은 인물에 한해 활동 분야를 부가 정보로 보여준다. 카드 표시 설정도 ‘카드 아래 부가 정보 표시’로 바꿨다.

가상 인물 두 개로 총 18개 샘플이다. 원형 기본 인물 아이콘을 쓰며 실제 사진이나 AI 초상화를 만들지 않았다. 직접 입력에서 이름·활동 분야·출처·좋아하는 이유를 남길 수 있다. 좋아하는 이유는 개인 메모이고 인물의 객관적 소개가 아니다. 글 연결 카드와 비공개 미리보기에는 자동 포함하지 않는다. 동명 인물은 분야 또는 서로 다른 명시 출처 주소로 구별할 수 있지만 완전한 인물 식별/중복 해소로 표현하지 않는다.

가상 인물의 취향 페이지 선택·배치·시안 파일 복원도 연결했다. 기존 파일 형식은 유지한다. 실제 계정 저장, 보관함 임시 자료와 취향 페이지 간 공유, 인물과 작품/책/발언의 명시 관계, 사진·약력 자동 조회는 후속이다. 입력 주소를 확인된 공식 출처라고 자동 인증하지 않는다.

## 2026-10-12 · 큰 분류 → 세부 종류

종류를 한 줄로 계속 늘리는 대신 큰 분류에서 좁히는 탐색을 네 곳(보관함, 직접 입력, 글에 담기, 페이지 꾸미기)에 적용했다. 공통 `docs/prototypes/collection-space/taxonomy.js`를 사용하며 새 라이브러리는 없다.

현재 세부 종류가 하나인 분류는 보관함에서 곧바로 선택한다. 등록/선택기에서는 해당 값을 자동 지정하고 세부 select를 비활성화한다. 앱/오픈소스/서비스는 아직 독립 타입이 아니며 기존 tool을 유지한다. 장르·주제·모음은 이 형식 분류와 별개다. 개인이 분류 트리를 편집하거나 태그를 새로 생성하는 기능은 이번 범위가 아니다.

보관함의 전체 보기에서는 세부 버튼을 접고, 큰 분류를 선택하면 필요한 종류만 보인다. 큰 분류 변경 시 이전의 호환되지 않는 세부 필터를 해제하면서 검색어와 모음 선택은 보존한다. 전체로 돌아가면 큰/작은 분류 필터가 모두 풀린다. 화면에 보이지 않는다는 이유로 고른 항목을 해제하지 않는다. 글 선택기의 적용/취소 계약도 유지한다.

페이지 자료 추가에서는 현재 섹션에 없는 자료만 분류해 보여주고, 후보가 없으면 안내와 비활성 추가 버튼을 제공한다. 분류 변경은 페이지 내용 수정이나 undo 기록으로 취급하지 않는다. 추가한 뒤 되돌리면 현재 필터 안의 후보에도 즉시 돌아온다. 기존 type 문자열·원본/메모·시안 JSON v1 계약은 바꾸지 않았다. 운영 내 페이지/계정 저장/SQL/공개 범위 변경도 없다.
