# 홈·탐색: 최근 기록에서 작업으로

2026-10-09 KST. 사용자가 책 관련 확장을 보류하고 **홈·탐색·전체 사용성**을 선택했다. root가 화면 설계·통합을 담당했다. 이번에는 기존 기능에 접근하고 돌아오는 흐름을 고쳤으며 책/원문/구성 저장 모델을 변경하지 않았다.

## 실제 화면에서 확인한 문제와 변경

| 변경 전 | 변경 후 |
| --- | --- |
| 책이 없어도 책 만들기 안내가 최근 기록보다 먼저 나옴 | 이어 읽기와 최근 기록이 먼저, 묶음·내 페이지·기존 책 요약은 뒤에 배치 |
| 빠른 진입의 기록·도구가 전역 탐색과 겹침 | 가져오기·글쓰기·연표로 직접 진입. 상단에는 검색을 남기고 중복 조작 제거 |
| 구성 조회 완료 때 기록 앞의 영역이 커짐 | 구성 영역을 기록 뒤에 두어 늦은 응답에도 원문 버튼의 위치·초점 유지 |
| 별도 연표 문서에 다녀온 뒤 가져오기에서 기존 검토를 찾기 어려움 | `보관한 검토 이어서 열기`가 기록 목록의 기존 검토 목록을 펼치고 초점 이동 |
| 새 입력 저장 직후 목록을 열면 오래된 목록에 새 검토가 빠짐 | 저장 성공 뒤 목록 재조회. 실패하면 입력 화면 유지, 명시 재저장 후 두 검토 모두 선택 가능 |

최근 글과 별도 구성 요약은 같은 익명 한글 자료로 비교했다. 책 기능을 없애거나 원고 데이터를 지운 것이 아니다. `내 책`과 목차·장 진입은 홈 아래와 기존 도구에서 유지한다. 저장된 초안이 여러 개면 하나를 임의로 선택하지 않는다.

## 선택 근거와 보존

기존 HomeUI, `navigate`의 가져오기/집필/구성 저장 경계, `renderStages`, 공통 아이콘과 토큰을 재사용한다. 새 프레임워크·라이브러리·저장 형식·SQL은 없다. Impeccable 공식 지침 4.5.0의 Operate/craft-floor와 프로젝트 디자인 기준을 직접 읽었다. 실행 엔진은 사용하지 않았다. 기존 [공식 도입 기록](impeccable.md)·[앱 표면 참고](app-feel-references.md)를 재사용했으며 이번에 외부 제품 최신 화면을 추가 조사했다는 뜻은 아니다. 단순한 재배치와 기존 탐색 연결에 새 UI 라이브러리를 추가할 필요가 없다.

홈은 현재 계정/작업공간을 읽기만 한다. 원문·정확한 버전·발췌·작성 관계·확보 범위·내 페이지 표시 선택을 유지한다. 기본 전역 메뉴는 홈·기록·도구·관리 네 개다. 원문에서 홈으로 돌아오는 초점과 검색 문맥을 보존한다. 검토 재진입은 기존 저장 실패 경계를 통과하며 늦은 조회가 다른 화면을 다시 그리지 않게 한다. 자동 공개·SNS 원본 변경·외부 AI 전송·자동 동기화를 추가하지 않는다.

## Local 인계와 체험

브랜치 `codex/home-navigation-focus`, 기준 main `d22ed42`. 연표 복구 PR #58 및 보류한 책 PR #56에 의존하지 않는다. **병합·배포·운영 조치는 Local 담당**이며 새 SQL이나 인증 설정 변경은 필요 없다. #58은 이 브랜치에 포함되어 있지 않다.

1. Local의 미커밋 변경을 보존하고 main과 이 브랜치를 비교한다. #58 연표 복구도 적용한다면 함께 통합한 결과를 확인한다. #58 캐시 v90, 이번 캐시 v91이므로 통합 후 최종 `sw.js`에 이전 버전이 덮이지 않도록 한다. 이후 다른 배포가 있었다면 겹치지 않는 새 캐시 번호를 쓴다.
2. `npm run check`, `npm test`, 로컬 서버의 `tests/home-entry-browser.cjs`와 `tests/unified-home-browser.cjs`를 실행한다. Playwright 설치 경로는 환경의 `PW_MODULE_PATH`로 지정하며 서버 주소는 `BASE_URL`로 지정한다. 공개 산출물은 기존 `scripts/prepare-site.mjs`를 사용한다.
3. 실제 계정으로 홈 → 최근 기록 → 홈 복귀, 가져오기 입력 → 홈 → 입력 복귀, 연표 목록 → 홈 → 가져오기 → 보관한 검토 이어서 열기, 글쓰기 초안 재개를 확인한다. 자료·구성 백업과 연표 백업은 별도다.
4. 승인된 Local 범위에서 병합·배포하고 라이브 로그인 복귀 및 서비스워커 갱신을 확인한다. Cloud는 병합·배포하지 않았다.

실제 개인 자료, Google 실로그인, Mac/iPad/iPhone의 IME·Files·VoiceOver·터치 사용 만족도는 이번 검사 범위 밖이다. 브라우저 폭 모사를 Apple 실기로 표시하지 않는다. **채연의 실제 연표 데이터 복구는 별도 미완료**이며 이 홈 변경이나 #58의 검사로 복구됐다고 볼 수 없다.

다음은 기록·도구·관리의 실제 하위 동선에서 현재 위치와 복귀가 헷갈리는 지점을 정리하고, 관리의 작업공간·보관·동기화·백업 범위를 검토한다. 책 확장은 사용자가 다시 지정하기 전까지 보류한다.
