# 9칸 구성 찾기와 정확한 검색 복귀

2026-10-14 KST. 기반은 #88 수정 HEAD `4672bd6`. 운영 SQL·저장 형식·공개 계약 변경 없음.

## 사용 장면과 선택

여러 9칸 구성을 보관한 사용자가 기억나는 선택 이유나 창작자로 항목을 다시 찾는다. 기존 통합 검색은 원문·저장 글·컬렉션만 찾아 9칸 결과물에는 별도 진입이 필요했다. **홈 → 통합 검색 → 9칸 구성/영역/항목 미리보기 → 검색 결과로 돌아가기**를 같은 탐색 흐름으로 연결했다. 자유롭게 이름 붙인 영역마다 최대 9개를 담는 구조를 유지한다.

새 목록이나 검색 엔진을 만들기보다 기존 읽기 전용 투영·종류 필터·표시 더보기·계정/작업공간 상태 폐기·하위 화면 왕복을 재사용했다. [공식 패키지 재확인과 선택 근거](../life-tools-design/open-source-review.md#저장한-9칸-구성의-검색-확장--2026-10-14-utc). 저장본을 다시 찾는 공백이 확인된 범위다. 고정 만다라·이미지 출력·새 제공자·AI 기능을 이 작업에 묶지 않았다.

## 보존과 실패 후 복구

- 구성 제목·소개, 영역 이름·설명, 항목 제목·만든 사람·출처·선택 이유를 찾는다. 구성/영역/항목은 별도 결과이며 같은 제목을 가진 항목도 칸별로 구분한다. 기본 문자 그대로 일치와 선택적 한글 수평 공백 무시는 기존 정확 문자열 규칙을 따른다.
- 처음 열 때 실제 저장소에서 구성/영역 ID와 해당 값의 스냅샷을 확인하고, 미리보기 mount에서도 다시 확인한다. 항목은 ID가 없는 기존 형식을 유지하며 칸 순서와 유형·제목·창작자·URL·이유 전체를 비교한다. 변경/이동/삭제된 결과를 다른 항목이나 첫 구성으로 대체하지 않는다. 다시 읽기 후 새 결과를 고르게 한다. 동일한 값의 항목 두 개는 기존 형식에서 역사적 개체까지 구분할 수 없다.
- 구성은 영역 전체, 영역은 그 9칸, 항목은 정확한 칸으로 열린다. 항목의 선택 이유를 펼치고 키보드 초점·스크롤을 맞춘다. 미리보기만으로 새 초안·내용·revision을 만들지 않는다. 저장 글을 검색해 열면 9칸 화면에서 실제 해당 글로 전환한다.
- 검색어·종류·한글 공백 옵션·더보기·초점·스크롤은 기존 왕복 상태로 유지한다. 검색어·검색 인덱스·목적지 스냅샷을 저장하거나 전송하지 않는다. 작성 중 초안·미반영 입력·가져올 파일 후보·공개 서버 사본은 제외한다.
- 네 저장 범위를 독립적으로 읽는다. 9칸 읽기가 실패해도 원문/글/컬렉션을 유지하고 실패 범위·재시도를 표시한다. 검색을 다시 읽으면 이전 목적지 오류를 지워 현재 상태만 안내한다. 늦은 읽기는 다른 화면·작업공간·계정에 적용하지 않는다.
- `nine_board_changed`는 IndexedDB 트랜잭션이 **완료된 뒤** 같은 계정 범위에 알린다. 다른 탭의 저장은 검색을 자동 교체하지 않고 다시 읽기를 제시한다. abort/충돌은 성공 알림을 보내지 않는다. 미반영 입력이 있으면 검색 복귀를 차단하고 기존 DOM에 보존한다.

**반대 검토:** 구성 전체 revision으로 결과를 막으면 무관한 영역 수정까지 진입을 차단한다. 해당 목적지의 정확 값만 확인한다. 대신 변경된 동일 항목을 자동 추적해 이동시키지 않는다. 실제 사용자에게 이 재선택이 반복 부담으로 확인되면 항목 ID 추가를 별도 호환성 설계로 비교한다. 범위는 최대 20×9×9 항목/2 MiB이지만 최댓값 검색 지연·메모리는 이번에 실측하지 않았다.
