# Obsidian ZIP에서 앱 복원까지

2026-10-17 KST. 이전에는 검토 도구의 ZIP을 풀고 노트/보조 파일 JSON을 각각 복원해야 했다. 이제 **변환 ZIP 선택 → 원문·경로·해시 검증 → 내용/범위 확인 → 새 작업공간 1~2개 동시 복원 → 읽기·검색·공간 이동·재백업**까지 앱의 기존 관리 화면에서 이어진다. [연결 선택](obsidian-decisions.md)과 [전체 원본 보존](obsidian-vault-integration.md)을 함께 사용한다.

## 실제 사용

1. 변환기가 만드는 `vault-package.zip` 또는 연결 검토 도구의 `obsidian-selected-copy.zip`을 준비한다. 일반 Obsidian 보관함 ZIP/사진 글 ZIP과 구분한다.
2. 로그인 후 관리 → 내보내기·사본 복원 → **Obsidian 패키지에서 복원**에서 ZIP을 선택한다. 압축을 풀 필요가 없다. 이 단계는 아직 저장하지 않는다.
3. 노트·보조 파일·노트 연결 개수, 처음 감사의 검토/보관 정보 개수와 Git 출처를 확인한다. 원문 목록은 각각 펼쳐 40개씩 더 확인한다. 원래 감사 개수는 선택 반영 후에도 감소시켜 표시하지 않는다.
4. 기본은 노트와 보조 파일을 별도 공간으로 함께 복원한다. **보조 파일도 별도 작업공간으로 함께 복원**을 해제하면 노트만 복원한다. **Obsidian 새 사본으로 복원**을 누르기 전까지 기존 공간은 바뀌지 않는다.
5. 저장 후 노트 공간을 연다. 결과 안내에서 함께 복원한 보조 파일 공간과 노트 공간을 오갈 수 있고 원래 공간으로도 돌아간다. 보조 파일은 평문 기록이며 스크립트/플러그인으로 실행하지 않는다.

연결 검토 도구도 변환 ZIP 하나를 바로 열 수 있다. 이전의 6개 파일 선택 경로도 유지한다. 실제 개인 보관함은 오프라인 ZIP 검증 뒤 사용자의 추가 지시에 따라 지정 계정 서버에도 저장했다. 개인 연결 판단은 대신 확정하지 않았다.

## 구현과 보존

- `assets/life/obsidian-package.js`: 기존 fflate의 필터로 평탄한 고정 파일명만 허용한다. 필수 6개와 선택/반영 이력·검토 도구 외 경로, 중복, 누락, 파일당 64MiB/ZIP 및 펼친 합계 256MiB 초과, 잘못된 UTF-8/백업/원문 해시를 거부한다. 일반 ZIP 파일 추출기가 아니다.
- 앱에서는 노트·보조 파일·감사·검토 JSON 4개만 펼쳐 읽고 기존 검증기를 재사용한다. 검토 HTML·Git bundle·선택/반영 이력은 원래 ZIP에 남기며 계정 저장소에 넣거나 실행하지 않는다. Git pack 자체 검증과 원본 정합성은 앞선 전체 가져오기 증거와 구분한다.
- 공유 검증기는 `assets/life/obsidian-decisions.js`로 옮겼다. CLI의 이전 `scripts/lib/obsidian-decisions.js` 경로는 호환 wrapper로 남긴다. 검토 도구·ZIP 읽기·CLI가 같은 원문/경로/정확 버전 검증을 쓴다. 새 parser·ZIP 라이브러리·DB 스키마는 추가하지 않았다.
- `Storage.installWorkspaces()`는 복원한 1~2개를 기존 `bundles/meta` 한 트랜잭션에 넣는다. 모든 ID/소유 충돌을 쓰기 전에 확인하고 두 번째 저장·소유 정보·완료 실패 또는 진행 중 계정 교체 때 함께 롤백한다. 기존 `installWorkspace()`도 이 경로를 재사용한다. 새 공간의 소유 계정만 기록하고 동기화를 연결하지 않는다.
- 기존 작업공간·원본 ZIP은 남는다. 복원 직전 현재 입력을 보관하며 저장 실패는 검토/재시도를 유지한다. 저장 뒤 목록 읽기 실패는 이미 보관한 사본으로 안내하고 재설치 동작을 제거한다. 일반 JSON 복원과 새 ZIP 복원이 저장 후 같은 화면 전환을 쓴다.
- `index.html/life.html`, 명시적 공개 빌드 목록, **PWA v117**에 같은 모듈을 넣었다. 개인 ZIP·노트·감사·도구 산출물은 공개 빌드/서비스워커 셸에 넣지 않는다. 기존 파일 기반 비공개 가져오기와 [fflate 재사용 결정](../life-tools-design/open-source-review.md)을 유지한다.

## 검수와 한계

익명 모의 Auth·실제 IndexedDB·Chromium으로 확인했다. [보고서](obsidian-package/report.json), [1440px 검토](obsidian-package/review-1440.png)·[820px](obsidian-package/review-820.png)·[390px](obsidian-package/review-390.png)를 참고한다.

- 전체 Node **503/503**, 정적 검사 **18 HTML / 90 JS / 356 로컬 참조**. 새 ZIP 검사는 원본/선택 반영본의 정확 본문·새 ID, HTML/이력 무실행, 경로/중복/누락/팽창 제한/해시·인코딩 실패를 포함한다. 저장 검사는 두 번째 쓰기 실패·중복/기존 ID 충돌·계정 교체 시 전체 롤백과 성공 후 두 공간의 비동기화 상태를 확인한다. 변환기 CLI가 만든 ZIP도 다시 읽어 검증했다.
- 새 ZIP 브라우저 **5/5**: 취소/잘못된 ZIP의 기존 공간 보존, 두 번째 IndexedDB 추가 중단/재시도, 공간 간 이동·검색 왕복·정확 제목/역방향 연결·재백업/reload, 노트만 복원과 저장 후 조회 실패의 중복 방지, 전체 **6,899개 파일** 복원을 확인했다. 노트 3,479개/보조 파일 3,420개가 함께 보존되며 40/80행은 표시만 제한한다.
- 기존 연결 선택 브라우저 **5/5**에서 ZIP 직접 재열기까지 확인했다. 기존 전체 보관함 JSON 복원 **4/4**, 관리 범위 **5/5**, 핵심 경험 **5/5**, PWA **v116→v117 9/9**도 확인했다. PWA의 의도한 전송/콜백 오류 3건은 예상 오류로 구분한다.
- 새 ZIP 화면의 1440/820/390px에서 가로 넘침·44px 조작·16px 입력·접근 가능한 이름·대비를 검사하고 이미지를 읽었다. 새 흐름의 실제 콘솔/페이지 오류와 외부 요청은 0이다.
- 실제 원본 **6,899개 파일 / 연결 2,568개 / 판단 152회·60묶음 / 보관 정보 302회**는 Node 오프라인 ZIP 재검증까지 수행했다. [개인 내용 없는 집계](obsidian-package/actual-input-counts.json). 개인 원문은 브라우저·테스트 계정·CI·이미지에 넣지 않았다.

검수 중 선행 #93 CI는 reader heading 표시보다 뒤에 실행되는 정확 위치 선택을 먼저 검사하고 있었다. 같은 선택 조건을 명시적으로 기다리도록 보완했다. 새 전체 규모 검사의 native details 역시 실제 40/80행 도착을 기다린다. 조건을 없애거나 원래 앱 동작을 변경한 수정이 아니다. 첫 PWA 준비는 빌더의 cwd를 잘못 지정해 같은 v117을 비교했으므로 무효였으며, 보존한 v116 소스를 올바른 cwd에서 재생성해 실제 갱신 9/9를 확인했다. 관리/핵심 경험의 첫 호출은 기본 4184 포트 연결 실패였고 명시적 4173 주소로 재검증했다. 핵심 경험의 이후 한 실행은 스크롤 복귀 12초 대기에서 4/5였고 단독 재실행은 같은 조건으로 5/5였다. 이 결과로 기기별 안정성을 보장하지 않는다.

Mac/iPad/iPhone의 실제 ZIP Files 선택·대규모 메모리·한글·VoiceOver는 여전히 실기 확인 대상이다. 브라우저 모사/오프라인 검증을 계정 설치나 운영 배포로 표시하지 않는다. 아래 서버 계정 반영과 사용자 브라우저의 자료 받기, 선행 PR 통합·운영 배포는 각각 별도다. 계정 복원 후 추가한 편집을 원래 ZIP이나 다른 사본으로 자동 병합하지 않는다.

## 지정 계정 서버 반영 — 추가 사용자 지시

사용자가 Google 로그인 계정을 지정하고 모든 자료를 그 계정에 넣도록 요청했다. Auth의 이메일/소유 ID를 확인하고 기존 서버 공간 1개·자료 6개를 먼저 앱 저장소 밖에 비공개 백업했다. 이메일·소유 ID·원문·실제 영수증은 공개 저장소에 남기지 않는다.

노트 **3,479개**와 보조 파일 **3,420개**, 노트 연결 **2,568개**를 두 새 비공개 `life_workspaces` 행으로 같은 소유 계정에 등록했다. 기존 자료는 변경하지 않았으며 계정 전체는 **3공간 / 6,905개 자료**다. 새 공간 데이터는 각각 서버의 16MiB 제한 안에 있다. 기본 RLS·인증 설정·공개 페이지·다른 계정은 변경하지 않았다. [개인 정보 없는 반영 집계](obsidian-package/account-installation-counts.json).

연결 도구의 요청 크기 제한 때문에 실제 데이터는 클라이언트에서 읽은 작은 바이트 조각을 DB 소유자만 접근 가능한 임시 binary 객체로 검증 전송했다. 서버 파일/OS를 읽거나 실행하지 않았다. 전체 파일 SHA-256 확인 뒤 한 SQL 문으로 두 공간을 등록하고 임시 객체를 함께 제거했다. 기존 스키마·함수·정책을 추가/변경하지 않았다.

등록 후 두 공간의 전체 JSONB 스냅샷 해시가 로컬 정규 사본과 같고 모든 본문 해시가 일치함을 확인했다. 기존 공간의 revision/전체 해시도 그대로다. DB의 authenticated/소유 주체 조건에서 전체 자료를 읽을 수 있고 다른 주체에서는 새 공간을 읽지 못한다는 RLS 검증을 통과했다. 임시 객체 잔여는 0이다. 실제 Google 브라우저 로그인/기기 설치 확인을 대신한 검증으로 표현하지 않는다.

해당 계정으로 앱에 로그인한 뒤 **관리 → 동기화 → 서버 작업공간 받기 → 서버 작업공간 목록 확인**에서 두 공간을 받을 수 있다. 사용자 브라우저 저장소를 원격 조작하거나 기존 로컬 공간을 교체하지 않았다. 원래 Git 이력/감사/선택 이력은 비공개 원본 패키지에도 계속 보관한다.

후속 [수신·읽기·보존 품질 묶음](obsidian-hardening.md)에서 ZIP 크기 검사와 후보 검증을 강화하고, 서버 받기의 미반영 메모 보존·동일 버전 정합성·검색 복귀와 서로 다른 위치 이동을 검증했다.
