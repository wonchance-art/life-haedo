# B안: 실제 비공개 내 페이지·미리보기 적용

2026-10-08 KST. 사용자 목표는 **B안의 출처 구분과 짧은 본문 앞부분을 실제 비공개 페이지에 적용하고, 기존 저장·동기화·백업·선택 공개 경계를 검증한 상태로 Local에 인계**하는 것이다. [A/B 비교](expression-page-comparison.md)의 같은 익명 8개 원문·9개 버전·6개 항목을 실제 앱/IndexedDB에 넣어 확인했다. root가 공통 UI를 통합하고 독립 에이전트가 기존 회귀와 새 보존 검사를 맡았다.

## 변경과 사용 흐름

편집과 비공개 미리보기가 같은 원문 표시 함수를 사용한다. 원문 사이의 얇은 선, 작은 제목·출처·작성일, 16px/1.8 본문, 민트 바탕의 내 코멘트로 구분한다. 코멘트와 짧은 글은 자르지 않는다. 제목이 항목과 같으면 중복 제목을 생략한다. 타인 글·부분 본문·누락·본문 미확보·버전 정보는 그대로 드러낸다.

긴 원문의 앞부분 뒤 **본문 펼치기**를 누르면 선택한 버전의 정확한 전체 본문을 읽는다. 펼친 본문으로 초점을 옮기고, 접으면 조작 버튼으로 복귀한다. 책 아이콘은 기존 원문 읽기를 열고, 돌아오면 같은 편집/미리보기·펼침·초점·스크롤을 복구한다. 미리보기의 내부 원문 열기는 로그인한 소유자에게만 제공하는 비공개 동작이다. 공개 방문 페이지의 기능을 바꾼 것은 아니다.

작성일은 `originalCreatedAt` 원값만 표시한다. 자유 문자열을 허용하는 기존 형식에 맞춰 임의로 자르거나 시간대를 바꾸지 않고, 미상인 경우 가져온 날짜로 대신 채우지 않는다. 기존 제목/표시/순서/고정/코멘트 편집은 그대로 작동한다.

## 보존 계약

- 펼침 상태는 작업공간 session의 항목 ID·버전 ID별 메모리에만 둔다. 새로고침하면 접힌 상태로 시작한다. 화면 폭이 바뀌어도 펼친 본문의 문자열이 같으면 DOM을 다시 쓰지 않아 선택 중인 구절을 유지한다. `mark()`·구성 revision·원문·동기화·백업에 기록하지 않는다.
- 접힌 글은 원문의 정확한 연속 앞부분이다. 요약·정규화 없이 emoji의 UTF-16 쌍과 CRLF 경계를 보존한다. 전체 문자열은 불변이며 보관 원문과 백업에 유지된다.
- 본문 표시 설정과 화면 접힘, 공개 사본의 명시적 본문 선택은 서로 독립적이다. 펼치기만으로 본문이 게시되지 않고 접기만으로 공개 본문을 줄이거나 철회하지 않는다.
- 원문 열기·미리보기 전 기존 저장 완료 경계를 재사용한다. 저장 실패는 입력과 현재 화면을 보존하고 재시도를 제공한다.
- 모델·SQL·저장 형식·로그인·동기화 프로토콜·공개 렌더러는 변경하지 않았다. PWA 캐시는 변경된 UI 파일을 받도록 v75로 갱신했다.

## 단계별 변경

1. `60cf7a7`: 편집/미리보기의 원문 표시 통일·날짜/누락·B 간격 적용. 정적 검사와 기존 page-flow 3/3 통과 후 다음 단계로 진행했다.
2. `ef7bb1f`: 화면 전용 펼침·정확 버전 열기/복귀·기존 테스트의 prefix/full 계약 적용. 단위 311/311과 기존 핵심/구성 경로를 확인했다.
3. 독립 통합 검사·반응형 구절 선택 보존 보완·CI 연결·화면 증거와 Local 인계. 실제 기기 및 공개 배포는 별도 단계다.

단계별 커밋으로 검토·되돌리기가 가능하다. 두 번째 커밋을 되돌리면 전체 본문 표시로 돌아가고 첫 번째의 공통 배치는 남는다. 첫 번째까지 되돌릴 때는 그 뒤 변경을 역순으로 되돌린 뒤 후속 배포의 캐시 버전을 새 번호로 올려야 한다. 이미 배포된 캐시 번호를 단순히 재사용하는 롤백을 권하지 않는다.

## 검증

기능과 화면 판단을 분리했다. 새 검사는 실제 앱·동봉 SDK·IndexedDB를 사용하지만 Auth/원격 HTTP와 자료는 모두 합성이다. 운영 Supabase에는 접근하거나 검사 자료를 만들지 않았다.

- 정적 검사: HTML 18개, JS 54개, 로컬 참조 259개·PWA 통과.
- 단위 검사: 311/311 통과. 백업·구성/원문 동기화·공개 선택·서비스워커 계약 포함.
- 기존 페이지 흐름: 첫 단계 1440·820·390px 3/3 통과.
- 기존 핵심 경험: 최초 4/5 뒤 짧은 본문에 숨긴 버튼을 해석하던 테스트 기대치를 수정하고 실패한 경로 1/1 재검증. 기존 Workbench는 최초 15/17 뒤 같은 기대치 수정 후 실패한 2/2 재검증. 전체를 다시 실행한 것으로 합산하지 않는다.
- 기존 게시 검사: 17/17 흐름·21개 시각 상태, 콘솔/페이지 오류 0. 기본 본문 제외·명시적 포함·갱신·철회·응답 유실·계정 경계를 모의 HTTP에서 확인했다.
- 새 표현 화면 검사: [종합 보고](evidence/page-expression/combined-report.json)의 6개 경로가 최종 통과했다. 최초 5/5, 경계 사례 추가 1/2 뒤 저장 실패의 비동기 종료를 기다리도록 테스트를 고쳐 해당 1/1을 재검증했다. 그 뒤 최종 읽기 검토에서 발견한 반응형 본문 재할당을 보완하고 선택 구절·Text 노드 보존 경계 검사 1/1을 추가 확인했다. 실행별 원본 보고를 보존했다. 자유 형식 날짜·미상, 같은 원문의 항목별 독립 펼침, 700/701px 경계, 실패 시 원문 이동 차단도 포함한다.
- 화면 검사: 편집/미리보기 각 3폭과 [390px 첫 화면](evidence/page-expression/viewport-report.json). 가로 넘침·44px 조작·16px 입력·접근 이름·대비 위반 0, 최소 글자 대비 6.05:1. 실제 콘솔/페이지 오류·외부 요청 0. root와 QA가 실제 캡처의 원문 구분·코멘트·한글 줄바꿈을 별도로 검토했다.
- 공개 산출물 생성 통과. 합성 공개 설정으로 검사했고 게시하지 않았다. [기존 게시 회귀](evidence/page-expression/publication-regression.json)는 실제 운영 HTTP 검증과 구분한다.

기존 [공식 참고](expression-references.md)의 명시적 펼침·정확 원문·날짜 구분 원칙을 재사용했다. 신규 런타임 라이브러리·에디터·빌드 시스템은 도입하지 않았다. 네이티브 버튼·pre·matchMedia와 기존 디자인 토큰으로 이번 범위를 구현할 수 있어 추가 의존성의 이득이 없다.

## Local 인계와 남은 범위

이번에는 SQL 설치가 없다. PR #41 다음의 후속 브랜치이며 선행 PR과 병합 순서를 확인해야 한다. Local이 병합·배포 후 v75 또는 이후 캐시의 실제 로드와 라이브 로그인/저장을 확인한다. Cloud의 브라우저 크기·터치 모사는 실제 Mac/iPad/iPhone·한글 IME·Files·VoiceOver 검증을 대신하지 않는다.

공개 방문 페이지를 B로 재설계하거나 신규 자동 수집·추천을 구현하는 것은 이 목표 밖이다. 여기서의 완료는 실제 비공개 UI 구현·회귀 확인·검토 가능한 인계이며 공개 배포 완료가 아니다.
