# 뉴스에서 본문·이미지 읽기

2026-10-29. 사용자 요청: 제목을 누르면 해도에 머물며 읽고 원문은 출처 링크로 첨부한다. 공개 후보 수집 → 내부 읽기 → 직접 좋아요/담기 → 필요한 본문 보관 → 기존 자료 활용을 한 흐름으로 연결한다. SNS 계정은 자료를 발견하는 선택 경로이며 외부 SNS에서 먼저 읽는 것을 필수로 두지 않는다.

## 구현 범위

- 뉴스 제목은 한 열의 내부 읽기 화면을 연다. 원문·번역은 사용자가 선택할 때만 별도로 연다. 전문, 요약, 본문 미확보를 구분하고 자료를 임의 생성하지 않는다.
- 원문 제목·저자·발행일·출처와 이용 조건을 유지한다. 읽기 화면은 목록의 설정과 관리 패널을 숨기고 본문에 집중한다. 원문 링크, 라이선스, 좋아요·담기·자료 보관은 기존 동작을 재사용한다.
- 읽기 시작·스크롤·닫기는 읽음/좋아요/유용성/개인화 동의를 만들지 않는다. 읽는 동안 도착한 목록이 열린 본문을 바꾸지 않으며, 명시적 목록 복귀와 브라우저 뒤로가기는 기존 초점·스크롤을 복원한다. 계정·공간 변경/화면 이탈에서는 읽기 사본과 Blob URL을 폐기한다.
- 좋아요·담기·읽기 비교 저장본은 계속 제목과 출처 메타데이터만 보관한다. 담은 글이 현재 공급 목록에 있으면 그 글의 본문을 열고, 목록에서 빠졌으면 본문 미확보로 표시한다. 담기는 원문 파일의 영구 보관이 아니다.

## 자동 수집과 권리

기존 아홉 출처와 예약 수집 경로를 유지한다. 이번에 본문 허용을 넓힌 출처는 기존 **Frontiers in Psychology** 한 곳이다.

| 확보 범위 | 조건 | 실패 시 동작 |
|---|---|---|
| 공식 RSS 초록 | 학술지 CC BY 정책, 제공된 description | 빈 내용은 링크만 제공 |
| 최신 세 편의 전문 | 공식 JATS XML, 정확 DOI, 개별 CC BY 4.0, 본문 구조·표현 검증 | 유효한 이전 사본 또는 초록으로 복구 |
| 논문 그림 | 해당 XML fig, 제3자 권리 예외 없음, 승인 host·robots·응답·바이트·형식 검증 | 해당 그림만 생략하고 본문 유지 |
| 나머지 출처 | 기존 제목·URL 메타데이터 | 본문을 확보했다고 표시하지 않음 |

원문 전체가 공개되어 있다는 이유만으로 재게재 권한을 추정하지 않는다. 표·수식을 정확히 전달하지 못하거나 제한 때문에 본문을 잘라야 하면 전문으로 표시하지 않는다. 이미지·원래 페이지 레이아웃·추가 파일의 완전한 사본을 제공하는 기능은 아니다. 원문 링크는 항상 유지한다.

- [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

## 전달·저장 계약

공개 feed schemaVersion 1의 기존 `summary`, `bodyText`, `coverage`, `rights`를 사용하고 선택 `images`만 추가한다. 외부 HTML·스크립트는 삽입하지 않는다. XML은 제한된 source adapter로 문단·표를 추출하고 브라우저는 텍스트 노드로 표시한다. 개인정보·관심문·계정 자격은 수집 요청에 포함하지 않는다.

이미지는 별도 서버나 CDN 프록시 없이 JSON에 제한된 원본 바이트를 포함한다. PNG/JPEG/WebP, 이미지당 256 KiB, 글당 두 개, 전체 768 KiB, 최대 한 변 4,096·16MiPixels로 제한한다. MIME·헤더·정규 base64·CC BY·출처 host·문단 위치를 검사한다. 캡션·크레딧·이미지 원문·라이선스를 함께 보관하고 reader에서만 Blob URL로 연다. 이미지 실패는 글을 지우지 않는다. 전체 JSON 상한은 기존 브라우저/SW의 4 MiB에 수집·배포 검사를 맞춘다. 실제 용량·읽기 부담이 커지면 별도 본문/이미지 전달을 재검토한다.

자료실 보관은 기존 가져오기 검토·중복 확인·불변 원문 판·계정 보관 경로다. 전문→full_text, 초록→partial, 링크→link_only로 보존한다. 받은 본문을 그대로 접두부에 두고 마지막에 **[해도 출처 정보]**를 별도 추가해 제목·저자·원문·이용 조건·서식 변경·사진/영상 미보관을 남긴다. 이 저장본의 hash는 출처 정보가 붙은 읽기 사본의 hash이며 publisher 파일의 hash가 아니다. 원문 문장 위치는 접두부에서 유지된다. 별도 이미지 원본 개인 보관이나 신규 DB schema는 추가하지 않는다.

공개 feed는 기존 별도 캐시를 유지하고 앱 셸 v167에 reader 모듈을 포함한다. 구버전 설치의 개인 자료·설정·반응을 지우거나 변환하지 않는다. 계정 뉴스 메타의 서버 연동은 기존 별도 인계 범위이며 이번 변경으로 완료된 것으로 표시하지 않는다.

## 대안·반대 검토

[Readability 공식 버전 0.6.0](https://github.com/mozilla/readability/tags), Apache-2.0과 [보안 권고 GHSA-3p6v-hrg8-8qj7](https://github.com/mozilla/readability/security/advisories/GHSA-3p6v-hrg8-8qj7)을 2026-10-29 확인했다. 해당 권고는 0.6.0에서 수정됐다. Readability는 sanitizer가 아니고 별도 DOM 구현·권리 검증이 필요하다. 이번 출처는 공식 XML이 있으므로 기존 Python ElementTree/HTMLParser와 안전한 DOM 생성을 재사용한다. 범용 페이지 추출기·새 AI/DB/API를 도입하지 않는다.

본문을 한꺼번에 모으면 속도·저작권·표현 정확성 문제가 생긴다. 따라서 검증된 출처의 최신 세 편과 제한된 그림부터 자동으로 채운다. 전체 본문을 못 얻어도 확보된 초록과 출처로 읽기가 끝나며 전문이라는 잘못된 표시는 하지 않는다. 이 공급 한계와 실제 사용자의 추천 유용성은 자동 검사 결과와 구분한다.

## 검수와 사용

정적 검사, 전체 단위 검사, 내부 읽기·기존 뉴스 흐름·PWA와 실제 공개 논문의 브라우저 검수를 수행했다. 최종 결과와 Git 인계는 아래 완료 기록을 따른다. 실제 사용자 계정·Apple 기기의 직접 평가와 합성 Auth/격리 IndexedDB/Chromium 검사를 구분한다. 실행: `npm run dev` → `/index.html?section=news` → 글 제목 → 내부 읽기 → 원문/반응/자료 보관 → 뉴스 복귀.
