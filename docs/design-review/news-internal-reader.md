# 개인 탐구 자료: 뉴스 내부 읽기

2026-10-29. 최신 사용자 결정은 **자신의 관심과 눈높이에 맞는 자료를 추천받아 개인적으로 읽는 것**이다. 뉴스 제목 → 해도 안의 본문·가능한 이미지 → 직접 반응/필요한 자료 보관이 현재 흐름이다. 출처 링크를 유지하며 SNS 발행은 이 기능의 선행 조건이 아니다.

## 구현과 추천의 범위

- 기존 관심 주제·다중 콘텐츠 언어·명시 좋아요의 추천을 유지한다. 담기는 읽을 목록이며 좋아요와 다른 신호다. 읽기·스크롤·닫기만으로 읽음/도움/좋아요를 생성하지 않는다.
- 제목은 한 열의 내부 읽기를 연다. 본문은 로그인 계정으로 요청하고, 읽는 동안 목록이 갱신돼도 받은 정확한 판을 유지한다. 원문·번역은 별도 명시 동작이다.
- 본문 대기, 실패 후 재시도, 지원하지 않는 출처의 원문 링크를 구분한다. 닫기·화면/계정/공간 전환은 요청과 늦은 응답을 폐기한다. 브라우저 뒤로가기·초점·스크롤 복귀를 보존한다.
- 제목만으로 사용자의 실력이나 자료 난이도를 추정하지 않는다. 본문 없는 후보에서 효과가 없는 분량 설정은 추가하지 않았다. 새로운 이해도 학습·AI 맞춤 설명/요약 생성은 이번 구현이 아니다.

## 공개 목록과 계정 전용 본문

공개 RSS 예약 수집은 기존 아홉 출처의 **제목·URL·작성자·분류·날짜**만 갱신한다. 공개 JSON과 Pages artifact에는 초록·본문·이미지·개인 영수증이 들어가지 않는다. 고정 필드와 값의 타입을 검사하며 실패한 출처는 마지막 정상 메타데이터를 유지한다.

본문은 별도 `haedo-discovery-private` Edge가 Auth 사용자와 현재 세션을 확인한 뒤 요청한다. 서버는 클라이언트가 보낸 owner를 받지 않는다. URL은 출처별 고정 호스트·경로만 허용하고 공식 응답/robots/리디렉션/크기/시간을 검사한다. 공개 재배포 허가와 개인 열람을 구분해 `rights.mode=private_reading`, 실제 수신 방법·시각·출처를 `acquisition`에 남긴다.

| 출처 | 해도에서 읽는 범위 | 미확보 시 |
|---|---|---|
| Frontiers in Psychology | 선택한 DOI의 공식 JATS 본문·표·참고문헌, 가능한 그림 최대 2개 | 정확히 옮길 수 없는 수식·표·초과 분량은 초록, 수신 실패는 이전 보관본 또는 원문 링크 |
| MIT News 언어학 | 정확 canonical과 고정 본문 영역이 확인된 기사 본문 | 공식 RSS 초록 또는 원문 링크 |
| Language Learning & Technology | 공식 RSS 초록 | 원문 링크. 별도 PDF 전문은 현재 미지원 |
| 나머지 여섯 출처 | 기존 제목·링크 | 미지원 상태에 반복 수집 버튼을 제시하지 않음 |

Frontiers는 공개 목록의 최신 세 편 제한을 없애고 선택한 DOI를 수신한다. 이미지 실패는 본문을 지우지 않는다. 이미지당 256 KiB·최대 한 변 4,096/16MiPixels, 글당 두 개를 검사하고 브라우저에서 Blob URL로 표시한다. 외부 이미지 URL을 자동 요청하지 않으며 닫을 때 Blob URL을 폐기한다. MIT/LLT 이미지·PDF는 이번 지원 범위가 아니다.

## 보관·성능·기기 연속성

`haedo_discovery_private`의 계정별 읽기 캐시는 최대 100편·32MiB다. 본문 한 편은 2MiB 이내, 정상 보관본은 24시간 재사용하며 수신 실패는 15분 뒤 재시도한다. 계정별 동시 수집 2개·시간당 30회/일 120회 제한은 기존 보관본 읽기를 막지 않는다. 만료 뒤 갱신이 실패하면 이전 본문과 원래 수신 시각을 그대로 보여준다. 이 캐시는 영구 자료실이 아니다.

같은 계정의 다른 기기는 서버의 같은 보관본을 받는다. 원문 URL과 계정으로 찾으며 별도 기기 이동 버튼을 요구하지 않는다. 본문 응답은 `private, no-store`이고 공개 SW 캐시에 넣지 않는다. 셸 v168은 과거 `haedo-discovery-feed-v1`을 폐기하고 메타데이터 전용 v2를 사용한다. 기존 원문·설정·반응·구판 읽기 비교는 변환하지 않는다.

자료실 저장은 기존 가져오기 검토 → 중복 확인 → 불변 원문 판 → 계정 보관이다. 실제 본문은 그대로 접두부에 두고 **[해도 출처 정보]**를 덧붙인다. 저장본 hash는 출처 정보가 붙은 읽기 사본 기준이다. 전문은 full_text, 초록은 partial, 링크만 있으면 link_only다. 본문의 사진·영상 원본을 자료실로 함께 보관하는 기능은 아직 없다.

좋아요·담기·읽기 비교 저장본에는 개인 본문을 넣지 않는다. **관심/언어/반응의 기기 간 연동은 기존 PR140의 별도 인계 범위**다. 이번 계정 전용 기사 캐시가 뉴스 설정 전체의 서버 연동을 완료한 것은 아니다. 구판 읽기 판단은 자동 전송하거나 새 정책에 옮기지 않는다.

## 설치와 검수

- CLI 생성 migration: `20261029084145_discovery_private_reader.sql`. 운영 적용 이름은 `discovery_private_reader`, 운영 영수증 버전은 `20261029084926`이다. 새 private schema만 추가했고 구조 검사 SQL을 통과했다.
- Edge `haedo-discovery-private` v1, gateway `verify_jwt=true`로 운영 연결을 확인했다. Auth/API 키·실제 개인 기록은 저장소나 보고서에 기록하지 않았다.
- 정적 검사: 22 HTML·176 JS·732 로컬 참조. 전체 단위 **1,647개 통과**.
- 합성 실제 PostgreSQL 17: 소유권·살아 있는 세션·동시 요청·늦은 lease·본문 hash·100행/32MiB·TTL/실패 복구 **12조건 통과**.
- 실제 SDK/격리 IndexedDB/Chromium: 내부 읽기 **4묶음**, 계정/늦은 응답/재시도·정확 저장 **7묶음**, 기존 발견 **19흐름** 통과. 1440/820/390px 표시·키보드·그림 decode와 본문 보존 확인. 오류/예상 밖 외부 요청 0.
- v167→v168 PWA **9조건 통과**: 기존 개인 자료·언어·반응·연간 계획·구판 읽기 판단 보존, 과거 공개 본문 캐시 제거, 새 셸과 메타데이터 갱신/실패 복구.
- 설정된 테스트 A/B 계정의 실제 Auth→Edge→DB→클라이언트 검증 **11조건 통과**. Frontiers 본문 88,579자·실제 그림 2장, MIT 본문 9,085자, LLT 초록 1,867자. 같은 계정의 독립 세션은 같은 hash/수신 시각을 재사용하고 B는 자기 보관본을 별도로 수신했다. 테스트 세션 세 개 로그아웃 및 이번 테스트 기사 4행·제한 2행 정리를 완료했다.

공개 목록은 9출처·120글을 유지하면서 **136,525바이트**로 줄었다(이전 1,441,512바이트 대비 약 90.5% 감소). 생성/수신 시각을 새로 꾸미지 않았다. 공개 목록 축소로 기존 관심순의 요약·본문 근거는 더 이상 제공되지 않지만 제목·태그 기반 좋아요 정책 v4와 과거 읽기 비교는 그대로다.

[현행 검수 요약](evidence/news-private-reader-20261029.json). 과거 공개 본문 수집 기록은 [이전 근거](evidence/news-internal-reader-20261029.json)에 보존하되 현행 동작으로 사용하지 않는다. 실제 Apple 기기·사용자의 추천 효용은 자동 검사와 별도다. 프런트엔드 출시/CI의 확정 상태는 [PR145](https://github.com/wonchance-art/life-haedo/pull/145)를 따른다.

사용 경로: `npm run dev` → `/index.html?section=news` → 지원 출처의 글 제목 → 본문/이미지 → 필요한 자료 저장 → 뉴스 복귀. 배포 설정은 기존 계정 프로젝트를 사용한다.

## 대안과 공식 근거

기존 Cheerio 1.2.0/MIT·고정 lock과 Naver의 네트워크/robots/이미지 검증을 재사용한다. Python 공개 본문 추출 중복 구현을 제거했다. 기존 임의 페이지 추출기나 새 AI API를 도입할 필요 없이 공식 XML/RSS·고정 HTML 본문에서 정확한 범위를 제공한다. [공식 OSS 검토](../life-tools-design/open-source-review.md#개인-뉴스-본문과-계정-전용-수신--2026-10-29).

공식 자료: [Frontiers JATS 예시](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2026.1997631/xml), [MIT RSS](https://news.mit.edu/topic/mitlinguistics-rss.xml), [LLT RSS](https://www.lltjournal.org/feedlet/), [Supabase Auth headers](https://supabase.com/docs/guides/functions/auth-headers), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

## 다음 큰 작업 묶음

1. **계정별 추천 상태 통합.** 이유: 어떤 기기에서든 같은 관심·언어·좋아요·담은 목록으로 이어 읽기. 선행: PR140의 기존 계정 CAS/충돌/구판 보존 계약. 완료: A 변경→B 같은 조건→B 수정→A 반영, 오프라인/삭제/충돌과 다른 계정 격리. 직접 읽기 판단의 이전 범위는 별도 계약을 유지한다.
2. **관심·눈높이에 맞는 자료 선별과 설명.** 이유: 외국어 학습·독서·집중력·Grit 자료의 실제 읽기 효용을 높이기. 선행: 관련 출처의 충분한 본문과 명시 관심·읽기 목적·설명 수준. 완료: 새 후보 발굴→출처 기반 읽기/필요시 AI 설명→직접 피드백→다음 추천 개선을 비교하고 근거 없는 난이도·이해도 추정을 배제한다. 공개 SNS 배포는 독립 후속 흐름이다.
