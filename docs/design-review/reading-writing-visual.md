# 읽기·글쓰기 표면 검토

2026-10-07. 공통 디자인 결정은 주 작업 에이전트가 맡고, `ui.css` 수정은 글쓰기 제목과 저장 행에 한정했다.

실제 앱의 변경 전 `dd7031c`를 4185, 변경 후 작업 코드를 4184에서 실행했다. 익명 Auth HTTP와 실제 IndexedDB를 사용하는 같은 한글 자료를 1440·820·390px, 높이 900px의 Linux Chromium에서 비교한다. 개인 계정·운영 DB·실제 사용자 기록을 사용하지 않는다.

## 시각 판단

변경 전 기록·원문·빈 글쓰기·긴 글쓰기 이미지는 `.local/experience-review/before-{records,reader,write,long-write}-{1440,820,390}.png`에 있다. 검토에는 익명 정원 산책 원문과 30문단 초안, 같은 긴 한글 제목을 사용했다. 원문과 글쓰기의 3폭 이미지 9장을 직접 확인했다.

- 원문은 흰 한 열 본문, 한 개의 제목, 옅은 라벤더 행동, 승인 A 인용 아이콘의 기존 위계를 유지한다. 이번 표면 수정으로 읽기 메뉴나 사이트 탐색을 다시 꾸미지 않는다.
- 긴 초안 제목은 한 줄 입력에서 세 폭 모두 잘렸다. 네이티브 textarea와 내용에 맞는 높이를 사용해 제목 전체를 검토할 수 있게 한다. 기존 제목 글꼴·색·가느다란 구분선·키보드 초점 표현을 재사용한다. 최종 확인에서 한글 단어가 `다/시`로 갈리는 점을 발견해 디자인 책임자의 결정으로 제목에만 `word-break: keep-all`과 긴 문자열의 넘침 방지를 적용했다.
- `기록에 저장`의 명시적 행동 문구가 상태 설명과 함께 놓인다. 상태 설명은 남은 폭에서 줄바꿈할 수 있고 저장 버튼의 크기는 줄어들지 않도록 한다.
- 본문 입력의 기존 높이와 네이티브 내부 스크롤을 유지한다. 빈 화면에서 아래 초안 조작이 멀어지는 점은 본문 작업 공간과의 선택이며, 이번 재현 결함인 제목 잘림과 읽던 편집 위치 복귀보다 우선하지 않는다.

## 측정과 한계

기존 입력의 `rows=14` 때문에 변경 전 본문 clientHeight는 390px에서 492px, 820·1440px에서 519px였다. 이 값과 본문 시작 위치는 같은 자료·뷰포트의 관찰값이며 제품 전반의 품질 점수가 아니다. 변경 전 측정은 `.local/experience-review/baseline.json`에 있다.

변경 후 `.local/experience-review/after-{reader,write,long-write}-{1440,820,390}.png`의 9장을 직접 확인했다. 제목 줄바꿈 수정 뒤 긴 초안의 3장만 다시 확인해 `다시`·`문장으로`가 단어 경계에서 자연스럽게 이어짐을 확인했다. 긴 제목 전체가 보이고 `기록에 저장`이 상태 설명과 한 행에 유지된다. 원문의 제목·본문·읽기 조작은 변경 전과 같은 위계다.

같은 render의 원문·긴 초안 6개 상태에서 측정한 결과는 `.local/experience-review/after-report.json`에 있다.

| 측정 | 결과 |
| --- | --- |
| 가로 넘침 | 6개 상태 모두 없음 |
| 44px 미만 조작 / 16px 미만 입력 / 이름 없는 조작 | 모두 없음 |
| 계산한 최소 글자 대비 | 6.05:1, 실패 없음 |
| 명시 저장 버튼 | 세 폭 모두 98.33×44px |
| 긴 제목 입력 높이 | 390px에서 130px, 820·1440px에서 103px |
| 본문 입력 clientHeight | 390px에서 492px, 820·1440px에서 519px 유지 |
| 본문 입력 초점 테두리 | 3px, 7.286:1, `:focus-visible` 활성 |

포인터로 원문을 연 뒤 프로그램이 초점을 준 제목은 `:focus-visible=false`였다. 이 관찰은 키보드 탐색 검사를 대신하지 않는다. 초안 중간 위치 복귀는 별도 상호작용 검사에서 내부 스크롤 970→970px, 선택 위치 620→620을 확인했다(`after-interaction.json`).

위의 계산 결과와 시각 판단은 별개이며 사용자 효용이나 실제 기기 접근성을 증명하지 않는다.

Impeccable 4.5.0은 프로젝트 지침 설치본의 직접 읽기 경로로 적용했다. `polish`와 `craft-floor`를 참고했고 실행 엔진·자동 hook·자동 시각 점수를 사용하지 않았다. 변경 전 확인 → 결함 묶음 수정 → 최종 확인 뒤 발견한 제목 줄바꿈만 책임자 지시로 바로잡았다. 전체 화면의 반복 캡처나 장식 조정을 늘리지 않는다.

실제 Mac·iPad·iPhone, Apple 한글 IME·Files·VoiceOver·앱 전환은 미검증이다. Chromium의 폭·터치 모사를 Apple 실기 결과로 표현하지 않는다. 배포는 이번 검토 범위가 아니다.
