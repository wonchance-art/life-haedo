# 핵심 경험의 품질 기준

2026-10-05. 디자인·통합 책임: 주 작업 에이전트. 개별 화면에 별도 스타일을 만들지 않는다.

## 실행 지시

사용자가 제기한 문제는 기능 부족보다 **개별 기능은 있으나 쓰는 흐름과 완성도는 낮은 상태**다. 신기능 확장을 멈추고 `기록 찾기 → 읽기 → 관련 기록 → 묶음 → 내 페이지 → 저장한 결과 재열기`를 실제 자료로 연결한다. 앞으로 짧은 지시는 AGENTS.md의 목표·범위·보존·완료 기준으로 해석한다. 판단 근거가 약하면 작은 실험을 하고, 사용자가 완벽한 요구사항을 쓰도록 기다리지 않는다.

이번 범위: 원문에서 정확한 버전을 기준으로 관련 기록 바로 보기, 읽던 위치 복귀, 내 페이지 결과 중심 편집, 현실적인 내용 평가, 브라우저 CI. 새 SNS 연결·AI API·런타임 프레임워크·SQL은 추가하지 않는다. 승인된 흰 본문/옅은 라벤더·민트와 A 인용 아이콘을 유지한다.

보존: 원문 UTF-16 위치와 불변 버전, 출처·부분/링크 표시, 계정/공간 격리, 입력 중 DOM과 실패 복구, 명시 저장/선택 동기화/백업, 공개 사본의 별도 검토·갱신·철회, 연표 값.

## 완료 기준을 분리한다

| 판단 | 이번 확인 | 통과가 보장하지 않는 것 |
| --- | --- | --- |
| 기능 보존 | Node 회귀, 실제 IndexedDB·모의 계정 브라우저, 실패 복구·백업·PWA 갱신 | 실제 Google 인증·운영 DB 쓰기 |
| 사용 흐름 | 실제 가져오기 UI에서 시작, 원문에서 기준 재선택 없이 관련 기록, 정확 버전/초점/스크롤 복귀, 선택 구성 저장·재열기 | 사용자에게 지속해서 가치 있는가 |
| 화면·내용 품질 | 같은 한글 자료로 1440/820/390px 전후 이미지 직접 검토, 제목 반복·정보 위계·키보드·터치 목표·줄바꿈·대비, 유용/무관 후보 비교 | 실제 iPad/iPhone·IME/Files, 광범위한 추천 정확도 |

본문 시작 Y와 클릭 수는 **동일한 샘플의 전후 비교**에만 쓴다. 이 수치를 제품 전반의 합격 점수로 만들지 않는다. 화면 크기 모사는 실제 기기 검증이 아니다. 테스트 개수를 제품 품질 점수로 쓰지 않는다.

## 화면 계약

- 원문은 한 개의 제목과 자체 읽기 조작만 보인다. `함께 읽을 기록`은 숨은 아이콘 대신 짧은 행동 문구로 드러낸다. 메뉴를 제거해 주요 행동까지 숨기지 않는다.
- 관련 기록은 기록 영역에서 열린다. 읽던 정확 버전을 즉시 기준으로 삼고, 후보를 읽었다 돌아와도 기준을 유지한다. 관련 기록의 뒤로 가기는 원래 원문·버전·읽던 위치·검색 복귀 맥락을 되돌린다. 새로고침하면 임시 읽기 맥락을 추측하지 않고 기록 선택으로 복구한다.
- 내 페이지 기본 화면은 결과다. 같은 항목/원문 제목을 반복하지 않고, 원문·코멘트를 먼저 보인다. 표시·고정·원문 선택·순서·삭제는 항목 편집에, 페이지 제목·소개는 설정에 둔다. 숨긴 내용은 편집에서 다시 켤 수 있다. 미리보기와 공개 게시를 혼동하지 않는다.
- 작성자 관계·본문 확보 범위·이전 버전은 간략히 표시하고 상세 출처·정확 버전 열기는 편집에서 보존한다.
- 기존 CSS·네이티브 HTML을 사용한다. 전체 프레임워크 교체는 이 문제의 선행 조건이 아니다. 입력 DOM을 유지하고 원문 결과의 불필요한 재생성을 줄인다.

## 현실적인 내용 검토

익명 Apple 메모의 긴 독서/산책 기록, Instagram 캡션, Obsidian 독서 메모, 네이버 링크만 있는 자료를 사용한다. 가져오기 UI와 버전이 있는 읽기를 포함한다. 추천은 로컬의 실제 공통어·직접 주제·직접 묶음만 설명한다.

공통 표현 `보고`, `읽고`, `적고`, `남긴`은 단독 의미가 약한 행동 표현으로 단어 근거에서 제외한다. `문장` 같은 관심 영역 단어를 전부 금지하지 않는다. 명시 주제·묶음은 그대로 유효하다. 조사·어미가 다른 표현과 의미만 비슷한 글은 놓칠 수 있으며, 이번 작은 사례 집합은 일반 추천 정확도를 증명하지 않는다. 샘플에 맞춘 거대한 금칙어 목록이나 근거 없는 결과 채우기를 만들지 않는다.

## 다음 우선순위

1. 이 기준 흐름을 사용자 실제 자료로 체험하고 막힌 한 지점을 수정한다.
2. [기기 간 이어쓰기 계약](../life-tools-design/device-continuity.md)에 따라 내 페이지·묶음·초안의 연속성을 구현한다. 현재 로컬 전용이라는 한계를 숨기지 않는다.
3. 충분한 익명/동의 자료에서 관련 기록의 유용성과 누락을 평가한 뒤 검색·추천 방식을 바꾼다.
4. 그 뒤 새로운 연결·자동화 기능을 확장한다.

## 이번 구현과 검증

동일한 익명 샘플의 변경 전 사이트는 `f189196`을 복사해 별도로 실행했다. 변경 후는 이번 코드의 실제 앱이며, 서로 다른 개인 자료나 임의 시안으로 비교하지 않았다.

독립 디자인 검토에서 긴 항목의 편집 진입이 너무 멀고, 긴 원문 끝에서 관련 기록으로 가려면 위로 돌아가야 하는 문제를 발견했다. 제목행 연필로 기존 편집을 바로 열고, 원문 끝에도 같은 관련 진입을 추가했다. 새 검토에서 편집 초점 이동과 20문단 원문의 끝 진입/복귀 스크롤 3603 → 3603px·끝 버튼 초점 복원을 확인했다. 스타일을 더 장식하기보다 실제 사용의 막힘을 해결했다.

- 정적 검사: HTML 17 / JS 44 / 참조 231 / PWA 통과. Node 회귀 277 통과(현실적인 한글 단어 근거 사례 포함).
- [핵심 브라우저 결과](evidence/core-experience/browser-report.json): 5/5 흐름과 6개 화면, 가로 넘침·44px 조작·16px 입력·대비·이름 검사, 콘솔/페이지 오류 0. Playwright 1.63.0 + 시스템 Chromium 151.0.7922.173의 모의 Auth/실제 IndexedDB 검증이다.
- 영향을 받은 기존 회귀: Workbench 5/5, 선택/담기 2/2, 공개 사본 17/17 및 21상태, 글쓰기 12개 경로 모두 통과(최초 11/12 뒤 바뀐 복귀 조작을 반영해 실패 경로 1/1 재검증). 원문·구성 저장·미리보기·공개 사본 경계를 유지했다.
- 공용 진입은 최초 12/13 뒤 읽기 복귀 버튼 기대치를 갱신해 실패 경로 1/1 통과. 이전 제목 버튼이 사라진 것을 실제 보이는 뒤로가기로 바꿨고, URL 직접 이동으로 검사를 우회하지 않았다.
- 추가 상태 검토: Workbench 빈/로딩/오류/많은 자료 3폭 27상태, 다시 찾기의 키보드·저장 실패·계정 변경 및 3폭 15상태 통과. 콘솔/페이지 오류 0.
- PWA·계정 경계 9/9: 보존한 v67 사이트의 캐시를 삭제하지 않고 v68로 갱신, 기존 기기 데이터 유지. 모의 Auth의 의도한 전송/콜백 오류 2건은 실제 장애와 분리했다.

전체 검사를 이번에 전부 다시 실행했다고 합산하지 않는다. 위에 이번에 수행한 범위와 실패 후 재검증을 구분했다. 운영 자료·계정·SQL을 생성/변경하지 않았으며 실제 Google 로그인, Mac/iPad/iPhone IME·Files·VoiceOver·장기 사용의 유용성은 이번 검증 범위가 아니다.
