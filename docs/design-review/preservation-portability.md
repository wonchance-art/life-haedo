# 선택한 글과 정확한 근거의 비공개 이동

2026-10-18 KST. **보관 범위 확인 → 직접 선택 → 근거 포함 파일 → 현재 계정의 새 사본 → 같은 근거 재열기**를 로컬 앱에 연결했다. 아래는 구현·보존 계약과 현재 확인한 로컬 검수 결과다. 실제 기기 사용·새 서버 전송·배포 완료를 뜻하지 않는다. [다음 작업 2→3 묶음](../life-tools-design/roadmap.md)을 따른다.

## 얻을 결과와 포함 범위

처음에는 글 한 편과 직접 고른 9칸, 그 선택의 정확한 재열기에 필요한 근거만 다룬다. 보관 현황에 원문·초안·구성·컬렉션 등 여러 종류를 표시한다고 모든 종류를 한 파일로 백업하거나 계정 전체를 전송하지 않는다. 홈·작성기·기존 글 정리는 다른 세션의 변경을 존중하며 관리 안의 보관·복구 진입으로 연결한다.

| 포함할 내용 | 보존할 의미 |
| --- | --- |
| 직접 고른 글의 제한 Delta·첨부·원본 사진 | 사진 바이트·크기·해상도·순서·설명·대체 텍스트를 유지한다. 인용문과 직접 쓴 생각은 본문 그대로다 |
| 고른 글의 구조화된 인용 근거 | 원문 버전·원본 본문 SHA-256·UTF-16 범위·구절을 함께 확인한다 |
| 직접 고른 9칸 구성 | 해당 구성의 소개·영역 설명·선택 이유·첨부·정확 참조를 유지한다. 다른 구성은 따라오지 않는다 |
| 정확 근거에 필요한 원천과 선택 버전 | 원제목·출처·원 작성자·원문 작성일·확보 범위를 보존한다. 오래된 버전을 최신 버전으로 바꾸지 않는다 |

구절 위치와 본문 해시를 검증하려면 인용구보다 넓은 **해당 원문 버전의 전체 본문**이 파일에 포함될 수 있다. 선택 검토는 그 범위와 글·사진·근거 개수를 알려야 한다. 파일은 비공개 이동용이며 공개 미리보기나 공개 주소가 아니다. 사진의 EXIF/GPS를 지우거나 암호화된 파일이라고 설명하지 않는다.

## 따라오면 안 되는 내용

기존 `Core.makeBackup()`은 작업공간 전체를 복제한다. 이번에는 필요한 `sources`·`sourceVersions`만 투영하고, 관련 없는 원문·다른 버전·발췌의 `records.note`·연결의 `links.note`·`resumeHints`·`tombstones`를 끌고 오지 않는다. 컬렉션의 개인 메모·태그, 검토 초안·쓰던 다른 글·회고·책·연표도 자동 포함하지 않는다. 선택한 9칸 자체의 설명·선택 이유와 외부 컬렉션의 개인 메모는 구분한다.

Auth 세션·키·이메일 기반 소유 정보, 기존 owner·원격 연결·동기화 outbox·충돌 사본·작업 영수증·공개 토큰·게시 상태·읽기 위치는 이동 파일과 복원 사본에 승계하지 않는다. 원래 계정의 공개 글을 수정할 권한이나 서버 연결을 새 사본으로 이전하지 않는다. 서버 보관은 복원과 별개의 기존 명시 경로로만 시작한다. 이번에는 DB migration이나 sidecar 자동 원격 동기화를 추가하지 않는다.

## 계정 사본과 정확한 근거

계정은 인증으로 확인한 `projectUrl`·`userId`로 결정한다. 파일 안의 계정 정보나 이메일은 소유권의 근거가 아니다. 미귀속 자료는 소유 정보와 기존 동기화 귀속을 함께 확인하며 다른 계정에 귀속된 자료를 미귀속으로 취급하지 않는다. 타 계정 저장소를 자동 탐색하거나 소유 레코드만 덮어쓰지 않는다. 원본은 유지하고 현재 계정 안에 새 사본을 만든다.

작업공간·글·사진·구성/영역·원문/버전 ID와 내부 참조를 함께 재매핑한다. `NineBoard.copies()`는 구성·영역 ID만 바꾸므로 그것만으로 근거 이동이 끝나지 않는다. `SourceReference.remap()`은 원문 참조에 재사용하고, 저장 글 참조는 별도 글 ID·revision 매핑이 필요하다. 원래 revision의 본문 해시·구절을 먼저 검증한 뒤 복원 글의 실제 저장 revision에 연결한다. ID만 바꾸거나 같은 제목의 최신 글로 연결하지 않는다.

원문 텍스트의 CRLF·공백·유니코드를 정규화하지 않는다. `SourceReference.resolve()`의 정확 버전·해시·UTF-16 slice 비교를 유지한다. 원저자·작성 관계·출처·누락 표시는 복사한 자료의 메타데이터이며, 내 계정에 들어왔다는 이유로 타인의 원문을 내가 쓴 글로 바꾸지 않는다. 필요한 원문이 없거나 참조한 저장 글이 바뀌었다면 이를 표시하고 정확 재열기 성공으로 처리하지 않는다.

## 저장·현황·검수 기준

파일은 `life-preservation-package-v1`의 **해도 전용 무압축 ZIP**이다. `manifest.json`과 선언한 `photos/<글 ID>/<사진 ID>`만 읽는다. 기존 사진 글 ZIP·Obsidian ZIP의 읽기 계약은 바꾸지 않는다. 압축 방식 8(DEFLATE), ZIP64·암호화·추가 필드·주석·데이터 descriptor는 이 새 형식에서 지원하지 않는다. 일반 압축 도구로 다시 저장한 ZIP까지 호환한다고 표시하지 않는다. 로컬/중앙 헤더의 경로·크기·CRC32와 실제 바이트를 대조한 뒤 기존 fflate로 읽는다.

현재 상한은 글 20개·사진 200개·JSON 16 MiB·ZIP 전체 256 MiB이며, 기본 장면은 사진 몇 장을 붙인 작은 글이다. ZIP 전체를 메모리로 처리하므로 상한 크기의 모바일 처리 성공이나 스트리밍을 보장하지 않는다. 사진/본문 검증과 새 사본 설치는 이 전용 형식의 선언을 모두 확인한 뒤 진행한다.

ZIP 읽기·사진 해시/픽셀·본문 해시 등 비동기 검증을 끝낸 소유 snapshot만 설치한다. 기존 idb 트랜잭션 안에서는 계정·중복·revision 확인과 저장만 하고 외부 파일 처리·네트워크를 기다리지 않는다. 새 원문·글·사진·sidecar·9칸과 소유 정보를 함께 커밋하고, 실패하면 부분 설치 없이 원본·선택·기존 공간을 유지한다. 계정 전환·두 탭·저장 용량 실패·늦은 응답도 같은 경계를 따른다.

독립 정적 검토에서 최종 원본 확인 뒤 사진 검증을 기다리는 동안 원본이 바뀔 수 있는 경합을 발견했다. 로컬 준비 사본의 직접 복원은 원본 workspace·소유 범위와 검토 snapshot을 설치 API에 전달하고, 마지막 readwrite 트랜잭션 안에서 선택 글·인용 근거·9칸·필요 원문/버전을 다시 대조하도록 보완했다. 선택하지 않은 글·구성·원문의 변경이나 컨테이너 revision만으로 복원을 막지 않는다. 파일 복원은 이미 검증한 파일 snapshot을 기준으로 하며 원래 브라우저의 현재 상태에 의존하지 않는다.

현황은 접근 가능한 현재 계정의 실제 읽기 결과를 표시한다. 조회 실패를 자료 없음으로, 마지막 전송 성공을 현재 서버와 동일함으로 바꾸지 않는다. 파일 생성·다운로드 요청·사용자의 보관 확인·파일에서 실제 복원한 결과를 구분하며 브라우저 밖 파일의 존재를 추정하지 않는다. 새 사본 설치 성공 뒤 목록 조회 실패도 설치 실패와 구분한다.

상단의 선택 영역 이동은 같은 화면에서 초점과 스크롤만 옮긴다. 프래그먼트 히스토리를 추가하면 앱의 `popstate` 처리로 화면이 다시 만들어져 선택을 잃을 수 있으므로 이 링크의 기본 탐색만 억제한다. 실제 이벤트 실험에서 수정 전 재생성·선택 유실을 재현했고, 수정 후 URL·동일 DOM·선택·초점 유지와 재생성 없음, Node 22의 전체 8개 흐름을 확인했다. 다른 계정 접근 검사도 유효한 글 선택 요청이 정확한 권한 오류로 거절되는지 확인한다.

같은 선택으로 포함 범위를 다시 확인할 때도 이전 검토 후보를 먼저 무효화한다. 새 원문 검증이 완료되기 전의 이전 미리보기를 새 결과로 표시하지 않으며, 읽기를 지연시키는 회귀에서 검토 화면 제거·완료 후 새 결과 표시를 구분한다. 설치 실패 후 동일 파일 후보를 재시도하는 별도 경로는 유지한다.

## 실제 확인한 사용·보존 결과

로컬 앱에서 **관리 → 보관 범위·근거 파일 → 글/9칸 선택 → 포함 범위 확인 → ZIP 받기 → ZIP 열기 → 현재 계정의 새 공간으로 복원**한다. 복원한 공간을 열면 저장 글을 읽고, 9칸의 정확한 근거에서 옛 원문 구절과 저장 글을 다시 열 수 있다. 미귀속 공간을 고른 경우에도 원래 공간을 유지하며 현재 계정에 새 사본을 만든다. 현황 위에는 선택·파일 복원 영역으로 바로 이동하는 링크를 두었다.

최종 독립 브라우저 증거는 `tests/preservation-browser.cjs`와 `.local/preservation/report.json`·`unowned-final.log`의 **8개 흐름·18개 화면 상태**다. 기존 15상태에 미귀속 복원 경합 거절의 세 화면 폭이 추가됐다. 실제 로컬 앱·공용 SDK·IndexedDB와 다운로드한 ZIP 바이트를 사용하고 Auth는 합성 응답이다. Chromium 151.0.7922.173의 1440·820·390px 화면 모사이며, 콘솔·페이지 오류·예상 밖 외부 요청·원격 쓰기는 0건이다.

- 4032×3024 PNG와 1200×1800 JPEG의 원본 SHA-256·바이트 수·픽셀 선언과 실제 디코딩, 설명·대체 텍스트·새 사진 ID를 대조했다. 픽셀 선언만 바꾼 파일도 설치하지 않는다.
- 다운로드 ZIP에서 필요한 옛 원문 버전 1개와 정확한 CRLF 본문, 선택 글·9칸과 필수 근거 글을 확인했다. 미선택 원문/버전·글·9칸·초안·개인 메모·원격 연결/공개 토큰 sentinel은 없고, 선택한 9칸 자체의 설명은 유지됐다.
- 원문 본문·구절 범위·사진 바이트·ZIP 경로 변조와 실제 IndexedDB 설치 중단에서 부분 공간이 남지 않았다. 실패 뒤 같은 파일 후보로 다시 복원할 수 있었다. 기존 공간·글·다른 보관 형식은 유지됐다.
- 복원 후 새 workspace/source/version/post/photo/구성/영역 ID와 실제 저장 revision으로 참조를 재매핑하고, 9칸에서 옛 버전의 동일 UTF-16 구절과 근거 글을 실제 UI로 열었다. 다른 탭에서 바뀐 검토의 내보내기를 거절하고, 일부 현황 읽기 실패를 0개로 표시하지 않았다. 늦은 옛 계정 읽기는 렌더·설치하지 않았다.
- 미귀속 자료의 직접 복원에서 실제 사진 디코딩 뒤 원본 변경과 새 소유 계정 귀속을 각각 끼워 넣어 설치가 거절되는지 확인했다. 새로 확인한 선택만 현재 계정에 복원하고 기존 공간과 자료는 유지했다.

독립 제품 검토는 모바일 현황·선택 검토와 데스크톱 선택 검토 캡처를 직접 읽었다. 흰색/차콜 체계·한글 줄바꿈·포함 범위와 원본 메타데이터 안내가 명료했고 가로 잘림이 없었다. 최종 보고서 18상태의 자동 점검은 가로 넘침·작은 조작·이름 없는 조작·대비 실패가 없었다. 자동 지표와 실제 화면 검토는 별도 근거다.

전체 `npm test`는 **623/623**, 그중 저장 계층 검사는 **71/71**이다. 선택 범위의 변경·소유 계정 귀속을 최종 저장 시점에 거절하고, 선택하지 않은 자료의 변경은 허용하는 회귀를 포함한다. `npm run check`는 **19 HTML·104 JavaScript·410 로컬 참조**와 manifest/SHELL의 정적 검사를 통과했다. 근거는 `.local/preservation/unit-final.log`와 `static-final.log`다. 정적 SHELL 검사는 실제 PWA 업데이트·오프라인 실행을 대신하지 않는다.

기존 관리 화면 회귀, 원격 CI·실제 서비스워커 업데이트 결과는 별도 확인 중이며 위 수치로 완료를 추정하지 않는다. 원격 저장/RLS·실제 Google 인증·Apple Photos/Files·Mac/iPad/iPhone·모바일 최대 메모리·운영 배포는 이번 로컬 검수의 증거가 아니다. DB migration·sidecar 자동 동기화·전체 계정 백업을 구현하지 않았다.
