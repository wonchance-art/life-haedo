# 가져오기·내 페이지·재발견 품질을 병렬로 개선하기

2026-10-07. 사용자 지시 “로드맵 펼치고 넓게 넓게 적극적으로 진행”을 [전체 실행 로드맵](../life-tools-design/roadmap.md#현재-실행-로드맵--2026-10-07)과 [v8 전체 도식](../diagrams/README.md)으로 구체화했다. PR #38 `8a6731b`를 기준으로 독립 영역을 병렬 감사하고 실제 사용 불편을 수정한다. 기능별 구현 완료와 운영 마무리는 구분하며 운영 설치·병합·배포는 Local이 담당한다.

## 목표와 보존

자료 가져오기 → 원문 확인 → 저장한 결과 다시 열기 → 묶음/내 페이지에 구성 → 미리보기 → 편집 계속하기를 완결한다. 기존 흰 본문·옅은 색·A 인용 도형·작은 탐색을 유지하고, 새 화면 체계를 만들지 않는다. 원문 문자열/UTF-16·정확 버전, 출처, 검색 맥락, 입력 실패 복구, 계정/공간, 선택 동기화·백업·공개 사본, 연표 값은 보존한다.

이번은 기존 네이티브 폼·순서 배열·화면 상태의 보완이다. 기존 [소셜 가져오기 비교](social-import.md), [핵심 경험](core-experience.md), [재발견 선택 근거](rediscovery.md)를 재사용한다. 신규 런타임 의존성·SQL·외부 AI·SNS 연결은 도입하지 않는다. 후속 검색 인덱스/연결 기능 착수 때는 공식 최신 릴리스·라이선스·유지보수·실측 적합성을 새로 확인한다.

재발견 엔진은 이번에 바꾸지 않는다. 상투어 한 종류를 반복한 결과를 여러 독립 오탐의 일반적 증거로 확대하지 않는다. 현재의 오탐·누락과 다음 비교 조건은 [재발견 품질 평가](rediscovery-quality.md)에 둔다.

## 책임과 검증 방식

root가 전체 로드맵·공통 디자인·통합을 책임진다. GPT-6.1 Sol/high는 가져오기 UI, 내 페이지 UI, 필요한 공통 CSS, 독립 통합 QA를 각각 맡고 GPT-6 Astra/high는 재발견 평가와 저장/비동기 보존을 독립 검토한다. 같은 파일을 동시에 수정하지 않는다. CSS를 추가할 필요가 없는 화면에는 기존 패턴을 유지한다.

변경 전 고정 스냅샷과 동일 익명 한글 자료를 비교한다. 자료 확보 범위·URL·원문 버전·후보 선택·원문 참조가 흐름 끝까지 유지되는지 확인한다. 기능 검사, 1440·820·390px 시각 검토, 추천의 내용 평가, 실제 Apple 기기, 운영 배포를 각각 구분한다. 이 문서의 결과 절에는 실제 실행 결과만 기록한다.


## 이번 구현과 확인된 결과

- 저장한 원문이 현재 필터에서 보이지 않을 때만 `보관한 원문 읽기`를 보여준다. 저장 성공한 정확한 버전과 첫 발췌 위치를 열고 돌아오면 원래 검색어·필터·조작 초점을 유지한다. 작업공간 전환 때 성공 표시를 지운다.
- 실제 선택 해제는 후보 미리보기와 추가 버튼에 반영한다. 주제/메모를 입력하려고 초점을 옮길 때는 마지막 유효한 구절을 잃지 않는다. 후보가 없을 때 자료 보관을 주 조작으로, 취소는 16px 간격을 둬 구분한다.
- 내 페이지는 같은 고정 상태 그룹의 순서대로 위/아래를 이동한다. 끝에 도달하면 비활성 상태가 비동기 버튼 처리 후에도 유지된다.
- 미리보기 복귀는 같은 세션·revision의 펼침 상태·입력 선택·방향·내부 스크롤을 복원한다. 익명 코멘트의 선택 `13..31/backward`, 스크롤 `65px`가 세 폭에서 그대로 돌아왔고 이어 입력·재열기·저장 실패 후 재시도도 확인했다. 입력 문자열을 이전 값으로 되돌리지 않는다.

정적 HTML 17 / JavaScript 51 / 참조 252 / PWA와 Node **308/308** 통과. 재발견 보존 22개는 이 Node 합계에 포함된다. 가져오기 집중 검사 **3/3**, 내 페이지 집중 검사 **3/3**을 1440·820·390px에서 실행했다. 각각 console/pageerror/외부 요청 0이다. 독립 보존 리뷰에서 차단 결함은 발견되지 않았다.

## 기존 검사와 진단

기존 모음 6/6, 홈의 가져오기/읽기 관련 2/2, 핵심 경험 5/5도 통과했다. Workbench 전체 첫 실행은 16/17이었다. 실패한 1건은 미리보기 복귀 초점이 항상 버튼이라는 이전 기대였으며, 현재 계약인 같은 코멘트 입력·열린 편집·값 보존으로 보강한 뒤 그 경로 1/1을 재검증했다. [첫 결과](evidence/product-flow-quality/page-existing-workbench-report.json)와 [집중 재검증](evidence/product-flow-quality/page-existing-workbench-recheck.json)을 구분하며 전체를 다시 실행했다고 보고하지 않는다.

여러 파일 가져오기에서는 기존 사용자 경로 6개가 통과하고 두 탭 CAS 경로가 오래된 메뉴명 `모아보기`에서 멈췄다. 실제 `기록 검색`으로 selector를 고쳐 해당 경로 1/1을 재검증했다. 마지막 콘솔 검사를 사용자 시나리오 개수에 합산하지 않는다. 새 동작을 우회하거나 앱 메뉴를 검사에 맞춰 되돌리지 않았다.

통합 검사의 수정본 시나리오는 제목만 같으면 기존 원문과 자동 연결된다고 가정해 최초 대기에 실패했다. 본문이 달라지고 출처 식별자가 없으면 별도 원문을 만드는 현재 계약은 정상이다. 후속 보존 검사에는 같은 익명 출처 URL을 제공하고 사용자가 검토에서 같은 자료로 확인하는 경로를 사용한다. 자동 병합을 새로 구현하지 않았다. 초기 캡처와 후속 보존 검사 fixture의 이 차이를 구분한다.
