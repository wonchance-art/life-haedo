## 캡처 전의 잠정 추천

**A를 먼저 비교한다.** 앞 문단을 6~8줄 읽고 코멘트로 넘어가는 방식이 현행 본문 중심 화면과 가깝다. 짧은 글은 전부 보이고 펼치기를 만들지 않아야 한다. 다만 첫 항목이 원문 두 개와 긴 코멘트로 구성되면 A도 다음 활동을 너무 늦게 보여줄 수 있다.

B는 같은 항목의 출처 두 개를 빠르게 구별하고 다음 활동을 찾는 데 유리할 수 있다. 반대로 3~4줄이 문맥을 끊고 작은 제목·메타가 본문보다 더 많이 보이면 링크 목록처럼 느껴질 수 있다. 단일 원문 항목에 항목 제목과 원문 제목을 중복 표시하면 B의 구분 효과가 사라진다. 줄 수는 영구 규칙이나 합격점이 아니라 같은 자료에서 검증할 가설이다.

두 안의 비교 과제는 **첫 활동의 코멘트 찾기, 두 원문의 확인된 작성 순서 설명하기, 짧은 일상 글 전체 읽기, 이전 버전 원문을 열고 같은 자리로 돌아오기**다. 펼치기 횟수·코멘트 시작 위치는 설명 자료로만 쓰고 적은 클릭 수를 곧바로 더 좋은 읽기 경험으로 판정하지 않는다. 실제 시안의 세 폭과 펼침 상태를 본 뒤 root가 선택한다.

## 반드시 반대 검토할 세 가지

1. **말줄임과 접근 가능한 접힘은 다르다.** `line-clamp`/`overflow:hidden`만으로는 숨겨 보이는 텍스트와 보조기술·선택/복사의 범위가 일치한다고 보장할 수 없다. 누구나 찾을 수 있는 `본문 펼치기`·`본문 접기`와 native summary 또는 정확한 `aria-expanded`/제어 대상이 필요하다. 미리보기와 전체 본문을 함께 넣었다면 펼친 상태에서 앞부분이 두 번 읽히지 않도록 한다. 전체 원문 문자열은 보존하고 접힌 영역에 초점 가능한 조작을 남기지 않는다. 접은 뒤 해당 조작으로 초점을 돌리며, 짧은 본문에는 불필요한 조작을 만들지 않는다. 키보드 Tab/Space/Enter와 터치·스크롤을 별도로 확인하고 실제 스크린리더 검사 없이 접근성 전체 통과를 주장하지 않는다.
2. **가져온 날짜는 활동 날짜가 아니다.** 선택한 정확 버전의 `originalCreatedAt`만 `원문 작성일`로 표시한다. `importedAt`·페이지 저장 시각·최신 버전의 날짜로 빈칸을 채우지 않는다. 서로 다른 날짜의 원문 두 개를 한 항목으로 묶었다는 이유로 항목 전체에 활동일을 만들지 않는다. 모르는 날짜는 미상으로 남기거나 생략하며 기존 수동 순서를 날짜순으로 재해석하지 않는다.
3. **본문을 접는 것은 공개 범위를 바꾸지 않는다.** 화면에서 접은 길이, 사용자의 본문 표시 선택, 공개 사본에서 선택한 본문/인용은 서로 다른 상태다. `본문 펼치기`로 업로드 범위가 늘거나 `접기`로 공개 철회가 된다고 표시하지 않는다. 비공개 미리보기·원문 포함 설정·공개 사본 검토/게시의 기존 구분을 유지한다. ‘숨김’이라는 단어 하나로 세 상태를 함께 설명하지 않는다.

이 세 항목을 지키면서 A/B가 글·코멘트 이해를 더 어렵게 만든다면 접힘 자체를 기각하고 날짜와 상단 조작의 위계만 정리하는 선택도 유효하다. 아직 어느 안의 실제 유용성·Apple 기기 체험·운영 앱 적용이 확인된 것은 아니다.
