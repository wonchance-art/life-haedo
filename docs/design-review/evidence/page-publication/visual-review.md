# 공개 사본 브라우저 검토

실제 앱·동봉 SDK·IndexedDB를 사용하고, Auth 및 공개 RPC HTTP만 익명 모사했다. 운영 SQL/RLS·실제 Google 로그인·실제 공개 게시를 증명하는 검사는 아니다. 원문 서비스 요청은 없었다.

기능 검사와 시각 검토는 분리했다. `verification-summary.json`은 분할 실행의 최신 결과와 원본 `run-*.json`을 연결하는 증거 목록이다. 최초 철회 응답의 publicId 계약 불일치와 수정 후 재검증 기록을 보존하며 단일 전체 재실행으로 표현하지 않는다.

- 검토·명시 게시·익명 읽기·갱신·철회·재게시를 확인했다. 원문 본문은 작성자 관계와 무관하게 기본 제외되며 명시 선택한 자기 본문과 정확한 CRLF/UTF-16 발췌만 게시된다. 숨긴 소개·항목·최근 항목·부분·본문·메모, 원본 ID·개인 작업공간 필드는 공개 사본에 없었다.
- 익명 화면은 exact-ID 읽기 RPC만 요청했다. Auth/개인 저장 모듈·IndexedDB 열기·localStorage 쓰기는 0이고 fetch는 no-store였다. 잘못된 ID·중복 ID·잘못된 원격 사본은 표시하지 않으며 HTML 문자열은 텍스트로만 나타났다.
- 로컬 편집은 공개 사본에 자동 반영되지 않는다. 검토 후 구성이 바뀌면 전송 전에 재검토를 요구한다. 응답 유실 재시도는 같은 operation을 사용했고, 서버 철회 후 과거 게시 영수증을 받아도 최신 상태를 다시 읽어 재공개하지 않았다.
- 계정 변경·늦은 응답·offline·pageshow/pagehide·실제 페이지 이동 후 뒤로 가기에서 철회된 본문을 다시 표시하지 않았다. 타인이 이미 내려받은 외부 사본은 철회할 수 없다는 한계는 그대로다.
- 같은 계정의 새 브라우저에서 개인 자료가 0개여도 원격 공개 목록을 찾고 철회할 수 있었다. 51개는 50+1로 조회되고 다른 계정의 항목은 섞이지 않았다. 철회 확인 뒤 서버 revision이 바뀌면 확인을 폐기하고 새 확인을 요구했다.
- 1440·820·390px에서 공개 검토·많은 기록·빈 페이지·불러오기·오류·공개 종료 18상태와 공개 목록 3상태를 측정했다. 가로 넘침·이름 없는 조작·44px 미만 조작·16px 미만 입력은 없었고 작은 글자 대비 최소 6.05:1이었다.
- 공개 1440/390, 관리 390, 오류 390 스크린샷을 육안 확인했다. 긴 한글 제목이 줄바꿈하고 항목·출처·작성자의 코멘트가 구분된다. 첫 원문 제목과 항목 제목이 같을 때 반복 출력을 제거한 뒤 대표 화면을 다시 확인했다.
- 키보드 Space로 본문 opt-in과 동의를 조작하고 Enter로 게시했다. 390px 터치 설정에서 공개 재조회와 관리의 철회 진입에 tap 이벤트를 사용했다. 화면 크기·터치 설정 모사이며 Apple 기기·실제 한국어 IME·Files 검증은 아니다.
