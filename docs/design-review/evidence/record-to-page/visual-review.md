# 기록 선택 → 묶음·내 페이지 검증 메모

검증 범위: 실제 로컬 앱·동봉 SDK·IndexedDB + 익명 Auth HTTP 모사. 운영 Supabase/SNS 요청 없음. Chromium의 1440×1000, 820×1000, 390×844 화면 크기 및 터치 설정을 사용했으며 Apple 실기·실제 한국어 IME·Files 검증은 아님.

- 기능 검사는 분할 실행 결과를 `verification-summary.json`에서 실행별 원본 JSON과 연결한다. 최초 실패와 후속 재검증을 보존한다. 기능 11개와 시각 흐름 3개가 최종 통과했다.
- 시각 검토는 빈 목록, 많은 자료·선택, 검색 밖 선택, 구성 로딩, 담을 기록 검토, 저장 오류를 각 3폭에서 확인했다. 최소 작은 글자 대비는 6.05:1. 가로 넘침, 이름 없는 조작, 44px 미만 조작, 16px 미만 입력은 없었다.
- 첫 캡처 이후 선택 전 빈 체크박스/선택 후 체크 표시, 선택 목록 펼침 화살표, 검토 중 불필요한 저장 버튼 숨김을 반영했다. 수정 후 `many-selected-1440.png`, `review-820.png`, `review-390.png` 대표 화면을 다시 캡처하고 육안 확인했다. 원본 18상태 전체를 재실행했다고 보고하지 않는다.
- 긴 한글 제목은 조작영역을 밀거나 겹치지 않고 줄바꿈한다. 390px에서는 제목이 여러 줄이 되어 검토 폼이 길어지지만, 체크·출처·항목 제목·명시 추가 순서가 유지된다. 선택 피드의 빈 체크박스와 선택 상태가 색상 이외에도 구분된다.
- fullPage 390px 스크린샷에는 고정 하단 메뉴가 뷰포트 기준 높이에 기록된다. 폼 하단의 `내 페이지에 추가`는 스크롤 후 터치 이벤트로 실제 활성화해 도달 가능함을 검증했다. 실기 소프트 키보드 겹침은 미검증이다.
- 저장 오류 뒤 입력과 생성 초안 한 개가 남고, 다시 저장해도 중복 생성되지 않는다. 다른 탭에서 구성 변경 후 새 저장본 읽기는 검토 중 제목·체크·목적지를 보존하며 삭제된 목적지를 임의의 새 묶음으로 바꾸지 않는다.
- 원문·버전·출처·UTF-16 위치, 기존 페이지 사본, 새 백업 사본의 재매핑·원본 불변성을 실제 IDB에서 비교했다. 선택/검토/취소만으로는 원문이나 구성 쓰기가 발생하지 않는다.
