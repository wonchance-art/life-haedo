# 회고 → 목차 구성: 실제 앱 수정 후 QA

2026-10-09 KST. [변경 전 감사](../before/audit.md)와 같은 익명 자료를 실제 UI로 가져와 비교했다. 자료 6개, 불변 원문 버전 7개, 과거 버전에 연결한 발췌 1개다. 처음 선택한 과거 원문은 2,217자, 현재 생각은 920자이며 기존 익명 책 샘플의 서로 다른 문단을 사용했다. 운영 DB·실제 계정·개인 자료를 사용하지 않았다.

[합산 보고서](../combined-report.json)는 실행별 원본, 최종 폭별 검사, 최초 검사 방법 오류·보정 이유와 이후 확인한 실제 앱 결함을 구분해 기록한다. 실제 기능 3폭은 마지막 코드에서 한 번의 전체 실행으로 모두 통과했고, 최종 기본 9장 캡처는 하나의 고정 코드 실행 `2026-10-08T21:53:22.807Z`에서 얻었다. 수정 전 시안/메모리 화면 검사가 아니다.

## 결과와 남은 실제 의미

- 회고 첫 화면에서 원문 앞 문단을 읽을 수 있다. 저장 정보와 긴 안내를 먼저 지나야 했던 배치가 정리됐다. 390px 첫 원문 행은 y627→363으로 올라왔다.
- 현재 생각 자체는 여전히 선택한 자료 뒤에 있다. 앞 문단을 보여 주면서 절대 위치는 더 아래로 내려갔지만, 고정된 쓰기 아이콘으로 바로 이동하고 생각 제목 옆의 고정 복귀 아이콘으로 **같은 자료·같은 위치**에 돌아간다. 단순히 현재 생각의 y값이 낮아졌다는 주장과 구분한다.
- 목차 만들기는 상단에 고정돼 전체 후보를 끝까지 내려가야 찾는 문제가 없어졌다. 후보의 포함 표시는 번호와 체크로 간결해졌고, 접근 이름은 `장 N 포함`으로 유지됐다. 390px 생성 버튼은 y1904→126, 첫 후보는 y693→586이다.
- 회고에서 목차로 갔다 닫을 때 작성 중 선택 15~36과 pageY가 그대로 복구된다. 펼친 원문도 유지된다. 목차의 원문을 열고 돌아오면 정확한 이전 버전, 후보의 열린 상태·변경한 제목·포함 체크·원래 원문 버튼 초점이 모두 유지된다.

## 의미 있는 기능 검사

`tests/reflection-to-outline-browser.cjs`를 새로 추가했다. 기존 앱/기존 테스트는 이 QA 담당자가 수정하지 않았다. 기존 workshop의 실제 가져오기 helper와 익명 샘플을 재사용했고, 자료·구성은 IDB에 직접 미리 만들지 않았다.

1. 선택한 정확한 과거 원문을 펼치고 내부를 읽은 뒤 쓰기 → 현재 생각 입력 → 같은 자료/내부 스크롤/초점으로 복귀했다. 390px에서는 현재 생각에 도착한 뒤 쓰기 아이콘을 한 번 더 눌러도 처음 읽던 자료 위치를 유지하는지 확인했다.
2. 현재 생각은 자동 높이로 표시됐고, 실제 한글 문자열을 중간에 삽입해도 pageY가 바뀌지 않았다. 저장된 결과는 bounded polling 안에서 `await page.evaluate`로 확인했다.
3. 목차에서 첫 장 제목 수정, 미상 시기 후보 해제, 정확 원문 열기/복귀를 거쳤다. 제목·질문·열림·체크·초점이 보존됐고, 책을 만들지 않은 검토만으로 구성은 변경되지 않았다.
4. 목차 닫기 뒤 현재 생각의 선택 범위와 viewport 위치가 복원됐다. 390px의 합성 조합 이벤트 중 목차 기준 전환과 닫기는 차단됐고, 입력값은 남았다.
5. 390px에서 실제 IDB 저장을 실패시켰을 때 목차 진입은 차단되고 현재 생각이 남았다. 상단 오류와 다시 저장 조작이 보였고, 실패를 해제한 후 같은 값이 저장됐다.

원문·발췌·선택의 정확 버전은 변하지 않았다. 비교 감사의 3폭에서도 작성 연도 필터가 저장 선택을 바꾸지 않으며, 실제 묶기 검토를 거친 묶음이 정확한 교집합만 포함하는 것을 확인했다. 원고·책을 자동 생성하지 않았다. console/pageerror/예상하지 않은 외부 요청/운영 쓰기는 0이다.

최종 기본 9화면과 상호작용 장면에서 가로 넘침·44px 미만 조작·16px 미만 입력·접근 이름 누락·계산된 대비 실패는 없었다. 기본 9화면의 최소 텍스트 대비는 5.889였다. 접근성 수치 통과만으로 전체 사용성의 합격을 주장하지 않는다.

## 실행 이력의 구분

최초 상호작용 실행은 async `waitForFunction`이 IDB의 저장 조건보다 먼저 완료되어 저장 전 revision 2를 비교 기준으로 잡았다. 목차 진입이 정상적으로 저장한 revision 3과 달라져 실패했으며 앱의 데이터 손실은 아니었다. 이후 실제 값을 await하는 Node 반복 대기로 수정했다.

최종 390px 최초 추가 검사에서는 조합 중 **회고의 묶음별 표시 전환**도 오류로 막아야 한다고 과하게 기대했다. 이 전환은 생각 입력 DOM을 유지하므로 해당 기대만 제거했다. 입력을 교체할 수 있는 **목차 기준 전환·닫기**의 조합 차단 검사는 유지했다. 기대 보정 뒤 통과한 세 폭을 마지막 취소 guard까지 포함한 전체 실행으로 다시 확인했다. 반복 누름 결함 수정까지 반영한 최종 원본은 `run-2026-10-08T22-02-57-577Z.json`이며 3/3 통과, 상호작용 화면 10장이다. 같은 케이스를 여러 번 더해 검사 수를 늘리지 않았다.

최종 자체 검토에서 **현재 생각 안에서 쓰기 아이콘을 반복 누르면 읽던 자료가 바뀌는 실제 앱 결함**을 확인했다. `run-2026-10-08T22-00-51-818Z.json`의 390px 경로는 기존 복귀 위치 assertion에서 실패했다. 화면에 교차하는 원문이 없을 때 마지막 행을 대신 기억하던 fallback을 root가 제거했고, 기존 읽기 위치를 유지하게 고쳤다. 같은 반복 조작을 유지한 채 최종 세 폭 전체 실행을 통과했다. 이는 앞의 테스트 대기·기대 보정과 별개의 앱 수정이며, 기본 9장 배치는 변하지 않아 다시 촬영하지 않았다.

추가로 목차 후보 원문 버튼과 닫기를 같은 JS task에서 연속 호출하는 합성 취소 계약 1개를 검사했다. 닫힌 후보의 원문이 뒤늦게 열리지 않고 회고·구성이 유지됐다. 임시 목차는 실제 dirty 구성을 만들지 않으므로 저장 지연이나 사람이 누르는 속도를 재현했다고 주장하지 않는다. 가짜 dirty 상태도 주입하지 않았다. 원문 행이 분리된 뒤의 비동기 취소 guard를 확인한 별도 계약이다.

기존 책 배치 테스트에는 async IDB 대기를 별도 보완할 여지가 남지만 이번 허용 범위 밖이라 수정하지 않았다. 이번 새 테스트는 같은 방식을 사용하지 않는다.
