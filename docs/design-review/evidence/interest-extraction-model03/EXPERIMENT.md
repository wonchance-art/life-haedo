# MODEL-03 실행 범위

## 목표와 완료 기준

선택한 한국어 자료의 관심 주제와 서로 다른 본문의 반복 질문을 정확한 원문 근거와 함께 제안할 수 있는지 검증한다. 후보 생성과 함의 검증을 분리하며 질문 검출·후보 검색·의미 판정을 각각 평가한다. 이번 작업의 완료는 새 독립 자료의 실제 모델 실행, 독립 채점, 채택/기각 이유와 다음 사용 단위 기록이다.

이전 MODEL-02의 48문서 기각과 NLI 12쌍의 제한된 가능성 판정은 그대로 보존한다. 새 평가의 결과를 앞선 평가의 재채점으로 표시하지 않는다.

## 작업 경계

- 제품 원본 `/workspace/life-haedo`는 수정하지 않는다. 활성 저장소는 `/workspace/haedo-discovery`다.
- 새로운 후보와 runner는 이 폴더에서만 구현한다. 평가 중 앱의 분석 활성화·다운로드 모델·저장 형식·PWA 셸은 변경하지 않는다.
- 평가 자료는 새로 작성한 합성 자료이며 실제 계정·개인 문서·운영 DB·유료 API를 사용하지 않는다. 문서 본문을 외부 서비스에 전송하지 않는다.
- 공개 모델과 런타임의 고정 버전만 명시 다운로드한다. 임베딩과 NLI를 실제 CPU에서 실행하고 입력 토큰 수와 절단 여부를 기록한다.
- 주제 관련성과 작성자의 신념·사용자의 현재 관심을 구별한다. 저자 미상은 미상으로 남기며, 반복 지지에서 같은 본문 SHA를 두 개로 세지 않는다.

## 독립성

- 평가 담당자는 새 정답과 본문을 사전 봉인하고, 후보 구현자는 공개 개발 자료만 사용한다.
- 구현·예산·임계값·모델·runner를 동결한 뒤 입력 전용 자료를 공개한다. 정답은 runner에 전달하지 않는다.
- 동결 전 인터페이스와 평가 범위의 수정은 가능하다. 동결 후 결과를 보고 같은 자료에서 임계값·규칙을 고쳐 재합격시키지 않는다.
- 추론·채점·코드 검토에서 발견한 결함과 실행 실패를 의미 정확도 실패와 구별해 기록한다. 수정 실행이 필요하면 동결 변경 이유와 결과의 탐색적 성격을 명시한다.

## 판정과 비용

사전등록의 최소 채택 문턱은 주제·질문별 근거 정밀도 95%, 주제 문서 macro recall 70%, 반복 질문 recall 70%, 금지 근거 0, 정확 source/hash/UTF-16 구간 100%, 무음 절단 0이다. 세부 분모와 정확성 검사는 평가 담당자의 사전등록을 따른다.

전체 원문 순회와 모델로 실제 의미를 검사한 범위를 구분한다. 예산을 초과한 항목은 부분 처리로 보고하며 전체 처리로 표시하지 않는다. 모델 준비·추론 시간, 입력·후보·모델 호출 수, 관측 메모리와 관측 한계를 남긴다.

합성 자료 통과만으로 제품 활성화하지 않는다. 원문 신뢰성·질문 누락·기권·성능과 실제 Apple 기기 수용 조건을 함께 검토한다. 결과와 다음 우선순위는 저장소의 검토 기록·로드맵·PR에 반영한다.
