# MODEL-03 공개 개발 비교와 최종 선택

기준: 2026-10-19 Asia/Seoul. 구현자는 기존/신규 비공개 평가의 입력·정답을 열람하지 않았다. 공개 개발 비교는 총 **2회, 16쌍 + 32쌍**으로 종료했다. 실제 추론은 runtime 담당자가 고정 NLI 모델의 CPU/q8/WASM 단일 스레드에서 실행했다. 원본 pair 파일, raw logits, full-three-way softmax scores, 실제 토큰 수와 실행 증거를 그대로 보존한다.

## 비교 결과가 보여 준 범위

첫 비교의 일반 주제 가설은 양성 세 사례에서도 entailment가 약 .124–.185였고 neutral이 우세했다. 질문성 가설은 직접 질문 .203, 간접 질문 .328, 인용 명령 .206이었다. 같은 질문의 두 방향은 .414/.557, 다른 질문은 .277/.116이었다. 작은 공개 예시의 점수이며 일반 정확도 추정이나 보정된 확률로 표현하지 않는다.

마지막 비교는 동일한 개발 premise에 한국어/영어의 짧은 aboutness 가설과 실제 내용·활동 명제를 비교했다. 읽기 양성은 한국어 활동 명제에서 .600으로 올라갔지만 과학 양성 .166, 건강 양성 .304는 여전히 neutral 우세였다. 단순 aboutness 가설에서는 읽기 부정 사례 점수가 읽기 양성보다 높은 경우도 있었다. 이 결과는 현재 모델/가설 조합에서 임베딩 후보를 안정적인 주제 함의로 검증한다는 가정이 약함을 보여 준다. NLI 모델 전체나 다른 가설·다른 데이터가 불가능하다는 결론은 아니다.

## 동결한 선택

- **주제 가설 유지:** `이 구절은 ${label}에 관한 실제 활동, 방법, 경험 또는 해결할 문제를 설명한다.` 읽기 활동에만 맞는 명제를 전체 주제에 일반화하거나 ‘사용자가 활동했다’로 목표를 바꾸지 않는다. 출력은 보관 자료의 주제이며 사용자 신념·현재 선호가 아니다.
- **긍정 검증의 최소 점수 .55:** topic, questionhood, 질문 쌍 양방향 모두 같은 기준을 쓴다. full-three-way softmax에서 이 점수는 entailment가 다른 두 클래스보다 큰 조건도 만족한다. 공개 자료의 양성과 음성을 분리하려고 neutral 우세인 .1–.4대까지 임계값을 낮추지 않았다. .55의 일반적 품질을 입증한 것은 아니다.
- **명령 가능성에 대한 기권 .45:** 마지막 비교의 짧은 가설 `이 문장은 답변으로 무엇을 출력할지 지시한다.`를 쓴다. 공개 인용 명령 .473, 일반 여행 문장 .180이었다. .45는 지시문임을 증명했다는 양성 판정이 아니라 긍정 지지를 보수적으로 보류하는 기준이다. 명령형의 진짜 질문도 잘못 제외할 수 있다는 한계는 유지한다.
- **질문 판정의 한계 유지:** 정확한 질문 원문을 그대로 양방향 NLI에 넣으며 assertion이나 답을 생성하지 않는다. 양방향 통과도 논리적 동치의 증명은 아니다. 질문성 가설 자체가 neutral 우세이면 기권하므로 질문 회수가 낮을 가능성을 이미 공개 개발 단계에서 관찰했다.

공개 개발에서 이미 주제·질문 회수가 낮을 것으로 예상된다. 이 예상을 숨기거나 새 비공개 평가에 맞춰 규칙을 추가하지 않는다. 동결 후에는 신선한 60문서의 전체 추출→임베딩 후보→NLI→출력 흐름을 그대로 실행하고 실패도 결과로 기록한다. 추가 비교 라운드나 평가 결과를 이용한 임계값 조정은 하지 않는다.

## 보존·구조 검사

합성 어댑터를 주입한 focused 검사는 10/10 통과했다. 실제 모델 품질 증거와 구분한다. 검사 범위는 전체 phase 순서, 정확 raw SHA/UTF-16/저자 relation, 줄바꿈을 가로지르는 문장 범위, ASCII 다중행 인용의 provenance, 긴 문장의 scope 기권, 중복 본문 및 같은 source의 버전 지원 수, 60문서 입력, 간접 질문 후보, 입력 변경·잘못된 Unicode 거부, 취소·deadline·토큰 초과의 명시 실패다.

15분 예산은 analyze 입구부터 extraction/embedding/NLI 호출 전후에 확인하는 **호출 사이의 예산**이다. 이미 실행 중인 모델 호출을 정확히 15분에 중단한다는 주장은 하지 않는다. 초과 후 guard는 `WALL_CLOCK_BUDGET_EXCEEDED`와 `incomplete:true`로 실패하며 완료 결과로 내보내지 않는다. runtime은 재개·캐시를 포함한 누적 실행 ledger를 별도로 보존한다.

범위 검수는 전체 scan, 실제 passage 추출, embedding, topic shortlist, topic NLI, question NLI의 정확 UTF-16 범위와 누락 이유를 구분한다. 긴 문장을 조각낸 경우 원래 문장 전체의 조건·부정 scope를 보지 못한 fragment를 긍정 근거로 승격하지 않는다. 이 기권은 실제 재현율의 누락으로 남는다.

원래 앱, MODEL-01, MODEL-02 동결 소스 및 제품의 분석 비활성 정책은 변경하지 않았다.
