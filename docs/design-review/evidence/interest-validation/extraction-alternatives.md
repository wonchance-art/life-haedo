# MODEL-02 이후 추출 구조 대안

작성 기준: 2026-10-19, Asia/Seoul. 동결한 MODEL-02 구현은 수정하지 않았다. 구현자는 독립 평가의 요약 수치만 전달받았으며 held-out 본문·정답·개별 실패 항목을 열람하지 않았다.

독립 평가에서 보고된 precision 90%, topic recall 26%, question recall 0%, forbidden support 1건은 현재 후보를 활성화하기에 부족하다. 이 수치로 원인을 특정할 수는 없다. 아래는 소스 구조에서 확인되는 한계와 다음 실험의 범위다. 원래 평가에 맞춰 임계값이나 예외 목록을 조정하는 제안이 아니다.

## 소스 구조에서 확인되는 한계

- **주제 유사도는 긍정 지지나 함의를 판별하지 않는다.** 문장·문맥과 주제 prototype이 가깝다는 사실만 계산한다. 부정·역사적 인용·상대방 입장·가정·논박의 대상을 완전히 구분하지 못한다. eligibility 정규식은 제한된 명시 표현에서만 기권시킨다. 알려진 부정어 목록을 늘리는 것만으로 이 간극을 해결하기 어렵다.
- **주제 하나를 우세한 승자로 고르는 규칙은 주제 간 중첩을 손실시킨다.** 교육/배움, 기술/연구처럼 관련된 prototype들의 점수 차이가 작으면 모두 탈락한다. 두 prototype 점수의 평균과 70/30 문맥 혼합은 별도의 한국어 calibration 없이 고정한 가설이다. 문맥을 더한 결과가 근거 문장 자체의 의미를 강화한다는 보장이 없다.
- **문맥은 원문상 가까운 세 문장의 요약이 아니다.** eligibility를 통과한 인접 조각을 합치므로 제외된 문장이나 긴 간격을 건너뛸 수 있다. 여러 문장을 한 벡터로 압축하면 서로 다른 질문의 세부 차이가 사라지거나, 같은 질문이 주변 주제 차이로 멀어질 수 있다.
- **질문 경로의 여러 제한은 함께 재현율을 낮출 수 있다.** 물음표가 있는 조각만 대상으로 삼고 문서당 최대 8개를 표본으로 고른다. 간접 질문·문장형 질문은 놓친다. 모든 기존 군집 구성원과 질문 cosine 및 문맥 cosine 조건을 동시에 만족해야 하므로 하나의 경계 사례가 군집을 분리할 수 있다. 반대로 문장 유사도만 높다고 질문의 논리적 요구가 동일해지는 것도 아니다. question recall 0%의 실제 원인은 개별 중간값을 보지 않고 단정할 수 없다.
- **표본과 토큰 범위는 서로 다르다.** 280 UTF-16 문자 분할은 tokenizer의 토큰 한도와 같지 않다. 문서당 12개 표본은 초기 후보보다 넓지만 긴 문서 전체를 읽는 경로는 아니다. coverage 수치는 보이는 제한을 설명할 뿐 누락을 복구하지 않는다.
- **보수적 제외는 해석 오류와 함께 유효 자료도 줄인다.** 일반 인용문 전체를 제외하고 명시적 부정 문장에서도 긍정적으로 다루는 다른 주제를 잃을 수 있다. 현재 방식은 타인 글의 주제를 사용자의 신념으로 부르지는 않지만, 인용의 주제와 현재 선호의 구분을 충분히 모델링하지 않는다.

NLI와 질문 임베딩은 대체 가능한 동일 기능이 아니다. NLI는 문장과 명시 가설 사이의 관계를 검사하고, 질문 임베딩은 문장 쌍의 유사성을 검색한다. 둘 다 원문 출처·선택 범위·사용자 확인을 대체하지 않는다.

## 질문 전용 신규 후보의 한정된 설계안 — 미구현

**목표:** 선택한 서로 다른 원문에서 사람이 함께 검토할 만한 질문 쌍을 제시한다. 관심 주제·성격·신념을 생성하지 않으며, 일치가 입증된 ‘반복 질문’ 대신 ‘비슷한 질문 후보’라고 표시한다.

1. 선택한 원문 전체를 순회하면서 명시 질문 후보의 정확 UTF-16 범위를 추출한다. 물음표 외의 한국어 질문 종결형 지원 여부는 별도 검출 검사로 정한다. 인용·대화·과거 표현의 상태는 근거 옆에 남기고, 이를 현재 질문으로 자동 승격하지 않는다. 기존 원문은 수정하지 않는다.
2. 전체 문서나 주변 세 문장을 하나의 필수 양성 조건으로 삼지 않고 **질문 구간 자체의 벡터**로 후보 쌍을 찾는다. 주변 문맥은 원문 확인에 보여 주며, 문맥을 추가한 벡터가 도움이 되는지는 별도의 개발 split에서 비교한다.
3. 동일 본문 SHA는 독립 지지로 세지 않는다. 초기 버전은 군집 전체의 공통 주장을 생성하지 않고 두 원문의 질문 쌍과 원문 복귀만 제공한다. 이 선택은 pairwise 유사성의 비추이성으로 인한 군집 확장을 줄인다.
4. tokenizer를 이용할 수 있다면 실제 토큰 한도 안에서 입력을 구성한다. 입력 예산을 넘으면 질문 일부를 조용히 버리지 않고 분석한 질문 수/전체 탐지 질문 수와 부분 처리 상태를 반환한다. 비교 비용은 상위 후보 검색으로 제한하되 탈락 원인별 집계를 남긴다.
5. 사용자가 두 원문을 보고 연결을 확인하거나 제외한다. 제안은 로컬 메타데이터에만 보관하고 원문·저자·공개 상태를 바꾸지 않는다. 개인 본문은 외부 서비스로 보내지 않는다.

이 설계는 현재 임베딩 모델과 CPU Worker를 재사용할 수 있어 작은 실험은 가능하다. 다만 현재 결과만으로 새 후보의 정확도나 질문 회복을 예상 수치로 제시할 근거는 없다. 구현 승인이나 다음 출시 범위로 간주하지 않는다.

## 다음 실험을 한다면

새로운 개발 자료와 새로운 비공개 held-out 자료를 사전에 분리한다. 이번에 이미 평가한 held-out을 개발 자료로 재사용하거나 그 개별 정답에 맞춰 예외를 추가하지 않는다. 질문 검출, 질문 쌍 검색, 근거 정확성, 사용자 확인 흐름을 각각 평가한다.

- 개발 split에서만 질문 단독/문맥 추가와 기존 임베딩/단순 문자 유사도 기준선을 비교하고, 모든 임계값·예산·동점 규칙을 동결한다.
- 독립 held-out에는 의미상 같은 질문의 다른 표현, 같은 주제의 다른 질문, 반대·부정 질문, 인용·과거 질문, 물음표 없는 질문, 긴 문서의 여러 위치와 동일 본문 중복을 포함한다. 구체 본문·정답은 구현자에게 공개하지 않는다.
- 합격 기준은 실행 전에 별도 문서에 등록한다. 정밀도·재현율과 구간 검출 실패를 구분하고, 원문 SHA/UTF-16/선택 범위/계정 경계는 품질 점수와 별도로 반드시 확인한다.
- 독립 평가가 실패하면 실패와 부분 범위를 그대로 보고한다. 자동 분석 정책은 수동 주제 경로와 독립적으로 비활성 상태를 유지할 수 있어야 한다.

현재 권고는 **수동 주제 입력을 완결하고 자동 분석 정책은 비활성화**하는 것이다. 질문 전용 경로는 사용자가 질문 연결을 필요로 할 때 새 자료·새 기준으로 한 번의 한정 실험을 하는 순서가 적절하다.
