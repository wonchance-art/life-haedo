# 앱 표면 개선 QA

실행 범위는 익명 한글 6원문·12문장, 기존 실제 SDK·IndexedDB와 모의 Auth HTTP이다. 운영 API 쓰기·원문 서비스 요청은 없었다. Apple 실기·실제 한국어 IME·Files·VoiceOver 검증은 하지 않았다.

변경 전 홈·기록·1720자 원문·도구·관리를 1440·820·390px에서 15장 캡처했다. 기본 대비·조작 크기·입력 크기·넘침은 이미 통과했으며, 핵심 개선 대상은 흰 화면에서 비슷하게 보이는 탐색/본문/행동의 위계와 선택·누름 반응이었다.

변경 후 동일 화면과 빈 홈·빈 검색·선택·홈 로딩/오류, 600px 분할폭과 844×390 짧은 가로 화면을 36장 검토했다. 189개 세부 지표가 통과했고 작은 글자 대비 최소는 5.661:1이었다. 44px 조작·16px 입력·가로 넘침·클리핑·이름 없는 조작 문제는 없었다. 실제 콘솔·페이지 오류·외부 요청도 없었다.

대표 화면을 직접 비교했다. 옅은 바탕 위 흰 앱 표면과 작은 탐색띠가 메뉴와 본문을 구분하며, 민트 코멘트는 원문과 내 생각을 구분한다. 본문은 흰색을 유지하고 색이 메뉴·검색·코멘트에 제한된다. 긴 한글 제목이 조작 영역을 밀지 않는다.

최초 after의 844×390 원문 화면은 본문 시작점이 374.98px여서 첫 화면을 제목·도구·메타가 거의 차지했다. 낮은 가로 화면 전용 간격 보완 후 해당 3장만 다시 확인했다. 본문 시작점은 270.58px로 약104px 올라왔고 첫 화면에 본문3줄이 보인다. 이는 원래 main과의 비교가 아니라 낮은 높이 보완 전후 비교다.

별도 기능 3여정(390·600·844×390)에서 피드 끝 조작의 키보드 초점이 floating dock에 가리지 않는지, 터치 발췌→정확한 원문·선택 구간→검색·초점 복귀, JSON 백업의 원문 버전·문장 동일성과 저장 자료 불변을 확인했다. 390px의 끝 조작 아래끝713px, dock 위끝772px로 약59px 여유가 있었다.

선택/공통 탐색의 키보드 초점, 터치 선택, IME 조합 이벤트 중 검색 유예, reduced-motion도 확인했다. 화면 크기와 터치·IME 이벤트 모사를 실제 Apple 기기 체험으로 표현하지 않는다.

원본 `before/run-*.json`, `after/run-*.json`, `browser-run-*.json`을 보존했다. `after/report.json`과 `verification-summary.json`은 집중 재검증의 최신 결과를 합친 목록이며 전체 검사를 마지막에 한 번 더 반복했다는 뜻이 아니다. 플랫폼 로그인·연표·목표·습관은 root의 별도 검사 범위다.
