# 직접 글쓰기 브라우저 검토

2026-10-05. 익명 샘플, 실제 로컬 앱과 SDK/IndexedDB, 모의 Auth HTTP를 사용했다. 운영 자료와 DB에는 접근하지 않았다.

## 기능

`verification-summary.json`은 다섯 번의 집중 실행에서 각 사례의 최신 결과를 모은다. 단일 전체 재실행 결과가 아니다. 원본 `run-*.json`을 보존했다. 9개 기능 흐름과 3개 화면 크기 검사, 총 12개가 통과했다.

- 빈 화면에서 원문을 생성하지 않음, 자동 초안, 영역 이동과 새로고침 재개, 명시 저장.
- 저장 뒤 읽기, 수정 시 새로운 불변 버전 생성, 이전 발췌의 UTF-16 위치와 원문 보존.
- 기록 JSON 내보내기와 새 작업공간 사본 복원, 직접 작성한 글의 수정 자격 보존.
- 가져오기 초안과 글쓰기 초안 분리, 내 글 필터에서 외부에서 가져온 self 자료 제외.
- 실제 IndexedDB staging 및 bundles 트랜잭션 중단 시 입력 보존, 실패한 이동 차단, 재시도 중복 없음.
- 초안 충돌 시 별도 초안 사본, 원문 최신 버전 충돌 시 별도 글로 복구.
- 작업공간 A/B와 계정 A/B 초안 격리.
- 합성 한글 composition 중 자동 저장 없음, 종료 후 보관, Enter 키로 최종 저장.

초기 4개 실패는 테스트의 화면 계약 가정이었다. 글쓰기 중에는 가져오기 툴바를 숨기고, 기록 영역으로 돌아오면 작성 화면을 복원한다. 직접 생성한 작업공간은 UI의 기존 목록 캐시를 갱신하지 않으므로 실제 빈 작업공간 생성 흐름으로 바꿨다. 전역 탐색 시 입력의 blur는 조합 종료로 처리될 수 있어 합성 IME 검사는 명시적인 compositionend와 복귀 보존으로 분리했다. 각 수정 뒤 해당 사례만 재실행했다.

## 시각 검토

1440×1000, 820×1000, 390×844에서 `empty`, `long-draft`, `save-error` 9장을 캡처했다. 9개 상태 모두 가로 넘침·44px 미달 조작·16px 미달 입력·이름 없는 조작·대비 실패가 0이며 계산한 최소 텍스트 대비는 6.05:1이다.

직접 확인한 대표 이미지: `empty-1440.png`, `long-draft-390.png`, `save-error-820.png`, `save-error-390.png`. 흰 본문과 작은 라벤더 저장 버튼, 기존 rail/dock를 유지한다. 좁은 화면의 오류와 재시도/TXT 버튼은 줄바꿈되며 겹치지 않는다. 본문은 한글과 영문 혼합도 영역 안에서 줄바꿈한다. 제목은 한 줄 native input이므로 긴 제목은 가로 입력 스크롤로 편집한다. 긴 본문의 캡처는 입력 직후 caret을 따라 textarea 내부가 아래로 스크롤된 상태다.

HTML 모양의 본문은 XSS 처리 검사용 문자열이며 실행되지 않고 글자로 유지되는 것을 기능 검사에서 확인했다. 사용자에게 보여줄 제품 예시는 root가 별도 현실적인 샘플로 캡처한다.

콘솔·페이지 오류와 허용하지 않은 외부 요청은 전체 실행에서 0이다. 820/390에서는 Chromium touch 설정과 tap 재시도를 확인했다. 화면 크기·합성 이벤트 검사이며 Mac/iPad/iPhone, 실제 한글 IME·Files·VoiceOver·Google 로그인 검사로 해석하지 않는다.
