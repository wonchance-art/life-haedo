# 비슷한 문단 실험 사전등록

2026-11-02 KST. 이 문서는 개발 세트 실행 전에 SHA-256으로 봉인한다(`seal.json`). 실행 뒤에는 고치지 않는다. 판정 기준은 총괄이 작업 지시서에서 정한 값을 그대로 옮겼다.

## 질문

기존 브라우저 안 임베딩 워커(`assets/life/interest-model-worker.js`·`interest-model-loader.js`, Transformers.js 4.3.1, `Xenova/paraphrase-multilingual-MiniLM-L12-v2` revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`, q8, WASM 1스레드, 384차원)로 자료·내 글의 문단을 색인해 "비슷한 문단" 후보를 내는 것이, 기존 재발견 규칙(`assets/life/rediscovery.js`의 공통 실제 단어 규칙)보다 유의미하게 낫고 iPhone·iPad에서 감당할 비용인가? 결과는 채택/기각이다.

## 과제

기준 문단 하나가 주어지면 **다른 문서**의 문단 중 관련 문단 상위 3개를 낸다. 같은 문서의 문단과 정규화 본문(NFC, 공백 하나로 압축, 앞뒤 공백 제거)이 같은 복제는 후보에서 뺀다. 후보 풀은 같은 세트의 색인 대상 문단 전체다.

## 자료

- 합성·익명 한국어 자료만 쓴다(`build-corpus.py`로 생성). 실제 사람·계정·개인 기록·실제 기사가 아니며 외부로 보내지 않는다. 연구·통계 서술도 가상이다.
- **개발 세트** `dev-corpus.json`: 14문서·70문단. 관련 기준 문단 16개(gold 쌍 18개), 관련 문단이 없는 기준 문단 10개.
- **평가 세트** `eval-corpus.json`: 새로 쓴 독립 세트 30문서·150문단. 개발 세트와 주제가 겹치지 않는다. 관련 기준 문단 35개(gold 쌍 39개), 관련 문단이 없는 기준 문단 16개. MODEL-03 heldout은 재사용하지 않는다(그 자료는 질문·주제 문서 단위 gold라 문단 쌍 과제와 맞지 않고, 이미 본 자료다).
- **gold 정의:** 기준 문단과 다른 문서에 있으면서 같은 질문·같은 종류의 경험·같은 구체 주제(문단의 중심 논점)를 다른 표현으로 다룬 문단. 같은 넓은 분야에 속하거나 단어가 겹칠 뿐인 문단은 관련이 아니다. 관련 문단이 없는 기준 문단은 그 중심 논점을 다루는 다른 문서 문단이 세트 안에 없는 문단이다. gold는 `build-gold.py` → `dev-gold.json`·`eval-gold.json`. 문단 번호는 빈 줄로 나눈 0부터의 번호다.
- 평가 세트에는 단어는 겹치지만 논점이 다른 문단(예: 비 오는 날 산책 건너뛰기 / 이삿날 비), 같은 문서 안의 비슷한 문단, 다른 문서에 그대로 옮긴 인용 복제(E10:4 = E11:4)를 일부러 넣었다.
- **알려진 한계(사전 기재):** 말뭉치와 gold를 같은 작업자 1인이 썼다. 독립 표시자가 없다. 평가 세트는 개발 실행 전에 쓰고 봉인했지만, 작성자가 방법의 성질을 알고 쓴 자료라는 편향 가능성은 남는다. 문단이 짧고(평균 약 55자) 한 문단에 논점이 하나라, 실제 글보다 쉬울 수 있다. 후보 풀(150문단)이 실제 보관함보다 작아 실제 오탐률은 더 높을 수 있다.

## 방법(후보)

`candidate.js`. 브라우저 실행면과 Node 평가기가 같은 파일을 쓴다.

- 문단: 빈 줄로 나눈 덩어리, 정규화 길이 10자 미만은 색인하지 않는다. 400자를 넘는 문단은 문장 경계에서 400자 이하 조각으로 나눈다(무음 절단 없음).
- 임베딩 입력 변형(개발 세트에서 하나만 고른다): **P** 문단 그대로, **TP** 문서 제목 + 줄바꿈 + 문단, **W2** 3문장 이상 문단은 두 문장 창(보폭 1).
- 문단 점수: 두 문단의 조각 벡터 쌍 중 최대 코사인(워커가 정규화한 벡터의 내적).
- 출력: 같은 문서·정규화 복제를 빼고, 점수 ≥ 임계값 τ인 문단을 점수 내림차순(동률은 id) 최대 3개. τ 미만이면 결과를 채우지 않는다.
- 품질용 벡터는 제품 경로(`interest-model-loader.js` → 전용 모듈 워커)로 감속 없이 만든다. 후보 계산은 평가기가 Node에서 같은 `candidate.js`로 한다.

## 기반선

제품 `assets/life/rediscovery.js`의 `related()`를 **수정 없이** 호출한다. 문단 하나를 원문 하나(소스·버전 한 쌍)로 둔 최소 묶음을 만들고, 같은 문서·정규화 복제는 제품의 방향 있는 제외 쌍(`discovery.excludedPairs`)으로 뺀다. 주제·묶음 근거는 없으므로 공통 실제 단어 규칙(서로 다른 단어 2개 이상, 조사 제거 없음)만 작동한다. `limit: 3`.

- **B1** 문단 소스 제목을 빈 문자열로 둔다.
- **B2** 문단 소스 제목에 문서 제목을 둔다.
- 채택 조건 (2)의 기반선 Hit@3는 **B1·B2 중 높은 쪽**이다.
- **B3(참고값, 판정 미사용)** 현재 제품처럼 문서 단위로 재발견하고, 돌려준 문서에 gold 문단이 있으면 적중으로 후하게 센다.

## 개발 세트에서만 정하는 것

- 변형별로 τ ∈ {0.20, 0.21, …, 0.95} 중 **개발 세트 무관 기준 오탐률 ≤ 0.10**에서 Hit@3가 가장 높은 값을 고른다. 동률이면 더 높은 τ.
- 변형은 각자 고른 τ에서 개발 Hit@3가 가장 높은 것. 동률이면 P → TP → W2 순(단순한 쪽).
- 개발 오탐 한도를 채택 기준(0.20)보다 낮은 0.10으로 둔 것은 새 자료에서 오탐이 늘어날 여유를 남기기 위해서다.
- 고른 변형·τ와 `candidate.js`·실행기·평가기·실행면 SHA를 `freeze.json`에 봉인한 뒤 평가 세트를 실행한다.

## 지표

- **Hit@3:** 관련 기준 문단 중 상위 3개 후보에 gold가 하나 이상 있는 비율.
- **무관 기준 오탐률:** 관련 문단이 없는 기준 문단 중 후보를 하나 이상 낸 비율(임베딩은 τ 이상, 기반선은 규칙 성립).
- 사실 보고(판정 미사용): MRR, gold 회수율, 돌려준 후보 중 gold 비율, 관련 기준에서 빈 결과 수, 유형별(질문·경험·주제) 적중, gold 쌍 중 공통어 규칙이 성립하는 비율.

## 비용 측정

- Chromium 153(Playwright, Linux headless), 390×844·DSF 3·모바일 모사, CDP `Emulation.setCPUThrottlingRate` 4.
- 사전 확인: Chromium 153에서 이 명령은 전용 워커 대상에 적용되지 않는다(`Operation is only supported for pages, not workers`, 페이지 감속 시 워커 반복 시간 변화 없음). 그래서 비용 측정은 **제품 워커 소스 바이트를 그대로**(SHA 대조) 같은 출처 iframe의 주 스레드에서 실행해 감속을 건다. 같은 입력에서 워커 경로와 벡터가 같은지(최대 절대 차 0) 대조한다. iframe 감속비(같은 반복의 감속 4 / 감속 1 중앙값)가 3 미만이면 측정 무효다.
- **색인 시간:** 모델 준비가 끝난 뒤 문단 200개의 모든 임베딩 입력을 제품 한도(32개·합계 32,000자)로 나눠 임베딩하는 데 걸린 시간. 두 풀 모두 60초 이하여야 한다.
  - 말뭉치 풀: 평가 세트 150문단 + 개발 세트 앞 50문단.
  - 긴 문단 풀: 각 문서의 다섯 문단을 시작 위치만 돌려 이은 약 250~300자 문단 200개(실제 글 문단 길이에 가까운 보수 조건).
- **질의 1회:** 감속 상태에서 저장 형식을 읽은 뒤, 200문단 각각을 기준으로 `similar()`를 1회씩 실행한 시간의 **최댓값**이 200ms 이하. 저장 형식 해독 시간은 따로 보고한다.
- **벡터 저장 크기:** `{schemaVersion, modelId, modelRevision, variant, dimensions, entries:[{id, docId, textSHA256, vectors: Float32 리틀엔디언 base64}]}` JSON의 UTF-8 바이트가 2,000,000바이트 이하(두 풀 모두).
- 사실 보고(판정 미사용): 모델 최초 다운로드 바이트·시간, 캐시가 있을 때 준비 시간, 감속 상태 준비 시간, 긴 문단 1개 임베딩 시간, 관측 메모리 최대치(브라우저 프로세스 트리 RSS 합, 250ms 표본).

## 채택 조건(모두 만족)

1. 평가 세트 Hit@3 ≥ 0.70
2. 평가 세트 Hit@3 − 기반선(B1·B2 중 높은 쪽) Hit@3 ≥ 0.15
3. 평가 세트 무관 기준 오탐률 ≤ 0.20
4. 감속 4배·390×844에서 문단 200개 색인 ≤ 60초, 질의 1회 ≤ 200ms, 벡터 저장 ≤ 2,000,000바이트

하나라도 못 미치면 기각한다. 측정 유효성(감속비 ≥ 3, 두 경로 벡터 동일, 승인 밖 외부 요청 0, 실행 전후 제품 파일 SHA 동일)이 깨지면 판정하지 않고 무효로 보고한다.

## 실행 규칙

- 실행기는 gold 파일을 읽지 않는다. 평가 세트는 `freeze.json` SHA를 인자로 받아 한 번만 성공 실행한다(`eval-output.json`이 있으면 거부).
- 네트워크·브라우저 오류로 끝난 시도는 `eval-failure-*.json`으로 남기고, 같은 동결 값으로만 다시 시도한다. 결과를 보고 임계값·변형·gold·말뭉치·평가기를 고치지 않는다.
- 평가 뒤의 문단 재독(예: gold에 없지만 그럴듯한 후보)은 별도 절로 기록할 수 있으나 판정을 바꾸지 않는다.
- 이 결과는 Linux Chromium 모사이며 실제 Apple 기기·Safari 측정이 아니다.
