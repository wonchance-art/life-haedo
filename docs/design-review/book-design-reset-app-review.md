# A안 실제 앱 적용 독립 시각 검토

2026-10-09 KST · 검토자 design_finish_review · 실제 앱 `index.html` 기준

## 1. 판정과 범위

**disposition: ship — 확인한 실제 앱 기본·긴 제목·저장 실패 화면의 시각 범위.** 사용자가 선택한 A의 흰 본문, 한 열 원고, 작은 조작과 접힌 보조 기능이 실제 앱에서도 유지된다. 시각상 적용을 막는 결함은 발견하지 못했다. 이 판정은 기능 QA 완료·병합·공개 배포·Apple 실기 검증을 뜻하지 않는다.

[비교 시안 리뷰](book-design-reset-independent-review.md)의 판정과 구분한다. 이번에는 `.local/book-design-reset-app/visual/`의 실제 앱 책 목록·장 집필·전체 읽기를 390×844, 820×1000, 1440×1000으로 검토했다. 1차 9장과 갱신된 최종 9장을 모두 개별 `view_image`로 확인했다. 최종 증거는 `run-2026-10-08T21-13-10-959Z.json`과 같은 내용의 `audit-report.json`, Chromium 151.0.7922.173이다. 자동 디자인 detector는 실행하지 않았다.

승인 기준은 [A 방향 계약](book-design-reset.md)과 `evidence/book-design-reset/after/A-{list,edit,read}-{390,820,1440}.png`다. 시안은 메모리만 쓰는 독립 HTML이고, 실제 앱은 기존 저장·원문·출력·복구를 보존하는 구현이다. 동일한 미적 방향을 확인하되 시안의 조작 수와 배치를 그대로 복제했는지를 합격 기준으로 삼지 않았다.

## 2. A의 유지와 허용한 차이

| 항목 | 실제 앱 판단 |
| --- | --- |
| 원고 우선 | 큰 책 제목·상태·설정·출력 도구가 원고 앞에 누적되던 구조를 정리했다. 집필은 장 제목과 경계 없는 원고, 읽기는 장 제목과 문단이 중심이다. |
| 색과 프레임 | 흰 본문, 옅은 자주색 조작, 짙은 본문 색이 유지된다. 기존 전역 rail/dock는 앱 맥락이며, 모바일 집필·읽기는 하단 도크가 원고를 덮지 않는다. |
| 목록 | 책 제목과 실제 앞부분을 먼저 보고 전체 읽기·편집으로 간다. 최종 헤더는 `내 책` 하나로 정리됐다. 1440px도 목차를 아래에 놓은 한 열이며, 시안의 옆 목차와 다르지만 기존 접기 동작을 보존한 허용 가능한 변형이다. |
| 집필 | 책 맥락을 작은 별도 행으로 남기고 장 번호·근거·이전/다음 장을 배치했다. 시안보다 상단이 길지만 원고 자체는 입력 폼 상자에 갇히지 않는다. 최종 장 번호를 왼쪽으로 정렬해 읽는 기준점이 분명하다. |
| 읽기 | `이 장 편집`을 작은 연필 조작으로 정리해 장 제목과 경쟁하던 버튼의 무게를 줄였다. 제목·문단 중심 흐름이 시안과 가깝다. |
| 기존 기능 | 관리·개정본·출력은 아래 보조 영역으로 내려가고 상단 아이콘으로 찾는 구조다. 시안의 단순 반영 버튼을 실제 저장 모델로 대체한 차이는 정당하다. 이미지로 기능 보존까지 증명한 것은 아니다. |

TYPE은 넓은 본문 19px/37.05px, 모바일 17px/32.3px로 A의 한글 읽기 방향을 유지한다. MATERIAL은 실제 문자와 공통 SVG이며 그림·색 면으로 빈 곳을 채우지 않는다. GROUND는 흰 본문과 옅은 바깥 바탕으로 구분된다. 긴 책 제목이 목록에서 2–3줄로 감기지만 잘라 숨기지 않고, 기본 원고의 한글은 오른쪽 밖으로 넘치지 않는다.

## 4. 남은 시각적 비용과 우선순위

**기본 화면에서 미처리 필수 시각 수정은 없다.** 추가 디자인 반복보다 아래 비용을 알고 실제 사용 결과를 보는 편이 타당하다.

1. 집필의 책 맥락·장 이동 두 행은 시안보다 본문 시작을 늦춘다. 기존 장 이동과 근거 확인을 보존한 비용이며 현재 원고를 가릴 정도는 아니다.
2. 목록에서 한 권과 네 장을 보여주는 높이가 크다. 많은 책을 연속 탐색하는 밀도는 이번 기본 한 권 증거로 판단하지 않는다.
3. 저장을 뜻하는 체크 상자, 관리 톱니, 근거 인용, 목차 책 아이콘은 간결하지만 초심자에게 모두 자명하지는 않다. 접근 이름·초점 도움말·펼친 결과는 별도 QA가 확인해야 하며 아이콘 수 감소만으로 사용성이 좋아졌다고 단정하지 않는다.

## 5. 추가 상태와 제약

기본 9장 이후 [긴 제목 390](evidence/book-design-reset/app/long-title-390.png), [820](evidence/book-design-reset/app/long-title-820.png), [1440](evidence/book-design-reset/app/long-title-1440.png), [저장 실패 390](evidence/book-design-reset/app/save-error-390.png)를 각각 `view_image`로 추가 확인했다. 모두 실제 앱에서 입력한 상태이며 독립 시안 캡처가 아니다.

긴 장 제목은 390px에서 다섯 줄, 820/1440px에서 세 줄로 표시된다. 제목이 원고를 아래로 밀지만 한글이 잘리거나 입력 영역끼리 겹치지 않는다. 390px에서도 첫 원고 문단을 함께 볼 수 있다. 제목 길이를 이유로 글자를 지나치게 줄이거나 내용을 감추지 않은 선택이 타당하다.

저장 실패 화면은 작은 고정 도구 행 아래에 붉은 오류 안내와 `초안 JSON 받기`·`다시 저장`을 보여준다. 아래에는 작업 중인 원고가 남는다. 고정 안내가 현재 화면의 위쪽 문단 일부를 가리는 비용은 있으나 실패 사실과 복구 행동을 놓치지 않게 하는 우선순위가 명확하다. 이미지에서 입력 보존을 볼 수 있다는 사실과 실제 복구 성공은 구분한다. 추가 네 화면에서도 시각적 차단 결함은 발견하지 못했다.

기능 QA 담당자는 최종 실제 앱 3폭 검사 3/3 통과를 전달했다. 읽기 위치·장 이동·집필 복귀와 입력 보존의 기능 결과는 그 별도 검사에 근거하며, 정적 이미지에서 정확성을 추론하지 않았다. 진단 중 보였던 복귀 차이는 검사 도구의 자동 스크롤 영향으로 정리됐으므로 미해결 기능 결함으로 남기지 않는다. 실제 IME 조합·소프트 키보드·iPad/iPhone·운영 데이터·공개 배포는 검증하지 않았다. 검사는 사용자 선호나 실제 사용 평가를 대신하지 않는다. 앱 코드는 디자인 책임자가 수정했으며 검토자는 이 리뷰 문서만 작성했다.
