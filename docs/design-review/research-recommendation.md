# 탐구 자료 엄선 추천 — 실행 설계

2026-10-29. 사용자는 **‘내가 읽을 탐구 자료를 추천받는 계정부터 시작’**으로 확정했다. 최우선은 소비 계정의 입력 품질이며, 필요한 경우에만 선택 자료를 SNS 콘텐츠 기획으로 넘긴다. 현재 코드·문서를 읽고 공개 공식 자료를 확인했다. 제품 구현·계정 접근·수집/게시 가동·추천 효용 검증은 하지 않았다. 특정 SNS·새/기존 계정·전달 방식은 아직 확정하지 않는다.

[실제 출처·첫 읽기 비교](research-source-pilot.md)로 공개 자료 10개와 SNS 게시 5개를 검토했다. 현재 운영 제안은 Bluesky의 두 출처로 시작하는 작은 시범이다. HTTP 실패와 JS 브라우저의 요약 접근, SNS 게시일과 원자료 발행일을 별도로 기록한다. 웹에서 편집한 목록을 개인 추천 성능이나 사용자 읽기 평가로 사용하지 않는다.

## 1. 추천할 대상과 목표를 먼저 분리

| 목적 | 추천 대상·성공 기준 | 혼합하지 않을 신호 |
| --- | --- | --- |
| 탐구·소비 | 지금의 질문에 답하거나 설명을 비교할 원자료. 읽을 자료를 찾는 수고와 실제 읽은 뒤 도움 | 클릭·체류·좋아요 수를 이해·실독·사실 정확성으로 바꾸지 않음 |
| 콘텐츠 기획 | 사용자가 정한 독자·주제·형식에 맞는 논점/자료 묶음. 근거 확인과 편집 부담, 명시 채택 | 인기·게시 성과를 사용자의 탐구 선호 또는 연구의 진실성으로 역전파하지 않음 |

첫 운용은 SNS 계정에서 직접 자료를 추천받는 흐름이다. 해도 화면이나 자체 추천 엔진을 반드시 거치게 하지 않는다. 다음 두 운용을 구별한다.

- **플랫폼 추천 그대로 소비:** 사용자가 선택한 관심·팔로우·목록·저장 등 플랫폼 제공 조절을 사용한다. 실제 제공되는 기능만 연결하며 개인 추천 피드 API가 있다고 가정하지 않는다. 외부 랭커의 가중치·전체 후보·노출 확률·모든 반영 시점을 알거나 통제할 수 없다.
- **허용된 후보를 독립 엄선:** 공식 API/피드·명시 URL/파일 등 확인된 경로로 확보한 후보만 해도 규칙으로 재정렬한다. 결과는 ‘확보한 후보 중 추천’이며 SNS 전체의 최적 추천이 아니다. 계정·원천 권한과 접근 실패는 별도 상태다.
- 플랫폼 피드에서 가져온 표본은 이미 외부 알고리즘이 선택한 자료다. 이 표본에서 해도 순서가 좋아졌다고 전체 SNS 품질 개선이나 인과 효과를 주장하지 않는다. 플랫폼별 허용 경로·호출량·자동화 권한은 실행 전 확인한다.

자동 좋아요·대량 팔로우·스크롤 시뮬레이션으로 외부 피드를 학습시키는 경로는 만들지 않는다. 자료 추천에서 콘텐츠 기획으로 넘어가는 것은 사용자가 고른 정확 자료의 인계이며 자동 발행 명령이 아니다.

| --- | --- | --- |

정기 검토의 초기 작업량은 주제별 후보5개 이내·주1회 검토를 **실험 가설**로 제안하며 사용 부담에 맞춰 줄인다. 알림·자동 보고서·외부 피드 수집을 켜는 명령이 아니다. 날짜별 플랫폼 후보가 달라지므로 전후 결과는 개인 관찰이며 동일 조건 A/B로 주장하지 않는다. 팔로워·수익·게시 빈도는 이번 소비 목표의 지표가 아니다.

아래 자체 순위 명세는 이 첫 묶음의 선행 조건이 아니라 **허용된 후보를 따로 엄선할 필요가 확인될 때 사용할 후속 계약**이다. 플랫폼별 자동화/계정 조작 가능 범위는 정해진 서비스의 공식 경로를 확인한 뒤 확정한다.

## 3. 실제 사용자 흐름과 입력 계약

뉴스/허용된 SNS 전달면에서 `탐구 주제`와 현재 질문을 선택적으로 좁힌다. 기존 관심을 재사용하고 질문 입력을 모든 읽기의 필수 입구로 만들지 않는다. 예시는 외국어 학습·독서·집중력·Grit이며 자동 저장된 사용자 프로필로 취급하지 않는다.

`ResearchRequest`는 논리 계약이며 기존 strict JSON에 숨겨 넣을 필드가 아니다: `id/revision, scope(owner+workspace), topic/query?, purpose, contentLanguages, sourceSelection, evidencePreference?, depth?, freshnessMode, K<=5, personalizationMode, explorationMode`.

purpose는 `개념 이해/연구 근거/실용 조언/다른 관점` 중 선택한 값 또는 미선택이다. 미선택이면 기존 관심순/최신순을 제공한다. 독서 시간·난이도는 제공자 정보나 사용자가 확인한 값만 사용하고 제목에서 분량·전문성을 확정하지 않는다.

결과 카드는 원제목·출처·날짜·확보 범위와 기존 반응 조작을 유지한다. 이유는 더보기에서 확인한다. 읽기만 하고 종료, 담기, 정확 자료 보관·메모, 계획 연결, 콘텐츠 기획에 채택을 서로 독립된 선택으로 둔다. 평가·저장·기획을 필수 후속 단계로 만들지 않는다.

## 4. 후보→품질 확인→순위→다양성→설명

1. 현재 요청·출처 설정 revision과 카탈로그를 고정한다. 사용자가 보관한 자료의 재발견과 새 외부 후보는 별도 풀이다. 새 후보의 known 제외를 모든 탐구에 복제해 필요한 기존 자료를 숨기지 않는다.
2. 기존 허용 출처·HTTPS/권리·형식·언어·끄기/URL 제외를 먼저 적용한다. 정해진 수집 경로가 없는 SNS는 임의 크롤링으로 보충하지 않는다. 추천 점수는 제외 조건을 뒤집지 못한다.
3. canonical URL은 기존 query 보존 규칙으로 정규화한다. DOI/게시자 ID는 실제 제공된 값을 확인한 경우에만 동일 저작물의 보조 식별자로 사용한다.
4. 같은 URL은 한 후보로, 명시 번역/동일 논문 보도는 연결 묶음으로 표현한다. 비슷한 제목·같은 사진·높은 벡터 유사도만으로 원문을 병합하지 않는다. 판·정정·철회·서로 다른 의견은 보존한다.
5. 요청에 맞는 관련성·검증된 증거 속성을 계산하고, 근거가 부족하면 후보 수를 줄인다. 언어·출처를 조용히 늘리거나 무관한 인기 글로 빈칸을 채우지 않는다.
6. 상위 관련 후보 안에서 반복 출처/저작물/세부주제를 줄인다. 조회 중 자동 갱신은 새 후보 준비까지만 하고, 사용자가 읽는 카드·초점·IME·스크롤을 갑자기 재배열하지 않는다.
7. `RankingRun`에 policy/config 버전·기준시각·입력 해시·후보/제외 집계·선택 순서·근거를 남긴다. 같은 입력/seed의 재실행은 같은 결과다. 개인 주제·반응·URL 결합은 비공개 범위다.

### 품질은 출처 유명도와 분리

| 관찰 항목 | 확인 근거 | 미확인 처리 |
| --- | --- | --- |
| 자료 종류 | 원저·리뷰·해설·실용 조언·의견·preprint라는 제공자 표기와 확인 위치 | 태그·기관명만으로 동료심사/합의를 선언하지 않음 |
| 추적 가능성 | 원 출처·작성자·발행/정정 정보·논문/자료 링크 | 미제공은 unknown. 수집일을 발행일로 채우지 않음 |
| 질문에 맞는 근거 | 실제 확보 범위에서 연구 대상/방법/한계·권고의 근거·적용 범위를 확인 | 제목만으로 연구 타당성·인과·개인 적용 효과를 추정하지 않음 |
| 독립성·중복 | 같은 논문/보도자료 재전재 여부와 실제 출처 연결 | 여러 매체 보도를 독립 연구 여러 개로 세지 않음 |
| 정정/철회 | 출처가 제공한 명시 상태와 확인 시각 | 조회하지 않음은 ‘철회 없음’이 아님. 확인된 철회는 일반 조언 추천에서 제외, 연구 검토 시 표시 |

`link_only`는 ‘검토할 후보’로 추천할 수 있지만 ‘본문을 검증한 엄선 자료’라고 표시하지 않는다. 본문 근거 확인은 [정확 판·메모 계약](reading-decision-journey.md)의 source/version/hash/locator를 사용한다. 품질 관찰은 값+출처 범위+확인 시각+규칙/검토자 버전으로 보존하고 원문을 재작성하지 않는다. 동일 URL 갱신으로 옛 근거를 최신 내용에 붙이지 않는다.

## 5. 초기 스코어와 재정렬 — 검증할 가설

독립 재정렬을 선택한 경우 현재 v4는 그대로 유지하고 새 `research-rules-v1` 후보를 shadow 계산한다. 아래 수치·구간·한도는 입증된 최적값이 아니라 최초 비교를 위한 **초기 실험 가설**이다. 사용자 결과 없이 운영 기본값으로 승격하지 않는다.

```text
S(d,q) = 0.70 R(d,q) + 0.15 Q(d,q) + 0.10 F(d,q) + 0.05 P(d,u)
MMR(d|L) = λ S(d,q) - (1-λ) max(sim(d,x), x∈L), λ∈{0.75,0.90}
```

- `R∈[0,1]`: 최초에는 기존 최대 어휘 근거값/8. 질문 목적에 맞는 후보인지 별도 판정하며, 긴 질문의 정확 일치0을 높은 품질점수로 메우지 않는다. 어휘일치가 없는 의미 후보는 검증한 의미검색 arm을 도입하기 전까지 만들지 않는다.
- `Q∈[0,1]`: 선택 purpose에 필요한 사전 정의 체크 항목 중 **실제 근거로 확인한 비율**. `연구 근거`는 자료종류/직접 원출처/질문에 맞는 방법·한계/정정정보 확인, `실용 조언`은 직접 원출처/권고의 근거/적용 조건·한계 등을 사용한다. 항목집합과 관찰 근거를 run에 고정한다. unknown은 확인점수 가산0이며 ‘나쁜 연구’ 판정이 아니다. 본문 미확보 항목은 통과시키지 않는다. 사실의 진실 확률이 아니다.
- `F∈[0,1]`: 뉴스형 요청에서만 유효 발행일 기준 `2^(-ageDays/H)`; `H∈{30,90}` 비교. 개념/기초 탐구는 `F=0`으로 고정하고 오래된 원저를 시간 때문에 제거하지 않는다. 날짜 미확인은 가산0, 미래/수정일 대체 여부는 기존 규칙을 보존한다.
- `P∈[0,1]`: 유효 좋아요 한 건과의 고유 제목/태그 표현 집합 Jaccard의 최댓값×시간 감쇠. 최소2표현·출처/언어 조건을 유지한다. opt-out이면0; 기존 순위 모드를 고르면 새 계산 자체를 하지 않는다. 반복 좋아요·같은 저작물 여러 재전재의 합으로 점수를 늘리지 않는다.
- 초기 `sim`: 실제 확보 제목/태그의 고유 표현 집합 Jaccard. 동일 저작물은 확인된 식별자로 먼저 처리한다. 긴 무공백 문장·다국어 번역판의 유사도를 이 값이 잘 측정한다고 가정하지 않는다. 의미 다양성은 별도 검증 전 미확인이다.
- MMR은 이미 관련성/범위 조건을 통과한 풀에서만 사용한다. 초기 후보는 상위5개 중 같은 출처 최대2개·확인된 같은 저작물1개를 비교한다. 충족 못하면 적게 제시하고 이유를 남긴다. 현재의 ‘1점 이내 출처 교체’와 대조한다.
- 가중치 합1도 효과 보증은 아니다. 단위가 다른 feature를 확률처럼 표시하지 않고 실제 기여값을 기록한다. 동점은 기존 관련성·유효 날짜·canonical URL의 고정 순서로 푼다. Q/F/P 하나를 제거한 ablation으로 개선 원인을 확인한다.

### Cold start·다국어·탐색

- 좋아요0·개인화 off·신호 부족이면 최신순/명시 관심순으로 시작한다. 온보딩 평가를 강요하거나 다른 사람의 취향을 기본 사용자 프로필로 넣지 않는다.
- 선택 언어 각각의 공급 수·적합 후보 수·본문 확보 수를 구분한다. 언어별 고정 몫으로 무관 글을 채우지 않는다. 실제 공급이 없는 ja/zh/fr은 부족을 표시하며 한국어/영어로 몰래 대체하지 않는다.
- 짧은 별칭은 기존 검토 목록 재사용. 다음 후보는 언어별 토큰화/BM25 또는 다국어 임베딩의 **고정 카탈로그 실험**이며 모델·토크나이저·버전·입력 범위·비용을 먼저 고정한다. 다국어 질문 번역은 원문 질문과 파생 표현을 따로 표시하고 사용자 관심을 덮지 않는다.
- 다국어 좋아요의 교차언어 전이는 현재 지원이라고 표시하지 않는다. 주제 번역·문장 임베딩은 언어별 관련성 라벨·오역/동음이의어 반례에서 기존 방식보다 나은 경우에만 활성화한다. 원문 열기 번역 설정과 독립적이다.
- 탐색은 선택한 주제 안의 새로운 출처/다른 설명을 찾는 옵션이다. 최초 비교는 `탐색0` 대 `관련 후보5개 중 최대1개`; 비율은 실험 가설이다. 미선택 주제·꺼진 언어/출처·명시 숨김은 탐색으로 우회하지 않는다.
- 비슷한 자료만 반복될 때 탐색 후보를 고정 seed로 표집하고 후보 수·선택확률을 기록한다. 수집 자체의 외부 선택확률은 모른다. 원천이 부족하면 탐색0으로 남기고 근거 없는 반대 주장을 다양성으로 넣지 않는다.

## 6. 반응 의미·수명·오염 방지

아래는 **해도가 소유한 반응과 독립 순위**의 계약이다. SNS 서비스 자체가 저장·팔로우·스킵을 어떤 강도로 사용하는지는 이 표로 통제할 수 없다. 외부 반응을 해도에 자동 복제하거나 숨은 수치로 환산하지 않는다.

| 입력 | 허용 의미와 사용 | 수명/취소 |
| --- | --- | --- |
| 명시 관심/현재 질문 | 현재 요청의 가장 강한 범위 | 사용자가 수정/끄기 전 유지. 임의 만료·심리성향 추론 없음 |
| 좋아요 | 이 글에 대한 긍정 표시; 개인화 허용 시 내용 근접성 보조 | 원래 표시는 유지. 새 P의 감쇠 반감기90일은 실험 가설, 기준시각 고정. 해제 즉시 신호0 |
| 담기 | 다시 볼 목록·개인적 활용 의향 | 기본 순위 가중치0. 읽음/찬성/게시 의도로 전환하지 않음 |
| 읽음 | 해당 글 재노출 제어 | 만족도0/1 아님. 새 후보 제외와 재발견 목록을 구분 |
| 관련 없음/숨기기 | 현재 기존 의미는 해당 URL 제외 | 주제/출처 전체의 불호로 확대하지 않음. 되돌리기 가능 |
| 추천 근거에서 제외 | 해당 좋아요를 개인화 근거로 쓰지 않음 | 즉시 적용. 후보 숨김과 다른 상태; hide+like 동시 존재 시 어느 상태가 어떤 계산에 쓰였는지 설명 |
| 실제 읽은 범위/도움 | 현재는 고정 비교의 직접 평가 | 자동 학습 금지. 향후 학습 사용은 별도 선택·버전과 철회 계약 필요 |
| 클릭·체류·무반응 | 열기/관측 부재 | 완독·도움·싫어요 라벨 생성0 |
| 기획 채택·게시 성과 | 콘텐츠 목적의 별도 피드백 | 탐구 프로필에 합산0. 자기가 만든 결과를 추천 정답으로 순환 학습하지 않음 |

신호는 owner+workspace·명시 시각·원래 메타 스냅샷으로 제한한다. 미래 신호는 과거 순위에 사용하지 않는다. AI가 쓴 요약·합성 평가·새 기기 복원·알림 열기·반복 토글은 독립된 사용자 선호 사건이 아니다. URL별 유효 상태 한 번만 계산한다.

원천/언어 끄기·개인화 중지·근거 제외·삭제는 진행 중 계산을 무효화한다. 오래된 캐시/작업 결과가 옵션을 되돌리지 않는다. 원래 반응을 지우지 않고도 추천 근거 사용을 끌 수 있어야 한다. 반응 계정 동기화는 기존 PR140 인계이며 이 설계만으로 구현 완료가 되지 않는다.

## 7. 설명·원문·콘텐츠 기획 인계

추천 이유는 실제 계산 경로만 출력한다: `선택한 주제의 제목 표현`, `허용한 좋아요와 공통 태그`, `확인된 자료 종류`, `같은 출처 반복 조정`, `탐색 후보`. 메타데이터 비교를 ‘본문이 내 고민을 해결한다’로 설명하지 않는다. 설명은 펼칠 때만 상세 근거와 확인 시각을 보여 준다.

허용 범위의 AI를 사용하더라도 원자료는 지시가 아닌 데이터다. 설명/방법 요약은 확보한 정확 판의 구절·불확실성을 함께 반환하고 결정적 제외·계정·권리·동의 검사를 모델에 맡기지 않는다. 모델 실패·비용 초과에는 기존 규칙 결과로 돌아간다. AI 설명 생성 여부는 순위 효과와 따로 평가한다.

기획 시스템에는 사용자가 고른 `canonicalUrl + coverage + 권리 + source/version/hash/locator(확보 시) + 선택한 메모 사본 + 관찰 근거`만 넘긴다. 링크-only를 기사 본문으로 확장하거나 선택하지 않은 개인 메모·좋아요 이력을 전부 전달하지 않는다.

기획 추천은 `독자 질문→명시 논점→서로 독립된 근거/한계→형식 후보→사용자 채택`의 별도 요청이다. 탐구 S를 ‘바이럴 점수’로 재명명하지 않는다. 노출/저장/팔로우 등 게시 성과가 있어도 유기적 효과·주장 타당성을 자동 입증하지 않는다. 특정 SNS 계정 운영·예약 게시·외부 전달은 별도 확정 계약을 따른다.

## 8. 평가·채택·중단 기준

**세 층을 분리한다:** 공급에 원하는 자료가 있는가 → 확보한 풀에서 잘 고르는가 → 실제 읽은 뒤 도움이 되는가. 공급 부족을 랭커 성능0으로, 자동 검사 통과를 실제 도움으로 바꾸지 않는다.

| 비교 | 고정할 것 | 측정·해석 |
| --- | --- | --- |
| 기준선 | 같은 catalog bytes/now/주제/언어/출처/known/hide/반응 snapshot/K | 최신순·관심순·현재 v4·새 규칙을 비교. 후보 풀이 다르면 end-to-end 공급 비교로 별도 기록 |
| 어휘/품질/MMR | 동일 후보·feature 관찰, 변경 한 요소와 policy ID | 관련성 누락, 확인된 품질 근거, 중복·출처 편중, 실제 선택 수. 단계별 ablation |
| 다국어 | 언어별 실제 후보·질문·라벨과 판정자 이해 범위 | 언어별 결과·공급량 보고. 번역문 자동 판정만으로 원어 품질 통과 금지 |
| 직접 읽기 | 읽기 전 의향과 읽은 범위/접근 실패/도움 분리 | ‘읽을 자료를 찾음’과 실독 도움을 따로 보고. 미평가·접근 실패를 만족도0으로 넣지 않음 |
| 기획 활용 | 같은 독자/형식/근거 범위와 편집 조건 | 채택·근거 오류·수정 부담. 소비 추천 평가와 별도 |

기존 읽기 비교는 모드별2개·현재1회 보관이므로 top5/다회 평가가 이미 가능하다고 쓰지 않는다. 첫 비교는 기존 화면/명시 로컬 평가 CLI를 재사용하고, 새 policy/평가 기록 형식은 과거 v2/v3/v4 스냅샷을 다시 계산하지 않는 호환 계약으로 구현한다.

표시 순서/정렬명을 고정 노출한 비교는 맹검·무작위 A/B가 아니다. 가능한 평가에서는 A/B명을 가리고 순서를 교차 배치하되 출처·확보 범위는 숨기지 않는다. 사용자 한 사람의 여러 글 평가를 독립 사용자 여러 명으로 세지 않는다.

라벨은 질문별 직접 관련성0/1/2와 실독 도움 yes/no/null을 별도로 둔다. NDCG는 `gain=2^관련성-1`, 공통 판정 풀의 이상순위로 계산하며 해당 풀 범위의 값이다. 판단이 부족하면 N/A·판정률 또는 상/하한을 보고한다. P@K의 미평가를 음성으로 채우지 않는다. 전체 풀 정답이 없으면 recall을 주장하지 않는다.

시간 분리로 학습/튜닝/평가를 나누고, 평가 시점 이후 반응·수정 기사·AI 생성 평가를 입력에서 제외한다. 외부 SNS가 준 표본에는 선택 편향이 있으므로 전 서비스 인과 비교나 관측되지 않은 노출 확률 보정을 하지 않는다. 평가용 탐색의 확률도 확보한 후보 풀 안에서만 유효하다.

채택 판단은 사전에 고정한다: 하드 제외/정확 근거/계정·해제 위반0, 기존 대비 실제 관련성·도움과 관리 부담의 개선 방향, 특정 언어/출처의 악화 여부를 함께 확인한다. 첫 파일럿의 작업량 가설은 질문3종×고정 후보 묶음2회이며 통계적 유의성·보편 효과 기준이 아니다. 표본/판정이 부족하면 `미결정`으로 둔다.

| 전환 | 필요한 증거 | 중단/유지 |
| --- | --- | --- |
| 규칙 v1 기본 적용 | 동일 후보의 실제 직접 평가·실패/철회 검수·기존보다 낮은 재선택 부담 | 효과 불명확·근거 왜곡이면 v4/관심순 유지 |
| BM25/다국어 embedding | 관련 자료가 풀에 있으나 어휘 정책이 놓친 사례, 언어별 고정 평가 개선과 비용/지연 확인 | 공급 부족만 있는 경우 모델 도입보다 공급 검토 |
| 학습 reranker/CF | 합법적으로 사용할 충분한 독립 사용자·시간 분리 라벨, 개인 내용 기반보다 나은 재현 평가·삭제/운영 비용 검증 | 현재 희소한 개인 데이터에서는 도입 보류. 사용자 수만으로 전환하지 않음 |
| 외부 SNS 성과 연동 | 실제 허용 데이터·목적별 신호 분리·관측 범위 확인 | 피드 API·개인 성과 접근이 미확인이면 수동/명시 입력 경로 유지 |

## 9. 구현 인계와 검수 묶음

추천 모델 담당은 후보/신호 snapshot·규칙/MMR·설명·버전, 수집 담당은 권리·언어 공급·정체성·확보 범위, UI 담당은 기존 뉴스/허용된 전달면·반응·정확 원문 왕복, 독립 검수 담당은 제외/누수/빈 결과/과거 판·실독 평가를 맡는다. Core/Storage/UI 공통 파일은 수정 담당을 한 명씩 정한다.

첫 순서는 **소비 관심 brief→사용자가 고른 원천/계정 구성→실제 읽기→입력 품질 검토**다. 독립 재정렬이 필요해진 뒤 **공통 후보/기준선 재현→품질 관찰·설명→shadow 규칙/MMR→소수 직접 평가→조건부 적용**한다. 신규 서버·벡터DB·추천 프레임워크·협업 필터링·AI API를 선행 설치하지 않는다. 최대500후보는 현재 순수 계산으로 비교하고 실제 병목 측정 뒤 구조를 바꾼다.

필수 반례: like+save/hide 동시 상태, unlike 직후 늦은 계산, 복원 반응의 opt-in 부활, 계정 전환, 미래 반응·날짜, 언어0개/공급0개, 태그1개의 분할 부풀림, 같은 논문 다매체 보도, 미확보 본문/철회 미조회, 읽기 후 답을 과거 순위에 사용, 편집·IME 중 자동 재정렬, 삭제 뒤 캐시 재노출, 모델/원천 실패 fallback. 메모·자료·글·공개 상태 변경0을 확인한다.

## 10. 직접 확인한 공식 자료와 적용 한계

확인일 **2026-10-29**, 공개 HTTP 읽기만 수행했다. 아래2개를 구조 참고로 삼으며 현재 운영 모델 전체·가중치·효과를 재현했다고 주장하지 않는다. 코드 복사·패키지 도입은 하지 않는다.

1. Meta Engineering, [Scaling the Instagram Explore recommendations system](https://engineering.fb.com/2023/08/09/ml-applications/scaling-instagram-explore-recommendations-system/), 발행2023-08-09, HTTP200 본문 확인. retrieval→1차/2차 ranking→최종 규칙/다양성, 서로 다른 engagement 예측과 가중 조합, 캐시/사전 계산을 설명한다. **채택:** 후보·점수·제외·재정렬 분리. **미채택:** 수십억 후보용 two-tower/ANN·시간당 학습·engagement 최적화를 작은 개인 탐구에 바로 도입하지 않음.
2. X 공식 공개 [twitter/the-algorithm README](https://github.com/twitter/the-algorithm/blob/main/README.md) ([직접 읽은 raw](https://raw.githubusercontent.com/twitter/the-algorithm/main/README.md)), HTTP200 확인. 후보원·explicit/implicit 신호·light/heavy ranker·mixing/filtering의 분리를 설명하고 최상위 BUILD/WORKSPACE가 없음을 명시한다. 2023 공개 계열의 설명이며 2026 현행 제품과 동일하다고 하지 않는다. **채택:** 목적별 단계와 신호 의미 분리. **미채택:** 서비스군·소셜그래프·예측 행동 점수를 사용자 좋아요 횟수 규칙으로 복사하지 않음.

MMR 수식·가중치·감쇠·출처 한도·탐색 몫은 위 서비스의 실제 정책을 인용한 것이 아니라 해도에서 비교할 명시 가설이다. [기존 조사](recommendation-feedback-research.md)의 당시 라이선스/릴리스/효용 미확인 범위를 유지하고, 새 외부 라이브러리를 실제 채택할 때 공식 최신 릴리스·라이선스·보안 권고를 별도 대조한다.
