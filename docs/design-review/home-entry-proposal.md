# 첫 접속 홈과 통합 기록

2026-10-05. 첫 접속 홈 요청과 “기록·발췌·활동 구분이 헷갈린다”는 피드백을 반영했다. 디자인 책임자는 root이며 홈 표면, 탐색 연결, 브라우저 검증을 별도 에이전트에 맡겼다.

## 결정과 실제 동작

전역 탐색은 **홈 · 기록 · 도구 · 관리**다. 발췌는 원문 중 저장한 문장이므로 별도 최상위 탭을 없애고 기록 안에서 보여준다. 여러 기록을 연결하는 활동 구성은 **묶음**으로 표시한다. 저장 구조와 기존 `activities` 주소는 유지한다.

| 위치 | 실제 내용과 행동 |
| --- | --- |
| 홈 빠른 진입 | 기록·내 페이지·도구. 검색·가져오기는 제목 옆 아이콘 |
| 최근 담은 기록 | 현재 작업공간의 원문별 최신 보관 버전 3건. 원래 글 작성일과 구분해 ‘담음’ 표시 |
| 기록 묶음 | 기존 순서 2건. 선택한 묶음 편집을 펼쳐 초점을 이동 |
| 내 페이지 | 표시 설정을 따르는 한 항목 요약, 편집·비공개 미리보기 진입 |
| 기록 목록 | 원문과 연결된 문장·내 메모를 함께 표시. 문장 3개 이후 펼치기 |
| 기록 검색 | 제목·본문·저장 문장·주제·내 메모. 메모만 일치해도 정확한 참조 버전 유지 |
| 기록 정리 | 묶음·내 페이지 진입. 주제별 저장 문장은 검색 필터에서 찾기 |

홈은 실제 최근 내용을 보여주는 한 열이다. 목표·일정·수치를 중심으로 한 대시보드는 이번 범위에 두지 않았다. 사용자가 각 영역을 먼저 직접 체험하고, 이후 자주 보는 영역이나 시작 화면 선택을 조정한다. 홈 자체는 공개 블로그가 아니며 내 페이지 또한 현재 비공개 편집·미리보기다.

## 보존과 실패 경계

- 일반 `index.html`은 홈, `life.html`과 `?section=records`는 기록 목록이다. 명시적 `?view=topics` 등 기존 링크와 로그인 복귀 목적지를 보존한다.
- 홈은 현재 계정의 선택한 작업공간만 읽으며 자료·구성 저장이나 자동 동기화를 호출하지 않는다. 구성 조회가 지연되거나 실패해도 최근 기록과 다른 영역은 열 수 있다.
- 계정·작업공간·영역 전환 뒤 늦은 구성 응답이 이전 내용을 다시 그리지 않게 한다. 오류는 빈 자료로 표시하지 않고 재시도를 제공한다.
- 내 페이지의 소개·항목·부분·본문·코멘트 표시, 고정 순서를 따른다. 홈 요약을 위해 숨긴 페이지 내용을 드러내지 않는다. 개인 기록 목록에는 보관한 자료 자체가 계속 있다.
- 원문·출처·UTF-16 구간·버전·백업 형식은 변경하지 않는다. 검색 결과에서 문장을 열면 해당 구간으로 이동하고 돌아오면 검색어·펼친 출처·초점을 복원한다. 내 메모 일치를 원문 일치로 꾸미지 않는다.
- 묶음에는 최근 편집 시각이 없으므로 ‘최근 활동’으로 표시하지 않는다. 영속 읽기 위치가 없으므로 ‘이어서 읽기’라고 표시하지 않는다.
- 원문 동기화와 묶음·페이지·회고의 로컬 저장 범위는 기존대로다. 새 SQL·SNS 연결·추천·공개 게시를 추가하지 않았다.

## 재사용과 반대 검토

`haedo-navigation.js`·`haedo-shell.css`·`life/ui.css`·승인 A 아이콘과 실제 IndexedDB/Workbench 조회를 재사용한다. 2026-10-05 [공식 오픈소스 검토](../life-tools-design/open-source-review.md)의 idb 8.0.3(ISC)와 기존 원문 검색 결정을 적용했다. 새 데이터 계층이나 대시보드 라이브러리는 이 읽기 전용 목록에 필요하지 않다. 외부 제품의 최신 UI를 이번에 추가 조사했다는 의미는 아니다.

홈은 `home.js`/`home.css`의 재사용 모듈이며 공개 빌드 allowlist와 서비스워커 셸에 함께 포함한다. 기능 추가 때 [DESIGN.md](../../DESIGN.md)와 프로젝트 디자인 스킬에 남긴 네 메뉴·기록 통합 규칙을 적용한다.

단순한 대안은 기록 목록으로 바로 들어가는 것이다. 사용자가 반복적으로 홈을 건너뛰면 시작 화면 선택을 검토한다. 저장 문장이 많은 자료는 기본 3개와 펼치기로 밀도를 제한한다. 사용자 실사용 전 ‘찾기 쉬워졌다’는 가정을 확정하지 않는다.

## 검증과 한계

격리된 브라우저의 익명 한글 샘플과 실제 앱·동봉 SDK·IndexedDB를 사용하며 실계정 자료와 운영 DB는 검사용으로 수정하지 않는다. HTTP Auth 모사, 브라우저 크기·터치 모사, 실제 Google·Apple 기기 검증을 구분한다.


- 정적 검사: HTML 16, JS 37, 로컬 참조 201, PWA 셸 통과. Node 회귀 **208/208**.
- 새 홈·통합 기록 **12/12**: 최근 3건/묶음 2건, 조회 시 IndexedDB 쓰기 0, 표시 토글, 고정 버전, 원문→홈 초점 복귀, 메모만 일치하는 검색, 네 번째 접힌 문장으로 복귀, 중복 DOM ID 없음, 늦은 영역·작업공간·계정 응답 폐기를 검사했다.
- 기존 통합 홈 **13/13**, 주제/출처 **6/6**, 검색 **7/7**, 저장·앱·PWA **23/23**, 묶음·페이지·다시 찾기·회고·통합 백업 **17/17** 통과. 묶음/페이지 검사의 27개 시각 상태도 통과했다. PWA의 의도한 오프라인 인증 오류 1건은 예상 결과이며 정상 경로의 콘솔/페이지 오류와 구분했다.
- 홈 12상태(3폭 × 내용/빈/로딩/오류), 통합 기록 6상태(3폭 × 많은 문장/메모 검색)에서 가로 넘침·44px 미달·이름 없는 조작·대비 실패 0. 새 홈/기록 텍스트 최소 대비 **6.05:1**. Chromium **151.0.7922.173**을 사용했다.
- root가 홈 1440/390, 오류 820, 통합 기록 390, 검색 1440 이미지를 직접 검토했다. 글과 메모를 구분선으로 나누고 긴 한글 제목·출처 표시·메모 검색 결과의 버전을 확인했다.
- 처음 검증에서 홈의 ‘편집’이 이전 미리보기 상태를 유지하는 앱 문제를 찾아 `pagePreview:false`를 명시했다. 원문 버튼의 초점과 비동기 홈 복귀 시점도 보완하고 해당 경로를 재검사했다. 초기 결과와 수정 후 재검증은 최종 보고에서 구분한다.
- 실제 Mac/iPad/iPhone의 한글 IME·Files·VoiceOver·선택 손잡이는 미검증이다. 동봉 SDK와 모사 HTTP Auth로 계정 경계를 검사했으며 이번에 실제 Google 로그인이나 운영 DB 합성 자료 검사를 반복하지 않았다.

### 직접 체험

로그인한 홈에서 최근 기록을 열고 뒤로 돌아온다. `기록`에서 저장한 메모의 단어를 검색한 뒤 책 아이콘으로 정확한 원문을 열어 본다. 홈의 묶음을 누르면 그 묶음의 편집이 펼쳐지고, 내 페이지의 편집/미리보기는 각각 요청한 상태로 열린다. 내 페이지는 공개 게시가 아니며 로컬 구성을 다른 기기에 옮길 때는 자료·구성 백업을 쓴다.
