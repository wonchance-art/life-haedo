# 뉴스 피드와 명시 반응의 UI·UX 개편

2026-10-21 KST. 사용자는 ‘취소한 글’이 dislike인지 묻고 SNS·뉴스 앱처럼 뉴스 화면을 크게 개편하도록 요청했다. 시작점은 PR123·124를 포함한 main `b835454` / SW149다. [뉴스 열기](https://wonchance-art.github.io/life-haedo/index.html?section=news).

## 목표와 선택

첫 화면에서 기사보다 설정·관리 설명이 먼저 보이고, 모든 행동이 비슷한 무게로 반복되는 문제를 바꾼다. **피드 → 원문/명시 번역 → 좋아요·담기 또는 더보기 → 자료 보관·글쓰기 → 같은 뉴스 복귀**, 그리고 설정·기록 재열기까지 한 작업으로 검수한다. 공통 흰 면·틸·Pretendard·전역 탐색은 유지하면서 뉴스의 정보 구조와 기사 조작을 교체했다. [화면 방향](../../.impeccable/news-social-direction.md).

- 상단은 **피드 / 좋아요 / 담기** 세 목적지다. 최신순·관심순·개인 추천은 피드 안의 별도 정렬이다.
- **주제·출처 / 언어 옵션 / 추천·기록**에서 필요한 설정만 펼친다. 주제와 언어 입력 DOM, 미저장 선택·실패 복구는 유지한다.
- 기사는 실제 출처 이니셜·이름·날짜, 큰 원문 제목, 제공된 요약, 좋아요·담기·명시 번역 순서다. 새로운 이미지·가짜 요약·반응 수·외부 favicon 요청은 없다.
- **글 옵션**에 자료 보관·읽음·관련 없음·추천 근거 제외·완전 삭제를 모았다. native details를 사용하고 Escape로 닫으면 해당 summary에 초점을 돌려준다. 같은 화면을 다시 그려도 펼친 기사 메뉴를 유지한다.
- 본문 확보 범위와 추천 표현의 근거는 **기사 정보**에서 확인한다. 출처 수집 실패는 짧은 안내와 기존 출처 상태 상세에서 확인하며 성공으로 바꾸지 않는다.
- **읽기 비교**는 추천·기록 안으로 옮겼다. 현재 비교의 DOM·입력·불변 스냅샷은 유지하고, 긴 피드 끝까지 내려가야 찾던 문제를 줄인다.

단순 CSS 보완만 하는 대안은 메뉴명 혼동과 행동 위계를 해결하지 못한다. 별도 뉴스 프레임워크·SNS 서버를 도입하는 대안은 기존 정적 앱·로컬 CAS와 운영 범위를 불필요하게 바꾼다. 기존 컴포넌트와 native DOM의 재배치를 선택했다.

## 반응과 제외의 뜻

| 표시 | 실제 동작 |
| --- | --- |
| 좋아요 | 명시 긍정 반응. 개인 추천을 직접 켰을 때만 기존 제목·태그 근거로 사용할 수 있다. |
| 담기 | 다시 볼 링크 메타데이터 목록. 본문 확보·자료실 보관·긍정 추천 신호가 아니다. |
| 반응 해제 기록 | `!liked && !bookmarked`인 기존 반응 행. 예전 ‘취소한 글’을 바꾼 이름이며 dislike가 아니다. 좋아요·담기를 다시 선택할 수 있다. |
| 관련 없음 | 해당 canonical URL을 발견 후보에서 제외한다. 비슷한 글 전체를 줄이는 학습이 아니다. |
| 읽음 | 사용자가 직접 고른 목록 제외. 원문 클릭·스크롤로 자동 생성하지 않는다. |
| 추천에 사용하지 않기 | 좋아요·담기는 유지하면서 해당 좋아요의 추천 근거만 제외한다. |

반응 해제 행은 명시 사본 병합·복구에서 기존 해제를 보호하는 데이터이기도 하다. 화면을 정리하기 위해 삭제하거나 부정 피드백으로 변환하지 않았다. Storage·Actions·Profile·추천 정책·읽기 비교 모델·원문/글/공개 형식은 변경하지 않는다.

## 검수와 출시 근거

고정 비교 자료는 체크인된 공개90글/7출처 SHA256 `446e471f2d262b5ca8f39c64244b96b9c799aeecc4eb5c011bd7d608a2b8bf4e`다. 운영 수집100글/8출처와 섞지 않는다. 실제 SDK·격리 IndexedDB·합성 Auth로 같은 자료와 상태에서 비교했다. 390px 첫 기사 제목은 y591.78→380.75, 820·1440px은 y588.03→392.75다. 첫 화면·기사 옵션·언어·추천 설정의12장 한 묶음에서 가로 넘침·44px 조작 미달·대표 글자 대비 미달이 없었고, 최소 측정 대비는5.59:1이었다. 이 수치는 화면 위계의 비교이며 추천 유용성이나 Apple 실기 성공의 증거가 아니다.

단위1173개와 정적22HTML/150JS/636참조를 통과했다. 새로운 집중 검사는 반응 해제의 중립성·명시 제외·독립 반응 복구·더보기 Enter/Escape·한글 조합·저장 실패 재시도를 확인한다. 기존 검사의 기대 데이터·단언·제한 시간은 유지하고, 숨겨진 조작까지 실제 summary를 클릭해 접근하도록 보완했다. 기존 발견19/19·뉴스9/9·읽기 비교5/5·언어14/14와 반응 기능21개/수정 후 시각3개가 통과했다. SW149 worker→현재150 모듈의 PWA9/9는 현재 읽기 세션·명시 판단·revision2 원시값을 업데이트/오프라인/되돌리기/인증 복구 동안 보존하고, 설치된15모듈의 해시와SHELL162를 확인했다. 전체 역사적149앱을 실행한 실기 검사가 아니다.

첫 반응 실행은 기능21개 통과 뒤 시각3개에서 실패했다. 새 보조 패널을 마우스로 연 뒤 키보드 초점을 검사해 `:focus-visible`이 해제된 테스트 준비 순서가 원인이었다. 실제 summary를 먼저 연 뒤 Tab/focus하는 순서와 summary의 중복 토글을 바로잡고, 원래 단언·제한 시간으로 해당 시각3개만 새 결과 폴더에서 통과했다. 최초 리포트를24/24 성공으로 덮어쓰지 않는다. 첫 PWA 실행의4개 통과 뒤 실패는 축약한 수집 지연 안내와 기존 기대 문구의 불일치였다. 정확한 새 문구2곳만 갱신해 최종9개 전체를 다시 확인했다. 원래 stale 헤더·공급 해시·보존·시간 제한·인증 검증을 약화하지 않았고 원본 실패를 남겼다.

독립 시각 최종 검토는 첫 판의 글 옵션 버튼이 열릴 때48px 내려가는 문제를 지적했다. 한 번의 보완으로 반응과 더보기를 같은 grid 행에 두고 옵션 본문만 정상 흐름에서 펼치도록 바꿨다. 동일 폭의 재캡처·위치/클릭 검수와 해당 검토자의 수정 항목 판정은 PR의 최종 영수증을 따른다. 추가적인 취향 보정 반복 없이 이 보완을 마감한다.

정확한 최종 커밋의 PR/main CI·운영 수집·공개 파일 대조·배포본 여정과 위 로컬 실행 범위는 [이 변경의 PR 기록](https://github.com/wonchance-art/life-haedo/pulls?q=is%3Apr+head%3Acodex%2Fnews-social-redesign-20261021)을 따른다. 자동으로 끝낼 수 있는 출시 검수를 사용자 실독의 선행 조건으로 넘기지 않는다.

합성 Auth·번역/원문 팝업·평가 답변은 실제 계정·Google/출판사 응답·사용자 읽기 효용이 아니다. 실제 Mac·iPad·iPhone의 사용과 도움 판단은 미확인이다. 부정확한 메뉴명·미저장 입력·초점/복귀·기존 데이터 보존의 결함이 발견되면 같은 흐름에서 고치며, 실제 직접 판단 없이 추천 모델이나 서버 학습을 새로 켜지 않는다.
