# 소셜 앱의 반응감을 적용한 세 가지 자료 화면

2026-10-03. 이번 요청은 Instagram·Threads·X처럼 익숙한 상호작용을 바탕으로 **더 트렌디하고 색과 반응이 통통 튀는 화면**을 비교하는 것이다. 이전의 따뜻하고 절제된 방향을 이번 시안의 고정 조건으로 두지 않는다. 아래 A/B/C는 이전 `design-sample.html`의 세 방향과 별개의 새 콘셉트다. 현재 [social-sample.html](../../social-sample.html)에서 메모리 기반의 상호작용 시안으로 비교할 수 있다.

이 문서는 디자인 제안이다. 서비스의 현재 UI를 그대로 복제하거나 최신 공식 화면을 직접 검증했다는 뜻이 아니다. 소셜 표현을 가져오되 중심 작업은 여전히 **내 자료 찾기 → 원문 읽기 → 발췌와 내 생각 → 다시 찾기**다. 사용자가 고른 방향이나 운영 기능 완료로 해석하지 않는다.

## 공통 비교 조건

세 안은 [공통 익명 자료](sample-content.md) 12건과 동일한 검색어·선택 원문을 사용한다. 긴 제목, 이전 버전, 작성일 미상, 일부 본문, 링크 전용 자료도 같은 조건으로 비교한다. 이전 감사의 자료 세트와는 다르므로 수치로 개선율을 계산하지 않는다.

| 소셜 앱에서 익숙한 표현 | 이 제품에서의 실제 의미 |
| --- | --- |
| 원형 링·주제 줄 | 내가 보는 주제 선택. 새 게시물 알림·24시간 만료·읽기 완료율이 아님 |
| 피드 항목 | 선택해 가져온 자료 또는 일치한 원문 버전. 자동 수집·추천 결과가 아님 |
| 저장 아이콘·선택 반응 | 내 저장 선택을 켜고 끄는 시안 반응. 기존 원문 보관·원격 저장 성공과 구분 |
| 답글 모양의 연결 줄 | 이 원문에서 만든 내 발췌와 연결 이유. 다른 사람의 댓글이 아님 |
| 작은 개수 표시 | 실제 시안에서 선택하거나 추가한 내 자료·발췌 수만 표시. 좋아요·조회·팔로워·인기도를 꾸며 넣지 않음 |
| 고정 탐색·옆 읽기 패널 | 현재 목록을 유지하며 자료를 열고 돌아오는 경로. 새로운 서비스 연동이 아님 |

## A · 컬러 모음

**목적:** 흩어진 개인 자료가 내 관심사로 모이는 느낌을 첫 화면부터 강하게 전달한다. 이번의 활기와 반응감 요구에 가장 적극적으로 답하는 안이다.

- **첫 화면:** 짧고 굵은 제목, 선명한 주요 행동, 가로 주제 링, 제목·일치 문장을 담은 그리드. 링은 ‘읽기와 기록’, ‘걷기와 관찰’처럼 이름을 함께 표시한다. 사람 얼굴이나 아직 없는 원문 사진을 예시 썸네일로 꾸미지 않는다.
- **정보:** 제목과 일치 문장이 카드의 주인공이다. 출처·본문 확보 범위·이전 버전은 작은 칩으로 구분하고, 정확한 날짜와 누락 범위는 상세에서 확인한다. 서로 다른 색은 주제/선택을 돕는 규칙으로 사용하며 임의의 인기도를 뜻하지 않는다.
- **활자·밀도:** 굵은 한글 산세리프와 넉넉한 제목 대비. 현재 시안은 진한 핑크 `#B5135B`와 흰 글자의 첫 문장 타일, 블루 `#DFE5FF`, 피치 `#FCE6C6`, 그린 `#D5EDE3` 타일을 번갈아 사용한다. 핑크·블루·피치·그린 계열의 주제 링과 밝은 핑크 바탕 `#FFF8FC`도 적용했다. 넓은 화면의 그리드는 고정 2열, 모바일은 1열이다. 색 값은 [시안 CSS](../../assets/design-social/ui.css)를 근거로 하며 대비 검사와 시각 선호는 구분한다. 카드 높이를 맞추려고 원문 제목을 잘라 저장하지 않는다.
- **반응:** 주제 선택 시 링과 선택 칩이 즉시 바뀐다. 저장 선택은 작은 눌림·한 번의 짧은 되튐과 ‘선택됨’ 상태로 응답한다. 발췌 추가에는 관련 카드/내 발췌 수만 반응한다. 모든 카드의 반복 등장 효과나 자동으로 계속 움직이는 링은 넣지 않는다.
- **읽기:** 선택한 자료는 넓은 읽기 영역으로 열고, 발췌 도구에도 같은 강조색을 이어간다. 길게 읽는 동안 전체 문단에 높은 채도를 두르지 않고 선택 구절과 행동에 반응을 집중한다.

**확인할 비용:** 색·링·그리드가 너무 강하면 제목과 일치 문맥보다 먼저 보일 수 있다. 390px에서도 첫 자료를 찾기 쉬운지, 긴 제목 카드가 섞여도 순서가 명확한지, 원문에서 돌아오면 기존 위치를 찾을 수 있는지 확인한다. 그리드는 시각 순서와 키보드 읽기 순서를 일치시킨다.

## B · 문장 피드

**목적:** 문장을 읽고 바로 내 생각으로 연결하는 일을 자연스러운 대화 흐름처럼 만든다. 한 자료를 오래 읽고 발췌·메모를 이어 붙이는 데 적합하다.

- **첫 화면:** 가운데 한 열의 문장 피드. 원천 이름/기호와 제목, 실제 일치 문맥, ‘원문 읽기·저장·발췌’ 행동이 항목 안에 이어진다. 옆 여백에는 주제 탐색만 둔다. 원천 기호가 다른 사람이 작성한 계정이나 개인 프로필로 오해되지 않게 표시한다.
- **정보:** 원문 발췌가 첫 문장, 내 연결 이유는 그 아래의 답글 형태다. 연결선·작은 들여쓰기로 둘의 관계를 보여주되 ‘원문’과 ‘내 생각’이라는 이름을 유지한다. 발췌 시점의 출처·버전은 연결 줄 안에서도 다시 확인할 수 있다.
- **활자·밀도:** 편하게 읽히는 16–18px 본문과 한 단계 굵은 제목. A보다 색의 면적은 줄이되 바이올렛 포인트 `#5442BC`, 보조 표면 `#EEEBFF`, 둥근 행동 버튼으로 이전 시안보다 경쾌하게 만든다. 텍스트가 긴 항목은 일부 문맥을 보여주고 전체 원문으로 연결한다. 피드가 클릭 수를 늘리는 긴 설명 목록이 되지 않게 한다.
- **반응:** 현재 시안에서는 피드의 ‘발췌’로 원문 읽기 화면에 들어가 구절·선택 주제·내 생각을 작성한다. ‘발췌 연결’ 뒤 목록으로 돌아오면 해당 자료 아래에 발췌와 내 생각이 답글 모양으로 붙는다. 피드 안에서 바로 작성하는 기능은 구현하지 않았다. 좋아요 수 대신 내 저장 상태를 바로 보여준다. 장식용 댓글·가상 대화·새 알림은 넣지 않는다.
- **읽기:** 선택한 원문을 중앙 읽기 영역으로 열고 검색 피드로 돌아올 위치를 유지한다. 모바일에서는 답글 들여쓰기를 작게 하여 긴 한글 문장의 폭을 지나치게 줄이지 않는다.

**확인할 비용:** 포인트를 약하게 쓰면 이번에도 ‘정돈됐지만 심심한 화면’에 머물 수 있다. 사용자 반응 기준은 단정함만이 아니라 저장·선택·발췌에서 충분한 활기가 느껴지는지다. 답글 모양이 원문과 내 메모를 섞거나 외부 사람의 의견으로 보이게 하는지도 확인한다.

## C · 빠른 탐색

**목적:** 자료가 많을 때 짧은 시간에 여러 원문을 열고 비교한다. 조밀한 피드와 고정 탐색으로 작업 리듬을 강조한다.

- **첫 화면:** 작지만 분명한 제목, 바로 쓰는 검색, 조밀한 한 열 결과, 고정 탐색. 현재 넓은 화면에서는 결과 목록과 **선택 원문의 간단 미리보기**를 나란히 놓는다. 비교를 돕지 않는 통계·추세 그래프는 넣지 않는다.
- **정보:** 한 항목에서 제목, 첫 일치 문맥, 원천·받은 범위·버전을 빠르게 훑는다. 선택 항목은 색뿐 아니라 윤곽과 상태로 구분한다. 현재 옆 패널은 각 항목의 ‘미리보기’로 선택한 자료의 제목·원천/확보 범위·짧은 문장을 표시한다. 전체 원문이나 검색 일치 위치를 패널 안에서 이어 읽는 기능은 아니다. ‘원문 읽기’로 별도의 읽기 보기로 전환한다. 운영 반영 때 과거 발췌 근거를 최신 본문으로 바꾸지 않는 계약을 유지해야 한다.
- **활자·밀도:** 검색 결과의 행 간격과 보조 정보는 조밀하게, 긴 원문은 17px 안팎의 별도 읽기 밀도로 분리한다. 블루 포인트 `#0964B4`, 흰 바탕 `#FFFFFF`, 옅은 블루 선택/보조 표면과 둥근 고정 탐색을 사용한다. 조밀함을 위해 터치 영역을 줄이지 않는다.
- **반응:** 항목의 ‘미리보기’에 선택 상태와 옆 패널 내용이 바뀌고, 저장/발췌 반응은 해당 항목에 연결된다. 빠르게 전환해도 오래된 응답이나 다른 자료의 선택 상태가 뒤늦게 덮어쓰지 않게 설계한다. 원문으로 가는 기능은 호버 없이도 보인다.
- **기기:** 현재 데스크톱은 목록+간단 미리보기다. 1200px 이하에서는 보조 패널·미리보기 버튼을 접고 주제 칩을 유지한다. 원문 읽기는 별도의 보기이며 iPad도 가용 폭에 맞춰 읽기·발췌를 세로로 배치한다. iPhone은 고정 하단 탐색과 읽기 보기로 이동하고 목록 복귀를 제공한다. 키보드·안전 영역에 가려지는 입력이나 행동을 만들지 않는다.

**확인할 비용:** 고정 메뉴와 패널이 실제 본문 폭을 빼앗을 수 있다. ‘많이 보인다’와 ‘읽기 쉽다’를 별도 판단하며, iPad 분할 폭·390px에서 주된 행동이 가려지면 보조 영역을 먼저 접는다.

## 추천과 선택을 바꿀 조건

**이번 새 요청에는 A를 우선 추천한다.** 이전의 낮은 시각적 에너지를 분명하게 바꾸고, 주제 선택·내 저장·발췌에 색과 반응을 직접 연결하기 좋기 때문이다. 단순히 버튼만 진하게 바꾸는 것보다 첫 화면·항목 형태·눌렀을 때의 응답까지 일관된 변화를 보여줄 수 있다. 장기 읽기는 A의 주제·선택 표현에 B의 문장·내 생각 위계를 결합하는 후속 조정 후보로 둔다.

B를 기본으로 A의 선택 반응을 더하는 조합도 타당하다. 다만 그것을 처음부터 추천 답으로 고정하면 ‘차분한 화면을 다시 만드는 것’으로 끝날 수 있다. 세 독립 안을 먼저 비교하고, 사용자가 활기보다 문장 흐름을 더 선호한다는 피드백이 있으면 B로, 많은 자료를 빠르게 비교하는 장면이 우선이면 C로 바꾼다. 한 화면에 세 안의 모든 장점을 한꺼번에 넣지 않는다.

| 비교 질문 | A가 답하는 방식 | B가 답하는 방식 | C가 답하는 방식 |
| --- | --- | --- | --- |
| 첫 화면에서 분위기가 충분히 달라졌나? | 주제 링·강한 색·2열 자료 그리드 | 문장 중심 피드·발췌 답글 연결 | 조밀한 탐색·뚜렷한 선택·간단 미리보기 |
| 눌렀을 때 실제로 무엇이 달라졌나? | 선택 주제와 다시 볼 자료 상태 | 원문에서 추가한 발췌·생각이 피드 아래에 이어짐 | 선택한 간단 미리보기와 목록 맥락 |
| 가장 큰 비용은? | 색과 카드가 원문 단서보다 강해질 가능성 | 변화가 소극적으로 보이거나 메모/원문이 섞일 가능성 | 고정 영역이 읽기 폭을 줄일 가능성 |

## 상호작용과 운영 계약의 경계

시안은 익명 자료와 메모리 반응으로 선택·저장 토글·발췌·복귀를 체험하는 **제안**이다. 공용 인증, 계정별 저장, 동기화, 백업, 기존 앱의 Core를 연결한 완전한 운영 개발이 아니다. 새로고침하면 시안의 선택과 발췌가 사라진다는 안내를 제공한다. 이전 `design-sample.html`과 운영 `life.html`은 보존한다.

- 원문·작성 시각·가져온 시각·본문 확보 범위·출처·버전의 뜻은 세 안에서 같다. 제목만 일치와 링크 전용 자료를 본문 일치로 표시하지 않는다. 예시 설명을 실제 인용이나 AI 분석으로 바꾸지 않는다.
- 시안의 DOM 텍스트 선택이나 예시 구절은 운영 `SourceVersion.contentText`의 UTF-16 위치 계약을 검증한 것이 아니다. 운영 반영 때 CRLF·이모지·중복 문장·이전 버전·정확한 참조를 다시 확인한다.
- 검색어·원천/주제 조건·선택 원문·복귀 위치는 상호작용 도중 유지한다. 검색어는 공유 URL·지속 저장·원격 요청에 쓰지 않는다. 주제와 내 생각은 선택 입력으로 유지한다.
- 화면의 ‘저장 선택’ 반응, 발췌 추가, 기기에 저장됨, 원격 동기화 성공을 서로 대신 쓰지 않는다. 실패·빈 결과·불러오는 중에도 무엇이 남았고 다음에 무엇을 할지 표시한다.
- 시안에서 생략한 작업공간 선택·계정·동기화·내보내기/사본 복원은 운영 통합 때 접근 경로를 마련한다. 작은 상단을 만들려고 기존 관리 기능을 없앤 것으로 간주하지 않는다.
- 현재 시안의 반응은 180–300ms다. 버튼 눌림/색 변화 180ms, 항목 행동 200ms, 주제 링 220ms, 저장 아이콘의 한 번 되튐 300ms를 CSS로 적용했다. 한 번의 반응 후 선택 상태가 남아야 하며, 모션 감소 설정에서는 이동·되튐을 줄여도 같은 결과와 상태를 제공한다. 자동 재생·무한 스크롤·반복 진동·실제 기기 햅틱을 이번 시안의 완료로 약속하지 않는다.

## 실제 시안 화면의 관찰

[시각 캡처](evidence/social/)는 세 안 모두 1440·820·390px의 피드와 원문 화면으로 구성된다. 아래는 직접 본 대표 화면과 현재 구현의 차이를 정리한 것이다. 색·반응의 취향이 확정됐다는 의미는 아니다.

| 방향 | 직접 확인한 대표 화면 | 관찰과 비교 추천 |
| --- | --- | --- |
| A · 컬러 모음 | [넓은 피드](evidence/social/color-feed-desktop.png), [모바일 원문](evidence/social/color-reader-phone.png) | 문장을 크게 놓은 컬러 타일과 주제 링이 세 안 중 시각적 변화가 가장 분명하다. 색으로 감싼 문장과 그 아래 제목·본문 문맥은 역할이 다르다. 최종 핑크 타일은 진한 바탕·흰 글자로 대비를 강화했다. 이번의 활기 요구에 우선 추천한다. |
| B · 문장 피드 | [넓은 피드](evidence/social/thread-feed-desktop.png), [모바일 원문](evidence/social/thread-reader-phone.png), [발췌·내 생각 연결](evidence/social/thread-connected-phone.png) | 문장·제목·행동의 한 열 흐름이 소셜 문장 피드처럼 이어진다. 원문에서 추가한 구절·주제·내 생각이 해당 자료 아래의 바이올렛 영역으로 연결된 모습도 확인했다. 피드 안의 즉석 작성이나 외부 댓글은 아니다. 긴 문장 읽기와 내가 붙인 생각의 관계를 우선하면 적합하다. |
| C · 빠른 탐색 | [넓은 피드](evidence/social/pulse-feed-desktop.png), [모바일 원문](evidence/social/pulse-reader-phone.png) | 블루 선택과 조밀한 결과, 옆 미리보기로 여러 자료를 오가기 쉽도록 구성했다. 미리보기는 실제 선택 항목의 짧은 문장으로 바뀌지만 전체 원문 병렬 읽기는 아니다. 모바일 원문은 큰 카드 테두리를 줄여 본문에 더 넓은 폭을 준다. |

현재 시안에서도 **A를 우선 비교할 안으로 추천**한다. B는 읽기 흐름, C는 빠른 탐색을 더 강하게 제공하지만 사용자에게 요청받은 색과 반응의 변화가 A에서 가장 직접적으로 드러난다. A의 선택 표현을 유지하면서 장기 읽기의 타이포그래피·원문/내 생각 구분에 B의 장점을 더할 수 있다. 세 안을 모두 섞은 한 화면을 만드는 결론은 아니다.

첫 캡처 검토에서 탐색 이름의 줄바꿈, iPad 폭의 가져오기 버튼 글자 분리, 주제 링 윤곽 공간을 확인해 디자인 책임자가 배치/여백을 조정했다. 처음의 연한 핑크 타일도 진한 핑크·흰 글자로 바꿨다. 갱신된 데스크톱 피드·모바일 원문 대표 6장, A/C의 820px 피드, B의 모바일 발췌 연결 화면을 직접 다시 확인했다. 820px의 A는 2열과 가로 가져오기 버튼을, C는 옆 패널을 접은 주제 칩과 한 열 결과를 유지한다.

별도 검증 담당자의 최종 Chromium 검사(시작 시각 `2026-10-03T16:38:47.950Z`)는 78장면·28흐름을 통과했고 콘솔/페이지 오류·가로 넘침·외부 요청은 0이었다. B의 연결 상태는 추가 1장면·1흐름 검사와 캡처로 확인했다. 실제 계산된 평면 색의 최저 텍스트 대비는 4.98:1이었다. 상세 실행 범위와 결과는 [소셜 시안 검증](social-verification.md)에 기록한다. 이 문서의 직접 이미지 검토와 별도 자동 검사 결과는 구분한다.

실제 Mac·iPad·iPhone, iPad Chrome, Apple 글꼴·키보드·텍스트 선택 손잡이 체험은 미검증이다. Chromium의 화면 크기/터치 모사와 DOM 선택 표시는 실제 Apple 동작이나 운영 Core의 UTF-16 위치 보존을 증명하지 않는다. 사용자의 시각적 선호·읽기 피로·체험 부담도 검사 통과만으로 결정하지 않는다. 시안의 메모리 동작과 공용 인증·계정별 저장·동기화·원문 참조를 연결하는 운영 통합은 이번에 완료한 범위가 아니다.
