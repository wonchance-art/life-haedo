## 비교 조건 보완과 한계

기존 언어 비교 도구는 출처 끄기·기보관·읽음/관련 없음의 화면 조건을 지정할 수 없었다. `--conditions-file`로 네 조건을 명시해 기존 앱 필터·피드백 검증기를 재사용한다. 네 비교군의 후보·좋아요 근거에 동일 출처/언어를 적용하고 과거 좋아요 URL 제외는 신호 제거 뒤에도 유지한다. 개인 저장소를 자동 읽거나 계정 설정/추천 opt-in을 바꾸지 않는다. [형식·실행 명령](discovery-field-languages.md).

집중27/27, 전체 단위1116/1116, 정적22HTML/147JS/627참조를 통과했다. CLI·테스트·문서만 바꾸며 앱 런타임·SW·수집 정책은 그대로다. 기본 실행과 명시 빈 조건의 순위/메타데이터를 보존했고 새 코드의 출처 해시는 달라진다. 기존 답을 덮어쓰지 않고 gitignored 새 폴더에만 비공개 결과를 쓴다.

고정 공개 공급·시각의 참고 비교는 전체90/영어40 후보이며 `Linguistics` 문자 일치20개다. 이 예시는 실제 사용자 선택이 아니다. 상위 MIT의 넓은 공식 태그 일치에는 특정한 읽기 목적에 직접 도움이 되는지 불명확한 기사도 포함된다. 실제 읽기 의향·실독 후 도움·사용자 조건 확인은 모두 null이며 취향·추천 품질 향상으로 계산하지 않았다. 다음 단계의 필요 이유·선행 조건·완료 기준은 [최신 로드맵](../life-tools-design/roadmap.md)을 따른다.
