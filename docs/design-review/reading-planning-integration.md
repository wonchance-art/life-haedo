# 읽기·메모·계획을 다시 입력하지 않고 잇기

2026-10-29. [생활 시스템](../life-tools-design/life-system-contract.md)의 통합 동선 결정이다. 코드 조사 기준은 main `30e94f0`, 최종 통합 기준은 `55a74ae`, 설계 기준은 PR142다. [PR143](https://github.com/wonchance-art/life-haedo/pull/143)의 네이버 수집 중지·목록 복구가 main에 병합됐으며 이번 조사 모듈은 바뀌지 않았다. 읽기 메모/계획 연결 구현이나 실제 상류 수집 가동 완료를 뜻하지 않는다. 따라서 이번 결과는 **코드 대조·설계 교정·합성 시연 검수**다. 실제 후보의 계정 저장·다른 기기 재개와 사용 효용은 아직 검수하지 않았다.

## 같은 목표 안에서 줄일 것

읽다가 작은 행동을 정했다면 선택 문장과 기존 습관만 연결한다. 생각 자체를 남기려면 메모를 저장하고, 필요할 때 그중 선택한 문장을 연결한다. 월 계획을 고쳤다면 그 자리에서 끝낸다. 기간을 확인했다면 저장 없이 돌아갈 수 있다. 이 네 장면에 같은 시작·종료 조건을 정해 재입력·재선택·복귀를 비교한다.

| 장면 | 시작 → 완료 | 새로 필요한 결정 | 반복해서 요구하지 않을 것 |
| --- | --- | --- | --- |
| 직접 연결 | 정확 원문에서 고른 문장 → 기존 습관에 연결 → 읽던 곳 | 의도 문구 확인, 기존 대상 선택, 연결 확정 | 메모 저장, 준비 만들기, 월 항목 선택, 문장/출처 재입력 |
| 메모 후 연결 | 같은 원문 → 내 판단 저장 → 선택 문장 연결 → 같은 메모 | 메모 내용 작성·저장, 연결할 부분·대상 선택 | 메모/제목 재입력, 다른 자료·개요 관리, 수동 보내기/받기 |
| 계획만 수정 | 열린 월 항목 → 문장 수정 → 같은 항목 재열기 | 바꿀 문장 | 목표 연결, 회고, 연도·생일·시간대 재설정 |
| 기간 확인 | 현재 대상·선택 기간 → 확인 후 복귀 또는 회고 저장·재열기 | 범위 변경은 선택, 저장과 내 판단도 선택 | 같은 대상·기간 재선택, 미선택 목표 해제, 평가 점수 입력 |

직접 연결과 메모 후 연결은 결과물이 다르므로 클릭 수를 단순 순위로 만들지 않는다. 직접 연결은 ‘연결만 하려는데 메모를 강제로 거치는 안’과 비교한다. 메모 경로는 판단 보관이라는 결과를 유지한 채 기존 작성 준비의 시각·관리 부담과 비교한다. 현재 준비는 빈 제목·개요를 허용하므로 ‘필수 제목 입력을 없앴다’고 주장하지 않는다.

비교 기록은 **명시 행동, 같은 내용 재입력, 대상 재선택, 문맥 전환, 복귀 실패, 실패 후 다시 해야 한 일**이다. 새 판단 작성은 재입력이 아니며, 저장소 반영 대기나 실제 사람의 사용 시간은 시연 클릭 횟수로 대신하지 않는다. 같은 자료의 후보가 여러 개인 예외는 정상 단일 후보와 분리한다.

## 입력과 확정의 경계

연결 선택기는 현재 읽기/메모 DOM을 보존하는 인라인 영역 또는 기존 dialog에서 연다. 열기·문구 검토·대상 선택에는 관계/목표 생성이 없다. `navigate()`를 호출해 전역 flush부터 실행하지 않는다. 실제 다른 화면으로 이동할 때만 dirty·IME·저장 보호를 통과한다.

| 상황 | 보존하는 것 | 사용자가 확인할 결과 |
| --- | --- | --- |
| 직접 연결 열기·취소 | 원문·선택·위치, 입력 | 새 메모/준비/목표/관계 0 |
| 메모 편집 중 선택기 취소 | 원래 DOM·미저장 입력·이미 커밋한 메모 | 새 관계/목표 0. 기존 자동 저장까지 취소됐다고 표시하지 않음 |
| 관계 확정 | 조작 당시 확인한 문구·정확 출처·고정 operationId | 관계 자체의 의도 사본 저장. 원본 메모/대상 값은 수정하지 않음 |
| 저장하지 않은 메모 문구 연결 | 선택 문구 사본·검증된 출처 | 관계는 가능; 존재하지 않는 저장 메모 ID/과거 판 참조 생성 금지 |
| 메모는 저장, 연결은 실패 | 메모·문구·대상·동일 operation | 연결만 재시도. 메모를 다시 쓰거나 다시 생성하지 않음 |
| 관계는 성공, 화면 열기는 실패 | 성공 영수증과 같은 대상 | 다시 열기. 관계 실패로 되돌리거나 새 관계 생성 금지 |
| 응답 확인 전 닫기 | 이미 시작한 작업과 원래 owner의 대기 | 아직 확인 중. 서버 작업까지 취소했다고 표시하지 않음 |
| 연결 후 뒤로가기 / 연결 해제 | 뒤로가기는 탐색만; 해제는 관계 tombstone | 원문·메모·목표·체크·저장 회고 유지 |

메모 계정 보관, 관계 계정 보관, 목표 상태 확인, 정확 근거 수신은 별개다. `store.flush()` 반환은 ACK 증거가 아니다. 입력 또는 대상이 바뀌면 예전 선택 사본으로 확정하지 않는다. 조합 중 문장을 중간 문자열로 잘라 연결하지 않는다.

메모의 ID/revision은 실제 커밋을 확인한 경우에만 참조로 붙인다. 관계는 독립된 의도 사본으로 사용할 수 있으며 메모의 원격 ACK를 모든 직접 연결의 선행 조건으로 만들지 않는다. 노트·관계·원문 각각의 실패/대기 상태를 합쳐 ‘모두 저장됨’이라고 표시하지 않는다.

## 정확 복귀와 기기 경계

같은 문서의 복귀 문맥은 owner/계정 세대, workspace, source/version/hash, 검증 locator, 원래 화면·focusKey·scroll, 메모 ID와 편집 상태다. 현재 제목이나 최신 판으로 목적지를 다시 찾지 않는다. 세션 위치는 사용자 기록·파일·공개 사본에 넣지 않는다.

목표·습관의 별도 HTML을 여는 경우에는 문서 메모리 Map만으로 복귀를 약속하지 않는다. 프로젝트/계정으로 구분한 **탭 세션의 짧은 복귀 기록**과 불투명한 반환 키를 사용한다. 개인 메모·인용문·임의 외부 URL을 쿼리 문자열에 싣지 않는다. 허용된 내부 화면·정확 ID만 해석하며 임의 URL로 이동하는 redirect를 만들지 않는다. 로그아웃/계정 전환에 비우고 키가 없거나 만료됐으면 현재 기기의 유효한 목록으로 돌아간다. 이 임시 탐색 상태는 브라우저 전용 자료 보관 정책이 아니다.

다른 기기는 계정에서 받은 같은 메모/대상부터 연다. A의 스크롤·임시 선택·미저장 입력을 B에 추정 복원하지 않는다. 원문이 없으면 ‘근거 미확보’, 대상 삭제면 ‘삭제된 대상’, 요청 실패면 ‘불러오지 못함’으로 구분한다. 동명 자료로 대체하지 않는다.

## 선택한 기간의 사실만 확인

화면 날짜는 시작일·종료일을 모두 포함하는 달력 날짜다. 내부 저장은 기존 `[start,endExclusive)`를 유지하며 종료일 다음 날로 변환한다. 같은 날 범위도 유효하다. 월말·윤일·지원 끝 날짜는 같은 변환기로 검증한다. 예시 10월 1~31일은 내부 `2026-10-01`~`2026-11-01`이다.

기간 진입 시 현재 대상·구간을 전달한다. 다른 목표를 기본 포함해 사용자가 해제하게 하지 않는다. 월 방향, 습관, 목표는 각각 선택할 수 있고 적어도 하나가 있어야 한다. **계획만 확인, 습관만 확인**도 유효하다. 표시·snapshot·내보내기의 선택 범위를 같게 한다.

관계는 선택 대상에 해당하는 것만 포함하고, 월 방향을 제외하면 관계의 monthRef/월 문장도 사본에서 제외한다. 직접 의도 문구는 선택 대상의 연결 근거로 남는다. 저장 전 비교는 선택한 계획 revision·대상 stamp·관계 투영에 한정한다. 무관한 목표 수정으로 전체 조회를 다시 요구하지 않는다. 선택 대상이 바뀌면 판단 입력을 보존하고 재확인한다.

자료의 최신 확인 여부와 회고의 계정 보관 여부도 분리한다. 사용자가 확인 가능한 사본과 누락 범위를 보고 저장을 선택하면 그 사본·판단의 계정 전송 의도를 영속 보관한다. 확인 실패 때문에 영구적인 브라우저 전용 회고로 전환하지 않는다. 나중에 근거가 도착해도 저장한 판을 조용히 다시 쓰지 않는다.

## 같은 실행 묶음의 책임과 출시 조건

| 담당 | 함께 끝낼 변경 | 통합 조건 |
| --- | --- | --- |
| 읽기/메모 | 새 메모 계정 기본 보관·기존 메모 명시 계승·재열기·파일 | 메모만 A→B→A, 미저장/ACK/정확 판·복원 구분 |
| 문맥/대상 | 구절 전달·기존 대상 조회·선택기·정확 페이지 진입/복귀 | 메모 없이 연결, 선택 문구 재입력 0, 실패 후 같은 작업 재개 |
| 계획/회고 | 선택 범위·날짜 표현·불변 판·계정/복원 | 계획만/습관만/조회만 완결, 무관한 변경 차단 0 |
| 통합/독립 검수 | 실제 후보와 시연 대조, 기존 데이터/입력/PWA | 정상·부분 성공·충돌·계정 전환·3폭·정확 파일과 출시 근거 |

새 읽기 메모 기본 보관, 직접 관계, 계획/회고의 선택 범위를 같은 사용자 목표로 구현한다. 서버·화면·파일을 따로 완료로 보고하지 않는다. 기존 준비 전체 자동 이관, AI, 새 뉴스 공급, 수행 이력 추정은 선행하지 않는다. 공통 ui/storage/platform 파일마다 단일 수정 담당을 지정한다.

실제 후보가 없는 상태에서 통합 검수 통과를 선언하지 않는다. 이 시연으로 확정하는 것은 화면의 조작·선택·복귀 계약이다. 실행자는 아래 시연과 같은 합성 장면을 실제 계정 후보에서 재현하고 결과물·실패 복구·다른 기기·기존 데이터 보존을 대조한다.

## 시연과 검수 근거

[단일 HTML](../prototypes/planning-practice-review.html)의 기존 계획 시연에 읽기·선택 메모·같은 대상 연결을 통합한다. 서버/Auth/IndexedDB 없이 탭 메모리만 사용한다. 명령: `python3 -m http.server 8768 --bind 127.0.0.1 --directory docs/prototypes`, 주소: `http://127.0.0.1:8768/planning-practice-review.html`.

원문은 고정 합성 판의 한 문장을 미리 선택한 장면이다. 임의 원문의 네이티브 구절 선택, 미저장 메모 문구의 직접 연결, 실제 메모 휴지통·계정 전송·파일 복원은 이 HTML의 검수 범위 밖이다. 메모 경유는 명시 저장한 메모 중 선택한 부분을 연결하는 장면을 제공한다. 제품 계약의 더 넓은 허용 범위를 이 시연의 제한으로 축소하지 않는다.

새 검수는 [독립 결과](evidence/handoff-integration/report.json)와 [재현 스크립트](evidence/handoff-integration/verify-prototype.cjs)에 기록한다. 저장소에서 `node docs/design-review/evidence/handoff-integration/verify-prototype.cjs`로 단일 HTML만 제공하는 임시 loopback 서버·독립 Chromium 검수를 실행한다. 설치된 Playwright와 Chromium이 필요하며 제품/Auth/DB helper는 import하지 않는다.

최종 HTML SHA `222296acc0da372bcfab495f44a9a6bba6cf8f29c40507aece1060a899d70f62`에서 독립 시나리오 17개를 통과했다. 메모·연결 중복 방지/입력 보존·같은 메모 복귀, 선택 대상의 기간 진입·선택 범위별 snapshot/재확인, 과거 체크 정정·불변 회고·초기화와 세 폭을 확인했다. 추가 네트워크 요청·저장소 접근·콘솔/실행 오류는 없었다. 비교 장면은 같은 문장·대상·원문 복귀에서 직접 연결 4조작, 메모 사본을 경유한 연결 9조작이었다. 후자는 명시 범위 선택과 선택 부분 가져오기를 사용해 문구 재입력은 없었고 메모 사본이 추가로 남는다. 이 숫자는 시연의 정해진 경로에만 해당하며 개인 판단 보관의 가치나 실제 제품 효율의 점수가 아니다.
