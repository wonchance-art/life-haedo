# 글을 쓰며 취향을 찾고 붙이기

2026-10-13. #76 이후 `codex/taste-writing-flow`의 후속. 병합·운영 SQL·배포는 Local 담당. 디자인 통합은 한 명이 담당했으며 별도 시안 엔진 실행을 주장하지 않는다.

## 목표와 결정

시작은 내 페이지의 작성 중인 글이다. 제목으로 책/공개 GitHub 프로젝트를 찾거나, 기존 컬렉션의 종류·주제와 메모를 살핀 뒤 제목·저자·출처를 첨부한다. 저장 후 같은 피드에서 읽고 제목·소개를 고쳐 방문자 미리보기로 확인한다.

이미 있는 작성/첨부/소개/표시/공개 후보 설정과 백업을 재사용한다. 별도 프로필 모델·레이아웃 저장 필드·새 컬렉션 선등록 단계를 추가하지 않는다. 본문 한 열/첨부 4px 두 열은 기존 기준 그대로다. `좁은 폭으로 보기`는 미리보기 본문을 최대 390px로 제한하는 임시 조작이다. 브라우저 viewport/OS/키보드/모바일 media query 전체를 모사하지 않는다.

이전 단절은 이름 입력이 저장한 컬렉션만 검색하고, 새 대상은 주소를 알아야 했던 점이다. 입력 중에는 여전히 로컬만 검색한다. 외부 검색은 제공자 이름과 전송 설명을 표시한 버튼을 직접 눌러 시작한다. Enter/한글 조합만으로 외부 요청을 보내지 않는다. 공급자 결과는 평문 후보이며 새 후보 선택 → 기존 정보 수정 폼 → 첨부 → 글 저장의 경계를 유지한다. 기본 비공개와 공개 후보/게시의 구분을 유지한다.

## 보존·실패 계약

- 원문/정확 버전/발췌/기존 컬렉션에 쓰지 않는다. 컬렉션 개인 메모·태그는 선택창에서만 읽고 첨부에 복사하지 않는다.
- 책은 Open Library **작품** 정보다. 번역·판본·책 표지·본문 확보를 추정하지 않는다. GitHub 소유자는 후보에만 소유자로 표시하며 저자 필드는 빈 값으로 시작한다.
- 고정 HTTPS endpoint, credentials omit, no-referrer, redirect error, no-store, 10초 제한과 64KiB 스트림 제한을 기존 URL 조회와 공유한다. 6개 후보만 받는다.
- 검색어와 응답 캐시는 dialog 메모리에만 둔다(최대 12개). 저장/백업/동기화/공개/앱 로그에 넣지 않는다. 간격 제한에는 시각만 사용한다.
- 입력/종류/주제 변경, 닫기, 계정/화면 종료 시 진행 요청을 취소하고 낡은 결과를 무시한다. 실패/빈 결과/제한에는 직접 입력 경로가 남는다. 같은 대화창 재검색은 캐시를 사용한다.
- Escape는 한글 조합 중을 제외하고 닫고 원래 버튼으로 돌아간다. 수동 첨부·취소도 숨겨진 입력에 초점을 남기지 않는다.
- 저장·충돌·백업은 기존 원자 저장과 CAS를 재사용한다. 새 SQL 없음. 운영 합성 검사/실계정 게시 없음.

새 SDK 대신 기존 모듈을 재사용한 이유와 라이선스·유지보수·제공자 정책은 [공식 출처 비교](../life-tools-design/open-source-review.md#이름으로-책프로젝트-찾기--2026-10-13)에 기록했다.

## 직접 체험

이 브랜치에서 `npm run dev`, 공용 인증이 설정된 로컬 앱의 `index.html?section=records&view=page`를 연다. 운영 사이트에 반영됐다는 뜻은 아니다.

1. 글쓰기에서 생각을 적고 `음악·책·대상 붙이기`를 누른다.
2. 책 이름 입력 → `책 찾기 · Open Library` → 후보의 저자/작품 정보 확인 → 수정 폼 → 첨부. 프로젝트는 GitHub 버튼 사용.
3. 다시 대상 붙이기에서 저장한 컬렉션을 종류·주제로 좁히고 `내 메모·주제`를 펼쳐 읽는다. 선택한 항목의 개인 메모는 글에 따라오지 않는다.
4. 비공개로 저장한 글을 피드에서 다시 확인한다. 페이지 설정에서 제목·소개를 수정한다.
5. 비공개 글은 방문자 미리보기에 나타나지 않는다. 시험 글을 명시적으로 `공개 후보`로 바꿔 저장하면 미리보기에 나온다. 실제 공개는 별도 게시 조작이다.
6. 좁은 폭을 켜고 긴 제목/본문을 읽은 뒤 편집으로 돌아온다. 공개 사본 관리로 들어갈 필요 없이 여기서 끝낼 수 있다.

- 1440/820/390px의 16개 상태: 재사용, 책 후보, 작성, 방문자 미리보기 각각 세 폭; 별도 좁은 본문 미리보기, 빈/오류/로딩. 가로 넘침·작은 조작·16px 미만 입력·접근 이름·대비 실패 없음. 스크린샷을 직접 검토해 주제 선택 스타일을 공통 입력과 맞췄다.
