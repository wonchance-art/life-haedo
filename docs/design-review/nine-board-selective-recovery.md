# 9칸 구성의 파일 범위와 선택 복구

2026-10-14. 사용자가 가능한 후속 작업을 찾아 계속 진행하라고 요청했다. 기존 [9칸 구성](nine-board.md)의 파일 경로를 검토한 결과, 현재 구성 화면에서 전체 JSON이 내려오는 범위가 충분히 명확하지 않고 여러 구성 중 일부만 복구할 수 없었다. 구성 하나를 옮기고 다시 편집하는 사용 흐름을 이번 단위로 완결한다. 이전 PR #87의 CI는 e3e2bf5에서 전체 통과했다.

## 목표·범위·보존·완료 조건

- **현재 구성 JSON 받기**는 선택한 구성 하나만 포함한다. **전체 구성 JSON 백업 받기**는 모든 구성을 포함한다. 버튼·설명·파일 이름을 구분한다. 현재 구성의 JSON/HTML로 다른 구성을 자동 출력하지 않는다. 다운로드 요청을 실제 파일 보관 완료로 표시하지 않는다.
- v1 파일을 선택하면 구성 제목·영역/항목 수·내용·정확한 출처·선택 이유를 읽고 복구할 것만 고른다. 기본 미선택, 모두 선택/선택 해제, 선택 개수와 실제 남은 구성 수를 표시한다. 미리보기·선택·취소만으로 저장하지 않는다.
- 중복은 로컬 ID와 객체 키 순서를 제외하고 제목·소개·영역 순서/이름/설명·항목 순서·4필드 snapshot·선택 이유를 정확히 비교한다. 보관본과 같은 내용, 파일 안의 반복 내용을 따로 표시한다. 제목 하나나 같은 URL만으로 다른 구성을 합치지 않으며 명시 선택하면 중복도 새 사본으로 복구한다.
- 선택한 구성만 새 board/area ID로 붙인다. 기존 구성·원문·글·초안·컬렉션은 유지한다. 기존 `life-nine-board-backup-v1` 파일과 저장 schema, CAS, 계정/작업공간 소유권, 2 MiB/20개/9×9 제한을 그대로 쓴다. 원격 SQL·공개 payload는 바꾸지 않는다.
- 실패 시 파일 내용과 선택을 유지하고 동일 화면에서 재시도한다. 다른 탭과 충돌하면 최신 저장본을 읽은 뒤 선택을 유지하며 다시 확인한다. 저장/복구 중에는 입력을 잠그고 진행 중 버튼의 중복 실행을 막는다. 최신 읽기 이후 새로 생긴 선택 화면의 설치 버튼도 잠금이 풀렸는지 다시 계산한다.
- 새 파일 선택과 화면/계정 변경은 이전 파일 읽기의 늦은 결과가 현재 선택을 바꾸지 않게 한다. 빈 파일은 빈 상태로 설명하고, 미선택·수량 초과에서는 복구 버튼을 비활성화한다. 실제 설치에서는 용량과 CAS를 다시 검증해 부분 복구를 거절한다.

## 선택 근거와 반대 검토

기본 모두 복구는 20개 제한과 이동 범위 확인을 어렵게 한다. 명시 선택을 기본으로 두고 전체 복구는 ‘모두 선택’으로 짧게 연결한다. 같은 내용의 자동 삭제/병합은 선택 이유나 순서가 다른 구성을 훼손할 수 있으므로 하지 않는다. 표시한 중복은 사용자의 별도 사본 선택을 막지 않는다. 파일 선택은 로컬 읽기이며 업로드/공개가 아니다.

새 모듈·라이브러리·파서를 도입하지 않는다. 기존 `NineBoard.backup/readBackup/copies`, `PagePosts` snapshot, native checkbox/details, idb 트랜잭션/CAS와 초안 선택 복구의 명시 선택 방식을 재사용한다. [기존 오픈소스 비교](../life-tools-design/open-source-review.md)의 공식 릴리스·라이선스·선택 근거를 유지한다.

완료 조건은 현재/전체 파일의 실제 범위, 구형 v1 왕복과 선택 복구, 실패/충돌/한도/빈 파일/늦은 파일의 입력 보존, 실제 화면의 이름·44px 조작·16px 입력·대비·넘침을 확인하는 것이다. 서버 공유·자동 동기화·만다라 고정 배치·이미지 생성은 이번 범위를 늘리지 않는다. 운영 병합/배포와 Apple 실기 체험은 Local 담당이다.
