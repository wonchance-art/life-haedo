2026-10-29 KST. [전체 설계](research-output-system.md)의 첫 공개 출처 비교다. **읽을 자료와 출처 운영안은 준비됐으며, 개인 계정 추천·실제 읽기 도움은 아직 관찰하지 않았다.** 코드 기준은 main `55a74ae`, 조사 시작 브랜치는 `c67f76c`다. [서지·확인 범위·채택 이유 카탈로그](evidence/research-source-pilot-20261029.json)는 설계 근거이며 앱 feed 형식이나 개인 평가 데이터가 아니다.

## 출처 조사 당시의 시범 결정

조사 당시에는 **Bluesky에서 소수 출처의 실제 글을 읽는 방식**을 시험할 후보로 둔다. 공식 사이트가 연결한 계정과 공개 게시물→글의 경로를 확인할 수 있었기 때문이다. X보다 추천이 좋다는 결론은 아니다. 계정 생성이나 일괄 팔로우 없이 아래 개별 자료부터 읽을 수 있다.

공급을 늘리기 전에 **출처 신원 → 게시물 → 읽을 수 있는 글 → 실제 근거**를 각각 확인해야 한다. OASIS는 정적 HTTP 조회가 404여도 공식 브라우저 화면에서 요약 PDF를 생성했다. RetrievalPractice의 최근 게시 두 건은 과거 글을 다시 소개했다. 상태 코드·인기·최근 게시·기관 이름만으로 연구의 최신성이나 읽기 가능성을 확정할 수 없다.

이번 편집 질문은 **“외국어 읽기를 기억에 남기고 꾸준히 이어가려면 학습 방법과 환경을 어떻게 비교할까?”**다. 기존 관심사를 연결한 작업 가설이며 새로 저장한 사용자 설정이 아니다. 한국어·영어·일본어·중국어·프랑스어 자료를 조사했지만 현재 사용자가 켠 언어 집합은 읽지 않았다.

**첫 운영안:** OASIS의 외국어 연구 요약과 RetrievalPractice의 실천 해설을 두 출처로 삼고, Learning Scientists는 필요한 설명을 찾는 보관 자료로 둔다. Bluesky를 사용할 때도 선택 출처/프로필을 기준으로 시작하고 Discover는 추가 탐색으로 둔다. 처음부터 8개 출처 전부를 팔로우하거나 여러 플랫폼을 동시에 운영할 이유는 없다.

Bluesky 선택은 공개 게시를 검증하기 쉬웠다는 **좁은 시범 제안**이다. 두 출처의 실제 게시에서 요약/해설까지 읽는 준비는 됐다. 지속적인 공급·다국어 범위·실제 읽기 도움은 더 관찰해야 하므로 최종 플랫폼 채택이나 추천 우위를 확정하지 않는다.

영상 선호가 분명하면 공식 기관의 YouTube 강의와 실제 자막/원문 연결을 먼저 확인한다. 이미 X를 쓰고 해당 출처의 읽을 글이 잘 도착한다면 기존 X 리스트를 유지할 수 있다. 이번 X의 403과 YouTube 추출 제약은 이 도구에서의 관측이며 서비스 전체의 장애나 열등함을 뜻하지 않는다. 게시 API나 새 추천 서버를 먼저 붙여 해결할 문제도 아니다.

Bluesky의 [공식 2026년 안내](https://bsky.social/about/blog/01-26-2026-whats-next-at-bluesky)와 [피드 설명](https://bsky.social/about/blog/7-27-2023-custom-feeds)은 팔로잉·Discover·사용자 선택 피드를 구분한다. [Starter Pack](https://bsky.social/about/blog/06-26-2024-starter-packs)은 출처 묶음이며 연구 품질 인증이 아니다. 이번에는 계정/리스트/피드를 생성하지 않았다. 공개 조회 범위는 [공식 author-feed 명세](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/feed/getAuthorFeed.json)를 따른다.

원문 언어는 영어 6개, 한국어·일본어·중국어·프랑스어 각 1개다. 고찰·해설·강의·사례가 섞여 있어 독립 연구 10개를 뜻하지 않는다. 철회·정정 이력을 전수 조사하지 않았고, 서로 다른 종합 연구에 포함된 원연구의 중복도 전수 대조하지 않았다. 사용자 원어 독해 수준이나 번역 품질을 검증한 것도 아니다.

## 추천 기준에 반영할 실제 발견

| 입력/관측 | 처리 계약 | 결과 |
| --- | --- | --- |
| 공식 사이트의 SNS 연결 | 소유 근거·확인일을 기록하고 게시 활동/내용 평가는 별도 확인 | 신원 확인과 품질 확인이 분리된 출처 |
| 새 게시가 오래된 글을 소개 | SNS 게시 시각·원자료 공개일·확인 시각을 각각 보관 | 오래된 연구를 신작으로 순위 올리지 않음 |
| 정적 조회 404와 브라우저 표시가 다름 | HTTP 응답·렌더 접근·요약/본문 확보를 각각 기록하고 동일 ID/서지를 대조 | 브라우저에서 읽는 후보는 유지할 수 있음. 자동 수집 성공·원논문 확보로 승격하거나 dislike/철회로 해석하지 않음 |
| 서지/초록은 읽히지만 전문은 미확보 | 확인한 범위만 설명하고 전문 검수 상태를 따로 둠 | 초록 후보로 읽기 가능. 전문 확보 표시 금지 |
| 같은 논문의 게시/해설/번역 | DOI 또는 확인된 동일 원문으로 연결. 유사 제목만으로 병합하지 않음 | 보완 설명은 남기되 독립 근거·새 추천으로 중복 계산하지 않음 |
| 특정 원문 언어 후보가 없음 | 공급 부족을 드러내고 해당 언어의 실제 출처를 검토 | 언어 설정을 몰래 넓히거나 번역문을 새 원문 공급으로 세지 않음 |

현재 비교에는 임의의 신뢰도 점수·효용 확률을 붙이지 않았다. 이후 자동화에서는 이 관측 필드를 수집 결과와 함께 검증해야 하며, 이번 JSON을 기존 엄격한 feed 형식에 그대로 넣지 않는다. **원문 도달·날짜·언어·중복의 공급 문제를 먼저 고친 뒤**, 적합한 자료가 있는데 순위에서 반복 누락될 때 기존 규칙과 새 재정렬을 같은 후보로 비교한다.

## 해도와 연결할 때 이미 있는 것과 남은 것

공개 배포 [후보 목록](https://wonchance-art.github.io/life-haedo/assets/life/discovery-feed.json)을 HTTP200으로 확인했다. 표본 생성 시각은 **2026-10-29 13:48:17 KST**, 9출처·120후보이며 한국어 50·영어 70개다. 일본어·중국어·프랑스어 옵션은 이미 있지만 이 표본에는 해당 언어의 공급이 없다. LLT·Frontiers는 이미 포함된다. 3출처는 error/stale, 6출처는 정상으로 표시돼 전체 수집 성공으로 합산하지 않는다. 이 표본은 저장소의 10/19 fallback 7출처·90후보와 다르다.

| 사용자 흐름 | 현재 기능 | 다음 구현에서 확인할 경계 |
| --- | --- | --- |
| 원문 언어 여러 개·번역 대상 선택 | [언어 설정](../../assets/life/discovery-language-settings.js), 필터 후 순위 | 언어 선택이 실제 공급이나 SNS 설정 변경을 뜻하지 않음 |

최신 기본 소비는 **해도 내부 글 열기 → 확보한 본문/초록과 그림 읽기 → 종료**로 완결된다. 원문·SNS 링크는 출처 확인 또는 본문 미확보 때의 선택 경로다. 필요한 경우에만 기존 자료 가져오기와 계정 보관으로 연결한다. 개인 뉴스 메타의 서버 연동이나 SNS adapter를 먼저 완성해야 읽을 수 있는 구조로 바꾸지 않는다. 이번 출처 조사는 공개 feed의 허용 출처·갱신 주기·현재 사용자 옵션을 바꾸지 않았다.

## 다음 비교와 검수

처음에는 제목·선정 이유에서 원하는 글 하나를 열면 충분하다. 읽기 평가를 요청하더라도 읽은 범위와 그 질문에 대한 도움만 구분한다. 무응답·미읽음·나중에 읽기는 미평가이며 좋아요·싫어요·완독·학습 신호를 생성하지 않는다. 직접 응답을 공개 카탈로그에 넣지 않는다.

실제 소비에서 부족함이 보이면 같은 질문·비슷한 읽기 여건으로 기존 방식과 선택 출처를 작은 교차 관찰한다. 후보·날짜가 달라지는 비교는 개인 사용 관찰이며 SNS 알고리즘의 인과 효과가 아니다. 독립 재정렬을 평가하려면 같은 후보·확인 시점·언어/출처/제외·과거 반응·정책·K를 고정하고 미래 반응을 쓰지 않는다. 실제 도움·절약 시간은 아직 미측정이다.

이번 검수는 주제별 근거 조사, SNS 신원/게시/도착 경로 조사, 현재 코드/배포 표본 대조, 독립 출처·문서 검토로 나눴다. 위험한 일반화는 다독의 언어/표본 편중, Grit의 상관과 개입 차이, 중국어 메타분석의 이상치 처리, 일본어 단일 사례, 최근 게시와 오래된 원자료의 혼동을 중심으로 확인했다. 앱 코드·DB·계정 설정을 바꾸지 않아 전체 앱 회귀 테스트나 로그인·업로드를 실행하지 않았다.

### 다음 큰 작업 묶음

1. **실제 소비의 출처 구성 보완과 작은 사용 관찰.** 목적은 원하는 자료가 충분히 오는지 확인하는 것. 선행은 읽을 언어/형식과 실제 사용하는 SNS 경로이며, 그 전에도 공개 링크로 읽기는 가능하다. 완료 기준은 정확한 출처→읽을 자료의 연결, 반복/무관/접근 실패의 정리, 사용자가 제공한 경우에만 실독 도움을 반영한 유지/수정 판단이다. 새 출처 수나 팔로우 수를 완료 기준으로 삼지 않는다.
2. **뉴스 설정·반응과 선택 자료 활용의 계정 통합.** 목적은 기기마다 관심·언어·반응을 다시 맞추는 부담 제거. 선행은 PR140 실행 담당의 기존 도메인 계약·최신 구현 확인. 완료 기준은 설정/반응의 서버 보관→선택 링크·정확 원문→출발 맥락 복귀, 충돌/삭제/구기기/오프라인/A·B 계정 검수를 같은 후보에서 완주하는 것. 이번 SNS 시범과 독립 진행한다.

AI 제작·외부 발행은 가치 있는 근거와 채택한 관점이 생긴 뒤의 기존 확장 순서를 유지한다. 이번 결과만으로 실제 게시나 모델 학습을 가동하지 않는다.
