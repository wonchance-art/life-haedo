## 확정 범위

1. **글 선택과 독립 사본.** 현재 계정·작업공간의 저장된 사진/리치 글을 골라 모음에 복사한다. 사진 없는 저장 글도 같은 형식이면 포함한다. 초안·원문 자료·책·컬렉션 전체를 자동으로 끌어오지 않는다. 선택 시 본문·사진·설명·대체 텍스트의 사본을 보관하며 이후 원글 수정/삭제가 모음의 내용을 바꾸지 않는다.
2. **목차 편집.** 모음 제목·소개와 선택 글의 순서를 비공개로 자동 보관한다. 이동/제거는 모음 안의 사본에만 적용하고 원글을 수정·삭제하지 않는다. 저장 실패·다른 탭 경합·계정 변경은 입력과 마지막 성공 상태를 구분한다.
3. **읽기.** 목차에서 정확한 항목을 열고 이전·다음으로 이동한다. 첫/마지막 항목·사진 없는 글·빈 모음·없는 모음을 명확히 처리한다. 목차 복귀는 선택 항목과 초점을 유지하며, 원본 사진을 줄인 파일로 대체하지 않는다.
4. **파일 재사용.** 기존 엄격한 패키지·PhotoPost 검증·사진 수화/해시 검증을 재사용한다. `series.json`과 글별 기존 사진 ZIP을 담는 해도 전용 무압축 ZIP이며 일반 ZIP의 재압축·추가 파일은 허용하지 않는다. 한 모음 최대 20편, 파일 전체 256MiB 제한으로 전체를 메모리에서 검증하므로 모바일의 최대 용량 성공을 보장하지 않는다. 파일은 선택 모음의 목차·본문·사진으로 자기완결하며 원래 브라우저의 글 ID나 Blob URL에 의존하지 않는다. 복원은 현재 작업공간에 새 모음·항목·글·사진 ID의 사본을 원자 설치한다. 일반 저장 글 목록에 글을 추가하지 않고 기존 모음/원글을 덮어쓰거나 서버 연결·공개를 시작하지 않는다.
5. **방문자 공유.** 기존 `ShareRemote`와 공개 페이지의 순서 있는 목차 사본을 사용한다. 이미 명시 공개된 글의 token 주소를 사용자가 골라 연결하고, 공개 미리보기에서 모음 제목/소개·항목·순서를 확인해 게시한다. 새 SQL·별도 연재 서버·원글 자동 게시·일괄 사진 공개는 추가하지 않는다.

## 비공개·공개·파일의 경계

- **로컬 모음:** 글을 고른 시점의 비공개 사본이다. 수정된 원글의 최신 내용을 자동으로 따라가지 않는다. 다시 선택하거나 새 모음으로 담는 조작은 별도 사용자 결정이다. 원글의 기존 인용 sidecar·원문 정확 버전·공개/서버 연결은 건드리지 않는다.
- **공유 목차:** 원래 비공개 사본의 본문·사진·식별자나 선택하지 않은 글을 보내지 않는다. 공개 저장본은 모음 제목·소개와 순서별 ‘1편’ 형태의 표제·공개 token 주소만 담는다. 익명 `series.html`은 현재 공개 상태를 다시 확인해 접근 가능한 글의 현재 제목·본문을 표시한다. 모음 제목/소개도 별도로 확인하는 공개 내용이다. 비공개 글을 골랐다는 사실을 자동으로 공개하지 않는다.
- **독립된 철회:** 모음 목차 철회는 개별 공개 글을 철회하지 않는다. 개별 글을 철회하면 새 조회에서 그 글/사진과 제목을 읽지 못하고 해당 순서의 공개 종료 안내를 표시한다. 별도로 게시한 모음 자체 제목·소개·token 연결을 없애려면 목차도 갱신하거나 철회해야 한다. 목차 사본을 개별 글 철회의 연쇄 권한으로 사용하지 않는다. 이미 받은 파일·화면 복사를 회수한다고 보장하지 않는다.
- **내보낸 파일:** 사본의 본문과 사진을 실제로 담는 비공개 파일이다. 원본 사진의 메타데이터도 포함될 수 있으므로 포함 범위를 생성 전에 알린다. 본문에 직접 넣은 인용·출처 URL은 남으며 구조화 인용 sidecar와 그 정확 원문 전체 본문은 포함하지 않는다. 서버 세션·계정 식별·영속 게시 요청·활성 공개 상태를 사본 복원에 승계하지 않는다. 기존 전체 자료/근거 파일을 모든 자료형의 통합 백업으로 바꾸지 않는다.
- **범위:** 책 확장·자동 정렬/추천·자동 수집·지도·댓글·구독·새 CMS·sidecar 자동 서버 동기화는 이번 모음을 만드는 선행 조건이 아니다.

- 파일 설치의 실제 사진 수화를 지연한 동안 홈 이동을 거절하고 원래 작업공간·파일 후보를 유지했다. 처리 완료 뒤 한 번만 사본을 설치하고 홈으로 이동했다.

편집·목차·사진 읽기의 1440/820/390px 총 9개 화면을 측정했고 가로 넘침·명명 없는 조작·44px 미만 유효 조작·입력 글꼴·텍스트 대비 위반이 없었다. 모바일 편집과 사진 읽기, 데스크톱 목차 PNG를 직접 읽어 긴 제목/출처와 사진·조작의 구분을 검토했다. 실제 사진 확대는 4032px 표시폭과 프레임 가로 스크롤까지 확인했다. 콘솔·페이지 오류·외부 요청·원격 자료 쓰기는 모두 0이었다. Linux Chromium151.0.7922.173의 화면 모사이며 Apple 실기 체험으로 보고하지 않는다.

독립 reader 검수 `tests/blog-series-reader-browser.cjs`는 6개 흐름을 통과했다(`.local/blog-series-reader/report.json`). 전체 소개문·사진 렌더 지연, 원래 목차 항목의 초점/스크롤 복귀, 원글을 다시 읽지 않는 정확 사본, 손상·읽기/렌더 실패 재시도, 늦은 계정/렌더 결과의 무효화와 Blob URL 해제를 확인했다. 이는 실제 계정별 IndexedDB·다운로드 파일을 다루는 owner UI 검수와 구분한다.

별도 공개 검수 `tests/blog-series-public-browser.cjs`는 4개 흐름과 3폭 9개 화면을 통과했다(`.local/blog-series-public/report.json`, `browser-cas-final.log`). 실제 UI·SDK·계정별 IndexedDB와 격리 PostgreSQL의 기존 page/blog RPC를 연결해 기본 선택 0개, 명시한 공개 token 순서, 응답 유실 영수증 재시도, 현재 공개 본문·원본 사진 접근, 변경 없는 재조회 때 DOM/선택/스크롤 유지, 자식/목차의 독립 철회·타 token 거절·비공개 원본 불변을 확인했다. 콘솔·페이지 오류·외부 요청은 0이었다. 별도 SQL 검수 4개 흐름도 통과했다(`.local/blog-series-backend/report.json`, `sql-final.log`). Auth/Storage/Edge HTTP는 합성이며 운영 서버 검수를 뜻하지 않는다.

검수 중 실제로 고친 사용 흐름은 다음과 같다.

- **원본 사진 확대:** 기존 모음 이미지 CSS의 우선순위가 원본 확대의 `max-width:none`을 덮어 decoded1280px 사진도 640px로 표시했다. 모음 안 원본 확대 예외를 추가한 뒤 실제 표시폭1280px와 프레임 가로 스크롤을 확인했다. owner UI에서도 별도 4032px 원본의 실제 표시폭·스크롤을 검사한다. 클래스만 붙었는지를 성공 기준으로 삼지 않는다.
- **파일 설치 중 이동:** 모음이 소유한 파일 설치/복구 동작 중 외부 `flush()`가 통과할 수 있었다. 내부 저장과 외부 이동용 flush를 분리해 처리 중에는 이동을 거절한다. 기존 동작 중 이동이 통과하는 단위 반례를 보존하고, 실제 사진 수화를 지연한 UI에서 홈 이동 거절→같은 작업공간 설치 완료→이후 이동을 검사한다.
- **공개 경합 후 재검토:** 공개 CAS 충돌 이후 이미 검토한 동의를 그대로 재사용해 다른 탭의 새 공개본을 덮어쓰지 않도록, 충돌 시 그 동의를 소모하고 상태 재조회·새 미리보기·명시 재동의를 요구한다. 실제 SQL을 연결한 대화상자에서 두 번째 클릭만으로는 덮어쓰지 못하고 새 검토 후에만 게시되는 영구 회귀를 확인했다.

초기 UI 테스트의 목차 복귀 기대값(직접 누른 항목과 이전/다음으로 이동한 항목의 혼동), 본문에서 목차 전용 편집 버튼을 찾은 동선, 합성 계정 전환 뒤 서버 검증 호출 누락은 테스트 준비 오류였다. 원래 사용자 동선·계정 검증 절차로 정정했으며 런타임 결함 수에 포함하지 않는다.

합성 Auth·격리 SQL·화면 크기 모사는 실제 Google 인증·managed Storage/Edge·Mac/iPad/iPhone IME/Files·사용자 개인 게시 성공을 뜻하지 않는다. 로컬 Chromium151 검수와 CI의 고정 Chromium153도 구분한다. 기반 PR100의 완료 검사와 이번 후보의 결과를 합치지 않는다.

### 직접 체험

로그인한 자료실의 선택 자료 페이지에서 **연재·모음**을 연다. 저장한 글 세 편을 골라 제목·소개·순서를 정하고 **모음 읽기**에서 목차와 이전/다음으로 읽는다. 파일·공유에서 ZIP을 내려받아 파일을 선택하고 포함 내용을 확인한 뒤 **새 모음으로 불러오기**를 누르면 현재 작업공간에 독립 사본이 생긴다. 방문자 공개는 별도 대화상자에서 이미 공개한 글을 명시 선택하고 게시한다. 파일 사본 보관과 공개 목차 게시를 같은 동작으로 설명하지 않는다.

## 이후 작업 판단

다음 제품 후보는 기존 비공개 9칸의 선택 영역을 방문자가 직접 둘러보는 취향 페이지, 고른 자료와 내 생각을 오가며 글 한 편으로 마치는 작성 흐름이다. 기존 PNG/JSON/HTML·9칸 초안·정확 인용·일반 작성기를 새로 만드는 계획이 아니다. 이유·선행 조건·완료 기준은 [최신 로드맵](../life-tools-design/roadmap.md#모음-이후의-큰-제품-후보)에 기록했다. 다른 세션의 완료 변경 통합과 실제 기기/관리형 환경 검수는 출시 조건으로 구분한다. 원글 새 버전으로 선택 갱신·새 구성 형식은 실제 필요가 확인될 때 별도 범위로 판단하며, 이번 설계만으로 자동 실행하지 않는다.
