# 같은 브라우저에서 이어 읽기

2026-10-07. 운영 설치·병합·배포 마무리는 사용자의 최신 지시에 따라 Local이 담당한다. Cloud는 PR #37 이후 제품 단위인 **긴 원문 읽기 → 앱 다시 열기 → 읽던 구간으로 복귀**를 구현한다. 신규 SQL·서버 기능·런타임 라이브러리는 없다.

## 사용자 흐름과 범위

원문을 스크롤하거나 구절을 선택하면 현재 계정·작업공간의 마지막 위치 한 개를 이 브라우저에 보관한다. 앱을 다시 열어 홈 또는 기록의 **이어 읽기**를 누르면 정확한 원문 버전과 문자 위치를 연다. 뒤로가기는 눌렀던 행의 초점·목록 위치로 돌아온다. 검색 결과와 저장한 문장의 목적지는 이 위치보다 우선한다.

읽기 화면에 진도바·패널을 추가하지 않는다. 홈·기록은 제목, `이 브라우저`, 필요한 `이전 버전` 표식과 작은 조작 한 행을 공유한다. 390px에서는 제목 아래에 두 조작을 함께 놓고 44px 터치 영역을 유지한다. 지우기 대상은 읽기 위치이며 원문은 그대로다. 다른 기기 이어 읽기·읽음 완료·분석 이력을 뜻하지 않는다.

## 저장·복구 계약

- 기존 IndexedDB `meta`에 `readingPosition:<accountKey>:<workspaceId>` 한 행만 둔다. source ID·정확한 version ID·UTF-16 offset·저장 시각과 독립 revision을 보관한다. 원문 문자열·검색어·위치 이력은 복제하지 않는다.
- 원문 bundle, 원문 revision, 백업 형식, 동기화 outbox와 공개 사본을 바꾸지 않는다. `bundle.resumeHints`도 재사용하지 않는다. 새 사본으로 복원한 자료에는 이전 브라우저 위치를 옮기지 않는다.
- 실제 wheel/touch/키보드 입력 후 발생한 스크롤과 실제 선택을 저장한다. 초기 열기·검색 이동·복원·resize·출처/발췌/담기 패널 스크롤은 위치를 바꾸지 않는다. 문자 위치는 변경하지 않은 원문의 Range 기하에서 찾으며 CRLF와 surrogate pair 경계를 보존한다.
- 400ms 묶음 저장과 독립 revision 비교를 사용한다. 지울 때도 revision을 남겨 늦은 탭이 이전 위치를 되살리지 못하게 한다. 충돌한 후보는 새 revision으로 자동 재전송하지 않는다. 저장 중 새 실제 입력은 자신의 저장 완료일 때만 다음 후보로 이어진다.
- 다른 탭에서 표시된 위치가 바뀌면 첫 클릭은 새 위치를 보여주고 재확인을 요구한다. 예전 원문이 사라졌거나 링크만 있으면 최신 버전으로 추측 이동하지 않는다. 계정·작업공간 변경 이후 늦은 응답이 현재 화면을 바꾸지 않는다.
- 로컬 위치 저장 실패는 짧은 상태 문구로 알리고 원문·발췌·이동을 계속 허용한다. 다음 실제 입력으로 저장이 성공하면 오류 표시를 지운다. 원문 저장 실패와 혼동하지 않는다.

앱 전환·종료 때 이미 잡힌 후보의 저장을 시도하지만 OS 강제 종료 이전의 마지막 픽셀까지 보장하지 않는다. 브라우저 데이터 삭제·용량 정책으로 로컬 위치가 사라질 수 있다. 읽기 중 초기 metadata 조회 자체가 실패하면 재진입으로 다시 확인할 수 있다.

## 설계 근거와 담당

[공식 구현 비교](reading-resume-references.md)에 Zotero·Kavita·epub.js의 확인일·고정 소스·라이선스·공개 권고와 선택 이유를 남겼다. 원문/주석과 화면 상태 분리, 복원 스크롤 저장 억제, 픽셀 대신 문서 위치를 참고했다. 현재 평문 리더에 EPUB/PDF 렌더러를 도입하지 않았다.

root가 설계·공통 시각·통합을 책임진다. GPT-6.1 Sol/high 에이전트는 읽기 UI, 로컬 저장, 공통 CSS, 독립 브라우저 QA를 각각 맡았고 GPT-6 Astra/high는 공식 사례/사용성과 저장·비동기 보존을 독립 검토했다. 구현 파일 담당을 분리하고 최종 이미지는 같은 캡처로 검토한다.

## 체험

개발 환경에서 `npm run dev`로 실행하고, 로그인한 자신의 작업공간에서 긴 원문 중간을 읽는다. 새로고침 후 홈의 이어 읽기를 누르면 같은 버전·구간이 보여야 한다. 기록으로 돌아와 위치를 지운 뒤 다시 열어도 행이 없어야 한다. 새 실제 읽기 입력은 새로운 위치를 만들 수 있다.

## 검증

- 정적 HTML 17 / JavaScript 51 / 참조 252 / PWA 검사와 Node 306/306 통과. 새 controller 6사례는 제어된 이벤트·저장 응답의 순서 검사이며 실제 사용자 입력의 증거는 아래 브라우저 검사다.
- 실제 IndexedDB 저장 13/13: 계정·공간 격리, 두 탭 CAS, 삭제 후 늦은 저장 차단, 이전 버전·surrogate 경계, 쓰기 중단 rollback, 빈 삭제 revision, 백업·outbox 불변을 확인했다. [저장 보고](evidence/reading-resume/storage-report.json).
- 실제 브라우저 사용자 흐름 11/11: 세 폭의 실제 wheel→새로고침→명시 복귀, Shift+키보드 선택의 정확 UTF-16, 390px 재배치, 검색 우선, 패널 제외, 다른 탭 삭제, 계정/공간 전환, 바뀐 행 재확인, 원문 미확보·metadata 조회/저장 실패 복구를 확인했다. console/pageerror/외부 요청 0. [흐름·표면 보고](evidence/reading-resume/browser-report.json).
- 별도 [터치 검사](evidence/reading-resume/touch-report.json) 1/1: Chromium CDP의 trusted touch 스크롤과 이어 읽기 tap으로 같은 이전 버전·위치를 확인했다. 전체 실행 11사례 이후 추가한 별도 검사이며, CI에는 합계 12경로를 등록했다.
- Chrome 계열 Chromium 151.0.7922.173의 1440·820·390px에서 11캡처를 만들었다. 표면 검사에서 가로 넘침·44px 미만 조작·16px 미만 입력·대비 실패는 없었다. 계산한 최소 텍스트 대비 5.66:1. root와 공통 화면 담당이 실제 이미지를 별도로 검토했다. 숫자를 미적 품질이나 실사용 평가로 대신하지 않는다.
- 공개 산출물의 모의 인증·계정 경계·원문/발췌/백업·오프라인·기존 v71→v72 업데이트 9/9 통과. 기존 캐시와 로컬 자료를 지우지 않고 새 읽기 모듈·홈/UI/storage의 실제 캐시 해시를 확인했다. 의도한 callback/전송 오류 2건은 예상 외 오류와 구분했다. [PWA 보고](evidence/reading-resume/pwa-report.txt).

검증 중 ‘한 번의 위치 저장 실패 후 이후 입력도 무시됨’을 재현해 실패 후 metadata 재조회로 수정했고, 다음 실제 입력 저장·오류 해제를 재검증했다. 다른 탭 삭제와 자신의 저장 완료를 구분하지 않아 새 읽기 입력이 사라지는 경합도 독립 제어 검사로 수정했다.

운영 DB·Google 실로그인·실제 Mac/iPad/iPhone 체험·공개 배포는 이번 격리 브라우저 검사에 포함하지 않는다. 브라우저 폭과 touch 모사를 실제 Apple 기기 결과로 보고하지 않는다.
