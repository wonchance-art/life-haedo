# 뉴스 화면 개편 시안 — 레퍼런스와 결정

2026-11-02. [전문가 기준](expert-design-brief.md)의 순서로 만든 개편 시안(부드러운 판)의 뉴스 화면 근거다. 시안 단계이며 앱 코드는 바꾸지 않았다. 기능 계약은 [뉴스 공급·추천 근거·직접 읽기 비교](discovery-quality.md)와 [기능별 작업 계약](../agents/feature-contracts.md)의 뉴스 항목을 그대로 따른다.

## 사용 장면

출근길 iPhone에서 관심 주제의 새 글 목록을 훑는다. 읽을 글은 담고, 관심 없는 글은 치운다. 저녁에 Mac에서 담은 글의 원문을 열어 읽고, 남길 글은 자료실에 보관한다.

화면 모드는 고르기·정리(Operate)가 주다. 읽기는 원문 사이트에서 한다. 공급 데이터는 제목·출처·날짜·언어·태그뿐이다. 요약·본문·이미지는 없다(`coverage: link_only`, `rights.mode: metadata_only`).

## 가져온 패턴

- **행:** 제목은 최대 2줄, 메타는 1줄(출처, 영어 글만 EN 표시, 관심 주제). 썸네일 칸은 없다. 왼쪽 고정 열(76px)에는 관심 주제를 두고, 출처·날짜·시간은 메타 줄에 둔다(2026-11-02 사용자 결정).
- **데스크톱 2열:** 왼쪽은 목록(520px), 오른쪽은 선택한 글이다. 본문 자리는 두지 않는다. 오른쪽 패널의 구성은 다음과 같다.
  - 메타와 출처 태그
  - "제목과 링크만 제공" 안내
  - 원문 열기, 한국어로 열기
  - 라벨이 붙은 동작: 담기·좋아요·읽음·관련 없음·자료실에 보관
  - 왜 이 글인가
- **휴대폰:** 제목을 누르면 원문이 열린다. 행에는 담기 버튼과 ⋯를 둔다. ⋯는 같은 동작을 아래 시트로 연다.
- **의도 분리:**
  - 좋아요는 관심 신호다.
  - 담기는 나중에 읽을 목록이다.
  - 관련 없음은 목록에서 바로 빠지고 "되돌리기" 알림을 띄운 뒤 숨긴 글 탭에 남는다.
  - 자료실에 보관은 별도의 명시 동작이다.
- **키보드:** J/K 이동, O 원문, S 담기, M 읽음, X 관련 없음, Z 되돌리기. 각 버튼의 툴팁에도 같은 키를 표시한다.
- **새 글 알림:** 새로 들어온 글은 목록 맨 위의 "새 글 n건" 버튼 하나로 알리고, 읽던 위치는 유지한다.
- **출처 실패:** 갱신 시각 옆에 실패 수를 표시한다. 누르면 출처·갱신 설정이 열리고, 거기서 이유와 다시 시도를 보여 준다.

## 피한 패턴

- 썸네일, Magazine/Cards 보기, 발췌·요약 표시. 원문 이미지와 본문을 복제하게 된다.
- 스크롤하면 자동으로 읽음 처리하는 방식. 읽음은 명시 동작으로만 한다.
- 효과가 보이지 않는 "덜 보기" 피드백. 관련 없음은 즉시 사라지고 숨긴 글 탭에서 되살릴 수 있다.
- 전역 메뉴의 안 읽은 글 수 배지, 인기·공유 수.
- 끝없는 추천 스트림, 제스처로만 할 수 있는 동작. 모든 동작은 보이는 버튼과 접근 가능한 이름으로도 할 수 있어야 한다.

## 독립 검수 뒤 바꾼 것 (2026-11-02)

독립 검수 결과(블로커 1, 메이저 6, 마이너 5)로 시안을 다음처럼 고쳤다.

- **iPad 820px 보드 추가.** 목록은 한 칸으로 두고, 글은 오른쪽 시트로 연다. 모든 폭에서 행을 누르면 글이 열린다(넓은 화면은 오른쪽 칸, 좁은 화면은 시트). 원문으로 이동하는 길은 `원문 열기` 하나다.
- **동작 모양 분리.**
  - 담기·좋아요는 아이콘 토글(켜짐 = 채운 도형, `aria-pressed`)이다.
  - 나머지는 ⋯ 메뉴에 둔다: 읽음 · 자료에 보관 · 기사 정보 / 관련 없음 · 완전히 지우기.
  - 보관한 글에는 버튼 대신 `자료에 있음 ›` 링크를 보인다.
  - 지금 앱처럼 읽음은 목록에서 빠진다. 시안에 흐리게 남겨 두었던 것은 되돌렸다.
- **번역:** 원문 주소가 외부 서비스로 간다는 것을 버튼 이름 `Google 번역`으로 밝힌다. 한국어 글에는 이 버튼을 두지 않는다.
- **상시 설명 제거.**
  - "제목과 링크만 제공" 줄은 `기사 정보`로 옮겼다.
  - 단축키 줄은 버튼 툴팁과 `?` 도움말로만 둔다.
  - `왜 이 글인가`는 한 줄로 접어 둔다. 펼치면 `관심 주제 편집`과 `이 태그로 추천하지 않기`가 나온다.
- **휴대폰 틀 축소.**
  - 갱신 상태는 실패했을 때만 `출처 1곳 갱신 실패` 버튼으로 보인다.
  - 정렬·주제·언어는 필터 아이콘 하나에 모으고, 적용한 개수를 붙인다.
  - 행에서 ⋯를 없애고 담기 하나만 남긴다. 탭은 가로로 스크롤한다.
  - 시트에는 닫기 버튼을 둔다. 동작 없는 손잡이는 없앴다.
  - 뉴스 화면에서는 글쓰기 버튼을 뺐다.
- **일관성.**
  - 주제 칩은 자료와 같은 회색 배지다.
  - 목록 폭은 자료와 같은 440px, 날짜 칸은 76px로 맞췄다.
  - 되돌리기 알림의 폭은 목록 칸에 맞췄다.
  - 선택한 행에 2px 외곽선을 둔다.
  - 아이콘은 `assets/life/icons.js`의 모양을 쓴다.
- **자료 시안 연동:** 뉴스에서 보관한 기사는 자료 목록에 `뉴스`·`링크만` 배지로 보인다. 발췌는 붙이지 않는다.

## 원문을 앱 안에서 보기 (2026-11-02 사용자 결정)

목록에서 글을 고르면 원문을 앱 안 읽기 칸에서 바로 보여 준다. 링크를 새 탭으로 여는 방식은 대체 경로로만 남긴다. 현재 공급 계약(`rights.mode`·`coverage`)을 그대로 따른다.

| 출처 권리 | 앱 안에서 보이는 것 | 저장 |
| --- | --- | --- |
| `metadata_only` (현재 출처 전부) | 출판사 페이지를 읽기 칸에 그대로 띄운다. 내용은 출판사 서버에서 직접 받는다. | 제목·링크 메타데이터만 저장한다. 본문을 복사하거나 보관하지 않는다. |
| `summary_allowed` | 공개 요약을 위에 두고, 그 아래에 원문 페이지를 띄운다. | 요약만 저장한다. |
| `full_text_allowed` | 허용된 본문을 해도 읽기 화면(본문 17px, 줄 길이 제한)으로 보여 준다. | 허용된 본문을 기존 계약대로 저장한다. |

- **출처별 허용 여부:** 출처의 권리를 확인할 때 "앱 안에서 보기" 허용 여부도 함께 기록한다. 판단 근거는 이용 약관, `X-Frame-Options`·`frame-ancestors` 응답이다. 허용되지 않았거나 페이지를 띄우지 못하면 "앱 안에서 열 수 없음" 안내와 새 탭 열기로 대체한다. 실패를 숨기지 않는다.
- **전송 고지:** 앱 안 보기도 새 탭과 마찬가지로 출판사 서버에 직접 접속한다. `Google 번역`은 원문 주소를 Google로 보낸다는 것을 버튼 설명에 밝힌다.
- **화면:**
  - 데스크톱: 목록 오른쪽의 읽기 칸이다. 칸 위에 메타 줄과 제목, 동작(한국어·담기·좋아요·더보기·새 탭)을 둔다.
  - iPad 820: 읽기 화면이 내용 영역을 채운다. 왼쪽 위 `‹ 뉴스`로 목록에 돌아간다.
  - iPhone: 전체 화면 읽기로 바뀌고 하단 탭을 숨긴다. 아래에 담기·좋아요·번역·새 탭 도구 막대를 둔다(Safari와 같은 위치).
- **미검증:** 실제 출처마다 앱 안에서 띄울 수 있는지는 아직 확인하지 않았다. 시안의 회색 줄은 원문 페이지가 들어갈 자리를 나타낸다. 실제 기사 내용이 아니다.

## 미결·검증할 것

- 빈 탭(담은 글 0개)과 갱신 중 상태는 시안에 아직 없다.
- 시안의 기사는 실제 공개 공급의 10.19 스냅샷이다. 다른 시안의 "오늘"(11.2)과 날짜가 맞지 않는다.

- 접은 "왜 이 글인가"를 모든 글에 보일지, 관심순 정렬이나 개인 추천을 켰을 때만 보일지는 정하지 않았다.
- 휴대폰 스와이프(읽음·담기)는 시안에 넣지 않았다. 넣는다면 실제 기기에서 확인해야 한다.
- 실제 Mac·iPad·iPhone 확인과 소유자의 직접 읽기 평가는 하지 않았다.
