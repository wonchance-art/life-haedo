# 저장한 책으로 돌아와 장을 고치기

2026-10-08. PR #51의 독자용 책자 위에 연결한 비공개 진입 개선이다. 병합·배포·운영 SQL은 Local 담당이며 공개 사이트 반영을 뜻하지 않는다.

## 확인한 장애물과 선택

격리된 브라우저에 [익명 네 장 백업](evidence/book-edition/reader-book-backup.json)을 실제 복원하고 처음 화면부터 탐색했다. 복원 안내는 자료·묶음·페이지 수만 표시했고, 복원 후 빈 내 페이지와 홈 어디에도 책이 없었다. 도구의 ‘책 만들기’로 들어가야 저장한 책을 발견했다. 둘째 장을 수정한 후 새로고침하면 책 목록으로 돌아왔고 책을 열면 첫 장부터 시작했다. 원고 자체는 보존됐다.

홈의 기존 읽기 전용 구성 조회와 책 화면을 재사용한다. 새 대시보드·저장 형식·추적 메타데이터·의존성을 추가하지 않는다. 날짜가 없는 자료에 ‘최근 편집’이나 완료율을 추정해 붙이지 않는다. 영속 자동 재개 대신 책 제목과 명시적인 목차 선택으로 원하는 장에 들어간다. 여러 날 사용을 대신한 검증은 브라우저 새로고침과 백업 복원이며, 실제 며칠간의 사용성 평가는 아니다.

- 홈 **내 책**: 활성 책 최대 세 권과 활성 장 수, 접힌 목차. 제목으로 책을 열거나 목차에서 장을 직접 연다. 전체 보기에서 나머지 책과 보관한 책 복구를 찾는다.
- 책 목록: 각 책의 목차에서 원하는 장을 직접 선택한다. 저장 실패·한글 조합 중에는 기존 이동 보호가 적용된다.
- 복원 전 확인: 책·활성 장·보관 책과 장·개정본 수를 실제 백업 값으로 표시한다. 개정본 내부의 장은 현재 장 수에 중복 계산하지 않는다. 책 없는 기존 백업도 수용한다.
- 홈 진입은 현재 작업공간·책·장의 부모 관계와 보관 상태를 확인한다. 없는 대상을 다른 장으로 바꾸지 않고 목록으로 돌아가 안내한다. URL·백업·동기화에 새 탐색 필드를 넣지 않는다.

디자인 책임자는 root다. 기존 흰 바탕, 얕은 색 아이콘, 한 열의 행과 네이티브 details 목차를 재사용한다. 새 라이브러리가 해결할 별도 요구가 없어 [기존 비교 기록](../life-tools-design/open-source-review.md)을 유지한다. 장 목록은 접혀 있고 본문을 홈에 중복 노출하지 않는다.

## 직접 체험

`npm run dev` → `http://127.0.0.1:4173/index.html`에서 기존 공용 인증으로 로그인한다.

1. 관리 → 자료·구성 백업에서 위 익명 JSON을 고른다. 책 1권·활성 장 4개·개정본 1개를 확인하고 **새 사본으로 복원**한다. 기존 공간은 보존된다.
2. 홈 → 내 책 → 목차 → 둘째 장을 선택한다. 원고 수정 후 저장한다.
3. 새로고침하면 책 목록이다. 같은 책의 목차에서 둘째 장을 선택해 수정문장을 확인한다. 자동으로 마지막 장을 기억하는 기능은 아니다.
4. 장의 근거에서 정확한 원문을 열고 책으로 돌아온다. 전체 원고 읽기와 책자 만들기로 이동해 수정 결과를 확인하고 HTML 또는 인쇄·PDF로 받는다.

## 보존 및 검증

원문·정확 버전·출처·발췌·작성자 관계·제외한 해석·개정본·계정별 저장·구성 CAS·백업 형식·공개 범위를 변경하지 않았다. 홈은 쓰기를 하지 않고 모든 편집은 기존 책 편집기와 저장 보호를 거친다. 실제 운영 자료나 개인 인증정보를 사용하지 않았다.

- 정적 검사: HTML 18·JS 58·참조 271/PWA 통과. Node 398/398.
- [새 사용 흐름 4/4](evidence/book-completion/browser-report.json): 1440·820·390px의 실제 JSON 복원 → 홈 목차 → 둘째 장 수정·저장 → 새로고침 → 목록 목차 → 정확 원문 왕복/초점 → 전체 읽기·HTML. 별도 활성 책 3권 제한·보관 책/장 제외·빈 책·계정 분리 확인. 각 실행의 최신 케이스를 합산했으며 하나의 동시 실행 결과로 표현하지 않는다.

[백업 안내 4/4](evidence/book-completion/backup-preview.json)는 별도 익명 검사이며 기존 책 보관/개정본 백업 회귀도 1/1 통과했다.
- 신규 화면 13개 측정: 가로 넘침·44px 미만 조작·16px 미만 입력·이름 없는 조작·대비 실패 0. 3폭 홈/목차/복원 안내를 직접 열어 한글 제목·본문 위계도 별도 검토했다. 빈 홈의 버튼과 구분선이 붙은 문제는 기존 빈 상태 컨테이너 재사용으로 수정했다. 화면 크기 모사는 Apple 실기 검증이 아니다.
- 820px에서 실제 내려받은 HTML을 앱 스크립트 없는 localhost 문서로 열어 [수정 후 PDF](evidence/book-completion/reopened-edited-book.pdf)를 생성하고 한글 수정문장을 추출해 확인했다. 실제 OS 인쇄 대화상자 저장이나 file:// 열기 성공을 뜻하지 않는다.

## Local 인계와 다음 우선순위

1. 선행 #51과 그 기반 PR의 병합 상태를 확인한 뒤 이번 브랜치를 적용한다. 신규 SQL 없음. 선행 책·해석·개정본 validator 조건은 [#51 인계](book-edition.md#local-인계)를 따른다. 기존 설치를 반복하거나 최신 validator를 과거 정의로 덮지 않는다.
2. 정적/Node 검사와 `node tests/book-completion-browser.cjs`, PR CI를 확인한다. 검사는 격리된 익명 Auth HTTP·실제 SDK·IndexedDB를 쓰며 운영 자료를 생성하지 않는다.
3. 배포 후 캐시 `haedo-v85`와 실제 로그인, 기존 책의 홈 표시, 장 선택·저장·출력을 확인한다. 실제 Mac/iPad/iPhone·IME·Files·OS PDF 저장·개인 원고 체험은 별도다.

다음 우선순위는 **집필 중 새 자료 가져오기 → 현재 장의 근거 연결 → 원고 복귀**다. 이번 독립 탐색에서도 이 왕복은 기록/가져오기/책을 다시 찾아가는 부담이 남았다. 그다음은 실제 개인 원고·Apple 기기 체험에서 발견한 불편 개선이며, 정밀 조판은 구체적인 출력 요구가 있을 때 비교한다. 목차 후보 제목·질문은 책을 명시 생성하기 전까지 임시라는 기존 한계도 유지한다.
