# 작품 링크에서 원출처 검토·비공개 첨부까지

2026-10-14 KST. `codex/artwork-reference-review`, #79 후속. **수동 작품 검토 흐름이며 자동 작품 검색은 미구현**이다. 병합·배포·운영 SQL은 Local 담당이다.

## 발견과 이번 결과

시카고 미술관 작품 링크를 입력해도 선택창은 YouTube/GitHub 조회 안내로 실패했고, 직접 입력은 기본 음악으로 시작했다. 이 잘못된 분류·안내를 고쳤다. 미술관 링크 형식만 로컬에서 식별해 예술 작품 입력을 제안하고 원출처를 새 탭으로 열어 제목·작가를 직접 확인할 수 있게 했다. 이미 사용자가 종류를 선택했다면 그 선택을 유지한다.

자동 검색은 공식 API/현재 약관·실제 CORS/한국어 검색을 확인한 뒤 연결해야 한다. 현재 환경에서 그 전제를 확인할 수 없어 미검증 API 버튼이나 가짜 후보를 노출하지 않았다. [제공자 비교와 범위](taste-provider-expansion.md)를 유지하며, 필요한 네트워크 초안을 저장하고 독립적으로 가능한 수동 검토 흐름을 마쳤다.

## 직접 체험

1. 내 페이지 → 글쓰기 → 음악·책·대상 붙이기.
2. `https://www.artic.edu/artworks/129884/starry-night-and-the-astronauts`를 입력 → `작품 정보 입력` 또는 `직접 입력`.
3. 예술 작품 유형과 입력한 출처를 확인한다. `원출처 열기`로 제목·작가를 직접 확인한 뒤 입력 → 첨부 → 비공개 저장.
4. 저장된 첨부의 책갈피로 컬렉션에 명시 보관할 수 있다. 본문·감상은 개인 메모로 자동 복사하지 않는다.
5. 컬렉션에서 같은 방식으로 작품을 추가할 때는 기존 연도·재료·소장처·이미지 권리 메모를 직접 작성하고 별도 백업으로 받는다.

링크 형식을 알아본다는 것은 작품 존재·제목·작가·이미지 권리를 조회하거나 검증했다는 뜻이 아니다. 주어진 작품 예시는 공식 API 문서에 연결된 공개 출처이고 개인 계정 자료가 아니다.

## 구현·보존 계약

- `CollectionMetadata.reference()`는 네트워크 없는 출처 힌트다. `https://www.artic.edu/artworks/{양의 ID}`와 선택적인 영문 slug만 식별한다. credential·별도 포트·query/hash·유사 호스트·다른 경로는 식별하지 않는다. 나머지 출처는 기존 직접 입력을 유지한다.
- 원래 입력 URL을 그대로 전달한다. 제목·작가·제작 시기·소장처를 URL에서 만들어내지 않으며 컬렉션/글에 자동 저장하지 않는다.
- 기존 `CollectionPicker`와 수정 가능한 첨부 폼을 재사용한다. 새로운 최상위 영역·패키지·저장 스키마·SQL은 없다.
- 첨부 폼의 원출처 링크는 기존 `Share.safeURL`로 확인하며 URL 변경 즉시 갱신한다. 빈/잘못된 주소는 링크로 열리지 않는다. 새 탭은 `noopener noreferrer`를 사용한다. 사용자가 누르기 전 외부 요청은 없다.
- 컬렉션에서도 인식한 작품 링크에는 잘못된 YouTube/GitHub 조회 버튼 대신 원출처 확인·수동 입력 안내를 보여준다. URL 변경 시 해당 안내를 갱신하며 입력·개인 메모·상세 정보는 유지한다.
- 실제 정보 검색이나 이미지 요청을 추가하지 않았다. 외부 AI·원본 SNS 변경·자동 공개도 없다. 원문·발췌·정확 버전·계정·동기화·백업 계약은 그대로다.
- 작성 중의 수동 입력은 기존대로 `첨부`를 눌러 초안의 첨부에 반영한다. 이 변경은 첨부 전 임시 폼의 별도 영속 복구 기능을 추가한 것이 아니다.

## 검증 증거

- Node **452/452**, 정적 **HTML 18/JS 72/참조 320/PWA** 통과.
- 새 브라우저 **3흐름**: 요청 없는 링크 식별과 명시 원출처 새 탭, 저장 실패/재시도/새로고침·컬렉션 명시 보관, 컬렉션 상세 정보/개인 메모/원문·페이지 독립성과 백업.
- 첨부·컬렉션 검토 각각 **1440/820/390px**와 좁은 저장 오류를 합쳐 **7상태**. 가로 넘침·44px 조작·16px 입력·접근 이름·대비 검사와 스크린샷 읽기를 구분해 수행했다. 긴 폼은 세로 스크롤하며 고정 하단 탐색을 유지한다.
- 기존 글쓰기 **13흐름**, 정보 조회 **6흐름** 통과. PWA/계정 경계 **9개**, **v103 → v104** 갱신에서 기존 자료 보존.
- 새 흐름 pageerror/console error 0. 외부 요청은 명시적으로 누른 **모의 미술관 출처 새 탭 한 건**뿐이다. 실제 미술관 페이지/API 접속을 검증한 결과가 아니다. PWA의 의도한 전송/콜백 오류 3은 별도다.
- Linux Chromium·실제 IndexedDB·익명 인증/개인 감상 샘플을 사용했다. 실제 개인 기록·Google 로그인·Apple 기기·운영 RLS는 미검증이다.

## 공식 출처와 접근 조건

[시카고 미술관 공식 API 문서 원본](https://github.com/art-institute-of-chicago/data-aggregator/blob/780e6c86025d5f80387dac7574d0f056bf26ff1a/docs/.sections/preface.md)은 위 작품 링크와 `/artworks/{id}` 형식, 작품별 권리 확인·공식 약관 우선 조건을 설명한다. 이전 공식 라이선스/릴리스 검토를 재사용하며 서버 코드는 설치하지 않았다. URL 식별과 폼 안내에 외부 SDK는 필요하지 않다. 서버 코드 라이선스를 이미지 이용 권리로 해석하지 않는다.

Cloud의 기존 설정 초안을 읽어 모든 custom domain을 보존하고 **`api.artic.edu`, `www.artic.edu`만 추가**했다. 저장 응답 `saved`, `requires_publish=true`, 재조회 draft revision 28에서 두 도메인을 확인했다. 실행 환경 재조회는 revision 38/관측 current이나 두 도메인 없음·정책 상태 unknown으로, 적용 완료라고 판단하지 않았다. 기존 차단 요청을 우회하거나 같은 미적용 상태에서 반복하지 않았다. 자격 증명·저장소 목록·설치/시작 스크립트는 변경하지 않았다.

환경 설정에서 변경을 저장한 뒤 **Publish**해야 한다. 적용 후 현재 상태를 확인하고 공식 API·약관·브라우저 CORS를 검증한다. 메타데이터 검색은 고정 API·명시 요청·작은 후보 목록으로 실험하고 한국어/원어 각 5개를 비교한다. 이미지는 권리·실제 요청을 별도로 검증하며 미술관 메타데이터 연결만으로 표시하지 않는다.
