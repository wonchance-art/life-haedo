# 관심 글에서 내 판단·다음 선택까지

2026-10-29 통합 교정. 기준 main 30e94f0, 설계 PR142. **새 읽기 메모는 명시 저장하면 기본 계정 보관으로 이어지고, 문장만 목표·습관에 연결할 때는 메모를 만들지 않는다.** 이전 판의 ‘새 메모=기존 작성 준비의 간결한 보기·선택 전송’ 가설은 기본 계정 연동 요구와 맞지 않아 이 명세로 대체한다. 기존 작성 준비 자체와 명시 전송은 보존한다. 새 메모·직접 연결은 구현/출시 전이다.

## 목표·범위·완료

**관심/질문 → 필요한 원문 읽기 → 개인 메모/작은 행동/글쓰기 중 선택 → 같은 계정 재개 → 정확 근거 복귀**를 하나의 작업으로 설계한다. 읽고 아무것도 남기지 않아도 완료다. 메모·월 계획·글 생성·AI·공개를 필수 단계로 만들지 않는다. [통합 동선·비교](reading-planning-integration.md)와 [계획·기간 회고](planning-practice-review.md)를 같은 실행 묶음으로 읽는다.

## 메모의 최소 모델·수명

소유 범위는 기존 bundle의 계정/자료공간이다. 저장 모양은 다음 기존 link 필드만 사용한다.

    id, kind: reading-note | reading-note-trash,
    note: 사용자가 쓴 평문,
    sourceRefs: [{sourceId, sourceVersionId, locator: null | 검증 구간}],
    revision, createdAt, updatedAt

새 helper는 정확 sourceRef **한 개**, note/revision/timestamps를 필수 검증한다. 같은 ID의 source/version은 편집으로 교체하지 않는다. 다른 판으로 옮기는 것은 명시 새 사본이다. 구절은 기존 UTF-16 locator와 정확 판의 본문으로 검증한다. hash는 참조한 sourceVersion의 값이다. 링크-only는 locator=null, 본문/hash도 계속 null이다. SourceReference의 필수 quote를 가짜 문자열로 채우지 않는다.

첫 메모 열기는 쓰기 0, 첫 유효 저장은 화면에서 한 번 정한 ID로 커밋한다. 같은 클릭/재시도는 같은 ID·작업 영수증을 확인한다. 공백뿐인 새 메모는 만들지 않는다. 기존 메모를 빈 값으로 바꾸는 편집과 휴지통 이동은 별도다. 기존 Core 문자·파일 한도를 유지하고 초과 시 입력을 보존한다. 자르거나 기존 자료를 삭제하지 않는다.

Core.applyChanges는 같은 ID·같은 revision의 재PUT도 다음 revision을 요구한다. 따라서 ID 고정만으로 멱등 재시도라고 하지 않는다. 동일 operation의 원자 커밋 영수증·정확 payload를 확인하면 쓰기 없이 기존 결과로 재개한다. 그 뒤 메모 수정/휴지통 이동이 있으면 옛 payload를 다시 적용하지 않고 현재 상태와 원래 작업 결과를 구분한다.

새 메모 조작은 새 메모를, 기존 메모 행은 정확 ID를 연다. 같은 source/version의 여러 메모를 자동 병합하거나 최신 메모를 덮지 않는다. 저장 전 link revision·bundle revision·계정/공간·원문 판을 재대조하고 Core 변경·원자 CAS·영속 전송 대기를 사용한다. 가변 메모의 옛 revision 재열기는 보장하지 않는다.

**기본 보관:** 저장 → 로컬 커밋·계정 전송 대기 → 기존 Core Sync ACK → 같은 계정 B의 같은 자료/메모 재개. 수동 보내기/받기·새 공간 수신을 새 메모의 기본 절차로 두지 않는다. IndexedDB는 캐시·대기·복구용이며 ACK 전에는 계정 저장 완료로 표시하지 않는다.

**삭제/복원:** 기존 Core는 remove.links와 link tombstone을 지원하지 않는다. reading-note↔reading-note-trash의 revision 증가로 휴지통 이동·복원을 구현한다. 일반 목록에서 숨기고 기존 관리에서 복원한다. 기존 generic link 스키마/구형 파서가 읽을 수 있는 필드만 사용한다. 영구 삭제라고 표시하지 않고 원문·목표·관계·회고를 연쇄 삭제하지 않는다. 원문이 이미 휴지통이면 현재 Core 변경 제한을 유지한다. 해당 자리에서 원문 복원→같은 메모 복귀를 제공한 뒤 메모를 정정한다.

trash→note는 사용자가 고른 명시 복원 작업만 만든다. 오래된 사본 재수신이나 응답 유실 재시도를 복원으로 취급하지 않는다.

새 생성·편집은 엄격한 메모 계약을 적용한다. 기존 generic 형식에서 이미 허용하던 같은 kind의 필드 결손/다중 source 항목 때문에 전체 자료실을 거절하지 않는다. 그런 항목은 원값을 보존한 읽기 전용 호환 항목으로 두고, 사용자가 정확 출처·문구를 확인해 새 메모 사본을 만들 때만 정규화한다. 필드를 조용히 채우거나 자료를 버리지 않는다.

새 메모로 검증된 항목은 로컬 helper뿐 아니라 기존 bundle 교체·수신·서버 CAS 커밋 경계에서 이전 상태와 대조한다. note/trash의 단조 revision, 같은 source/version, createdAt, kind 전이와 항목 보존을 확인한다. 최신 bundle revision만으로 옛 note를 부활시키거나 임의 generic kind로 바꿔 검증을 빠져나가지 못하게 한다. 기존 SOURCE_LINK_KINDS 보호가 새 메모에도 자동 적용된다고 가정하지 않는다. 기존 원문 도메인의 검증 보강·필요한 설치/구기기 호환 확인을 같은 실행에 포함하되 별도 서버 도메인/복제 엔진은 만들지 않는다. 부적합한 수신은 현재 메모와 복구 사본을 유지한 충돌로 표시한다. bundle CAS가 메모별 독립 병합을 제공한다고 가정하지 않는다.

## 화면·확정·복귀

| 화면/행동 | 핵심 | 결과·복귀 |
| --- | --- | --- |
| 읽기 | 제목·정확 본문/링크, 기존 출처 위치 | 읽고 종료 가능; 메모/반응/글 생성 없음 |
| 목표·습관에 연결 | 선택 문구·기존 대상 한 폼, 기본 미선택 | 확인한 관계만 저장; 메모·월 항목 생성 없음 |
| 메모 편집 | 입력 한 칸·저장 상태, 근거는 필요할 때 펼침 | 정확 ID 재열기·원문 복귀; 제목·개요 입력 없음 |
| 메모에서 연결 | 선택 구간만 의도 후보 | 메모 전체 자동 복사 없음; 같은 메모 위치로 |
| 글쓰기 | 기존 준비/작성기에 명시 채택 | 기존 저장·공개 선택; 메모 자동 게시 없음 |
| 관리 | 기존 자료 관리·휴지통·파일 묶음 | 정상 읽기 중 설정 방문 불필요 |

연결 폼은 원래 DOM을 보존하고 열기만으로 route 이동/전역 flush를 시작하지 않는다. 미저장 문구도 직접 확인한 사본으로 연결할 수 있으나 저장 메모 ID/옛 revision 참조를 만들지 않는다. 실제 커밋된 메모만 참조 ID/revision을 붙인다. 관계 의도 사본은 메모 수정·휴지통 이동에 불변이다.

같은 세션은 정확 source/version/hash·locator·메모 ID·초점·스크롤·목록으로 돌아간다. 현재 원문→준비 seed는 locator가 없고 기본 뒤로가기는 원문의 상위 목록을 계승한다. 새 왕복은 beginSourceEdit/closeSourceEditor의 패턴으로 원문 자체를 출발점으로 보존한다. 목표·습관 별도 HTML의 복귀는 [문서 간 계약](reading-planning-integration.md#정확-복귀와-기기-경계)을 따른다.

## 기존 자료·파일·표현

기존 발췌/작성 준비 메모는 원래 객체에 보존한다. 고른 메모 한 개/문구를 계승할 때만 정확 출처와 평문 사본을 검토·저장하고 새 메모를 연다. 질문·다른 자료·개요·output·미완성 사진을 자동 복사하거나 양쪽에 이중 저장하지 않는다. 원본과 새 사본의 ID/편집은 독립이다. 같은 계승 작업 ID로 재시도 중복을 막는다.

기존 자료 JSON은 Core.links와 정확 참조를 포함하며 새 공간 복원에서 link/source/version ID를 재매핑한다. 이를 기본 파일로 재사용한다. 현재 Markdown은 links.note를 누락하므로, **개인 메모 포함을 명시 선택한 출력**에 활성 메모·정확 출처를 넣는 투영을 함께 구현한다. 링크-only에는 인용을 생성하지 않고 휴지통 메모는 기본 출력에서 제외한다. 비공개 JSON의 휴지통 보존과 읽기용 Markdown 포함 범위는 다르다.

계획의 새 통합 파일에 메모를 함께 넣을 때는 선택한 Core 정확 자료 closure에 해당 link를 명시 포함하고 관계 origin의 note ID도 새 link ID로 매핑한다. 메모 미포함 관계는 확인 의도 사본을 유지하되 근거 미확보로 남긴다. 새 별도 메모 파일이나 기존 v1의 임의 필드는 만들지 않는다.

메모 저장은 비공개 계정 보관이다. Share/PhotoPost·공개 renderer/파일에 links.note를 자동 투영하지 않는다. 선택 글쓰기에는 고른 평문/검증 인용만 채택한다. 일반 글의 정확 근거는 PR140, 사진 복구는 PR141의 기존 구현을 재사용한다.

실행 순서는 새 kind helper/검증→Core 계정/파일 경계→읽기 UI/기존 메모 계승→직접 대상 adapter/정확 왕복→A/B·복원·시각/기존 회귀다. 공통 Core/storage/ui는 단일 담당이 통합한다. 기본 메모·직접 연결·재개를 같은 목표로 완주하며 준비·발췌·원문 Sync의 기존 검사/보존 단언을 재사용한다.

시연은 조작·선택·복귀 검수다. 실제 계정 저장·사용자 기기·생활 효용을 입증하지 않는다. 후보가 준비되면 같은 장면으로 통합 검수하고 메모/읽기만으로 종료하는 조건을 유지한다.
