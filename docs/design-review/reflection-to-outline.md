# 글을 읽고 생각을 남겨 목차로 연결하기

2026-10-09 KST · 디자인 책임자 root · `codex/reflection-to-outline`

Local이 PR #55의 실기 검증·선행 PR 통합·배포를 맡는 동안 별도 브랜치에서 **자료 검토 → 작성 연도/묶음별 읽기 → 현재 생각 → 목차 구성**을 개선했다. 기준은 사용자가 선택한 A · 원고 중심이며, 새 수집기·AI 분석·저장 구조를 만들지 않았다. #55의 `8afd77c` 위에서 시작한 후속 변경이다.

## 실제로 막혔던 부분

익명 자료 6개·정확 버전 7개를 기존 가져오기 UI로 넣고 회고에 담았다. 같은 자료로 390·820·1440px을 비교했다. 변경 전 모바일 첫 원문 제목은 y627이고 본문은 모두 접혀 있었다. 현재 생각 입력은 y2018, 목차 생성 조작은 별도 화면의 y1904에 있었다. 현재 생각을 길게 쓰다가 목차에 갔다 돌아오면 입력값은 남지만 페이지는 위로 이동하고 읽던 본문도 다시 접혔다. 넓은 화면에서도 같은 정보 순서 문제가 있었다.

위 좌표는 페이지 위에서 측정한 값이다. 모든 거리를 사용자가 반드시 수동으로 스크롤했다는 뜻은 아니다. 자동 초점 이동·도착 위치와 따로 기록했다.

## 체험 경로

해당 브랜치를 실행하고 **기록 선택 → 회고에 담기**, 또는 **도구 → 회고**로 들어간다. 기존 선택이 있으면 그대로 사용한다. 자동 검사는 격리된 브라우저의 익명 자료로 수행하며 개인 자료를 샘플로 교체하지 않는다.

1. **연도별/묶음별**에서 선택한 글의 앞부분을 바로 읽는다. 작성자 관계·본문 확보 범위·선택 버전·원문 작성일은 본문과 함께 남는다.
2. **본문 읽기**를 펼쳐 해당 버전 전체를 확인한다. 책 아이콘은 정확한 원문 화면을 연다. 열린 본문은 같은 화면 세션에서 유지된다.
3. 상단 연필 아이콘 **내 회고 쓰기**로 현재 생각을 적는다. 원문과 구분한 입력이며 문서 높이로 늘어난다. 생각 제목 옆 복귀 아이콘으로 읽던 자료에 돌아온다.
4. 필요하면 선택 정보 옆 연결 아이콘 **선택한 글 묶기**로 직접 묶음을 만든다. 묶음별 보기는 이 명시적 분류를 사용한다.
5. **목차 구성**에서 연도/묶음 후보를 보고 제목·질문·장 포함 여부를 고른다. 상단에서 회고로 돌아가거나 책을 만든다. 후보는 아직 임시이며 명시적으로 책을 만들기 전에는 영속 저장된 목차가 아니다.
6. 후보의 연결 원문을 펼쳐 정확한 버전을 확인한 뒤 같은 후보·펼침·조작 초점으로 복귀한다. 만들어진 책은 기존 A안의 집필·개정·전체 읽기·PDF 흐름을 사용한다.

## 선택한 구조

- 회고는 A안의 흰 단일 읽기 열과 옅은 자주색 조작을 사용한다. 반복 ‘도구/회고’ 제목·저장 설명은 줄이고 읽기 모드·생각 작성·목차·저장을 작은 고정 행으로 묶었다.
- 선택 변경·작성 기간·선택 통계는 펼치는 보조 조작이다. **보기 기간과 영속 선택, 목차 후보 범위, 원고 내보내기 범위**는 계속 별개다.
- 글 미리보기는 첫 비어 있지 않은 문단의 앞 260개 코드포인트를 안전한 평문으로 보여준다. 요약·AI 해석·저장된 발췌가 아니다. 전체 본문을 펼치면 미리보기는 접고 불변 원문 전체를 보여준다. 원문·버전·UTF-16 위치는 바꾸지 않는다.
- 현재 생각은 별도의 제목과 원고 입력으로 구분한다. 입력 DOM/value를 재생성하지 않고 높이만 조정한다. 높이 측정 전후 페이지 위치를 보존한다.
- 현재 생각에서 연필 아이콘을 다시 눌러도 이전 읽기 위치를 덮어쓰지 않는다. 반복 진입 뒤 복귀 위치가 바뀌는 실제 브라우저 실패를 확인하고, 읽기 대상이 화면 위로 지나간 경우 기존 복귀 지점을 유지하도록 고쳤다.
- 목차는 큰 설명 블록을 줄이고 장 번호·포함 체크·제목·근거를 한 후보에 모았다. 포함 체크의 접근 이름은 ‘장 N 포함’으로 유지한다. 생성/복귀 조작은 상단에 고정하고 임시 보관 경고는 숨기지 않았다.

[공식 오픈소스·제품 비교](book-design-reset-references.md)의 같은 날 확인한 novelWriter·Zettlr·Manuskript 사례를 재사용했다. 자료/원고/목차를 구분하고 선택한 대상을 이어가는 구조를 참고했다. 라이선스와 이미지/코드 열람 범위는 해당 문서에 있다. 상시 3열·새 에디터·자동 요약은 도입하지 않는다. 기존 Reflection·Books·native details/textarea·아이콘으로 해결하며 새 앱 의존성은 없다.

## 보존 계약

`Reflection.chronology/themes/markdown`, `Books.outline/fromOutline`과 저장·동기화·백업 모델은 그대로다. 보기 기간 밖 선택, 작성 시기 미확인, 타인 글, 누락 참조, 겹친 묶음을 삭제하거나 다른 버전으로 바꾸지 않는다. 연도는 원문 작성 시기이며 사용자의 나이·경험 시기를 추정하지 않는다.

본문 펼침·읽던 자료 위치·목차 진입 전 페이지/커서·후보 출처 펼침과 표시 수는 계정/작업공간의 기존 화면 session 안에만 둔다. 백업·동기화·공개 사본에 추가하지 않는다. 후보는 최초 선택+기간을 기억하고 **후보 다시 만들기**를 명시적으로 확인한 경우에만 갱신한다. 후보 제목 한글 조합 중 분류 전환·닫기로 입력 DOM을 버리지 않는다.

책 생성의 회고 저장 → 모델 검증 → 새 책 저장 → 집필 이동 순서는 유지한다. 저장 실패 뒤 같은 책 ID를 재시도하며 중복 생성하지 않는다. 별도 원문 열기와 내보내기는 저장 실패 시 차단한다. 이번 변경에 신규 SQL은 없다. 서비스워커 캐시는 v89로 갱신한다.

목차를 떠난 뒤 제거된 후보의 원문 요청이 이어지지 않도록 행 연결 여부를 추가 확인한다. 이는 정적 검토에서 발견한 비동기 경계의 예방 보완이며 실제 사람의 지연 저장 결함을 재현·수정했다고 주장하지 않는다.

실제 iPad/iPhone·Apple 한글 IME·Files·운영 로그인·배포는 Local의 별도 작업이며 여기서 통과로 보고하지 않는다. 실제 개인 자료의 유용성 평가, 수백 개 기록의 장기 사용 밀도도 별도다. Chromium 151의 폭·터치 모사와 일반 한글 입력/합성 조합 이벤트를 실제 Apple 검증으로 부르지 않는다.

Local은 PR #55의 후속 수정과 이번 브랜치를 비교해 필요한 수정부터 반영한다. #55가 먼저 병합됐다면 해당 main을 기준으로 충돌을 해결하고 최종 CI를 확인한다. 캐시 번호가 다른 후속 변경과 겹치면 통합 커밋에서 새 번호로 갱신한다. Cloud는 이 브랜치를 병합·배포하거나 운영 SQL을 실행하지 않는다.

Local 실행 순서:

1. 현재 사용자 변경을 보존하고 #55 및 그 선행 PR의 실제 통합 상태를 확인한다. 이 브랜치는 #55의 `8afd77c`를 기반으로 하며, 후속 Local 수정과 비교해 필요한 변경을 보존한다.
2. 통합 후보에서 `npm run check`, `npm test`와 CI 브라우저 검사를 통과시킨다. 새 검사는 `BASE_URL=http://127.0.0.1:4184 node tests/reflection-to-outline-browser.cjs`이며 Playwright/Chromium 경로 설정은 기존 README의 브라우저 환경을 따른다.
3. 실제 iPad Chrome에서 긴 원문→현재 생각→목차 원문 왕복, 한글 입력 중 분류 전환/닫기, 화면 회전·소프트 키보드·마지막 조작 접근을 확인한다. 원문·발췌·선택 버전·회고 입력과 책의 PDF/백업 결과를 대조한다. 원격 저장은 사용자가 이미 연결한 범위에서만 검증한다.
4. 기존 사용자 승인 범위에서 Local이 병합·배포하고 라이브에서 같은 경로와 새 캐시를 확인한다. 신규 SQL 설치나 합성 운영 자료 생성은 필요 없다.

다음 우선순위는 실제 20대 글로 장을 구성하면서 후보 이름·묶음·현재 생각의 연결이 충분한지 확인하는 것이다. 기능을 늘리기 전에 책 한 권을 끝까지 만드는 과정의 막힘을 수집한다.
