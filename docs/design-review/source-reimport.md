# 보관한 네이버 글에서 새 본문 검토

2026-10-08 KST. [공식 경로 비교](../life-tools-design/source-intake-next.md)의 첫 작은 구현이다. 네이버 검색 요약이나 임베드를 원문으로 수집하는 대신, 사용자가 제공한 본문을 기존 출처에 명시적으로 연결한다. 새 API·스크래퍼·런타임 의존성·SQL은 없다.

## 직접 사용할 흐름

**기록 → 네이버 원문 읽기 → 출처 정보 → 본문 추가·다시 가져오기 → 본문 입력 → 포함 범위 확인 → 원문·출처 확인 → 저장.**

기존 제목·원형 URL·작성자 관계·작성일을 제안하고 본문은 비워 둔다. 작성자·날짜는 현재 읽는 정확한 버전에서 가져온다. 제목은 기존 모델의 원문 공통 제목이며 버전별 제목 이력을 새로 만들지 않는다. 포함 범위는 항상 미확인으로 시작하며 이전 전체/일부·누락을 기계적으로 승계하지 않는다. 날짜 입력기가 받아들이지 못하는 기존 문자열도 텍스트 입력으로 원값을 보여준다.

기존 출처 정보 안에 버튼 하나를 추가하고 기존 입력·검토 화면을 재사용했다. 새 본문과 포함 범위를 이미 채워진 출처 정보보다 먼저 배치했다. 원문 읽기 도구나 최상위 탐색을 늘리지 않는다. 새 본문을 검토하기 전 입력 중인 메모와 초안을 먼저 보관한다. 보관 실패 때는 새 초안으로 덮어쓰지 않는다. 새 초안 자체의 저장에 실패하면 새 입력 화면과 재시도 경로를 유지한다.

새 본문 없이 확인을 누르면 입력을 요청한다. 링크만 보관할 의도라면 기존 ‘링크 보관’을 명시적으로 선택한다. 미적용 초안으로 보관·재개할 수 있고, 취소는 그 검토 초안만 지운다. 이미 저장한 원문은 유지한다.

## 식별과 보존 경계

- 기존 `existingSourceId`와 `prepareStage` → `Core.prepareImport` → `renderPrepared/apply`를 재사용한다. 새 버전 저장 엔진을 추가하지 않는다.
- 본문·제목·작성자·작성일 변경에는 명시적으로 선택한 원문 연결을 유지한다. 원천 또는 원형 URL 변경, 파일명 변경에는 연결을 해제하고 기존 겹침 확인을 다시 거친다. 주소를 비운 경우도 해제한다. 되돌려 입력했다고 자동 연결하지 않는다.
- 같은 본문·범위·메타데이터·형식이면 기존 버전을 재사용한다. 내용이나 메타데이터가 바뀌면 새 불변 버전이다. 기존의 파일 식별 조건은 완화하지 않는다. 다른 파일명으로 보관한 원문을 같은 파일로 강제 연결하지 않는다.
- 이전 발췌의 정확한 UTF-16 위치와 원문 버전 참조, 묶음·내 페이지·공개 사본은 이전 버전에 남는다. 선택 동기화·백업·게시 모델과 Auth는 수정하지 않는다. 새 자료를 SNS로 보내거나 공개 사본을 자동 갱신하지 않는다.
- 새 진입은 네이버 원문에 한정한다. 일반 가져오기에서 이미 선택한 원문 연결도 본문·메타데이터 수정에 유지하도록 개선했다. 따라서 기존 일반 가져오기 회귀도 함께 확인한다.

## 검증

기능 검사·시각 검토·실제 기기·배포를 구분한다. 합성 계정과 모의 HTTP로 실제 앱과 IndexedDB를 실행하며 운영 Supabase·개인 SNS를 조회하지 않는다. 결과는 다음과 같다.

- 정적 검사 HTML 18 / JS 54 / 참조 259 / PWA 통과, 단위 311/311 통과.
- 기존 가져오기→정확 발췌→저장 결과 복귀: 1440·820·390px 3/3 통과.
- 기존 소셜 검사: 최초 8/9 통과 뒤 오래된 ‘모아보기’ 탐색을 현재 ‘기록 목록’으로 고쳐 초안 재개 1/1 재검증. 수정 중의 잘못된 selector도 실패 기록에 남겼다. 앱의 저장 로직을 바꿔 테스트를 맞추지 않았다. CI에서는 전체 9개를 실행한다.
- 새 집중 검사: [7개 경로 최종 통과](evidence/source-reimport/combined-report.json). 최초 세 폭 검사가 저장 후 조건부 결과 버튼을 항상 기대해 중단됐고, 실제 피드 카드에서 정확 버전을 여는 helper로 수정한 뒤 해당 3개와 날짜 경계 1개를 확인했다. 취소/재개·식별 변경·실제 IndexedDB 트랜잭션 실패/재시도는 최초부터 통과했다. 실행별 보고를 보존하며 전체 7개를 로컬에서 한 번에 재실행한 것으로 합산하지 않는다.
- 최종 본문 우선 배치의 [세 폭 화면·초점·식별 검사](evidence/source-reimport/layout-report.json)와 저장 실패 경로 1/1을 추가 확인했다. 10개 시각 상태에서 가로 넘침·44px 조작·16px 입력·접근 이름·대비 위반 0, 최소 글자 대비 6.05:1. 실제 콘솔/페이지 오류와 외부 요청 0.
- root가 모바일 진입·입력 캡처를 보고 본문 우선 순서를 개선했고 최종 캡처를 재검토했다. QA가 화면·입력 경계를 독립 확인했다. 실제 기기 사용 평가로 보고하지 않는다.
- 합성 설정으로 공개 산출물 생성 통과. 선행 PR #43과 각각 70개 파일, 추가/삭제 없이 `ui.js`·`sw.js`만 변경됐다.

## Local 인계

PR #43 이후 변경이며 서비스워커 v77, SQL 설치 없음. Local이 선행 PR 병합 순서·캐시 갱신·라이브 로그인을 확인한다. 실제 Mac/iPad/iPhone에서 네이버 본문 복사·붙여넣기, 한글 IME와 Files 전달은 별도로 확인해야 한다. 브라우저 폭과 터치 모사는 그 검증을 대신하지 않는다. 원천 앱에서 본문을 복사하는 작업 자체는 이번 개선으로 없어지지 않는다.
