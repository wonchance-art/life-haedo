# 사용 흐름 중심 블로그 UX·UI 개편

2026-10-18 KST. 디자인·통합 책임: 주 작업 에이전트. [승인한 상세 설계](../life-tools-design/sns-blog-user-journeys.md)의 P0 흐름 구현과 이번 검증의 기록이다.

## 문제와 결과

사용자는 SNS처럼 깔끔한 화면과 함께 실제 사용 흐름을 먼저 설계하고, 이미 만든 화면도 일관되게 개편하도록 요청했다. 이전에는 홈과 글 관리가 비슷한 글 목록을 제공했고, 프로필·작성·기존 선택 자료 페이지가 한 화면에 함께 있었다. 이번에는 **홈에서 쓰기 → 초안 보관 또는 명시 저장 → 글 읽기 → 출발 목록 복귀**를 연결했다.

홈은 내 글의 대표 목록이며 `글 / 초안 / 보관함`과 `내 글 검색`을 제공한다. 첫 사용자는 로그인 전에 누른 `첫 글 쓰기` 의도를 유지해 작성기로 들어간다. 재방문자는 새 글과 실제 초안 이어쓰기를 구분하고, 읽기·수정 뒤 원래 탭과 검색 조건으로 돌아간다. 프로필은 독립 편집 폼으로 열며 같은 피드를 다시 만들지 않는다.

이번 범위는 기존 로컬 작성·읽기·초안·복귀를 완결하는 P0이다. 기본 작성 글의 공개 목록·안정 글 주소·게시·갱신·철회는 별도 P1이며 이번 개편에서 지원된 것으로 표시하지 않는다. 사진 공개와 원문에서 새 글 쓰기 연결은 P2이다. 기존 선택 사본 공개·원문 읽기·동기화·백업은 각 경로로 보존한다.

대표 화면: [이전 홈](evidence/blog-user-journeys/before-home-390.png) · [현재 홈](evidence/blog-user-journeys/after-home-390.png) · [초안](evidence/blog-user-journeys/after-drafts-390.png) · [작성](evidence/blog-user-journeys/after-writing-390.png) · [최종 읽기](evidence/blog-user-journeys/after-reading-390.png) · [최종 프로필](evidence/blog-user-journeys/after-profile-390.png). 이전·현재 홈의 익명 샘플 내용이 달라 정보 구조·역할 전환 비교로 사용하며 글 길이 차이를 개선 수치로 해석하지 않는다.

## 실제 동선과 화면 계약

| 시작 의도 | 실제 동선 | 완료 결과 |
| --- | --- | --- |
| 첫 글을 남기기 | 첫 글 쓰기 → 로그인 → 본문 입력 → 글 저장 | 제목·사진 없이도 비공개 저장한 글 읽기 |
| 새 글 쓰기 | 홈의 새 글 쓰기 → 본문부터 입력 | 기존 초안을 덮어쓰지 않는 별도 글 |
| 초안 이어쓰기 | 최신 초안 행 또는 초안 탭 → 해당 초안 | 새 글 초안과 기존 글 수정 상태 구별 |
| 글 다시 찾기 | 내 글 검색·탭·20개 더 보기 → 읽기 | 전체 읽기 결과를 검색하며 일부 실패는 따로 표시 |
| 읽고 돌아오기 | 글 읽기 → 내 글로 돌아가기 | 출발 탭·검색어·표시 범위·정확 항목과 초점 유지 |
| 수정하고 돌아오기 | 글 읽기 → 글 수정 → 저장 → 복귀 | 실제 새 저장 항목을 중심으로 복귀 |
| 프로필 수정 | 프로필 편집 → 이름·소개·표시 수정 → 저장하고 돌아가기 | 홈의 실제 이름·소개 반영 |
| 자료·기존 형식 활용 | 자료실 또는 접힌 자료실 입구 → 원문/컬렉션/묶음/선택 자료 페이지 | 정확 버전·기존 작성·공개 사본·파일 기능 보존 |

빈 홈에는 `첫 글 쓰기` 한 주행동을 둔다. 글이 있는 홈의 작성 안내는 비상호작용 텍스트이며 `새 글 쓰기` 버튼으로 시작한다. 글·초안·보관함은 같은 목록 위치의 탭이며 방향키와 Home/End 키로 이동한다. 검색은 제목·본문과 실제로 읽은 첨부 제목을 대상으로 하며 현재 탭의 전체 결과에서 찾는다. 사진의 개수만 읽은 요약으로 사진 설명이나 첨부 상세까지 모두 검색했다고 주장하지 않는다.

새 글은 본문에 먼저 초점을 두고 제목을 선택 입력으로 둔다. 입력 중에는 `초안 보관 중… / 초안 보관됨`, 명시 저장에는 `글 저장`과 읽기 화면의 저장 확인을 쓴다. 저장 전 수정 초안이 기존 저장 글을 바꾸지 않는다. 사진 선택 취소는 본문에 복귀하며 사진 원본·설명·대체 텍스트·순서를 유지한다. 실패·충돌에는 입력을 남기고 오류 가까이에 다시 저장·백업·새 사본 경로를 둔다.

760px 이하 작성 중에는 전역 하단 메뉴를 감추고 작성기의 닫기와 저장을 남긴다. 상단의 중복 복귀는 감춘다. 읽기로 전환하거나 닫으면 해당 화면의 탐색이 복원된다. 읽기에는 명시적인 목록 복귀를 두어 긴 글 끝에서도 출발 흐름을 마칠 수 있다.

새로 저장한 글이 검색 조건에 가려지면 저장 실패나 빈 목록으로 오해시키지 않고 이유와 명시적 검색 해제 조작을 제공한다. 검색·탭을 조용히 초기화하지 않는다. 느린 글·초안·구성 조회가 다른 화면이나 다른 계정의 DOM·초점·읽기 위치를 바꾸지 않도록 현재 세대·작업공간을 확인한다.

## 정보 구조와 보존

표시 탐색은 `홈 / 자료실 / 도구 / 설정`이다. 내부 ID `home / records / tools / manage`와 기존 주소를 보존한다. 자료실의 기존 `내 페이지` 입구와 화면 이름을 `선택 자료 페이지`로 통일했다. 선택한 원문·첨부 글·공개 후보를 관리하는 역할이다. 홈의 중복 페이지 요약은 제거하고 명시 미리보기 입구를 유지한다.

| 형식 | 읽기·초안 보관 | 보존 조건 |
| --- | --- | --- |
| 기본 텍스트·사진·리치 글 | 별도 photo-post metadata와 실제 Delta·Blob | 원본 바이트·해상도, revision/replaces CAS, ZIP 복원, 브라우저 비공개 범위 |
| 기존 일반 첨부 글 | workbench의 page.posts와 별도 page-drafts | 글·초안의 독립 revision, 같은 트랜잭션의 저장, 기존 공개 후보 범위 |
| 원천 기반 직접 작성 글 | source와 불변 sourceVersion, 별도 kind=writing 초안 | 정확 원문 버전·UTF-16 구간, sourceRevision/baseVersion CAS, 선택 이어쓰기 |

홈은 세 형식을 표시 어댑터로 합친다. 데이터 형식을 서로 변환하거나 초안을 공개·일반 JSON·기기 간 동기화에 자동 포함하지 않는다. 기존 선택 자료 페이지의 작성·초안·사진 파일 조작은 접힌 호환 영역에 남기고 정확한 글·초안 목적지가 있으면 필요한 과업만 연다. 글 보관을 공개 철회나 원문 삭제로 설명하지 않는다.

공통 흰색·차콜, 얇은 구분선, 실제 한글 본문과 사진, 작은 이니셜 프로필을 유지한다. [DESIGN.md](../../DESIGN.md)와 [.impeccable/design.json](../../.impeccable/design.json)에 실제 토큰과 새 탭·초안 행·작성·복귀 행동을 기록했다. 새 외부 라이브러리나 서버·SQL은 추가하지 않았다. [앞선 공식 사이트 조사](sns-blog-experience.md)의 Threads·Substack·Medium·브런치 참조를 재사용했고 이번에 새 외부 조사를 수행한 것으로 보고하지 않는다. Impeccable 문서화 지침은 수동 적용했으며 설치되지 않은 엔진을 실행하지 않았다.

## 검증과 해석

이번 검증은 Linux Chromium, 익명 HTTP Auth/공개 RPC 응답, 실제 로컬 앱·공용 SDK·IndexedDB를 사용했다. 개인 계정·운영 자료·실제 OAuth 세션은 사용하지 않았다. 가로 넘침·44px 조작·16px 입력·접근 가능한 이름·실제 대비·콘솔/페이지 오류를 기능 흐름과 함께 확인했다. 화면 폭 모사는 실제 Apple 하드웨어·OS 한글 입력기·Files·VoiceOver 검증이 아니다.

완료한 검증은 범위별로 구분한다. 같은 과업의 재검증과 겹치는 캡처를 합산해 전체 성공 수로 만들지 않는다.

홈의 최종 전체 실행은 14/16이었고, 첫 글 버튼의 실제 초점 대상에 맞춘 검사 1개와 실제 위치 수선 1개를 각각 1/1로 재검증했다. 늦은 조회가 빈 홈의 중복 작성 행을 감출 때, 이미 초점을 둔 원문 행이 scrollY=0에서 약 43px 위로 이동하는 문제를 재현했다. 위 영역의 수축 높이를 필요한 동안 보존해 이동을 1px 이내로 제한했고 기존 정확 버전·키보드 열기 검사를 유지했다. 기존 블로그 홈은 전체 5/6 후 계정 B의 첫 글 작성 의도를 닫고 홈을 확인하는 마지막 과업을 1/1 재검증했다. 명칭 통일 후 홈 관련 2개와 검색/도구/설정 복귀의 세 폭 3개도 필요한 범위만 추가 확인했다.

신규 과업의 기능 결과는 `final-functional-report.json` 8/8이며 24상태 시각 묶음과 분리한다. 초기 fixture의 표시 문구·날짜 경계 적응을 최종 기능 실패나 새 기능 검증으로 합산하지 않는다. 위 브라우저 흐름은 실제 콘솔·페이지 오류 0을 확인했다.

## 독립 마감 검토와 수선

공유 히스토리가 없는 독립 검토가 승인 계약, 필수 24개·보조 27개·공통 프레임 16개 캡처와 기능 기록을 읽었다. 첫 판정은 `fix`였다. 통합 읽기의 공통 뒤로가기와 내부 목록 뒤로가기 중복(F1), 프로필의 공통 제목·뒤로가기와 내부 제목·복귀 중복(F2)을 material 문제로 지적했다.

읽기에서는 공통 상단 복귀 하나와 수정·다운로드·더 보기, 글 끝의 명시 복귀를 남겼다. 기존 독립 사진 글 화면의 필수 목록 복귀는 보존했다. 통합 프로필에서는 공통 헤더 아래 실제 이름·소개 폼부터 시작하도록 내부 중복 행을 제거했다. 수선 뒤 세 폭의 읽기·프로필 6캡처와 3개 과업에서 실제 ZIP 다운로드, 상단/하단 복귀의 검색·탭 유지, 프로필 저장 후 같은 홈과 새 이름을 확인했다. 이 수선의 재캡처가 앞선 읽기·프로필 상태를 대체한다. 독립 검토자가 여섯 원본을 직접 다시 확인하고 F1/F2 해결, `ship`으로 판정했다. 남은 material 문제는 없다.
