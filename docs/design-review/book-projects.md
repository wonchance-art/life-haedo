# 책 프로젝트와 장별 원고

2026-10-08 KST. [회고의 첫 읽기 흐름](reflection-reading.md)을 이어 **주제·기간별 책 만들기 → 목차 구성 → 장별 원고와 정확한 원문 연결 → 책 원고 파일**까지 구현했다. 자기 이해 분석이나 인쇄용 책자가 완성됐다는 뜻은 아니다. root가 화면을 통합하고 모델·SQL·독립 브라우저 QA·공식 참고조사를 나눴다.

## 직접 써볼 흐름

Local 적용 후 **도구 → 책 만들기**로 들어간다. 개발 환경에서는 `npm run dev`로 실행하고 로그인된 보호 화면의 `index.html?section=tools&view=books` 경로를 사용한다. 합성 검증은 `BASE_URL=http://127.0.0.1:4173 node tests/book-projects-browser.cjs`다. 개발 주소를 공개 배포 주소로 제시하지 않는다.

1. ‘20대’ 또는 원하는 주제로 빈 책을 만든다. 기존 회고가 있으면 ‘기존 회고로 책 만들기’로 선택 원문과 회고를 첫 장에 **독립 복사**한다. 나이·생년으로 기간을 추정하지 않는다.
2. ‘책 설정’에서 제목·선택 기간·이 책에서 돌아볼 질문을 적는다. 시작/끝 연도는 빈 값 또는 0001–9999이며, 시작이 끝보다 늦으면 저장을 막고 입력을 유지한다. 기간은 설명 정보이며 연결 자료의 자동 필터가 아니다.
3. ‘목차’에서 장을 추가하고 위/아래 조작으로 순서를 바꾼다. 한 번에 한 장의 제목과 원고를 편집한다. 장 안의 ‘근거’를 펼쳐 원문 버전을 연결하고 읽는다. 정확한 옛 버전으로 갔다가 같은 장·조작으로 돌아온다.
4. ‘책 원고 파일로 보관’에서 **현재 책의 모든 장**을 목차 순서대로 받는다. 기본은 직접 쓴 원고와 출처다. 원문 본문은 명시적으로 켜야 들어간다. 다른 책·기존 회고·연결하지 않은 자료는 포함하지 않는다.
5. ‘책 목록’에서 다른 책을 열거나 새로고침한 뒤 다시 연다. 앱에서 복원하려면 관리의 자료·구성 JSON을 받는다. Markdown은 편집용 원고이며 복원 백업이나 공개 사본이 아니다.

처음에는 본문을 바로 편집할 수 있는 기본 textarea를 유지했다. 설정·목차·근거·내보내기를 접고 큰 대시보드나 새 최상위 메뉴를 만들지 않는다. 장당 길이 표시, 한국어 줄바꿈, 기존 아이콘·44px 조작·색 토큰을 재사용한다. 실제 책 장면의 질문/해석 효용은 사용자 체험으로 확인하며 자동 검사 수로 대신하지 않는다.

## 저장·보존 계약

- `life-workbench-v1`에 선택적 `books`만 추가했다. 책이 없는 기존 v1 및 단일 `reflection`을 그대로 수용한다. 회고 복사는 명시적이며 이후 어느 쪽을 고쳐도 다른 쪽을 덮어쓰지 않는다.
- 책은 제목·기간·질문과 순서 있는 장 목록을 갖는다. 장은 제목·원고·정확 `versionIds`다. 원문 복제·최신 버전 대체 없이 같은 버전을 여러 장에서 참조할 수 있다. 장 내부 중복은 거절하고 누락된 연결은 그대로 표시한다.
- 한 작업공간 최대 20권, 책당 100장, 장당 1,000개 연결, 제목 500·질문/원고 20,000 UTF-16 단위, **묶음·페이지·회고·책 전체 2 MiB**다. 책 전체를 한 메모에 밀어 넣지 않지만 무제한 원고 용량이나 개정 이력을 약속하지 않는다.
- 기존 계정/작업공간별 CAS·저장 실패·충돌·독립 복구 사본을 재사용한다. 장/책 이동·원문 이동·내보내기 전에 저장하며, 실패하면 원고와 현재 장을 유지한다. 저장 중 뒤늦은 원문 열기는 이미 바뀐 장에서 실행되지 않도록 현재 화면도 확인한다.
- 원문 도착 후 구성 이어쓰기라는 기존 순서를 유지한다. 책이 포함된 구성 전체가 전송되며 책 필드를 버리고 재시도하지 않는다. 충돌 비교에서 양쪽 책의 질문·장 원고·근거를 확인한다. 선택하지 않은 쪽의 복구 JSON에도 책을 보존한다.
- 자료·구성 JSON의 새 사본 복원은 책/장 ID와 정확 원문 참조를 함께 바꾼다. 여러 장의 같은 누락 ID는 하나의 새 미연결 ID로 유지한다. 원문·발췌 UTF-16 구간·공개 사본·연표는 바뀌지 않는다.
- Markdown의 제목·출처·원문은 안전한 코드 블록으로 보존하고 사용자가 쓴 원고는 Markdown 원값을 유지한다. 각 장의 정확 버전·원저자 관계·작성일·확보 범위를 함께 남긴다. 다운로드가 외부 AI 전송·게시를 일으키지 않는다.

[전체 설계와 Mermaid](../life-tools-design/reflection-book.md), [최신 공식 mdBook·novelWriter 비교](../life-tools-design/open-source-review.md)를 따랐다. 목차 순서와 원고/자료 구분을 참고했으며 실행 패키지를 추가하지 않았다. 조판·PDF 엔진은 실제 출력 단계에서 별도 비교한다.

## 기능 검사와 시각 검토

익명 한글 원고와 모의 Auth/HTTP, 실제 앱·SDK·IndexedDB를 사용했다. 운영 Supabase·개인 기록에는 접근하지 않았다.

- 정적 검사 HTML 18 / JS 56 / 참조 265 / PWA 통과. 단위 검사 338/338 통과(책 모델/복원/Markdown 11개 및 구성 원격·재시도 책 보존 3개 추가).
- 신규 브라우저 고유 7경로 통과: 1440/820/390에서 2권·3장 생성/전환/순서/정확 원문/원고 범위/재열기, 실제 IDB 저장 실패 복구, 경쟁 저장본과 원고 비교, 통합 JSON 새 사본, 계정/작업공간 분리. 초기 준비 대기 오류와 수정 후 재실행 범위를 실행별 보고에 구분한다.
- 기존 구성 동기화 전체 9/9 통과. 책을 포함한 양쪽 충돌 비교, 다른 쪽 복구 JSON과 새 사본 참조 재매핑, 중지·계정 전환·자료 선행 확인. [결과](evidence/book-projects/composition-browser.json).
- SQL은 격리 PostgreSQL 17.11에서 기존 163 + 책 109, 설치 확인 기존 11 + 책 12, JS/SQL 차등 193사례 통과. 최초 적용·재적용 전후 기존 자료·메타데이터·함수 OID/owner/ACL 동일. 임시 컨테이너 제거. [결과](evidence/book-projects/sql-report.json).
- 첫 시각 검토에서 중복 ‘책 만들기’ 제목을 줄이고 저장 조작을 책 목록 행에 합쳤다. 원고 입력 높이와 길이 설명도 줄였다. 최종 배치·원문 복귀 집중 3/3도 통과했다. [실행별 합산](evidence/book-projects/combined-report.json)에 초기 환경 시작 전 오류, 빈 목록의 테스트 대기 조건 수정과 재실행 범위를 구분했다. 8개 상태에서 가로 넘침·44px/16px/접근 이름 위반 0, 최소 글자 대비 6.05:1, 콘솔/페이지/외부 요청·운영 쓰기 0이다. 시각 수치와 root/독립 QA의 직접 이미지 검토는 구분하며 정확 HEAD CI는 PR에 기록한다.

## Local 인계

PR #45 다음에 적용할 후속이며 캐시 **v79**다. Cloud에서는 운영 SQL·병합·배포를 실행하지 않는다.

1. 선행 구성 migration `20261006010000_life_compositions.sql`이 설치돼 있어야 한다. 이미 설치한 선행 SQL을 반복 적용하라는 뜻은 아니다.
2. [책 검증 확장](../../supabase/migrations/20261008010000_life_composition_books.sql)을 운영의 정확한 프로젝트에 적용한다. 기존 `life_composition_valid(jsonb)` 하나만 교체하며 새 테이블·RPC·권한·Auth·자료 변경은 없다. SHA-256 `d05a97a907b98bf9118a0d36cafad091d7b5ee25eb73f52e50ea33fbfbf5ef9d`.
3. [읽기 전용 설치 확인](../../supabase/tests/life-composition-books-installation.sql)의 12조건이 모두 통과하는지 확인한다. SHA-256 `8728c88951d65dee662b2767acec37d5bd0e7ae578749c00363f30dc9084f687`. [로컬 합성 SQL](../../supabase/tests/life-composition-books.sql)은 운영에서 실행하지 않는다.
4. 선행 PR부터 순서대로 병합·배포하고 v79에서 책 생성·장 편집·새로고침·명시 구성 이어쓰기·JSON 보관을 확인한다. 구형 서버/앱은 새 책 필드를 거절할 수 있으므로 모든 작업 기기의 새 앱 로드를 확인한다. 책을 제거해 동기화를 억지로 성공시키지 않는다.

운영 설치 성공·실제 HTTP 저장·기기 간 이어쓰기 완료는 이 문서의 로컬 SQL 결과로 대체할 수 없다.
