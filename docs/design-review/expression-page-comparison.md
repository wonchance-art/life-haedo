## 바로 비교하기

[설치 없이 여는 비교 HTML](evidence/expression-page/expression-comparison.html)을 내려받아 브라우저에서 연다. 네트워크 연결이 없어도 A/B 전환·본문 펼치기·보관 원문 열기·코멘트 편집 체험이 동작한다. 실제 앱 로그인·게시에는 연결되지 않는다. 화면 위 **표현 페이지 비교 · 익명 예시**를 열면 빈 상태·로딩·오류도 체험할 수 있다.

개발 소스는 [`expression-sample.html`](../../expression-sample.html)이며 `npm run dev`로 정적 서버를 시작한 뒤 해당 파일을 연다. 배포 사이트의 주소가 아니다. `node scripts/build-expression-preview.mjs`로 같은 자체완결 HTML을 다시 만든다. 기본 결과는 `.local/expression-design/expression-comparison.html`이다.

## 추천: B의 출처 구분과 압축된 앞부분

**B를 실제 내 페이지에 연결할 다음 후보로 권고한다.** 이 제품은 한 편의 글을 읽는 것과 함께 한 사람의 여러 활동·코멘트를 보려는 목적이 있다. B는 한 항목 안의 원문을 얇은 구분선·작은 제목·작성일로 나누며, 더 짧은 앞부분으로 코멘트와 다음 항목에 빨리 닿는다. 전역 프레임·색·한 열 구조는 A와 같다. 새로 만든 시간선·자동 활동 분류나 요약이 아니다.

A는 첫 원문의 문맥을 더 길게 읽을 수 있어 집중 독서에는 유리하다. 다만 두 원문이 연결된 첫 항목에서는 내 코멘트가 다시 아래로 밀렸다. 현재 시안의 B를 완성된 최종 디자인이나 사용자 선호로 확정하지 않는다. 모바일 첫 화면에서는 둘 다 코멘트까지 보이지 않았으며, 실제 앱 상단·편집 조작과 연결했을 때 다시 확인해야 한다. 숫자가 적거나 스크롤이 짧다는 사실만으로 더 좋은 디자인이라고 판정하지 않는다.

| 비교 | A · 글 중심 | B · 활동 구분 |
| --- | --- | --- |
| 본문 | 17px·행간 1.95, 앞 문단을 더 길게 | 16px·행간 1.8, 짧은 앞부분 |
| 출처 구분 | 넓은 문단 간격, 날짜 별도 행 | 원문 사이 얇은 선, 날짜·메타를 압축 |
| 내 코멘트 | 원문 뒤 민트 표면 | 같은 위치·내용, 앞 본문이 짧아 더 일찍 등장 |
| 강점 | 문맥을 충분히 읽기 | 여러 출처와 다음 활동을 구별하기 |
| 한계 | 긴 첫 항목의 읽기 부담 | 문장 중간 접힘이 생겨 전체 펼치기가 필요 |

접힌 부분은 말줄임 표시와 **본문 펼치기**로 명확히 나타낸다. 본문 문자열을 생성 요약하거나 수정하지 않으며 펼치면 정확히 같은 버전의 전체 문자열이 나온다. 접기/펼치기는 전송·공개 포함 범위와 무관하다.

## 같은 자료와 동작

8개 익명 원문·9개 버전·6개 항목을 그대로 공유한다. 첫 두 항목의 고정·수동 순서, 문구·코멘트·날짜는 A/B가 동일하다. 전시 기록의 12문단 **이전 버전**, 다음 날의 부분 캡션, 내 독서 메모와 허구의 타인 책 소개, 100자 제목·8문단 회고, 짧은 두 문장, 본문 미확보 링크와 날짜 미확인 글이 포함된다. 실제 개인 자료나 실제 책의 인용문이 아니다.

- 짧은 글에는 펼치기 조작을 만들지 않는다. 긴 글의 앞부분은 실제 원문의 연속 prefix이며 emoji·CRLF를 보존한다.
- 작성일은 선택 버전의 `originalCreatedAt`만 표시한다. 없는 날짜는 생략하고 가져온 날로 대체하지 않는다. 타인 글·본문 일부·누락 항목·이전 버전은 기본 표시에서 구별한다.
- 보관 원문 보기 → 같은 항목으로 복귀할 때 버전·펼침·초점·스크롤을 유지한다.
- 편집 체험 → 항목의 연필 → 코멘트 입력 → 미리보기 → 편집 복귀가 동작한다. 입력은 비교 화면의 메모리에만 있고 A/B가 공유한다. 새로고침하면 초기 예시로 돌아간다. 원문 fixture는 재귀 동결한다.
- 빈/로딩/오류는 명시적인 **상태 체험**이며 실제 서버 응답으로 꾸미지 않는다. 오류의 다시 보기에서도 시안의 코멘트를 유지한다.

## 비교 측정과 시각 판단

초기 정상 화면에서 문서 위쪽부터의 Y좌표다. 비교용 A/B 조작과 익명 예시 안내도 포함된 **시안의 좌표**이며 실제 앱의 첫 화면 위치가 아니다. 1440·820px은 높이 1,000px, 390px은 높이 844px이다.

| 폭 | 첫 본문 A / B | 첫 코멘트 A / B | 두 번째 항목 A / B |
| --- | --- | --- | --- |
| 1440·820px | 534 / 501px | 1,239 / 891px | 1,417 / 1,064px |
| 390px | 557 / 524px | 1,129 / 994px | 1,398 / 1,259px |

넓은 폭의 B에서 첫 코멘트 시작이 첫 화면에 들어왔으며, 모바일에서는 두 안 모두 첫 화면 밖이다. 실제 이미지를 별도로 보며 한글 문맥·제목 반복·메타의 비중·내 코멘트 구별을 판단했다. 상대적으로 빨라진 코멘트 도달과 출처별 구분이 B 권고의 근거다. 사용자 실험·선호 점수·장기 사용의 근거는 아니다.

## 보존·검증과 적용 경계

운영 앱의 HTML·JavaScript·CSS·서비스워커·SQL은 변경하지 않았다. 같은 공개 설정으로 만든 산출물 **70개 파일의 경로와 SHA-256이 PR #40의 산출물과 모두 동일**하며, 비교 화면·시안 전용 자산은 공개 산출물에서 제외된다. 기능을 보존했다는 근거는 이 산출물 대조이고, 시안의 기능 검사로 운영 로그인·동기화까지 재검증했다고 주장하지 않는다.

새 라이브러리를 도입하지 않고 실제 앱의 공통 토큰·버튼·입력·승인 아이콘을 재사용했다. [공식 참고와 선택 이유](expression-references.md)에 확인한 자료와 확인하지 않은 제품을 구분했다. CSS 말줄임으로 전체 글을 접근 불가능하게 하지 않고 실제 원문 전체를 열 수 있다.

정적 검사와 독립 전체 흐름 6/6(초기 42캡처)이 통과했다. 수동 시각 검토에서 긴 본문을 펼친 뒤 조작 버튼의 초점이 화면 밖에 남는 문제를 추가로 확인했다. 펼침은 읽기 영역으로 초점을 옮기고 접힘은 버튼으로 복원하도록 보완했으며, 잘린 앞부분에는 시각적 말줄임 표시를 추가했다. 원문 DOM 문자열은 바꾸지 않았다. 최종 관련 흐름 A/B×3폭 6/6(18캡처)을 재검증했다. [전체 보고](evidence/expression-page/browser-report.json)와 [보완 검사](evidence/expression-page/browser-expansion-recheck-report.json)에 실행 시점과 범위를 분리했다. 저장소·외부 요청·console/pageerror·시각 검사 위반 0, 최소 글자 대비 5.661:1이었다. 원문·구절·코멘트 메모리 초기화와 날짜를 확인했다. 실제 Mac/iPad/iPhone·IME·VoiceOver는 미검증이다. 운영 저장·백업·공개 선택의 동작은 이 독립 시안에 구현하지 않았으며 가짜 성공 버튼도 만들지 않았다.
