# 판본 선택에서 컬렉션 보관까지

2026-10-14 KST. `codex/edition-collection-flow`, #77 후속. 병합·배포·운영 SQL은 Local 담당이다.

## 이번 결과

내 페이지 글쓰기 → 책 이름 검색 → 작품의 판본 찾기 → 언어·출판사·발행일 대조 → 첨부 정보 확인 → 비공개 저장 → 첨부의 책갈피 버튼으로 컬렉션 보관을 연결했다. 새 컬렉션을 선등록하거나 글 본문을 개인 메모로 자동 복사하지 않는다.

[이름 검색의 공식 출처/라이선스 검토](../life-tools-design/open-source-review.md#이름으로-책프로젝트-찾기--2026-10-13)를 재사용하며 새 SDK·저장 구조·SQL은 없다. 추가한 Open Library 판본 API는 [공식 Books 문서](https://openlibrary.org/dev/docs/api/books)의 `/works/{id}/editions.json`이다. 실제 HTTP와 브라우저에서 익명 공개 자료를 확인했다. [영화·작품·인물 제공자 비교](taste-provider-expansion.md)는 별도 후속 설계이며 이번 연결 완료 범위에 포함하지 않는다.

## 설계·보존 계약

- 작품 후보의 `판본 찾기`를 눌렀을 때만 요청. 고정 Open Library endpoint, 6개씩 명시 pagination, 응답의 `works`에 선택한 작품이 있어야 후보로 사용한다. 외부 `next` URL을 따라가지 않는다.
- 판본 ID의 출처 URL을 그대로 저장한다. 제목만으로 번역/판본을 추정하지 않는다. 판본 저자 이름은 응답에서 확보하지 못하므로 빈 값으로 두고 작품 저자를 **참고 정보**로만 표시한다. 사용자가 저자·번역자를 확인해 수정한다.
- 언어/출판사/발행일 미상이면 미상으로 표시한다. 한 번에 6개, offset 최대 600의 제한된 탐색이며 전체 판본 목록 확보라고 주장하지 않는다. 추가 검색이나 직접 출처 입력도 유지한다.
- 기존 64KiB JSON/10초/credentials omit/no-referrer/redirect error와 취소 신호 재사용. 작품 검색 직후 판본 클릭은 제공자 간격 1.1초 중 남은 시간만 기다린다. 응답 실패를 자동 재시도하지 않는다. 대기 중 닫기/화면 이동도 취소한다.
- 표지/영상은 기존 명시적 표시 조작을 사용한다. 판본 정보 조회만으로 이미지·임베드 요청을 보내지 않는다. 알려진 판본의 출처 주소는 기존 표지 기능과 호환되며 표지 존재를 보장하지 않는다.
- 저장된 내 글의 첨부에만 `컬렉션에 보관` 버튼을 둔다. 방문자 미리보기/공개 렌더러/작성 중 첨부에는 쓰기 버튼이 없다.
- 종류·제목·저자·URL만 새 컬렉션 항목으로 복사하고 note/tags/details는 비운다. 글 본문·기존 개인 메모·원문·발췌·공개 상태를 복사/변경하지 않는다.
- 동일 종류의 **정확히 같은 URL**이 있으면 기존 항목을 그대로 유지한다. URL이 없을 때만 종류·제목·저자의 정확 일치를 사용한다. 다른 판본/다른 URL을 이름으로 자동 병합하지 않는다. URL 표기 차이의 완전 중복 판정은 후속이며 자동 정규화로 다른 자료를 합치지 않는다.
- 기존 항목이 보관 상태여도 새 사본을 만들거나 보관 해제하지 않고 알려 준다. 컬렉션 목록에서 사용자가 관리한다.
- 클릭할 때 최신 컬렉션을 읽고 기존 `saveCollection` CAS로 저장한다. 충돌은 덮어쓰지 않고 재클릭 시 최신 자료와 중복을 다시 확인한다. 계정/화면이 바뀐 늦은 조회는 새 저장으로 이어지지 않는다. 쓰기 도중 이미 완료된 이전 계정의 원자 저장은 취소 완료라고 표시하지 않는다.

## 실제 체험 경로

이 브랜치에서 `npm run dev`, 공용 인증이 설정된 앱의 `index.html?section=records&view=page`를 연다.

1. 글을 작성하고 대상 붙이기 → 책 이름 → `책 찾기 · Open Library`.
2. 후보의 `판본 찾기` → 언어·출판사·발행일 확인. 필요하면 다음/이전 판본으로 이동한다. 못 찾거나 실패해도 작품 정보 선택·직접 입력이 남는다.
3. 원하는 판본을 선택해 출처와 저자를 확인하고 첨부한 뒤 글을 비공개로 저장한다.
4. 저장된 첨부의 책갈피 버튼으로 컬렉션에 보관한다. 재클릭해도 동일 항목의 개인 메모를 덮어쓰지 않는다.
5. 기록 → 컬렉션에서 항목을 확인·메모하고 컬렉션 전용 백업으로 받는다. 페이지 저장/구성 동기화와 컬렉션 전용 보관·백업은 별도다.

## 검증과 증거

- Node **446/446**, 정적 HTML 18/JS 72/참조 320/PWA.
- 새 브라우저 흐름 4개: 판본 pagination/선택/원출처, 명시 보관·중복/보관함·백업, 저장 실패·실제 두 트랜잭션 CAS 충돌·재시도, 판본 빈/오류/대기/늦은 응답.
- 기존 이름 검색/작성 흐름 4개, 글쓰기 13개와 피드 미디어 검사 통과. 원문·공개 경계·계정별 저장·초안/백업 복구 회귀와 이미지의 명시적 요청을 유지한다.
- 1440/820/390px의 판본 선택/보관 결과 + 좁은 저장 충돌/빈/오류/대기 총 **10개 상태**. 가로 넘침/작은 조작/작은 입력/접근 이름/대비 실패 없음. 기능 검사와 별도로 캡처를 직접 읽어 긴 제목·언어·출판사 구분을 검토했다.
- PWA/계정 통합 9개: **v101 → v102** 갱신·기존 로컬 자료 보존. 의도한 전송/콜백 오류 3개를 별도 구분한다.
- 실제 Linux Chromium에서 `채식주의자` 작품 `/works/OL17334243W` → 연결된 판본 6개·추가 판본을 확인했다. 한글 검색/모든 판본의 완전성은 증명하지 않는다.
- 새 흐름 pageerror 0, console 오류는 의도한 429 응답. 모의 Auth/익명 한글 자료·실제 IndexedDB이며 실제 개인 자료/Google 로그인/Apple 기기는 미검증이다.
