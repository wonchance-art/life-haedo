## 목표와 이번 범위

한 기기에서 쓴 글을 다른 기기에서 받아 수정하고 돌아와도 원본과 공개 범위를 지킨다. 저장과 파일 보관의 차이를 사용 중인 조작 가까이에서 이해하고, 이미 만든 9칸의 선택 영역을 파일 재첨부 없이 새 비공개 글 초안으로 활용한다.

| 묶음 | 시작과 결과 | 완료 기준 |
| --- | --- | --- |
| A→B→A 글 이어쓰기 | A가 명시 보관한 글을 B가 새 사본으로 받고 수정·보관한 뒤 A가 다시 받는다 | 본문·사진 설명/대체 텍스트·원본 해시/실제 픽셀과 정확 서버 revision을 대조한다. 두 기기의 기존 글·미전송 초안은 그대로 보존하며 수신 오류를 성공으로 표시하지 않는다 |
| 충돌·공개 범위·재시도 | 같은 글을 양쪽에서 바꾸거나 전송/게시 응답이 유실된 뒤 다시 시도한다 | 원격 CAS와 영속 작업 영수증을 유지한다. 충돌 선택 전후 양쪽 내용을 재열 수 있고 같은 전송/게시 작업의 재시도가 서버 글·원본을 중복 생성하지 않는다. 전체 원본 비공개 보관과 선택 사진 공개는 별도 동의다 |
| 저장·파일 안내 | 글 저장, 원본 내려받기, 사진 ZIP/HTML, 근거 포함 ZIP과 원본 파트 파일을 고른다 | 저장=현재 계정의 이 브라우저, 서버 보관=명시한 한 글, 공개=별도 확정을 구분한다. 생성 파일과 복원 메뉴·포함/제외 범위·실패 재시도 방법이 일치한다. 다운로드 요청을 파일 앱 보관 완료라고 표시하지 않는다 |
| 9칸→새 글 초안 | 저장된 9칸에서 한 영역을 고르고 글로 작성한다 | 기존 1800×2100 PNG와 제한된 항목 정보만 재사용해 새 비공개 사진/리치 글 초안을 연다. 설명·출처 문자열은 편집 가능하고 원래 9칸과 기존 글은 불변이다. 생성/저장 실패·계정 변경 때 잘못된 공간에 부분 저장하거나 입력을 잃지 않는다 |

명시적인 ‘새 사본 받기’는 새 로컬 ID를 만드는 기존 계약이다. 이를 같은 ID 덮어쓰기나 모든 수신 글의 자동 병합으로 바꾸지 않는다. 수신 사진의 새 ID와 기존 서버 manifest가 다르면 기존 검증·업로드·CAS로 정렬하며, 바이트가 같은 다른 사진 ID를 임의로 합치지 않는다.

## 직접 확인할 흐름과 복구

내 페이지 → 9칸 구성 → 영역 선택 → **선택 영역으로 글쓰기 검토**에서 PNG와 본문 전체를 읽고 **새 비공개 글 초안 만들기**를 누른다. 새 초안에서 본문·설명·대체 텍스트를 편집하고 저장할 수 있으며 9칸으로 돌아와도 원래 구성은 유지된다. 기존 PNG·JSON·HTML 파일 받기는 별도 메뉴 그대로다.

- 이미지 생성·초안 저장이 실패하면 원래 구성을 유지하고 같은 화면에서 다시 시도한다. 실제 저장 트랜잭션이 중단되면 문서나 목록만 부분 설치하지 않는다.
- 검토 후 다른 탭에서 9칸을 바꾸면 이전 후보를 거절한다. **9칸 다시 불러오기**로 최신 저장본을 읽은 뒤 내용을 새로 검토한다. 미반영 입력·한글 조합과 저장 실패가 있으면 그 입력을 먼저 해결하도록 막으며, 조회 실패 때 현재 입력을 교체하지 않는다.
- 초안 저장은 성공하고 열기만 실패하면 **보관된 초안 열기**로 같은 글을 재시도한다. 다시 저장해 중복 초안을 만들지 않는다. 다시 열 때 현재 revision을 읽고, 저장 글 재수정으로 ID가 교체된 경우에도 같은 계정·작업공간의 현재 글을 찾는다. 이 세션의 재열기 정보를 기기 동기화나 영속 작업 영수증이라고 부르지 않는다.
- 서버 충돌은 글 관리의 **서버와 변경 확인**으로 최신 비교를 읽고 양쪽 보존 방식을 고른다. 비교 후 상태가 바뀌면 그 선택을 거절하고 다시 확인한다. 전송 재시도는 기존 영속 작업을 사용하며, 공개 갱신·철회는 별도로 검토한다.

## 보존·공개 경계

- 브라우저 저장, 글별 비공개 서버 보관, 공개본은 각각 다른 결과다. 연결하지 않은 글·초안·컬렉션·9칸 전체를 자동 전송하지 않는다. 이메일 문자열로 계정 소유권을 추정하지 않는다.
- 공개 사진 기본 선택은 0개다. 사진 원본의 EXIF/GPS 포함 가능성을 별도 안내하고 선택하지 않은 사진·개인 메모·원문 전체 본문·구조화 인용 sidecar를 공개하지 않는다. 이미 게시된 글은 명시 갱신·철회 경로를 따른다.
- 사진 글 ZIP은 해당 글의 복원용, HTML은 읽기용이다. 근거 포함 ZIP은 선택 글/사진/9칸과 필요한 정확 원문 버전 전체 본문을 담는 별도 비공개 파일이다. 원본 첨부 파트 ZIP은 별도 보관함의 전용 형식이며 글에 자동 삽입하지 않는다. 기존 형식과 복원 경로를 합치지 않는다.
- 새 9칸 초안의 PNG는 보기용 사본이며 복원 파일이 아니다. 구성/영역 제목과 항목 제목·만든 사람·종류·출처를 사용하고 긴 그림 글자는 기존 출력 규칙대로 줄인다. 편집 가능한 본문은 원래 문자열을 유지한다. 소개·영역 메모·선택 이유·인용 구절/정확 원문 근거는 자동 포함하지 않는다.
- 9칸의 이미지 생성은 외부 표지나 사진을 새로 조회하지 않는다. 새 초안 생성만으로 서버 연결·공개·원래 9칸 수정이 시작되지 않는다. 이후 글을 저장하거나 공개할 때 기존 검토를 그대로 거친다.
- 원문 정확 버전·UTF-16 구절·기존 인용 sidecar의 로컬 보존 범위를 바꾸지 않는다. sidecar의 기기 이동은 기존 근거 전용 ZIP을 사용하며 글별 서버 보관에 새로 끼워 넣지 않는다.

## 구현 선택과 반대 검토

기존 `blog-sync`/`blog-remote`·CAS·영수증, `PhotoPost`·기존 작성기, `NineBoard.imageContent()`/`png()`·Canvas와 기존 저장 어댑터를 재사용한다. 새 SQL·서버·라이브러리·일반 ZIP 엔진·외부 이미지 수집을 추가하지 않는다. 기존 [9칸 PNG 선택 근거](nine-board-image.md#구현-선택)와 [블로그 보관·공개 계약](../life-tools-design/blog-completion.md)을 따른다. 직접 재첨부보다 한 번의 명시 조작으로 초안을 여는 부분만 연결한다.

| 확인할 가정 | 더 단순한 대안과 실패 복구 | 담당·최소 확인 |
| --- | --- | --- |
| 지금 동기화 엔진으로 왕복을 완결할 수 있다 | 정상 경로가 이미 맞으면 로직을 늘리지 않고 누락된 실제 회귀만 고정한다. 실제 결함이 있으면 재현된 ID/revision/영수증 경계만 수정한다 | 동기화 담당·독립 SQL 검수: A→B→A와 충돌/유실 응답 |

기능 보존, 실제 사용 흐름, 화면·문구 품질을 따로 판단한다. 1440·820·390px의 같은 합성 한글 자료를 비교하되 시험 수나 캡처 수를 사용자 만족의 증거로 삼지 않는다. 기존 9칸 출력·Obsidian 선택 갱신·원본 첨부 파트 선택은 이미 구현된 기능이므로 다시 만들지 않는다.
