# 가져오기·내 발췌·주제 모음 정리

2026-10-04 KST · 로컬 구현·검증 완료. [검색·긴 원문 통합](integration.md)에 이어 자료를 받는 방법과 보관한 발췌를 읽고 거르는 화면을 같은 본문 중심 기준으로 정리했다. 이번 디자인 변경은 공개 배포 전이며 실제 Apple 기기 검증과 구분한다.

## 이번 범위

| 화면 | 개선할 흐름 | 보존할 경계 |
| --- | --- | --- |
| 가져오기 | 본문·파일·링크의 입력 방법 구분, 원문 검토와 입력 수정, 여러 파일 진행 상태 | 전환 중 초안 보존, 확정 전 자동 업로드 없음, 링크만 제공하면 본문 미확보 |
| 내 발췌 | 원문 인용과 내 메모 구분, 각 출처의 원문 버전 표시, 제거 행동 접기 | 정확한 원문 참조·다중 출처·목록 복귀 유지, 발췌 제거로 원문을 지우지 않음 |
| 주제 모음 | 주제별 개수, 미분류 선택, 조건 해제, 빈 결과에서 돌아가기 | 필터가 기록이나 주제 문자열을 변경하지 않음, 검색 조건과 복귀 상태 유지 |

공통 CSS와 시각 판단은 디자인 책임자 **root**가 통합한다. 여섯 담당은 제품 UI 구현, 신규 UX 회귀, 기존 기능 회귀, 정적 자원 구성, 시각 검토, 문서·독립 검토를 나누어 진행한다. 입력·발췌·주제마다 다른 프레임이나 아이콘 체계를 만들지 않는다.

## 재사용과 더 단순한 대안

기존 HTML 입력, 네이티브 `details`/`summary`, CSS와 일반 DOM으로 처리한다. A 인용 아이콘과 [Lucide 1.51.0](../../vendor/lucide/README.md), `HaedoLife.Icons.create()`도 그대로 재사용한다. 새 드롭다운·폼·탭 라이브러리나 프레임워크가 필요한 상호작용이 아니므로 런타임 의존성을 추가하지 않는다. [기존 공식 출처·라이선스 비교](references.md)를 재사용하며 이번 작은 구성 변경 때문에 전체 오픈소스 후보 조사를 반복하지 않는다.

입력 방법을 별도 페이지나 새 저장 단계로 분리하는 대신 같은 초안의 표시와 안내를 나누는 것이 단순하다. 내 메모와 인용은 이미 분리된 필드를 시각적으로 구분하면 되고, 접힌 제거 도구도 기존 삭제 확인·저장 경로를 사용한다. 주제는 새 분류 모델을 만들지 않고 기존 문자열과 빈 주제를 거른다.

## 반대 관점과 보존 검사

- 입력 방법 전환으로 숨은 본문·출처·발췌 초안이 지워지거나, URL만으로 외부 본문을 확보한 것처럼 표시되지 않는지 확인한다.
- 검토 뒤 입력을 수정하면 이전 확인 결과를 그대로 적용하지 않는다. 본문이 바뀌어 구절 좌표가 무효가 되면 기존 구절·메모를 확인하고 다시 선택할 수 있어야 한다.
- 미분류는 **주제 없음**으로 표시하고 전체 주제와 구분한다. 사용자가 실제로 `주제 없음`이나 `모든 주제`라고 이름 붙인 항목은 **주제 이름: …**으로 표시한다. 개수는 현재 자료 검색에 일치한 발췌를 세며 주제 이름 찾기는 필터 목록을 좁힌다.
- 한 발췌에 여러 원문이 있으면 각 참조의 자료·버전·raw UTF-16 위치를 그대로 연다. 같은 제목이라도 다른 버전을 최신판으로 바꾸지 않는다.
- 제거는 접힌 도구에서 실행해도 확인 취소가 가능하며, 성공했을 때 발췌와 연결만 제거하고 원문은 보존한다.
- 여러 파일의 읽기 실패·건너뜀·보관 완료는 구분한다. 파일을 읽었거나 초안으로 보관한 상태를 원문 확정으로 안내하지 않는다.

저장 형식·계정 경계·동기화·백업·원문 좌표 계약은 그대로다. SQL 재설정·실제 Auth 관리자 작업·AI 기능 확대는 이번 범위에 넣지 않는다.

## 직접 확인하기

저장소를 실행할 수 있는 컴퓨터에서 `npm run dev` 후 `http://127.0.0.1:4173/life.html`을 연다. 개인 화면의 기존 인증 설정이 필요하며 Cloud localhost를 외부 미리보기 링크로 제공하지 않는다. 익명 자료를 사용하고 공개 사이트의 개인 기록을 옮기지 않는다.

1. **가져오기**에서 **본문 붙여넣기 / 텍스트 파일 / 링크 보관**을 바꾸어도 제공한 내용·출처·발췌 후보가 유지되는지 확인한다. 기존 본문이 있는 상태에서 링크 보관을 고르면 본문도 함께 보관된다는 안내를 확인한다.
2. **원문·출처 확인**에서 실제 제공 범위를 읽고, **입력 수정**으로 돌아가 내용을 바꾼 뒤 다시 검토한다. 검토만으로 확정되지는 않는다.
3. 자료를 보관하고 필요한 구절·주제·내 메모를 모은다. 모아보기에서 인용·메모와 각 출처의 버전을 대조하고 **원문에서 보기**로 정확한 위치를 연다.
4. **검색 필터**에서 **주제 없음**과 이름이 있는 주제를 각각 선택한다. **필터 해제**는 자료 검색어를 남기고 주제 조건을 지우며, 빈 결과의 **검색·필터 초기화**는 검색어까지 지운다. 주제가 많으면 **주제 이름 찾기**로 필터 목록을 좁힌다.
5. **발췌 관리**를 펼쳐 제거를 취소해 본다. 제거를 확정하면 발췌만 사라지고 원문은 원천 기록에 남아야 한다.
6. **텍스트 파일 → 여러 텍스트 파일 가져오기**에서 두 파일을 제공한다. **다음 파일 검토**로 하나씩 확인하고, 진행 막대는 자료로 확정한 개수만 나타내는지 본다. 검토 초안·건너뜀·실패·미읽음은 별도로 표시된다.

| 구분 | 이번 결과 |

기존 흐름은 `node tests/life-browser.cjs`(23), `tests/life-sync-browser.cjs`(14), `tests/life-batch-browser.cjs`(8), `tests/life-search-browser.cjs`(7), 새 흐름은 `node tests/life-collections-browser.cjs`(6)로 확인했다. 격리 Linux Chromium에서 실제 앱·동봉 SDK·IndexedDB와 모의 Auth를 사용했다. 예기치 않은 console/pageerror는 없었다. 신규 UX 6개 검사에서는 예상 밖 외부 요청과 모의 서버 쓰기도 0건이었다. 실제 Supabase에는 접근하지 않았다. 기존 실패 회귀의 의도한 오프라인 Auth 1건·전송/스키마 오류 9건은 예상 밖 오류와 구분했다.

입력 방법 전환 후 본문 보존, 링크만 보관한 자료의 미확보 표시, 입력 수정 후 발췌 후보·메모 보존과 본문 변경 시 좌표 재선택, 동명 주제와 미분류 구분, 빈 결과 복구, 각 과거 원문 이동, 제거 취소와 제거 후 원문 4개 버전 보존을 확인했다. 검색·복귀·동기화·백업·충돌/공간 부족·계정 전환의 기존 회귀도 유지했다.

`node scripts/check-life-collections-design.cjs`의 기본 배치는 Linux Chromium 151.0.7922.173에서 1440×1000·820×1000·390×844px를 검사했다. 최소 텍스트 대비 5.57:1, 가로 넘침·예기치 않은 console/pageerror·외부 요청·실제/모의 원격 쓰기 0건이었다. 대표 10장을 직접 검토하고 출처 행의 왼쪽 정렬과 메모·검토 원문의 한글 단어 줄바꿈을 보완했다.

기본 배치 뒤, 하단 탐색이 키보드 초점 테두리를 가리지 않는지 390px에서 별도로 강화했다. 실제 Tab → 발췌 관리 summary → Enter 경로에서 초점 테두리 전체와 하단 메뉴 사이 8.578125px 여유를 확인했고 console/pageerror는 0건이었다. 이 마지막 보정 후 기본 211개 전체를 다시 실행한 것은 아니다. 영구 감사의 초점 검사도 테두리 바깥 8px와 실제 Tab을 확인하도록 강화했다.

독립 검토에서 방식 전환의 숨은 본문, 미분류와 동명 주제, 정확한 과거 원문 참조, 필터 해제·파일 선택 후 초점 복귀를 확인했다. 내 생각은 색 차이만으로 구분하지 않고 **내 메모**라고 명시했다. 최종 코드 검토에서 보존 계약을 막는 미해결 결함은 없었다.

플랫폼 10개는 공통 8개와 실제 이전 산출물의 SW v54→v55, 공개 main과 같은 셸의 v53→v55 업데이트 2개다. 원문·검토 초안·기존 저장 자료 보존을 확인했으며 예상 밖 console/pageerror 0건, 의도한 callback/전송 실패 1건이었다. 이전 셸은 원본 git 커밋에서 만들고 파일 해시를 대조했으며 버전 문자열만 바꾼 모사가 아니다. 플랫폼 10개는 마지막 모바일 초점 가림 방지 보정 직전에 실행했다. 이후 UI/CSS의 초점 위치 보정은 시각 담당이 확인했고 플랫폼 전체 검사는 반복하지 않았다. 최종 v55 산출물을 다시 만들고 정적 검사와 현재 소스의 운영 셸·서비스워커 37개 파일 해시 37/37 일치를 확인했다. 공개 산출물에 시안·내부 경로는 포함되지 않는다.

앞선 검색·원문 통합의 Node 182·브라우저 61·시각 201 결과는 [이전 증거](integration.md)로 보존한다. 전체 Node 182는 이번에 다시 실행하지 않았다. 브라우저 크기·터치 설정·한글 조합 이벤트 모사는 실제 Apple 기기·IME·Files·VoiceOver 확인을 뜻하지 않는다.
