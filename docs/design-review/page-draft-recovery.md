# 내 페이지 초안 선택 복구

2026-10-14 KST. PR #83 위 후속. 초안 구분 → 파일 내용·중복 검토 → 선택 복원 → 다시 열기를 한 사용 흐름으로 묶었다. 병합·배포는 Local 담당이다.

## 목표·범위·보존

파일을 고르는 즉시 초안 전부를 추가하던 흐름을 명시 선택으로 바꾼다. 이전 구현은 `state.posts`를 먼저 수정하고 저장을 시도해, 실패 뒤에도 가져온 사본이 메모리에 남았다. 같은 파일 재선택이 중복 사본으로 이어질 수 있었다.

| 이번 묶음 | 동작·보존 조건 |
| --- | --- |
| 초안 구분 | 실제 수정일 내림차순. 새 글/수정 초안/현재 공간에 원래 글이 없는 수정 초안, 연도를 포함한 한국 시간 날짜, 첨부 개수 표시. 목록 재개 후 본문 초점 |
| 파일 선택 검토 | 기존 v1 파일을 엄격 검증. 본문·첨부·원래 URL 문자열과 공개 후보→비공개 변경을 펼쳐 확인. 검토 자체는 초안을 추가하지 않음 |
| 중복 표시 | 본문과 첨부 네 필드·순서의 **완전 일치**만 표시. ID·날짜·공개 범위는 비교에서 제외. 같은 내용은 기본 미선택이며 원하는 사본은 직접 선택 가능 |
| 안전한 복원 | 저장 직전 최신 로컬 초안을 읽고 새 ID·비공개·수정 연결 없는 사본만 추가. CAS/기존 원자 저장 성공 뒤에만 화면 상태 교체. 기존 글·초안·원문·컬렉션·공개 사본 보존 |
| 실패·경합 | 저장 실패/두 탭 CAS 경합 때 초안과 파일 선택 유지. 다시 읽은 최신 초안에 추가하며 다른 탭 내용을 덮지 않음. 검토 뒤 새로 생긴 중복은 추가 저장 전에 재확인 안내 |
| 취소·늦은 응답 | Escape/닫기는 본문 DOM·커서를 보존. 파일 읽기 후 계정/공간/화면 수명과 선택 요청 순서를 확인해 이전 응답이 검토를 다시 열거나 새 파일을 교체하지 않음 |

`life-page-drafts-v1` 파일과 `page-drafts:{workspaceId}`의 revision/posts 구조는 유지한다. 내용·출처·원래 날짜는 정확히 보존하며 공개 후보도 가져온 새 초안은 비공개다. 수정 대상 연결을 끊으므로 다른 공간의 같은 ID를 덮지 않는다. 200개와 합산 2 MiB 한도는 기존 저장 계층에서 검사한다. 파일 자체 2 MiB, UTF-8 오류, saved 항목·알 수 없는 필드도 거부한다.

## 설계 판단과 반대 검토

- 기존 PagePosts 검증·PagePostsView 평문 렌더·네이티브 dialog/선택창 스타일·계정별 idb 트랜잭션과 CAS를 재사용한다. 새 모듈·라이브러리·SQL·저장 스키마를 만들지 않았다. [오픈소스 재사용 검토](../life-tools-design/open-source-review.md)의 기존 저장 계층 판단을 따른다.
- 자동 중복 삭제는 같은 내용을 의도적으로 다른 글로 이어 쓰는 경우를 막는다. 따라서 표시와 기본 선택만 조절하며 선택한 사본은 보존한다. 공백·URL·첨부 순서를 정규화하지 않는다.
- 복원은 기존 내용을 수정하지 않는 추가 작업이므로 최신 보관함과 합치는 경로를 사용한다. 읽기와 저장 사이 경합은 CAS로 거절한다. 검토 이후 새 중복이 생긴 경우 선택을 바꾸지 않고 다시 확인하게 한다.
- 파일 검토는 본문 편집과 명시 저장을 분리하기 위해 모달을 사용한다. 배경 입력은 유지하고 검토 도중 편집되지 않는다. 저장 중에만 닫기/선택을 잠그며 실패하면 조작·초점을 복구한다. 상태 코드/저장 구현을 제품 설명에 노출하지 않는다.
- 원본 파일의 내용은 파일을 선택했을 때만 읽는다. 이미지·외부 정보를 자동 요청하지 않는다. 출처 링크는 안전한 HTTP(S)·새 탭·referrer 차단으로 기존 계약을 재사용한다.

## 체험

`npm run dev` 후 `http://127.0.0.1:4173/index.html?section=records&view=page`에서 자기 계정으로 내 페이지를 연다. 합성 계정의 자동 체험은 `node tests/page-draft-recovery-browser.cjs`다.

1. 초안이 여러 개면 `초안`을 펼쳐 새 글/수정·날짜·첨부 수로 구분하고 이어 쓴다.
2. `초안 파일 → 초안 파일 받기`로 파일을 받은 뒤 같은 파일을 불러온다.
3. 같은 내용은 표시되고 기본 미선택이다. `본문·첨부 확인`에서 전체 본문·작가·원래 링크·비공개 전환을 확인한다.
4. 필요한 것만 선택해 `선택한 초안 불러오기`. 비공개 새 초안이 열리고 기존 초안·저장한 글은 남는다. 글 `저장`은 별도 행동이다.
5. 실패하면 같은 검토 화면에서 재시도하거나 취소할 수 있다. 다른 작업공간에서 선택 복원해도 원래 공간의 초안은 유지된다.

작성 초안은 계속 이 브라우저 전용이다. 파일 다운로드 요청을 실제 Files 보관 완료로 표시하지 않는다. 미반영 첨부 폼의 강제 종료 후 복구는 [앞선 첨부 입력 보호](attachment-edit-preservation.md)의 한계 그대로이며 이번 복구 파일에 넣지 않는다.
