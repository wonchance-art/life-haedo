# 블로그 플랫폼 형태의 메인

2026-10-17. 문구·정보설계 검토. 디자인·통합 책임은 주 작업 에이전트다.

## 판단

블로그 형태는 적합하다. 사용자가 메인에서 이해해야 할 대상이 `여러 생활 도구`에서 `내가 쓰고 읽는 글`로 분명해진다. 기존 제품의 직접 글쓰기, 사진·대상 첨부, 내 페이지, 선택 공개와도 이어진다. 가져오기·발췌·회고·컬렉션은 글을 쓰거나 다시 읽는 데 사용하는 비공개 자료실로 배치한다.

이번 범위는 **개인 블로그 + 비공개 자료실 + 선택한 사본의 공개**다. 블로그 포털, 다른 작성자 발견·구독·추천 피드, 여러 작성자의 공동 발행을 제공한다는 뜻으로 넓히지 않는다. 로그인 전에는 서비스 설명, 로그인 뒤에는 내 글과 글쓰기, 공개 주소에서는 게시한 사본을 읽는 서로 다른 목적을 갖는다.

가장 큰 반대 근거는 현재 기본 작성기의 신형 글이다. 사진 유무와 관계없이 이 형식은 이 브라우저에 보관되며 일반 JSON 백업·기기 간 동기화·공개 사본에 포함되지 않는다. 따라서 메인 이름을 바꾸는 것만으로 공개 블로그의 완성을 주장할 수 없다. 현재 범위의 **비공개 글쓰기와 재열기**를 먼저 완결하고, 지원되는 공개 사본의 경로를 구분한다. 이후 주 글쓰기 형식의 공개·기기 간 보관은 별도 구현 단위다.

## 첫 화면의 최소 위계

1. 제목: **내 블로그**. 개인이 설정한 블로그 제목이 있으면 그 실제 값을 사용하고 기본 제목을 반복하지 않는다.
2. 한 줄 설명: **생각과 일상을 글로 남기는 내 공간입니다.**
3. 주 행동: **글쓰기**. 기존 기본 작성기를 연다.
4. 실제 콘텐츠: **최근 글**. 저장한 글의 제목·본문 일부·실제 저장 상태를 보인다. 없는 사진·대표 글·작성일을 만들지 않는다. 여러 형식에서 골라 보여주는 최근 목록이므로 지원 범위가 다른 화면을 `전체 보기`로 연결하지 않는다.
5. 보조 경로: **자료실과 도구**. 가져온 기록과 메모, 이어 읽기, 기존 묶음·책 등으로 들어간다.

글쓰기와 가져오기를 같은 무게로 놓으면 메인이 다시 수집 도구와 블로그 사이에서 흔들린다. 가져오기는 자료실에서 계속 찾을 수 있게 한다. 소개·통계·기능 카드보다 실제 글이 앞선다. 같은 화면에 `홈 / 내 블로그 / 내 페이지 / 내 글` 제목을 차례로 반복하지 않는다. 전역 탐색의 기존 주소·접근 가능한 이름과 데이터 구조는 구현 계약에 맞춰 보존한다.

글이 없을 때도 블로그 소개·분류·프로필을 먼저 완성하게 하지 않는다. 주 행동 바로 뒤에 짧은 빈 상태 하나를 보이고, 책·묶음·컬렉션의 빈 상태를 메인에 모두 나열하지 않는다. 글이 있는 사용자는 자신이 쓴 글을 읽는 화면이 메인의 대부분을 차지해야 한다.

## 상태별 문구

| 상태 | 제안 문구와 행동 | 근거·주의 |
| --- | --- | --- |
| 로그인 전 제목 | **내 생각과 일상을 쓰는 블로그.** | 블로그라는 대상과 글쓰기 목적을 한 번에 전달한다. |
| 로그인 전 설명 | **글과 사진을 남기고, 다른 곳의 기록과 관심 있는 것을 모아 나만의 이야기를 이어가세요.** | 자료 수집은 글쓰기 뒤의 보조 역할이다. |
| 로그인 전 주 행동 | **내 블로그 시작하기** | 실제 공용 인증 경로와 연결한다. |
| 로그인 전 보관 안내 | **새 글과 사진은 이 브라우저에 비공개로 보관합니다. 기존 기록에서 고른 내용은 별도로 공개할 수 있습니다.** | 로그인이나 저장을 공개로 오해하지 않게 하고 현재 새 글의 공개 제약을 구분한다. |
| 빈 개인 홈 | **첫 글을 써보세요.** / **일상이나 생각을 자유롭게 남겨보세요. 글은 먼저 비공개로 저장됩니다.** / **글쓰기** | 자료 가져오기를 첫 글의 필수 조건으로 만들지 않는다. |
| 재방문 개인 홈 | **최근 글** / 실제 제목과 본문 일부 / **글쓰기** / **글 관리** | 가상 예시를 사용자 글처럼 섞지 않는다. `글 관리`는 기존 내 페이지의 피드·관리로 이동하며 최근 글 전체 조회를 약속하지 않는다. |
| 신형 글 상태 | **비공개 · 이 브라우저에 보관** | `게시됨`·`동기화됨`·`모든 기기에 저장됨`으로 바꾸지 않는다. |
| 초안 복귀 | **쓰던 글** / 실제 제목 또는 **제목 없는 글** / **계속 쓰기** | 현재 브라우저 범위는 짧게 함께 표시한다. 초안이 없으면 행을 생략한다. |
| 비공개 자료실 | **자료실과 도구** / **가져온 기록과 메모** / **자료 가져오기** | 내가 쓴 글과 저장한 타인의 원문을 동일한 블로그 글로 표시하지 않는다. |
| 공개 사본 방문 | 실제 게시 제목·소개 / **글** / 게시한 본문 | 개인 관리·초안·가져오기 상태를 조회하거나 노출하지 않는다. |
| 비공개 미리보기 | **선택한 내용 미리보기** | 자료실 안에 두고 고른 기록·기존 첨부 글의 범위를 설명한다. 신형 글을 포함하는 전체 블로그 미리보기나 공개 주소로 표현하지 않는다. |
| 조회 실패 | **내 글을 불러오지 못했습니다. 다시 시도해 주세요.** / **다시 불러오기** | `아직 글이 없습니다`라는 빈 상태로 바꾸지 않는다. 읽힌 다른 영역은 유지한다. |

개인 홈은 `글쓰기`와 `글 관리`의 두 진입을 먼저 둔다. `선택한 내용 미리보기`는 신형 글을 포함하지 않으므로 상단 주 행동에서 제외하고 자료실에 둔다. 현재 작성기·최근 글·기존 내 페이지 미리보기는 서로 포함 범위가 다르므로 같은 결과를 다른 표현으로 여는 것처럼 설명하지 않는다. 초안·보관함의 세부 관리와 형식별 백업 제약은 해당 작성기·자료실·관리에서 확인할 수 있게 한다.

## 첫 화면에 두지 않을 설명

첫 화면의 제한 안내는 저장·공개를 판단하는 데 필요한 짧은 문장으로 충분하다. JSON payload, Delta, Blob, 버전 번호, CAS, SQL 설치 상태, 파일 형식별 제외 목록을 메인 소개에 넣지 않는다. 대신 해당 저장·공개·백업 행동 가까이에서 실제 지원 범위와 다음 행동을 설명한다. 제한을 상세 도움말로 이동하더라도 `비공개`와 `이 브라우저`라는 의미는 글과 저장 맥락에 남긴다.

## 확인할 사용 장면

- 처음 온 사용자가 로그인 전 화면에서 `글을 쓰는 내 블로그이며, 가져온 자료는 비공개로 보관한다`고 설명할 수 있는가.
- 빈 홈에서 글쓰기를 찾아 한 편을 저장하고, 홈으로 돌아와 제목과 본문 일부로 다시 열 수 있는가.
- 가져온 기록만 있는 사용자가 그 원문을 자신의 블로그 글로 오해하지 않고 자료실에서 찾을 수 있는가.
- 사진이 없는 신형 글도 공개·일반 백업·동기화가 자동 완료됐다고 오해하지 않는가.
- 재방문 첫 화면에서 같은 제목·소개·조작의 반복 없이 실제 글을 읽기 시작할 수 있는가.

이는 사용자 이해도 확인 항목이다. 브라우저 자동화 통과나 첫 본문 위치의 측정만으로 사용자가 목적을 이해했다고 보고하지 않는다.

## 구현 최종 시각 검토

QA 담당이 실제 앱·합성 인증·익명 한글 글로 생성한 `.local/blog-platform/{public,empty,saved,posts-error}-{1440,820,390}.png` 최종 12장을 직접 열어 보았다. `public` 파일은 **로그인 전 안내**이며 실제 공개 블로그 사본 캡처라는 뜻이 아니다. 기능 검사를 이 문서 작성자가 실행한 것으로 합산하지 않는다.

- 로그인 전에는 `내 생각과 일상을 쓰는 블로그.`와 `내 블로그 시작하기`가 먼저 읽힌다. 서비스 대상과 첫 행동이 문구로 분명하다. 주 행동 아래에서 새 글·사진의 브라우저 비공개 보관과 기존 기록의 선택 공개를 구분하며, 상세 사용 예시는 접혀 있다.
- 빈 개인 홈에서는 글쓰기 주 행동과 첫 글의 빈 상태가 보이고 자료실·도구는 아래 접혀 있다. 같은 의미의 글쓰기 버튼이 두 번 있지만 다른 도구의 빈 상태들이 경쟁하지 않는다.
- 저장 후에는 실제 제목·본문 일부가 `최근 글` 아래에 나오며 `비공개 · 이 브라우저에 보관`이 해당 글 가까이 있다. 제목·본문·보관 상태를 통해 글을 다시 고를 수 있다. 사진 글이 공개됐다는 성공 표현은 이 화면에 없다.
- 세 폭에서 한글 제목·설명·버튼의 가로 잘림은 이미지에서 관찰되지 않았다. 가로 넘침·대비·터치 목표·키보드 동작을 수치로 검증한 결과와는 구분한다.
- 개인 홈 H1은 `내 블로그`로 보인다. 첫 검토에서 발견한 `홈`이라는 추상적 제목은 최종 이미지에서 수정됐음을 확인했다.
- 조회 실패에서는 `최근 글` 아래에 `글 목록을 불러오지 못했습니다`와 `다시 불러오기`가 보인다. 실패를 첫 글의 빈 상태로 오해하게 만들지 않으며 상단 글쓰기와 아래 자료실 진입은 남아 있다.

이번 독립 검토는 위 12개 정적 이미지와 관련 문구·코드의 직접 확인이다. 공개 사본·사진이 있는 글·다수 글·접힌 자료실 내부·로딩 화면은 이 이미지 묶음에 없으며, 실제 Google 인증·Mac/iPad/iPhone 실기·사용자 이해도·공개 배포를 확인한 결과도 아니다. 첫 화면의 목적·글쓰기 발견성·저장한 글의 재식별에는 추가 시각 수정이 필요한 막힘을 발견하지 않았다.

## 팀의 기능·보존 검증

- 첫 세션의 Obsidian 보존 후속 `7b78a05`를 통합한 최종 코드에서 HTML 18개·JS 90개·로컬 참조 356개·PWA 셸과 Node 519/519을 통과했다.
- 신규 블로그 흐름 6/6, 기존 홈 16/16, 하위 탐색·초점 복귀 11/11 통과. 가짜 계정의 HTTP 인증과 실제 앱·IndexedDB를 사용했으며 자동 원격 게시·외부 요청은 없었다.
- 기존 사진 글 12/12, 입력·출력 품질 6/6, 이어 읽기 12/12 통과. 사진 원본·ZIP 왕복·입력 실패 복구와 정확 원문 버전 복귀를 유지했다.
- 책 가져오기 7/7, 복원 진입 7/7, 책 완주 검사는 최초 3폭 3개와 수정 후 계정 격리 1개를 나누어 통과했다. 접힌 자료실은 실제 펼침 조작으로 검증하고 기존 기능 주장을 삭제하지 않았다.
- 공개 산출물의 플랫폼·PWA 9/9 통과. 최종 부모의 v118→v119 갱신에서 기존 로컬 자료 보존을 확인했다. 의도한 전송/콜백 실패 3건과 예기치 않은 오류를 구분했다.

늦은 홈 조회가 자료실의 읽던 원문을 159px 밀던 결함은 실제 초점 요소를 기준으로 스크롤 위치만 보정해 수정했다. 새 작성기의 글·사진이 공개 사본에 포함되지 않는 안내 누락과 이전 9칸/공개 관리 화면이 홈 진입을 가로채던 문제도 수정 후 관련 흐름을 재검했다. 화면 크기 검사는 Linux Chromium 모사이며 Apple 실기·실제 OAuth·운영 DB·배포 성공을 뜻하지 않는다. 새 블로그 흐름은 정규 CI에 추가했고 익명 보고서·캡처를 CI 산출물로 보관한다.

첫 세션의 `7b78a05`를 기반으로 블로그 변경을 재배치한 뒤 신규 블로그 6/6·기존 홈 16/16을 통합 코드에서 다시 확인했다. Obsidian 저장·변환 모듈은 선행 커밋 그대로이며 원문이 블로그 글로 자동 분류되지 않음을 독립 검토했다.

통합 코드에서 기존 Obsidian ZIP 검사도 5/5 통과했다. 합성 6,899개 파일의 두 공간 복원·원문 바이트·연결·백업을 확인했다. 공간 전환과 펼침 목록의 실제 DOM 완료를 기다리는 선행 검사를 유지했으며, 복원 앱 코드는 선행 커밋과 동일하다.
