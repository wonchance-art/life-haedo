# SNS 형태의 블로그 경험 재설계

2026-10-17 KST. 디자인·통합 책임: 주 작업 에이전트. 공식 자료 조사와 최종 구현 기록을 위한 문서다.

## 목표와 범위

사용자는 블로그 방향을 유지하면서 기존 화면의 오래된 도구·관리 화면 인상을 없애고, SNS처럼 바로 쓰고 읽는 UX·UI 전체를 요청했다. 이번 방향은 **실제 글·사진을 중심에 두는 개인 블로그 피드**다. 첫 화면에서 내 공간과 글쓰기 진입을 이해하고, 작성·비공개 저장·읽기·수정·홈 복귀를 같은 제품 경험으로 이어간다.

개인 원문·가져온 자료·글·초안·사진·선택한 공개 사본의 저장 경계는 유지한다. 포털·다른 작성자 발견·좋아요·댓글·팔로우·가짜 사회적 지표를 추가하는 요청으로 확대하지 않는다. 신형 글은 사진 유무와 관계없이 이 브라우저에 비공개 보관되며 일반 JSON 백업·기기 간 동기화·공개 사본에 포함되지 않는 현재 제한도 유지한다. 기존에 지원하는 선택 사본의 공개는 별도 흐름이다.

## 선택한 시각 방향

공통 프레임은 흰색·차콜을 중심으로 바꾸고, 콘텐츠 밖 캔버스와 구분선만 옅게 둔다. 검정 바탕·흰 글자의 주 행동, 파란 링크와 초점으로 행동을 구분한다. 기존 한글 산세리프와 SVG 아이콘을 유지하며 색상 유행이나 새 글꼴 도입을 디자인 완성의 기준으로 삼지 않는다.

| 역할 | 방향 계약 |
| --- | --- |
| 본문 / 보조 글자 | `#18181b` / `#66666f` |
| 읽기 표면 / 캔버스 / 구분선 | `#ffffff` / `#f7f7f8` / `#ececee` |
| 주 행동 | 검정 바탕·흰 글자, 짧은 행동 이름, 둥근 버튼 |
| 링크·키보드 초점 | `#3156d3` |
| 중심 콘텐츠 | 실제 글·사진, 약 680–720px의 읽기 열. 정확한 최종 값은 구현 토큰·컴포넌트에 기록 |
| 넓은 화면 탐색 | 라벨이 보이는 왼쪽 탐색, 현재 위치가 분명한 선택 상태 |
| 좁은 화면 탐색 | 화면 가장자리에 이어지는 하단 탐색, 안전 영역·본문 끝 여백 보존 |
| 프로필 표식 | 실제 페이지 제목에서 얻은 이니셜. 사용자 이미지·인물 사진·계정 식별자를 꾸며내지 않음 |

피드는 흰 콘텐츠 면과 가는 구분선으로 이어진다. 기능별 둥근 상자와 소개 카드를 쌓는 구조를 줄이고, 제목·본문 일부·사진·작은 상태 표시가 각 글을 설명한다. 사진 없는 글에서도 제목과 한글 본문으로 리듬이 성립해야 한다. 실제 사진은 원본 해상도·바이트·순서·설명·대체 텍스트를 보존하며, 피드 표시를 위한 미리보기와 원본 저장을 구분한다.

개인 홈·내 글 관리·작성기·읽기 화면은 같은 탐색·활자·행동 색을 사용한다. 글쓰기 중에는 제목·본문·저장·복귀가 먼저 보인다. 읽기에서는 실제 글과 사진이 먼저 나오며 형식별 관리·보관·내보내기와 공개 검토는 필요한 위치에서 연다. 화면을 현대화한다는 이유로 미지원 동작을 가진 조작이나 무의미한 사회적 지표를 만들지 않는다.

## 반대 검토와 적용 원칙

1. **피드 형태가 공개를 뜻하는가.** 아바타·글 목록·작성 버튼은 SNS의 공개 화면을 연상시킬 수 있다. 새 글의 `비공개 · 이 브라우저에 보관`을 실제 글과 저장 맥락에 남기고, 선택 사본 미리보기를 전체 블로그의 공개 완료로 표현하지 않는다.
2. **자료만 많은 사용자도 내 공간을 이해하는가.** 가져온 수천 원문이 직접 작성한 글로 자동 승격되지 않아야 한다. 실제 앱 작성 표식으로 판정하는 기존 내 글 계약을 유지하고, 가져온 자료는 자료실에서 출처와 함께 연다. 개인 보관에서 끝나는 사용도 유효하다.
3. **사진 없는 긴 한글 글도 좋은가.** 사진·짧은 문구만 있는 샘플로 디자인을 평가하지 않는다. 긴 제목과 여러 문단, 링크·첨부·서식이 있는 글에서도 본문 위계·줄바꿈·읽기 폭을 확인한다.
4. **새 프레임이 콘텐츠를 밀어내는가.** 넓은 탐색과 작은 중앙 열이 과한 빈 공간·새 관리 화면을 만들 수 있다. 데스크톱 첫 시야에서 실제 프로필·작성 진입·글이 주체여야 하며, 모바일에서는 중복 설명·조작을 줄인다.
5. **미니멀함이 행동을 숨기는가.** 저장·새 글·복귀·실패 후 재시도는 실제 이름으로 찾을 수 있어야 한다. 보조 조작만 아이콘으로 줄이고 접근 가능한 이름·초점·44px 조작 영역을 유지한다.
6. **모든 상태에서 같은 제품인가.** 로그인 전·빈 홈·저장 후·긴 글·사진 글·조회 실패·저장 실패를 별개 시안처럼 만들지 않는다. 공통 토큰과 컴포넌트를 재사용하고 입력·정확 버전·계정 격리·복구·백업의 기존 기능을 보존한다.

## 실제 구현

흰색·차콜 공통 체계와 라벨 탐색·전체 너비 모바일 탐색을 홈·프로필·작성·읽기·자료실·원문·도구·관리에 연결했다. 개인 홈은 실제 제목·소개·이니셜, 작성 프롬프트·글쓰기, 저장한 글의 제목·본문·첫 사진 미리보기로 이어진다. 프로필 이니셜은 실제 제목의 공백을 뺀 두 글자이고 기본 내 블로그는 `나`다. 작성은 자주 쓰는 서식과 추가 서식을 나누고 비공개 저장을 유지한다. 사진 원본·기존 글·초안·보관함과 관리·공개 사본 기능은 각 기존 저장 범위에 남는다.

최종 구현 값은 [DESIGN.md](../../DESIGN.md)의 YAML frontmatter·정규 8개 절과 [.impeccable/design.json](../../.impeccable/design.json)에 기록했다. 전자는 색·활자·반경·간격·컴포넌트 primitive, 후자는 그림자·모션·반응형·초점·독립 렌더 가능한 컴포넌트 7개의 HTML/CSS와 적용 원칙을 담는다. 실제 CSS에서 추출했고 기존 상세 읽기·쓰기·출처·공개·복원·원고 계약과 이전 링크를 보존했다. 책·회고의 과거 보라색 예외도 현재 공통 토큰으로 갱신했다. Impeccable 문서화 지침은 수동 적용했으며 설치되지 않은 엔진을 실행한 것으로 보고하지 않는다.

### 기능·보존 검사

아래는 QA·통합 담당이 실행하고 보고한 결과다. 문서 담당이 동일 검사를 다시 수행한 것으로 합산하지 않는다.

- 신규 SNS 흐름 **2/2**, 로그인 전·피드·프로필·읽기·작성·자료실·원문·관리·도구의 **9장면 × 1440·820·390px = 27상태**. Chromium **151.0.7922.173**, 실제 로컬 앱·공용 SDK·IndexedDB와 익명 HTTP Auth/공개 RPC 응답을 사용했다.
- QA 보고서에서 콘솔 오류·페이지 오류·예상 밖 외부 요청·품질 위반 **0건**. 일반 조작 44px·입력 16px·작은 글자 대비·가로 넘침·네 탐색 영역의 3개 반응형 배치·최대 720px 콘텐츠 열을 확인했다. 한글 합성 이벤트 검사는 실제 OS 입력기 검증과 구분한다.
- 프로필 소개 편집·저장·홈 반영, 사진 포함 비공개 글의 저장·수정·읽기·홈 복귀, 검색·원문·관리·도구, 실패 복구·계정 전환을 확인했다. 합성 사진 원본 해시와 ZIP 복원 후 해시·1800×1200 해상도를 유지했다.
- 1차 렌더에서 발견한 820px 브랜드 링크 너비 **39.2px**를 최소 44px로 고친 뒤 최종 캡처·품질 검사를 확인했다. 작성 세 폭은 실제 초안 보관 상태가 안정된 뒤 캡처했다.
- 이번 코드에서 기존 홈 **16/16**·이전 블로그 홈 **6/6**을 재실행했다. 통합 담당은 Node **519/519**, 정적 HTML **18개**·JS **90개**·참조 **356개**·PWA 셸, 하위 탐색 **11/11**·원문 읽기 **3/3**·공개 사본 **4/4**을 보고했다.

### 독립 마무리 검토

새 대화 문맥의 독립 검토자는 요청·방향 계약·실제 전후 캡처를 읽고 최초 **`fix` — 국소 수정 1건**을 판정했다. 전체 재설계는 요구하지 않았고 그 밖의 material 항목은 없었다. 발견한 P2는 장문 작성 중 실제 비고정 상단 제목이 사라진 뒤에도 저장바가 60/64px 아래에 남아, 그 위 틈에 본문·서식 조각이 지나가는 문제였다.
