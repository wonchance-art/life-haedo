# 같은 원문 판의 사진을 다른 기기에서 복구

2026-10-27. 기준은 배포 main `ab6aef594a2d6d0cabbaf89864e7994ce22a6fec`(PR139)다. 목표는 **A의 수집 원문·사진 보관 → 계정 원문 동기화 → B의 같은 판에서 사진 가져오기 → 기존 인용·읽던 위치 유지 → 오프라인 읽기와 전용 ZIP 복원**이다. 실제 사용자 기기 체험과 익명 자동 검수를 구분한다.

## 해결할 공백과 선택

계정 자료 동기화는 원문과 불변 버전을 전달하지만 네이버 사진 sidecar는 원래 기기에만 있다. 기존 사진 검증은 원문 identity·본문·형식·확보 범위를 비교하므로 같은 본문에 서로 다른 사진이 있는 두 수집 판을 구분할 수 없다. 본문이나 최신 수집 순서로 과거 사진을 추정하지 않는다.

새 서버 테이블·동기화 도메인 대신 기존 Core 링크에 정확한 사진 판의 참조를 저장한다. `naver_capture_reference` 링크는 sourceVersion 한 개를 가리키며 note에는 format·blogId·logNo·captureHash만 있다. owner·서버 capture ID·Storage 경로·사진 바이트를 포함하지 않는다. 같은 판의 중복·교체·삭제와 그 판의 내용 변경을 거절하고, 백업 복원은 기존 entityRefs 재매핑을 재사용한다. 일부 자료를 투영하는 복구가 참조를 제외하더라도 기존 공간의 참조를 지우지 않는다.

이 참조는 **조회 대상을 고정하는 포인터**다. 파일 사본에 참조가 있다는 사실은 사진 포함이나 서버 보관 완료 증명이 아니다. 현재 계정의 소유권·정확 hash·실제 원문·사진 바이트를 매번 다시 검증한다. 별도 서버 영수증은 기존 저장 형식의 변경을 피할 수 있으나 새 등록 RPC·내구 전송·ACK 순서·복구 도메인이 필요하다. 이번 목표에는 기존 불변 Core·소유자 RLS·사진 검증으로 필요한 경계를 유지할 수 있어 추가하지 않는다. [공식 대안과 재사용](../life-tools-design/open-source-review.md).

불변성은 새 앱의 직접 저장·원격 설치에서 이미 보유한 참조를 보존하는 계약이다. 기존 서버 Core RPC는 전체 JSON CAS이며 링크의 과거 이력을 별도 감사하지 않는다. 구클라이언트나 직접 RPC가 바꾼 유효 포인터를 처음 받는 기기가 그 변경 이력을 알아낸다고 보증하지 않는다. 이 강한 보증이 필요하면 별도 서버 영수증·검증 도메인이 후속 선행 조건이다.

## 저장과 복구

새 수집 원문은 source/version·사진·참조를 같은 IndexedDB 트랜잭션에 보관한다. 기존 계정 자료 CAS가 참조도 함께 전송한다. 기존 원문에 유효한 원격 사진 sidecar만 있는 경우에는 사용자가 `사진 연결 보관`을 선택해 참조를 추가한다. 읽기·부팅·메뉴 이동으로 기존 자료에 쓰지 않는다. sidecar가 없는 과거 원문은 본문이 같더라도 사진 판을 추정하지 않고 기존 수집 사본 검토로 안내한다.

`사진 가져오기`는 저장소의 현재 참조를 다시 읽고 현재 owner·blogId·logNo·captureHash를 모두 제한한 조회만 한다. 기존 서버의 unique(owner,blog,log,hash)와 owner SELECT RLS를 재사용하며 결과가 없거나 둘 이상이면 멈춘다. 원문 판·반환 owner·수집 fingerprint·게시물 identity·원문 문자열/형식/확보 범위를 비교하고 비공개 Storage의 파일을 가져와 SHA·실제 이미지 픽셀을 확인한다. 상류 네이버 요청이나 예약 수집을 시작하지 않는다.

해시·디코딩은 쓰기 트랜잭션 전에 끝낸다. 마지막 원자 설치에서 계정·공간·현재 참조·원문 판·활성 상태를 다시 확인한다. 기존 source/version·본문·인용과 Core revision은 변경하지 않고 사진 sidecar만 붙인다. 같은 hash는 멱등, 다른 기존 sidecar는 교체 거절이다. 저장 실패·중복 조작·삭제·계정/화면 전환·늦은 응답은 부분 설치나 잘못된 성공 표시로 이어지지 않아야 한다.

## 화면과 파일

원문을 다시 그리지 않고 기존 사진 영역만 갱신한다. 본문 Text 노드·구절 선택·스크롤·인용 위치·목록 복귀를 보존한다. 참조가 있고 사진이 없으면 `사진 가져오기`, 기존 원격 사진만 있으면 명시적 `사진 연결 보관`, 참조도 없으면 기존 수집 사본 검토를 둔다. 오류와 재시도는 해당 영역에 표시하며 로컬 파일 오류를 사진 없음으로 바꾸지 않는다. 사진 글쓰기·ZIP은 보이는 captureHash를 고정해 실행한다.

기존 일반 자료 JSON·Preservation은 네이버 원문 사진을 포함하지 않는다. 전용 `haedo.naver.capture.v1` ZIP은 선택 원문 한 판과 수집 명세·사진만 보관하고 새 독립 공간에 localOnly 사본으로 복원한다. 서버 owner·row ID·Storage 경로·개인 메모·다른 자료·공개 상태를 옮기지 않는다. 수집 사진의 `originalStatus:unverified`를 유지하며 원 작성자가 최초 업로드한 파일과의 동일성을 새로 보증하지 않는다.
