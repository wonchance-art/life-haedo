# 노션 방향 화면 정리 — 구현 계약과 작업 분리 (2026-11-16, Designer)

- **소유자 지시(11-16, Designer 세션):**
  - "디자인 위주로만 ㄱㄱ. 디자인 세션이니까 작업 분리 잘해서 진행해. 오케스트레이션 쪽으로 넘어가서 관리하겠다."
  - 그래서 [노션 방향 시안](notion-direction.md)을 실제 화면에 옮기기로 한다. 노션의 기능(블록 편집, 백링크, 데이터베이스)은 넣지 않는다.
- **기준:** main `b18adc5`. 시안은 Design 캔버스 「해도 노션 방향 시안」(소유자 계정의 비공개 artifact)이다. 데스크톱 노트·글 읽기·일정 M, iPhone 노트(390·320)·글 읽기·자료·일정 M을 지금 화면과 나란히 그렸다.
- **다른 계약과의 관계:**
  - 화면 구조(메뉴 5칸, 노트, 일정은 달력만, 주소)는 [노트 메뉴·일정 정리 계약](notes-menu.md)을 따른다. 이 문서는 그 위에 입히는 **시각 규칙**이다.
  - 둘이 어긋나면 구조는 notes-menu, 모양은 이 문서를 따른다.
  - 11-08 계약 중 남은 것(계획 화면 틀, 저장 상태 문구, 화면의 날짜)은 그대로다.
- **이번에 정한 기본값:** 소유자가 남은 판단을 정하지 않고 진행을 지시해서 시안의 권고대로 두었다. 바꾸려면 토큰 한 줄이나 해당 단위만 고치면 된다.
  - 강조색: 틸 `#145B50` 유지
  - iPhone 노트 첫 화면의 블로그 소개 묶음: 빼고, `글 메뉴 → 프로필 편집`으로 간다
  - 노트 행의 중복 `글 읽기 →`와 종류 아이콘: 뺀다
  - 자료 행의 정보·폴더: `⋯` 하나로 합친다

## 범위

- **한다:**
  - 색·글자·모서리·간격 토큰, 틀(회색 캔버스 위 흰 판 → 흰 바탕 하나), 데스크톱 메뉴 바탕, 하단 탭
  - 머리줄과 화면 제목, 탭·거르기·목록 행·속성 줄·꼬리표
  - 글 읽기의 도구 줄 한 줄로 합치기
  - 자료·뉴스·설정 머리의 조작 정리
- **하지 않는다:**
  - 저장 형식·동기화·공개·백업 로직, 데이터 키
  - 화면 문구의 뜻(아래 보존 문구), 행동의 추가·삭제
  - 노션 기능, 움직임(`haedo-motion`) 규칙
  - `sw.js` CACHE 판올림(총괄이 병합 때)

## 공통 부품 규칙

- **틀:**
  - 페이지는 흰 바탕 하나다. 데스크톱 메뉴만 `--haedo-sidebar` 면을 쓰고 화면 높이를 채운다.
  - 본문을 회색 바탕 위 흰 판(테두리·둥근 모서리)으로 감싸지 않는다.
  - 경계는 1px `--haedo-line`이고 그림자는 떠 있는 것(메뉴·시트·알림)에만 쓴다.
- **데스크톱 메뉴(1101px 이상):**
  - 순서: `해도` 글자 표지 → `글쓰기` → (`검색`, 지금 있으면) → 8px → 뉴스·일정·노트·자료·설정.
  - 항목 높이 44px, 모서리 6px. 현재 항목은 `--haedo-selected` 바탕, 먹색, 600이다.
  - 나머지 항목은 `--haedo-muted`, 400이다. 아이콘 20px, 선 1.8.
  - `글쓰기`는 채운 틸 버튼이 아니다. 틸 **글자와 아이콘**의 조용한 항목이고, 한 화면에서 틸을 쓰는 유일한 곳이다.
  - 새 글을 쓰는 중이면 현재 항목 모양으로 바뀐다(지금 규칙 15 유지).
- **하단 탭(760px 이하):**
  - 5칸 같은 폭, 높이 64px, 위 1px 선, 흰 바탕.
  - 현재 칸은 먹색 600, 나머지는 `--haedo-meta` 400이다. 아이콘 20px, 라벨 12px.
  - 320px에서 칸 64px, 라벨이 잘리지 않아야 한다.
- **노트 아이콘:** Lucide 1.51.0 `file-text`를 새로 넣는다. 원본 SVG와 SHA-256을 `vendor/lucide/UPSTREAM.json`과 `vendor/lucide/icons/`에 남긴다. `write`(글쓰기)·`edit`(수정)·`quote`(인용)·`book`(자료)과 겹치지 않는다.
- **머리줄과 화면 제목:**
  - 데스크톱 머리줄은 높이 44px이고 왼쪽에 경로(14px, `--haedo-muted`, 예: `노트 › 빛이 길게 머무는 오후`), 오른쪽에 행동을 둔다.
  - 화면 제목은 본문 맨 위의 큰 제목(`--haedo-text-page-title`, 700)이다.
  - iPhone은 지금처럼 한 줄 머리(제목 24px 700 + 오른쪽 아이콘)다.
  - 머리의 아이콘은 **최대 3개**이고 `글쓰기`는 iPhone에서 늘 맨 오른쪽이다. 나머지 행동은 `⋯` 메뉴로 옮긴다. 행동은 지우지 않는다.
- **탭(화면 안 보기 전환):**
  - 글자 탭이고 현재 탭은 먹색 600 + 아래 2px 먹색 선이다. 회색 분할 상자는 쓰지 않는다.
  - 높이 44px. 탭 줄 아래 1px 선.
- **거르기·꼬리표:**
  - 보이는 바탕은 28px(선택 시 `--haedo-selected`, 모서리 6px)이고 누르는 범위는 44px이다.
  - 원천 꼬리표(`Apple 메모`, `Obsidian`)는 `#F1F1EF` 바탕, `--haedo-muted` 글자, 12px, 모서리 4px다(대비 5.73).
- **목록 행:**
  - 행 전체가 하나의 열기 동작이다. 제목(16px 600, 최대 2줄), 발췌(14px `--haedo-muted`, 데스크톱 1줄·iPhone 2줄), 메타 한 줄(13px `--haedo-meta`), 사진이 있으면 오른쪽 64–72px 사진을 둔다.
  - 행 사이는 1px 선이다. 같은 행에 같은 일을 하는 두 번째 버튼을 두지 않는다.
  - 행에 따로 할 일이 있으면 오른쪽 `⋯` 하나로 모은다.
- **날짜 머리:** 13px 500 `--haedo-muted`, 위 28px 여백.
- **속성 줄(글 읽기):** 이름 칸(데스크톱 140px·iPhone 88px, 16px 아이콘 + 이름, `--haedo-meta`)과 값(14px 먹색). 높이 32–36px.
- **빈 상태:** 표나 상자를 그리지 않고 한 줄 문장(14px `--haedo-meta`)과, 있으면 링크 하나만 둔다.
- **메뉴(`⋯`)·시트:** 흰 바탕, 1px 선, 그림자 `0 0 0 1px rgba(15,15,15,.05), 0 3px 6px rgba(15,15,15,.1), 0 9px 24px rgba(15,15,15,.2)`, 모서리 8px, 항목 44px.

## 화면별 규칙

- **노트(notes-menu 단위):**
  - 탭 `글 · 초안 · 숨긴 글`과 `내 글 찾기`가 한 줄에 온다.
  - 그 아래 `작성하던 글 · 제목 · 이어쓰기` 한 줄을 `--haedo-soft` 바탕으로 둔다.
  - 그다음 날짜 머리와 행이 온다.
  - 머리 오른쪽은 `글 메뉴`(⋯: 글 공개·보관, 계정 보관 상태, 프로필 편집)와 iPhone `글쓰기`다.
- **일정(모든 단위 같은 틀):**
  - 데스크톱 머리: 제목(`2026년 11월` 등) 오른쪽에 단위 글자 탭 `Y Q M W D`, `오늘`, `‹ ›`, `일정에서 찾기`를 둔다.
  - 그 아래 거르기 `전체 · 글 · 발췌 · 사진`, 본문, 옆 칸(280px, 왼쪽 1px 선)이 온다.
  - M 칸: 1px 선 격자, 칸 높이 104px, 날짜 13px. 오늘은 24px 먹색 원에 흰 글자다.
  - 그 날의 글은 칸 안 회색 꼬리표(12px)다. **칸 전체가 하나의 링크**(44px 이상)이고 이름은 `11월 5일, 글 1편`이다. 꼬리표를 따로 누르게 하지 않는다.
  - iPhone: 단계 막대가 없다(소유자 결정). `‹ 2026`(연으로)과 `찾기`·`글쓰기`가 한 줄, 제목과 `오늘 ‹ ›`가 한 줄이다. 날짜 44px, 오늘 32px 먹색 원, 글 있는 날 4px 먹색 점이다.
  - 옆 칸 순서는 `예정 → 습관 · 행복도 → 목표 · 계획`이다(notes-menu). 습관 점은 6px이고 한 날은 채움, 지난 할 날은 1.5px 테두리, 앞으로의 할 날은 옅은 테두리다.
  - 범례에 `보기 전용 · 체크는 하루·주 보기에서`를 둔다(결정 13).
- **글 읽기:**
  - 도구는 한 줄이다: `뒤로` · `🔒 공개 알약`(지금 `글 정보` 동작 그대로) · `수정`(숨긴 글이면 `목록에 다시 보이기`) · `⋯` · iPhone `글쓰기`.
  - 지금 둘째 줄의 `사진 포함 백업`·찾기·`삭제`(맨 아래)는 `⋯` 안으로 옮긴다. 순서는 지금 메뉴 순서를 따른다.
  - 제목(`--haedo-text-post-title`, 700) 아래에 속성 줄 `작성`(처음 쓴 날, 결정 8)과 `저장`(두 단계 저장 상태 문구 그대로)을 두고, 1px 선 뒤 본문이 온다.
  - 공개 상태는 위 알약에만 둔다. 글 끝의 저장 상태 줄과 `다시 시도`는 속성 줄로 옮긴다.
  - 본문 17px/1.8은 그대로다. AI 점 표시도 그대로다.
- **자료:**
  - 머리 아이콘은 `담기(+)` · `⋯`(여러 개 고르기, 폴더 관리) · `글쓰기` 셋이다.
  - 검색 칸(44px, `--haedo-selected` 바탕) 안 오른쪽에 `거르기` 하나를 둔다. `최신 버전만`·원천·날짜는 그 안으로 옮긴다.
  - 탭 `전체 N · 원문 · 발췌 · 기사`의 오른쪽에 `모든 폴더 ⌄`를 둔다. `자료 N개 · 최신 버전` 줄은 탭 개수와 거르기 표시로 대신한다.
  - 행: 제목 1줄, 발췌 2줄, 꼬리표 + 시각, 오른쪽 `⋯`(정보, 폴더로 옮기기)다.
- **뉴스·설정:**
  - 위 머리 규칙(아이콘 최대 3개, 나머지 `⋯`)과 탭·행 규칙을 적용한다.
  - 각 조작의 새 자리는 작업자가 표로 적어 Designer 확인을 받는다(아래 W5). 화면별 시안이 따로 없으므로 이 확인이 시안을 대신한다.

## 보존 조건 (모든 단위)

- **행동:** 행동을 지우지 않고 자리만 옮긴다. 접근 가능한 이름(`글 메뉴`, `글 저장`, `내 글 찾기`, `글쓰기` 등)과 키보드 순서·초점 복귀 키(`data-focus-key`)를 유지한다.
  - 노트 행의 초점 복귀는 제목 버튼(`home:post:…`)으로 모은다.
- **문구는 그대로 둔다:**
  - 공개 표시: `비공개 원본` · `공개 중 · 원본은 비공개` · `공개 확인 못 함 · 원본은 비공개` · `기록 글 · 비공개` · `첨부 글 · 비공개`
  - 저장 상태 세 가지와 `다시 시도`
  - 빈 상태와 오류 문장
  - 시안의 줄인 메타(`비공개`)는 그림일 뿐이고, 실제로는 위 문구를 쓴다.
- **조작과 글자:**
  - 조작은 44px 이상이다. 데스크톱 블록 손잡이처럼 포인터 전용 예외는 이번에 없다.
  - Pretendard, `word-break: keep-all`, 글자 대비 4.5:1, 비글자 3:1.
  - 팔레트를 바꿨으므로 **실제 표면색 기준**의 대비와 색각 구분(공개 중/미반영 같은 상태색)을 다시 잰다.
- **화면 전환:**
  - 노트·일정·글 읽기의 복귀(스크롤·검색어·탭)를 유지한다.
  - 계정 전환·늦은 응답·한글 조합·열린 편집기의 미저장 입력을 유지한다.
  - 옛 주소는 notes-menu 표대로 연다.
- **겉모양만 바꾼다:** 숨긴 UI, 제품 전용 분기, 단언 약화를 쓰지 않는다. 바뀐 규칙을 단언하던 검사는 같은 작업에서 새 규칙으로 고친다.
  - 예: `tests/life-naver-capture-browser.cjs:509`의 `.home-post-read` 클릭은 제목 버튼(`.home-post-open`)으로 바꾼다.

## 작업 분리

파일 담당이 겹치지 않게 나눴다. `ui.js`는 두 단위가 쓰지만 서로 다른 함수 영역만 맡는다.

| 단위 | 맡을 곳(권장) | 파일 | 선행 | 할 일 |
| --- | --- | --- | --- | --- |
| **W1 바탕·토큰** | Designer | `assets/haedo-shell.css`, `assets/haedo-type.css`, `assets/life/ui.css`의 `:root`와 공통 판 규칙, `assets/life/icons.js`(`file-text` 추가), `DESIGN.md`, `.impeccable/design.json` | 없음 | 위 토큰 표. 회색 캔버스·흰 판 걷기, 메뉴 면, 조용한 `글쓰기`, 하단 탭을 N칸 같은 폭으로, 공통 부품 클래스(`.haedo-page-title`·탭·거르기·꼬리표·메뉴) |
| **W2 노트** | notes-menu 작업자 | `assets/life/home.js`, `assets/life/home.css`, notes-menu가 정한 탐색·주소 파일(`assets/haedo-navigation.js` 등) | W1, notes-menu 구현과 **한 번에** | 노트 구조(notes-menu)와 위 노트 규칙을 같이 넣는다. 같은 파일을 두 번 고치지 않는다 |
| **W3 일정 달력** | notes-menu 작업자(같거나 둘째) | `assets/life/schedule.css`, `assets/life/schedule-*.js`, 일정 머리 | W1, notes-menu와 한 번에 | 모든 단위 같은 틀과 위 일정 규칙 |
| **W4 글 읽기 한 줄** | 작업자 | `assets/life/photo-post-ui.js`, `assets/life/photo-post.css`, `ui.js`의 쪽 화면 머리 영역(`heading.textContent = … '글 읽기'` 주변 함수) | W1 | 도구 한 줄, 속성 줄, 글 끝 상태를 속성으로. D1 후속 "읽기 머리줄과 `ui.js` 공통 머리줄 통합"을 이 단위로 끝낸다 |
| **W5 자료·뉴스·설정 머리** | 작업자 | `ui.js`의 자료 목록 머리·행 영역, `assets/life/source-folders-ui.js`, `assets/life/records.css`, `assets/life/discovery.css`, `assets/life/settings.css` | W1 | 자료 규칙. 뉴스·설정은 조작 자리 표를 먼저 Designer에 보내 확인받고 구현 |
| **W6 나머지 굵기·모서리 정리와 통합 검수** | Designer | W2–W5 밖의 CSS(`workbench.css`, `platform.css`, `public-cover.css`, `timeline-shell.css`, `habit-tracker.css` 등) | W2–W5 병합 | 굵기 750·650·550·450과 옛 모서리를 토큰으로. 통합본에서 아래 검사 전체 |

- **순서:** W1 → (W2+W3는 notes-menu 구현과 묶어서) ∥ W4 ∥ W5 → W6 → 총괄 병합(`sw.js` CACHE 판올림, 새 브라우저 검사 CI 등록, AGENTS 스킬 절의 시각 체계 문장 갱신).
- **notes-menu와 묶는 이유:** 노트·일정 파일을 구조 변경과 시각 변경으로 두 번 고치면 충돌과 검사 수정이 두 배가 된다. 총괄이 notes-menu를 배정할 때 이 계약의 노트·일정 절을 함께 넘기는 것을 권한다.
- **W1을 먼저 하는 이유:** 토큰만 바뀌어도 화면 대부분의 색·면이 바뀐다. 나머지 단위는 W1의 클래스와 토큰을 재사용한다(같은 일을 하는 새 도우미를 만들지 않는다).
- **진행 중인 작업과의 충돌:** 총괄 기록에 notes-menu는 "작업자 A·C 병합 뒤"다. W1은 공통 CSS 파일만 고쳐서 A·C와 겹칠 가능성이 낮다. 그래도 착수 시점은 총괄이 정한다.
