## Designer 기본값 (소유자가 바꿀 수 있음)

소유자는 남은 판단을 정하지 않고 진행을 지시했다. 그래서 아래는 시안의 권고값으로 두었다. 각각 토큰 한 줄이나 한 단위의 별도 커밋이라 따로 되돌릴 수 있다.

1. 강조색은 틸 `#145B50`을 유지한다.
2. 노트 첫 화면의 블로그 소개 묶음(프로필 줄)을 뺀다.
   - 프로필 보기·편집·불러오기 실패 재시도는 `글 메뉴 → 프로필 편집`으로 간다.
   - W2가 묶음의 각 요소(이름·소개·아바타·`소개 표시`·재시도)의 새 자리를 표로 보고한다.
   - 공개 블로그의 소개 표시는 바뀌지 않는다.
3. 노트 행의 종류 아이콘(`home-row-mark`)과, 제목 버튼과 같은 일을 하는 `글 읽기 →`(`.home-post-read`)·사진 열기 버튼(`.home-post-media`)을 뺀다. 행은 제목 버튼 하나로 연다.
4. 노트 행의 사진은 4:3 큰 사진 대신 오른쪽 64–72px 사진으로 줄인다.
   - 이것은 `DESIGN.md`와 AGENTS 스킬 절의 "실제 사진 피드"를 바꾸는 일이다.
   - 채택하면 총괄이 AGENTS 문장을 고친다. 소유자가 원하면 이 한 가지만 되돌린다.
5. 자료 행의 `자료 출처 정보`·폴더 두 아이콘을 행의 `⋯` 하나로 합친다.

### W1이 함께 해야 하는 것

- **채움 이전:** 지금 `--canvas`를 유일한 채움으로 쓰는 곳은 바탕이 흰색이 되면 경계가 사라진다. 이런 곳을 `--haedo-soft`나 입력 테두리로 옮긴다.
  - `ui.css`: `.life-search-bar` `:88`, `.life-selection-bar` `:126`, `.life-import-methods` `:200`
  - `home.css`: `:24`·`:70`·`:87`·`:102`
  - `workbench.css`: `:133`
  - 검색 칸 안쪽 입력은 `border:0`(`ui.css:91`)이라 바깥 칸이 `--field-line` 테두리를 가져야 한다.
- **`--soft` 사용처 점검:** 셸에서 `--soft`는 `--haedo-selected`를 가리킨다(`haedo-shell.css:10`). 눌림·현재·일치 표시(`ui.css:58,98,109,116,124,202,349,357`, `workbench.css` 여러 곳)가 함께 옅어진다.
  - 각 사용처를 분류해 보고한다: 두 번째 표시를 더할 곳, `--haedo-mark`로 갈 곳, 그대로 둘 곳.
- **틸 사용처 분류:** `var(--color-primary)` 136곳과 `var(--haedo-accent)` 36곳을 아래 "틸 규칙"에 따라 "유지 / 먹색으로"로 나눈 표를 만든다.
  - 표는 W1이 만들고, W1은 자기 파일만 고친다. W2–W4는 자기 담당 파일에서 표대로 고치고, 나머지는 W5가 고친다.
  - 링크의 실제 색은 `ui.css:23` `a{color:var(--color-primary)}`이다. 글 안 링크만 먹색 + 밑줄(`var(--field-line)` `#8A8984`, 흰 3.50:1, 오프셋 4px)로 바꾼다. 호버는 먹색 밑줄이다. 행·메뉴 모양의 링크는 행 규칙을 따른다.
    - 처음 값 `rgba(55,53,47,.4)`는 흰 바탕 2.3:1로 비글자 3:1에 못 미쳐 W3 검수 MAJOR가 됐다. 총괄이 11-18에 `--field-line`으로 확정했고, 글 읽기(W3)와 앱의 다른 글 안 링크(W5)가 같은 값을 쓴다.
    - 테가 있는 버튼 모양 링크(`a.life-button`)에는 밑줄을 긋지 않는다.
- **공개 페이지 보호:**
  - 공개 5쪽은 `ui.css`만 읽고 `haedo-shell.css`는 읽지 않는다. `body`에 `haedo-shell` 클래스도 없다(`blog.html`·`series.html`·`share.html`은 맨 `<body>`, `cover.html`은 `public-cover-page`, `taste.html`은 `nine-public-page`).
  - 그래서 **모양을 바꾸는 규칙은 `haedo-shell.css`에 두거나 `ui.css` 안에서 `body.haedo-shell` 범위로 쓴다.** 위의 `a` 색, `--soft` 사용처, `mark`가 모두 여기에 해당한다.
  - `ui.css`의 범위 없는 규칙에는 대체값만 더한다. 예: `var(--haedo-mark, <지금 값>)`, `var(--haedo-canvas, #f4f6f5)`. 대체값 없는 `var(--haedo-*)`로 바꾸지 않는다.
  - 공개 검사(`blog-public-browser`, `public-cover-visual-browser --prepare-database`, `nine-public-browser`, `blog-series-public-browser`)와 전·후 캡처로 공개 화면이 바뀌지 않았음을 보인다.

## 틸 규칙

- **탐색·머리줄에서 틸은 `글쓰기` 하나다.** 메뉴의 현재 항목, 탭, 거르기, 행, 머리 아이콘은 먹색·회색이다.
- **틸을 유지하는 곳:**
  - 초점 링
  - 체크된 체크·`accent-color`
  - 인용 바(소유자 결정 "인용 = 틸 3px 바")
  - 진행 막대
  - 편집기·대화상자의 주 버튼(`글 저장`, `공개하기` 등)
  - 빈 상태의 첫 행동(`첫 글 쓰기`)
  - iPhone 머리의 `글쓰기` 아이콘
- **바뀌는 것:** 달력의 오늘 표시는 먹색 원이다(시안). 습관 표의 오늘 표시는 W2가 같은 규칙으로 맞춘다.
- **바꾸지 않는 것:** 연표·행복도의 데이터 색(`DESIGN.md` 데이터 색 절).

## 공통 부품 규칙

- **재사용:** 기존 클래스와 도우미를 쓴다(11-09 교훈). 같은 일을 하는 새 도우미를 만들지 않는다.
  - 예: 머리 제목 `.haedo-page-heading h1`, 메뉴 `.life-feature-menu`, 자료 탭 `RecordsList.tabs`
- **뜻은 바꾸지 않는다:** 모양만 바꾸고 지금의 역할·상태 속성을 유지한다.
  - 설정의 분할 선택은 라디오 묶음이고(`settings-ui.js:237`), `Y·Q·M·W·D`는 `aria-current="true"` 링크다(`schedule-ui.js:654-659`). 모양만 글자 탭이 된다.
- **틀:**
  - 페이지는 흰 바탕 하나다. 메뉴만 `--haedo-sidebar` 면이고 화면 높이를 채운다.
  - 본문을 회색 바탕 위 흰 판으로 감싸지 않는다.
  - 경계는 1px `--haedo-line`이다. 그림자는 떠 있는 것(메뉴·시트·알림)에만 쓴다.
- **데스크톱 메뉴(1101px 이상, 폭 240px):**
  - 순서: `해도` 글자 표지 → `글쓰기` → 8px → 뉴스·일정·노트·자료·설정. 메뉴에 검색을 새로 더하지 않는다. 통합 검색은 머리에 남는다.
  - 항목 높이 44px, 모서리 6px.
  - 현재 항목: `--haedo-selected` 바탕 + 먹색 + 600(두 번째 표시)이다. 나머지는 `--haedo-muted` 400이다.
  - `글쓰기`는 채운 틸 버튼 대신 틸 글자·아이콘의 조용한 항목이다. 새 글을 쓰는 중이면 현재 항목 모양이 된다(결정 15).
- **좁은 세로 메뉴(761–1100px, iPad 세로·분할 화면):**
  - 지금 폭(88px)과 아이콘 위·라벨 아래 배치를 유지한다. 면은 `--haedo-sidebar`다.
  - `글쓰기`는 채움 없는 틸 아이콘+라벨이다. 현재 항목 규칙은 데스크톱과 같다.
- **하단 탭(760px 이하):**
  - 5칸 같은 폭, 높이 64px, 위 1px 선, 흰 바탕이다.
  - 현재 칸은 먹색 600이고 나머지는 `--haedo-meta` 400이다. 아이콘 20px, 라벨 12px.
  - 각 칸 44px 이상이고 320px에서 라벨이 잘리지 않아야 한다(지금 좌우 여백 `max(12px,…)` 기준, notes-menu 문장과 같다).
- **노트 아이콘:**
  - Lucide 1.51.0 `file-text`를 새로 넣는다. `icons.js`의 글리프 이름은 `note`로 정한다. W1이 넣고, W2는 메뉴 항목에 `glyph: 'note'`로 쓴다.
  - `vendor/lucide/icons/`에 원본 SVG를 두고, `vendor/lucide/UPSTREAM.json`의 `files`(또는 `npm_subset.files`)에 SHA-256과 함께 적는다. 그래야 `tests/icons.test.cjs`가 통과한다.
  - 판에 그 아이콘이 없으면 Designer에 알리고 멈춘다. 다른 판에서 가져오지 않는다.
- **머리줄:**
  - **데스크톱:** 머리줄 높이 44px. 왼쪽은 경로(14px `--haedo-muted`, 예: `노트 › 빛이 길게 머무는 오후`)이고, 오른쪽은 행동이다. 화면 제목은 본문 맨 위 큰 제목(`--haedo-text-page-title`, 700)이다.
  - **1100px 이하(좁은 세로 메뉴·iPhone):** 지금처럼 한 줄 머리(제목 28px 700 + 오른쪽 아이콘)다.

- **목록 행:**
  - 지금의 제목 버튼(`h3 > button`)을 유지하고 누르는 범위만 행 전체로 넓힌다(늘린 링크 방식). 버튼 안에 다른 조작을 넣지 않는다.
  - 사진은 보이기만 하고 따로 누르지 않는다. 같은 일을 하는 두 번째 버튼을 두지 않는다.
  - 제목 16px 600(최대 2줄), 발췌 14px `--haedo-muted`(데스크톱 1줄·iPhone 2줄), 메타 한 줄 13px `--haedo-meta`, 행 사이 1px 선이다.
  - 행에 따로 할 일이 있으면 오른쪽 `⋯` 하나로 모은다.
- **날짜 머리:** 13px 500 `--haedo-muted`, 위 28px.
- **빈 상태:** 표나 상자 없이 한 줄 문장(14px `--haedo-meta`)과, 있으면 행동 하나(링크, 또는 노트의 `첫 글 쓰기` 버튼)다.
- **메뉴(`⋯`)·시트:**
  - 흰 바탕, 1px 선, 그림자 `0 0 0 1px rgba(15,15,15,.05), 0 3px 6px rgba(15,15,15,.1), 0 9px 24px rgba(15,15,15,.2)`, 모서리 8px, 항목 44px.

    - 지금 id·클래스로 초점을 돌려주는 코드(`#lifeSelectionToggle` `ui.js:2652,4248`, 폴더 이동 `:4420-4427`)는 닫힌 메뉴 안의 요소를 가리키지 않게 고친다.
- **아이콘:** Lucide 선 아이콘만 쓴다. 공개 알약의 자물쇠도 Lucide `lock`이다. 이모지는 쓰지 않는다.

  - 머리가 이미 화면 이름을 보이므로 묶음·다시 찾기 본문 첫 줄의 같은 이름(`h2`)은 화면 읽기 프로그램에만 남긴다. 선택 자료 페이지·책이 쓰던 방식과 같고, 그 줄의 `지금 저장`은 오른쪽 끝에 남는다.
  - 주제의 검색 칸은 자료 검색 칸 규칙, 주제 행은 자료 행(`.records-row`) 규칙을 따른다.
  - 가져오기의 방법 고르기(`본문 붙여넣기`·`텍스트 파일`·`링크 보관`)는 회색 분할 상자 대신 글자 탭 모양이다. 지금의 `aria-pressed` 단추 묶음은 그대로다.
  - 컬렉션의 고른 거르기는 어두운 채움 대신 선택 면 + 먹색 600이다.
  - 1101px 이상에서 `최신 내용 확인`은 머리 줄 안 오른쪽에 들어간다. 머리가 둘째 줄로 늘어나지 않는다(105px → 45px).
  - 자료의 `⋯`에서 `기록 선택`·폴더 관리 위의 `목록`은 같은 메뉴 안의 구역 이름이다. 중첩 하위 메뉴로 만들지 않는다(W4 판정).
- **뉴스·설정:**
  - 위 머리·탭·행 규칙을 적용한다.
  - **뉴스 탭 줄(11-18 판정):** 탭 이름(`제외한 글` 등)을 줄이지 않는다. 760px 이하에서 탭 사이를 16px로 줄여, 390px에서는 개수 두 개가 두 자리여도 네 탭과 필터가 한 줄에 들어가고 375px에서는 한 자리일 때 들어간다.
    - 그보다 길면(320px, 세 자리 개수) 탭 줄만 옆으로 밀어 보고 끝을 흐리게 한다. 고른 탭은 줄 안으로 들어온다.
    - 필터 단추는 미는 영역 밖에 둔다. 밀어도 마지막 탭이 필터 아래로 들어가지 않는다.
  - 시안이 따로 없으므로 작업자가 조작마다 "지금 자리 → 새 자리 → Esc·실행 뒤 초점" 표를 먼저 Designer에 보내 확인받고 구현한다.

## 보존 조건 (모든 단위)

- **행동:** 행동을 지우지 않고 자리만 옮긴다.
  - 접근 가능한 이름을 유지한다: `글 메뉴`, `글 저장`, `내 글 찾기`, `통합 검색`, `가져오기`, `기록 선택`, `검색 필터`, `단축키 (?)`, `글쓰기`, `내 글로 돌아가기` 등.
  - 키보드 순서와 초점 복귀 키(`data-focus-key`)를 유지한다. 노트 행의 복귀는 제목 버튼(`home:post:…`)으로 모은다.
- **문구는 그대로 둔다:**
  - 공개 표시: `비공개 원본` · `공개 중 · 원본은 비공개` · `공개 확인 못 함 · 원본은 비공개` · `기록 글 · 비공개` · `첨부 글 · 비공개`
  - 저장 상태:
    - `저장됨 · 계정에 올림` · `계정에 올리기 대기` · `계정에 올리지 못함 · 다시 시도`
    - `다른 기기 변경을 맞추는 중 · 진 쪽은 복구 사본으로 남김` · `저장됨 · 앱을 새로고침하면 계정에 올림`
  - 공개 알약의 덧붙임: `올리기 실패` · `새로고침 필요` · `맞추는 중` · `수정 중`, `공개 여부 확인 중`/`확인하지 못함`
  - 그 밖에: `마지막 선택 미반영`, 빈 상태와 오류 문장
  - 시안 그림의 문구는 예시다. 실제로는 위 문구를 쓴다.
- **조작과 글자:**
  - 조작은 44px 이상이다(이번 범위에 포인터 전용 예외는 없다).
  - 굵기는 `--haedo-weight-*`(400·500·600·700) 토큰, 모서리는 `--haedo-control-radius` 6px(버튼·입력·아이콘 단추·선택 바탕)·`--haedo-radius` 8px(카드·시트·떠 있는 막대)만 쓴다. 예외: 습관 확인 칸 12px, 데이터 색, 공개 페이지(W5).
  - 공개 페이지와 함께 쓰는 `ui.css`에서는 값을 바로 바꾸지 않고 `var(--ui-…, 지금 값)` 고리로 쓴다. 앱 값은 `haedo-shell.css`에만 둔다. 그래서 공개 5쪽은 픽셀 단위로 그대로다(W5 전후 비교).
  - Pretendard, `word-break: keep-all`, 글자 대비 4.5:1, 비글자 3:1.
  - 팔레트를 바꿨으므로 **실제 표면색 기준** 대비와 색각 구분(공개 중/미반영 같은 상태색)을 다시 잰다.
- **화면 전환:**
  - 노트·일정·글 읽기의 복귀(스크롤·검색어·탭)를 유지한다.
  - 계정 전환·늦은 응답·한글 조합·열린 편집기의 미저장 입력을 유지한다.
  - 옛 주소는 notes-menu 표대로 연다.
- **검사:** 숨긴 UI, 제품 전용 분기, 단언 약화를 쓰지 않는다. 바뀐 규칙을 단언하던 검사는 같은 작업에서 새 규칙으로 고친다(아래 단위별 표).

- **배포는 두 번이다.** 단위마다 main에 넣으면 반쯤 바뀐 화면이 나가므로 단계별 통합 브랜치(총괄이 정함)에 모은다.
  - **1단계 배포:** W1 + W2(notes-menu 포함)를 모아 통합 검수 뒤 배포한다. 소유자는 이때 노트와 일정을 실기기에서 먼저 써 본다(방향 문서의 "한 화면 먼저" 방안).
  - **2단계 배포:** W3 + W4 + W5를 모아 같은 절차로 배포한다.
  - 배포마다 총괄이 `sw.js` CACHE를 한 번 올린다.
- **notes-menu와 묶는 이유:**
  - 노트·일정 파일을 구조와 시각으로 두 번 고치면 충돌과 검사 수정이 두 배가 된다.
  - 그래서 notes-menu 구현은 W1 병합을 기다린다. W1이 늦으면 구조를 먼저 하고 시각 커밋을 W1 뒤에 더한다.
  - 시각 커밋만 되돌릴 수 있게 나눈다(방향 문서의 "한 화면 먼저 써 보기" 방안).
- **검사 파일 담당:** 위 표의 단위가 그 검사 파일을 고친다. 두 단위가 같은 검사 파일을 고쳐야 하면 먼저 병합하는 단위가 고치고, 뒤 단위는 main을 합친 뒤 이어서 고친다.
- **통합·검수:**
  - 병합과 통합은 총괄이 하고, 작업자 커밋의 작성자를 보존한다. Designer는 디자인 최종 판단을 한다.
  - 독립 검수자는 그 단위의 구현자가 아닌 에이전트다. W1·W5는 Designer가 구현하므로 다른 에이전트가 검수한다.
- **총괄의 병합 할 일(작업자 금지 범위):**
  - 배포마다 `sw.js` CACHE 판올림, 새 브라우저 검사의 CI 등록
  - 아래 문장 갱신은 **1단계 배포 때** 한다. 그래야 1단계 뒤 검수자가 옛 규칙을 기준으로 위반을 올리지 않는다.
  - AGENTS 스킬 절의 시각 체계 문장("흰 읽기 면·옅은 초록 회색 캔버스·짙은 틸 조작…·실제 사진 피드") 갱신
  - `.agents/skills/life-haedo-design/SKILL.md:32`, `.agents/skills/unslop/INSTALLATION.md:27`의 초록 캔버스·틸 문장 갱신
- **진행 중인 작업과의 충돌:** 총괄 기록상 notes-menu는 "작업자 A·C 병합 뒤"다. W1은 공통 CSS가 중심이라 A·C와 겹칠 가능성이 낮지만, 착수 시점은 총괄이 정한다.
