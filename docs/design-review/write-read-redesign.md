# 글쓰기·읽기 개편 시안 — Markdown 파일, 블록 편집

2026-11-02. [전문가 기준](expert-design-brief.md)의 순서로 만든 개편 시안(부드러운 판) 가운데 글쓰기와 글 읽기 화면의 근거다. 시안 단계이므로 앱 코드는 바꾸지 않았다. 구현은 총괄의 작업 지시로 따로 진행한다.

사용자 요청: "obsidian 같은 마크다운인데 노션처럼 돌아가도록, 기본적인 구조만."
이 문서에서는 이 요청을 다음 두 가지로 해석했다.
- 저장되는 글은 Obsidian에서 그대로 열리는 Markdown 파일이다.
- 편집은 Notion처럼 블록 단위로 한다: `/` 메뉴, 손잡이, `[[` 연결.

## 사용 장면

- **시작:** 저녁에 Mac에서 `+ 글쓰기`를 누르거나, 일정·자료에서 하루를 골라 쓴다. 출근길 iPhone에서는 연필 버튼으로 짧게 쓰고, 이어서 다른 기기에서 고친다(계정 자동 동기화, 2026-11-01 소유자 지시).
- **입력:** 문단, 소제목, 목록, 체크, 사진 1~3장, 자료실의 발췌 인용, 예전 글로 가는 연결.
- **종료:** `글 저장`으로 새 본문 버전이 생긴다. 같은 글을 Obsidian 보관함에 넣으면 제목·속성·연결이 그대로 읽힌다. 공개는 여전히 따로 고르는 명시 동작이다.

## 결정

1. **상태는 읽기와 편집 두 가지뿐이다.**
   - 원문(Source) 모드는 화면에 두지 않는다.
   - 읽기에서 `편집`을 누르면 같은 위치에서 편집이 열린다. 편집에서 `읽기`를 누르면 저장하지 않은 입력을 유지한 채 미리 본다.
   - 두 상태에서 본문의 시작선(데스크톱 왼쪽 104px)과 글자 크기가 같아서, 전환할 때 줄이 움직이지 않는다.
2. **저장 형식은 Markdown 파일이다.**
   - 앞부분 속성: `title`·`date`·`tags`·`public`.
   - 제목은 본문 H1이 아니라 별도 입력칸이다.
   - 본문은 표준 Markdown(CommonMark + GFM 체크)으로 쓴다.
   - 예시는 아래 「저장되는 파일」.
3. **블록은 Markdown으로 저장할 수 있는 것만 둔다.**
   - 문단, 제목(`##`), 작은 제목(`###`), 목록, 번호 목록, 체크, 인용, 코드, 구분선, 사진, 자료에서 인용, 글 연결.
   - 토글·열·글자색처럼 파일로 왕복할 수 없는 블록은 만들지 않는다.
4. **블록 표시는 줄을 밀지 않는다.**
   - 커서가 들어간 제목의 `##`는 데스크톱에서 왼쪽 여백에 걸린다. 본문 줄은 그대로 있다.
   - iPhone은 여백이 좁으므로 블록 표시를 숨긴다. 블록 종류는 도구 막대 `Aa`에서 보고 바꾼다.
   - 글자 안의 표시(`**`, `[[ ]]`)는 커서가 들어가면 그 자리에 보인다.
   - 한글을 조합하는 중에는 표시를 바꾸거나 블록을 변환하지 않는다.
5. **블록 조작:**
   - 데스크톱은 마우스를 올리거나 키보드 초점이 블록에 오면 `+`(아래에 블록 넣기)와 `⋮⋮`(블록 메뉴, 끌어서 옮기기)를 보인다. `⋮⋮` 메뉴에는 종류 바꾸기, 위로/아래로, 복제, 삭제를 둔다.
   - 같은 동작을 키보드 단축키로도 할 수 있다.
   - 터치 기기에서는 손잡이를 쓰지 않는다. `+`는 도구 막대에, 이동은 블록 메뉴의 위로/아래로 버튼에 둔다.
6. **`/` 블록 메뉴:**
   - 줄 맨 앞이나 공백 뒤에서만 열리고, 한글로 검색한다. Esc나 공백을 입력하면 닫힌다.
   - 한글을 조합하는 중에는 열지 않는다.
   - 순서는 고정한다. 기본(문단·제목·작은 제목·목록·번호 목록·체크·인용·구분선)을 먼저 두고, 넣기(사진·자료에서 인용·글 연결)를 뒤에 둔다. 각 항목 오른쪽에 같은 결과를 내는 Markdown 입력을 보인다.
7. **Markdown 단축 입력은 표준 의미를 따른다.**
   - `## `, `- `, `1. `, `[ ] `, `> `(인용), `---`, ```` ``` ````, `[[`.
   - 자동 변환 바로 다음에 ⌘Z를 누르면 입력한 글자로 돌아간다.
8. **`[[` 글 연결:**
   - 글 제목을 검색해 제안한다. 선택한 글자를 `[[`로 감쌀 수 있다.
   - 없는 글은 자동으로 만들지 않고, `"…"로 새 글 만들기`를 명시적으로 고를 때만 만든다.
9. **자료에서 인용:**
   - 저장 형식은 `> [!quote] 출처` + 인용문 + `> [[원본#^위치]]` + `<!-- haedo:src=자료ID ver=판 -->`이다.
   - 화면에서는 판이 고정된 잠긴 카드다. 출처, 판 배지, 잠금 표시를 함께 보인다.
   - 고치려면 블록 메뉴의 `내 문단으로 바꾸기`로 원문 연결에서 분리한다. 원문 그대로의 인용과 내 글을 섞지 않는다.
   - 콜아웃을 지원하지 않는 앱에서는 인용으로 보인다.
10. **iPhone 도구 막대:**
    - 키보드 위에 고정하고, 순서는 `[+ 블록][Aa][[ ]][자료에서 인용][사진][체크][들여쓰기] … [키보드 닫기]`다.
    - 폭이 모자라면 가로로 넘긴다.
    - 블록을 넘는 연속 선택과 iOS 기본 편집 메뉴(복사·붙여넣기·찾아보기)는 가로채지 않는다.
11. **읽기 화면:**
    - 본문은 17px, 줄 길이는 680px(한글 약 38자)로 제한한다. 제목 아래 한 줄에 날짜·시간·태그를 둔다.
    - 데스크톱 오른쪽에는 개요(소제목 2개 이상일 때), 이 글을 가리키는 글(문맥 한 줄), 인용한 자료(판 배지)를 둔다.
    - iPhone은 개요를 머리의 버튼으로 시트에 열고, 이 글을 가리키는 글을 본문 아래에 둔다.
    - 연결되지 않은 언급(unlinked mentions)은 보이지 않는다.
12. **글자 크기:**
    - 기존 단계를 따른다: 12 배지, 13 메타·사진 설명, 15 조작, 17 본문·인용, 20 소제목, 28 데스크톱 글 제목, 24 iPhone 글 제목.
    - 인용은 본문보다 크게 하지 않는다. 세로 바로만 구분한다.

## 저장되는 파일

```markdown
---
title: 월요일 아침, 도서관 반납
date: 2026-11-02T09:12
tags: [도서관, 산책]
public: false
---

『도서관의 시간』 반납일이라 출근 전에 조금 돌아서 걸었다. …

![반납함 옆 은행잎](photos/2026-11-02-ginkgo.jpg "반납함 옆에 은행잎이 쌓여 있었다.")

## 반납하는 길

> [!quote] 『낮은 창』 42쪽
> 천천히 걸을 때만 보이는 골목이 있다.
> [[낮은 창#^p42]]
<!-- haedo:src=자료ID ver=11.2 -->

지난주 [[목요일 저녁 산책]]에서 쓴 것과 같은 이야기다.

## 다음에 빌릴 책

- 4장과 5장 다시 읽기
- 『낮은 창』 나머지
- [ ] 11월 16일까지 반납
```

- 사진의 대체 텍스트는 `![…]`에, 사진 설명은 이미지 제목(`"…"`)에 둔다. 사진 파일은 글과 같은 묶음의 `photos/`에 둔다.
- `public: false`는 공개 여부 기록일 뿐이다. 이 값을 바꿔도 게시되지 않는다. 공개는 지금처럼 명시 동작으로만 한다.
- `<!-- haedo:… -->` 주석은 다른 Markdown 앱에서 보이지 않는다. 해도에서는 원문 판을 다시 찾는 데 쓴다.

## 지금 앱과의 차이 (구현 전에 정할 것)

- **현재 저장 형식:**
  - 사진 글 편집기(`photo-post-ui.js`)는 Quill Delta(`photo` 삽입 포함)로 저장한다.
  - 직접 글쓰기(`writing.js`)는 `text/plain` 본문 버전이다.
  - Obsidian은 가져오기 전용이다(`obsidian-*`).
  - 이 시안의 Markdown 저장은 새 형식이다.
- **선택지:**
  - (A) Markdown을 정본으로 저장하고, 기존 Delta 글은 변환기로 새 버전을 만든다. 원래 Delta 버전은 보존한다.
  - (B) Delta 저장을 유지하고 Markdown은 내보내기·가져오기 형식으로만 쓴다.
  - 정확 원문 버전, CAS, 영수증, 실패 복구 조항은 어느 쪽이든 유지한다.
- **최소 실험:** 익명 샘플 글로 Delta → Markdown → Delta 왕복을 돌려 잃는 속성(밑줄, 정렬, 사진 크기 등)의 종류와 개수를 센다. 그 결과로 A와 B를 고른다.
  - 실제 계정 글은 쓰지 않는다.
  - 바뀌지 않은 블록이 원문 바이트 그대로 다시 저장되는지 확인하는 회귀 사례를 함께 만든다.
- **재사용할 것:** 자료실의 읽기 전용 Markdown 보기(`source-markdown.js`)는 이미 markdown-it 15.0.3과 DOMPurify를 로컬에 두고 허용 태그·크기 제한·안전 링크 검사를 한다. 읽기 화면의 렌더러는 이를 먼저 재사용한다.
- **엔진 후보:** [편집기 비교](blog-editor-comparison.md)의 1순위인 Tiptap(ProseMirror)이다. 단일 편집 영역이라 블록을 넘는 선택과 iOS 편집 메뉴를 지키기 쉽다. Markdown 직렬화, 사진 노드, 자료 인용 노드, 한글 조합 처리는 실험으로 확인한다.
- **바꾸지 않는 것:**
  - 글쓰기 초안과 가져오기 초안의 분리
  - 열린 편집기의 미저장 입력과 한글 조합을 원격 반영으로 덮지 않는 규칙
  - 사진 공개 선택 기본 0개
  - HEIC 원본과 보기용 JPEG 함께 보관

## 미결·검증할 것

- `⋮⋮` 끌어서 옮기기의 키보드 대체 단축키 조합은 정하지 않았다.
- 표, 각주, 수식은 블록에서 뺐다. 필요한 글이 생기면 Markdown 왕복이 되는지부터 확인한다.
- iPad 편집 화면(손잡이와 터치를 함께 쓰는 폭)은 시안에 아직 없다.
- 실제 Mac·iPad·iPhone 확인, 한글 입력기(두벌식·천지인) 조합 확인, 소유자의 직접 쓰기·읽기 평가는 하지 않았다.
