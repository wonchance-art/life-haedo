# 글쓰기·읽기 개편 시안 — Markdown 파일, 블록 편집

2026-11-02. [전문가 기준](expert-design-brief.md)의 순서로 만든 개편 시안(부드러운 판) 가운데 글쓰기와 글 읽기 화면의 근거다. 시안 단계이므로 앱 코드는 바꾸지 않았다. 구현은 총괄의 작업 지시로 따로 진행한다.

사용자 요청: "obsidian 같은 마크다운인데 노션처럼 돌아가도록, 기본적인 구조만."
이 문서에서는 이 요청을 다음 두 가지로 해석했다.
- 저장되는 글은 Obsidian에서 그대로 열리는 Markdown 파일이다.
- 편집은 Notion처럼 블록 단위로 한다: `/` 메뉴, 손잡이, `[[` 연결.

## 사용 장면

- **시작:** 저녁에 Mac에서 `+ 글쓰기`를 누르거나, 일정·자료에서 하루를 골라 쓴다. 출근길 iPhone에서는 연필 버튼으로 짧게 쓰고, 이어서 다른 기기에서 고친다(계정 자동 동기화, 2026-11-01 소유자 지시).
- **입력:** 문단, 소제목, 목록, 체크, 사진 1~3장, 자료실의 발췌 인용, 예전 글로 가는 연결.
- **종료:** `저장`으로 새 판이 생기고, 같은 위치의 읽기 화면으로 돌아와 `n번째 판 저장됨`을 보인다. 뒤로 가기는 출발한 화면(예: `‹ 11월 2일`)으로 간다. 같은 글을 Obsidian 보관함에 넣으면 제목·속성·연결이 그대로 읽힌다. 공개는 여전히 따로 고르는 명시 동작이다.

## 결정

1. **상태는 읽기와 편집 두 가지뿐이다.**
   - 원문(Source) 모드는 화면에 두지 않는다.
   - 읽기에서 `편집`을 누르면 같은 위치에서 편집이 열린다. 편집에서 `읽기`를 누르면 저장하지 않은 입력을 유지한 채 미리 본다.
   - 두 상태에서 본문 폭(680px), 시작선(데스크톱 왼쪽 104px), 글자 크기, 사진 비율, 메타 줄 높이(28px)가 같다. 전환할 때 줄이 움직이지 않는다(1440에서 제목·첫 문단·소제목의 세로 위치가 같음을 측정).
   - 날짜는 편집에서도 테두리 없는 글자 버튼이다. 읽기와 같은 높이를 유지한다.
   - 읽기 화면의 체크 상자는 표시만 한다. 체크를 바꾸면 새 판이 생기므로 편집에서 바꾼다.
2. **글 파일은 Obsidian에서 그대로 열리는 Markdown이다.** 해도 안의 정본 저장 형식은 아래 「저장 형식 실험」 결과에 따라 따로 정한다.
   - 앞부분 속성: `title`·`date`·`tags`. 공개 여부는 파일에 넣지 않는다. 파일을 고쳐도 공개가 바뀌지 않으므로, 오해를 부르는 값을 두지 않는다.
   - 제목은 본문 H1이 아니라 별도 입력칸이다.
   - 본문은 표준 Markdown(CommonMark + GFM 체크)으로 쓴다.
   - 예시는 아래 「저장되는 파일」.
3. **블록은 Markdown으로 저장할 수 있는 것만 둔다.**
   - 문단, 제목(`##`), 작은 제목(`###`), 목록, 번호 목록, 체크, 인용, 코드, 구분선, 사진, 자료 인용, 글 연결.
   - 토글·열·글자색처럼 파일로 왕복할 수 없는 블록은 만들지 않는다.
4. **블록 표시는 줄을 밀지 않는다.**
   - 커서가 들어간 제목의 `##`는 데스크톱에서 왼쪽 여백에 걸린다. 본문 줄은 그대로 있다.
   - iPhone은 여백이 좁으므로 블록 표시를 숨긴다. 블록 종류는 도구 막대 `Aa`에서 보고 바꾼다.
   - 글자 안의 표시(`**`, `[[ ]]`)는 커서가 들어가면 그 자리에 보인다.
   - 한글을 조합하는 중에는 표시를 바꾸거나 블록을 변환하지 않는다.
5. **블록 조작:**
   - 데스크톱은 마우스를 올리거나 키보드 초점이 블록에 오면 `+`(아래에 블록 넣기)와 `⋮⋮`(블록 메뉴, 끌어서 옮기기)를 보인다. 포인터 전용이라 28×28px이다.
   - `⋮⋮` 메뉴: 종류 바꾸기, 위로(⌥⇧↑), 아래로(⌥⇧↓), 복제(⌘D), 자료 인용이면 `내 문단으로 바꾸기`, 삭제(⌫).
   - 터치 기기에서는 손잡이를 쓰지 않는다. `+`는 도구 막대에, 이동은 블록 메뉴의 위로/아래로 버튼에 둔다.
6. **`/` 블록 메뉴:**
   - 줄 맨 앞이나 공백 뒤에서만 열리고, 한글로 검색한다. Esc나 공백을 입력하면 닫힌다.
   - 한글을 조합하는 중에는 열지 않는다.
   - 순서는 고정한다. 기본(문단·제목·작은 제목·목록·번호 목록·체크·인용·구분선·코드)을 먼저 두고, 넣기(사진·자료 인용·글 연결)를 뒤에 둔다. 각 항목 오른쪽에 같은 결과를 내는 Markdown 입력을 보인다.
7. **Markdown 단축 입력은 표준 의미를 따른다.**
   - `## `, `- `, `1. `, `[ ] `, `> `(인용), `---`, ```` ``` ````, `[[`.
   - 자동 변환 바로 다음에 ⌘Z(실험에서 확인) 또는 ⌫를 누르면 입력한 글자로 돌아간다. iPhone은 ⌫를 쓴다.
8. **`[[` 글 연결:**
   - 글 제목을 검색해 제안한다. 선택한 글자를 `[[`로 감쌀 수 있다.
   - 없는 글은 자동으로 만들지 않고, `"…"로 새 글 만들기`(목록의 선택 항목)를 명시적으로 고를 때만 만든다.
   - 한글을 조합하는 중의 Enter는 조합을 끝내는 데만 쓰고 제안을 고르지 않는다.
   - 아직 없는 글로 가는 연결은 회색 점선으로 보이고, 누르면 새 글로 만들지 묻는다.
9. **자료에서 인용:**
   - 저장 형식은 `> [!quote] 출처` + 인용문 + `> [[원본#^위치]]` + `<!-- haedo:src=자료ID ver=판ID -->`이다.
   - 화면에서는 판이 고정된 잠긴 카드다. 출처와 자료실과 같은 판 표기(`v2`)를 보이고, 편집에서만 잠금 표시를 더한다.
   - 원문에 새 판이 생기면 카드 아래에 `원문에 v3이 있습니다 · v3으로 바꾸기`를 보인다. 저절로 바꾸지 않는다.
   - 고치려면 블록 메뉴의 `내 문단으로 바꾸기`로 원문 연결에서 분리한다. 원문 그대로의 인용과 내 글을 섞지 않는다.
   - 콜아웃을 지원하지 않는 앱에서는 인용으로 보인다.
10. **iPhone 도구 막대:**
    - 키보드 위에 고정하고, 순서는 `[+ 블록][서식][글 연결][자료 인용][사진][체크][들여쓰기] … [키보드 닫기]`다. 모두 같은 크기(20px)·굵기의 아이콘이다.
    - `+`를 누르면 키보드 자리에 블록 판이 열린다. 사진 블록을 고르면 도구 막대가 사진 도구로 바뀐다.
    - 블록·사진을 지우면 `되돌리기` 알림을 띄운다.
    - 폭이 모자라면 가로로 넘긴다.
    - 블록을 넘는 연속 선택과 iOS 기본 편집 메뉴(복사·붙여넣기·찾아보기)는 가로채지 않는다.
11. **읽기 화면:**
    - 본문은 17px, 줄 길이는 680px(한글 약 38자)로 제한한다. 제목 아래 한 줄에 날짜·시간·태그를 둔다.
    - 데스크톱 오른쪽에는 개요(소제목 2개 이상일 때), 이 글을 가리키는 글(문맥 한 줄), 인용한 자료(판 배지)를 둔다.
    - iPhone은 개요를 머리의 버튼으로 시트에 열고, 이 글을 가리키는 글과 인용한 자료를 본문 아래에 둔다.
    - iPad 세로(820)와 1100px 이하에서는 오른쪽 칸을 본문 아래로 내리고, 개요는 머리줄 버튼으로 연다.
    - 연결되지 않은 언급(unlinked mentions)은 보이지 않는다.
12. **글자 크기:**
    - 기존 단계를 따른다: 12 배지, 13 메타·상태, 15 조작·사진 설명, 17 본문·인용, 20 소제목, 28 데스크톱 글 제목, 24 iPhone 글 제목.
    - 사진 설명은 편집과 읽기 모두 15px이다. 하나의 편집 영역(본문 17px) 안에 있으므로 iOS 확대가 일어나지 않을 것으로 보지만, 실제 기기에서 확인한다.
13. **저장·동기화 상태 (2026-11-01 자동 동기화 규칙):**
    - 머리줄 상태는 `초안 · 저장 중`, `초안 · 모든 기기에 반영됨 09:12`, `초안 · 이 기기에만 있음 · 연결되면 올립니다`, `초안 · 저장 못 함 [다시 시도]`, 저장 뒤 `3번째 판 저장됨 09:14` 다섯 가지다. iPhone은 짧은 이름(`반영됨` 등)을 보이고, 누르면 시트에서 자세히 보인다.
    - 서버가 받기 전에는 `반영됨`으로 표시하지 않는다.
    - 다른 기기의 변경은 본문 위 한 줄 알림과 `불러오기`로만 알린다. 입력 중인 글자와 한글 조합은 바꾸지 않는다.
    - 두 기기 충돌은 최신 판을 남기고, 진 쪽을 복구 사본으로 보관한다. 알림에서 `복구 사본 보기`로 연다.
    - 저장하지 못한 채 화면을 나가도 입력은 이 기기에 남는다.
14. **공개 경계:**
    - 공개는 `⋯ → 공개하기`에서만 한다. 저장한 판으로 공개 사본을 만들고, 원본 글은 비공개로 남는다. 이후 고친 내용은 공개 사본을 갱신해야 반영된다.
    - 공개할 사진은 기본 0장이고, 고른 사진도 보기용 JPEG만 공개한다.
    - 읽기·편집 머리줄에 공개 상태(`비공개`·`공개 중`)를 보인다.
15. **아이콘:** 조작 20px, 글 안 16px 두 가지이고 선 굵기는 1.8 하나다(Lucide 1.51.0 모양). 같은 개념에는 같은 그림을 쓴다(자료 = 펼친 책, 인용 = 줄과 세로 바). 강조 버튼은 화면마다 하나다. 편집 화면에서는 `저장`이고, 왼쪽 메뉴의 `+ 글쓰기`는 지금 화면 표시로 바뀐다.
    - 인용은 본문보다 크게 하지 않는다. 세로 바로만 구분한다.

## 저장되는 파일

```markdown
---
title: 월요일 아침, 도서관 반납
date: 2026-11-02T09:12
tags: [도서관, 산책]
---

『도서관의 시간』 반납일이라 출근 전에 조금 돌아서 걸었다. …

![반납함 옆 은행잎](photos/2026-11-02-ginkgo.jpg "반납함 옆에 은행잎이 쌓여 있었다.")

## 반납하는 길

> [!quote] 『낮은 창』 42쪽
> 천천히 걸을 때만 보이는 골목이 있다.
> [[낮은 창#^p42]]
<!-- haedo:src=자료ID ver=판ID -->

지난주 [[목요일 저녁 산책]]에서 쓴 것과 같은 이야기다.

## 다음에 빌릴 책

- 4장과 5장 다시 읽기
- 『낮은 창』 나머지
- [ ] 11월 16일까지 반납
```

- 사진의 대체 텍스트는 `![…]`에, 사진 설명은 이미지 제목(`"…"`)에 둔다. 사진 파일은 글과 같은 묶음의 `photos/`에 둔다.
- iPhone HEIC 사진은 본문이 보기용 JPEG(`…-ginkgo.jpg`)를 가리키고, 원본은 같은 이름의 `…-ginkgo.heic`로 `photos/`에 함께 둔다. 내보내기에서 원본이 빠지지 않는다.
- 공개 여부는 파일에 쓰지 않는다. 공개는 지금처럼 해도 안의 명시 동작으로만 한다.
- `<!-- haedo:… -->` 주석은 다른 Markdown 앱에서 보이지 않는다. 해도에서는 원문 판을 다시 찾는 데 쓴다.

## 지금 앱과의 차이 (구현 전에 정할 것)

- **현재 저장 형식:**
  - 사진 글 편집기(`photo-post-ui.js`)는 Quill Delta(`photo` 삽입 포함)로 저장한다.
  - 직접 글쓰기(`writing.js`)는 `text/plain` 본문 버전이다.

- **선택지:**

  - (B) Delta 저장을 유지하고 Markdown은 내보내기·가져오기 형식으로만 쓴다.

- **실험 결과와 판단:** 아래 「저장 형식 실험」 절. 지금은 (B)를 권한다. (A)로 바꾸려면 그 절의 조건이 모두 갖춰져야 한다.
- **재사용할 것:** 자료실의 읽기 전용 Markdown 보기(`source-markdown.js`)는 이미 markdown-it 15.0.3과 DOMPurify를 로컬에 두고 허용 태그·크기 제한·안전 링크 검사를 한다. 읽기 화면의 렌더러는 이를 먼저 재사용한다.

- **바꾸지 않는 것:**
  - 글쓰기 초안과 가져오기 초안의 분리
  - 열린 편집기의 미저장 입력과 한글 조합을 원격 반영으로 덮지 않는 규칙
  - 사진 공개 선택 기본 0개
  - HEIC 원본과 보기용 JPEG 함께 보관

## 저장 형식 실험 — Quill Delta ↔ Markdown (2026-11-02)

임시 폴더에서 익명 샘플로만 한 실험이다. 저장소와 DB는 건드리지 않았다.

- **방법:**
  - 지금 사진 글 형식(`life-photo-post-v2`)의 허용 속성은 굵게, 기울임, 밑줄, 제목 1·2, 인용, 목록, 가운데 정렬, 링크, 사진(id·alt·caption)이다. 이 속성을 모두 담은 샘플 31개를 만들었다. 합성 24개, tests 픽스처 5개, 편집기 동작 재현 2개다.
  - 무작위 문서 1,500개를 추가로 만들었다.
  - vendor Quill 2.0.3에 앱의 사진 블롯을 붙여 headless Chromium에서 정규화한 뒤, Delta끼리 비교했다.

| 변환 방식 | 같은 Delta로 돌아옴 | 두 번 돌려도 같은 Markdown |
| --- | --- | --- |
| 설계 매핑 그대로 | 11/31 | 24/31 |
| 표준 Markdown(이스케이프 포함) | 17/31 | 29/31 |
| 확장(`<u>`, 정렬 주석, `&nbsp;` 문단, 강조 HTML 대체) | 29/31 | 31/31 |
| 정확(확장 + 공백 위치 유지) | 31/31 · 무작위 1500/1500 | 31/31 · 1500/1500 |

- **표준 Markdown이 잃는 것:**
  - 밑줄
  - 정렬(문단·목록·사진)
  - 빈 문단
  - 겹친 굵게·기울임 범위
  - 닫는 문장부호 바로 뒤에 한글이 오는 강조(`**"천천히"**라고`). 서식이 사라지고 `**`가 글자로 남는다.
- **빈 문단은 실제 글에 흔하다.** 지금 편집기는 사진을 넣을 때마다 빈 문단을 만든다. 자료 인용 초안에도 항상 하나 들어간다.
- **본문 밖 정보는 Markdown에 들어가지 않는다:**
  - 사진: 이름, 형식, 해시, 크기, HEIC 보기용 사본
  - 문서: 첨부, 상태, 보관, 대체 관계, 판
  - 이런 정보는 앞부분 속성이나 별도 파일로 옮겨야 한다.
- **평문 글(`text/plain`):** 줄 첫머리의 `#`·`>`·`- `·`1.`·`---`, 들여쓰기, 줄바꿈 하나 같은 것이 Markdown으로 읽으면 의미가 바뀐다.
  - 줄머리·인라인 이스케이프와 줄 끝 `\` 규칙을 쓰면 무작위 20,024개 중 20,022개가 같은 글로 돌아왔다.
  - 실패 2개는 입력칸에서는 생기지 않는 세로 탭 문자였다.
- **판단: (B)를 권한다.** Delta를 정본으로 두고, Markdown은 「정확」 변환기로 내보내기·가져오기에만 쓴다.
  - 표준 Markdown만으로는 기존 글의 서식 일부가 사라진다.
  - 손실을 없애려면 HTML·주석이 필요하다. 그런데 재사용할 읽기 렌더러(`source-markdown.js`)는 `html:false`라서 `<u>`가 글자로 보인다.
- **(A)로 바꿀 조건(모두 필요):**
  1. 운영 글에서 밑줄·정렬·빈 문단을 쓴 글 수를 센다. 개수만 세는 읽기 전용 SQL [`supabase/operations/photo-post-format-count.sql`](../../supabase/operations/photo-post-format-count.sql)을 준비했다. 격리 PostgreSQL 16에서 합성 글 29개·공개 사본 3건으로 계산 일치(차이 0건)와 읽기 전용 트랜잭션의 삭제 거부를 확인했다. 운영 DB 실행은 총괄 세션만 한다.
  2. 그 서식을 확장 문법으로 남기거나 버리는 것을 소유자가 승인한다.
  3. 읽기 렌더러가 확장 문법을 안전하게 허용한다.
  4. 사진 뒤 빈 줄의 처리를 정한다.
- **새 편집기와의 관계:** 이 시안의 블록 목록에는 밑줄·정렬이 없다. 새로 쓰는 글은 표준 Markdown으로 손실 없이 저장된다. 문제는 기존 글뿐이다. 밑줄·가운데 정렬을 새 편집기에서 뺄지는 소유자가 정한다.

## 편집 엔진 실험 — Tiptap 3 (2026-11-02)

임시 작업 폴더에서 한 실험이다. 앱 코드와 저장소는 바꾸지 않았다. 위 「저장되는 파일」의 예시 글을 시험 문서로 썼다.

- **대상:** `@tiptap/core`·`@tiptap/markdown` 3.32.2(2026-10-30 배포)이다. 설치한 53개 패키지는 모두 MIT이고 `npm audit` 결과는 0건이다. Markdown 변환은 marked 17.0.6을 쓴다.
- **번들:** esbuild로 만든 IIFE 하나가 min 492,588B, gzip 156,167B다. Link를 빼면 gzip 141,947B다. 일반 `<script>`로 불러와 동작한다.
  - Tiptap은 바로 쓸 수 있는 UMD 파일을 배포하지 않는다. 그래서 vendor에 공식 파일을 그대로 두는 지금 방식(markdown-it 등)과 다르다. 빌드 명령, lock 파일, 해시를 함께 기록해야 한다.
  - 현재 vendor의 `quill.js`(209KB)보다 크다.

| 시험 | 결과 | 근거 |
| --- | --- | --- |
| 1. 예시 글 왕복(기본 확장) | 실패 | `> [!quote]`·`[[…]]`는 `\[` 이스케이프로 바뀌었다. HTML 주석은 빈 문단이 됐다. 체크 항목은 목록이 둘로 갈라져 빈 줄이 생겼다. |

| 2. 고치지 않은 블록 보존 | 통과(직접 만든 확장) | 한 문단만 고쳤을 때 7블록 중 그 블록만 달라졌다. 기본 확장에서는 5블록이 달라졌다. |

- **직접 만든 확장(약 150줄):**
  - `[[ ]]` 인라인 노드
  - 원문 바이트를 지키는 잠긴 인용 카드(콜아웃 + haedo 주석)
  - 단독 HTML 주석
  - 목록·체크 저장 보정
  - `/`·`[[` 제안
- **채택 조건으로 함께 정할 것:**
  1. 편집기마다 `Marked` 인스턴스를 따로 둔다. 기본 설정은 전역 marked에 규칙을 쌓아, 다른 편집기에서 `[[…]]`가 지워지는 누수를 실제로 재현했다.
  2. 줄머리 기호를 이스케이프한다. 지금은 문단에 글자로 남긴 `## `·`- `·`1. `·`---`가 다시 열면 제목·목록·구분선이 된다.
  3. 잠긴 카드를 보호한다. 지금은 카드를 고른 채 글자를 치면 카드가 사라진다(실행 취소로는 복구된다).

  5. 읽기 화면은 markdown-it, 편집기는 marked를 쓴다. 콜아웃·`[[ ]]` 규칙이 두 번 구현되므로 같은 시험 문서로 표시 결과를 맞춘다.
- **판단:** 엔진 후보로 유지한다. 블록 편집, 실행 취소, 조합 중 메뉴 억제, 블록을 넘는 선택은 기본으로 동작했다. 실패는 모두 Markdown 저장 쪽에서 나왔고, 위 조건을 지키면 예시 글의 바이트 동일을 지킬 수 있었다.
- **미검증:**
  - 실제 Mac·iPad·iPhone의 한글 입력기와 Safari
  - iOS 터치 선택·편집 메뉴, VoiceOver
  - 긴 글 성능, 붙여넣기
  - 사진 Blob·HEIC 연결, 동기화·CAS 연결

  - `[[` 새 글 만들기를 선택 항목으로 바꾸고 조합 중 Enter 규칙을 정했다.
  - 이름을 `자료 인용`·`저장`으로 통일했다.
  - iPhone 편집에 `+ 태그`와 날짜 줄을 넣었다.
  - iPhone 읽기 끝에 인용한 자료를 더했다.
  - 읽기 화면의 체크를 표시 전용으로 정했다.
  - 읽기 화면 인용의 잠금 표시를 뺐다.
- **그대로 둔 것:** iPhone 뒤로 꺾쇠(왼쪽 6px)와 가운데의 저장 상태는 정렬 기준의 예외다. 시스템 탐색 막대와 같은 자리이기 때문이다.

## 미결·검증할 것

- 자료실에서 인용할 자료를 고르는 화면, 자료실의 `인용`으로 들어올 때 넣을 글을 고르는 화면은 시안에 없다.
- 사진 변환 실패, 여러 장 넣기, 변환 중 저장은 시안에 없다.
- 긴 글의 이어 읽기 위치는 기존 `reading-position` 계약을 따르며, 시안에 따로 그리지 않았다.
- `⋮⋮` 단축키(⌥⇧↑↓, ⌘D)가 브라우저·입력기 단축키와 겹치지 않는지 확인하지 않았다.
- 표, 각주, 수식은 블록에서 뺐다. 필요한 글이 생기면 Markdown 왕복이 되는지부터 확인한다.
- iPad 편집 화면(손잡이와 터치를 함께 쓰는 폭)은 시안에 아직 없다.
- 실제 Mac·iPad·iPhone 확인, 한글 입력기(두벌식·천지인) 조합 확인, 소유자의 직접 쓰기·읽기 평가는 하지 않았다.
