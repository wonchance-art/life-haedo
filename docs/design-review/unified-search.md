# 한 입구에서 비공개 자료 다시 찾기

2026-10-13 UTC. 디자인·구현·통합 책임자 Codex. #74 `codex/two-cycle-integration`의 `45cc9c42` 위에 쌓는 후속이며 main 병합·운영 SQL·배포는 Local 담당이다.

## 목표와 직접 체험

기억나는 말로 검색 → 자료 종류와 일치 이유 확인 → 정확한 항목 열기 → 같은 검색어·필터·펼친 결과·초점·스크롤로 돌아오기. 별도 검색 인덱스나 화면마다 다른 검색 메뉴를 늘리지 않는다.

`npm run dev` 후 기존 인증 설정의 테스트 계정으로 로그인한다. 홈 상단 돋보기 또는 `index.html?section=records&view=find`에서 시작한다. 기존 `life.html?view=find` 주소도 지원한다.

1. 같은 단어가 있는 원문, 내 페이지 저장 글, 컬렉션을 준비한다. `산책`처럼 기억나는 말을 입력한다.
2. 전체 결과는 종류별 첫 5개, 한 종류는 첫 20개를 보여준다. 더 보기는 20개씩 늘린다. 검색 범위 전체에서 센 결과 수이며 표시 수와 다르다.
3. 원문 결과는 **그 버전과 실제 일치 구절**을 연다. 발췌·메모·주제 일치는 연결된 정확 버전으로 간다. 제목이 바뀌었으면 현행 원문 제목이 표시되며 과거 제목 이력을 만든 것은 아니다.
4. 페이지 글은 해당 글을 펼쳐 읽는다. 수정 초안을 자동 생성하지 않는다. 구성 항목의 코멘트는 해당 항목 편집 영역을 펼친다. ‘표시 꺼짐’ 항목도 비공개 검색 대상이다.
5. 컬렉션은 해당 상세 화면을 연다. 검색 복귀 전에 수정 중인 입력의 기존 저장/취소 절차를 지킨다. 화면 복귀가 저장 성공을 뜻하지 않는다.
6. 검색 결과로 돌아와 이어서 고른다. 계정/작업공간을 바꾸면 이전 검색어·필터·결과를 지운다. 새로고침 후 검색어를 복원하는 기능은 아니다.

## 범위·보존·실패 처리

- 현재 계정·작업공간의 보관 원문과 버전, 연결 발췌·메모·주제, **저장한** 페이지 글/첨부·구성 코멘트, 컬렉션 제목/창작자/주제/개인 메모/세부 정보/출처를 검색한다.
- 작성 중 초안, 책 원고, 공개 서버 사본은 제외한다. 페이지의 ‘공개 후보’ 표시는 서버 게시 완료가 아니다. 보관한 컬렉션은 옵션을 켰을 때만 포함한다.
- 기본은 문자 그대로 검색이다. 한글 띄어쓰기 무시는 선택적 수평 공백 일치이며 원문을 정규화하지 않고 실제 UTF-16 구간을 사용한다. 유사도·의미·AI 추천으로 표현하지 않는다.
- 검색어는 URL, 영속 저장, 외부 요청에 넣지 않는다. 읽기 전용 결과 모델은 자료·구성·컬렉션·초안을 변경하지 않는다. 화면 열기의 기존 로컬 읽기 위치 메타데이터와 자료 본문은 별도다.
- 세 저장소를 따로 읽는다. 하나가 실패해도 다른 결과를 유지하고 실패 범위와 재시도를 표시한다. 늦은 읽기 응답은 다른 화면이나 작업공간으로 들어오지 못한다. 변경 알림은 입력을 덮어쓰지 않고 ‘다시 읽기’를 제시한다.
- 항목 열기 전 현재 자료를 확인하며 삭제된 목적지를 다른 항목/최신 버전으로 바꾸지 않는다. 기존 저장 실패 이동 차단·충돌 복구·백업·동기화·공개 계약을 재사용한다. 저장 형식·운영 SQL 변경 없음.

[공식 배포·라이선스 비교](../life-tools-design/open-source-review.md#통합-비공개-검색--2026-10-13-utc): MiniSearch 7.2.0/MIT, Fuse.js 7.5.0/Apache-2.0을 검토하고 기존 정확 문자 검색을 재사용했다. 새 의존성은 없다. 자체 구현은 교차 저장소 결과 투영과 화면 수명/복귀 처리를 맡는다.

## 기능 검증

Linux Chromium **151.0.7922.173**, Playwright **1.63.0**. 익명 모의 Auth, 실제 계정별 IndexedDB. 원문 25개/26버전, 페이지 글 1개/구성 1개, 컬렉션 24개와 별도 비공개 초안을 저장 API로 준비했다. 준비 자료의 UI 가져오기를 이번 검사에서 수행했다고 보고하지 않는다.

- 정적 검사: HTML **18** / JS **72** / 로컬 참조 **320** / PWA 통과. Node **436/436**(신규 검색 모델 6개 포함).
- [검색 전 과정](evidence/unified-search/report.json): **9/9**, console/pageerror/외부 요청 **0**. 정확 과거 버전·한글 원문 위치, 결과별 왕복, 펼친 결과 유지, 비공개 초안 제외, 읽기 실패·재시도, 늦은 응답 무효화, 다른 계정의 독립 세션, UI 작업공간 전환을 확인했다. 자료 전체 snapshot으로 검색과 읽기 후 저장 내용 보존을 대조했다.
- 관련 브라우저 회귀: 기존 검색 **7**, 홈 **16**, 하위 화면 왕복 **11**, 페이지 작성 **13**, 컬렉션 **12** 통과. 페이지 저장 실패·동시 수정 충돌·사본 복구는 기존 페이지 작성 검사에서 확인했다.
- 공개 산출물 플랫폼 **9/9**: 익명/다른 계정 차단, 기존 가져오기·발췌·백업 새 사본 복원, 실패한 저장 중 이동/로그아웃 차단, 오프라인/재인증, **SW v98 → v99** 갱신과 기존 자료 보존. 의도적 전송/콜백 실패 3건은 별도다.
- GitHub 고정 Chromium 다운로드는 Cloud 네트워크 정책으로 차단되어 로컬 151을 사용했다. GitHub CI의 전체 고정 브라우저 결과는 후속 PR의 최종 커밋 checks로 별도 확인한다. 이전 #74 CI를 이번 변경의 증거로 대신하지 않는다.

## Local 인계·다음 우선순위

1. Local 변경을 보존하고 **#74 → 이 검색 후속 PR** 순서로 통합한다. 후속 PR의 base는 `codex/two-cycle-integration`이다. #74가 squash 병합되면 중복 과거 커밋이 보일 수 있으므로 main 기준 차이를 재정리해 검토한다. 선행 개별 PR들을 다시 중복 병합하지 않는다.
2. #74 문서의 기존 #71 게시 글 SQL 설치 확인을 따른다. **이번 검색은 추가 SQL 없음.** 과거 합성 운영 검사를 재실행하지 않는다.
3. 최종 check/browser 성공, 새 검색 모듈의 공개 산출물 포함, SW v99를 확인한다. Local에서 병합·배포하고 로그인·돋보기·세 종류 정확 항목·검색 복귀·기존 캐시 갱신을 라이브에서 확인한다. 운영 자료를 테스트 샘플로 바꾸지 않는다.
4. iPad/iPhone/Mac에서 실제 찾기 작업으로 입력 부담·첫 결과 도달·뒤로 가기를 확인한다. 기기/브라우저, 막힌 단계, 기대/실제 결과를 남긴다. 검색 지연이 체감되면 익명 표본과 측정으로 다음 최적화를 정한다.
5. 다음 Cloud 우선순위: **실제 사용에서 막힌 검색·탐색 개선 → 회고의 출력 선택 발견성 → 수집 입력 개선**. 자동 SNS 연결·AI 전송·책 확장은 별도 범위다.
