# 이 브라우저의 내 글 찾기

2026-10-20 · 읽기 전용 점검 설계. 실제 글의 발견·복구는 아직 확인하지 못했다.

## 목표와 현재 근거

- 사용자가 같은 브라우저에서 기존 홈·글 관리·초안·보관함을 확인했지만 찾지 못한 글이 있다.
- 현재 계정의 서버 블로그 보관 목록과 이전 글쓰기 경로에서도 원글을 확인하지 못했다.
- 이 관찰만으로 삭제·미저장·계정 오류·목록 손상 중 어느 원인인지 확정하지 않는다.
- 기존 홈과 글 관리는 `listPhotoPosts()`의 요약 목록을 사용한다. 본문 레코드와 요약을 독립 대조하는 별도 읽기가 필요하다.
- 목적은 현재 계정에서 읽을 수 있는 브라우저 자료를 점검하고, 찾은 후보를 직접 읽거나 선택해 파일로 보관하는 것이다.

## 범위와 보존 조건

- 현재 origin·브라우저 프로필에 있는 기존 앱 DB만 대상으로 한다. 다른 브라우저·기기·과거 origin·삭제된 저장소는 조사하지 못한다.
- 기본 범위는 현재 검증된 계정 소유의 모든 작업공간이다. 작업공간 선택·활성 공간 키는 바꾸지 않는다.
- 계정 미연결 자료는 별도 명시 옵션으로만 포함하며 기존 무소유·소유권 검사와 계정 전환 가드를 재사용한다.
- 다른 계정 소유 공간은 검색·개수·제목·본문·결과에 포함하지 않는다. 이메일로 소유자를 추정하지 않는다.
- 모든 스캔·미리보기·내보내기는 읽기 전용이다. 요약 재생성·재저장·새 사본 설치·서버 조회·동기화·공개를 자동 실행하지 않는다.
- DB 버전·스키마·기존 키·문서 ID·revision·원문 버전·사진 Blob을 변경하지 않는다.

## 최소 읽기 계약

1. 인증 범위를 고정한 뒤 기존 저장소의 `readonly` 트랜잭션과 커서로 허용 작업공간을 순회한다.
2. PhotoPost 본문 레코드와 요약 목록을 각각 읽어 정상 일치·요약 누락·요약만 존재·값 불일치를 구분한다.
3. 본문은 기존 `PhotoPost.validate()`로 검증한다. 손상 레코드를 정상 글로 추정하거나 검증 실패를 조용히 제외하지 않는다.
4. 기존 `Writing.isOwnSource()`의 엄격한 내 글 판정, 첨부 글 `page.posts`, 해당 글쓰기 초안과 PhotoPost 초안·보관 상태를 함께 조사한다.
5. 후보 제목 검색은 원문을 바꾸지 않는 읽기 투영이다. 후보 선택 시 정확 버전을 다시 검증하며 옛 본문을 최신판으로 대체하지 않는다. 제목 없는 첨부 글은 본문 첫 유효 줄 최대 200자를 제목으로 표시한다.
6. 커서는 순차 처리하고 결과 DOM은 제한해 표시한다. 결과 더 보기는 읽은 범위·검색 대상의 누락으로 표현하지 않는다.
7. 완료·부분 실패·중단을 구분해 조사한 공간과 실패 범위를 표시한다. 실패한 읽기를 0건으로 합산하지 않는다.
8. 계정·화면 전환이나 늦은 결과는 기존 scope/epoch 검사로 차단한다. 이전 계정의 후보·미리보기·Blob URL은 정리한다.

## 사용 흐름과 실패 복구

- 사용자가 점검을 시작하면 현재 범위와 읽기 전용임을 안내하고, 작업공간·글 종류·상태·요약 대조 결과로 후보를 구분한다.
- 후보 선택 후에만 본문·첨부·사진 미리보기를 연다. 미선택 전체 본문이나 사진을 DOM에 한꺼번에 만들지 않는다.
- 원본 문서의 저장 상태와 검증 결과를 유지한다. 읽기 화면에 쓰기 작성기를 붙여 자동 저장을 일으키지 않는다.
- 파일 보관은 직접 고른 후보에만 적용한다. PhotoPost는 기존 `backup()` 및 `Blog.hydrate()` 검증 계약을 재사용한다.
- 내보낸 파일은 별도 보관 사본이며 기존 DB를 복구했다는 뜻이 아니다. 형식별 포함·제외 범위와 원본 사진 포함 여부를 미리 표시한다.
- 읽기·검증·다운로드 실패 시 후보와 오류를 남겨 재시도한다. 손상 자료의 임의 정규화나 자동 수리는 하지 않는다.
- 검색 결과 없음은 “이 범위에서 확인하지 못함”이다. 원본이 어디에도 없거나 영구 삭제됐다는 판정으로 표시하지 않는다.

## 재사용과 공식 근거

- 신규 프레임워크·DB 라이브러리는 도입하지 않는다. 동봉 `vendor/idb`의 커서, 기존 계정 scope, 모델 검증·백업과 native DOM을 재사용한다.
- 2026-10-20 확인: [MDN 공식 소스 — openCursor](https://github.com/mdn/content/blob/main/files/en-us/web/api/idbobjectstore/opencursor/index.md)는 커서 순회와 키 범위 조회를 설명한다. 종료의 `null`과 요청 실패를 구분한다.
- 같은 날 확인: [MDN 공식 소스 — transaction mode](https://github.com/mdn/content/blob/main/files/en-us/web/api/idbtransaction/mode/index.md)는 `readonly`에서 자료를 읽을 수 있고 변경할 수 없음을 명시한다.
- 이 근거는 읽기 API 선택을 뒷받침한다. 실제 구현이 쓰지 않는다는 보장은 트랜잭션 모드·쓰기 호출 감시와 전후 자료 대조로 별도 검증한다.

## 완료 기준과 검수 상태

- 합성 자료로 요약 없는 정상 본문, 요약만 남은 항목, 손상 본문, 기존 글 형식, 초안·보관 글, 정확 원문 버전을 재현한다.
- 계정 A/B·무소유 명시 옵션·여러 공간·전환 중 늦은 결과·부분 읽기 실패에서 범위와 상태를 확인한다.
- 읽기 전용 트랜잭션·쓰기 0·활성 공간 불변, 선택 파일의 본문·정확 버전·원본 사진 바이트 보존을 확인한다.
- 실제 UI의 시작→검색→선택 읽기→선택 내보내기·실패 재시도와 모바일/데스크톱 접근성을 별도 검수한다.
- 위 항목은 검수 계획이다. 자동 검증 통과와 사용자 개인 글의 실제 발견·복구 여부를 같은 결과로 보고하지 않는다.
- 최종 구현 범위·실행 결과·미검증 한계는 통합 검수 후 추가한다.
