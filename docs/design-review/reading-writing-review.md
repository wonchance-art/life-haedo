# 읽기·글쓰기 독립 경험 검토

2026-10-07. 기준 사이트 `dd7031c`, 익명 모의 계정·실제 IndexedDB, 시스템 Chromium의 1440×900 / 820×900 / 390×900 뷰포트로 검토했다. 실제 Apple 기기·한글 IME·운영 인증 검증은 아니다. 디자인 책임자는 주 작업 에이전트이며 이 검토는 앱 파일을 수정하지 않았다.

## 확인한 문제와 우선순위

1. **긴 초안의 작업 위치가 사라진다.** 390×844에서 40문단 초안의 중간에 커서를 두고 `도구 → 기록`으로 돌아왔다. 본문은 보존됐지만 textarea 내부 스크롤이 970 → 0px, 커서는 UTF-16 위치 620 → 1989(본문 끝)로 바뀌었다. 보이는 부분과 다음 입력 위치가 달라 계속 쓰기 전에 위치를 다시 찾아야 한다. 세션 안의 초안별 선택·스크롤 보존을 우선한다. 재현: `.local/experience-review/interaction.cjs`, 측정: `interaction.json`.
2. **긴 제목 전체를 확인하기 어렵다.** 모바일 단일 행 제목 입력에서 약 20자 뒤가 잘린다. 입력값 손실은 없으나 제목을 읽고 고치려면 가로로 커서를 이동해야 한다. 기존 native 입력·한글 조합 계약을 보존하면서 여러 줄 제목을 허용하는 것이 작은 개선이다. 줄바꿈을 저장 제목에 어떻게 처리하는지는 구현 시 명시해야 한다.

## 유지할 부분

읽기 화면의 한 열 본문, 한 번만 나오는 제목, 간단한 출처·버전 표시, 위아래 `함께 읽을 기록` 진입은 현재 목적에 맞는다. 기존 흰 읽기 표면·옅은 라벤더·A 인용 아이콘을 유지하고 추가 프레임이나 설명 패널을 만들 필요는 없다.

글쓰기 본문은 모바일 492px, 넓은 화면 519px 높이의 textarea 안에서 긴 본문을 스크롤한다. 이것 자체를 결함으로 보지는 않는다. 자동 확장은 저장 조작까지의 거리를 늘리고, 높이 축소는 편집 가능한 본문 공간을 줄인다. 이번에는 제목 검토와 초안 복귀의 재현 가능한 문제를 먼저 해결한다.

## 근거와 한계

동일한 core-experience 익명 한글 원문과 별도 30문단 초안으로 변경 전 `records`, `reader`, `write`, `long-write`를 각 3폭에서 캡처했다. 증거는 `.local/experience-review/before-{scene}-{width}.png`, 스크립트는 `review.cjs`, 측정은 `baseline.json`이다. 로컬 증거는 개인 자료를 포함하지 않으며 운영 계정이나 DB를 사용하지 않았다.

기능 회귀 통과와 이 시각·사용 흐름 판단은 별개다. 뷰포트 모사를 실제 Mac/iPad/iPhone 사용성 또는 지속적인 사용 가치의 증명으로 해석하지 않는다. 변경 후 결과는 아래에 구분한다.

## 변경 후 확인

글쓰기 수정 후 동일한 독립 재현을 4184에서 다시 실행했다. `도구 → 기록` 복귀 후 textarea 스크롤은 970 → 970px, 선택 시작·끝은 620 → 620으로 보존됐다. 근거: `.local/experience-review/after-interaction.json`. 이는 같은 열린 앱 세션의 복귀 검증이며 새로고침·다른 기기에서의 편집 위치 보존을 약속하지 않는다.

제목 변경은 native textarea의 시각적 줄바꿈을 사용하고, 실제 값에서는 CR/LF를 제거해 이전 단일 행 제목 계약을 유지한다. 입력 조합 중 정규화는 보류하고 최대 500자를 유지한다. `기록에 저장` 문구는 자동 초안 보관과 명시적인 기록 저장을 구분한다. 이 문단은 코드 검토 결과이며 실제 IME 사용 검증은 아니다.


최종 동일 샘플 12장(`기록`, `읽기`, `빈 글쓰기`, `긴 글쓰기` × 3폭)을 한 번 캡처했다. 독립 검토자는 긴 글쓰기 세 폭과 390px의 기록·읽기·빈 글쓰기 화면을 직접 확인했다. 긴 제목은 390px에서 높이 130px로 전체를 보여주며, `기록에 저장` 버튼은 98.33×44px로 상태와 같은 행에 유지된다. 본문 입력 높이 492/519px는 보존된다. 읽기 화면에는 새로운 프레임·색 면이 생기지 않았다.

- 같은 긴 제목·본문의 [변경 전 390px](evidence/reading-writing-quality/before-long-write-390.png) / [변경 후 390px](evidence/reading-writing-quality/after-long-write-390.png).
- [최종 표면 측정](evidence/reading-writing-quality/visual-report.json): 읽기·긴 글쓰기 6개 상태에서 가로 넘침 없음, 44px 미만 조작·16px 미만 입력·이름 없는 조작·텍스트 대비 실패 없음. 측정한 최소 텍스트 대비 6.05:1. 이 측정은 전체 앱 접근성 인증이 아니며 키보드 이동 경로를 자동 검증한 결과도 아니다.
- [독립 초안 복귀 측정](evidence/reading-writing-quality/editor-return-review.json): 스크롤 970px와 선택 위치 620 보존.

짧은 샘플의 읽기·기록 화면은 시각적 회귀가 없고, 긴 제목 개선은 새 표면을 추가하지 않고 실제 입력 확인 문제를 해결한다. 이번 검토에서 추가적인 재스타일 필요는 발견하지 않았다.

최종 제목 CSS의 `word-break: keep-all; overflow-wrap: anywhere` 반영 후 긴 글쓰기 세 폭만 한 번 갱신했다. 390px의 `다시`, 820px의 `문장으로`가 단어 중간에서 나뉘지 않는 것을 직접 확인했다. 제목 높이·저장 버튼 크기와 위의 표면 측정 결과는 동일하다. 대표 390px 이미지와 표면 측정 파일도 최종 CSS 결과로 교체했으며 다른 화면은 다시 캡처하지 않았다.
