# 장별 생각과 근거

2026-10-08 KST. [책 프로젝트](book-projects.md)의 다음 단위로, **직접 쓴 해석 → 뒷받침하는 글·다른 관점 → 아직 모르는 점 → 수정·제외·복원 → 책 원고**를 연결했다. 원문을 읽으며 생각의 변화를 정리하는 도구이며, 자동 분석·AI 보고서·성격 진단은 아니다. root가 디자인·UI를 통합하고 모델/SQL/독립 QA/공식 참고 조사를 분담했다.

## 사용 흐름과 설계 선택

Local 적용 후 도구 → 책 만들기 → 책/장 → **생각과 근거**를 펼친다. ‘생각 추가’를 누르면 빈 해석 초안부터 보관하고 ‘지금의 생각’과 ‘아직 모르는 점’을 자동 저장한다. 별도 긴 입력 폼을 제출하기 전까지 보관하지 않는 방식을 피했다. 빈 문자열은 초안이며 가짜 해석을 기본값으로 넣지 않는다.

근거와 다른 관점은 각 목록에서 원문 버전을 직접 고른다. 내 글·타인 글·작성자 미확인, 작성일·확보 범위·누락을 표시하고 책 아이콘으로 정확한 원문을 다시 연다. 20개씩 더보기는 표시만 제한하며 두 역할의 표시 개수와 원문 복귀 초점을 독립 유지한다. 같은 글의 옛 버전과 새 버전을 연결할 수 있고 같은 버전도 양쪽 역할로 쓸 수 있다. 다만 **서로 다른 구절을 지정한 것은 아니다.** 이번 근거 단위는 원문 버전 전체이며 문장별 인용/발췌 locator는 후속이다.

장 전체의 근거와 개별 생각의 근거는 독립적이다. 장 목록에서 원문을 빼도 그 글을 참조한 해석과 역할 목록을 몰래 바꾸지 않는다. 연결만으로 해석이 입증됐다고 표시하거나 반례 개수·기록 개수를 확신/성장 점수로 바꾸지 않는다. 자료가 없는 기억부터 적어도 되며 ‘아직 연결한 근거가 없음’과 ‘반례를 아직 찾지 못함’을 구분한다.

‘원고에서 제외’는 해당 구조화 해석을 Markdown에서 빼는 조작이다. 내용과 연결은 남고 **제외한 생각 → 생각 복원**으로 되돌린다. 원문 삭제·전역 분석 제외·동기화 제외가 아니다. 사용자가 장 원고에 이미 쓴 같은 문장을 지우지 않으며, 다른 활성 해석이나 장 전체에 같은 글을 별도 연결했다면 그 선택도 유지한다. UI와 내보내기 범위 설명에 이 차이를 남겼다.

기존 한 열 원고 아래에 접힌 패널을 두고 한 생각씩 편집한다. 현재 해석은 작은 민트 입력면, 다른 관점과 모르는 점은 기존 흰 표면을 쓴다. 설정 프레임·최상위 메뉴·새 편집기·AI API를 추가하지 않았다. [Taguette·Hypothesis 공식 비교](../life-tools-design/open-source-review.md)는 원문/주석 분리와 명시 선택만 참고하며 런타임을 도입하지 않은 이유와 후속 조건을 기록한다.

## 보존 계약

기존 `chapter`에 optional `insights`만 추가했다. 각 항목은 `id`, `statement`, `uncertainty`, `supportVersionIds`, `counterVersionIds`, `excluded`다. 장당 100개(제외 포함), 각 역할 100개 정확 버전, 두 텍스트 각 20,000 UTF-16 단위이며 빈 초안을 허용한다. 전체 Workbench 2 MiB·전역 구성 ID 유일성·문자 검증은 유지한다. 두 목록 내부 중복은 거절하지만 역할 사이의 같은 버전과 없는 참조는 허용한다. 기존 v1과 `insights` 없는 책/장은 그대로 수용한다.

- 입력 중 DOM/value를 재설정하지 않는다. 대상 전환·제외/복원·원문 이동·내보내기는 저장을 마친 뒤 현재 책/장/해석을 확인한다. 저장 실패·충돌·계정/공간 변경 때 현재 문구를 보존한다.
- Markdown에는 제외하지 않은 해석과 역할별 정확 출처를 포함한다. 기본 원문 본문은 제외하며 기존 명시 본문 포함 선택을 유지한다. 해석·불확실성·자료 메타데이터는 안전한 코드 블록, 장 원고는 기존 Markdown 원값이다. 제외된 해석만 연결한 원문은 새로 내보내지 않는다.
- JSON 백업과 개인 구성 동기화는 **제외한 해석까지** 보존한다. 새 사본 복원에서 해석 ID와 두 역할 참조를 재매핑하며 다른 장/묶음/해석과 같은 누락 참조는 하나의 새 미연결 ID로 유지한다.
- 구성 충돌 비교에는 양쪽의 해석·아직 모르는 점·두 역할·제외 상태를 표시한다. 선택하지 않은 쪽의 복구 사본을 유지한다. 구형 서버/앱이 새 필드를 거절하면 내용을 버려 재시도하지 않는다.
- 원문·정확 버전·발췌 UTF-16 위치·기존 회고·장 원고·연표·공개 사본과 로그인 계약은 유지한다. 외부 AI 전송·SNS 쓰기·자동 공개는 없다.

## 검증과 화면

합성 계정·익명 한글 자료, 실제 앱/SDK/IndexedDB를 사용했다. 운영 Supabase와 개인 기록에는 접근하지 않았다.

- 정적 HTML18/JS56/참조265/PWA, 단위 **348/348** 통과. 새 해석 모델/제외/내보내기/백업 10개와 기존 원격·재시도 검사에 해석 보존 사례를 포함했다.
- 신규 브라우저 **7/7**: 3폭 생성·입력·정확 원문·장 근거 독립성·제외/복원·책 파일, 실제 IDB 실패/경쟁 저장 비교, JSON 새 사본, 계정/공간 분리, 각 역할 21번째 원문 복귀. 콘솔/페이지 오류·외부 요청·운영 쓰기 0.
- 기존 구성 동기화 전체 **9/9**: 활성/제외 해석 양쪽 비교, 선택하지 않은 쪽 복구 JSON·새 사본 ID/역할/공통 누락 참조 재매핑·자료 선행·중지·계정 경계. [보고](evidence/book-insights/composition-browser.json).
- 격리 PostgreSQL17.11: 기존163 + 책109 + 해석80, 설치11 + 12 + 13, 실제 JS/SQL 차등134 통과. 선행 책 SQL 미설치 차단, 적용/재적용 전후 기존 자료·함수 OID/owner/ACL·메타데이터 보존. [보고](evidence/book-insights/sql-report.json). 16,000개 빈 해석(1.82 MB)의 단일 로컬 실험에서 전역 ID 중복검사를 한 번 집계해 5.14초→1.41초로 줄였으며 운영 지연을 보장하는 수치가 아니다.
- root와 독립 QA가 화면을 직접 검토했다. 1440·820·390px의 긴 해석/여러 근거/빈 상태/저장 오류에서 가로 넘침·44px 조작·16px 입력·접근 이름·대비 위반 0, 최소 글자 대비6.05:1. 자동 지표가 해석의 유용성이나 미적 품질을 증명하는 것은 아니다.

## Local 인계와 다음 단위

PR #46 뒤의 후속, 캐시 **v80**. Cloud는 SQL 설치·병합·배포를 하지 않았다.

1. 구성 SQL과 PR #46의 책 validator 확장이 먼저 설치돼 있어야 한다. 이미 설치한 선행 SQL의 재실행을 요구하지 않는다.
2. [해석 validator 확장](../../supabase/migrations/20261008020000_life_composition_insights.sql)을 적용한다. SHA-256 `69570ed81fc862ba19fbe2886447bf9505800a62f80e781e5fae9046645f7d88`. 기존 함수만 교체하며 테이블·RPC·권한·Auth·개인 자료는 변경하지 않는다.
3. [읽기 전용 설치 확인](../../supabase/tests/life-composition-insights-installation.sql) 13조건 모두 통과 확인. SHA-256 `d36c078bfccde7cbd89f8b6f9644b54bebd857ed24e56e4a3b14cf0b077c79b0`. [로컬 합성 검사](../../supabase/tests/life-composition-insights.sql)는 운영에서 실행하지 않는다.
4. 선행 PR부터 병합·배포 후 각 기기 최신 앱에서 빈 생각 생성·수정·제외/복원·명시 구성 이어쓰기·JSON 보관을 확인한다. 로컬 SQL 통과를 운영 설치/HTTP 왕복 성공으로 대체하지 않는다.

다음은 **원고 미리보기·개정과 생각을 장 원고로 반영하는 편집 흐름**, 이어 책/장 정리·복구, 한글 PDF/책자 출력이다. 자동 분석은 수동 검토 구조와 구별하며 제공처·전송 범위·비용·동의 계약 및 실제 개인 자료의 충분함을 먼저 확인한다.
