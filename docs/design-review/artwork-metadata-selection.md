# 작품 검색·출처 조회에서 비공개 저장까지

2026-10-14 KST. PR #81 후속. 관련 기존 흐름·검색 의미·입력 보존·외부 요청·접근성을 검토하고 작은 작품 메타데이터 연결을 완결했다. 병합·배포는 Local 담당이다.

## 목표와 전문가 검토 결과

글을 쓰다가 작품 이름 또는 미술관 링크로 대상을 찾아 제목·작가를 확인하고, 수정한 뒤 비공개 글에 붙인다. 컬렉션 선등록을 요구하지 않으며 수동 입력도 유지한다. 조회·선택·첨부·저장은 각각 명시 조작이다.

| 검토 대상 | 발견·판단 | 이번 조치 |
| --- | --- | --- |
| 이전 제공자 연결 보류 | 약관 전체 페이지 접근을 작은 메타데이터 연결에도 필수로 둬 공식 API의 현재 라이선스·앱 통합 안내보다 넓게 작업을 막았다 | 공식 API가 공개한 메타데이터 범위로 연결. 약관 본문 미확인은 기록 유지하며 확인 완료로 표현하지 않음 |
| 검색 의미 | 기본 q는 무관한 후보를 반환. 이전 AND 실험은 제목·작가를 같은 필드에서 찾아 결합 입력 누락 가능 | title/artist_title/artist_display의 cross_fields/AND를 실제 API로 비교·선택 |
| 작가 귀속 | artist_title만 쓰면 Attributed to/Style of 등 불확실한 귀속 표현을 잃을 수 있음 | artist_display 우선, 줄바꿈을 ` · `로 표시. 빈 display만 artist_title로 보완 |
| 사용자 입력 | 새 작가 적용 선택 뒤 직접 편집한 작가가 덮일 가능성 | 직접 작가 입력 시 해당 적용 선택 해제. 기존 제목·메모·상세는 기본 보존 |
| 후보 동일성 | 공식 링크의 slug 유무로 기존 항목을 새 후보로 취급할 가능성 | 작품 ID의 고정 출처로 비교. 기존 항목은 현재 제목·작가를 사용 |
| 실패·키보드 | 조회/다음 쪽 실패 후 입력·기존 후보·조작 초점을 잃으면 수동 복구 부담 | 취소·늦은 응답 무시·기존 후보 보존·초점 복구 재사용. 새 검색 성공 시 결과로 초점 이동하되 사용자가 다른 조작으로 이동했다면 유지 |

전체 저장소의 모든 기능을 새로 감사했다고 주장하지 않는다. 이번 변경과 맞닿은 제공자 어댑터·공유 선택기·컬렉션 입력·글 첨부·저장/백업·PWA 경계를 검토했다. 사용 흐름·기능 보존·시각 품질의 결과를 구분한다.

## 직접 체험

1. `npm run dev` → `http://127.0.0.1:4173`. 개인 화면은 기존 공용 로그인을 사용한다. 자동 검수는 익명 모의 Auth를 사용했다.
2. 내 페이지 → 글쓰기 → 음악·책·대상 붙이기 → `Monet` → **작품 찾기 · 시카고 미술관**.
3. 제목·작가·제작 시기·재료를 확인하고 후보 선택 → 제목/작가/출처 수정 → 첨부 → 저장 → 같은 비공개 피드와 새로고침 후 재열기.
4. 미술관 작품 링크는 **작품 정보 확인**을 누른 뒤 후보를 선택한다. `직접 입력`은 요청 없이 원래 입력 링크로 이어간다.
5. 저장한 첨부의 책갈피로 명시 보관한다. 컬렉션에서 주소로 정보를 조회할 때는 원하는 제목·출처·작가 표기만 선택 적용한다. 입력 중 새로 고친 작가는 적용 선택이 해제된다.

검색은 시카고 미술관 소장 범위다. 한국어 검색은 제한적이며 원어 제목/작가 또는 작품 링크를 사용할 수 있다. `Starry Night`가 고흐의 작품이라는 뜻은 아니다. 후보의 작가·시기를 확인한다. 최대 6개씩 다음/이전 결과를 제공하며 100쪽까지다. 빈 결과를 자동 번역·임의 이미지·무관한 후보로 채우지 않는다.

## 설계·재사용·보존

- 기존 CollectionMetadata.requestJSON·입력 검증·AbortController, CollectionPicker/native dialog·메모리 캐시·명시 선택, 수정 가능한 글 첨부/컬렉션 폼과 CAS 저장을 재사용했다. 외부 서버 코드·패키지·SQL·저장 스키마를 추가하지 않았다. 기존 공식 라이선스/유지관리 검토는 [제공자 비교](taste-provider-expansion.md)를 재사용한다.
- 제목/작가 결합 `La Grande Jatte Seurat`의 실제 후보에 작품 27992가 있었고, `Starry Night Van Gogh`는 0이었다. cross_fields는 전 단어 일치를 요구하므로 오타·한국어 이름·다른 표기와 소장되지 않은 작품은 놓칠 수 있다. 자동 번역보다 누락을 드러내는 작은 연결을 택했다. 실제 사용 누락이 반복되면 이 조건과 다른 제공자를 비교한다.
- 요청 필드는 id/title/artist_title/artist_display/date_display/medium_display뿐이다. 소장처는 제공자 이름으로 표시한다. description·image_id·이미지·IIIF·개인 메모·본문을 요청/전송하지 않는다. API의 HTML/이미지 URL은 쓰지 않고 평문과 고정 작품 출처만 사용한다. 제작 시기·재료는 후보 검토용이며 첨부에는 기존 네 필드만 보관한다.
- 글 첨부는 type/title/creator/url만 보관한다. 개인 감상은 별도 본문·비공개 메모다. 조회는 저장·공개·이미지 이용 권한을 바꾸지 않는다. 기존 입력을 자동 덮지 않고 선택·명시 저장을 유지한다.
- 작품 번호가 다른 상세 응답은 거절한다. 고정 HTTPS API만 GET, credentials=omit/referrerPolicy=no-referrer/redirect=error, 64 KiB/10초 상한을 유지한다. 작품 조회와 검색은 1.1초 간격을 공유하며 명시한 후속 요청 한 번만 기다린다. 자동 재시도·백그라운드 수집은 없다.
- 후보는 선택창 메모리에만 있고 닫기/계정/공간/검색 변경 때 폐기한다. 원문·불변 버전·검색 위치·작성 초안·구성 동기화·컬렉션 백업·공개 사본의 기존 경계를 유지한다.

## 근거와 이용 조건 판단

[현재 공식 API 문서](https://api.artic.edu/docs/)는 공개 REST 데이터를 앱에 통합하는 용도, 익명 60회/분과 fields 제한을 안내한다. 실제 작품 API 응답은 description 외 데이터를 CC0 1.0 및 artic.edu 약관으로 명시한다. [공식 데이터 저장소의 Licensing](https://github.com/art-institute-of-chicago/api-data#licensing)은 응답의 라이선스 표기가 메타데이터에 해당하고 이미지/미디어와 구분됨을 설명한다.

이 직접적인 메타데이터 제공 근거로 이미지·설명문을 제외한 작은 개인 보관 흐름을 진행했다. 약관 전체 본문은 여전히 미술관 측 Cloudflare 403으로 확인되지 않았으며, 법률 검토 완료나 모든 콘텐츠의 자유 이용을 뜻하지 않는다. 이미지 연결은 추가하지 않았다. 이전 [PR #81 실험](artwork-provider-verification.md)의 보류는 당시 판단 이력이며 이번 메타데이터 범위의 판단으로 갱신했다. 네트워크 정책을 우회하거나 설정을 추가 변경하지 않았다.
