# Obsidian 수신·읽기·보존 품질 묶음

2026-10-17 KST. 지정 계정의 서버 설치 이후, 자료를 받기 → 검색 → 정확한 원문 위치 → 같은 검색으로 돌아가기 → 백업하는 기존 흐름을 여섯 담당이 병렬 검토했다. 개인 서버 자료를 다시 쓰지 않고 합성 계정·자료와 실제 Chromium/IndexedDB로 재현했다. 새 제공자·자동 연결·AI·원본 수정·공개 범위는 추가하지 않았다.

## CI와 실행 범위

이전에는 모든 PR과 배포가 `pages` 동시 실행 그룹을 공유해 관련 없는 검수도 이전 브라우저 실행이 끝나기를 기다렸다. PR은 번호별 그룹을 사용하고 같은 PR의 이전 실행만 취소한다. main/수동 배포는 기존 공유 그룹과 취소하지 않는 설정을 유지한다. 배포 조건·권한·환경은 바꾸지 않았다. 새 수신·대규모 읽기 검사와 익명 보고서 경로도 CI에 포함했다.

읽기 전용 사용자 체험: 관리 → 기기 간 동기화 → 서버 작업공간 목록 확인 → 원하는 공간 받기 → 기록 검색 → 원문 → 연결된 노트의 위치 선택 → 검색 결과 복귀. 서버 받기는 기존 공간을 유지하며 백업 사본 복원과 구분한다. 단독 검토 도구도 직접 ZIP 복원 안내로 갱신했다.

ZIP 전체 구조/CRC 인증은 새로 구현하지 않았다. fflate의 잘못 작게 선언한 DEFLATE 출력 길이 잘림도 이 변경만으로 해결했다고 주장하지 않는다. 가져오는 자료 JSON에는 기존 원문 해시·경로·검토 정합성 검사를 계속 적용한다. Mac/iPad/iPhone 실기, 사용자 브라우저의 받기, main 통합과 공개 배포는 별도다. 이번 작업에서 운영 DB·계정 자료·정책·스키마를 변경하지 않았다.
