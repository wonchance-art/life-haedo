# 소셜 앱의 표현을 참고한 새 디자인 비교

확인일: **2026-10-04 KST / 2026-10-03 UTC**. 사용자의 새 요청은 “최신 Instagram·Threads·X처럼 interactive하고 트렌디하고 통통 튀는 느낌”이다. 이전 [읽기 중심 비교](references.md)의 따뜻하고 차분한 색·명조 우선 추천을 새 스타일의 기본값으로 삼지 않는다. 기존 시안은 비교 기록으로 보존하고, 새 비교는 **색·밀도·탐색·반응 방식이 다른 세 방향**으로 제안한다. 제품 목적은 계속 **흩어진 기록을 찾고, 읽고, 발췌하고, 연결하기**다.

## 공식 자료를 확인한 범위와 한계

이번 환경에서 최신 Instagram·Threads·X의 실제 웹 화면을 보거나 로그인하여 조작하지 못했다. 아래 여섯 URL 요청이 모두 관리 프록시의 `Tunnel connection failed: 403 Forbidden`으로 중단됐다. 다른 프록시·미러·인증 우회는 사용하지 않았다. 이는 해당 서비스 자체의 장애나 URL의 존재 여부를 판정한 결과가 아니다.

따라서 아래의 “Instagram/Threads/X에서 영감받음”은 널리 알려진 플랫폼 패턴을 해도 목적에 맞게 번역한 **디자인 가설**이다. 최신 앱 버전·현재 배치·모션 값을 확인했다는 뜻이 아니다. 본 문서에서 직접 확인한 소셜 앱 UI 스크린샷은 **0개**다. 사용자 제공 최신 화면이나 허용된 공식 화면 접근이 생기면 색보다 탐색과 조작의 차이를 대조한다. 그 확인을 기다리며 시안 제작을 중단할 필요는 없다.

## 같은 자료를 사용하는 세 방향

[기존 공통 한글 자료](sample-content.md)를 그대로 쓴다. 제목·원문·출처·본문 확보 범위와 기본 검색 조건을 같게 유지하여 스타일 차이를 비교한다. 사진이 없는 기록에 외부 사진이나 생성 표지를 끼워 넣어 한 방향만 유리하게 만들지 않는다.

| 방향 | 시각·배치 가설 | 찾기 → 읽기 → 발췌 → 연결에 적용 | 이 방향에서 비교할 상호작용 |
| --- | --- | --- | --- |
| **A · 컬러 모음** — Instagram에서 영감 | 코럴·마젠타 강조, 둥근 주제 모음, 넉넉한 카드, 굵은 산세리프 제목. 검색과 주제 모음 뒤에 같은 한글 자료가 이어짐 | 원형 요소는 사람 프로필이나 24시간 스토리가 아니라 **내 주제 모음**이다. 카드는 제목·일치 문장·원천을 먼저 보여준다. 카드를 열어 읽고 발췌를 실제 주제로 연결한다 | 주제 선택 표시, 카드 누름 반응, 발췌 추가 시 해당 행동의 명확한 상태 변화. 다채로운 요소가 본문보다 강해지지 않는지 비교 |
| **B · 문장 피드** — Threads에서 영감 | 흑백 중심과 바이올렛 포인트, 세로로 이어지는 문장, 얇은 연결선과 가까운 인라인 행동. 본문/선택 문장/내 생각의 차이를 활자로 구분 | 한 기록의 발췌와 내 생각을 **출처가 연결된 묶음**으로 표현한다. 댓글이나 타인의 답변을 만든 것처럼 표시하지 않는다. 검색 결과에서 원문 문맥으로 바로 이동한다 | 일치 문맥 펼치기, 발췌와 원문의 연결 확인, 행동한 위치에서 완료/실패 피드백. 연결선이 실제 관계 이상을 암시하지 않는지 비교 |
| **C · 빠른 탐색** — X에서 영감 | 높은 정보 밀도, 분명한 탭, 탐색 레일, 선명한 파랑, 짧은 행과 강한 선택 표시 | 탭은 전체·다시 볼 자료·발췌 있는 자료를 구분하고 출처와 주제는 필터로 고른다. 작은 화면에서도 제목·일치 문장·확보 범위를 빠르게 훑는다. 선택 기록을 읽으며 발췌·연결 행동을 가까이 둔다 | 탭/필터의 즉각적인 상태 변화, 키보드로 결과 이동, 눌림·포커스의 선명한 피드백. 높은 밀도가 긴 한글 제목이나 터치 영역을 해치지 않는지 비교 |

**새 요청에 대한 출발 추천은 A**다. 색과 원형 모음·카드의 반응으로 기존 차분한 시안과 차이가 명확하고, 이미 기록된 자료를 둘러보는 성격에도 맞는다. B는 긴 문장과 발췌를 오래 읽을 때, C는 많은 자료를 빠르게 찾을 때의 대안이다. 이 추천은 실제 동일 자료 시안과 조작 결과를 보고 조정하며, 이전 A안에 새 색만 입히는 것으로 완료하지 않는다.

## 소셜 표현을 제품 의미에 맞게 바꾸기

| 가져올 수 있는 표현 | 해도에서의 실제 의미 | 넣지 않을 표현 |
| --- | --- | --- |
| 원형 모음·선택 링 | 사용자가 고르는 주제와 현재 선택 | 보지 않은 새 글, 실시간 활동, 소멸 시각을 암시하는 표시 |
| 문장 피드·연결선 | 실제 원문과 발췌, 사용자가 남긴 생각 또는 명시적으로 연결한 자료 | 가짜 댓글·답변·자동 생성된 대화 상대 |
| 카드 아래 인라인 행동 | `읽기`, `발췌`, `모음에 추가`, `출처 보기`처럼 현재 가능한 행동 | 좋아요·팔로워·조회·도달·인기·알림 숫자 |
| 탭·탐색 레일·활성 밑줄 | 실제 검색 범위와 선택 상태 | 추천 알고리즘이 없는 `추천 피드`, 근거 없는 트렌딩·개인화 |
| 강조색·짧은 모션 | 선택·누름·펼침·성공/오류 같은 실제 상태 변화 | 저장 성공 전 성공 애니메이션, 계속 움직이는 장식·주의를 끄는 가짜 배지 |

결과 개수·발췌 개수는 샘플의 실제 상태에서 계산할 때만 보여준다. 출처 로고나 계정 아바타를 원형 장식에 임의로 합성하지 않는다. 해도가 SNS로 게시하거나 사용자의 계정을 수집하는 흐름을 추가하지 않는다.

## 상호작용과 읽기 품질의 공통 기준

- **반응은 행동에 붙인다.** 주제 선택·카드 열기·발췌 연결·검색 필터 등 실제 조작에 눌림/활성/완료 상태를 제공한다. 호버는 터치와 키보드에서도 같은 의미를 얻을 수 있는 보조 표현이다.
- **작은 움직임부터 비교한다.** 짧은 색·그림자·변형 전환을 사용하고, 튀는 반응은 사용자가 누른 대상에 한정한다. 시간·탄성 값은 해도 시안의 선택이며 최신 Instagram·Threads·X 수치로 소개하지 않는다. `prefers-reduced-motion`에서는 움직임을 줄여도 상태 의미가 남아야 한다.
- **움직임 때문에 읽던 위치가 밀리지 않는다.** 카드를 열거나 발췌를 추가할 때 큰 레이아웃 이동, 자동 스크롤, 끝없이 이어지는 자동 피드를 기본으로 삼지 않는다. 검색 결과로 돌아오면 조건·선택·위치를 유지한다.
- **한글은 원문을 기준으로 본다.** 긴 제목·80자 이상의 제목·여러 문단·URL·공백 없는 문자열을 1440·820·390px에서 비교한다. 장식용 큰 제목으로 첫 원문이 밀리거나, 정보를 촘촘하게 넣기 위해 입력 글자를 줄이지 않는다.
- **상태와 출처는 계속 정확하다.** 본문 일부/링크만/작성일 모름/이전 버전을 피드 스타일에서도 구분한다. 발췌와 설명을 원문으로 섞지 않고, 디자인 때문에 실제 저장 문자열·UTF-16 위치를 바꾸지 않는다.
- **밀도와 접근성을 함께 유지한다.** 주요 터치 목표 44px, 입력 16px, 보이는 키보드 포커스, 대비와 색 이외의 상태 표기를 확인한다. 원형 모음이 가로 스크롤이라면 숨겨진 항목과 키보드 접근을 확인한다.
- **실제 기능과 시안을 구분한다.** 샘플의 메모리 안에서 성공한 행동을 운영 저장·동기화 완료로 안내하지 않는다. 비교 도구의 상태 전환은 제품의 자동 추천이나 실제 오류로 설명하지 않는다.

## 구현 비용과 다음 확인

이번 조사로 외부 라이브러리·폰트·추적·SNS SDK를 설치하지 않는다. 기존 로컬 CSS/JS와 공통 샘플로 세 방향을 만들고, 새 색·모션·배치에 필요한 요소만 추가한다. 실제 채택한 오픈소스 자산이 생기면 [기존 재사용 검토](references.md)의 버전·라이선스·고지 규칙을 적용한다.

최신 소셜 UI를 직접 대조하는 일과 해도의 시안을 실제 브라우저에서 검사하는 일은 별개다. 전자는 현재 접근 제한으로 미완료이며, 후자는 새 시안에서 정상·많은 자료·빈 결과·로딩·오류를 비교해 진행한다. Apple 기기의 실제 터치·선택 핸들·IME 검증과 브라우저 화면 크기 검증도 구분한다.
