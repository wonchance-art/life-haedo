# 기록에서 묶음·내 페이지로 담기

2026-10-05. 첫 접속 홈 다음 단위로 기존 기록을 정리하고 페이지에 구성하는 단계를 줄였다. 디자인 책임자는 root이며 구성 편집 연결과 브라우저 검증을 독립 에이전트에 맡겼다.

## 시작과 결과

이전에는 기록을 읽거나 검색한 뒤 묶음·내 페이지로 이동해 같은 원문을 다시 검색하고 골라야 했다. 이제 목록에서 여러 원문을 선택하거나 읽던 원문 하나를 넘겨 담을 곳을 정한다. 원문이나 기존 문장을 합치지 않는다.

| 단계 | 동작 |
| --- | --- |
| 기록 목록 | 체크 아이콘으로 선택 모드를 열고 원문 버전을 고름. 검색·출처 필터를 바꿔도 선택은 유지 |
| 선택 확인 | 선택 개수와 현재 결과 밖의 선택을 표시. 목록을 펼쳐 각 제목·버전을 확인하고 개별/전체 해제 |
| 원문 읽기 | 연결 아이콘에서 현재 읽는 버전을 묶음 또는 내 페이지로 전달 |
| 담기 검토 | 정확한 버전·출처·작성자 관계·확보 범위를 확인하고 제외할 기록을 해제 |
| 묶음에 담기 | 기존 묶음에 중복 없이 연결하거나 이름을 정해 새 묶음 생성 |
| 내 페이지에 담기 | 선택한 원문들을 하나의 비공개 항목으로 구성. 이후 본문·코멘트·표시를 편집하고 미리보기 |
| 취소 | 원래 검색·필터·선택 또는 읽던 원문과 초점으로 복귀 |

목록 선택은 한 번에 100개까지이며 기존 페이지 항목의 원문 수 한도와 같다. 선택은 현재 계정·작업공간의 화면 상태다. 선택/검토/취소만으로 저장하거나 원격 전송하지 않는다. 새로고침 전 확정하지 않은 선택을 영속 초안처럼 표시하지 않는다.

## 저장·실패 경계

- 명시적으로 담기 버튼을 누르면 기존 Workbench 초안에 한 번 반영하고 같은 저장 경로로 확정한다. 저장 실패 시 해당 초안을 유지하고 재시도하며 동일 항목을 다시 생성하지 않는다. 확정 저장 전에는 ‘초안에 담음’과 저장 상태를 구분한다.
- 다른 탭과의 revision 충돌, 계정 폐기, 작업공간 변경은 기존 저장 보호를 따른다. 선택 검토의 느린 조회가 전역 탐색을 잠그지 않으며, 이전 조회가 새 화면을 덮지 않는다.
- 취소는 원문·구성을 수정하지 않는다. 검토에서 해제한 기록은 담지 않으며, 사용한 선택 묶음은 목록에서 정리한다. 원문 읽기에서 별도로 한 건을 담아도 목록에서 선택한 다른 기록은 유지한다.
- 이전 버전을 최신 버전으로 바꾸지 않는다. 누락 원문·다른 작업공간의 참조·빈 제목·개수 한도는 적용 전에 검사하고 자동 대체하지 않는다.
- 원문·출처 위치·자료/구성 백업·원문 동기화·연표 값과 형식은 유지한다. 묶음·페이지 구성은 여전히 이 브라우저의 계정별 저장이며 공개 게시 기능이 아니다.

## 선택 근거와 재사용

같은 날 확인한 [공식 오픈소스 비교](../life-tools-design/open-source-review.md#활동내-페이지돌아보기의-최소-로컬-구성)의 idb 8.0.3(ISC), native DOM과 기존 Workbench 저장·검증을 재사용했다. 새 라이브러리·에디터·라우터·DB 스키마·SQL을 도입하지 않았다. 이번 기능 때문에 동일 후보의 최신 버전 조사를 새로 수행했다는 의미는 아니다.

단순한 대안은 기존 구성 화면의 원문 선택기를 계속 쓰는 것이다. 그 경로를 유지하면서 이미 찾은 기록만 전달하므로 저장 엔진과 선택기를 교체할 필요가 없다. 별도 모달 대신 기존 묶음/페이지 영역 안에 검토를 표시한다. 기본 피드에는 작은 선택 아이콘만 더하고, 여러 행동은 선택한 때에만 보여준다. 선택/출처 아이콘은 기존 20px 도형과 44px 조작 영역을 재사용한다.

실제 사용에서 100개 넘는 일괄 정리가 필요하거나 화면 이동 자체가 부담이라는 피드백이 생기면 한도와 인라인 정리 방식을 다시 검토한다. 공개 게시·기기 간 구성 동기화는 별도 다음 단위다.

## 검증

격리된 익명 한글 샘플, 동봉 SDK와 모사 HTTP Auth, 실제 IndexedDB로 검사한다. 기능 검사와 직접 스크린샷 검토를 분리하며 운영 DB에 합성 자료를 만들지 않는다.

실행: `BASE_URL=http://127.0.0.1:4184 node tests/record-arrange-browser.cjs`. 기존 구성 회귀는 `tests/life-workbench-browser.cjs`를 사용한다. 

실제 Mac/iPad/iPhone의 한글 IME·Files·VoiceOver는 미검증이다. 브라우저 폭/터치 설정과 composition 이벤트 검사를 Apple 실기 확인으로 표현하지 않는다.

- 정적 검사 HTML 16·JS 37·로컬 참조 201·PWA 셸 통과. Node **208/208**.
- 신규 담기 기능 11개와 폭별 흐름 3개: 최신 결과 **14/14**. 기존 Workbench 기능 **14/14**, 변경 영향을 받는 홈 흐름 **2/2** 통과. 분할 실행의 원본을 보존하며 모든 검사를 한 번에 재실행했다고 보고하지 않는다.
- 1440·820·390px × 빈/다수 선택/검색 밖 선택/로딩/검토/저장 오류 = **18상태**. 글자 대비 최소 **6.05:1**, 44px 미달 조작·16px 미만 입력·가로 넘침·이름 없는 조작·대비 실패 0. 콘솔/페이지 오류·운영 DB 쓰기 0. Chromium **151.0.7922.173**.
- 원문 이전 버전·선택 좌표, 기존 묶음의 중복 없는 연결, 내 페이지 독립 사본·표시·재열기·백업 복원, 100개 상한, 계정·작업공간별 선택 격리, 다른 탭의 대상 묶음 삭제와 복구를 확인했다.
- 처음에는 느린 구성 조회 동안 전역 탐색이 잠기는 문제가 재현됐다. 선택 검토의 화면 조회가 끝나길 기다리지 않도록 수정하고 늦은 응답 폐기를 재검증했다. 독립 리뷰에서 발견한 새 저장본 조회 시 미확정 제목·선택이 닫히는 경로도 보존하도록 고쳤다.
- root는 선택 1440·검토 1440/390·저장 오류 820 이미지를 직접 확인했다. 선택 전 체크는 빈 네모, 선택 후 체크와 색을 함께 표시하고 선택 목록의 펼침 도형을 추가했다. 검토 중의 별도 저장 아이콘과 반복 제목을 줄인 뒤 대표 화면을 다시 확인했다.
- 390/820px에서는 실제 브라우저 스크롤 후 담기 버튼에 `tap`으로 도달하는 것도 확인했다. 긴 페이지 전체 캡처에서 고정 하단 메뉴가 중간에 찍히는 현상과 구분한다.
