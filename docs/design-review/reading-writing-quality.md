# 읽기·글쓰기 품질 개선

2026-10-07 KST. 사용자 지시 “에이전트 풀 가동, 전문가 식으로 번역해서 설계부터 완수”를 현재 우선순위에 맞춰 실행한다. 설계·최종 통합 책임은 root 한 명이다.

## 목표와 범위

목표는 실제로 쓰던 위치와 입력을 지키면서 `기록 찾기 → 읽기 → 발췌 → 복귀`, `글쓰기 → 다른 메뉴 → 이어쓰기 → 기록 저장`을 완결하는 것이다. 구현 전 독립 검토로 재현된 결함을 우선한다. 현재 승인된 흰 본문·옅은 라벤더·A 인용 도형·작은 탐색을 유지한다.

PR #35·#36의 구성·선택 초안 이어쓰기는 구현·CI 완료 상태다. 두 운영 SQL은 [Local 일괄 설치 인계](../life-tools-design/continuity-batch-installation.md)를 따르며 아직 설치 보고를 받지 않았다. 이 개선은 두 PR 위에서 진행하며 운영 설치 확인 전 병합·공개 배포하지 않는다.

이번 변경은 기존 UI와 네이티브 폼을 재사용한다. 저장 구조·정확한 원문 버전·UTF-16 발췌 위치·계정/작업공간 격리·선택 전송·공개 사본 계약은 보존한다. 기존 SQL과 백업 형식을 변경하지 않는다. 기기 간 읽기 위치 전송과 SNS 자동 연결은 후속 범위다.

## 재현된 문제

독립 검토에서 390px 긴 글쓰기의 중간 선택 위치 620·내부 스크롤 970이 메뉴 이동 후 각각 본문 끝·0으로 바뀌었다. 본문 문자열 보존만으로 이어쓰기 경험이 보존되지 않았다. 긴 제목은 한 줄 입력으로 잘리고, 자동 초안 보관과 명시 기록 저장의 버튼 의미도 더 분명하게 표시할 필요가 있었다. [독립 검토](reading-writing-review.md)에 같은 익명 자료의 근거와 범위를 남긴다.

## 완료 기준

- 동일 익명 한글 자료의 1440·820·390px 화면과 실제 키보드 조작을 확인한다.
- 제목·본문·선택/커서·스크롤 복귀와 실패 때 입력 보존을 확인한다.
- 새 글/다른 초안/다른 공간/다른 계정에 이전 편집 상태를 적용하지 않는다.
- 원문·발췌·백업·선택 동기화 회귀와 시각 검토를 분리한다.
- 예상 외 console/pageerror를 수집하고 의미 있는 실패가 남으면 수정한다.
- PR의 정확한 커밋으로 CI를 확인하고 운영 설치·실제 Apple 기기·공개 배포 상태를 별도 보고한다.

실제 Mac/iPad/iPhone, Google 로그인, 운영 DB 쓰기를 모의 브라우저 결과로 주장하지 않는다.

## 구현 결과

- 메뉴 이동 후 현재 초안의 제목/본문 선택·방향·내부 스크롤을 같은 stage에서 복원한다. 본문 값은 복원 동작으로 덮어쓰지 않는다. 새 초안과 계정 종료에는 이전 위치를 옮기지 않는다.
- 긴 제목을 자동 높이 textarea로 보여주고 한글 단어 단위로 줄바꿈한다. 저장되는 제목은 기존 한 줄·최대 500 UTF-16 단위 의미를 유지한다. 한글 조합 중에는 값 정규화를 미룬다.
- `기록에 저장`과 `이 브라우저에 초안 보관됨`을 구분한다. 접힌 이어쓰기에서도 중지·전송 대기·완료 확인을 알 수 있다. 다른 기록의 과거 저장 성공 알림은 새 글 진입이 성공한 뒤 지우며, 실패한 이동의 오류는 유지한다.
- 검색 목록 아래에서 정확한 위치 지정 없이 원문을 처음 열면 맨 위에서 시작한다. 검색 구간·기존 읽기 위치·검색 복귀 위치가 있으면 그 기준을 유지한다. 비어 있는 발췌는 저장 버튼을 비활성화하고 유효한 구절 선택 후 활성화한다.

같은 샘플의 새 원문 진입 스크롤은 1440/820/390px에서 2973/2973/4205 → 0/0/0px가 됐다. [변경 전](evidence/reading-writing-quality/reader-before-390.png)과 [변경 후](evidence/reading-writing-quality/reader-after-390.png)는 동일한 이전 버전 원문이다. 새 진입의 맨 위 복귀와 이미 읽던 구간의 복귀를 같은 규칙으로 처리하지 않는다.

## 검증 결과

- 정적 HTML 17 / JS 50 / 로컬 참조 249 / PWA 통과, Node 300/300 통과.
- 새 읽기 회귀 3폭 3/3, 기존 검색 7/7. 정확한 이전 버전·실제 CRLF·반복 구절/🌱의 UTF-16 위치, 원문 불변성과 검색·필터·목록 초점/스크롤을 확인했다. [읽기 보고](evidence/reading-writing-quality/reader-report.json).
- 독립 통합 검사의 기능·표면 assertion 198/198, 3폭 30캡처. 500자 제목, 역방향 선택 610..640과 내부 스크롤 970px 복귀, 새 초안 격리, 실패한 IndexedDB 쓰기·재시도·로딩, 이전 저장 알림 정리를 확인했다. console/pageerror/외부 요청 0. assertion 개수를 별개 사용 시나리오 수나 품질 점수로 해석하지 않는다. [통합 보고](evidence/reading-writing-quality/browser-report.json).
- 기존 글쓰기 12/12와 이어쓰기 10/10 통과. 이전 저장 실패 테스트의 비동기 대기 경쟁을 baseline에서 재현하고, 이동 시도에 따른 저장 실패가 실제 완료될 때까지 기다리도록 하네스만 수정했다. 수정한 검사는 baseline에서도 통과했고 기존 보존 assertion은 유지했다.
- 변경된 글쓰기 UI의 지연 알림 회귀 2/2 통과. 이는 실제 DOM/Writing 모델과 제어한 메모리 저장소의 경합 검사다. 저장·발췌·계정 경계의 독립 코드 검토에서 차단 결함을 발견하지 못했다.
- 최종 공개 산출물의 모의 인증/PWA 검사 9/9: 보존한 v70에서 v71로 캐시를 삭제하지 않고 갱신, 이전 자료·가져오기 초안·연표 키와 변경 모듈 해시 확인. 의도한 전송/콜백 오류 2개와 예상 외 오류 0을 구분했다.

[독립 경험 검토](reading-writing-review.md)와 [공통 표면 검토](reading-writing-visual.md)는 기능 통과와 별도로 이미지를 직접 읽었다. 긴 제목 390px [전](evidence/reading-writing-quality/before-long-write-390.png)/[후](evidence/reading-writing-quality/after-long-write-390.png), [위치 복귀 측정](evidence/reading-writing-quality/editor-return-review.json), [표면 측정](evidence/reading-writing-quality/visual-report.json)을 남겼다. 로컬 Chromium의 화면 폭·포인터/터치 모사와 실제 Apple 검증은 다르다. 변경된 두 브라우저 검사는 기존 CI에 추가했다.

## 운영 적용 뒤 실제 기기 확인

Mac·iPad Chrome·iPhone에서 같은 검증용 글을 사용해 긴 제목과 한글 조합을 편집하고, 본문 중간에서 메뉴를 이동했다 돌아온 뒤 다음 글자가 의도한 위치에 입력되는지 확인한다. 긴 원문의 구절을 실제 선택 손잡이로 고르고 발췌·복귀하며, 선택 초안 이어쓰기와 오프라인 복귀·TXT/백업 파일 열기를 확인한다. 기기·OS·브라우저와 실제 결과를 기록한다. 이 단계는 아직 실행하지 않았다. 이번 변경으로 추가 설치할 SQL은 없다.
