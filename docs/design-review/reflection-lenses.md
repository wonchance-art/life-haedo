# 실제 선택 자료의 관점 읽기

2026-10-11 KST. `codex/reflection-evidence-lenses`, 기준 main `29a325b`(#62 포함). PR #63의 고정 예시와 별개로 **실제 회고에 선택한 원문 버전**을 읽는 기능이다. 디자인·화면 통합 책임자는 Codex 한 명이다. 자동 분석·후보 저장·외부 AI 전송은 구현하지 않았다.

## 체험과 완료 범위

저장소 루트에서 `python3 scripts/dev-server.py --port 4189`를 실행하고 앱의 **도구 → 회고 → 원문 선택 → 관점으로 읽기**로 들어간다. 직접 경로는 `/index.html?section=tools&view=reflection`이며 기존 `life.html` 진입도 지원한다. 실제 개인 화면에는 정상 공용 로그인이 필요하다. 자동 검사는 익명 Auth HTTP를 가로채는 별도 브라우저에서 실행한다.

1. 회고할 글을 직접 선택한다. 선택한 과거 버전은 최신 버전으로 바뀌지 않는다.
2. **관심**에서 기존에 직접 만든 묶음에 속한 글을 읽는다. 묶음 없는 글도 남는다.
3. **질문**에서 물음표가 있는 원문 구절을 읽는다. 책 모양 버튼으로 정확한 버전·구절을 열고 돌아오면 같은 관점·조작 초점이 복원된다.
4. **변화**에서 작성 연도를 확인한 두 글을 직접 고른다. 두 본문이 펼쳐지고 같은 연도면 전후 순서를 단정하지 않는다.
5. 아래 기존 ‘내 회고’에 생각을 적고 저장한다. 현재 저장·충돌·원고 출력·자료/구성 백업을 그대로 사용한다. 관점 선택과 비교 대상 자체는 저장하지 않는다.

질문은 문장 의미 분석이 아니라 `?`/`？`가 있는 구절의 기계적 추출이다. URL·수사적 질문·내 글 안에서 인용한 타인의 말도 포함될 수 있으므로 화면에서 맥락 확인을 안내한다. 반복 고민·성격·성장·인과관계를 추정하지 않는다. 관심은 사용자의 묶음이며 자동 군집이 아니다. 변화는 비교할 자료를 펼치는 기능이며 변화 판정이 아니다.

## 보존 계약

- `ReflectionLenses.scope`는 작업공간 일치와 회고 선택 포함을 확인한다. 기존 `Reflection.chronology`의 작성 연도 규칙을 재사용한다.
- 선택 버전 그대로 조회한다. 원문 연결 없음, 타인 글, 작성자 미확인, 본문 미확보는 이유별 개수로 표시하고 이 보기에서만 제외한다. 원래 선택·자료·공개 범위는 바꾸지 않는다.
- 날짜 미확인 글은 관심·질문에 남기고 전후 비교에서는 제외한다. 경험 시기·나이를 작성일에서 추정하지 않는다.
- UTF-16 원문 위치를 직접 사용한다. 줄바꿈·이모지를 정규화하지 않는다. 질문의 긴 구절은 앞 600 code units 안에서 접고 전체 범위를 유지한다. 서로게이트 쌍 경계도 보존한다.
- 40개씩 더 보고 최대 1,000개 표시 후 범위를 좁히도록 안내한다. 표시 한도는 저장·선택·기존 내보내기 범위를 줄이지 않는다.
- 같은 회고 세션에서 관점·더보기·펼친 긴 구절·비교 선택을 유지한다. 새로고침 후 기본 보기에 돌아온다. 이는 계정/작업공간별 기존 Workbench UI 세션 안에만 존재한다.
- 원문으로 이동하기 전 기존 `flush()`가 성공해야 한다. 실패하면 입력을 보존한다. 저장 응답 중 관점을 바꿨다면 사라진 버튼의 이전 이동을 취소한다. 원문 복귀는 기존 `returnContext`와 `focusKey`를 사용한다.
- 원고·원문·발췌·구성 저장 스키마, 동기화 RPC, 백업·공개 형식은 변경하지 않는다. 새 SQL·실계정·외부 AI가 필요하지 않다.

## 구성과 선택 이유

- `assets/life/reflection-lenses.js`: 읽기 계산만 담당하는 순수 함수.
- `assets/life/reflection-lenses-ui.js`: 기존 sourceRow·입력·버튼·본문 스타일을 재사용하는 세션 화면.
- `workbench-ui.js`: 회고의 작은 진입점과 선택 구절 전달. `ui.js`의 기존 원문 열기에 locator를 전달한다.
- `index.html`, `life.html`, Pages 허용 목록, 서비스워커에 두 런타임 파일을 함께 등록한다.

[공식 오픈소스 비교](../life-tools-design/open-source-review.md#선택-자료의-읽기-관점--2026-10-11): Taguette 1.5.2와 Hypothesis client 1.1766.0의 배포 메타데이터를 재확인했다. 기존 질적 분석/인용 설계 검토를 이어가며 서버·계정·라이브러리 전체를 도입하지 않는다. 새 의존성 없음. 독립 시제품의 고정 예시나 가상 결론을 실제 글에 붙이지 않는다.

- 정적 검사: HTML 18 / JavaScript 61 / 참조 277 / PWA 통과.
- Node 407/407: 새로운 읽기 계약 7개, 새 캐시 자산의 설치 실패 보존 2개 포함. PR #63의 별도 테스트는 아직 main에 없어 이 수치에 포함하지 않는다.
- 새 브라우저 흐름 10개, 세 관점 × 1440/820/390px 9개. 원문 구절·빈 계정·근거 부족·저장 실패 화면도 보관했다.
- 정확한 과거 버전·선택한 질문 구절·원문 복귀 초점, 다른 계정의 빈 범위, 기간 필터의 저장 불변, 실패 후 회고 입력 보존과 재시도, 늦은 저장 완료 뒤 잘못된 이동 차단 확인.
- 긴 질문 펼침·45개 구절 더보기·중복 없음 확인. 원격 쓰기 0, 예상 밖 외부 요청 0, 콘솔/페이지 오류 0. Auth HTTP는 익명 모사이며 실 Supabase 검사 아님.
- 기존 `reflection-reading-browser.cjs`: 5/5 흐름, 8개 화면. 원고 Markdown·선택 버전·기간/묶음·실패 복구·자료/구성 백업의 새 사본 복원 통과.
- 명시적 가짜 공개 설정으로 Pages 산출물을 생성해 두 런타임 모듈 포함 확인. 운영 키나 운영 데이터 사용 없음.
- 실제 서비스워커/SDK/IndexedDB의 플랫폼 검사 9/9: 보존한 main v90 산출물에서 v94로 원자적 갱신, 새 모듈의 캐시 해시 일치, 기존 자료 유지·오프라인 재검증·계정 경계 통과. 의도한 전송/콜백 오류 2건과 예상 밖 오류 0을 구분했다. [PWA 로그](evidence/reflection-lenses/pwa.log).

자동 비교는 합성 데이터의 실제 앱·SDK·IndexedDB 경로로 실행했다. 실제 개인 자료·Apple 기기·native 한글 IME·Files 체험은 미검증이다. 기존 운영 SQL/Google 로그인 검증을 반복했다고 표현하지 않는다.

## Local 통합 순서와 충돌 지점

**병합·배포는 Local 담당이다.** #63은 설계 참고이며 런타임 의존성이 아니다. 이번 브랜치는 현재 main에서 시작했다. 현재 열려 있는 #56/#59–61을 대신 병합하지 않았다.

1. 독립 계산 모듈과 Node 테스트 커밋은 다른 앱 변경 없이 검토할 수 있다.
2. Local이 #56의 A 회고 화면을 통합한 후 화면 연결 커밋을 적용한다. `renderReflection()`의 상단 controls, bodyNode.append, 연도/묶음 모드 전환은 양쪽 변경이 겹친다. 파일 전체를 어느 한쪽으로 선택하지 않는다.
3. #56의 `wb-reflection-bar`와 본문/현재 생각/관리 배치를 유지한다. ‘관점으로 읽기’는 그 controls에 넣고, `lenses` 호스트는 `selectedList` 바로 앞에 둔다. 기존 노트·목차 편집 구조는 유지한다. `fill()` 끝의 `fillLenses()` 호출과 sourceRow의 locator 전달을 남긴다. `fill()` 최초 실행은 `plan/group/fillLenses` 정의 후여야 한다.
4. #59–61을 합칠 때 `ui.js`의 locator 한 줄, CSS 끝의 `.wb-lenses` 범위, HTML 두 script, Pages 허용 목록과 CI 단계도 남긴다.
5. 캐시 이름은 현재 main v90에서 **v94**로 올렸다. 대기 중 #61의 v93과 충돌하지 않도록 골랐다. 최종 통합 시 이미 더 큰 버전이 있다면 그보다 높게 정하고 두 모듈을 같은 SHELL에 포함한다. 실패한 설치가 기존 캐시를 지우지 않는 검사를 유지한다.
6. 최종 통합본에서 아래 검사와 실제 계정 체험을 진행한 뒤 배포한다. 이 브랜치 단독 검사는 #56과 병합한 결과의 시각 검증을 대신하지 않는다.

```sh
npm run check
npm test
# 4189 서버 실행 후, 설치된 고정 Playwright 경로를 사용
BASE_URL=http://127.0.0.1:4189 PW_MODULE_PATH=/절대/경로/playwright node tests/reflection-lenses-browser.cjs
BASE_URL=http://127.0.0.1:4189 PW_MODULE_PATH=/절대/경로/playwright node tests/reflection-reading-browser.cjs
```

CI는 기존 Pages 검증 workflow에서 새 흐름을 실행하고 증거를 보관한다. `CHROMIUM_PATH`를 로컬 브라우저 경로로 바꿀 수 있다. 새 운영 SQL·OAuth 설정은 없다.

## 다음 우선순위

1. Local 통합본에서 같은 원문 왕복과 최소 UI 확인. 실제 앱에 연결된 이 읽기 기능을 먼저 체험한다.
2. 사용자가 고른 구절과 직접 쓴 해석을 **명시 저장하는 후보 계약** 설계·구현. 기존 장별 해석 재사용과 계정/공간·용량·충돌/백업을 먼저 비교한다.
3. 그 후 유용한 분석만 실행기로 비교한다. 물음표 찾기나 두 글 펼침을 AI 분석 완료로 포장하지 않는다. 외부 전송은 별도 범위다.
