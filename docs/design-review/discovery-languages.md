# 추천 콘텐츠 언어와 원문 번역 열기

2026-10-19 KST. 사용자가 콘텐츠 언어 설정과 번역 언어 설정을 요청하고, 번역 범위로 **선택한 언어로 원문을 번역해 열기**를 선택했다. 목표는 원하는 원문 언어의 새 글을 찾고, 필요할 때 같은 원문을 선택한 언어로 여는 한 흐름이다.

## 적용 범위와 보존

콘텐츠 언어는 전체·복수 선택·선택 없음으로 보관한다. 한국어/영어/일본어/중국어/스페인어/프랑스어/독일어와 언어 미상·여러 언어·기타를 구분한다. 출처가 제공한 글의 `language`만 비교하고 제목이나 출처 언어로 추정하지 않는다. 지역·문자 태그는 기본 언어로 비교하며 원래 태그는 바꾸지 않는다. 미지원의 유효 태그는 기타, 빈 값/손상 태그와 `und`는 미상이다. 기존 literal `unknown`/`mixed`는 비교 때만 미상/여러 언어로 처리한다. 현재 고정 공급은 한국어 50개·영어 40개이며 나머지 선택 언어는 일치하는 글이 없으면 빈 결과로 표시한다. 공급의 언어 표기는 본문 언어 감지 결과가 아니다.

관심순·최신순·개인 추천 모두 상위 개수를 자르기 전에 같은 필터를 적용한다. 좋아요의 추천 근거도 같은 언어 선택을 적용한다. 번역 언어는 순위나 관심 표현을 바꾸지 않으며 한국어 주제를 영어로 자동 검색하지 않는다. 기본은 모든 콘텐츠 언어·번역 끔이다. 저장한 좋아요/담기/취소 목록은 콘텐츠 필터와 독립적으로 다시 열 수 있다.

새 `DiscoveryLanguageSettings`와 별도 계정/작업공간 메타 키의 CAS를 사용한다. 기존 엄격한 `DiscoverySettings` v1에 필드를 넣지 않아 이전 코드의 설정 읽기·쓰기를 보존한다. 초기화는 revision/tombstone을 남긴다. 원문·수동 관심·기존 출처/자동 갱신 설정·피드백·반응·사본 형식을 바꾸지 않는다. 언어 선택은 이 브라우저 전용이며 기존 원문/구성/사진 백업이나 서버 동기화·공개에 추가하지 않는다.

언어가 바뀌면 이전 개인 추천 결과를 즉시 버리고 새 선택으로 계산한다. 번역 대상 변경·끄기·다른 탭 알림 때 이전 번역 링크를 중단하고 저장·재읽기 후 확정된 언어만 사용한다. 실패·충돌·늦은 저장 성공이 더 최신의 끄기/초기화를 되살리지 않도록 확인한다.

## 번역과 외부 서비스

번역 대상은 한국어·영어·일본어·중국어 간체/번체·스페인어·프랑스어·독일어다. 기존 원문 링크와 별도로 `…로 번역해 열기 · Google 번역` 링크를 표시한다. 명시 클릭 때 승인된 출처의 공개 HTTPS 원문 URL과 목표 언어로 Google 번역 웹페이지를 새 탭에서 연다. 원문 URL을 검증·canonicalize하되 원문 링크 자체와 보관 스냅샷은 그대로 유지한다. `noopener noreferrer`와 `no-referrer`를 적용한다. 클릭은 읽음·좋아요·담기·가져오기 기록을 만들지 않는다.

공식 [Google 번역 웹사이트 안내](https://support.google.com/translate/answer/2534559?hl=ko&co=GENIE.Platform%3DDesktop)와 빈 웹사이트 번역 UI에서 8개 언어 코드를 확인했다. 이 링크의 `/translate?sl=auto&tl=…&u=…` 형태는 공식 안정 API로 문서화되지 않았다. 따라서 외부 웹사이트 번역 바로가기로만 제공하며 성공·전체 페이지 번역·로그인 페이지 접근을 보장하지 않는다. 기기/지역·원문 사이트 제한으로 열리지 않을 수 있다. 원문 열기는 계속 제공한다.

앱은 설정 변경/그리기 시 번역 요청이나 원문 본문 수집을 하지 않는다. 개인 관심·메모·본문·인증 정보를 링크에 넣지 않는다. 클릭 후 Google은 공개 URL을 전달받고 자체 방식으로 원문을 가져올 수 있으며 정상적인 네트워크 정보·쿠키 처리는 해당 서비스에 따른다. 제목 자동 번역·번역 API·비용·새 모델/서버/패키지를 추가하지 않는다.

## 재사용 선택과 바꿀 조건

기존 Discovery URL/출처 검증, 후보 풀·정렬과 로컬 idb/CAS를 재사용한다. 네이티브 `Intl.getCanonicalLocales`와 `URL`/`URLSearchParams`, checkbox/select/anchor를 사용한다. 새 언어 파서·번역 SDK는 도입하지 않는다. 고정된 소수 언어의 표시·필터·외부 열기에는 외부 패키지의 버전/라이선스/보안 유지 범위를 늘릴 이점이 없다. 본문 번역 보관·비교·요약이 필요해지면 명시 전송 범위·공식 API 계약·권리·비용·실패 복구를 새로 검토한다. 외부 바로가기 실패가 잦으면 기존 원문 열기를 유지하면서 연결 방식을 재평가한다.

## 자동 검수와 남은 조건

전체 단위 **1078/1078**, 정적 HTML22·JS146·로컬 참조624, 발견19·자동 갱신23·반응24·신규 언어14, PWA9와 이전 전체 앱137/운영main134→138 플랫폼10 검사를 통과했다. 최종 실행 결과와 파일 해시는 [검수 증거](evidence/discovery-languages/verification.json)에 기록했다. 신규 언어 검사는 최종 제품 바이트 불변·콘솔/페이지 오류·개인 표식 전송·모델 요청·예상 밖 외부 요청·원격 쓰기 0을 확인했다. 번역 8종/원문1개의 명시 클릭 후 새 탭은 합성 HTML로 가로챘으며 실제 번역 성공은 검증하지 않았다. 390/1440 폭의 두 화면을 직접 검토했고 실제 Apple 기기 검수로 부르지 않는다. 모의 Auth와 실제 로컬 UI/SDK/IndexedDB·Service Worker, 합성 공개 글을 사용한다. 실기·실제 계정·사용자의 독서 효용·Google 번역의 실제 번역 성공과 구분한다. SW v137 원본에서 v138 업데이트와 기존 자료/반응/언어 설정 보존을 확인했다. 독립 검수에서 찾은 출처 ID 강제 변환, 초기 읽기/알림·Promise.all 완료 경합, 언어 선택 후 초점 소실을 보완하고 같은 반례를 재검증했다.

첫 원격 CI에서 기존 비교 화면의 viewport 갱신 전 단언과 통합 검사의 진행 중 요청 종료 오류를 발견했다. 비교 화면은 네이티브 media-query 알림 뒤 예상 DOM을 최대5초 기다린 뒤 같은 단언을 유지하도록 보완했다. 통합 검사는 원래 실패/단계/보고서를 종료 전에 남기고, 명시 종료의 취소와 실행 중 실제 네트워크 실패를 구분한다. 기존 시각 검사6/6과 실제 로컬 HTTP/Chromium 고장 주입5/5를 통과했다. 앱·SQL·검사 판정 기준과 timeout은 바꾸지 않았다. [재현·검수 보완 근거](evidence/discovery-languages/ci-recovery.json)를 따르며 정확한 최종 HEAD의 원격 CI로 다시 검증한다.

로컬 체험: `npm run dev` → `http://127.0.0.1:4173/index.html?section=tools&view=external-discovery` → 언어 옵션에서 콘텐츠 언어 선택 → 번역 언어 선택 → 각 글의 번역 링크 확인 → 좋아요/담기 목록에서 같은 원문 다시 열기. 모의 인증 검수와 실제 소유자 로그인은 다르다.
