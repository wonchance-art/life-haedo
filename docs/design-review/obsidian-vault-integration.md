# Obsidian 보관함 전체 통합

2026-10-16 KST. 사용자가 지정한 비공개 GitHub 보관함을 전체 복제하고, 해도의 기존 비공개 자료·읽기·검색·JSON 복원에 연결한다. 기반은 #92 `9f46066`이다. 원본 저장소의 내용을 공개 앱 코드·PR·CI·배포 산출물에 넣지 않는다. 이 문서와 검수 화면에는 집계와 익명 합성 자료만 남긴다.

## 실제 가져온 범위

전체 Git 복제와 이력을 별도로 보존했다. Git 메타데이터를 제외한 **6,899개 파일 / 14,635,235바이트**를 모두 변환했다. Markdown **3,479개**는 노트 작업공간, YAML·설정·Canvas·스크립트 등 **3,420개**는 보조 파일 작업공간으로 나눈다. 일상 기록과 기계 추출물을 같은 노트 목록에 섞지 않으면서 모든 파일을 보관하기 위한 선택이다.

본문을 UTF-8로 엄격히 읽고 BOM·CRLF·공백·원문 Markdown을 바꾸지 않는다. 각 원천의 `sourceKey`에 원래 상대 경로, URL에 정확한 Git commit의 파일 출처를 둔다. 제목이 같아도 경로별로 별도 원천을 만든다. 원 작성자·관계·작성일은 추정하지 않는다. 비어 있는 파일은 출처와 0바이트 정보를 유지하는 링크 자료로 남긴다. 스크립트·플러그인·HTML·YAML은 읽기용 텍스트이며 실행하거나 AI 추출물을 사용자 발췌로 승격하지 않는다.

내부 노트 연결 **2,568개**를 기존 `links.sourceRefs`에 저장했다. Wikilink·별칭·상대 경로·URL 인코딩된 Markdown 링크·제목/블록 위치를 지원한다. fence/inline 코드·주석·외부 URL·이스케이프한 링크는 노트 연결로 만들지 않는다. 대상이 없는 **446개**, 동명 후보 **6개**, 제목/블록 위치 미확인 **2개**는 원문을 유지하고 비공개 감사 파일의 `unresolvedReferences`에 위치·대상·사유를 남긴다. 링크 본문은 고치지 않고 대상이 명확한 경우에만 연결한다. Wikilink의 `%`는 문자 그대로, Markdown 경로는 URL decode 한 번만 적용한다.

## 구현과 사용

변환기는 기존 `Core.createWorkspace/validateWorkspace/makeBackup/restoreBackup`과 Node 표준 파일·Git·SHA-256만 사용한다. 최종 두 JSON을 실제 앱과 같은 복원기로 검증하고 새 ID/참조 재매핑도 확인한다. 파일별 본문 바이트를 실제 원본과 다시 대조했다. 전체 이력은 `repository.bundle`, 경로·크기·해시·미해결 연결은 `private-audit.json`에 보관한다. 기존 원본과 작업공간을 덮어쓰지 않는다.

```sh
node scripts/import-obsidian-vault.mjs \
  --vault /private/path/to/vault \
  --output /private/path/to/new-export \
  --repository https://github.com/OWNER/REPO \
  --title '내 Obsidian 노트'
```

깨끗한 Git checkout만 받는다. 출력은 앱 저장소 밖의 새 디렉터리로 제한하며, 기존 경로의 실제 위치를 확인해 심볼릭 링크로 앱 안에 쓰는 것도 막는다. 보관함의 심볼릭 링크·잘못된 경로/UTF-8·NUL·1MiB 초과 파일·중복 경로는 누락 처리하지 않고 전체 변환을 중단한다. 이미 만든 출력 폴더를 덮어쓰지 않는다. 출력 디렉터리는 0700, 개인 JSON과 Git bundle은 0600이다. 콘솔에는 집계/오류 코드만 출력한다.

`npm run dev` 후 `http://127.0.0.1:4173/index.html?section=manage&view=transfer`에서 로그인한 계정의 **JSON 백업을 새 작업공간 사본으로 복원**을 사용한다. `notes.json`을 선택해 개수·원문을 확인하고 새 사본으로 복원한다. `supporting-files.json`도 같은 방식으로 별도 작업공간에 복원할 수 있다. 기존 작업공간은 남고 자동 동기화는 연결하지 않는다. 원본 파일을 소유한 계정에서 명시 복원하며, 테스트 계정에 실제 개인 자료를 설치하지 않았다.

노트 읽기의 접힌 **연결된 노트**는 나가는 링크와 들어오는 링크를 구분하고 정확한 원문 버전·확인된 위치를 연다. 링크 탐색과 백업 확인은 40개씩 추가하며 전체 개수·데이터는 줄이지 않는다. 출처 정보와 백업 확인에 원본 경로를 보여 동명 노트를 구분한다. 본문은 기존 하나의 Text node로 유지해 발췌의 UTF-16 위치와 읽기/검색 복귀를 보존한다.

## 한계·다음 판단

계정 반영은 사용자가 로그인한 계정에서 파일을 복원하는 마지막 단계다. 보관함의 앱 설정/스크립트를 해도의 실행 코드로 합치거나, 원본 GitHub에 다시 쓰거나, 기기 간 동기화/자동 공개를 시작하지 않는다. Obsidian의 전체 플러그인·Dataview·Canvas 편집기나 전용 Markdown 렌더러를 이식한 작업은 아니다. 원문과 모든 보조 파일을 보존하며 기존 해도 읽기/검색/발췌/백업을 이용한다.

외부 첨부 파일을 다운로드하지 않았으며 파일에 없는 대상·복잡한 Markdown/중첩 링크·제목 경로는 자동 추정하지 않는다. 현재 스캐너가 지원하지 않는 표현도 원문에는 그대로 남는다. 파일별 1MiB 제한은 기존 앱 계약이다. Mac/iPad/iPhone 실기의 파일 선택·큰 JSON 복원·IME·VoiceOver는 미검증이다. 전체 규모를 실제 Apple에서 확인하고 부담이 드러나면 분할 가져오기/진행·취소 UX를 비교한다. 실제 개인 자료의 재분류·AI 해석·태그 자동 생성은 이번 범위가 아니다.
