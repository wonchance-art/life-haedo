# SNS에서 탐구 자료를 받는 운영과 선택적 콘텐츠 제작

2026-10-29. [제품 목적](../life-tools-design/product-purpose.md)과 [자동화 계약](../life-tools-design/workflow-automation.md)에 연결하는 **설계 문서**다. 사용자는 **‘내가 읽을 탐구 자료를 추천받는 계정부터 시작’**하기로 확정했다. 실제 SNS 계정 접속·설정 변경·게시·예약·AI 서비스 가동은 수행하지 않는다. 플랫폼 API의 지원 범위·할당량·게시 제한은 별도 검토를 따른다.

## 1. 먼저 구분할 두 가지 SNS 사용

첫 목적은 SNS 계정을 **개인 탐구 자료를 받는 입구**로 운영하는 것이다. 계정/채널의 구체적 선택은 후속 능력 검토를 따르며 새 계정 생성·자동 조작을 가정하지 않는다. 타인 대상 큐레이션·브랜딩·콘텐츠 제작은 가치 있는 탐구가 쌓인 뒤 선택할 확장이다. 첫 운영에 공개 프로필·브랜드 문구·발행 주기를 요구하지 않는다.

| 방향 | 약속할 사용자 결과 | 먼저 필요한 설정 | 발행과의 관계 |
| --- | --- | --- | --- |
| **지금: SNS를 자료 받는 입구로 사용** | 원하는 주제·언어의 자료를 적은 선별 부담으로 만남 | 관심 질문, 허용 출처, 읽을 언어, 반복·제외 기준 | 콘텐츠 제작·브랜드·게시 일정 없이도 완결 |
| 이후 선택: 큐레이션 계정으로 제공 | 특정 독자가 이해하고 판단하는 데 필요한 자료·관점 제공 | 독자 상황, 제공할 가치, 근거 기준, 공개 범위 | 선택한 자료만 콘텐츠 제작 후보로 승격 |
| 이후 선택: 두 용도를 함께 사용 | 개인 탐구에서 가치가 확인된 일부를 다른 사람에게 전달 | 소비 기준과 편집 기준을 각각 보관 | 개인 저장·팔로우·좋아요가 발행 동의로 바뀌지 않음 |

SNS 추천 피드의 순위나 계정의 학습 결과를 해도가 보장한다고 설명하지 않는다. 공식적으로 가능한 구독·목록·저장·수신 경로와 앱 안의 선별을 구분하고, 자동 조작 가능 여부는 채널 검토 뒤 정한다. 발행을 선택하지 않은 사용자에게 독자·브랜드·성과 지표 입력을 요구하지 않는다.

### 첫 운영: 관심 기준 → 자료 선별 → 탐구 리뷰

| 단계 | 자동화·기존 기능의 역할 | 사용자의 최소 결정 | 완료와 중단 |
| --- | --- | --- | --- |
| 관심 기준 보관 | 기존 관심·복수 언어·제외 설정을 재사용하고 현재 질문을 연결 | 지금 확인할 질문 또는 주제 선택 | 매번 언어·관심·맥락 재입력 없음 |
| 계정의 자료 입구 정리 | 허용된 경로로 관련 계정·출처·리스트 후보와 이유 준비 | 지원되는 팔로우/리스트·구독 범위 선택 | 조회만으로 팔로우·좋아요·계정 설정을 바꾸지 않음 |
| 소수 후보 엄선 | 출처·원문 확보 범위·중복·현재 질문과의 관련성 표시 | 읽을 대상 선택 또는 종료 | 읽을 시간/대기량을 넘으면 추가 추천 묶음 중지 |
| 읽기·짧은 탐구 리뷰 | 정확 원문·내 메모·관련 자료 재개 | 필요하면 ‘알게 된 점/남은 질문’ 중 하나만 남김 | 모든 글 평가·메모·글쓰기 의무 없음 |
| 다음 자료 조정 | 명시 관심·제외 설정은 그대로 적용. 리뷰는 사용자가 다음 질문·출처 조정을 판단할 때 참고 | 어긋난 주제·출처·깊이를 필요한 때 수정 | 읽기/도움 평가는 자동 순위 학습에 사용하지 않음. 학습 사용은 별도 선택 |

소비 기준의 최소값은 현재 질문, 관심 주제, 읽을 언어, 번역 언어, 출처 범위, 제외 조건, 읽기/관리 여유다. 기존 값이 있으면 다시 묻지 않는다. 복수 원문 언어와 하나의 번역 언어는 독립이며, 번역된 문구를 원문 근거로 바꾸지 않는다.
외국어 학습·독서·집중력·Grit은 현재 관심 후보로 사용한다. 매번 네 주제를 채우지 않는다. 연구 결과·실무 조언·개인 경험을 구분하고 어떤 종류의 자료를 찾는지 현재 질문으로 좁힌다. 후보가 부족하면 없는 자료를 만들지 않고 출처/언어/조건을 넓힐 선택을 제시한다.
출처 후보는 원문 접근, 주장과 자료의 연결, 방법/한계 공개, 정정 가능성, 이해관계 표기를 확인한다. 팔로워 수·인기·전문가 직함을 사실 검증의 대체물로 쓰지 않는다. 제목/초록만 본 상태와 전문을 확인한 상태를 구분한다.
팔로우·리스트·구독은 해당 SNS의 실제 지원 기능 안에서만 설계한다. 지원되지 않으면 계정 목록/원문 링크를 안내하는 대안부터 비교한다. 자동 좋아요·자동 댓글로 추천 피드를 조정하는 경로를 기본 운영에 넣지 않는다.
좋아요·저장·관심 없음의 의미와 전파 대상은 해당 플랫폼에서 확인한다. 해도에서 ‘읽을 후보로 보관’했다고 외부 좋아요를 보내거나, 글을 열었다고 도움이 됐다고 기록하지 않는다. 사용자 반응은 원래 의미 그대로 유지한다.
짧은 리뷰는 선택이다. 새 이해 한 문장, 근거가 약한 부분, 다음 질문 중 필요한 것만 남긴다. 시스템은 연결한 출처·판·시점을 채우고 사용자가 ‘무슨 글이었는지’를 다시 쓰게 하지 않는다. 리뷰를 채점·연속 기록·매일 제출로 만들지 않는다.
리뷰·읽기 도움을 추천 학습에 쓰려면 후속 기능에서 사용 범위·정책/모델 버전·철회와 반영 취소 조건을 별도로 정한다. 현재 리뷰 보관이나 열람을 그 선택으로 대신하지 않는다. SNS 자체 추천의 변화와 해도 설정·선별의 변화도 별개로 확인한다.
관리 한도는 운영에 쓸 시간과 읽지 않은 후보의 양으로 정한다. 피드 전체 분석·모든 반응 추적 대신 선택한 소수 묶음에서 관련성·중복·찾기 수고를 확인한다. 조정 비용이 커지면 출처/질문 수와 갱신 빈도를 줄인다.
첫 성공은 ‘원하는 자료를 실제로 만나고, 다시 찾을 수 있으며, 관리 부담이 감당 가능함’이다. 추천 순위 상승·콘텐츠 생산·공개 게시를 조건으로 붙이지 않는다. 실제 자료의 도움 여부는 사용자가 확인하며 이번 설계에서 가상의 도움 응답을 만들지 않는다.
SNS에서 읽고 종료하는 것도 정상 경로다. 해도의 내 페이지·글쓰기·프로필 완성을 거쳐야 추천 자료를 받을 수 있게 만들지 않는다. 원문 보관·메모·실천 연결이 필요할 때만 정확 맥락을 이어 간다.

| 기존 Output | 소비 운영에서 남길 수 있는 결과 | 자동으로 만들지 않는 것 |
| --- | --- | --- |
| 이해 | 확인한 주장·한계·다음 질문 또는 읽고 종료 | 이해 완료·지식 점수 |
| 내 생각 | 선택한 개인 메모와 정확 원문 | 사용자 관점·경험의 AI 대필 확정 |
| 실천 | 사용자가 고른 의도를 기존 목표/습관에 연결 | 메모에서 일정·수행·효과 자동 생성 |
| 표현 | 이후 선택한 글·형식별 초안 | SNS 계정 발행·내 페이지 공개 |

이후 제작을 선택할 때만 아래 편집 기준을 활성화한다. 개인 리뷰·저장 자료를 자동으로 공개 대기열에 넣지 않는다.

## 2. 매번 다시 설명하지 않는 저장된 편집 기준

아래 2~9절은 **선택적 제작 확장**의 준비 계약이다. 첫 기획에서는 현재 질문과 사용할 자료로 시작한다. 나머지는 제안값으로 채우고 필요한 차이만 고친다. 아래 필드를 모두 입력해야 자료를 읽거나 초안을 만들 수 있는 마법사를 만들지 않는다.

| 편집 기준 | 보관할 내용 | 반복 작업에서 재사용할 것 |
| --- | --- | --- |
| 독자와 상황 | 누구의 어떤 질문·선택을 돕는가. 개인 소비라면 ‘나’ | 대상·난이도·필요한 배경 설명 |
| 독자에게 줄 가치 | 한 편을 읽고 얻을 이해·질문·검토할 행동 | 제목·첫 문장·종료 지점의 일치 |
| 주제 축 | 포함할 질문, 인접 탐구, 제외 주제 | 범위를 벗어난 자동 생산 차단 |
| 반복 연재 | 되풀이할 편집 질문과 구성, 종료 조건 | 매번 포맷과 기획서를 새로 쓰지 않음 |
| 목소리와 관점 | 채택한 관점, 말투 예시, 금지 표현, 경험 인용 범위 | 사용자 의견과 AI 제안의 구분 |
| 근거·권리 기준 | 허용 자료, 필요한 원문 수준, 인용·번역·자산 조건 | 확인된 출처·사용권의 유효 범위 재사용 |
| 형식·언어 | 선택 채널의 형식, 읽을 언어와 제작 언어, 접근성 | 같은 논지를 유지한 변형·자막·대체 텍스트 |
| 운영 여유 | 검토 가능한 시간, 동시 작업 한도, 비용 상한, 중지 조건 | 사람이 확인하지 못할 초안의 증식 방지 |
| 자동화 범위 | 수집·기획·초안·제작·예약 각각의 허용 범위 | 유효한 범위의 작업을 매번 재승인하지 않음 |

브리프에는 ID·판·적용 범위·갱신 시점을 둔다. 개인 자료 수신 기준과 타인 대상 편집 기준은 별개다. 새 브리프가 과거에 검토한 원고나 기존 공개 사본을 조용히 바꾸지 않는다. 계정에 보관한 기준은 기기마다 다시 설정하지 않는다.

## 3. 독자 약속·주제 축·연재를 정하는 방법

채널별 생산량보다 한 문장으로 설명 가능한 독자 약속을 먼저 비교한다. “외국어 학습·독서·집중력에 관한 주장을 근거와 한계까지 살피고, 자신에게 맞는 작은 선택을 돕는다”는 **후보 문장**이며 사용자 브랜드로 확정하지 않는다.

| 후보 주제 축 | 반복해서 다룰 질문 | 연재의 후보 | 피할 단정 |
| --- | --- | --- | --- |
| 외국어 학습 | 어떤 학습 조건·대상에서 어떤 결과를 말하는가? | 연구 한 편의 적용 범위 | 모든 학습자에게 통하는 비법 |
| 독서 | 읽은 내용과 내 해석을 어떻게 구분하는가? | 한 문장·다른 해석·남은 질문 | 책을 보관했으므로 읽고 이해했다는 서술 |
| 집중력 | 과제·환경·측정 방법이 바뀌면 결론도 달라지는가? | 주장 하나를 비교하는 읽기 | 치료·진단·개인 효과의 추정 |
| Grit·지속성 | 개념·측정·맥락과 다른 설명은 무엇인가? | 익숙한 개념 다시 묻기 | 개인의 성실성·인격 점수화 |

이 네 축은 사용자 관심에서 가져온 탐구 가설이다. 모두 운영하거나 같은 비율로 발행할 필요가 없다. 한 주제를 이해한 뒤 멈추는 결과도 유효하다. 연재는 ‘주간 몇 편’보다 반복 가능한 질문·구성으로 정의한다.
독자 요구와 근거를 설명하지 못하는 유행은 자동 채택하지 않는다. 공식 YouTube 가이드도 주제·형식·시리즈·대상·제작 비용으로 콘텐츠를 묶고 지속 가능한 반복 형식을 검토하도록 제안한다[S1]. 이 제안을 모든 SNS의 순위 공식으로 일반화하지 않는다.

## 4. 하나의 연구 묶음에서 기준 원고와 형식별 사본으로

연구 묶음 → 기준 원고 → 선택한 형식별 사본 → 검토 완료 묶음 → 허용된 운영 전달 순서로 연결한다. 화살표는 가능한 연결이며, 이해·내 생각·실천에서 종료해도 된다. 기준 원고는 공개해야 하는 블로그 글이 아니라 여러 형식이 공유할 논지와 근거다.

| 산출물 | 최소 내용 | 불변 연결 |
| --- | --- | --- |
| 연구 묶음 | 질문·자료 선택 이유·확보 범위·확인한 주장·반대 근거·남은 질문 | 원문 ID/판·구절/위치·출처 URL·확인 시각 |
| 주장 목록 | 주장 문장, 근거 위치, 대상/조건, 한계, 확인 상태 | claim ID·근거 판·변경 이력 |
| 내 관점 | 사용자가 채택한 해석 또는 아직 채택하지 않은 제안 | 사용자 입력/채택 여부·시점 |
| 기준 원고 | 독자 질문, 중심 논지, 설명 순서, 사례, 필요한 제한, 선택 행동 | 연구 묶음/브리프 판·사용 claim ID |
| 형식별 사본 | 제목·본문·카드/장면·자막·설명·출처·자산 목록 | 기준 원고 판·사용 claim/자산·제작 조건 |
| 전달 묶음 | 검토한 정확 사본, 대상 채널/계정, 공개 범위, 일정 조건 | 사본 해시·검토 범위·운영 작업 참조 |

같은 근거를 형식마다 복사해 관리하지 않고 정확 참조를 재사용한다. 원문이 링크뿐이면 ‘링크 확보’, 초록뿐이면 ‘초록 확인’으로 남긴다. 모델이 인용문·표본·효과 크기·저자·DOI를 채워 넣지 않는다.
AI가 만든 주장 목록은 후보다. URL의 실재 확인과 그 자료가 해당 주장을 뒷받침하는지는 다른 검사다. 같은 자료를 반복 인용하거나 다른 모델이 동의했다는 이유로 독립 근거가 늘었다고 세지 않는다.

## 5. 기획·생성·제작의 단계와 품질 관문

| 단계 | 자동 처리 | 통과 조건 | 사람이 볼 예외 |
| --- | --- | --- | --- |
| 탐구 선정 | 저장 기준으로 후보·중복·범위·빠진 근거 정리 | 질문과 자료의 관계·확보 범위가 설명됨 | 독자/질문 변경, 새로운 민감 범위 |
| 논지 구성 | 확인된 주장과 대안·한계를 연결한 개요 후보 | 주장이 근거 범위를 넘지 않고 반대 설명을 누락하지 않음 | 근거 충돌, 새 해석의 채택 |
| 기준 원고 생성 | 저장된 말투·길이·독자 배경으로 초안 작성 | 원문/내 관점/AI 제안을 추적할 수 있음 | 사용자 경험·신념을 대신 말하는 문장 |
| 형식 변환 | 필요한 카드·대본·짧은 글·번역 후보 제작 | 요약 후에도 조건·한계·출처가 유지됨 | 새 주장, 뜻이 바뀐 번역·강한 제목 |
| 자산 제작 | 허용한 텍스트·도형·사진·음성으로 선택 자산 생성 | 사용권·표기·가독성·자막·음성/화면 일치 | 권리 미확인 자산, 개인 정보 노출 |
| 최종 묶음 | 변경점·차단 사유·미리보기를 한 번에 구성 | 정확 사본·근거·공개 범위·채널 조건 일치 | 변경된 논지·공개 대상·권리 조건 |
| 운영 전달 | 검토 판을 설정된 운영 경로에 전달 | 유효한 운영 권한과 작업 영수증 | 범위 밖 요청, 만료·취소·불명확한 결과 |

과학적·사실적 문장에는 claim 연결을 요구한다. 조언은 적용 조건을 밝히며 인과관계·보편성·효과를 과장하지 않는다. 창작 예시는 예시로 표시하고 가짜 개인 경험을 쓰지 않는다. 근거 미확인 주장은 삭제하거나 확인 대기로 남긴다.
사용자 관점이 없는 상태에서는 ‘내가 해보니’, ‘나는 확신한다’ 같은 1인칭 확언을 생성하지 않는다. 중립적 질문·설명 초안으로 둘 수 있으며, 관점 채택을 자동 학습 결과로 추정하지 않는다.
출처 표시만으로 이미지·표·음악·전체 번역의 재사용 권리가 해결되지는 않는다. 원저작물·라이선스·허용 용도·변형/상업 이용·표시 조건을 자산별로 확인한다[S3]. 불명확한 자산은 허용된 자체 제작 대안으로 교체한다.
비공개 자료 보관 허용과 외부 AI 전송, 공개 배포 허용은 별개다. 연구 묶음 전체 대신 제작에 필요한 선택 범위만 전달하는 계약을 유지한다.

## 6. 반복 검토를 줄이는 자동화 수준

| 선택한 수준 | 반복해서 자동 실행할 일 | 멈추는 지점 |
| --- | --- | --- |
| 개인 수신·보관 | 허용 후보 정리·선별·확보 범위 확인 | 콘텐츠 생성·발행으로 승격하지 않음 |
| 기획까지 | 질문별 연구 묶음·논지·형식 후보 | 사용자 관점 채택 전 |
| 제작까지 | 유효 브리프 안에서 기준 원고·선택 사본·기계 검수 | 미확인 주장·권리·새 공개 범위 |
| 정한 조건의 운영 | 향후 별도로 허용한 정확 계정·형식·시간·주제 범위의 검토 완료 묶음 처리 | 허용 범위 변경·만료·중지·검수 차단 |

이 표는 설계 선택지이며 현재 외부 게시 권한이 아니다. 이후 운영 모드를 선택하면 허용 범위 안의 같은 작업은 재확인하지 않는다. 형식 생성 허용을 외부 계정 게시 허용으로 해석하지 않는다.
첫 묶음은 기준 원고의 관점과 형식별 차이를 함께 검토한다. 다음 묶음부터 바뀐 claim·관점·권리·공개 대상만 우선 표시하고 이미 검토한 동일 근거와 서식은 재사용한다. 승인 판·범위·검수 규칙이 그대로인 경우 같은 문장을 다시 평가시키지 않는다.
기계 검수는 출처 연결·누락·길이·자막·참조 판을 확인한다. 문장의 사실성·권리 해석·사용자 관점의 채택을 자동으로 보증하지 않는다. 사람 판단이 필요한 예외를 해결할 수 없으면 그 묶음만 보류하고 기본 읽기·보관은 계속된다.
보여 줄 기본 정보는 결과 미리보기, 달라진 점, 필요한 한 가지 결정이다. 세부 claim·라이선스·자동화 영수증은 해당 항목에서 펼친다. 새 최상위 ‘콘텐츠 공장’ 메뉴나 매 생성 단계의 승인 화면을 추가하지 않는다.

## 7. 수정 이후 파생 콘텐츠의 재검토

| 바뀐 것 | 자동 처리 | 보존할 것 |
| --- | --- | --- |
| 원문 새 판·철회·오류 제보 | 기존 정확 판을 유지하고 해당 claim과 사본에 재검토 표시 | 이전 판·원래 인용·검토 기록 |
| claim·사용자 관점 | 의존하는 기준 원고/사본을 오래된 상태로 표시 | 무관한 사본과 사용자의 직접 수정 |
| 제목·분량·채널 규칙 | 해당 형식만 다시 생성/검수 후보로 만듦 | 다른 형식·근거 묶음 |
| 권리·개인 정보·공개 범위 | 관련 자산/사본의 운영 대기를 중단 | 이미 보관된 비공개 원본 |
| 검토 뒤 원고 수정 | 정확 diff를 제시하고 영향받은 검토만 무효화 | 이전 검토 판과 취소 가능한 작업 |

연결은 연구 묶음/claim/기준 원고/사본의 정확 판으로 추적한다. 최신 자료가 도착했다고 공개 문구를 자동 교체하지 않는다. 초안 재생성은 사용자가 편집한 사본을 덮지 않고 별도 후보·차이로 제공한다.
예약 대기 중인 오래된 사본은 재검토 전 전달하지 않는다. 이미 게시된 사본은 ‘비공개 초안 수정’과 구분하여 정정·교체·철회가 필요한 운영 항목으로 남긴다. 실제 외부 변경은 허용 범위와 채널 지원을 확인하는 별도 실행이다.
플랫폼 응답이 불명확하면 재게시로 해결하지 않는다. 정확 작업/사본의 결과를 확인하는 동안 해당 전달만 보류한다. 검토 유효 상태와 실제 게시 성공은 서로 다른 상태다.

## 8. 검토 시간·진행 중 작업·발행 일정

편집 기준의 검토 시간 예산과 현재 검토 대기량을 제작 시작 전에 확인한다. AI가 만들 수 있는 양을 발행 목표로 삼지 않는다. 초안·재검토·권리 확인·정정 작업을 모두 진행 중 작업(WIP)에 포함한다.
첫 실험은 한 주제·기준 원고 한 편과 선택한 형식만으로 시작할 수 있다. 아래 세 형식 예시는 재사용 가능성을 확인하는 샘플이며 매번 세 개를 만드는 요구가 아니다. 동시 작업 한도와 시간 예산은 사용자 여유에 맞춰 정한다.
생성 후보의 예상 검토 시간이 남은 예산을 넘으면 새 제작을 대기시키고 기존 묶음을 먼저 마무리한다. 자료 받기·읽기를 차단하지 않으며, 다음 후보는 요약된 보관 목록으로 남긴다. 실제 검토 시간이 쌓이기 전 예상치를 실측처럼 표시하지 않는다.
운영 순서는 긴급 정정·기한 있는 확인 → 진행 중 검토 → 검토 완료 묶음의 선택 일정 → 새 제작이다. 매일 발행을 기본값으로 넣지 않는다. 주제의 시효·관점 중복·검토 여유를 보고 일정 후보를 제안한다.
일정에는 대상 계정/채널, 사본 판, 기준 시간대, 공개 가능 시각, 마감/만료 조건을 둔다. 같은 내용을 여러 채널에 동시에 보내는 기본 규칙을 만들지 않는다. 검토가 늦으면 날짜를 다시 제안하고 미검토 묶음을 자동 발행하지 않는다.
운영 토글은 새 기획, 제작, 외부 전달을 따로 멈출 수 있어야 한다. 중지는 성공한 자료를 삭제하지 않으며 아직 시작하지 않은 일을 취소한다. 채널별 재시도·중복 방지·실제 예약 지원은 운영 담당의 계약을 따른다.

## 9. 한 주제에서 세 형식으로 만드는 완성 예시

다음은 **합성 기획·비공개 초안**이다. 사용자 체험·확정된 브랜드·학습 효과·SNS 성과를 주장하지 않는다. 주제는 ‘읽은 뒤 남은 질문 하나로 다음 읽기를 고르기’, 가상 독자는 ‘독서 뒤 생각을 정리하고 싶은 사람’이다. 발행 언어·채널·세 형식 운영 여부는 미정이다.

| 연구 묶음의 항목 | 내용 | 사용 상태 |
| --- | --- | --- |
| 질문 | 읽은 내용을 바탕으로 다음에 무엇을 확인할까? | 탐구 질문 |
| C1 | ‘자료를 덮고 떠올리는 연습이 다시 읽기보다 장기 기억에 유리하다’ | **근거 필요**. 대상·조건·측정 시점의 원문 확인 전 효능 문장으로 사용 금지 |
| C2 | ‘짧은 질문 기록이 읽기 지속성이나 집중력을 높인다’ | **근거 필요**. 이번 예시의 효과 설명으로 사용 금지 |
| P1 | 다음 행동을 정할 때 요약과 남은 질문을 구분해 보자는 제안 | 편집 제안. 사용자 관점 채택 전 |
| 사례·자산 | 자체 작성 문장·빈 메모·도형만 사용 | 타인 본문/사진·사용자 경험을 꾸미지 않음 |

기준 원고의 논지: “정확히 기억하는지 시험하거나 점수를 매기기보다, 지금 이해한 부분과 다시 확인할 부분을 나누어 다음 읽기를 고르는 방법을 제안한다.” C1·C2가 미확인인 동안 아래 본문에는 연구 효과를 넣지 않는다. 원문 근거가 확보되면 효과 문장을 무조건 추가하지 말고 이 독자 질문에 필요한지 다시 판단한다.

### 형식 A — 짧은 글

**다음 읽기를 고르는 질문 하나**

책을 덮은 뒤 정리가 필요하다면 두 문장만 적어보세요.
“지금 내 말로 설명할 수 있는 것은 무엇인가?”
“다시 확인하고 싶은 것은 무엇인가?”
첫 문장은 현재의 해석이고, 두 번째 문장은 다음 읽기의 후보입니다. 기억이 불확실한 부분은 원문에서 확인하면 됩니다.
남은 질문 하나를 고르고, 다시 펼칠 장이나 구절을 표시해 두세요.
다음 읽기는 그곳에서 시작해 봅니다.

### 형식 B — 카드 5장

1. **다음 읽기, 어디서 시작할까?** 다 읽었다는 표시 대신 남은 질문 하나를 골라봅니다.
2. **현재의 해석** “지금 내 말로 설명할 수 있는 것은?” 책의 문장과 자신의 해석을 섞지 않습니다.
3. **확인할 부분** “어떤 부분을 다시 보고 싶은가?” 기억이 흐릿하면 원문으로 돌아갑니다.
4. **다음 선택** 질문에 필요한 장·구절·다른 자료 중 하나를 고릅니다. 모두 읽을 계획을 세울 필요는 없습니다.
5. **다음번에 펼칠 곳** 고른 질문 옆에 다시 볼 장이나 구절을 표시해 둡니다. 다음 읽기는 그곳에서 시작해 보세요.

### 형식 C — 짧은 영상 대본·장면

| 장면 | 화면 | 내레이션·동일 의미 자막 |
| --- | --- | --- |
| 시작 | 자체 제작 책 모양과 물음표 | “다음에 어디부터 읽을지 막막하다면, 질문 하나를 골라보세요.” |
| 구분 | 빈 메모의 ‘현재 해석’ 칸 | “지금 내 말로 설명할 수 있는 부분을 떠올려봅니다.” |
| 확인 | ‘다시 확인할 부분’ 칸 | “불확실한 부분은 기억으로 채우지 않고 원문에서 확인합니다.” |
| 선택 | 질문에서 장·구절로 이어지는 선 | “그 질문에 필요한 한 곳을 다음 읽기 후보로 고릅니다.” |
| 종료 | 화면에 ‘질문 하나, 다음 읽기 한 곳’ | “질문 하나와 다시 볼 곳 하나. 다음 읽기는 그곳에서 시작해 보세요.” |

실제 영상은 아직 제작하지 않았다. 재생 길이는 음성·자막·장면을 완성한 뒤 확인하며 채널 제한을 가정하지 않는다. 음원·인물 영상 없이 자체 도형과 텍스트로도 제작할 수 있는 안이다.
세 사본의 공통 요소는 질문·해석/원문 구분·다음 선택이다. 글은 여유 있는 설명, 카드는 순서, 영상은 장면 진행으로 전달한다. 제목을 더 강하게 만들기 위해 미확인 C1·C2를 끌어오지 않는다.

## 10. 성과 확인과 다음 탐구의 연결

| 확인할 가치 | 실제로 남길 근거 | 자동으로 단정하지 않을 것 |
| --- | --- | --- |
| 내가 필요한 자료를 받는가 | 직접 고른 유용/무관 이유, 놓친 질문, 읽을 후보의 중복 | 피드 노출·저장이 이해 또는 호감이라는 추정 |
| 제작 부담이 줄었는가 | 같은 결과의 재입력·검토 시간·수정 횟수·대기량 | 생성량 증가가 개인 여유 증가라는 판단 |
| 내용이 정확한가 | claim별 근거 충족, 정정·반려 이유, 미확인 유지 | AI 검사 통과가 사실의 보증이라는 주장 |
| 전달이 적절한가 | 선택 채널이 실제 제공하는 도달·유지·반응의 정의/기간 | 조회가 학습 효과, 저장이 동의, 댓글이 전체 독자 의견이라는 해석 |
| 다음 탐구에 도움이 되는가 | 남은 질문·반대 사례·독자 요청을 원문과 분리해 채택 | 반응이 많은 주제가 내 신념·다음 발행 의무라는 결론 |

채널 성과는 같은 정의·형식·관찰 기간·유입 조건끼리 비교한다. 제목·주제·형식·일정을 동시에 바꾸고 한 원인으로 설명하지 않는다. 작은 표본·특이치·관측 누락은 그대로 남기며 플랫폼마다 다른 ‘조회’ 지표를 한 점수로 합치지 않는다[S1][S2].
피드백은 ‘다음에 확인할 질문 후보’로 연구 목록에 연결한다. 댓글의 주장·개인 사례는 검증된 연구 근거가 아니며, 자동 답글·DM·개인 프로필 추론을 실행하지 않는다. 단순한 관심 반응을 추천 설정 변경이나 공개 약속으로 승격하지 않는다.
게시가 없어도 이해·내 생각·실천이 남으면 개인 작업은 완결된다. 발행을 선택했다면 표현 결과를 별도로 확인한다. 플랫폼 도달과 개인의 이해·도움·관점은 각각 보고한다.

## 11. 채택·축소·중단과 검수

소비 운영 묶음의 완료는 저장한 관심 기준 → 지원되는 자료 입구 → 소수 후보 → 읽기/선택 리뷰 → 필요한 기준 조정이다. 실제 자료 수신과 사용 부담을 확인하기 전에는 운영 완료·추천 효용을 주장하지 않는다.
선택적 제작 묶음의 완료는 선택 근거 → 기준 원고 → 필요한 사본 → 변경 검토 → 보관·재열기까지다. 외부 운영을 포함하는 이후 작업은 정확 게시/예약 결과와 중지·복구까지 별도로 확인한다. 문서와 비공개 초안만으로 실제 SNS 운영 완료를 보고하지 않는다.
채택 기준은 같은 목적의 수동 준비보다 재입력·검토 부담이 줄고, 개인 관점·사실·권리·정확 판이 보존되는가다. 비교에는 같은 연구 묶음·선택 형식·완료 조건을 사용한다. 글 하나와 세 형식 묶음의 단순 소요시간을 직접 비교하지 않는다.
대기열이 반복 증가하면 새 주제·형식을 줄인다. 같은 오류가 반복되면 해당 생성 단계의 자동화를 낮추고 원인을 수정한다. 독자 가설이 맞지 않으면 질문·대상부터 바꾸며 생산량으로 보상하지 않는다.
제작·전달에서는 근거 없는 주장, 사용자 경험 위조, 선택 밖 개인 자료, 권리 미확인 자산, 오래된 검토 판의 전달이 완료 차단이다. 해당 묶음을 보류하면서 이미 가능한 개인 읽기·보관·실천은 유지한다.
검수 반례는 근거 누락/새 판, 관점 미채택, 번역에서 조건 누락, 자산 권리 만료, 검토 후 수정, 대기량 초과, 중지 직후 응답, 중복 전달 요청이다. 저장한 브리프·사용자 수정·기존 사본을 보존하고 영향받은 결과만 재검토한다.
첫 실행 산출물은 **소비용 관심 기준·지원 계정 기능의 능력표·소수 후보 선별·선택적 짧은 리뷰·다음 기준 조정**이다. 실제 계정 변경·외부 전송·가동은 당시 허용된 요청을 따른다. 선택적 제작 확장은 유용한 탐구 묶음을 고른 뒤 브리프·필요한 형식·운영 비활성 검수까지 별도 완료 조건으로 적용한다.
