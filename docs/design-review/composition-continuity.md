# 구성 이어쓰기의 사용·품질 검토

2026-10-06 KST. 디자인·통합 책임: root. 기존 관리 화면에 묶음·내 페이지·회고·관련 기록 제외의 선택 연결을 추가했다. 읽기 피드·본문·전역 탐색은 유지한다. [제품 계약](../life-tools-design/device-continuity.md), [SQL 설치 인계](../life-tools-design/composition-installation.md)를 따른다. **운영 설치·배포는 대기 중**이다.

## 사용 결과로 정한 완료 기준

두 분리된 브라우저에서 같은 계정의 원문과 구성을 이어 편집한다. 오프라인 동시 변경은 양쪽이 남아 있고, 고르지 않은 쪽을 통합 JSON으로 내려받아 새 사본으로 복원할 수 있어야 한다. 응답 유실·계정 변경·SQL 미설치를 성공으로 표시하지 않는다. 초안·공개본·연표 값은 전송 범위를 바꾸지 않는다.

## 화면과 독립 검토 반영

- 관리의 기존 원문 상태 아래에 구성 상태·연결/중지·비교를 둔다. 버튼은 기존 라벤더 강조·44px 조작과 한글 본문 토큰을 재사용한다. 새 라이브러리·상시 상태 패널·메뉴는 추가하지 않았다.
- 처음 시작할 때 포함 범위와 원문 선행 조건을 보여준다. 내부 revision·operation ID를 기본 UI에 노출하지 않는다.
- 충돌은 제목·코멘트뿐 아니라 고른 정확 원문의 제목/버전/본문 일부·표시를 펼쳐 확인한다. 개수만 같아서 다른 선택을 알아보기 어려웠던 초기 구현을 수정했다. 누락된 버전을 최신 버전으로 대체하지 않는다.
- 원격 요청이 멈춰도 중지를 누를 수 있다. 오래된 작업의 종료가 새 상태/오류를 바꾸지 않게 했다. 주기적 갱신에서 펼친 상세와 키보드 초점을 유지한다.
- 첫 시각 검토에서 발견한 연속 구분선은 섹션마다 하나로 줄였다. 복구 사본은 비교 아래에 펼쳐 다운로드하며 파일 범위와 복원 위치를 설명한다.

디자인 책임자가 위 화면을 직접 확인했다. 한글 긴 제목은 `keep-all`/`overflow-wrap`로 읽고, 비교 상세는 높이를 제한해 펼쳐 읽는다. 전체 페이지 캡처의 하단 고정 메뉴 위치는 실제 화면 높이 기준이며 문서 전체의 바닥을 뜻하지 않는다. 키보드 초점은 상세 갱신 후 같은 요약에 남는다.

- Node 회귀 290 통과. 새 transport는 공유 인증 범위·응답 형식·요청 스냅샷·취소를 확인했다. manager는 중지 후 새 요청·예약 직후 계정 변경·동일 영수증 재시도·A→B→A의 늦은 응답을 확인했다.
- [구성 브라우저 결과](evidence/composition-continuity/report.json): 9/9 시나리오, 1440·820·390px의 7상태/21캡처. 미연결·로딩·빈 구성·충돌·동일 개수 다른 버전·연결 중지·설치 오류를 확인했다. 가로 넘침·44px 조작·접근 가능한 이름·대비 검사 통과(측정한 텍스트 최소 6.05:1). Playwright 1.63.0/시스템 Chromium 151.0.7922.173, 모의 Auth/HTTP와 실제 IndexedDB이며 예상 외 console/pageerror 0, 의도한 HTTP 오류 4건이다. 접근성 전체 적합성 인증은 아니다.
- 실제 IndexedDB/BroadcastChannel 구성 저장 13조건, 기존 Workbench 저장 5조건 통과. 둘은 모의 서버 검증과 구분한다.
- 원문 동기화 회귀 14조건, 공용 인증/PWA 경계 9조건 통과. 보존한 v68 정적 산출물에서 v69로 갱신하며 원문·가져오기 초안·기존 연표 로컬 키를 유지했다. 의도한 전송/콜백 실패와 예상 외 오류를 구분했다.
- 격리 PostgreSQL 17.11 역할/RLS/RPC 163조건·설치 11조건·다중 트랜잭션 4조건 통과. 기존 자료·구조·권한 보존, 검사 컨테이너 정리. 운영 합성 쓰기는 하지 않았다.

새 구성 저장·브라우저 흐름을 기존 GitHub Actions의 고정 Playwright/Chromium 검사에 추가했다. 앱을 공개하는 build/deploy는 이 검사에 의존한다. 로컬 시스템 Chromium 결과와 CI의 고정 Chromium 결과를 같은 실행으로 보고하지 않는다.

직접 실행: `npm run dev -- --port 4184` 후 `BASE_URL=http://127.0.0.1:4184 PW_MODULE_PATH=/사용할/playwright/경로 node tests/composition-sync-browser.cjs`. 실제 운영 체험은 설치·배포 뒤 A에서 원문 연결 → 구성 시작 → B에서 서버 작업공간 받기 → 구성 시작/비교 → 내 페이지 열기 순서다. 변경 중 공개 게시를 누르지 않아도 비공개 구성이 이동해야 하며 공개본은 바뀌지 않아야 한다.
