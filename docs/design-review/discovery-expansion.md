# 외부 공급 보완과 같은 목록의 두 순서 비교

2026-10-19 KST. [첫 발견 흐름](external-discovery.md) 다음 P1인 **빈 관심 원인 진단 → 공식 공급 보완 → 같은 시점 카탈로그의 관심순/최신순 비교 준비 → 새 출처의 원문·명시 보관·복귀·보존 검수**를 진행했다. 기존 자동 관심 분석 비활성·원문 보존·명시 저장·계정/공간별 피드백 경계는 유지한다. 이번 작업도 main 병합·공개 배포·운영 계정 변경을 실행하지 않았다.

## 결과와 실제 사용

공식 피드의 한국어 메타데이터는 **20개→50개**다. 서울시 문화 10·우아한 기술블로그 10개에 독서신문 최신 20·서울시 환경 10개를 추가했다. 등록 피드 5개 중 4개 성공, D2는 robots의 HTTPS→HTTP 이동을 차단해 실패·이전 성공 없음·0개다. 최신 한 번의 수집은 2026-10-18T18:41:59Z, 한국 시각 10월 19일 03:41:59다. 기존 20개 글의 ID를 모두 유지했고 브라우저 검증 탈락은 0이다. 모두 metadata_only/link_only이며 본문·요약·이미지를 복사하지 않는다.

`npm run dev` → 공용 인증 설정이 있는 환경에서 로그인 → 도구 → 관심 확인에 `신간`을 직접 보관 → 새 글 찾기에서 최대 5개를 읽는다. `공연`은 1개다. 원문 제목을 눌러 새 탭을 열고 돌아온 뒤 `링크 보관 검토 → 원문·출처 확인 → 자료만 보관`하면 기존 원문 읽기로 이동한다. 목록으로 돌아오면 같은 URL은 제외된다. Cloud localhost는 외부 기기 체험 주소가 아니며 실제 Google/Apple 체험과 자동 검수의 익명 인증 모사는 구분한다.

공개 비교 자료를 재현하려면 다음 명령을 쓴다. 새 출력 경로가 필요하며 기존 검토는 덮어쓰지 않는다.

```sh
node scripts/evaluate-discovery.cjs --out .local/discovery-comparison-new
```

[이번 실제 비교 목록](evidence/discovery-expansion/comparison.md)을 먼저 읽고, [비교 JSON·미평가 양식·조사 근거 묶음](evidence/discovery-expansion/evaluation-bundle.zip)의 `review-template.json` 복사본에 원문을 직접 본 뒤 판단을 기록한다. 새로 생성하는 명령도 evaluation.json/evaluation.md/review-template.json 세 파일을 만든다. 양식은 관심별 글의 읽을 만함·이미 앎·무관함과 두 순서 선호를 묻는다. 현재 59개 검토 행의 판단/메모와 9개 순서 선호는 모두 null이며 사용자 효용을 판정하지 않았다.

## 원인 진단과 바뀐 검색

기존 20개 카탈로그와 core SHA를 동결해 먼저 읽기 전용 진단했다. 독서·클라우드·기후변화·접근성에는 title/tags의 동일 표현·현행 동의어 단서가 없다. 공연은 ‘공연봄날’, 전시는 결합된 명칭에 부분 문자열이 있지만 독립 단어 경계가 아니어서 제외된다. 이 결합명칭을 임의로 쪼개거나 독서를 책·신간으로 자동 확장하지 않았다.

실제 결함은 **AI가·AI에게**처럼 영문 표현 뒤 한글 조사가 붙을 때 제목 근거를 놓친 점이다. 완전한 조사 뒤 실제 경계가 끝나는 경우만 수용해 기존 글 3개의 제목 근거를 복구했다. 기존 AI 5개는 태그로 이미 검색됐으므로 결과 수를 새로 늘린 개선이라고 세지 않는다. `RAIL`, `PAID`, `GenAI`, `AI가나다`, `공연봄날` 같은 임의 내부 문자열은 계속 제외한다. 근거는 원래 필드의 정확 UTF-16 구간이며 원문을 정규화하지 않는다.

| 공개 관심 | 이전 20개 전체 일치 | 현재 50개 전체 일치 | 현재 표시 | 같은 공급 최신순 5개와 공통 |
| --- | ---: | ---: | ---: | ---: |
| AI | 5 | 7 | 5 | 1 |
| 전시 | 3 | 3 | 3 | 0 |
| 공연 | 0 | 1 | 1 | 0 |
| 독서 | 0 | 0 | 0 | 0 |
| 클라우드 | 0 | 0 | 0 | 0 |
| 기후변화 | 0 | 0 | 0 | 0 |
| 접근성 | 0 | 0 | 0 | 0 |
| 책 (추가 표본) | 0 | 1 | 1 | 0 |
| 신간 (추가 표본) | 0 | 7 | 5 | 0 |

공급 확대가 모든 빈 관심을 해결하지는 않았다. 독서신문이라는 출처명으로 독서 태그를 만들지 않고, 서울 환경이라는 분야 이름으로 기후 관심을 추정하지 않는다. 서울 환경에는 행사·공원·행정 안내가 섞여 있으며 현재 공연 제목 1개에 직접 일치한다. 관련 없는 글로 3~5개를 채우지 않는다. 위 일치 수·교집합은 자동 집계이며 문맥 적합성·새로움·읽고 싶음의 평가가 아니다.

## 채택·보류 근거

[공급 계약과 공식 링크](discovery-sources.md), 묶음 안의 research-reading.json/research-topics.json/research-environment.json에 실제 HTTP 상태·원응답 SHA·공식 날짜·robots·권리 근거를 남겼다. 개인 연락처·기사 본문·description·이미지·정책 전문은 공개 증거에서 제외한다.

- **독서신문:** 홈→공식 RSS 안내→실제 피드 200/50개. 안내는 외부 사이트에서 제목·링크 등을 수집해 표시하는 예를 명시한다. 일반 저작권정책의 무단 본문 복제/전송 금지도 보존하고 metadata_only로 제한한다. 원문 HTTPS·공식 article:published_time의 +09:00과 RSS 무시간대 날짜를 대조했다. category가 없으므로 태그를 만들지 않는다. 기존 출처별 20개 상한으로 최신 20개를 받았다.
- **서울시 환경:** 기존 문화와 같은 공식 news.seoul.go.kr의 robots 허용·공식 홈/피드 200/유효 10개, 서울시 저작권의 개별 표시 조건을 유지한다. 원문·요약을 재배포하지 않는다. 별도 seoul.go.kr의 RSS 안내 주소는 robots 금지로 요청하지 않았으며 그 문서를 읽었다고 주장하지 않는다.
- **AWS 한국 블로그:** 공식 RSS와 클라우드 글은 확인했지만 Site Terms에 자동 수집/추출 제한이 명시돼 RSS 예외를 확인하기 전까지 제외했다. robots 허용을 이용 허락으로 바꾸지 않았다.
- **NHN Cloud·Kakao Tech:** 정상 최신 RSS라도 현재 제목·분류에 목표 클라우드/접근성/기후 표현이 없어 추가하지 않았다. NAVER Cloud·널리·일부 출판사는 robots 단계의 차단/실패를 우회하지 않았다.
- **문체부·서울문화투데이·아트인사이트 등:** 원문 HTTP, 손상된 XML, RSS 재게시 권리 근거 미확정 등을 각각 구분해 제외했다. 피드를 임의 복구하거나 HTTP를 추정 HTTPS로 바꾸지 않았다.

이번 범위는 채택한 2개 추가 피드로 고정했고 출처 수를 목표로 더 탐색하지 않았다. 새 패키지 없이 기존 제한 parser·Core·Storage·Discovery.rank를 재사용한다. feedparser와 표준 XML 보안·정확 검색 라이브러리의 앞선 비교는 [오픈소스 검토](../life-tools-design/open-source-review.md)에 연결했다.

## 식별·날짜·비교 재현성

collector의 query 파서가 `%20`을 `+`로, `%2f`를 `%2F`로 바꾸는 실제 불일치를 고쳤다. 알려진 추적 key만 제거하고 필수 값의 표기·순서·중복을 유지해 브라우저 canonicalUrl과 맞췄다. 5분 넘는 미래의 공식 발행/수정 시각은 원값·future를 유지하되 최신 발행 정렬에 쓰지 않는다. 이전 generatedAt/수집 성공·시도 시각이 명확히 손상되거나 역전되면 새 파일로 전파하지 않고 기존 bytes를 보존한 채 실패한다.

비교 도구는 원본 feed bytes의 SHA와 core SHA, generatedAt와 평가 시각을 고정한다. 9개 표본 모두 같은 전체 공급의 최신순 top5이며 양쪽에 동일한 공개 관심·limit5·knownUrls[]·feedback[]를 적용한다. 개인 작업공간·관심·보관/피드백을 읽지 않으므로 개인화된 실제 새로움 평가와 구분한다. 검증 탈락 기사가 있으면 조용히 빼지 않고 비교 생성을 실패시킨다. 근거를 원래 필드의 정확한 slice와 대조하고 입력을 변경하지 않는다. 기존 출력 디렉터리/파일/심볼릭링크는 거절해 사용자 검토 덮어쓰기를 막는다. 링크 접속·원문 읽기·모델 요청은 수행하지 않는다.

## 검증과 다음 조건

단위 검사 **747/747**, 정적 검사 HTML 19·JS 118·로컬 참조 477 통과. 단위 검사에는 공급 16·검색 19·비교 도구 9와 기존 전체 회귀가 포함된다. 최종 feed/core 동결 후 v130→v131 PWA **9/9**, 사이트 산출물 **2/2**를 통과했다. 설치 모듈 해시, 원문·구성·수동 관심·피드백 보존, 독립 feed 갱신·stale/수신 시각·캐시 없음·엄격한 인증 거절/복구·차단 probe 3개를 확인했다. 개인 데이터/원문 사이트/모델의 자동 요청은 없다.

독립 브라우저 검수의 최종 결과는 [browser.json](evidence/discovery-expansion/browser.json), 시각 캡처와 CI는 [manifest.json](evidence/discovery-expansion/manifest.json)을 따른다. 새 두 출처의 native 원문 새 탭·복귀·기존 3단계 명시 링크 보관·중복 제외와 기존 피드백/원문/관심/workbench 보존을 확인한다. publisher popup 응답은 가로챈 합성 응답이며 실제 원문 페이지 읽기로 세지 않는다. 실제 공개 RSS GET과 익명 Auth/합성 오류 주입을 분리했다. 앞선 commit26093f3의 CI는 전체 성공을 확인했다. 이번 HEAD의 CI와 운영 배포는 별도다.

CI `39155636667`에서는 새 두 출처·PWA가 통과했지만 로그아웃 뒤 계정 전환 검사 1개가 `ERR_ABORTED`로 실패했다. 실제 logout 응답과 다음 login 문서 요청을 조절해 같은 경합을 재현했다. 개인 영역/저장소 닫힘은 SDK 종료와 자동 공개 홈 이동보다 먼저 끝나므로, 검사가 새 문서와 공개 홈 표시를 확인한 뒤 다음 login으로 이동하도록 보완했다. 임의 sleep·오류 무시·timeout 증가는 추가하지 않았고 계정 격리 검증은 유지했다. [재현·수정 기록](evidence/discovery-expansion/ci-regression.json)에 실패 CI와 로컬 재검증을 구분한다. 최종 CI 상태는 PR의 현재 HEAD를 따른다.

다음 P1은 접근 가능한 실행본에서 사용자 평가 양식으로 두 순서의 읽을 만함·이미 앎·무관함·조작 부담을 확인하는 것이다. 남은 0개 관심은 사용자 평가에서 필요성이 확인된 허용 공급 또는 사용자가 직접 고른 관심 표현으로 보완한다. 출처명·임의 동의어·제목 부분 분해로 수를 채우지 않는다. 실제 Google·Mac/iPad/iPhone·운영 버전/캐시 검증은 미완료이며 릴리스 권한 안에서 진행한다. 자동 추출 연구는 P2로 유지하고 새 가설·비용 상한·독립 평가가 준비될 때 재개한다.
