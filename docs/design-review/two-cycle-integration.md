# 두 순환을 실제 사용 흐름으로 연결하기

2026-10-13. 디자인·통합 책임자 Codex. `codex/two-cycle-integration`은 main `29a325b` 위에서 미병합 기능을 함께 검증하는 브랜치다. 운영 SQL·main 병합·배포는 Local 담당이며 이번 Cloud 작업은 개인 자료를 읽거나 운영 게시본을 생성하지 않았다.

## 목표와 통합 범위

자료 선택 → 정확 원문 읽기·근거 검토 → 직접 생각 작성 → 개인 파일 또는 비공개 페이지 → 선택 게시·철회 → 새 경험과 질문으로 돌아오기. 기존 기능을 연결하며 책 확장, 자동 SNS 수집/수정, AI 전송, 자동 공개를 추가하지 않았다.

- P0: 연표 복구, 홈 재진입, 하위 화면 복귀, 관리·백업 범위.
- P1: 원고 중심 회고와 근거의 관심/질문/변화 보기. 타인의 글을 자신의 생각으로 분석하지 않는다.
- P2: 계정별 컬렉션, URL 정보 검토, 선택적 표지, 대상 선택. 기존 컬렉션 선등록 없이 글에 대상을 붙일 수 있다.
- P3: 내 페이지 글·첨부·피드·미리보기·선택 게시. 회고에서 페이지로 내 생각을 옮기는 연결을 보완했다.

통합한 선행 PR: #56, #58, #59→#60→#61, #64, #66→#67→#68→#69→#71→#72, #73. #70은 대체된 방향이며 제외했다. #63/#65는 시안으로 필수 선행 구현이 아니다. 각 병합은 별도 커밋으로 유지했다. 작업공간의 미커밋 변경을 없애거나 운영 자료를 테스트 샘플로 대체하지 않았다.

## 직접 체험

`npm run dev`로 실행하고 테스트 계정으로 로그인한다. 로컬 인증 반환 URL은 기존 환경 설정을 따른다.

1. 기록에서 여러 시기의 원문을 가져오고 선택하여 회고로 보낸다. 최신 버전이 생겨도 선택한 과거 버전·출처를 유지한다.
2. 도구 → 회고에서 연도별/묶음별 또는 관점으로 읽기. 지금의 생각을 쓰고 읽던 자료로 돌아간다.
3. `원고 파일로 보관`을 펼쳐 Markdown을 받거나 `내 생각을 새 페이지 초안으로`를 누른다. **현재 회고 텍스트만** 비공개 초안으로 복사된다. 원문·근거·첨부는 자동 복사되지 않는다. 사용자가 회고 안에 직접 인용한 문장은 그대로 복사되므로 게시 전 저자·출처를 확인해야 한다.
4. 내 페이지에서 음악·책·도구 등의 대상을 붙이고 비공개 저장한다. 회고로 돌아가도 원래 생각은 유지된다. 수정한 페이지 초안을 원래 회고로 덮어쓰지 않는다.
5. 원하는 글만 공개 후보로 고르고 방문자 미리보기·공개 검토 후 명시적으로 게시한다. 후보 선택은 게시가 아니다. 게시·철회 실서버 체험은 Local의 SQL 확인 후 수행한다.
6. 관리 → 자료·구성 백업에서 JSON을 받고 새 사본으로 복원한다. 기존 작업공간은 남는다. 컬렉션 전용 백업과 페이지 작성 중 초안 파일은 별도 범위다.
7. 회고로 돌아가 실제로 해본 결과와 다음 질문을 남긴다. 이미 저장한 페이지 글은 자동 변경되지 않는다.

## 설계와 실패 복구

새 라이브러리나 스키마를 추가하지 않았다. 기존 `PagePosts.draft/validate`, 계정별 `page-drafts`의 revision 비교 저장, `PageComposer`, 공통 탐색을 재사용한다. 외부 편집기나 워크플로 엔진은 텍스트 한 건을 기존 초안에 명시 복사하는 요구보다 도입·업그레이드 비용이 크다. 선행 컬렉션/미디어의 공식 배포·라이선스 비교는 [기존 비교 기록](../life-tools-design/open-source-review.md)에 있다. 이번 통합을 신규 외부 라이브러리 평가/도입으로 보고하지 않는다.

회고 저장이 먼저 성공해야 초안을 만든다. 초안 저장 실패·동시 탭 충돌에서는 회고 화면과 입력을 유지하고 다른 탭의 초안을 덮어쓰지 않는다. 다시 누르면 최신 초안 목록을 읽는다. 같은 화면 세션에서 수정하지 않은 복사본은 재사용하며, 이미 고친 복사본은 보존하고 별도 초안을 만든다. 새로고침을 넘는 영구 복사 이력은 추가하지 않았다. 계정/작업공간과 화면 수명이 바뀌면 늦은 결과로 이동하지 않는다.

복귀 버튼은 회고의 원래 조작과 스크롤을 복원한다. 초안 처음 열기에서는 본문 시작에 초점을 놓는다. 기존 한글 composition·저장 실패 시 이동 차단·계정별 저장 계약을 유지한다. 읽던 근거로 돌아갈 때 숨겨진 일반 목록 대신 현재 보이는 관점의 정확한 행을 사용한다.

## Local 일괄 실행

1. Local의 현재 변경을 보존하고 통합 브랜치와 비교한다. 통합 PR 하나에 위 선행 PR 커밋이 포함되어 있으므로 같은 PR들을 다시 순차 병합하지 않는다. Local만의 변경이 있다면 통합 후 관련 검사부터 다시 실행한다.
2. #71 `supabase/migrations/20261012010000_life_page_posts.sql` 설치 여부를 확인한다. 미설치일 때만 적용하고 `supabase/tests/life-page-posts-installation.sql`의 읽기 전용 **8조건**을 확인한다. 이번 통합은 추가 SQL이 없다. 기존 동기화·게시 SQL을 재설치하거나 과거 합성 운영 검사를 반복하지 않는다.
3. 통합 PR의 check/browser 성공과 포함 파일을 확인한다. 브랜치 변경 시 캐시 버전·공개 산출물의 reflection/collection/page 모듈을 함께 검토한다. 새 저장값을 가진 자료를 옛 strict client에 맞춰 삭제하는 롤백은 금지한다. 필요하면 UI 연결만 되돌린다.
4. 실제 테스트 자료로 로그인 → 기록·회고 → 비공개 초안 → 취향 첨부 → 저장·다시 열기 → JSON 새 사본 복원. Apple IME·Files·분할/회전과 실제 YouTube/Open Library 요청을 확인한다.
5. 사용자 승인 범위에서 Local이 main 병합·배포하고 라이브 로그인·위 흐름·기존 캐시 갱신을 재확인한다. 실서버 게시·철회는 테스트용 자료를 명시 선택해 확인한다.

## 다음 우선순위와 순환 B

1. **Local 일괄 적용과 실제 사용 피드백:** 가장 먼저 사용자가 멈춘 위치, 기대한 결과, 실제 결과를 남긴다. 이 문서의 에이전트 체험을 사용자 평가로 대체하지 않는다.
2. **한 입구에서 다시 찾기:** 원문·페이지 글·컬렉션의 검색 범위와 결과 출처를 구분하면서 해당 항목으로 돌아가기. 현재 원문 검색에 모든 종류가 포함됐다고 약속하지 않는다.
3. **출력 선택의 발견성:** 현재 접힌 파일 영역에서 페이지 초안 연결을 찾는지 확인한다. 찾지 못할 경우 같은 자료로 두 배치를 비교한 뒤 수정한다. 지금 새 전역 메뉴를 추가하지 않는다.
4. P4 자동 입력/이름 검색 제공자·AI/외부 채널은 접근·권한·개인정보·유지 비용을 따로 설계한다. 책 확장은 계속 보류한다.
