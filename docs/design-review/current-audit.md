# 현재 화면 디자인 감사

2026-10-03. 기준 코드 `d44772d`의 앱을 로컬 서버에서 실행했다. 앱 HTML·JS·CSS는 변경하지 않았다. 디자인 평가는 아래의 실제 캡처 관찰과 개선 가설을 구분한다. 기능 동작 검사 통과를 시각 품질 승인이나 실제 사용자 평가로 해석하지 않는다.

## 화면과 시작 조건

- 공개 홈: 로그인하지 않은 첫 방문. 다음 진입점과 제품 목적을 살펴본다.
- 원천 검색: 합성 계정의 자료 네 개에서 `다시 읽기`를 검색한다. 이전 버전 본문 일치, 최신 본문 일치, 제목만 일치, 본문 미확보 링크 자료를 같은 결과에 둔다.
- 긴 원문: 검색에서 이전 버전의 일치 구절을 열어 원문 안으로 이동한다. 구절 선택, 주제·메모 입력 후 원문에 다시 포커스를 둔 상태다. 화면은 그 실제 읽기 위치에서 캡처했으므로 페이지 최상단과 다르다. 저장 버튼은 누르지 않았다.

본문·제목·메모·작성자 계정은 모두 익명 합성 자료다. 원문에는 CRLF·한글·이모지와 반복 문단을 포함했다. 반복 문단은 긴 읽기 화면을 재현하는 재료이며 실제 사용자의 글이나 읽기 행동이 아니다. 원문 작성 시각은 미상, 가져온 시각은 비교용 고정값이다.

## 관찰과 개선 가설

| 관찰 | 자료 | 개선 가설·시안에서 볼 점 |
| --- | --- | --- |
| 자료 화면의 상단에 전역 메뉴·계정, 앱 제목·작업공간, 보기 메뉴·세 개 작업 버튼, 저장 안내, 화면 제목·설명, 검색·지우기·원천 필터가 연달아 쌓인다. 첫 검색 카드의 문서 Y 좌표는 1440px에서 777, 820px에서 763, 390px에서 996이다. 390×844의 첫 화면에는 결과가 하나도 보이지 않는다. | 검색 세 크기 및 `report.json` | 읽기·찾기 화면은 검색과 자료가 먼저 보이도록 머리 부분을 압축한다. 작업공간·동기화·사본 기능의 접근 경로는 유지하며 주목도를 낮춘다. 시안에서는 첫 화면에서 검색 입력과 적어도 첫 결과의 제목·일치 문맥을 볼 수 있는지 비교한다. |
| 공개 홈은 큰 제목과 연표 곡선이 대표 이미지다. 기존 자료를 가져오는 가치는 본문의 세 번째 줄에 소개되고, 자료 모아보기 항목은 연표·목표·습관 뒤에 있다. | 홈 대표 캡처와 전체 페이지 | 자료 추출·통합을 먼저 원하는 방문자가 그 용도를 바로 이해할 수 있도록 문구·대표 예시·주요 진입점의 순서를 비교한다. 연표 기능이 잘못됐다는 결론이나 기능 제거 요구는 아니다. |
| 홈과 자료 화면은 같은 종이색 계열을 쓰지만 제목 서체·크기, 주요 버튼 색, 모서리, 메뉴 표현이 다르다. CSS상 공개 홈 제목은 68/48/49px, 자료 화면 앱 제목은 35.2/25.6/25.6px다. 플랫폼 버튼 모서리는 5px, 자료 버튼은 10px다. | 실제 제목 CSS 수치, 두 CSS, 홈·검색 캡처 | 공통 메뉴·활자 단계·색·간격·버튼 세 등급을 먼저 맞춘다. 공개 안내와 개인 작업 화면의 서로 다른 밀도는 허용하되 같은 제품이라는 단서는 유지한다. 수치 자체가 좋고 나쁨의 기준은 아니다. |
| 카드의 버전, 받은 범위, 작성 시각 미상, 긴 ISO 가져온 시각, 일치 유형이 비슷한 크기·색으로 여러 줄을 차지한다. 820/390px에서는 가져온 시각이 줄바꿈된다. 제목과 일치 구절 사이에 이 정보가 끼어 있다. | 검색 전체 페이지 | 제목·일치 문맥을 앞에 두고 버전·본문 확보 범위는 짧게 구분한다. 날짜는 읽기 쉬운 표현으로, 정확한 시각·출처 상세는 펼쳐 확인한다. 미상·이전 버전·본문 미확보는 계속 구분되어야 한다. |
| 원문은 스크롤·크기 변경이 가능한 textarea이고, 포커스 시 두꺼운 테두리가 보인다. 선택 구절이 별도 블록에 반복되며 주제·메모 입력이 옆이나 아래에 상시 표시된다. 820/390px에서 연결 폼은 원문 아래로 내려간다. | 원문 세 크기 | 평소 읽기는 본문 행길이·문단·여백에 집중하고, 선택 후에는 구절·출처·다음 행동을 간결하게 연결한다. 폼을 감추는 것만으로 저장 동작을 찾기 어려워지는 반례도 비교한다. 원문 보존과 키보드 선택은 유지한다. |

따뜻한 색이나 둥근 모서리 자체가 품질을 보장하지 않는다. 위 가설은 자료를 찾고 읽는 목적에 맞춘 위계·밀도·일관성에 관한 제안이며 개인 취향을 객관적 결함으로 판정한 것이 아니다.

## 비교 시안에 넘길 기준

먼저 **검색 결과와 긴 원문·발췌**를 동일한 자료·상태로 비교한다. 공개 홈은 그 방향을 연결해 보여준다. 기존 원천·버전·본문 확보 범위·검색 복귀·발췌 기능의 의미를 유지하며 새로운 기능·페이지·자동 연동을 추가하지 않는다.

- 두 안은 색만 달리하기보다 자료를 찾는 위계와 읽기·선택·메모 배치를 달리한다.
- 1440/820/390px에서 검색 입력, 일치한 제목·구절, 정확한 버전, 다음 행동을 확인한다. 넓은 화면의 여백을 좁은 화면에 그대로 옮기지 않는다.
- 긴 제목, 제목만 일치, 본문 미확보, 긴 원문을 같은 샘플로 비교한다. 폴백 글꼴·한글 줄바꿈도 견딘다.
- 공통 메뉴·버튼 위계·간격·모서리·활자 규칙을 짧게 설명할 수 있어야 한다. 색 외에도 현재 보기·원문 상태를 구분한다.
- 44px 터치 목표, 16px 이상의 주요 읽기·입력 글자, 명확한 키보드 포커스, 가로 넘침 없음, 검색→원문→복귀 맥락 보존은 구현 단계의 확인 항목이다. 이번 감사가 새 시안의 접근성·동작 검증을 대신하지 않는다.

최종 방향 선택은 디자인 책임자와 사용자의 비교 피드백으로 결정한다. 이번 수치는 과도한 화면 머리·정보 위계를 확인하는 근거이며 실제 사용자의 작업 시간이나 선호를 측정한 값은 아니다.

공개 홈의 글꼴 실패는 이 Cloud 브라우저에서 관찰한 실행 조건이다. 운영 사이트의 모든 사용자에게 동일하게 발생한다고 판단하지 않는다. 홈의 활자 품질·미세한 줄바꿈 비교에는 폴백이라는 제한이 있다. 시안에서 로컬 시스템 글꼴을 사용하더라도 플랫폼별 실제 폰트 확인은 별도 필요하다.

## 재현

이미 실행 중인 로컬 서버에서 다음을 실행한다. 앱 의존성·새 브라우저 패키지는 설치하지 않는다.

```sh
node scripts/design-audit.cjs
```

서버가 없다면 별도 터미널에서 `npm run dev`를 실행한다. `BASE_URL`은 localhost 계열만 허용하며 실제 DB 주소로 바꾸지 않는다. 기존 테스트와 같은 익명 HTTP helper를 재사용한다. 캡처 스크립트와 샘플은 [scripts/design-audit.cjs](../../scripts/design-audit.cjs), 상세 기록은 `.local/design-review/before/report.json`이다. 스크립트는 생성한 같은 이름의 감사 캡처를 갱신하므로 필요한 이전 감사 결과는 다른 디렉터리에 보관한다.
