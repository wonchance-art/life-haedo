# 내 페이지 · 본문과 선택적 표지·영상

2026-10-12. #71의 내 페이지 작성 흐름 위에 연결했다. 디자인·통합 책임자는 Codex 한 명이다. 선등록 없이 글을 쓰고 대상을 붙이는 순서, 계정별 저장·동기화·백업·공개 범위를 유지한다. 이번은 Cloud 구현·로컬 검증이며 운영 배포 완료가 아니다.

## 직접 체험

`npm run dev` → 인증된 테스트 환경의 `index.html?section=records&view=page` (기존 `life.html?view=page`도 동일).

1. 글쓰기 → 음악·책·대상 붙이기 → 제목/출처 입력 또는 기존 컬렉션 선택 → 비공개 저장.
2. 지원하는 Open Library ISBN/edition 링크와 YouTube 영상 링크가 있으면 접힌 `표지·영상`에서 외부 이미지를 켠다. 원래 페이지의 제목·소개 아래, 본문 한 열과 4px 간격의 첨부 카드가 나온다. 제목은 잘라 버리지 않고 줄바꿈한다.
3. 음악/영화에 붙인 YouTube 링크도 `영상 보기`로 연다. 자동 재생하지 않으며 닫기/Escape로 원래 버튼에 돌아온다. 제한된 영상은 `YouTube에서 열기`로 확인한다.
4. 화면을 떠나 돌아오면 이미지 설정은 다시 꺼진다. 저장/공개 설정은 바뀌지 않는다.

이름만으로 앨범·영화 포스터를 자동 찾는 기능은 아니다. 책 표지는 확인 가능한 ISBN/edition, 영상 썸네일은 같은 ID의 oEmbed 결과만 사용한다. 음악 영상 썸네일을 앨범 이미지로, 채널을 아티스트로 바꾸지 않는다. 영상/이미지 파일 업로드는 없다.

## 구현·보존 경계

- 기존 `CollectionMedia`의 URL 검증·IntersectionObserver·요청 취소·오류 복구를 재사용한다. 새 `PageMedia`는 화면 수명과 native dialog만 관리한다. 저장 형식, SQL, API 키, 앱 의존성 추가 없음. [공식 오픈소스 비교](../life-tools-design/open-source-review.md#2026-10-12--페이지-피드의-표지영상).
- 외부 이미지는 기본 꺼짐이며 hover/focus만으로 요청하지 않는다. 켜더라도 화면 근처 항목만 요청한다. 끄기/이동/계정 종료/페이지 숨김에서 이미지 요청을 취소하고 iframe을 제거한다. 같은 화면의 내부 다시 그리기에서는 켠 상태만 유지하고, 화면 재진입·새로고침에서는 초기화한다.
- 재생 iframe은 클릭으로만 만들며 고정 호스트/영상 ID, autoplay=0, playsinline=1, 최소 200px 플레이어 높이를 쓴다. 18초 연결 제한과 원본 출처 링크를 둔다. iframe load는 재생 성공의 증거가 아니다. 자막·재생 제어는 YouTube 플레이어의 역할이다.
- 긴 본문(600자 초과)은 피드에서 6줄로 접되 전체 텍스트는 보존한다. 더 읽기/접기·초점·출처를 제공한다. 공개 전 검토에서는 본문을 접지 않는다.
- 공개 후보를 보는 소유자 미리보기에는 명시적 미디어 조작이 있다. **익명 공개 URL과 공개 전 검토에는 외부 이미지/iframe 조작을 넣지 않았다.** 공개 CSP와 스냅샷 allowlist는 그대로이며 제목·출처·본문만 같은 컴포넌트로 표시한다. 내 페이지의 이미지 켜짐을 공개 변경으로 오해하지 않는다.
- 표지 없음·제공자 실패에서도 유형 도형, 본문, 제목·출처가 남는다. 미리보기 설정·이미지 바이트·URL 캐시는 원문/초안/첨부/백업/공개 payload에 추가되지 않는다.

## Local의 다음 일괄 반영

1. 작업 중인 Local 변경을 보존하고 #66 → #67 → #68 → #69 → **#71 → 이 후속 PR**을 비교한다. **#70은 대체된 방향이므로 제외**한다. 이 후속 브랜치의 base는 `codex/page-composer` HEAD `317fc81`이다. Cloud가 main에 병합/배포하지 않는다.
2. #71의 [SQL 설치·읽기 전용 8조건 검사](page-composer.md#local-실행-순서)를 먼저 완료한다. 이번 후속에는 추가 SQL이 없다. 기존 동기화·공개 SQL/합성 운영 검사를 다시 실행하지 않는다.
3. 테스트·공개 산출물에 `page-media.js`와 갱신 CSS가 포함되고 서비스워커가 v97 이상인지를 확인한다. 다른 Local 변경과 합치면 캐시 번호를 새로 정한다.
4. 실제 테스트 자료로 글쓰기 → 비공개 저장 → 이미지 명시 켜기 → 영상 열기/닫기 → 수정/새로고침, iPad/iPhone 터치·회전·앱 전환/복귀와 키보드/VoiceOver를 확인한다. 실패한 이미지에서도 출처가 남고 자동 재생하지 않아야 한다. 실제 서비스 연결이 막혀도 원래 출처 열기는 유지한다.
5. 사용자 승인 범위에서 Local이 병합·배포하고 실제 URL을 확인한다. 공개 후보 변경만으로 자동 게시되지 않는지 확인한다. 이번 후속을 되돌리려면 앱의 UI 변경만 되돌릴 수 있으나 #71의 새 저장 데이터를 옛 strict client에 맞추어 삭제하지 않는다.
