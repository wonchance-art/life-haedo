# 자료 마크다운 읽기·수정·휴지통 통합 설계

2026-10-22 KST. 기준 main `ce9d0d6` / SW154. 사용자 요청은 마크다운으로 보관된 자료의 서식을 표시하고 자료를 수정·삭제할 수 있도록 관련 작업을 한 번에 설계하는 것이다. 사용자의 후속 실행 승인에 따라 아래 계약을 구현하고 통합 검수 중이다. 최종 PR·배포 결과는 문서 끝의 실행 기록으로 구분한다. 기존 앱과 다른 작업 트리는 보존한다.

## 목표와 이번 범위

**자료실 → 마크다운 서식 읽기 → 원문 확인/발췌 → 내 사본 수정·미리보기 → 새 버전 저장·재열기 → 휴지통 이동·복원 → 같은 목록 복귀**를 하나의 실행 단위로 한다. 검색·정확한 인용·이어 읽기·원본 파일/사진·기존 선택 동기화·백업/사본 복원까지 함께 검수한다. 렌더러나 삭제 버튼만 따로 완료 처리하지 않는다.

여기서 자료는 `Source/SourceVersion`에 보관한 TXT·Markdown·링크와 가져온 노트/글이다. 컬렉션의 책·음악 항목, PhotoPost 사진 글, 연표의 삭제 계약까지 한 버튼으로 합치지 않는다. 앱에서 직접 쓴 기존 평문 글의 수정은 기존 WritingUI를 사용하고, 자료실에서의 휴지통 상태는 그 글의 자료 투영에도 반영한다. 기존 앱 작성 글에 Markdown 판을 추가해 `isOwnSource` 판정을 깨뜨리지 않는다.

실행 가설은 **본문의 저장 형식은 그대로 두고 표시·편집 진입·수명주기를 보완**하는 것이다. 기존 자료를 일괄 변환하거나 원본 파일을 덮어쓰지 않는다. 읽기/입력은 기존 단일열, 기본 메뉴·상시 관리 행 추가 없이 기존 출처 정보 패널을 자료 옵션으로 확장한다.

## 읽기와 최소 화면

- Markdown 자료의 기본은 **서식 보기**다. 제목·문단·강조·목록·인용·링크·코드·표·취소선을 지원 대상으로 삼는다. 체크 목록은 읽기 전용으로 표시하고, 수식/임의 HTML/Obsidian 플러그인·내부 링크 해석을 지원한다고 약속하지 않는다.
- 기존 `lifeSourceDetails` 안에 **원문 텍스트 보기 / 서식 보기**, **내 사본 수정**, **휴지통으로 이동**을 모은다. 출처 URL의 **출처 열기**와 마크다운 문자열의 **원문 텍스트 보기**를 구분한다. 상시 설명·관리 카드·두 번째 도구 행은 만들지 않는다.
- 발췌 도구를 열면 정확한 구절을 고를 원문 보기로 연결한다. 서식 화면의 일반 복사 선택을 저장 가능한 원문 locator로 처리하지 않는다. 이미 저장한 발췌·정확 검색 결과·글 근거에서 진입하면 지정한 판의 원문 보기와 정확한 구간을 우선한다.
- 표·코드는 해당 블록 내부에서만 가로 스크롤하며 전체 문서가 넘치지 않게 한다. 한국어 본문·기존 글꼴/토큰, 44px 조작, 16px 이상 입력, 키보드 초점과 터치 동작을 유지한다.
- 편집은 원문 textarea와 **편집/미리보기** 전환의 단일열이다. 모바일 강제 분할이나 새 리치 편집기를 도입하지 않는다. 미리보기는 입력 DOM/value를 다시 만들거나 저장하지 않는다.
- 휴지통은 자료실의 접힌 관리 경로에 둔다. 읽기에서 이동하면 출발 목록, 목록에서 이동하면 이웃 항목으로 초점을 돌린다. 복원은 같은 source ID의 자료로 돌아온다.

## 원문 위치와 이어 읽기

`ui.js`의 `capture/restoreSelection`과 [reading-position.js](../../assets/life/reading-position.js)의 `visibleOffset/queue/selected`는 현재 첫 자식 Text 노드를 전제로 한다. 렌더러만 넣으면 발췌뿐 아니라 이어 읽기도 깨진다.

1. `contentText`, BOM·CRLF/CR·탭·공백·이모지, `contentHash`, 기존 locator는 표시 전환으로 바꾸지 않는다. parser에 전달하는 정규화 사본만 메모리에 둔다.
2. 원문 보기의 발췌·글/9칸 인용·검색 강조는 기존 raw UTF-16 구간을 사용한다. 렌더 DOM의 `textContent` 길이나 반복 문장 `indexOf`로 원문 위치를 역추정하지 않는다.
3. 서식 보기의 이어 읽기는 parser의 **block line map → 원문 문자열의 줄 시작 UTF-16 offset**으로 연결한다. 실제로 보이는 안정된 블록의 시작을 저장하며 글자 단위 정밀 재개로 표현하지 않는다. 중첩 표/목록/인용의 map 중복과 표시 블록이 없는 reference 정의를 처리한다.
4. 보기 전환은 같은 블록으로 돌아오며, 정확한 기존 locator 진입은 원문 보기에서 그대로 복원한다. 프로그램 스크롤·미리보기·형식 전환은 실제 읽기 행동으로 저장하지 않는다.
5. mapper가 실패하면 추정 위치를 저장하지 않고 이전 읽기 위치를 보존한다. 원문 보기에서 이어 읽을 수 있게 한다. 렌더링 자체의 실패·중첩/자원 한도 초과도 원문 읽기로 복구한다.

이 adapter의 최소 실험은 반복 문장·강조/링크·escape/entity·코드·표·중첩 목록·빈 줄·reference 정의·BOM/CRLF·한글/이모지의 읽기↔원문↔검색 왕복이다. 이 검증 전 renderer만 연결해 완료 처리하지 않는다.

## 렌더러 선택과 안전한 표시

2026-10-22 KST 공식 안정 릴리스·고정 package/license·공개 advisory를 대조했다. [오픈소스 선택 기록](../life-tools-design/open-source-review.md)의 이번 절을 함께 따른다.

| 선택지 | 채택 판단 |
| --- | --- |
| **markdown-it 15.0.3 + DOMPurify 3.4.17** | 채택·공식 배포물 동봉 완료. block token의 공식 `map=[line_begin,line_end]`가 이어 읽기 계약에 맞는다. 공식 로컬 UMD를 고정 동봉하고 기본 parser와 제한된 표시 adapter를 사용한다. |
| Marked 18.1.1 + DOMPurify | 정적 UMD와 직접 runtime 의존성0은 장점이다. 그러나 고정 Lexer는 reference 정의를 소비하면서 raw token을 생략할 수 있어 `token.raw` 단순 누적으로 원문 map을 보장할 수 없다. 이 이유로 우선순위를 내린다. |
| mdast-util-from-markdown 2.1.0 | UTF-16 AST 위치는 있으나 ESM/micromark 의존성과 별도 표시 adapter 비용이 있다. 서식 DOM에서 직접 정밀 발췌가 실제 요구가 될 때 재검토한다. |
| 자체 정규식 Markdown parser | 중첩/escape/표/코드·안전성 유지 비용 때문에 채택하지 않는다. 직접 유지하는 범위는 표시 정책·원문 위치 adapter·기존 저장 연결이다. |

markdown-it은 `html:false`, `linkify:false`, `typographer:false`, 외부 플러그인0을 기본으로 검증한다. renderer 출력은 허용 태그/속성만 DOMPurify로 정제한 뒤 한 번 설치하며 재해석하지 않는다. 임의 HTML·script·iframe·SVG/MathML·style·event handler·DOM id/name을 허용하지 않는다. 링크는 허용한 http/https와 검증한 문서 내부 anchor만 처리하고 안전한 rel을 붙인다.

**정제만으로 외부 이미지 요청이 막히지는 않는다.** Markdown image token과 img/media를 별도로 비요청 텍스트로 대체한다. 상대 파일·Obsidian 첨부·외부 이미지/임베드/미리보기를 자동 조회하지 않는다. 기존 원본 파일/사진의 명시 표시 경로는 유지한다. 체크 목록은 서버/자료 상태를 바꾸지 않는 읽기 전용 표현이다.

parser는 기존 1MiB 입력 한도를 넘겨 읽지 않으며, 중첩/토큰 수·렌더 작업의 제한은 익명 병적 입력 실험으로 정한다. 전체 라이브러리 LICENSE·고정 파일 digest를 보존하고 CDN 런타임 로딩·프레임워크·빌드 시스템을 사용자 앱에 추가하지 않는다. markdown-it package의 runtime 의존성6개는 실제 동봉 시 고정 배포물의 전이 라이선스·권고까지 확인한다. 현재 정확 버전 advisory0은 전체 보안성 보장이 아니다.

## 수정과 새 버전 저장

- 가져온 자료에는 엄격한 `source-edit` 로컬 stage를 둔다. `stageId/workspaceId/baseSourceId/baseSourceRevision/baseSourceVersionId/baseHash/lifecycleRevision`과 raw 입력을 보관한다. 기존 Writing stage 판정을 느슨하게 하지 않고 동일 stage ID의 kind 변경을 막는다.
- 일반 수정은 최신 판에서 시작한다. 이전 판은 읽기로 유지하며 명시 **이 버전으로 복원**하면 그 내용을 새 최신 판으로 저장한다. 지정한 판을 현재 최신 값으로 몰래 바꾸지 않는다.
- `prepareImport(...,{forceNewVersion:true})`와 기존 `commitLocal`의 stage/bundle CAS·영속 operation receipt·정확한 appliedResult를 재사용한다. 과거 본문과 같아도 옛 판을 재사용해 최신 head가 그대로 남는 문제를 막는다. 변경이 전혀 없으면 불필요한 새 판을 만들지 않는다.
- 제목은 기존 모델의 자료 공통 제목이다. 버전별 제목 이력을 약속하지 않는다. 작성자·작성일·형식·확보 범위는 판별로 보존하며 원천 종류·원형 URL·기존 파일 경로를 같은 자료에서 변경하지 않는다. 다른 정체성은 별개 자료로 보관한다.
- 타인/미확인 자료의 관계를 `self`로 자동 바꾸지 않는다. 내 편집으로 외부 원문 전체를 확보했다고 표시하지 않는다. 원문 보완(새 취득)과 내 사본 편집을 구분하고, 수정 판은 기계적으로 **해도에서 수정한 사본**임을 식별한다.
- 원문 파일·기존 사진 sidecar/Blob은 수정하지 않는다. 새 판에 사진을 자동 재결속하거나 기존 파일이 새 텍스트와 같은 원본이라고 표시하지 않는다.
- IME 조합·미확정 입력·저장 실패·두 탭·계정/공간 전환·ACK 유실은 입력/커서/초안을 보존한다. prepare와 실제 transaction 모두 자료의 현재 head·휴지통 상태·revision을 재확인하고, 저장 성공 뒤에만 같은 자료의 새 판을 연다.

## 휴지통 상태와 수정 사본의 영속 계약

기존 v1의 generic `links`를 재사용하는 **새 의미 계약**을 우선한다. 새 Source 필드나 schema2를 임의 추가하지 않으며 `note`에 JSON을 숨기지 않는다. Core의 예약 kind 검증·변경 방어와 공통 adapter를 함께 구현한다.

| 예약 link | 제안한 엄격한 계약 |
| --- | --- |
| `source_trash` / `source_active` | 자료당 상태 행 최대1개, entityRef는 정확한 source 1개, 필수 revision/timestamps. 행이 없으면 active. 최초 이동은 workspace CAS에서 행 부재를 확인해 생성하고, 복원은 **같은 link ID의 다음 revision**으로 kind를 바꾼다. 복원 때 행을 삭제하지 않는다. |
| `source_edited_copy` | 수정한 정확한 sourceVersion 1개만 가리키는 불변 marker. 판당1개, note/sourceRefs 없이 지정 필드만 허용한다. 버전이 남아 있는 동안 marker 제거·변조를 거절한다. |
| `source_edit_base` | 기준 판→새 판의 정확한 두 version entityRef를 가진 불변 편집 이력. 같은 source의 실제 두 판과 수정 marker를 검증한다. 전체 작업공간에 보존하되 선택 근거의 부분 전송에 자동 포함하지 않는다. |

최초 marker ID는 기존 UUID 생성과 원자 operation receipt를 사용한다. 현재 sync는 **전체 스냅샷 CAS**이며 link별 자동 merge가 아니다. 서로 다른 오프라인 상태 행을 concat하지 않고 충돌 비교·반대쪽 복구 사본을 유지한다. 자료당 상태 행/판당 수정 marker의 중복은 일반 가져오기·복원·수신에서도 거절한다. 새 작업공간 사본은 기존 ID map으로 source/version/link와 entityRefs를 함께 재매핑한다.

`source_active`는 이전 삭제를 모르는 낡은 상태가 아니라 명시 복원 기록이다. 늦은 편집·보완·수신은 transaction에서 휴지통 상태를 확인해 자동 복원하지 않는다. 실패하면 초안/수집 판을 보존하고 명시 복원 또는 별개 사본 경로로 이어간다.

원천·불변 버전·발췌·기존 메모·정확 참조는 휴지통에서도 보존한다. **자료실 휴지통은 원본 SNS/네이버 글 삭제, 계정 서버 보관함 삭제, 수집 중지, 공개 철회가 아니다.** 이번 기본 동작에 영구 삭제·자동 비우기를 섞지 않는다. 물리 삭제는 글·9칸·준비·사진·서버·외부 백업까지 참조 범위가 별도로 확정돼야 한다.

## 목록·검색·동기화·사본의 동작

부분 전송은 validator 한 군데만 고쳐 끝내지 않는다. `PreservationReferences.project/copy`, `MaterialContinuity.snapshot/remap`, `Storage.preservationSelectionPayload/materialNewWorkspace/재수신`의 **선택 marker 포함·검토 fingerprint·link ID 재매핑·원자 설치·재수신/충돌 영수증**을 함께 바꿔야 한다. 선택하지 않은 기준 판의 본문을 추가하지 않는 것이 보존과 개인정보 범위의 완료 조건이다.

수정 표식은 앱이 관리하는 수정 이력이며 원작성 기원의 암호학적 증명이 아니다. marker 불변/제거 거절은 **알려진 이전 snapshot·동일 전송 영수증·검토 fingerprint·새 projection**의 전후 대조에 적용한다. 기존 `links=[]` 파일을 계속 읽는 한, marker와 manifest까지 임의로 다시 작성한 독립 파일을 정상 legacy 자료와 구별할 수 없다. 알 수 없는 파일의 원저자/수정 여부를 확정하거나 구버전 앱이 만든 부분 전송의 누락을 검출한다고 주장하지 않는다. 새 marker를 보존하는 전송은 지원 클라이언트·서버 capability를 확인하고, 구버전 경로로 표식을 조용히 버려 재전송하지 않는다.

전체 v1 bundle sync는 현재 generic link 형태를 사용할 수 있지만, 준비 이동의 기존 SQL validator는 `links=[]`를 요구한다. **예약 수정 marker만 허용하는 클라이언트/기존 서버 validator의 additive migration과 marker 불변성 검증을 함께 출시**한다. 설계 당시에는 새 API·새 테이블·기존 RLS 완화를 전제하지 않았다. 실제 구현은 아래의 명시적 읽기 전용 capability만 추가하며, 테이블/RLS는 유지한다. migration 이름은 CLI로 생성했고 격리 SQL/구버전 파일/롤백 보존 검수를 거쳤다. 구버전 서버가 준비되지 않으면 전송 전에 멈추고 로컬 자료·초안을 보존한다.

구버전 앱은 새 휴지통 의미를 모르거나 새 선택 파일을 거절할 수 있다. 새 앱의 기존 파일 읽기와 모든 옛 앱의 새 파일 쓰기 호환은 다른 주장이다. 사용 기기의 앱 업데이트·PWA 모듈 일치·오프라인 재개를 확인하고 이를 물리 삭제/전 기기 영구 삭제 보장으로 표시하지 않는다.

## 설계 검토 당시 기록

현재 수행한 것은 기준 코드·제품 계약·공식 OSS와 독립 역할6개의 읽기 전용 검토, 관련 문서/링크·diff 점검이다. 이 설계에서 정의한 앱·라이브러리 동봉·SQL·기기 검사를 실행했다고 표시하지 않는다. Supabase 지침은 기존 owner/CAS/부분 전송의 검토에 사용했으며 실제 계정·DB는 조회/수정하지 않았다.

다음 실행은 위 **자료 읽기·수정·휴지통·인용/검색·사본/동기화·복구 전체 묶음**이다. 첫 내부 선행은 renderer block map과 예약 marker의 작은 익명 실험이며, 결과에 따라 더 단순한 대안을 선택한다. 다른 세션의 완료된 뉴스·네이버 보관 연결을 다시 구현하지 않는다. 최신 우선순위와 조건은 [로드맵](../life-tools-design/roadmap.md)을 따른다.


## 구현·설치·통합 검수 (2026-10-22 UTC)

Core의 예약 link·SourceEdit·Storage의 실제 트랜잭션 검증과 기존 작업 영수증을 연결했다. 서식/원문 전환은 같은 reader 안에서 하고, 정확 검색·발췌는 raw UTF-16 위치를 유지한다. 자료 옵션에서 수정·과거 판 복원·휴지통, 관리에서 휴지통 복원을 제공하며 기본 본문에 관리 행을 늘리지 않는다. 새 선택·검색·추천은 활성 자료만 포함하고 기존 정확 근거는 계속 읽는다. 두 탭의 휴지통/새 선택 경합도 저장 시점에 검사하며 기존 인용의 재저장은 보존한다.

설계의 ‘새 API 없이 우선 연결’ 가설은 부분 전송의 안전한 구서버 중단에 맞춰 변경했다. 기존 페이지 cursor를 지원 여부 신호로 재해석하지 않고, 인증된 읽기 전용 `life_material_capabilities()`가 상수 `{source_edited_copy:1}`만 반환한다. 지원 확인에 실패하면 수정 marker를 포함한 본문 쓰기를 보내지 않는다. 기존 marker 없는 전송은 원래 경로를 유지한다. 공개 Share-v1은 새 필드를 넣지 않고 수정판의 기존 표시 제목에 수정 사본임을 명시한다. 이미 공개한 사본은 자동 변경하지 않는다.

`20261022031304_life_material_edited_copy_markers.sql`은 기존 valid/put 함수와 hash namespace를 확장한다. 테이블·컬럼·RLS·기존 RPC signature를 바꾸지 않는다. 격리 PostgreSQL17의 합성 자료10흐름에서 기존 행/영수증·설치 반복·populated rollback/재설치와 marker 변조/소실·remove/re-add를 확인했고 별도 읽기 전용 코드 검토를 통과했다. 운영 설치 버전은 `20261022031948`이며 동일 SQL SHA256 `dee903b0c70841228077bcffa7977c76d353822920dd295e0488c40fbd5f36ac`다. 운영에서는 프로젝트·함수·권한·RLS 메타데이터만 조회했다. 개인 원문·준비·Auth 행이나 실제 자료 RPC 읽기/쓰기는 실행하지 않았다.

공식 markdown-it15.0.3/DOMPurify3.4.17 UMD 원본과 manifest·전체 LICENSE·전이6종 고지를 동봉했다. 원문 BOM/CRLF와 parser용 표시 사본을 분리하고 이미지/미디어 자동 요청을 막는다. 선택 근거/준비 이동에는 선택한 수정판 marker만 포함하며 미선택 기준판 본문과 base edge는 제외한다.

검수의 최종 수치·브라우저/시각·PWA·PR/main CI·실제 배포본 결과는 아래 출시 기록에 확정한다. 실제 Apple 기기·Google 로그인·개인 데이터·네이버 운영 수집은 합성 자동 검수와 구분한다. 휴지통은 복구 가능한 로컬 자료 상태이며 영구 삭제나 외부 글/공개 사본 철회가 아니다.
