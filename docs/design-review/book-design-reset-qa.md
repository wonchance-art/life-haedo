# 책 작업실 A/B 시안의 독립 조작 검토

2026-10-08. [독립 비교 HTML](evidence/book-design-reset/comparison.html)의 실제 브라우저 조작을 검토했다. **최종 11개 흐름이 통과**했다. 처음 발견한 입력 유실·상태 전환 오류·문단 복귀 오류는 root가 시안에서 수정했고, 관련 경로를 다시 확인했다.

[최종 실행 보고서](evidence/book-design-reset/interaction-report.json)에는 최초 실패와 후속 검사 범위, 각 사례의 마지막 실행 파일·시각, 산출물 SHA-256을 함께 기록했다. 최초 결과를 마지막 성공으로 덮어 설명하지 않는다. 원본 실행 JSON과 검사 스크립트는 `.local/book-design-reset/interaction-run-*.json`, `.local/book-design-reset/interaction.cjs`에 보존했다.

## 확인한 사용자 흐름

| 범위 | 실제 조작과 확인 |
| --- | --- |
| A/B × 1440·820·390px | 목록의 2장을 키보드로 열기 → 한글 문장 입력 → 미반영 상태의 읽기 이동 차단 → 반영 → 읽기 → 고정 헤더에서 해당 장 편집 → 같은 문단 위치로 복귀 → 예시 원고 Markdown 다운로드 |
| 입력·선택 | A/B 방향 전환과 원문 패널 열기/닫기 뒤 원고 값·문자 선택 범위 유지. 높이가 늘어나는 원고 입력창에서 내부 세로 스크롤을 만들지 않음. 새로고침하면 예시 편집이 초기화된다는 안내와 실제 동작 대조 |
| 출처·포함 범위 | 첫 장의 내 글과 정확한 이전 버전 본문, 3장의 타인 글·일부 보관·누락 표시 확인. 제외한 해석이 원고/출처 패널에 나타나지 않음. 예시 Markdown에는 수정한 장 원고가 들어가고 원문 본문·제외한 해석은 들어가지 않음 |
| 빈 목록·로딩·많은 책 | 빈 목록에서 예시 책을 실제 읽기로 열기, 불러오기 완료 체험, 가상 40권 목록, 없는 제목 검색과 검색 지우기 |
| 저장 오류·회복 | 직접 입력한 글을 유지한 채 저장 실패 상태로 바꾸기 → 실패 → 다시 시도. 미반영 상태에서 많은 책 화면으로 빠져나가지 않도록 차단하고 반영 버튼으로 초점 이동 |
| B 모바일 장 선택 | 미반영 글이 있을 때 다른 장 선택 차단·현재 선택값 유지. 반영 후 다른 장을 고르면 그 장 제목과 원고 표시 |
| 문단 추가 후 복귀 | 읽던 문단 앞에 새 문단을 삽입해도 원래 문장의 본문으로 돌아옴. 단순한 문단 번호 일치로 검사를 대신하지 않음 |
| 최종 A 원문 패널 위치 | 원문을 열면 패널 시작이 viewport 안에 나타나고, 원고 값·문자 선택·토글 초점을 보존. 마지막 위치 수정 뒤 이 경로만 집중 재검증 |

첫 문단 일부가 화면에 걸쳐 있으면 그 문단이 복귀 초점을 가질 수 있다. 검사는 임의의 문단 번호 하나를 강제하지 않고 **같은 장의 본문 초점과 실제로 관찰하던 문단의 y 위치**가 유지되는지를 확인했다. 앞에 문단을 새로 넣은 경우에는 초점의 문자열도 원래 문장과 대조했다.

## 처음 발견한 문제와 수정 확인

1. **저장 실패 상태 선택이 입력을 지움.** 기존 상태 선택기가 2장으로 이동하며 임시 초안을 비웠다. 현재 편집 중인 장과 초안을 유지하도록 바뀌었고, 실패·재시도 후 문장 보존을 확인했다.
2. **미반영 상태에서 많은 책 화면으로 이동하면 편집 복구가 막힘.** 목록에는 `.status`가 없는데 이동 가드가 이를 갱신해 TypeError가 발생했다. 미반영 초안이 있으면 해당 상태 전환을 막고 반영 조작으로 안내한다. 수정 뒤 페이지 오류는 없었다.
3. **앞에 문단을 추가하면 다른 문단으로 복귀.** 번호 ID만 복원 기준으로 사용했다. 이제 저장한 문단 문자열을 먼저 찾으며, 그대로 남아 있는 문장 앞에 새 문단을 넣어도 올바르게 돌아왔다.
4. **편집 버튼까지 이동하는 과정에서 읽던 위치가 바뀜.** 초기 버튼은 원고 위에 있어 중간 문단에서 버튼에 도달하면 페이지가 먼저 올라갔다. 고정 헤더에서 집필을 누를 수 있게 바뀐 뒤 같은 viewport 위치 복귀를 확인했다.
5. **빈 상태 문구·터치 크기 불일치.** `예시 책 열기`가 목록만 채우던 동작은 실제 읽기 진입으로 수정됐다. 집필/읽기 버튼의 38px 높이도 44px 이상으로 조정됐다.

초기 기본 흐름 여섯 개의 실패에는 “버튼을 누르러 스크롤하기 전의 문단”을 그대로 기대한 검사 조건도 포함돼 있었다. 이를 데이터 손실로 분류하지 않았다. 수정본 후속 네 사례의 특정 문단 번호 기대 역시 관찰 위치·본문 초점 기준으로 고쳤다. 보고서에서 앱/시안 문제와 검사 조건 보정을 구분했다.

## 격리와 측정

Chromium 151.0.7922.173에서 1440×1000, 820×1000, 390×844px를 사용했다. 좁은 두 폭은 터치, 모두 reduced-motion 설정이다. 최초 로컬 HTML 문서를 받은 뒤 브라우저 context를 offline으로 전환해 조작했다. 새로고침 초기화 검사를 위한 문서 요청 한 번을 제외하면 외부 자원을 읽지 않았다.

- IndexedDB·localStorage·sessionStorage 접근, fetch/XHR 호출, 허용하지 않은 요청 모두 **0**. CSP 위반도 없었다. 실제 앱 Auth/저장소를 초기화하지 않았다.
- 최종 실행의 console/pageerror는 **0**. 최초 상태 전환 문제에서 발생한 페이지 오류 1건은 이력에 남겼다.
- 최종 기본 A/B 세 폭에서 가로 넘침이 없었고 가시 조작은 44px 이상이었다. 정상 한글 입력과 키보드 Enter·초점 복귀를 확인했다.
- 화면 캡처·상태 24조합의 별도 검사는 디자인 책임자가 기록한 [after 상태 보고서](evidence/book-design-reset/after/states-report.json)와 구분한다. 해당 검사 전체를 이 독립 기능 검사에서 반복했다고 보고하지 않는다.

## 시각적 판단과 남은 범위

원고가 입력 폼 안에 갇히지 않고 문서 길이에 맞춰 늘어나며, 읽는 중에 헤더에서 편집으로 돌아갈 수 있어 기존 감사에서 발견한 긴 상단 관리 행과 이중 스크롤 부담을 줄였다. A는 원고에 집중하기 쉽고, B는 넓은 화면에서 목차 이동과 근거 대조를 유지하기 쉽다. B의 모바일 장 선택은 별도 선택기로 제공하므로 두 방향의 차이를 데스크톱 사진만으로 판단하면 안 된다.

원문 패널과 선택 범위 보존은 확인했지만, 장·문단을 대폭 삭제하거나 다시 쓴 경우의 독서 위치 의미는 아직 단순하다. 문장 일치가 사라지면 번호로 복귀한다. 읽기 중 스크롤만으로 ‘현재 장’이 자동 추적된다고 검증하지 않았으며, 상단 집필은 선택한 장을 기준으로 한다. 가상 40권은 같은 예시 내용을 반복하므로 실제 서재 검색·분류·대용량 성능을 입증하지 않는다.

이 HTML은 **디자인 시안**이다. 편집은 메모리에만 있고 예시 다운로드는 장 원고 Markdown이다. 실제 앱의 로그인·저장 실패·CAS·동기화·백업 복원·출처 부록·PDF·공개 게시를 대체하거나 검증한 결과가 아니다. 파일에는 제외 상태를 포함한 전체 익명 샘플이 내장되어 있으므로 접힘/제외 표시를 비밀 자료 제거 방식으로 사용해서는 안 된다.

실제 Apple 기기의 한글 조합·가상 키보드·Files·OS 인쇄, 실제 사용자 선호와 장기 집필은 미검증이다. 정상 한글 문자열 입력을 IME 실기 검증으로 보고하지 않는다. 기능 통과만으로 A/B의 디자인 선택을 확정하지 않는다.
