# 홈에서 서버 글을 찾아 같은 글 이어쓰기

2026-10-21 · 구현 계약. 코드·통합 검수·최종 배포는 진행 중이며 실제 사용자 기기 확인은 미완료다. 최종 SHA·캐시 버전은 릴리스 증거로 확정한다.

## 목표와 기존 기능의 재사용

한 기기에서 명시 저장한 여행 글을 다른 기기의 홈에서 찾아 받아 쓰고, 수정·재보관한 뒤 선택 공개와 방문자 읽기까지 이어간다. 이미 있는 서버 목록·새 사본 받기·원본 검증·수정·충돌 복구·공개를 새로 만들지 않는다.

현재 홈은 로컬 글·초안·보관함을 읽고 서버 글은 글 관리에서 별도로 찾는다. 기존 수신은 명시할 때마다 새 사본을 만드는 계약이다. 이번에는 홈의 발견 동선과 같은 서버 글의 현재 로컬 사본으로 재개하는 경로를 연결한다.

## 사용 흐름

1. 홈의 **서버에 보관한 글**에서 본문 중심 계정 목록(`account-blog`)을 연다. 현재 작업공간과 로컬 초안은 유지한다.
2. 계정 서버의 글 메타데이터를 현재 작업공간의 연결 정보와 대조한다. 목록 조회만으로 글 본문·사진을 다운로드하거나 로컬 자료를 업로드하지 않는다.
3. 유효한 연결이 있으면 같은 로컬 글을 다시 연다. 연결된 로컬 글이 서버 최신판과 같다고 추정하지 않고, 서버 새 판·로컬 변경·보관 중지·충돌을 구분한다.
4. 연결이 없으면 사용자가 고른 서버 revision을 확인하고 원본을 받아 현재 공간에 새 로컬 사본을 설치한다. 다른 작업공간으로 강제 이동하거나 새 공간을 만들지 않는다.
5. 서버 새 판이나 충돌은 기존의 해당 글 관리 화면에서 비교한 뒤 명시 선택한다. 선택하지 않은 쪽의 복구 사본과 기존 초안을 보존한다.
6. 작성기의 명시 저장은 기존 비공개 서버 보관을 사용한다. 공개할 내용·사진 선택과 게시·갱신·철회는 기존 별도 흐름을 따른다.

## 정확 재개와 원자 설치 계약

- `openRemote(workspaceId, remoteId, { expectedRemoteRevision, localPostId? })`는 현재 계정·공간과 선택한 글을 검증한다. 기존 유효 연결은 같은 ID로 재개하며 열기 자체가 새 사본을 만들지 않는다.
- 새 수신은 선택 row의 정확 revision과 실제 서버 문서를 대조한다. 조회 사이 서버 판이 달라지면 재확인하며 다른 판을 조용히 대신 설치하지 않는다.
- 새 로컬 글·사진 ID를 발급하고 문서·목록 요약·서버 연결·수신 영수증을 한 트랜잭션에 설치한다. 다운로드·검증 실패나 트랜잭션 abort는 부분 문서·연결만 남기지 않는다.
- 같은 공간의 동시 탭·중복 클릭·재진입에서는 영수증과 현재 연결을 다시 확인해 설치를 한 번으로 제한한다. 새 operation만으로 같은 글을 또 만들지 않는다.
- 서버 `remoteId`는 기기 간 같은 글의 논리적 기준이고 로컬 ID는 기기별 사본이다. 수정 저장의 `replaces`로 로컬 ID가 교체되면 연결·영수증도 원자적으로 현재 글을 가리킨다.
- 초안·보관함·명시한 서버 보관 중지 상태를 재개 편의를 위해 자동 변경하지 않는다. 이전 사본·다른 글·개인 메모를 덮어쓰지 않는다.
- 기존 `receive`의 **명시 새 사본 받기**는 유지한다. 이 별도 동작과 같은 글 재개를 동일한 의미로 바꾸지 않는다.

## 보존·권한·실패 경계

- 기존 `Blog.hydrate`와 PhotoPost 검증으로 정확 본문·사진 선언·형식·크기·해시·원본 바이트를 확인한다. 사진을 재압축하거나 새 형식으로 변환하지 않는다.
- 서버 글에 있는 인용 문자열·출처 URL과 별도 구조화 근거를 구분한다. 원문 자료·근거 sidecar·개인 메모·작성 준비가 자동 수신됐다고 표시하지 않는다.
- 읽기·서버 목록·새 사본 설치가 서버 업로드·공개를 새로 시작하지 않는다. 공개 사진은 기본 미선택이며 공개본 갱신·철회는 별도 명시 동작이다.
- 목록·본문·사진·저장 중 계정이나 작업공간이 바뀌면 이전 결과를 차단한다. 타 계정 연결이나 제목 일치로 같은 글을 추정하지 않는다.
- 서버 오류·자료 없음·로컬 연결 손상·판 변경·충돌을 구분한다. 실패를 빈 목록이나 성공으로 표시하지 않고 기존 로컬 글과 재시도 경로를 유지한다.
- 초안 자동 저장의 300ms/2000ms 기준과 hidden/pagehide의 최선의 노력 보관은 유지한다. 기기 간 초안 자동 이동·실시간 공동 편집·강제 종료 시 마지막 입력 보장을 추가하지 않는다.

## 구현 선택과 오픈소스 재사용

기존 `blog-remote`/`blog-sync`의 계정 확인·CAS·영속 작업 영수증, PhotoPost/Blog 모델, 작성기·글 관리·공개 렌더러를 재사용한다. 새로 필요한 것은 현재 공간의 연결 투영과 원자 수신·재개 어댑터다. 별도 동기화 엔진은 같은 문서·사진 검증과 충돌 정책을 중복하고 기존 영수증과 다른 성공 기준을 만들므로 도입하지 않는다.

동봉 Quill·idb·Supabase SDK와 native DOM을 유지한다. [기존 오픈소스 선정·라이선스 검토](../life-tools-design/open-source-review.md)와 [글 원본·보관 계약](../life-tools-design/blog-completion.md), [앞선 기기 왕복·복구 검수](blog-continuity-usability.md)를 재사용한다. 새 라이브러리·vendor 버전 변경·새 글 형식은 없다. 앞선 검수 수치를 이번 연결 기능의 완료 증거로 재사용하지 않는다.

## 완료 기준과 현재 상태

- 합성 계정 A의 두 브라우저에서 저장→홈 서버 글 발견→선택 수신→같은 ID 재개→수정·재보관→원래 기기의 새 판 비교·복귀를 확인한다.
- 중복 클릭·동시 탭·재부팅·수정 ID 교체, revision 변경·사진 검증 실패·실제 IndexedDB abort·재시도에서 중복·부분 설치와 기존 자료 변경이 없는지 확인한다.
- 로컬 초안·보관함·서버 중지·양쪽 복구 사본을 보존하고 타 계정·늦은 결과를 차단한다. 목록 요청의 본문/사진 다운로드·업로드 0을 별도로 확인한다.
- 선택 공개·갱신·철회와 익명 방문자 읽기, 원본 사진 바이트·계정 경계·기존 PWA 업데이트 보존을 끝까지 검수한다. 화면 폭 검토와 실제 Apple 체험은 구분한다.
- 현재는 검수 계획이며 통과 수치·최종 SHA/SW·배포 완료를 선취하지 않는다. 실제 사용자 데이터 전송이나 개인 기기 조작은 합성 검수 범위가 아니다.

SQL 연계 브라우저 검수에서 목록 복귀의 초점 대기 실패를 재현해 서버 목록의 렌더 완료와 복귀 순서를 보완 중이다. 원래 단언·제한 시간을 유지해 재검수하며 최종 통과 여부는 아직 미확정이다.

## 다음 큰 사용자 목표

**Mac·iPad에서 여행 글 한 편을 실제로 완주하기.** 자동 검수와 별개로 Apple 한글 입력·Photos/Files 전달·앱 전환·기기 이동의 확인이 남아 있기 때문이다. 선행은 이번 릴리스 확인과 소유자의 실제 기기·로그인·직접 고른 사진이다. 기존 자동 초안·원본 서버 보관·홈 재개·파일·선택 공개를 재사용하며, 같은 글과 전달된 JPEG/PNG/WebP 원본을 두 기기에서 대조하고 실패 재시도·공개 선택을 확인하면 완료다. HEIC 등 새 지원을 자동 요구로 늘리지 않는다.
