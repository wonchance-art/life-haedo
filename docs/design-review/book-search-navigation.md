# 책 검색 결과와 한국어판 확인

2026-10-14 KST. `codex/book-search-navigation`, #78 후속. 디자인·통합 책임자는 Codex 한 명이며 기존 A 화면과 CollectionPicker를 재사용했다. 병합·배포·운영 SQL은 Local 담당이다.

## 재현한 문제와 결정

기존 외부 책 검색은 첫 6개 후보만 표시해 다른 후보로 이동할 수 없었다. 작품별 판본은 6개씩 넘길 수 있지만 한국어판을 찾으려면 다른 언어 판본을 먼저 훑어야 했다. 검색 다음 페이지와 작품별 `한국어판 찾기`를 연결했다. 기존 `판본 찾기`는 모든 언어의 판본 탐색으로 유지한다.

[Open Library 공식 Search API](https://openlibrary.org/dev/docs/api/search)를 직접 읽었다. `lang`은 순위를 바꿀 뿐 필터가 아니며 `language:kor`가 언어 조건이다. `editions` 하위 응답은 조건에 맞는 대표 판본 **한 개**를 제공하며 전체 판본 목록이 아니다. `key:/works/… language:kor`로 작품을 고정하고, 응답 작품 ID·판본 ID·`language`에 `kor`가 있는지 대조한다. 저자·번역자를 추정하거나 작품 저자를 판본 저자로 복사하지 않는다.

기존 제한 JSON 어댑터와 선택창만 확장했다. 새 SDK·검색 서버·번역기·저장 스키마·SQL을 도입하지 않았다. [기존 공식 배포·라이선스 검토](../life-tools-design/open-source-review.md#이름으로-책프로젝트-찾기--2026-10-13)를 재사용한다. 별도 검색 프레임워크는 제공자 데이터 누락을 해결하지 못하며 유지 비용만 늘리므로 추가하지 않았다.

## 사용 흐름과 보존

내 페이지 → 글쓰기 → 음악·책·대상 붙이기 → 이름 입력 → 책 찾기 → 다음/이전 검색 결과 → 한국어판 찾기 → 판본 출처·창작자 확인 → 첨부 → 비공개 저장 → 새로고침 후 재확인.

- 검색은 6개씩 명시 이동하며 최대 100쪽이다. 전체 검색 결과를 확보했다는 뜻이 아니다. 현재 검색어를 그대로 보내며 임의 번역·자동 추가 검색이 없다.
- 한국어판 버튼을 눌렀을 때만 고정 API에 작품 식별자와 언어 조건을 요청한다. 입력 중 외부 요청, 이미지 요청, 외부 AI 전송은 없다.
- 64KiB/10초/자격 증명·referrer 제외/redirect 거부, 취소와 제공자 간격을 재사용한다. 후속 조회는 1.1초 중 남은 간격만 기다리고 실패 응답을 자동 재시도하지 않는다.
- 응답 캐시는 선택창 안에서 최대 12개이며 계정/작업공간의 영속 자료에 섞지 않는다. 페이지 번호와 한국어판 조회 종류를 구분한다.
- 다음 페이지 실패 시 기존 후보와 이동 조작을 보존한다. 조회 중 기존 후보를 inert로 두고 완료/실패 때 복원한다. 키보드 초점은 성공 시 결과, 실패 시 눌렀던 이동 버튼으로 돌아온다. 입력 변경·닫기 뒤 늦은 응답은 버린다.
- 한국어판 미확인은 제공자 검색 결과에 한정해 표시한다. 대표 한 개와 전체 판본 목록을 구분하며 전체 탐색·직접 입력을 계속 사용할 수 있다.
- 선택한 정확한 판본 URL을 기존 첨부 폼과 비공개 저장으로 전달한다. 본문·원문·발췌·개인 메모·컬렉션·공개 범위를 바꾸지 않는다. 컬렉션 보관은 #78의 별도 명시 조작이다.

## 검증

- Node **450/450**, 정적 **HTML 18/JS 72/참조 320/PWA** 통과.
- 새 브라우저 **3흐름**: 6개 이후 후보/실패/이전 결과/키보드 복구, 한국어판 정확 출처 검토·첨부·비공개 저장·새로고침, 빈/오류/재시도/대기·검색어 변경/늦은 응답과 본문 보존.
- 검색 결과와 한국어판 각각 **1440·820·390px**, 좁은 페이지 실패·판본 빈/오류/로딩을 합쳐 **10상태**. 가로 넘침·작은 조작·입력 글자·접근 이름·대비 검사 통과. 가로 스크롤 종류 칩의 화면 밖 항목은 문서 가로 넘침과 구분한다.
- 기능 검사와 별도로 넓은 결과/좁은 판본 스크린샷을 읽었다. 긴 한글 제목은 카드 안에 줄바꿈되고 한국어판/전체 판본 버튼을 좁은 폭에서도 나란히 배치했다. 첫 검토에서 발견한 버튼 세로 밀림과 페이지 복귀 초점을 한 번에 수정 후 확인했다.
- 기존 판본·명시 보관 **4흐름**, 취향 작성 **4흐름** 통과. 원문·개인 메모·정확 판본·CAS 충돌·백업·공개 렌더러 경계를 회귀 확인했다.
- PWA/공용 인증 경계 **9개**, 보존된 **v102 → v103** 갱신에서 기존 자료 유지. 모의 인증/전송이며 실제 Google 로그인·운영 RLS를 검증한 것이 아니다.
- 새 브라우저 pageerror 0; 의도한 429 응답 console 오류 2. PWA의 의도한 전송/콜백 오류 3은 별도다.

## 실제 제공자 결과와 한계

실제 Linux Chromium 앱 어댑터에서 공개 검색 6개를 확인했다. `채식주의자`/`The Vegetarian`, `소년이 온다`/`Human Acts`는 각각 같은 작품을 첫 후보로 반환했다. `데미안`은 `데미안 ; 향수` 합본 한 개, `Demian`은 다른 작품 후보를 반환했다. 이는 제공자 색인의 차이를 보여주며 한국어 전체 검색 품질을 보증하지 않는다. `채식주의자`의 한국어판은 `/books/OL23965279M`, 한국어·출판사·2007과 빈 저자 값으로 확인했다. 정확 판본 출처와 사용자의 확인을 유지한다. [공개 API 증거](evidence/book-search-navigation/live-provider.json).

예술 작품·인물·영화는 [제공자 비교](taste-provider-expansion.md) 상태를 유지한다. 이전 확인에서 차단된 `api.artic.edu`, `metmuseum.github.io`, `developer.themoviedb.org`, `www.wikidata.org`의 정책 변경 근거가 없어 같은 요청을 반복하거나 우회하지 않았다. API/약관·한국어 검색 검증과 실제 연결 완료로 보고하지 않는다. 예술 작품 실험에는 공식 API/약관에 접근 가능한 환경이 필요하다.

## Local 인계와 다음 우선순위

실제 통합 순서는 #74 → #75 → #76 → #77 → #78 → 이 후속이다. 선행 squash 후에는 main/base/잔여 diff를 먼저 대조한다. #74에 포함된 P0를 다시 만들거나 선행 PR을 개별 중복 병합하지 않는다. #71 운영 SQL 설치 여부와 읽기 전용 8조건을 확인하되 이미 설치된 SQL은 재설치하지 않는다. 이번 변경에 필요한 신규 SQL은 없다.

최종 HEAD의 CI는 해당 초안 PR에 기록한다. build/deploy SKIPPED를 배포 완료로 해석하지 않는다. Local이 병합·배포 후 실제 iPad/iPhone/Mac의 IME·터치·키보드·라이브 로그인과 위 흐름을 확인한다. 이번 검사는 익명 자료·모의 인증·브라우저 크기 검증이며 실제 개인 자료/Apple 기기는 미검증이다.

다음은 (1) 실제 자주 찾는 책 표본으로 검색 누락과 정확 판본 확인, (2) 허용된 환경에서 예술 작품 API·현재 약관·한국어 후보 실험, (3) 인물 동명이인과 영화 제공자 인증/표시 조건 확인이다. 제공자 확대보다 출처를 확인하고 기존 글로 돌아오는 흐름을 우선한다.
