# 소수 글 비교와 릴리스 준비 상태

2026-10-19 UTC. [공급 보완·전체 비교](discovery-expansion.md) 다음은 실제 사용자 유용성 평가다. 이번 확인은 기존 결과를 한 관심·목록별 2개·중복 제외 최대 4개로 줄이고, 응답을 받을 수 있는 상태와 구현 후보의 전체 CI를 확인한 범위다. 사용자 관심 선택·판정·원문 읽음·유용성은 미평가다. 앱 기능·모델·공급·저장 형식은 변경하지 않았다.

## 확인한 상태

구현 HEAD `7a1c4e417c1aba6d3c40e8f9002f3de24c4e8ae3`의 [전체 CI](https://github.com/wonchance-art/life-haedo/actions/runs/39156048408)가 최종 성공했다. 성공 8개·실패 0개, PR 조건으로 build/deploy 2개는 건너뛰었다. PR #103은 draft/open·병합 가능이며 원격 main은 `88ccfe5e381a37818a46e7abdaabfc48cff58c56`이다. 운영 사이트가 이 후보로 배포됐다는 뜻은 아니다. [기계 판독 확인](evidence/discovery-pilot/readiness.json).

기존 동결 카탈로그 50개와 core SHA를 대조했다. 9개 표본에서 최신순이 같고, 축소한 AI·신간·전시의 기존 두 순서 상위 2개·원문 URL·날짜·정확 UTF-16 근거를 유지했다. 전체 참조 12개를 canonical URL로 묶으면 공개 글 8개다. AI의 실제 상위 2개는 출판 관련 글이며 기술 분야 글로 교체하지 않았다. 출처명이나 사용자 선택용 범주를 새 관심 태그로 바꾸지 않는다. 원문 링크를 자동으로 열거나 본문을 수집하지 않았다.

## 실제 평가 방법과 완료 기준

1. 사용자가 먼저 관심 하나를 고른다. 답이 없으면 선택을 추정하지 않는다. 공개 예시 화면을 준비해도 사용자 관심으로 저장하지 않는다.
2. 같은 수집 목록의 두 방식에서 상위 2개씩 보여준다. 중복 글은 같은 번호로 한 번만 평가한다. 처음에는 중립적인 목록 A/B, 제목 링크·출처·발행일·본문 미확보만 간단히 보여준다.
3. 제목을 보고 지금 읽어보고 싶은 글을 고른다. 이 답은 읽기 의향이며 원문을 읽었거나 도움이 됐다는 증거가 아니다. 없음·이미 앎도 그대로 기록한다.
4. 사용자가 실제로 읽은 글만 도움 여부와 이유를 기록한다. 아직 안 읽음·접근 실패는 미평가로 남기며 무관함으로 바꾸지 않는다. 읽을 만함·이미 앎·무관함과 순서 선호도 같은 값으로 합치지 않는다.
5. 결과는 이 소수 표본의 탐색·목록 선호로 한정한다. 서로 다른 글의 구성과 순서가 함께 바뀌므로 순서만의 인과 효과·전체 추천 성능·모든 관심의 유용성으로 일반화하지 않는다.

완료 기준은 선택한 관심, 읽기 전 의향, 실제 읽은 범위와 도움/이유, 두 목록의 선호·조작 부담이 명시적으로 확인되는 것이다. 일부만 답하면 그 단계까지만 완료다. 현재 선택과 모든 판단은 null이다. [기존 전체 비교표](evidence/discovery-expansion/comparison.md)의 미평가 상태도 유지한다.

## 응답 보존

실제 응답·관심·선호는 이 채팅과 git에서 제외된 `.local/discovery-pilot/`의 새 영수증에만 보관한다. 공개 PR·문서·증거에 사용자 판단을 복사하지 않는다. 명시 답과 자동 관측·해석을 나누고 답이 없는 값을 채우지 않는다. 정정은 새 영수증으로 남기며 기존 답을 덮어쓰지 않는다. 이 로컬 기록의 삭제와 채팅 기록 삭제는 별개다. 원문·앱 관심/피드백·서버/공개 사본에 자동 반영하지 않는다. 개인 bundle·Storage·Auth·브라우저 프로필에 접근하지 않았다.

## 독립 검수와 남은 실행 조건

평가 방법·사용 부담·자료/응답 보존·기존 순위/근거·전체 CI·릴리스 경계를 독립 대조했다. 기존에 통과한 단위·브라우저 검사를 반복하지 않았고 문서/공개 표본의 링크·SHA·null 상태만 확인했다.

사용자 평가와 실제 Google·Mac/iPad/iPhone·라이브 버전 검증은 미완료다. 릴리스 실행 전 실제 직전 배포 SHA·캐시·origin과 현재 메타데이터를 보존하는 호환 복구 후보를 고정해야 한다. 과거 v90 배포 기록을 현재 상태로 재사용하지 않는다. `workflow_dispatch`도 build→deploy로 이어지므로 읽기 전용 CI처럼 실행하지 않는다. main 병합·배포·운영 데이터 변경은 수행하지 않았다. [현재 로드맵](../life-tools-design/roadmap.md).
