# 글과 취향을 함께 저장하기

2026-11-02 소유자 요청: "글 쓸 때 취향과 엮어서 함께 저장. 예: 인용한 인물·작품·장소". 기준 main `c108dbb`.

## 목표와 범위

- **목표:** 블로그 글을 쓰며 인용한 인물·작품·장소를 컬렉션에도 남긴다. 컬렉션 항목에서 그 항목을 붙인 글로 다시 간다.
- **이번 범위**
  - 블로그 편집기의 `음악·책·대상 붙이기` 확인 폼에 `컬렉션에도 저장` 선택을 둔다.
    - 새 첨부는 켜진 상태로 시작한다.
    - 이미 붙인 첨부를 수정할 때는 기본 끔이다. 컬렉션에 이미 있으면 선택 대신 `컬렉션에 있음`만 보인다. 오탈자만 고쳤는데 뜻밖에 저장되는 일을 막는다(검수 m3).
  - 저장 결과는 글 상태줄이 아니라 그 첨부 카드 안의 한 줄(`role=status`)에 표시한다(검수 M1).
    - `컬렉션에 저장하는 중…` → `컬렉션에 있음`(보관한 항목이면 `· 보관한 항목`)
    - 실패하면 `컬렉션에 저장하지 못함 · <이유>`와 `다시 시도` 버튼이 카드에 계속 남는다. 다시 시도해도 계속 실패하는 이유를 알 수 있게 이유를 짧게 구분한다(후속 검수 m-b).
      - `컬렉션을 읽지 못함`
      - `컬렉션 한도(1,000개·2 MiB)를 넘음`
      - `항목 정보가 컬렉션 형식에 맞지 않음`
      - `다른 탭에서 컬렉션이 계속 바뀜`
      - `저장 중 오류`
    - 첨부를 빼거나 다른 대상으로 고치면 그 대상의 저장 상태도 지운다. 그래서 같은 대상을 다시 붙인 새 카드에 이전 실패가 남지 않는다(m-a).
    - 같은 대상의 저장이 겹치면 가장 나중에 시작한 저장의 결과만 카드에 반영한다(m-c, 대상별 순번).
    - 글 상태줄과 복구 버튼 묶음(`다시 보관`·`현재 입력 백업`·`새 초안으로 보관`)은 컬렉션 결과로 바뀌지 않는다. 이전 구현은 상태줄에 썼다가 300ms 뒤 자동 저장 표시가 덮었고, 안내 중에 복구 버튼이 잠깐 열렸다.
  - 컬렉션 항목 상세에 `이 항목을 붙인 글` 목록을 둔다. 초안이면 `초안 ·`, 그 뒤에 수정 날짜를 붙인다. 누르면 그 글을 연다.
- **기존 구현 재사용**
  - `Collection.fromAttachment`·`attachmentMatch`: 내 페이지 작성기의 `컬렉션에 보관`과 같은 중복 판정
  - `storage.saveCollection`의 revision CAS
  - 블로그 관리자와 같은 글 열기 경로(`navigate('page', { searchTarget: { photoPostId } })`)

## 지킨 것

- **글 첨부 형식은 그대로다.** `{type, title, creator, url}`이며, 서버 검증(`20261101091500_life_blog_account_sync.sql`)이 이 키를 고정한다.
  - 항목 ID 참조를 넣지 않았다. 그래서 글과 항목의 연결은 같은 판정 규칙(종류 + 출처 주소, 주소가 없으면 제목·만든 사람)으로 계산한다.
  - 컬렉션 항목의 제목이나 주소를 나중에 고치면 연결 목록에서 빠질 수 있다.
- **컬렉션 저장은 글 저장과 별개다.** 첨부를 반영한 뒤에 따로 저장한다. 실패해도 첨부는 글에 남고, 카드의 `다시 시도`로 다시 저장할 수 있다.
- **중복 저장 금지.** 같은 대상이 이미 있으면 저장하지 않는다. 보관한 항목도 그대로 둔다.
- **다른 탭 변경 보존.** 다른 탭이 컬렉션을 먼저 저장했으면 최신 내용을 다시 읽어 덧붙인다(최대 3회). 다른 탭의 변경은 그대로 남는다.
- **복사하지 않는 것.** 개인 메모·태그는 어느 쪽으로도 복사하지 않는다. 새 컬렉션 항목은 빈 메모·빈 주제로 만든다.
- **문구.** 저장한 남의 글·작품은 사용자의 신념이 아니므로 화면 문구는 `취향`이라고 단정하지 않고 `컬렉션`이라고 쓴다.
- **편집·해제는 컬렉션을 건드리지 않는다.** 글의 첨부를 고치거나 빼도 컬렉션 항목은 지우거나 바꾸지 않는다. 해제할 수 있는 연결이며 원본을 합치지 않는다.
- **열린 입력 보존.** 저장이 끝나면 카드 표시만 덧붙인다. 그사이 연 첨부 폼과 한글 조합 중 입력은 다시 그리지 않는다.
- **읽기 전용.** `이 항목을 붙인 글`은 같은 계정·같은 자료공간의 사진 글만 읽는다(다른 자료공간 글은 섞이지 않음). 비공개 컬렉션 화면에만 있으며 공개 화면에는 나타나지 않는다. 보관한 글과 기존 글을 수정 중인 사본은 목록에서 뺀다.
- **선택 사항.** 컬렉션 선등록을 필수 단계로 만들지 않는다(기능별 작업 계약). 선택을 끄면 이전과 같이 글에만 붙는다.
- **목록 읽기.** `이 항목을 붙인 글`은 후보 글을 `readPhotoPosts`로 한 번에 읽는다. 없거나 검증되지 않는 글(`null`)은 건너뛰어 목록 전체가 실패하지 않는다(검수 m1·m2. 검수자 측정: 글 151개에서 순차 142ms, 일괄 17ms).
- **바꾸지 않은 것.** SQL·동기화 엔진·`storage.js` 구조는 바꾸지 않았다. 컬렉션은 기존 계정 동기화(`library-meta.js`)로 다른 기기에 간다.

## 남은 것

- 후속 후보(2026-11-02 총괄 결정, 지금은 하지 않음): 글과 항목을 ID로 연결하려면 서버 검증에 선택 필드를 추가하는 마이그레이션이 필요하다(총괄·운영 DB 절차). 착수 기준은 제목·출처 기준 연결이 실제 사용에서 틀리는 사례가 나오는 것이다.
- 같은 대상을 한 글에 두 번 붙이는 것은 이전처럼 허용한다. 컬렉션 쪽은 1개로 유지한다.
- **중복 판정의 경계(검수 m4, 이번에는 바꾸지 않음).** 내 페이지 작성기와 같은 기존 규칙을 쓴다.
  - 출처 주소가 있으면 종류와 주소만 비교한다. 같은 주소에 제목이 다른 항목은 같은 대상으로 본다.
  - 주소가 없으면 종류와, 앞뒤 공백을 뺀 제목·만든 사람을 비교한다. 띄어쓰기나 표기가 조금만 달라도 다른 대상이 된다.
- **카드 표시 시점(검수 m5).** `컬렉션에 있음`은 그 첨부 목록을 그린 시점의 컬렉션 기준이다. 다른 탭이나 다른 기기에서 컬렉션을 바꾸면 다음에 그릴 때 반영된다.
- **공개 화면 검사의 판별력(검수 m6).** 로그아웃 공개 홈은 계정 확인 전 개인 저장소를 열지 않는다. 그래서 이 검사는 그 경로로 새지 않는다는 것만 보여 준다. 공개 글·공개 사본 화면이 컬렉션 목록을 쓰지 않는다는 것은 코드 경로(비공개 `collection-ui`에만 존재)로 확인했다.
- `readPhotoPosts`가 `null`을 돌려주는 글을 건너뛰는 경로는 코드로 확인했다. 브라우저 검사로 일부러 만들지는 않았다.
- 겹친 저장 중 나중 결과만 반영하는 순번(m-c)은 코드로 확인했다. IndexedDB 요청 순서상 먼저 시작한 저장이 늦게 끝나는 상황을 브라우저에서 결정적으로 만들 수 없어 검사는 없다.
- 실제 Mac·iPad·iPhone 확인은 하지 않았다.
