# 글과 취향을 함께 저장하기

2026-11-02 소유자 요청: "글 쓸 때 취향과 엮어서 함께 저장. 예: 인용한 인물·작품·장소". 기준 main `c108dbb`.

## 목표와 범위

- **목표:** 블로그 글을 쓰며 인용한 인물·작품·장소를 취향 컬렉션에도 남긴다. 컬렉션 항목에서 그 항목을 붙인 글로 다시 간다.
- **이번 범위**
  - 블로그 편집기의 `음악·책·대상 붙이기` 확인 폼에 `취향 컬렉션에도 저장` 선택을 둔다.
    - 새 첨부는 켜진 상태로 시작한다.
    - 이미 붙인 첨부를 수정할 때는, 컬렉션에 아직 없는 항목만 켜진 상태로 시작한다.
  - 첨부 카드마다 컬렉션에 있으면 `취향 컬렉션에 있음`(보관한 항목이면 `· 보관한 항목`)을 표시한다.
  - 컬렉션 항목 상세에 `이 항목을 붙인 글` 목록을 둔다. 초안이면 `초안 ·`, 그 뒤에 수정 날짜를 붙인다. 누르면 그 글을 연다.
- **기존 구현 재사용**
  - `Collection.fromAttachment`·`attachmentMatch`: 내 페이지 작성기의 `컬렉션에 보관`과 같은 중복 판정
  - `storage.saveCollection`의 revision CAS
  - 블로그 관리자와 같은 글 열기 경로(`navigate('page', { searchTarget: { photoPostId } })`)

## 지킨 것

- **글 첨부 형식은 그대로다.** `{type, title, creator, url}`이며, 서버 검증(`20261101091500_life_blog_account_sync.sql`)이 이 키를 고정한다.
  - 항목 ID 참조를 넣지 않았다. 그래서 글과 항목의 연결은 같은 판정 규칙(종류 + 출처 주소, 주소가 없으면 제목·만든 사람)으로 계산한다.
  - 컬렉션 항목의 제목이나 주소를 나중에 고치면 연결 목록에서 빠질 수 있다.
- **컬렉션 저장은 글 저장과 별개다.** 첨부를 반영한 뒤에 따로 저장한다. 실패해도 첨부는 글에 남고, `첨부 정보 수정`에서 다시 저장할 수 있다.
- **중복 저장 금지.** 같은 대상이 이미 있으면 저장하지 않는다. 보관한 항목도 그대로 둔다.
- **다른 탭 변경 보존.** 다른 탭이 컬렉션을 먼저 저장했으면 최신 내용을 다시 읽어 덧붙인다(최대 3회). 다른 탭의 변경은 그대로 남는다.
- **복사하지 않는 것.** 개인 메모·태그는 어느 쪽으로도 복사하지 않는다. 새 컬렉션 항목은 빈 메모·빈 주제로 만든다.
- **읽기 전용.** `이 항목을 붙인 글`은 같은 작업공간의 사진 글만 읽는다. 보관한 글과 기존 글을 수정 중인 사본은 목록에서 뺀다.
- **선택 사항.** 컬렉션 선등록을 필수 단계로 만들지 않는다(기능별 작업 계약). 선택을 끄면 이전과 같이 글에만 붙는다.
- **바꾸지 않은 것.** SQL·동기화 엔진·`storage.js` 구조는 바꾸지 않았다. 컬렉션은 기존 계정 동기화(`library-meta.js`)로 다른 기기에 간다.

## 남은 것

- 글과 항목을 ID로 연결하려면 서버 검증에 선택 필드를 추가하는 마이그레이션이 필요하다(총괄·운영 DB 절차).
- 같은 대상을 한 글에 두 번 붙이는 것은 이전처럼 허용한다. 컬렉션 쪽은 1개로 유지한다.
- 실제 Mac·iPad·iPhone 확인은 하지 않았다.
