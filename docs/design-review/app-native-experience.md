# 앱다운 탐색과 반응

2026-10-18 Asia/Seoul. 기존 블로그의 작성·저장·읽기·복귀를 하나의 앱 경험으로 연결하는 후속 작업이다. 구현 전에 [모션·셸 계약](../../.impeccable/app-native-direction.md)을 작성했다. 제품은 일반 HTML/CSS/JavaScript와 브라우저의 자연스러운 문서 스크롤을 유지한다.

## 목표와 보존

홈에서 글을 쓰고 저장한 내용을 읽은 뒤 출발 목록으로 돌아오는 흐름이 중심이다. 안정된 상단 조작·현재 메뉴 표시, 수준이 다른 이동과 같은 수준의 전환, 실제 상태 반응을 함께 적용한다. 기존 사진/리치 글·첨부 글·원천 글의 저장 형식, 초안 보관과 명시 저장·공개·동기화의 구분, 원문 버전·정확 위치·백업·계정 격리를 보존한다.

화면의 새 모션은 실제 이동에만 사용한다. 읽던 문단이나 입력 DOM에 반복 등장 효과를 추가하지 않고 DOM 복제·전체 화면 스냅샷·개인 본문의 별도 outgoing 캐시를 만들지 않는다. 모션 실패·중단·미지원은 데이터 작업과 탐색을 막지 않는다.

## 실제 구현과 선택

기존 플랫폼 CSS/WAAPI를 사용하며 외부 애니메이션 라이브러리는 추가하지 않는다. 선택 비교와 재검토 조건은 [구현 계약](../../.impeccable/app-native-direction.md#구현-선택)에 있다. 실제 값은 [모션 모듈](../../assets/haedo-motion.js)과 [탐색](../../assets/haedo-navigation.js)에서 추출했다.

| 역할 | 실제 값과 동작 |
| --- | --- |
| 다음 화면 / 이전 화면 | 220ms / 200ms, 현재 실제 요소의 작은 수평 이동과 opacity |
| 같은 수준 / 작성 진입 | 160ms / 260ms, 탭의 수평 이동 / 작성의 20px 수직 이동 |
| 저장 후 결과 표시 | reveal 180ms, 실제 성공한 저장 결과만 표시 |
| 실제 저장/실패 안내 | 140ms opacity, 초기 제안 180ms에서 짧게 확정 |
| 현재 탐색 표시 | 220ms, `aria-current`가 확정된 링크의 좌표로 이동; 빠른 재이동은 현재 그려진 위치에서 이어짐 |
| 버튼 누름 / 색 | 100ms·scale(.975) / 140ms, 탐색 링크는 자리를 유지하고 도형만 scale(.9) |
| easing | `cubic-bezier(0.16, 1, 0.3, 1)` |
| 취소·대체 | 요소별 취소, 숨김·pagehide·모션 감소 때 즉시 종료; WAAPI가 없거나 실패하면 기본 화면 유지 |

애니메이션에는 fill이나 임시 본문 복제본을 남기지 않는다. 탐색 표시의 크기·좌표는 목적지가 확정된 뒤 즉시 갱신하고 이동만 transform으로 표현한다. ResizeObserver·창 폭 변경·글꼴 준비·작성기 종료에서 다시 배치한다. 새 화면의 모션은 저장/flush와 렌더 결과를 확인한 뒤 적용하며, 늦은 응답이나 사용자가 이미 입력한 화면을 움직이지 않는다. 원문의 정확 구간 위치 측정은 모션 이전에 수행한다.

[작성기](../../assets/life/photo-post-ui.js)는 명시 저장이 성공한 읽기에 체크와 비공개 저장 문구를 남긴다. 자동 초안 저장은 같은 성공 모션을 반복하지 않는다. 오류는 입력을 유지하고 실제 오류·복구 조작과 함께 표시하며 저장 성공으로 바꾸지 않는다. 작성 본문은 문서와 함께 자연스럽게 늘어나고, 펼친 서식/더보기 메뉴만 제한된 높이에서 스크롤한다. 메뉴 밖 클릭과 Escape로 닫고 해당 조작에 초점을 돌려준다.

[공통 모션 CSS](../../assets/haedo-motion.css)는 앱의 세로 문서 스크롤을 유지하며 연표 외 가로 넘침만 clip한다. 공통 제목·복귀는 흰 sticky 행(top:0·z-index:35·좌우 24px/모바일 20px·위쪽 safe-area)으로 남긴다. 신형 작성 중에는 바깥 header와 형제 toolbar·빈 main 간격을 감춰 작성기의 닫기·저장 행 하나에 집중한다. [홈](../../assets/life/home.js)은 실제 세 상태 탭을 누를 때 목록에 160ms, 검색을 펼칠 때 180ms를 적용하고 떠날 때 해당 모션을 취소한다. 탭의 3px 안쪽 여백·44px 조작·흰 선택면은 이전 선택선을 대신하며 실제 키보드 탭 동작은 유지한다.

모션 CSS는 공통 셸 다음, 모듈은 탐색 모듈 전에 기존 8개 앱 표면에서 로드한다. 오프라인 캐시와 준비 묶음에 두 파일을 포함한다. 외부 CDN이나 새 런타임·빌드 단계는 추가하지 않는다.

## 검증 근거와 한계

모션 모듈의 별도 Chromium 검사는 1440·820·390px에서 탐색 표시 이동·연속 재이동·좌표 일치·화면 모션 대체와 정리·미지원·숨김·모션 감소를 확인했다. [보존한 검증 요약](evidence/app-native/verification-summary.json)의 모듈 검사 세 폭 항목은 모두 통과했다. 이 결과는 모듈 검사이며 앱의 작성·저장·복귀 통합 검증과 구분한다.

통합 [브라우저 검사](../../tests/app-motion-browser.cjs)는 최종 **9/9** 통과했다. [보존한 검증 요약](evidence/app-native/verification-summary.json)의 실행은 Linux Chromium 151.0.7922.173, 익명 모의 Auth와 실제 계정별 IndexedDB 기반이며 console/page 오류는 0이고 외부 요청은 없었다. push/back/tab/compose에서 실제 WAAPI의 중간 rAF 프레임·computed transform/opacity 변화와 최종 정리, 5개 폭/방향과 축소 키보드 viewport의 작성 집중·44px 조작, 모션 감소 설정의 최초/실행 중 변경, 실패 flush의 입력·메뉴 보존과 거짓 성공 없음, 빠른 이동의 최종 메뉴, 긴 글 제목과 탭·검색·초점·스크롤 복귀, 영역 위치 메모리, 늦은 읽기·공간 전환·로그아웃·다른 계정 격리를 확인했다.

통합 검사에서 작성기의 바깥 제목이 실제 형제 toolbar로 남는 결함을 발견해 함께 감췄다. 새 읽기에 목록 스크롤이 이어지는 문제도 정확 구간·복귀 맥락이 없는 진입에 한해 상단으로 이동하도록 고쳤다. 초기 검사 selector/fixture 실패와 제품 결함을 분리하고 수정 뒤 전체 9개를 다시 확인했다.

최종 시각 확인은 1440×1000·820×1000·390×844·320×568·844×390의 홈/자료실/읽기/집필/저장 후 읽기 **25장**, 실제 동작 도중 **4개 중간 화면**과 [연속 모션 영상](evidence/app-native/haedo-native-flow.mp4)으로 수행했다. [최종 검증 요약](evidence/app-native/verification-summary.json)의 가로 넘침·44px 미만 일반 조작·작은 입력·이름 누락·대비 지적은 0이며 console/page 오류와 외부 요청도 없었다. 정지 이미지가 모션 품질을 증명한다고 보지 않고 실제 rAF 관찰과 Linux Chromium 화면 녹화를 함께 사용했다.

직접 이미지 검토에서 320px 사진 조작의 줄바꿈, 작성 중 중복 제목, 지역 파란 초점과 공통 틸의 불일치, 읽기 진입의 스크롤·영역 이동 방향을 한 번에 고친 뒤 최종 1회로 확인했다. 최종 읽기 다섯 폭 모두 제목·복귀가 보이는 상단에서 시작했고, 작성의 닫기·저장은 44px이며 바깥 toolbar는 보이지 않았다. 홈의 문서 위치는 420→420px로 복원되고 모션 감소에서는 실행 중 공간 모션이 없었다. 이 수치는 해당 익명 샘플의 관찰값이다.

영상은 Linux Chromium의 실제 브라우저 동작을 390×844·25fps로 녹화했다. 약 12.6초 WebM에서 검사 준비의 첫 0.5초만 잘라 12.08초 MP4로 제공했다. 속도 변경·슬라이드쇼·추가 오버레이는 없다. [모바일 흐름](evidence/app-native/mobile-flow.png)과 [실제 영상의 6프레임](evidence/app-native/actual-nav-motion-frames.jpg)도 함께 보존한다. 중간 화면·영상·정지 이미지는 익명 합성 자료이며 운영 계정이나 개인 자료를 사용하지 않았다.

기존 회귀는 홈 10/10, 사용 흐름 8/8, SNS 2/2와 27개 캡처를 통과했다. `npm test`는 520/520, `npm run check`는 HTML 18개·JS 91개·참조 377개를 통과했다. PWA 회귀도 9/9 통과했다. 이 결과는 로컬 기능·정적·서비스워커 검사이며 공개 배포 완료를 뜻하지 않는다.

PWA는 기존 `haedo-v123`을 보존한 상태에서 `v124`로 갱신했다. 캐시 응답 95개의 SHA가 준비 묶음과 일치했고 생성 설정을 제외한 94개는 원본 소스와도 같았다. 새 모션 JS/CSS는 소스·준비 묶음·캐시가 모두 일치했다. HTTP 캐시와 네트워크를 끈 상태에서 두 자산을 서비스워커의 200 응답으로 받고, 실제 WAAPI 4회와 작성→저장→홈을 확인했다. `animate`가 없는 정적 대체 경로도 수정·저장·복귀와 입력을 보존했다. 원격 쓰기·예상하지 않은 오류는 0이며 의도한 전송/콜백 오류 2건은 별도 실패 복구 검증이다. [보존한 PWA 결과](evidence/app-native/verification-summary.json)의 `pwa`에 범위와 해시를 남겼다.

저장소에는 위의 검증 요약·대표 이미지·MP4를 보존한다. 모듈/통합/전체 시각 검사의 원시 결과는 각각 `.local/app-motion/module-report.json`, `.local/app-native/qa/browser-report.json`, `.local/app-native/visual/report.json`에 있으며 로컬 재현 산출물로 구분한다.

실제 Mac/iPad/iPhone의 IME·가상 키보드·Files·VoiceOver·앱 전환, 운영 OAuth·DB·공개 배포는 미검증이다. 축소 viewport는 실제 가상 키보드 검사와 구분한다.
