# 글에 붙인 대상 수정·미반영 입력 보호

2026-10-14 KST. PR #82 후속. 기존 첨부를 같은 위치에서 수정하고 검토 중 입력이 저장·전환에서 빠지지 않게 했다. 병합·배포는 Local 담당이다.

## 전문가 검토와 설계

기존에는 첨부 제목·작가·출처를 고치려면 해제 후 다시 넣어야 했다. 순서가 바뀌거나 12개 한도에서 교체가 어려웠다. 반영하지 않은 첨부 폼이 글 저장·초안 닫기·다른 화면 이동에서 결과에 빠지는 공백도 있었다. 새 제공자 확대보다 이 확인된 편집 공백을 먼저 완결했다.

| 검토 항목 | 선택·보존 조건 |
| --- | --- |
| 수정 위치·동일성 | 선택한 스냅샷 한 개만 같은 위치에서 교체. 다른 첨부·글 ID/생성일·컬렉션 원본 보존 |
| 본문 집중 | 기존 네 필드 폼을 수정할 대상 바로 아래에서 재사용. 본문 textarea/선택 구간 재생성 없음 |
| 반영·취소 | 명시 반영은 검증한 값만 사용. 취소는 원래 첨부 유지. 빈 제목/잘못된 출처/한글 조합 중 입력 보존 |
| 저장 의미 | 이미 반영된 본문·첨부는 기존 자동 초안 보관. 별도 검토 폼은 ‘첨부 입력 미반영’으로 표시 |
| 전환·복구 | 미반영 폼이 있으면 저장/다른 초안/선택창/첨부 순서·해제/앱 탐색/초안 파일 조작 차단. 반영·취소 후 해당 경고만 제거하고 다른 저장 오류 유지 |
| 다른 탭 | 새 저장본 읽기가 내부 상태를 비우기 전에 첨부 검토·초안 저장 확인. CAS 충돌은 원래 글과 수정 초안을 유지하고 새 글로 복구 |

기존 PageComposer·PagePosts.attachment·수정 폼·아이콘·650ms 초안 보관·CAS/원자적 저장·백업을 재사용했다. SDK/의존성/SQL/저장 스키마를 추가하지 않았다. 새 편집기를 도입할 필요가 없는 좁은 일반 JavaScript 확장이다. [기존 글쓰기 설계](page-composer.md)와 [Impeccable 지침 설치](impeccable.md)를 따른다. 인물/영화 제공자는 현재 Cloud 허용 목록 밖이며 이번에 연결하지 않았다.

## 직접 체험

1. `npm run dev` → `http://127.0.0.1:4173`. 기존 공용 로그인으로 내 페이지를 연다. 자동 검수는 익명 모의 Auth다.
2. 글 수정 → 첨부 옆 **첨부 정보 수정** 연필 → 제목·작가·출처를 수정한다.
3. 반영하기 전에 글 저장이나 도구 이동을 누르면 입력이 남고 반영/취소 안내가 나온다. 본문은 별도로 자동 초안 보관된다.
4. **수정 반영** → 같은 위치의 첨부 확인 → **저장** → 새로고침 후 같은 글로 재열기.
5. 입력 취소는 원래 첨부를 유지한다. 첨부 12개에서도 기존 한 개를 수정할 수 있다. 인물로 바꾸면 해당 폼의 만든 사람만 비운다.

반영·취소 뒤 초점은 해당 첨부로 돌아온다. 순서를 바꾼 뒤에도 새 위치의 편집 조작으로 복귀한다. 원출처 링크는 기존 safeURL/noopener noreferrer를 사용한다. 이 편집으로 API·이미지·외부 서버 요청을 만들지 않는다.

## 저장 범위와 한계

반영된 첨부는 기존 type/title/creator/url 스냅샷이다. 컬렉션 원본·개인 메모/주제/상세·기존 공개 사본을 자동 변경하지 않는다. 비공개/공개 후보·동기화·공개 투영·불변 원문·자료/구성 백업의 기존 계약을 보존한다.

**미반영 폼은 현재 화면의 임시 입력**이다. 잘못된/반쪽 첨부를 기존 초안 스키마에 자동 넣지 않았다. 앱 내 이동과 일반 beforeunload는 보호하지만 강제 종료·세션 강제 폐기·OS 종료 뒤 폼 복구를 보장하지 않는다. 반영한 첨부/본문은 기존 로컬 초안·파일 사본으로 복구한다. 실제 기기에서 종료·앱 전환이 반복되면 별도 임시 폼 보관을 검토한다.
