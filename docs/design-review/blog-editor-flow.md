# 내 페이지 블로그 글쓰기 흐름 개선

2026-10-15 KST. [대표 편집기 비교](blog-editor-comparison.md)의 후속 구현. 기반 #90 `ac3444b`, Quill 2.0.3·fflate 0.8.3과 기존 저장 형식을 유지한다. 새 엔진·프레임워크·SQL·업로드 서버를 추가하지 않았다.

## 목표와 보존 조건

내 페이지에서 글을 쓰다가 사진을 넣고 설명을 붙인 뒤 저장·다시 읽는 한 흐름을 편하게 만든다. 기존 원문·첨부 글·초안·공개 후보·백업은 그대로 유지한다. 이번의 단일 진입은 **내 페이지 안의 기본 글쓰기**를 뜻하며, 원천 자료로 저장하는 기존 전역 글쓰기까지 같은 형식으로 바꾼 작업은 아니다.

두 저장 형식을 곧바로 합치면 기존 글의 첨부·공개·동기화와 백업 계약이 함께 바뀐다. 이를 피하기 위해 UI 진입과 목록을 통합하고, 기존 문서의 읽기·수정과 대상 첨부 작성 경로를 보존했다. 저장 형식까지 통합했다고 표현하지 않는다.

## 구현한 흐름

- **기본 `글쓰기` 하나.** 내 페이지에서 글쓰기 아이콘을 누르면 같은 본문 편집기가 열린다. 사진 없는 짧은 글도 이곳에서 저장한다. 별도의 `사진 글쓰기` 선택은 제거했다. 기존 첨부 글 수정은 원래 작성기로 열리고, 새 대상 첨부 글은 접힌 `기존 글·첨부 → 대상 첨부 글쓰기`에서 계속 쓸 수 있다. 새 rich-text 글에 음악·책 첨부까지 합친 것은 아니다.
- **공통 글 목록.** 기존 첨부 글과 새 글·사진 글을 수정일 내림차순으로 함께 놓는다. 각 문서의 기존 ID/저장 경계를 유지한다. 사진 글의 대표 이미지는 실제 문서 첫 사진의 원본 Blob에서 가져오며 보이는 행만 읽는다. 원본 파일을 축소·재인코딩하지 않고, 목록의 작은 표시 상자만 CSS로 조절한다. 늦은 읽기는 화면/작업공간이 바뀌면 적용하지 않는다. 목록이 합쳐질 때 기존 초점을 보존한다.
- **사진 바로 아래 설명.** 사진이나 `사진 설명 추가`를 선택하면 해당 사진 아래에 설명 입력이 열린다. 대체 텍스트·해상도·이동·빼기는 접힌 `사진 설정`에 둔다. 큰 고정 패널을 제거했다. 설명의 공백·줄바꿈·한글 조합을 유지하고, `사진 편집 닫기`로 사진 다음 본문에 커서를 둔다.
- **설명과 실행 취소.** Quill의 embed retain patch와 updatable embed 이벤트를 사용한다. 설명 입력 때 figure/textarea를 삭제·재생성하지 않는다. Delta handler의 compose/invert/transform을 등록해 설명·대체 텍스트를 history에 연결한다. 사진 추가·이동·빼기와 설명 필드 전환에는 history 경계를 둔다. 입력 중 Ctrl/Cmd+Z, Shift+Z/Y도 같은 history를 사용한다. 영속 문서는 이전과 같은 insert 기반 제한 Delta다.
- **상단 저장.** 닫기·작은 로컬 저장 상태·`글 저장`을 서식 도구와 함께 본문 위에 고정한다. 긴 글 끝에서도 저장 버튼에 접근한다. 백업·초안 재저장·충돌 새 사본 복구는 `더 보기`에 둔다. 메뉴는 주 저장 조작 아래로 열리며 그 버튼을 덮지 않는다. 저장 실패 때 기존 입력과 문서는 그대로 남는다.

재사용은 Ghost의 본문·사진·설명 순서, ONE의 친숙한 기본 진입과 도구 배치, Gutenberg의 사진 가까운 조작을 참고한 범위다. 타 제품의 코드·이미지·브랜드를 복사하지 않았다. Quill 2.0.3의 공식 [embed 갱신](https://github.com/slab/quill/blob/v2.0.3/packages/quill/src/blots/scroll.ts)과 [history로 이어지는 이벤트 처리](https://github.com/slab/quill/blob/v2.0.3/packages/quill/src/core/quill.ts)를 확인하고 현재 vendor API에 맞췄다. 이 부분은 향후 Quill 버전 변경 때 재검증할 결합점이다.

## 한계와 다음 판단

Mac/iPad/iPhone의 실제 한글 키보드·Photos/Files·VoiceOver·소프트 키보드/회전·분할 화면은 미검증이다. 390/820/1440px 검사는 Chromium 화면 크기 검증이다. HEIC 지원·갤러리/나란히 배치·사진 자르기·새 글의 음악/책 첨부 통합·사진 동기화/공개는 이번 범위가 아니다. 새 기본 글은 사진이 없어도 이 브라우저의 새 rich-text 형식이며 전용 ZIP으로 보관한다. 기존 일반 JSON·구성 동기화·공개 사본에 자동 포함하지 않는다.

실기에서 선택/조합/history 문제가 반복되거나 이미지 블록 확장 때문에 우회가 커지면 Tiptap과 같은 글로 비교한다. 원본 바이트·기존 Delta/ZIP 복원·기존 글/첨부 보존과 실패 복구를 유지하면서 실제 조작 부담이 줄어드는 것을 전환 조건으로 둔다.

직접 체험: `npm run dev` → `http://127.0.0.1:4173` → 로그인 → 기록 → 내 페이지 → **글쓰기**. 문장을 쓰고 사진을 넣어 사진 아래 설명을 작성한 뒤 **글 저장**한다. 목록에서 기존 첨부 글과 함께 확인하고 사진을 확대·원본 내려받기 한다. 편집 중 **더 보기 → 사진 포함 백업**, 목록의 **사진 글 파일 → 사진 글 백업 열기**로 새 초안 복원을 확인한다. 서버는 Ctrl+C로 종료한다.
