# 언어 주제 연결과 비교 당시 근거 확인

2026-10-21 KST. PR127을 포함한 main `d6009ea`/SW152에서 시작했다. 목표는 공개 공급 진단→명확한 표현 연결→기존 읽기 비교의 선정 근거 확인→자료 보관·글 저장·재열기·뉴스 복귀를 한 번에 보완하고 검수하는 것이다. 새 UI·평가 도구·추천 서버를 늘리지 않는다.

## 확인과 구현

같은 공개100글/8출처의 고정 바이트를 기준으로 빈 반응·동일 시각/필터에서 비교했다. 언어교육 연구 출처의 수집 회복은 기존 운영 상태이며 이번 수정 성과가 아니다. 기관 태그·날짜 순서·일반적인 language 표현만으로 도움이나 문맥 적합성을 확정할 수 없다. 날짜 없는 논문에 수집일을 발행일로 채우지 않는다.

직역이 분명한 `언어 학습/언어학습 ↔ language learning`, `언어 교육/언어교육 ↔ language education`만 기존 공개 동의어에 추가한다. 긴 문장을 자동 주제로 분해하거나 generic language·복수형·기관 태그 가중치를 바꾸지 않는다. 설정의 기존 주제 예시6개 안에 한국어 언어 학습/교육을 배치하며, 클릭 전 관심을 저장하지 않는다. 원문 언어 필터와 명시 번역 설정은 그대로다.

기존 **뉴스 설정 → 추천·기록 → 읽기 비교 → 비교 조건·근거** 안에서 당시 보관한 제목·관심 표현 일치·태그와 개인 추천의 대응 표현을 확인한다. 근거는 기존 불변 세션의 reasons/evidence/sourceSnapshot만 사용하며 현재 피드나 추천기를 다시 호출하지 않는다. 목록 소속·순서를 함께 표시하고 일치 표현을 최신순의 선정 원인으로 표현하지 않는다. 최대6글·글당 최대5근거이며 기본 피드·읽기 카드에 새 설명줄을 추가하지 않는다. 내용은 textContent로 표시한다.

개인 추천은 명시 좋아요·제목 단어/태그 전체 표현·서로 다른 최소2표현의 기존 규칙을 유지한다. 새 동의어 입력과 구분할 정책 이름은 `public-title-tag-expressions-v3`다. 기존 v2 비교는 v2 그대로 열기·판정 수정·삭제하며 재계산/응답 승계/새 필드를 넣지 않는다. 비교 입력 SHA는 정규화된 입력의 식별자이며 코드·동의어 버전 동일성의 증명이 아니다.

## 공급 점검과 전후 근거

운영 고정본은100글/8출처/6성공이며 별도 로컬1회 점검은7성공이었다. Woowa의 한 번200과 이미 정상인 LLT를 이번 수정으로 운영 장애를 고쳤다고 표시하지 않는다. D2는 robots의 HTTP 이동을 기존 HTTPS 정책이 거절해 피드를 요청하지 않았다. OpenLearn은 공식 언어 페이지에서 RSS 선언을 찾지 못하고 권리 문서를 확인하지 못했으며, The Conversation은 명시된 AI robots 제한으로 추가 요청을 중단했다. 두 후보 모두 보류하고 출처·collector를 유지한다.

동일 시각·필터·빈 반응의 전후에서 한국어 언어 학습 두 표기는 기존0→실제 영어 제목 표현 후보1개로 연결됐다. 언어 교육 두 표기는 공급에 정확한 대응 표현이 없어0을 유지한다. 최신순 URL 순서와 두 명시 합성 반응의 추천 내용은 같고 정책 라벨만 구분된다. 이는 문자 표현의 도달성 증거이며 문맥·실제 도움의 개선 수치가 아니다. 기관 태그·날짜 없는 논문·일반 language의 다의성은 직접 읽기 비교에서 판단할 한계로 남긴다.

v2 호환 검수는 기준 main의 실제 모듈로 만든 익명 합성 역사 판을 사용한다. 현재 추천 결과의 정책 라벨만 바꿔 과거 자료로 주장하지 않는다. 실제 model·storage에서 재조회·응답/선호 수정·삭제·늦은 CAS 거절을 확인하며 재계산 호출을 차단했다. 단위1202개와 정적22HTML/153JS/648참조를 통과했다. 브라우저·PWA·정확한 최종 CI·공개 배포의 증거는 변경 PR 기록에 구분해 갱신한다.

## 보존과 완료 기준

기본 꺼짐 opt-in·담기/읽음/무응답과 좋아요 분리·개인자료/서버/공개 전송 경계, 기존 계정/공간 CAS·실패 입력·삭제 tombstone·정확한 원문/글쓰기 왕복과 최소 UI를 유지한다. 학습 모델·라이브러리·DB 스키마·저장 형식·소스 본문 수집을 추가하지 않는다. 실제 좋아요/평가 기록을 개발 환경에서 조회하지 않으며 비교는 빈 반응 또는 명시 합성 반응으로 구분한다. 직접 읽기 도움과 실제 기기는 자동 검수로 채우지 않는다.

완료는 같은 공급·시각·필터의 전후 정확한 표현/URL/날짜 대조, v2 역사 판의 실제 읽기·수정·삭제, 당시 근거와 후속 피드 변경의 분리, 새 한국어 주제의 실제 UI 연결, 기존 기사→글 완주·PWA와 정확한 PR/main CI·배포 파일 검증을 함께 확인하는 것이다. [최종 PR·출시 기록](https://github.com/wonchance-art/life-haedo/pulls?q=is%3Apr+head%3Acodex%2Fnews-usefulness-20261021).

화면은 기존 native details·문자 노드·Discovery/Recommendations·Reading/Storage를 재사용했다. 새 범용 추천/검색 서비스 도입은 실제 학습 근거·운영 요구가 생기면 기존 [공식 비교](../life-tools-design/open-source-review.md)를 바탕으로 재검토한다. 실제 읽기 판단이 선행돼야 하는 개선 채택 결정과, 이번에 자동으로 끝낼 수 있는 구현·연결·검수·배포를 구분한다.
