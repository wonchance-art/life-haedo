# 많은 자료에서 다시 찾기: 한글 공백과 결과 표시

2026-10-08 KST. PR #39 `55d07f2` 다음 단위. 기억나는 구절 검색 → 정확한 원문 버전 읽기 → 같은 검색 결과로 복귀를 개선한다. 본문·출처·연표·공개 사본·동기화·백업 형식은 바꾸지 않았다. 운영 설치·병합·배포·라이브 검증은 Local이 담당한다.

## 사용자가 확인할 변화

- 기록 검색은 전체 자료를 찾고 처음 40개를 보여준다. **자료 더 보기**로 40개씩 추가하며 기존에 펼친 출처 정보와 결과 DOM을 유지한다. 총결과 수와 현재 표시 수를 구분한다.
- 검색 필터의 **한글 띄어쓰기 무시**를 켜면 `가을산책의호흡`으로 원문의 `가을 산책의 호흡`을 찾는다. 기본은 기존 검색이다. 제목·본문·저장한 문장/메모에 같은 한글 공백 옵션을 적용한다.
- 결과를 열었다 돌아오면 검색·필터·옵션·표시 범위를 유지한다. 정확 버전이 표시 범위 밖으로 밀렸으면 해당 결과까지 펼친다. 직전 저장 바로가기 대신 결과 카드가 보이게 된 경우에는 같은 버전의 원문 버튼으로 초점을 복원한다.
- 조건을 바꾸면 처음 40개로 돌아간다. 선택한 기록은 전체 선택 목록에 유지하며, 화면 밖 선택을 몰래 제외하지 않는다. 작업공간·계정 변경 시 검색과 선택 상태를 초기화한다. 더보기·검색어·공백 옵션은 저장·전송하지 않는다.

한글 **완성형 음절 사이의 수평공백만** 유연하게 찾는다. 줄바꿈·문장부호·영문 단어를 합치거나 조사·동의어·흩어진 단어의 뜻을 추론하지 않는다. NFC/NFD 동등 검색은 후속 범위다. 원문을 정규화하지 않고 실제 문자열의 UTF-16 위치와 구절을 반환한다. 제목·메모만 일치할 때 본문 구절을 만들어내지 않는다. [엔진 계약과 측정](search-quality-engine.md)을 함께 본다.

## 선택 근거

실제 앱의 익명 100/1,000개 자료를 측정했다. 자료당 평균 약 1,373 UTF-16 단위이며 이전 버전 하나를 포함한다. 1,000개에서는 DOM 21,203개를 만들었고, 공통어 검색 입력부터 두 번째 animation frame까지 중앙값이 1440px에서 약 275ms, 390px에서 약 286ms였다. 전체 본문을 검증하는 엔진 비용과 별개로 결과 DOM을 모두 만드는 비용이 컸다.

가상 목록보다 명시적인 더보기를 택했다. 브라우저 기본 스크롤·키보드·원문 복귀를 유지하며 기존 결과를 제거하지 않기 때문이다. 40개는 초기 렌더 부담을 줄이는 단위이지 전체 결과 상한이나 모든 기기의 성능 보증이 아니다. 사용자가 계속 펼치면 DOM은 늘어난다.

[공식 오픈소스 비교](../life-tools-design/open-source-review.md#기억나는-한글-문구-찾기--검색-계약을-보존하는-작은-개선)에서 Fuse.js·MiniSearch·FlexSearch의 최신 배포·라이선스·유지관리·공개 권고를 확인했다. 이번 요구는 한글 음절 사이 공백과 실제 원문 좌표이므로 네이티브 정규식과 기존 화면을 재사용했다. 라이브러리·AI·원격 인덱스를 추가하지 않았다. 다중 단어·순위 검색은 별도 평가 후 선택한다.

## 검증과 증거

검증에는 익명 Auth HTTP·동봉 SDK·격리 IndexedDB를 사용한다. 개인 계정·원격 자료는 사용하지 않는다. 기능 회귀, 시각 검토, 속도 측정, 실제 기기 체험을 구분한다.

- `npm run check`: HTML 17·JS 51·참조 252·PWA 정적 검사 통과.
- `npm test`: 311/311 통과. 새 엔진 경계 검사 3개 포함.
- 기존 검색 7/7과 가져오기 3폭 3/3 통과. 원문 UTF-16·이전 버전·발췌·IME 이벤트·검색 복귀·계정 분리를 보존한다.
- [PWA 9/9](evidence/search-quality/pwa-report.txt) 통과. 기존 v73의 캐시·자료를 유지한 v74 갱신과 변경 모듈 해시를 확인했다. 의도한 전송/콜백 오류 2개는 예기치 않은 오류와 구분했다.

속도는 같은 Linux Chromium/합성 자료의 공유 실행환경 측정이다. 입력부터 두 번째 프레임은 앱 연산과 렌더 기회를 포함하며 실제 터치 지연·Core Web Vitals·Apple 기기 성능을 뜻하지 않는다. 시간 임계치를 테스트 합격 조건으로 사용하지 않는다. 메모가 많은 자료, 실제 파일 공급자·IME·VoiceOver와 실기 사용은 미검증이다. 10,000개는 엔진만 탐색했고 전체 앱 사용 완료로 보고하지 않는다.

## 최종 브라우저 결과

새 검사는 **5/5** 통과했다. 100개 자료의 1440·820·390px, 1,000개 자료의 1440·390px를 확인했다. 더보기와 기존 DOM/출처 펼침·선택 유지, 마지막 묶음·빈 결과, 한글 조합 입력, 옵션의 제목/본문/메모 적용, 정확 버전·검색 복귀를 검증했다. 820px에서는 실제 저장 알림 뒤 새 버전을 읽어 기존 40번째 결과가 41번째가 되는 경우와 작업공간/계정 변경 초기화도 확인했다. 첫 40개 밖에 저장한 자료의 [복귀 화면](evidence/search-quality/browser-after-saved-outside-window-100-390.png)도 남겼다.

최종 21캡처에서 가로 넘침·조작 크기·입력 크기·접근 가능한 이름·대비 위반 0, 측정 최소 글자 대비 5.661:1이었다. console/pageerror·외부 요청·실제 원격 쓰기 0이다. root와 독립 QA가 같은 캡처를 시각 검토했다.

초기 새 검사에서 자료만 보관하면 목록으로 돌아온다는 잘못된 기대, 단일 버전 화면의 없는 selector, 같은 값 입력의 이벤트 대기, 외부에서 만든 작업공간이 현재 UI에 즉시 나타난다는 fixture 가정을 수정했다. 앱 계약에 맞게 발췌 후보 저장·실제 원문/ID 확인·값 변경 시 측정·실제 새 작업공간 UI를 사용했다. 이미 통과한 경로는 반복하지 않고 820px만 재검증했다. 최종 보고의 sourceRuns에 이전 결과와 재검증 시각을 남겼으며 로컬 전체 5경로를 마지막에 한 번 더 실행했다고 주장하지 않는다. 최종 커밋의 전체 CI 결과는 PR에 별도로 기록한다.
