# Obsidian 연결 선택과 새 비공개 사본

2026-10-17 UTC. [전체 보관함 통합](obsidian-vault-integration.md)의 읽기용 보고서 다음으로, **원문·후보 대조 → 참조별 선택 → 변경 미리보기 → 새 사본 ZIP → 앱 복원·정확 위치·역방향 연결**을 연결했다. 원래 Git/본문/감사 파일과 기존 계정 작업공간은 수정하지 않는다. 운영 배포와 실제 Apple 기기 검증은 별도다.

## 사용 순서

새 보관함 변환에는 `review-tool.html`도 생성된다. 기존 패키지를 다시 변환할 필요 없이 다음 명령으로 개인 자료가 들어 있지 않은 도구만 만들 수도 있다.

```sh
node scripts/create-obsidian-review-tool.mjs --output /private/review-tool.html
```

1. 도구를 열고 같은 변환 폴더의 **notes.json · supporting-files.json · private-audit.json · review.json · review.html · repository.bundle**을 함께 선택한다. 처음 파일을 읽을 때 같은 패키지인지, 모든 원문/해시/경로/정확 버전이 일치하는지 확인한다. 이력 있는 사본은 `applications.json`도 함께 고른다.
2. 검토할 묶음과 참조를 고른다. 원래 링크 주변 원문과 후보 경로·본문을 대조하고 **이 참조 선택**을 누른다. 같은 묶음의 다른 참조는 자동 선택하지 않는다. 제목/블록을 가리킨 링크는 실제 제목·블록 위치까지 골라야 한다. 코드 fence 안 제목은 위치 후보에서 제외한다.
3. **선택 파일 내려받기**로 중간 작업을 보관하고 나중에 다시 연다. 기존 선택 교체/화면 종료에는 입력 보존 안내가 있다. 선택 파일의 원본·토큰·해시가 다르면 현재 선택을 유지하고 거부한다.
4. **변경 미리보기**에서 추가·위치 보완·이미 반영·보류·보관 정보 개수를 확인하고 **새 사본 ZIP 내려받기**를 누른다. 다운로드 요청과 실제 파일 보관 완료는 구분한다.
5. ZIP을 새 폴더에 풀고 `notes.json`을 로그인한 본인 계정의 관리 → 내보내기·사본 복원에서 **새 작업공간**으로 복원한다. 보조 파일 JSON도 별도 작업공간으로 복원할 수 있다. 이미 앱에서 추가 편집한 기존 작업공간에 덮어쓰거나 합치지 않는다.

파일이 전부 준비되기 전이나 검증 실패 시 기존 선택/출력에 반영하지 않는다. 후보가 없는 참조는 보류할 수 있다. 최초 미확정 감사 454회·검토 152회/60묶음·보관 정보 302회는 그대로 보존하며 해결 결과는 별도 이력으로 남긴다. 실제 후보 15묶음과 위치 확인 2묶음의 판단은 사용자가 한다.

## 오프라인 명령

화면과 명령은 같은 검증·적용 어댑터를 사용한다. 선택 파일만으로 명령을 실행할 수도 있다.

```sh
node scripts/apply-obsidian-decisions.mjs --input /private/original-export --decisions /private/decisions.json --preview
node scripts/apply-obsidian-decisions.mjs --input /private/original-export --decisions /private/decisions.json --output /private/new-selected-copy
```

`--preview`는 집계만 출력하며 파일을 쓰지 않는다. 실제 출력은 앱/입력 폴더 밖의 새 경로만 허용하고 기존 디렉터리를 대체하지 않는다. 새 디렉터리 0700/파일 0600이며 심볼릭 링크 입력을 거부한다. 쓰기 실패 시 이번에 만든 불완전 디렉터리만 제거한다. 콘솔에는 개인 경로·본문·대상이 나오지 않는다.

CLI와 ZIP은 원래 6개 파일 중 `notes.json`의 선택한 연결과 백업 메타데이터를 바꾸고 나머지 파일 바이트를 보존한다. `decisions.json`과 누적 `applications.json`을 추가한다. 원래 `review.html/json`과 감사는 변경 전 근거로 유지된다. Git bundle과 읽기 HTML은 실행하지 않고 원래 바이트로 복사하며, Git pack 검증은 앞선 전체 가져오기 단계의 증거와 구분한다. 이미 적용된 사본을 다시 열고 같은 선택을 적용하면 중복 연결을 만들지 않는다. 도구 HTML은 개인 자료를 담지 않는 별도 실행 도구이며 새 ZIP에서 다시 생성할 필요가 없다.

## 구조·보존·반대 검토

- `scripts/lib/obsidian-decisions.js`는 Node/브라우저 공유 어댑터다. 기존 Core의 JSON 검증/해시 검증/새 ID 복원/백업을 재사용한다. 원문 바이트·sourceKey·정확 Git URL·source/version ID 매핑을 확인하고 검증한 사본을 내부 컨텍스트에 보관한다.
- 선택 파일은 저장소/Git ref/원래 감사 파일 SHA-256과 출발 경로·정확 UTF-16 범위·토큰·출발/대상 SHA-256에 묶인다. 묶음 ID나 파일명만으로 반영하지 않는다. 감사와 ID가 다른 계정 복원본을 입력 패키지로 간주하지 않는다.
- 제목·블록 위치 미확인 참조는 이미 있는 문서 연결의 위치만 보완한다. 상충하는 기존 연결은 덮어쓰지 않는다. 같은 선택의 재적용은 변경 없음으로 구분한다. 원문·발췌·다른 연결은 그대로 둔다.
- `renderDecisionTool()`은 Core·공유 어댑터·native file API·기존 fflate를 담은 독립 HTML을 만든다. 읽기용 `review.html`은 계속 스크립트가 없다. 선택 도구는 고정 스크립트/스타일의 SHA-256 CSP, 외부 리소스/연결 차단, 평문 DOM 표시를 쓴다. 개인 파일을 웹 루트에 복사하거나 계정/원격 API를 연결하지 않는다.
- 본문에 있는 HTML/스크립트/YAML은 실행하지 않는다. ZIP 엔트리는 고정 파일명만 사용하며 원본 코드/플러그인을 앱 기능으로 설치하지 않는다. 선택 결과는 새 패키지에만 적용하므로 원래 폴더가 복구 기준으로 남는다.
- 새 UI 프레임워크·parser·DB/동기화 형식을 추가하는 대안은 원문 보존/단일 작업에 비해 비용이 컸다. [공식 비교·라이선스](../life-tools-design/open-source-review.md)를 따르고 기존 fflate의 MIT 원문도 도구 HTML에 포함한다. 위치 보완은 Markdown 전체 문법 지원이 아니며 실제 한 줄 제목/블록만 명시 선택한다.

- 전체 규모 익명 **6,899개 파일 / 60묶음 / 152회**를 브라우저에서 검증·선택·ZIP 출력하고 노트 3,479개·새 연결 1개를 다시 복원했다. 원래 감사 바이트는 동일하다. 로컬 로딩 시간은 보고서의 해당 실행값이며 모바일/실기 성능 보장은 아니다.
- 실제 개인 패키지 **6,899개 파일 / 검토 152회/60묶음 / 보관 정보 302회**는 오프라인 입력 검증만 수행했다. 개인 원문을 브라우저·스크린샷·CI에 넣거나 실제 연결을 대신 선택하지 않았다.
- 1440/820/390px의 대조/미리보기 **6개 화면**에서 가로 넘침·44px 조작·16px 입력·이름·대비를 확인하고 이미지를 직접 읽었다. 파일 선택을 마치면 해당 조작이 접혀 본문 대조를 먼저 볼 수 있다.

## 남은 한계와 운영

도구는 파일 선택 기반이며 로컬 HTTP로 재열어 검증했다. 실제 Apple Files의 HTML 직접 실행·파일 선택/ZIP 저장·VoiceOver와 한글 실기는 미검증이다. Chromium 폭 모사를 실제 Mac/iPad/iPhone 검증으로 표시하지 않는다. 브라우저 다운로드/ZIP 해제 뒤 파일 권한은 운영체제에 따르며 CLI의 0700/0600 보장과 다르다. 화면 입력은 파일당 64MiB/총 256MiB, CLI는 파일당 64MiB로 제한하고 ZIP은 기존 사진 글처럼 무압축을 사용한다.

원본에 없는 첨부를 복구하거나, 이미 가져온 작업공간의 후속 편집을 자동 합치거나, Git 최신 상태를 자동 반영하는 기능은 아니다. 운영 계정 반영은 본인 로그인 후 새 사본 복원이다. main 병합·운영 배포·실기 확인은 기존 Local 인계 범위를 유지한다.
