# 회고 → 목차 구성 실제 앱 독립 시각 검토

2026-10-09 KST · 검토자 design_finish_review · `codex/reflection-to-outline`

## 1. 판정과 검토 범위

**disposition: ship — 이번 실제 앱의 시각·내용 위계 범위.** 선택된 A의 흰 본문·한 열·절제된 보조 조작을 회고와 목차 구성에 일관되게 확장했다. 읽기 → 현재 생각 쓰기 → 목차 후보 검토 → 원문 대조의 목적지가 화면에서 구분되며, 적용을 막는 시각적 결함은 발견하지 못했다. Local의 PR55 실기 확인·병합·배포 판정을 대신하지 않는다.

독립 시안이 아니라 실제 앱에 익명 자료 6개·정확한 원문 버전 7개를 UI로 가져온 증거를 검토했다. 화면의 현재 선택은 원문 버전 6개로 표시된다. 자료 전체 개수와 선택 개수를 혼동하지 않는다. 변경 전과 최종 변경 후의 연도별·묶음별·목차 구성 각 390/820/1440px, 총 18개 기본 이미지를 `view_image`로 각각 열었다. 최종 after 9장은 QA 확정 뒤 한 번만 판단했다. 390px 긴 원문·현재 생각 2장, 쓰기 도착·읽기 복귀·목차 원문 복귀 각 세 폭 9장, 저장 실패 390px 1장도 개별 확인했다. contact sheet나 테스트 통과 수로 시각 검토를 대체하지 않았다.

기본 after 증거는 `2026-10-08T21:53:22.807Z` 실행, Chromium 151.0.7922.173이며 실제 기기 검증이 아니다. 자동 디자인 detector는 실행하지 않았다. 앱 수정은 root가 담당했고 검토자는 이 문서만 작성했다.

## 2. 변경 전 문제와 최종 화면의 판단

| 작업 | 변경 전 실제 화면 | 최종 실제 화면과 판단 |
| --- | --- | --- |
| 연도별 읽기 | 저장·소개·선택·분류·목차·기간을 지나 원문 제목만 보였다. 모바일 첫 화면에 실제 문장은 없었다. | 원문 첫 문장을 기본으로 보여 글을 알아볼 수 있다. 작성 연도·출처·작성자 관계·이전 버전 표시는 본문보다 작게 남아 맥락을 보존한다. |
| 묶음별 읽기 | 제목과 관리 정보의 반복이 중심이며 원문은 매번 펼쳐야 했다. | 직접 만든 묶음 제목 아래 실제 문장이 보인다. 묶음과 발췌 주제가 다르다는 설명을 남겼으므로 분류 의미를 임의로 단순화하지 않는다. |
| 현재 생각 쓰기 | 긴 목록 뒤 작은 입력 상자로 내려가고 목차 조작이 멀리 위에 있었다. | `지금의 생각`과 `원문과 별도로 남기는 내 회고입니다.`가 작업을 분명히 구분한다. 긴 글이 페이지에 펼쳐지고 상단 쓰기·목차 조작이 남는다. |
| 목차 검토 | 제목·질문·여러 안내와 반복 후보 라벨이 먼저였고 책 만들기는 아래에 있었다. | `회고로 돌아가기`와 `이 목차로 책 만들기`를 상단에 유지한다. 후보는 체크·순번·장 제목·연결 원문으로 읽히며 반복된 `장 N 포함/제목` 라벨을 줄였다. |
| 정확 원문 왕복 | 목차의 후보와 원문을 오간 뒤 무엇을 검토했는지 다시 찾을 부담이 있었다. | 원문 복귀 캡처에서 첫 후보의 연결 원문이 펼쳐진 채 `1/2 버전`과 자료 제목이 보인다. 인접 후보와 포함 상태도 함께 남아 있다. 실제 위치·초점 보존 성공은 별도 QA 근거다. |

원문 미리보기는 첫 문단을 최대 260자로 보여주는 표시층이며, 전체 읽기는 명시적으로 펼친다. 캡처에서 원문과 현재 생각을 자동 요약·합성한 결과처럼 보이는 표시는 없다. 미리보기의 문자열 보존이나 정확 버전 동일성은 이미지로 전부 대조한 것이 아니며 별도 보존 검사 범위다.

TYPE은 산세리프 한글, 굵은 분류·자료 제목, 편안한 본문 간격으로 내용 위계를 만든다. MATERIAL은 실제 문자·입력·공통 아이콘이며 장식 이미지를 더하지 않았다. GROUND는 흰 본문과 옅은 자주색 조작으로 기존 A를 유지한다. 쓰기 도착의 선명한 초점 테두리는 입력 위치를 알리는 상태이며 평상시 프레임으로 평가하지 않았다.

## 4. 남은 시각적 비용과 우선순위

**이번 적용에 필요한 미처리 시각 수정은 없다.** 다음은 실제 사용에서 판단할 비용이며 새 기능·추가 의존성·추가 구현 요구가 아니다.

1. 묶음별 설명과 선택·기간 조작이 모바일에서 여러 행을 차지한다. 연도별보다 첫 원문이 아래로 내려가지만 자료 분류의 의미를 보존하는 비용이다. 앞으로 자주 보는 사용자에게 반복 설명이 얼마나 필요한지 사용 경험으로 판단할 수 있다.
2. 목차의 책 제목과 질문이 여전히 후보보다 앞선다. 상단 생성 행동과 간결해진 후보 덕분에 완료 경로는 분명하지만, 휴대폰에서 여러 후보를 한눈에 비교하는 밀도는 낮다. 질문을 곧바로 편집할 수 있는 장점과 함께 선택한 구조다.
3. 모바일 전역 도크는 중간 스크롤 캡처의 아래쪽 문장·다음 후보와 겹친다. 이는 현재 viewport의 overlay이며, 해당 이미지가 문서 끝이나 마지막 조작의 접근 불가를 보여주는 것은 아니다. 첫 후보와 주요 상단 조작은 가리지 않는다. 이 겹침만으로 material blocker라고 판단하지 않았으며 마지막 콘텐츠의 실제 도달 여부와 소프트 키보드 동시 가림은 정적 이미지 검토 범위 밖이다.
4. 연필·연결·책 아이콘은 간결하지만 처음 쓰는 사람에게 의미가 전부 자명하지는 않다. 접근 이름·도움말·실제 클릭 도착을 보존하는 것이 필요하며, 아이콘 수나 픽셀 수 자체를 품질 지표로 삼지 않는다.

## 5. 추천과 한계

현재 결과를 A의 실제 확장으로 유지하는 것을 추천한다. 이전의 관리 중심 첫 화면에서 실제 문장으로 대상을 알아보는 읽기로 바뀌었고, 현재 생각을 쓰다가 목차로 이어지는 조작을 화면 위에서 찾을 수 있다. 반대 근거는 묶음 설명과 목차 질문 폼이 남기는 상단 지면 비용이다. 본문과 보존 조건을 희생해 이를 더 줄일 이유는 이번 증거에서 발견하지 못했다.

시각 검토는 별도 QA의 클릭·초점·커서·정확 버전·저장 실패·후보 보존 검사를 대신하지 않는다. 긴 원문 2,217자·현재 생각 920자는 QA가 제공한 익명 자료이며 개인 자료가 아니다. 세 폭은 Chromium 모사이고 실제 Apple 한글 IME·소프트 키보드·파일 저장·운영 DB·공개 배포는 검증하지 않았다. 이번 판정은 사용자 선호의 증명이나 테스트 수에 따른 미적 합격이 아니다.
