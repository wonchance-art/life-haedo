# 작품 작업과 분리한 독립 품질 검수

2026-10-14 KST. 기준은 PR #84의 `fd395aafa2e1`이며 별도 worktree에서 검토했다. 작품 제공자·작품 입력·페이지 초안 편집은 다른 세션의 범위로 두었다. root가 통합을 맡고 세 독립 에이전트가 컬렉션 백업, 검색 왕복, CI 실패를 나누어 검수했다.

## 목표와 보존 조건

기존 자료를 찾고 정확한 원문을 읽는 흐름이 무관한 초안 조회 장애로 막히지 않게 하고, 저장과 PWA 갱신의 완료를 실제 결과로 확인한다. 새 기능·SQL·라이브러리는 추가하지 않는다. 기존 버전·UTF-16 위치·검색 복귀·계정/공간 경계·원자 저장·파일 형식을 보존한다. 새 검수 실행기는 기존 `prepare-site.mjs`와 `platform-life-browser.cjs`를 재사용하며 테스트 설정만 생성한다.

원문 자체의 읽기 장애에는 이동을 계속 차단하고 같은 검색어에서 재시도할 수 있다. 초안 읽기 실패를 무시하는 방식으로 원문 저장 실패까지 감추지 않는다.

## 배포 산출물 검수

`node scripts/verify-prepared-site.mjs`는 전체 Git 이력에서 현재와 다른 직전 실제 캐시를 찾고 `origin/main`의 별도 캐시도 검사한다. 이전 커밋 전체를 `git archive`로 보존하고 각 커밋의 생성기를 실행한다. 단순히 현재 SW의 버전 문자열을 바꾸어 이전 릴리스를 흉내 내지 않는다.

모든 생성에 HTTP 시뮬레이터용 URL/key를 명시한다. 플랫폼 검사도 해당 익명 설정을 확인한 뒤 생성된 설정 파일 자체를 읽는다. 공통 fixture가 설정 파일을 대체하던 route를 제거하여, 현재 `SHELL`의 **모든 리소스**를 실제 설치 캐시의 SHA-256과 생성 파일로 대조한다. 원문·검토 초안·localStorage는 갱신 전후 완전히 같아야 한다.

이번 실제 보존 경로는 `v107 → v108` 및 main의 `v90 → v108`이다. 두 출발점은 보존한 소스 커밋의 fixture이며 사용자의 실기 설치를 검사한 결과가 아니다. 병렬 브랜치의 변경을 병합한 최종 산출물에도 새 캐시 버전과 이 검사를 적용해야 한다.

CI는 전체 이력을 checkout하고 기존 pinned Playwright/Chromium을 사용한다. 검사 실패는 browser job 실패로 전달되고 기존 `build.needs: [check, browser]`가 배포를 차단한다. 결과와 기준 커밋은 `.local/prepared-site-check/platform-report.txt` 및 `baseline.json`에 남아 CI artifact에 포함된다. 생산 secrets·운영 DB가 필요하지 않다.

예상 외 콘솔/페이지 오류 및 외부 요청은 해당 수집 검사에서 0이었다. 플랫폼 검사의 의도한 오프라인/콜백 오류 3건은 따로 집계했다. 숫자는 제품의 미적 품질·유용성을 대신하지 않는다. root가 좁은 폭의 원문 및 필터가 남은 보관 결과 이미지를 직접 확인했다.

로컬은 Linux Chromium `151.0.7922.173`이다. CI의 pinned Playwright `1.63.0`은 설치되지만 Chromium 153 다운로드는 환경 정책의 403으로 차단됐다. 해당 CI의 성공 여부는 최종 PR HEAD에서 확인해야 한다. 실제 Google 로그인·운영 RLS/SQL·Mac/iPad/iPhone IME/Files·VoiceOver·실기 강제 종료는 이번 검증에 포함되지 않는다. 병합·운영 설정·배포는 수행하지 않았다.

## 후속 인계와 반대 검토

1. **다른 세션의 페이지 초안 작업:** `readPageDrafts`만 실패해도 정상 저장 글 피드가 사라지고 읽기 오류를 저장 중단으로 표시한다. 정상 저장 글 읽기와 초안 편집 장애를 분리할지 검토한다. 최소 완료 기준은 초안 조회 실패 중 저장 글 읽기·검색 복귀가 가능하고, 초안 조작에는 명시적 재시도가 남는 것이다. 이번에는 관련 파일을 수정하지 않았다.
2. **최종 통합/Local:** main 보호와 필수 상태 검사는 현재 설정되지 않았다. 기존 배포 gate와 main 병합 보호를 구분하며 최종 HEAD의 check/browser 성공을 병합 기준으로 확인한다. 저장소 보호 설정을 이번 변경으로 적용하지 않았다.
3. **실기 체험:** Safari/iPad 파일 보관과 앱 전환 후 복귀는 실제 기기에서 확인한다. 로컬 백업 테스트 통과를 다운로드 보관 완료로 표시하지 않는다.

더 단순한 대안은 검색에서 전체 갱신을 계속 요구하고 오류를 재시도하게 하는 것이지만, 읽기와 무관한 저장소 장애가 정상 원문을 막는 결합을 유지한다. 이번에는 읽기에 필요한 확인만 좁혔으며 저장·공간 전환의 전체 갱신 절차는 유지했다. 초기 조회 동안 탐색 클릭이 무시되는 busy 동작은 보호 계약에 영향을 주므로 재현만 기록하고 범위를 넓히지 않았다.

## 재실행

전체 Git 이력과 최신 `origin/main`, 기존 pinned 브라우저 도구가 필요하다.

```sh
npm run check
npm test
node scripts/verify-prepared-site.mjs
npm run dev
BASE_URL=http://127.0.0.1:4173 node tests/unified-search-browser.cjs
BASE_URL=http://127.0.0.1:4173 node tests/core-experience-browser.cjs
BASE_URL=http://127.0.0.1:4173 node tests/collection-picker-browser.cjs
```

수동 체험은 `기록 → 통합 검색 → 과거 버전 결과 → 검색 결과로 돌아가기`다. 정확 원문과 검색어·결과 초점이 유지되어야 한다. 개발 서버는 `http://127.0.0.1:4173`, 종료는 `Ctrl+C`다. 독립 재현 자료는 `.local/independent-backup/`, `.local/independent-search/`, `.local/independent-ci/`에 보관했다.
