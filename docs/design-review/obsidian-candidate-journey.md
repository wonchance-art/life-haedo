# Obsidian 내부 링크와 사진 보관 경계

2026-10-26. 원문에 남은 위키·상대 Markdown 링크의 발생 위치를 UTF-16 그대로 찾고, 현재 공간에 보관된 Obsidian 원문 판을 사용자가 직접 비교해 연결한다. 코드 블록·주석과 외부 주소는 자동 후보로 삼지 않는다. 동명 경로, 여러 원문 판, 중복 제목·블록과 누락된 본문은 서로 다른 상태로 표시한다. 후보가 하나여도 사용자의 명시 선택이 필요하다. 링크 항목은 각각 접혀 있고, 사용자가 연 항목의 후보와 위치만 계산·표시한다. 서로 다른 보관함의 같은 상대 경로는 같은 자료로 추정하지 않으며 경로·출처와 정확한 원문 판을 함께 보여 준다.

연결 전 출발 원문 토큰·UTF-16 범위·양쪽 판의 해시와 대상 제목/블록 위치를 다시 확인하고, 기존 Core `obsidian_link`와 CAS 트랜잭션을 사용한다. 다른 연결이 이미 있거나 원문·화면·계정이 변경된 경우 선택을 다시 확인한다. 기존 원문과 인용은 변경하지 않는다. 첨부는 원본 보관소의 명시 범위를 확인하기 전에는 후보 미확인으로 남기며, 이름만으로 ZIP을 내려받거나 영속 연결하지 않는다.

일반 자료 JSON과 근거 ZIP에는 네이버 원문 사진 sidecar가 포함되지 않는다. 현재 브라우저에서 사진 사본을 찾지 못한 경우 원래 사진의 유무나 서버 보관 여부를 알 수 없다고 안내하고, 네이버 수집 사본을 별도로 검토하도록 연결한다. 이 경로에서 새 판을 반영하더라도 기존 인용이 가리키는 옛 판의 사진이 복구됐다고 주장하지 않는다. 본문이 같아도 사진이 다른 판이 있으므로 자동 대조하지 않는다. 파일 제공자가 MIME 정보를 주지 않는 JPEG·PNG·WebP는 서명과 실제 이미지 디코딩을 검증하고 원래 바이트·픽셀·SHA를 유지한다. HEIC 지원이나 실제 Apple 기기 성공으로 확대하지 않는다.

검수 결과와 출시 커밋은 해당 PR 및 CI 기록을 따른다. 실제 네이버 응답·CDN·예약 수집은 실행 환경과 서버 설정이 준비될 때까지 미확인이다.

익명 합성 3,479노트·기존 연결 2,568개·링크 20개·동명 후보와 중복 위치 각 20개의 390px Chromium 측정에서 기존 일괄 렌더는 첫 프레임까지 10.9초와 DOM 59,346개였다. 이는 최악 조건의 단일 실험이며 실제 사용자의 기기 측정값이 아니다. 링크별·후보별 지연 표시와 기존 연결 인덱스를 적용한 같은 조건의 최종 측정에서는 전체 펼침 227ms·DOM 126개, 링크 하나 열기 250ms·349개, 후보 하나 열기 211ms·492개였다. 정확한 후보와 위치로 복귀하는 검사도 통과했다.
