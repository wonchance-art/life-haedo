# 해도 — life-haedo

연표·목표·습관을 함께 사용하는 개인 기록 플랫폼. 공개 홈에서 Google 로그인 후 내 공간으로 들어간다.
따뜻한 종이색과 간결한 그래프를 유지하며, 빌드 없이 정적 호스팅에서 실행한다.

[배포 사이트](https://wonchance-art.github.io/life-haedo/) · 로컬 변경은 배포 전까지 사이트에 반영되지 않는다.

## 사용

1. Google 계정으로 로그인하고 `내 공간`에서 연표·목표·습관을 연다. `새 연표`는 빈 문서로 시작한다.
2. `＋ 추가`로 사건·기간·생각을 추가한다. 입력을 마치거나 `완료`를 누르면 기기에 저장된다.
3. `기록`에서 제목·내용·날짜와 종류로 찾고 편집한다. `⌘/Ctrl+K`로 전체 검색도 가능하다.
4. 내 공간의 `전체 백업`으로 연표·목표·습관을 함께 보관한다. `기존 기록 연결`과 JSON 가져오기는 항상 **새 사본**을 만든다.

- 행복도는 −1~+1. 같은 달의 사건·명시적 값은 평균을 내고, 기록이 없는 달은 기간 값으로 채운다.
- 연표에서 드래그·확대·기간 조절, 실행 취소/다시 실행, 지도·생애 격자, PNG/SVG 내보내기를 지원한다.
- 데이터는 브라우저 localStorage에 저장된다. 저장 상태는 상단에 표시된다. 브라우저 데이터 삭제에 대비해 파일 백업을 보관한다.
- 로그인과 동기화는 해도 전용 Supabase에 연결한다. 실제 서버에서 계정을 확인한 뒤 개인 화면을 열며, RLS로 계정별 데이터를 보호한다.
- 목표는 마감일·진행률·완료, 습관은 반복 요일·날짜별 체크·연속 실천을 지원한다.
- 기존 브라우저 기록은 자동으로 다른 계정에 연결하지 않는다. 백업 후 본인 기록 확인을 거쳐 새 사본으로 연결한다.

## 로컬 실행과 검사

Node.js 20 이상과 Python 3이 필요하다. 앱용 패키지 설치와 빌드는 없다.

```sh
npm run check
npm test
npm run dev
```

[로컬 앱](http://127.0.0.1:4173)을 연다. 서버 종료는 실행 터미널에서 `Ctrl+C`.
Node 없이 화면만 실행하려면 `python3 -m http.server 4173 --bind 127.0.0.1`.

로컬 주소와 배포 사이트는 저장 공간이 다르다. 개발 시 익명 샘플을 사용하며 개인 기록·DB 설정은 자동으로 옮겨오지 않는다.
저장소의 연결 설정은 빈 값이다. 공개 홈은 서버 없이 확인할 수 있으며, 로그인에는 전용 서버 설정이 필요하다. [플랫폼 연결 설정](docs/platform.md)을 따른다.
지도·장소 검색·폰트는 외부 서비스에 의존한다. 오프라인 앱 셸은 남지만 개인 화면을 다시 열 때는 서버 인증이 필요하다. 이미 열린 화면의 수정은 기기에 보존하고 연결 후 전송한다.

- `npm run check`: JavaScript 구문, 로컬 리소스와 PWA 셸.
- `npm test`: 날짜·데이터 보존·동기화 충돌·서비스워커 회귀 검사.
- 실제 편집과 모바일 화면은 프로젝트 스킬의 격리 브라우저 절차로 검증한다.
- `main` 푸시는 GitHub Pages 배포로 이어진다.

| `index.html`, `login.html` | 공개 홈과 Google 로그인 |

| `timeline.html` | 기존 연표 화면 |

| `assets/data.js` | 달력 검증·데이터 정규화·안전한 가져오기 |
