# 실제 RSS 원천 허용 목록 PR 초안

이 문서는 주소를 받은 뒤 총괄이 만들 PR의 초안이다. 지금 실제 PR을 만들거나 Edge의 `ALLOWED_HOSTS`를 바꾸지 않는다. 원천 자리표시자는 **`__RSS_FEED_URL__` 한 개**만 사용한다. 기본 꺼짐과 빈 허용 목록은 [운영 활성화 절차](rss-activation.md)를 마칠 때까지 유지한다.

## 원천을 받았을 때 확인할 것

- 소유자가 지정한 공개 RSS 2.0 또는 Atom 1.0의 정확 URL인지 확인한다. HTTPS, 정확 호스트, 리다이렉트 없음, 사용자 정보·명시 포트·IP/로컬 주소·프래그먼트 없음이 조건이다. 인증 토큰·서명 값이 든 URL은 이 PR에 기록하지 않는다.
- 신뢰할 수 있는 운영자가 관리하는 공개 호스트인지 확인한다. 호스트 문자열 허용은 DNS 고정을 보장하지 않는다. 임의 도메인·사용자 제공 호스트를 모두 허용하는 변경으로 넓히지 않는다.
- 최신 글이 앞에 오고, 관측 완료한 글만 있는 페이지 뒤에 더 새 글이 나오지 않는지 확인한다. 페이지 이동은 같은 origin이며 다음 URL이 안정적인지 본다. 임의 재정렬·삭제가 반복되는 피드의 전체 이력 보존을 약속하지 않는다.
- 안정적인 GUID/Atom ID 또는 원문 링크, 발행 시각, UTF-8 텍스트 본문 범위를 확인한다. Atom `published`가 없으면 `updated`를 사용하므로 과거 글의 수정이 새 시각으로 나타나는 원천인지 기록한다.
- 텍스트의 비공개 보관이 가능한 원천인지, 피드에 제공된 범위가 요약인지 본문인지 확인한다. 원문 페이지·사진·영상·댓글 추가 수집은 이 PR 범위에 넣지 않는다. 피드 본문을 저장소 fixture나 PR에 그대로 옮기지 않는다.

현재 예산은 원천별 정상 60분, 연결별 실행 2페이지·100항목·텍스트 합계 2 MiB, 자료 한 항목 1 MiB다. 처리한 한 회차는 총 50페이지까지다. 실제 원천이 예산을 넘으면 상한을 조용히 키우지 말고 총괄이 채택 조건을 다시 결정한다. 식별자가 요청마다 바뀌는 원천은 즉시 실행이 무한 반복되지는 않지만 바뀌는 항목당 시간당 최대 2행이 계속 쌓이므로 그대로 채택하지 않는다.

## PR 제목과 본문 초안

**제목:** `RSS/Atom: 승인된 원천 한 곳의 수신 허용`

> 소유자가 지정한 `__RSS_FEED_URL__`을 RSS 1단계의 원천으로 추가한다. Edge의 정확 호스트 허용과 DB의 정확 URL 허용을 같은 검수 기준으로 맞춘다. 과거 글은 기준 목록에서 제외하며 이후 새 글의 피드 제공 텍스트만 비공개로 보관한다. 원천 등록·원격 활성화·Cron 설치 완료는 이 PR의 코드 병합과 구분한다.
>
> 원천 검토: 제공자, 확인 날짜, 공개 호스트 관리 주체, RSS/Atom 형식, 최신순·페이지 이동, 안정 식별자·날짜 사용, 본문 포함 범위와 보관 조건을 기록한다. 실제 기사 본문·키·서명 URL은 기록하지 않는다.
>
> 변경: `supabase/functions/haedo-rss/feed.mjs`의 `ALLOWED_HOSTS`에 위 URL의 **정확 host 한 개**를 넣는다. 문자열 접미사·와일드카드·요청 매개변수로 허용 범위를 넓히지 않는다. 승인된 URL은 `rss-activation.sql`의 `feed_url` 입력으로 같은 값이 사용되도록 검수 기록에 고정한다. 기본 `action='inspect'`는 유지한다.
>
> 검증: 기존 RSS 단위·격리 SQL·브라우저 검사를 실행한다. 실제 원천의 구조·경계 차이는 익명 합성 fixture로 재현하고, 허용 호스트/정확 URL 불일치·다른 origin의 next·리다이렉트·과거/누락 날짜·본문 예산을 확인한다. 실제 피드 요청 여부와 횟수는 fixture 검사와 별도로 기록한다. 주소를 받기 전 준비 단계의 실제 피드 요청은 0건이다.
>
> 운영 인계: 최종 head SHA·변경 파일 해시와 독립 검수 결과를 총괄에게 전달한다. 총괄이 배포된 `haedo-rss`의 의존 파일·`verify_jwt=false`를 대조한 뒤 activation → Cron을 적용한다. 불일치 시 runtime을 켜지 않는다. 실패 시 `rss-rollback.sql`로 RSS 수집만 중지하며 이미 받은 자료는 남긴다.

위 본문에서 검증 결과는 실제 실행한 결과로 채운다. 아직 받지 않은 URL을 임의로 정하거나 검증되지 않은 날짜·권리·페이지 동작을 완료로 쓰지 않는다. 후속 PR의 파일 담당 범위는 착수 전에 #212에서 총괄에게 확인한다. E의 자료 반영/ACK 구현과 앱·자료 저장소를 겹쳐 수정하지 않는다.

## 변경할 값의 일치 확인

| 대상 | 일치 조건 |
| --- | --- |
| 코드 `ALLOWED_HOSTS` | 승인 URL에서 검토한 정확 호스트 한 개 |
| DB 활성화 입력 `feed_url` | `__RSS_FEED_URL__`를 대체한 승인 URL 전체와 일치 |
| DB runtime `allowed_feed_urls` | 승인 URL 한 개, 실제 원문 URL·다음 페이지 URL의 범용 목록으로 확장하지 않음 |
| 배포물 | 허용 목록 PR 최종 SHA의 entrypoint·handler·feed·파서·공통 키 helper 포함 |
| Cron | 동일 프로젝트의 RSS Edge, Vault 이름 참조, `apikey`, `{"action":"run"}` |

DB는 등록한 피드의 정확 URL을 제한하고 Edge는 각 페이지의 호스트·같은 origin을 제한한다. 첫 페이지의 URL 정규화 결과도 DB 입력과 같아야 한다. 이 둘은 서로를 대체하지 않는다. URL이나 호스트가 나중에 바뀌면 기존 허용 목록에 몰래 추가하지 말고 같은 검수·배포·활성화 절차로 다시 판단한다.
